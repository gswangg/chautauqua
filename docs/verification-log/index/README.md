# Verification log index entries

`docs/verification-log.md` was a single append-only file that every
verification-lane worker edited at the same tail location, and merge
conflicts on it repeatedly starved other work (4 conflicts observed by wave
28's structure-custodian pass). This directory decomposes it into one file
per section, with no change to the assembled content or the DEC-069
exit-predicate grep contract.

- Each file here is `NNNN-<date>-<branch>-<scope-slug>.md`, holding exactly
  one `## <date> <branch> — <scope> [@ <sha>]` section verbatim (same content
  that used to live inline in `docs/verification-log.md`).
- `docs/verification-log.md` is generated by concatenating these files in
  filename order behind a fixed preamble -- see
  `scripts/assemble-verification-log.ts`.
- These are the *index* entries (the short summary + "Full detail:" link).
  They are distinct from the pre-existing `docs/verification-log/*.md`
  detail files (one per run, unchanged by this decomposition) that they
  link to.

## Adding a new entry

1. Find the next sequence number: `tsx scripts/assemble-verification-log.ts --next-seq`
2. Create `docs/verification-log/index/<seq>-<date>-<branch>-<scope-slug>.md`
   containing your `## ...` section, in the same format as existing entries
   (this is a new file, so it cannot merge-conflict with any other lane's
   new entry).
3. Run `tsx scripts/assemble-verification-log.ts` to regenerate
   `docs/verification-log.md`.
4. Commit both the new index file and the regenerated
   `docs/verification-log.md`.

If two lanes pick the same sequence number, resolving the conflict is just
re-running step 1/3 with the correct next number -- the generated file is
never hand-edited, so there is nothing to reconcile by hand.
