# CONFIRM_TITLE_OBJECT_CEILING residual nine — disposition (v12m-w43-f, DEC-941 wave-43 amendment)

`app/src/confirm-title-object.scan.test.ts` measures every `<ConfirmDialog` call site under `app/src/**` (recursive, `.test.` files excluded — `srcFiles()` verified to walk the real population, not a hand-listed manifest) and grades its `title=` prop: a JSX expression is the object-naming idiom, a bare fixed string is not. `CONFIRM_TITLE_OBJECT_CEILING` stood at 9 since wave 25 with no rule for what the nine residual sites *were* — DEC-069 wave-34's "an exclusion with a promotion promise and no promotion rule is a permanent loophole." This task gives the residual a rule (DEC-941 wave-43 amendment, landed on both `decisions/DEC-941.md` and `src/decisions-data/DEC-941.md`) and drains what the rule condemns.

**Method**: `CONFIRM_TITLE_OBJECT_CEILING` was forced to `-1` and the test run to print the real offender roster, rather than trusting the task brief's own guess at the nine (which named `TracksRoomsPanel.tsx`, `CallForPapersPanel.tsx`, `FormsPage.tsx`, `BulkEmailModal.tsx`, `MergePage.tsx` — 5 of the real 9 — and missed `PlanEditor.tsx` ×2, `ProgressPanel.tsx`, `TaskView.tsx`). Each site's local component code was read to determine whether the caller already holds a single named record in state. Each literal title string was also grepped against every `docs/design/*.dc.html` frame; none of the nine literals is drawn verbatim by any v12 frame, so no site is a frame-wins case (DESIGN-RULINGS.md's "Confirm dialogs" section rules the two-weight/verb-primary grammar generically and names no site-specific title text).

## The instrument change

Each of the 7 residual `<ConfirmDialog` tags now carries a `// DEC-941 (wave-43 amendment): ...` comment stating, in the DEC-099 shape (a fact about the subject that stays true with every branch name and wave number deleted — no "later wave", no lane token), the principle that makes it a residual rather than an offender. `confirm-title-object.scan.test.ts` gained a companion assertion, `every bare fixed-string title= site carries a principle comment on its own tag`: for every occurrence graded `titleIsLiteral: true`, the scan reads the RAW (comment-preserving) source of that `<ConfirmDialog>` tag — using the same `[start, end)` byte offsets the comment-stripped grading pass already computed, since `stripComments` preserves length and newlines, so the two views of the file stay index-aligned — and requires a `//` comment line citing `DEC-941 (wave-N amendment)` with no `task-wN-x`/`v12m-wN-x` lane token standing in for the principle. A site with a bare literal title and no such comment now fails the scan by name. Two controls ship with it: a synthetic tag whose comment cites DEC-941 but also carries a lane token is rejected; a synthetic tag with a durable, lane-token-free DEC-941 comment is accepted.

This closes the loophole DEC-069 wave-34 named: the residual can no longer be a bare count with no rule for its members, because the instrument now enforces that every member states its own rule.
