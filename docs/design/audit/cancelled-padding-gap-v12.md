# Cancelled-padding companion-gap audit (DEC-393 wave-121 amendment, task w10-l)

Generated by reading the population `app/src/cancelled-padding-gap.scan.test.ts`
enumerates. DEVIATIONS.md:346-351's rider on the cancelled-padding idiom
(`padding-inline: Npx` cancelled by `margin-inline: -Npx`, DEC-383 wave-109)
reads: "wherever such a family renders as ADJACENT SIBLINGS, the rule owning
their separation adds the cancelled padding back, or the rendered gap
closes". This audit is the measured instrument for that half of the ruling
— the sibling `comms-cancelled-padding.w5n.test.ts` only checks the FACE
(bordered vs borderless), never the gap on the row that hosts the cancelled
subjects.

Every cancelled-padding rule in the tree declares `N = 10px`. Two adjacent
cancelled-padding subjects each extend 10px past their own edge, so the
required gap to cancel that overlap is **2N = 20px**. Where the effective
phone gap is below that, `overlap = max(0, 2N − gap)`; where no `gap`/
`column-gap` is declared anywhere reachable, the row is recorded as `NONE`
and treated as the worst case (the full 20px stays unclaimed).

**Container derivation**: for each comma-separated selector branch made of
two or more combinator-joined compounds, the container is the branch's own
text with its last compound (and the combinator before it) removed — e.g.
`app/src/pages/settings/settings.css`'s `.chq-settings-people-actions
.chq-link-button` → container `.chq-settings-people-actions`. A branch made
of a single bare compound (no combinator at all) has no container and is
**out of population** — there is no sibling for a lone bare-text subject to
overlap.

**Design gap flagged for the planner** (narrowest reasonable reading taken,
per this task's instructions): DEC-393's own wave-121 amendment prose also
names `.chq-content-worklist-col-actions` and `.chq-reviewer-plan-row-action`
as containers declaring "no gap". Both are declared as SINGLE-compound
selectors in the live CSS — the cancelled-padding pair sits directly on the
selector itself, with no descendant/child combinator in any of that
selector's rules — so under the population rule this scan implements
("a selector with no container compound is out of population") neither is a
member here.  `app/src/pages/content/content.css`'s own comment records
`.chq-content-worklist-col-actions` as an inert empty `<th>` header spacer
with no children at all; `.chq-reviewer-plan-row-action`
(`app/src/pages/review/review.css`) sits in a CSS grid cell (`grid-area:
action`), so its true separation is owned by the grid's own `gap` on an
ancestor selector this selector-string lens has no way to name. Re-measure
on your branch, do not copy: this doc is this branch's own measurement, not
a copy of the ruling's illustrative prose.
