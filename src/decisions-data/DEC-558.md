# DEC-558: The contacts sibling-email conflict `.limit(1)` takes a total order because its refusal message NAMES the row it found

The usual 'any row proves the predicate' argument does not apply here: the handler throws `${firstName} ${lastName} already uses this email`, so WHICH row the engine returns is user-visible copy that can differ between runs over the same data.
