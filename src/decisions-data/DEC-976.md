# DEC-976: The claim receipt becomes executable over test files: a citation inside a frame's extent must carry the literal it cites and an assertion beneath it

DEC-967's wave-86 amendment ruled that a claim is three things in one place -- a strict citation landing inside the frame's computed extent, the cited line's literal quoted verbatim beside it, and an assertion beneath pinning what that literal declares -- and then left the rule enforced by nothing but each worker's care. DEC-976's wave-23 amendment already makes the literal-quoting half executable for NON-test files; the test-file half is the half that matters now, because twenty-five-plus claims are about to land from ten lanes and the ledger counts a citation whether or not anything is asserted under it. The repo has already paid for exactly this gap twice: DEC-967's wave-57 amendment banned the tautological test, and its wave-62 amendment banned the line-number pin. RULED: frame-citation.scan.test.ts gains the test-file direction, reusing its OWN existing STRICT_RE and flatten (never a second copy of either -- a second copy of a vocabulary is a trap with a delay fuse); the frame extent is COMPUTED the way the ledger computes it, from the width:390px line up to the next font-size:19px label line, never listed; and the violations are held by a two-sided ratchet ceiling that may only be lowered. The scan does not edit other lanes' tests to make itself green -- the ceiling exists so the measurement can land honest.

## Amendment (wave 91): a frame citation in PRODUCTION source carries the same receipt as one in a test file — the backtick-quoted literal, verbatim at the cited line

frame-citation.scan.test.ts fails three ways on main. Eighteen citations in production source (forms.css, review.css ×6, scorecard.css, settings.css ×3, submissions.css ×3, portal/edit.tsx ×2, portal.css.ts, portal/tasks/views.tsx) carry no quoted literal at all, so nothing checks that the rule beneath them still matches the frame line they name. Separately, 87 test-file citations are unreceipted against a ceiling of 14 — which is the real state of the campaign: test/phone-frame-ledger.scan.test.ts reads 53 of 53 CLAIMED on main, but a claim is a citation, and the receipt scan says most of those citations assert nothing. The ledger is therefore not the exit predicate the campaign can rest on; the receipt scan is. This wave closes all eighteen production citations and the SSR test files' share; the remainder is named as the wave-10 backlog rather than papered over by raising the ceiling.

## Amendment (wave 93): a receipt quotes a literal from the child line it came from — not the frame container, not a selector name, never elided

app/src/frame-citation.scan.test.ts measures 2 citations with no backtick quote and 19 whose quote is not verbatim at the cited line, extracted by running the scan's own findCitations/quoteAfter standalone (vitest truncates the arrays to `[ ...(19) ]`). They fall into exactly three shapes, and only the first is a wrong quote: (a) OFF-BY-A-FRAME — eleven quote real frame CSS but name the frame's `width:390px; height:844px` container line instead of the child line the declaration came from (agenda.css cites Agenda.dc.html:129 for text at :130; content.css cites Content.dc.html:254 for the anchor at :256; review.css cites Review.dc.html:413 three times for literals at :441 and :443; settings.css cites :347 for a literal at :349, :275-296 for `{{ g.label }}` at :288, and :393-441/552-575 for a padding run at :450; speakers.css cites :133/:138/:260 for literals at :130/:141/:257). Fix the NUMBER, not the quote. (b) A SELECTOR NAME IS NOT A RECEIPT — four settings.css citations quote `.chq-settings-rail-link-*`, `.chq-settings-panel h2`, `.chq-link-button`; a receipt is a literal the FRAME contains, so the quote is replaced with real frame text and the citation re-pointed at the line carrying it. (c) AN ELIDED QUOTE IS NOT VERBATIM — a quote containing a literal ellipsis (agenda.css's `background:#1B1D17; color:#F4F1E8; ... font-weight:600`, forms.css's `<div style="width:390px; height:844px; ...">`) can never match; quote a contiguous run instead. Also ruled: src/routes/portal/tasks/views.tsx quotes its own template literal `/portal/tasks/${assignment.id}/form` as the receipt for Public and Portal.dc.html:508 — code from the citing file is never a receipt for a frame.

## Amendment (wave 97): A frame's docked footer is an executable ledger of controls, not a picture of them

The campaign has measured frame GEOMETRY (tap floor, overflow, cascade, citations) and never once measured whether the controls a frame DRAWS exist in the build. Run over main, the four unbuilt controls this wave fixes were invisible to every green gate. RULED: a scan enumerates each `width:390px`/`height:844` frame (the phone-frame-ledger's own population idiom), extracts every literal string inside that frame's docked-footer region — identified by the frames' own repeated signature `flex-shrink:0; border-top:1px solid #1B1D17; background:#EFEBDF` — plus every `min-height:44px` back-link anchor, drops any string containing `{{`, and requires the remainder to appear verbatim in non-test source under `app/src/**` or `src/**`. A footer is the one frame region where every string is a control and none is sample data, which is why the population is drawn there and not from the whole frame. Seeded as a one-sided CEILING at the measured 12 unmatched of 73 (`toBeLessThanOrEqual`, so the four lanes landing this wave can only tighten it), never an allowlist populated from the failure output, and never a number a later wave may raise.

## Amendment (wave 98): an elided quote is not a citation, and a range citation quotes its RANGE-START line

app/src/frame-citation.scan.test.ts is RED on main with 16 production mismatches. They fall into exactly two shapes and both need a written rule so the repair is mechanical rather than a judgement call each time. (1) OFF-BY-A-FRAME: eleven citations name the frame's own `width:390px; height:844px` container line or a wrapper div while quoting a CHILD's inline style (review.css three times at Review.dc.html:413, settings.css six times, content.css at Content.dc.html:254, agenda.css at Agenda.dc.html:129). The repair is to move the NUMBER to the child line the quote actually came from — never to loosen the quote. (2) ELISION: forms.css quotes `<div style="width:390px; height:844px; ...">` and agenda.css quotes `background:#1B1D17; color:#F4F1E8; ... font-weight:600`. A `...` makes the quote unfalsifiable, which is the whole defect DEC-976 exists to prevent; replace it with a real contiguous substring of the cited line. Corollary for range citations (`:275-296`, `:393-441`): the quote must appear at the RANGE-START line, because that is the only line the scan can check. A citation whose quote does not survive whitespace-normalised verbatim matching is a broken citation, not a stylistic preference.

## Amendment (wave 99): The campaign's desktop half has never had a population; the 108 desktop frames get the ledger the 53 phone frames already have

The goal is "every screen matches its v12 frame on desktop AND phone", and `test/phone-frame-ledger.scan.test.ts` has answered the phone half since wave 83 by deriving its population from the pack itself (53 frames, per-file breakdown as a vacuous-population tripwire, claim by citation, a two-sided CLAIMED_FLOOR). Nothing answers the desktop half. Re-deriving from the same label-span grammar on main cf06f988: the pack carries 161 `font-size:19px` frame labels, 53 of whose extents contain `width:390px`+`height:844` — leaving 108 desktop frames with no enumeration, no claim measure and no floor, so eighteen waves of "desktop is frozen and already conformant" has been an assumption, not a measurement. RULED: a sibling ledger derives the desktop population by the same grammar minus the phone extents, minus a WRITTEN, justified exclusion predicate for label spans that are not frames — `{{ … }}` interpolation labels (`{{ e.name }}`, `{{ s.name }}`) and the pack's own explainer panels (`Widths · what a wide monitor gets`, `Rules you can't see on the page`, `How the screenshots are made`) — with the exclusion list itself asserted against the pack so a future re-cut cannot silently grow it. Floor seeded to measured; the failure message names every unclaimed desktop frame so a planner can schedule it. This instrument is the only thing that can ever make goalComplete provable for the desktop half; it changes no desktop bytes.

## Amendment (wave 100): a frame cannot mint a capability the domain does not have — the portal-resource 'Link' chip keeps the domain's own second kind, while the frame's LABELS and its single primary bind

docs/design/Chautauqua Settings.dc.html:1443-1470 draws the Add-a-resource modal with a 'Name' field captioned 'What speakers see in the list', a two-chip Kind control reading File / Link, a dashed drop zone, and ONE primary reading 'Add it' beside Cancel. app/src/pages/settings/ResourcesPanel.tsx renders 'Title' with no caption, chips reading File / Wiki page, and TWO primaries whose label swaps by kind ('Upload file' / 'Add wiki page'). Splitting the frame into what binds and what cannot: `resource.kind` is `file | wiki` — wiki is stored markdown, not a URL — so 'Link' names a URL-resource capability with no column, no validation and no renderer behind it. DEC-650's rule that a drawing's sample content does not bind covers numbers; this extends it to a CAPABILITY drawn in a chip: a frame is geometry and copy authority, never a schema migration. So the chip keeps 'Wiki page'. Everything the domain already supports does bind: the field label 'Name' and its helper line, and ONE primary reading 'Add it' — a primary whose text changes with an unrelated control is exactly the 'two primaries whose scopes differ' failure DESIGN-RULINGS A1 rules against. The Link-vs-Wiki divergence is recorded as a written finding, not worked around silently.

## Amendment (wave 101): desktop-frame claims are receipted the same way phone claims are — one node-tier test file per cluster, expected values typed as literals in the test, never read back from docs/design — and CLAIMED_FLOOR is set to the number the branch itself measures

The desktop half of the campaign goal has an instrument (`test/desktop-frame-ledger.scan.test.ts`, 16 of 102 claimed) and no working practice for spending it, which is why 86 frames have sat unclaimed for two waves. Three rules make the claims real rather than decorative. (1) SHAPE: each cluster's claims live in ONE new `test/desktop-frames-<cluster>.test.ts`, a pure string scan over the app's own sources (`readFileSync` of the cluster's `.css` / `.css.ts` / `.tsx`), modelled on `test/auth-card-geometry.test.ts`. Node tier, no jsdom import, so `test/test-tiers.test.ts` keeps deriving FAST membership with no config edit, and no existing test file is touched — which keeps every lane single-owner. (2) HONESTY: the expected value is TYPED as a literal in the test file. A receipt whose `expect()` subject is read from `docs/design` at runtime is a contract with the pack, not with the app — the exact defect `app/src/tautological-assertion.scan.test.ts` was extended to catch this train, and the one `settings-phone-390.frames.test.ts` still documents in its own title. Each claim is a comment carrying `docs/design/<File>.dc.html:<line>` followed in the same comment by the cited line's literal in backticks, with a real `expect(` within six lines beneath — the phone half's receipt grammar, applied to desktop. (3) RATCHET: a lane sets `CLAIMED_FLOOR` to the number the scan prints on ITS branch. Several lanes will edit that one line at once; the merge resolution is deterministic and is not "take either side" — re-run the scan on the merged tree and write the number it prints. Desktop citations are exempt from `frame-citation.scan.test.ts`'s unreceipted-claim ratchet (its extents are anchored on `width:390px`+`height:844`), so this campaign cannot worsen that already-red number. A frame that cannot be receipted honestly is left unclaimed and named in the lane's report — an unearned claim is worse than an unclaimed frame.
