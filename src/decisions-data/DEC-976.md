# DEC-976: Amendment (wave 103): an unclaimable desktop frame stays UNCLAIMED — a claim test never weakens its assertion to what the tree already satisfies, and a divergence from a frozen desktop frame is filed as a finding

The desktop half is 16 of 102 and this wave puts six lanes on it simultaneously — the first time claims are written at scale. DEC-976 wave-101 fixed the SHAPE (one node-tier test file per cluster, expected values typed as literals) but not the STANDARD, and a claim is trivially cheap to fake: every frame can be "claimed" by asserting something the tree obviously satisfies, which would drive CLAIMED_FLOOR to 102 of 102 while proving nothing about conformance, and this ledger is the desktop half's only instrument. Desktop is FROZEN by the campaign mandate, so a claim lane cannot fix a divergence it finds even when the divergence is real. The honest output is therefore asymmetric: assert the frame's drawn value against the tree, and when the tree contradicts it, leave the frame unclaimed and write the divergence (frame line, drawn value, shipped value) into docs/design/audit/desktop-frame-ledger-v12.md for a later lane or a DEVIATIONS entry. The floor then measures conformance rather than effort, and an unclaimed frame is a scheduled task rather than a hidden defect.

## Amendment (wave 105): a desktop frame the tree contradicts stays UNCLAIMED, and its divergence is filed in the claiming test file's own header

38 of 102 desktop frames are unclaimed on main; wave 5 schedules 32 of them (v12m-w4-k holds the 6 Review frames). The pressure a claim ledger creates is to claim, and the honest outcome for several of these frames is a divergence, not a claim: DEVIATIONS.md §6 already defers `Chautauqua Settings.dc.html:1111` (Your-data edit view -- retention select, keeping-and-deleting checkboxes, revoke-every-token footer, unbuilt), the shared ConfirmDialog 480/subtitle/typed-label anatomy behind :1392/:1414, and the Sessionboard importer modal behind :1507. RULED: a frame whose drawn anatomy the tree does not carry stays unclaimed, and the divergence is filed in the header comment of the lane's OWN new test file -- never appended to DEVIATIONS.md (user-owned; a worker does not bless a deviation) and never to a shared docs/design/audit/*.md, which would put five parallel lanes on one file for no benefit. Correctness against the pack beats claim count, and an unclaimed frame with a written reason is worth more than a claim propped up by a weak assertion. Second half, binding on every citing `it()` this wave: the frame-receipt tautology guard sits at FRAME_RECEIPT_OFFENDER_CEILING 0 and v12m-w4-j is widening its population to read citations out of it()-BODY comments as well as titles. Every new `it()` must therefore carry (a) the strict citation, (b) a backtick-quoted literal copied verbatim from that frame line, and (c) at least one `expect()` whose subject textually resolves to a readFileSync of a path OUTSIDE docs/design or to a render/DOM query. An it() whose every expect() subject is a frame read is a receipt stapled to itself.


## Amendment (wave 106): a claim a DOCUMENT makes about the tree is a citation and must resolve; the decision registry is inside the scan's population, and an audit finding is re-derived before it is scheduled

The user filed an INTEGRITY item into docs/mobile-campaign.md on 2026-08-19 evening: 'src/decisions-data/DEC-986.md (scribe wave 10/11) documents phone-CFP fixes that DO NOT EXIST in the tree'. Fixed (2) with querySelectorAll + forEach', and at that sha the Next handler still advanced with an unvalidated setStep while the visibility script still un-required with a singular querySelector. Both landed in wave 109; the receipts now read cfp-steps-script.tsx:77 `if (!control.checkValidity()) return control;` and form-render.tsx:314 `wrap.querySelectorAll`. DEC-976 already governs this class of defect for stylesheets and tests -- a citation must be followed by a verbatim backtick-quoted literal, and frame-citation.scan.test.ts enforces it -- but the decision registry itself, the document every other document defers to, is outside every scan's population. That is the same hole DEC-808 names as A DIRECTORY IS NOT A POPULATION, one level up. RULING (a): src/decisions-data/DEC-*.md joins the citation contract. Every `<repo-relative path>:<line>` a decision doc states must resolve to a file that exists and is at least that long, and every backtick-quoted literal that follows such a citation must appear verbatim in the cited file, enumerated by readdirSync and pinned by a vacuous-population tripwire. Unresolvable claims carry a shrink-only ratchet seeded at the measured truth, so a scribe can no longer write fiction into the one artefact nothing checks. RULING (b), the same rule read backwards: a finding recorded as OPEN in docs/design/audit/*.md is a claim about the tree with the same standing, and it is RE-DERIVED against main before a planner schedules it. Five of the open findings I read this wave were already built (speakers-v12.md §2 and §3, comms-drill-v12.md's three held items, review-admin-v12.md §3), and re-ploughing them is exactly the cost this rule exists to stop. So the desktop half of the campaign's own exit test is unreachable BY CONSTRUCTION: the ledger enumerates its population from the pack and has exclusion classes for template interpolations and explainer panels, but none for the third authority the mandate names. A ratchet whose ceiling no honest work can reach is not a gate — it is a permanent red with no owner, which is exactly the failure DEC-367 named for SHADOWED_CEILING. RULED: a desktop frame is excluded from the ledger's population when docs/design/DEVIATIONS.md defers it BY EXACT `docs/design/<file>.dc.html:<line>` CITATION inside §6. The exclusion is DERIVED from that file at test time, never hand-listed in the test (DEC-808), so adding one is a visible edit to the authority document under the user's own deferral section, not a quiet test edit. Four guards make it non-abusable: the pre-exclusion total (102) stays asserted so the population can never shrink by breaking the grammar; the excluded count is asserted EXACT so growth is loud; each excluded citation must resolve to a real frame LABEL line whose title appears verbatim in the bullet that cites it; and no excluded frame may be claimed by any test — an exclusion a claim has overtaken is stale and is deleted, never carried. The mirror image of the phone ledger's stale-floor companion (DEC-808 wave-85), applied to the population instead of the floor.

## Amendment (wave 113): A widened-population citation is repaired by re-pointing the coordinate to the line that carries the literal — never by softening or deleting the quote

43 unresolved rows against a ceiling of 42. 27 live in docs/design/audit/phone-tap-floor-links.md (owned by v12m-w8-f); the other 16 are spread over ten campaign authority documents and are almost all the same shape — the citation names a section's opening line, or a line that a later edit moved, while the backtick quote beside it is still true somewhere in the file. RULED: the repair is to grep the named file for the quoted text and rewrite the coordinate to the line that actually carries it. Deleting the quote to make the row pass is forbidden: the quote is the receipt and a citation without one is the very thing this scan exists to catch (DEC-967, 'a citation is not an assertion'). Where the quote is genuinely wrong about the file — the cited construct was deleted or renamed — the row is repaired by rewriting BOTH the coordinate and the quote to what the file now says, and the audit prose around it must be corrected in the same edit, never left contradicting its own citation. One row — `phone-tap-floor-links.md`'s `chq-reviewer-plan-row-action` entry, which cited line 478 of a `PlanList.tsx` only 336 lines long — had no target at all and belongs to w8-f's document, not to this wave; w8-f has since re-pointed that entry at `app/src/pages/review/ReviewerQueue.tsx:510` `className="chq-reviewer-plan-row-action"`, the file the control actually moved to.

## Amendment (wave 115): a receipt repair is a LEDGER edit — repointing a citation can silently drop a frame claim, because both contracts read the same syntax

`test/desktop-frame-ledger.scan.test.ts` is RED on main: claimed 70 of 102, below CLAIMED_FLOOR 71. Root cause located by diffing the unclaimed set across the wave-114 merge train: commit 944e4fff (task v12m-w3-ab, whose job was "receipt the 8 remaining desktop-frame citations") rewrote a frame comment on `app/src/pages/review/PlanEditor.render.test.tsx:2191` (a line number captured at wave-115 measurement time; the surrounding file has since moved again under later, unrelated edits, so this narrative describes history rather than the tree's current line numbering) — the rewrite repointed that frame comment away from `docs/design/Chautauqua Review.dc.html:788-831` and toward `:888-889`. Line 788 was the ONLY citation falling inside the extent of the desktop frame labelled "New plan · /review/plans/new" (`Chautauqua Review.dc.html:718`), so improving that citation's RECEIPT moved it out of that frame's CLAIM. Two instruments — frame-citation.scan (is this citation receipted?) and desktop-frame-ledger.scan (which frame does this citation claim?) — read the same `path:line` strings for different purposes, and nothing asserts that a receipt repair preserves the claim set. RULED: a lane that moves a frame citation owns the claim it was carrying. The repair restores a separately-receipted citation inside [718, next frame) rather than reverting w3-ab's better receipt, and CLAIMED_FLOOR is never lowered to match a regression — the ratchet caught this correctly and the merge train landed the batch anyway, which is the real failure.

## Amendment (wave 118): a Tier-0 probe finding is CLOSED only by a receipt the citation scan re-verifies — an unmarked-but-fixed finding is a lie that costs a planning wave

## Amendment (wave 123): a desktop frame receipt is an expect() that asserts APP content within the proximity window; the comment moves below the assertion, the citation never moves

All 15 remaining `DESKTOP_UNRECEIPTED_CLAIM_CEILING` offenders fail for one reason: "no expect( within 6 lines beneath". Every one already carries its backtick quote -- the claim is stated, the proof is just parked below a four-to-six-line explanatory comment. Two wrong fixes are available and both must be foreclosed: deleting or shortening the citation (DEC-967: never re-point, never delete a live claim to make a scan green) and adding an `expect()` that re-reads `docs/design/*.dc.html` (a pack-vs-pack tautology, which `tautological-assertion.scan`'s `FRAME_RECEIPT_OFFENDER_CEILING` holds at 0). RULED: the receipt is an `expect(` within `EXPECT_PROXIMITY_LINES` of the citation line that asserts PRODUCT bytes -- app/SSR source, rendered DOM, or a stylesheet -- for the quoted frame literal; when the prose in between is worth keeping it moves BELOW the assertion rather than being cut; and the citation's own `file:line` is left exactly as written.
