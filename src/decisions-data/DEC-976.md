# DEC-976: The claim receipt becomes executable over test files: a citation inside a frame's extent must carry the literal it cites and an assertion beneath it

DEC-967's wave-86 amendment ruled that a claim is three things in one place -- a strict citation landing inside the frame's computed extent, the cited line's literal quoted verbatim beside it, and an assertion beneath pinning what that literal declares -- and then left the rule enforced by nothing but each worker's care. DEC-976's wave-23 amendment already makes the literal-quoting half executable for NON-test files; the test-file half is the half that matters now, because twenty-five-plus claims are about to land from ten lanes and the ledger counts a citation whether or not anything is asserted under it. The repo has already paid for exactly this gap twice: DEC-967's wave-57 amendment banned the tautological test, and its wave-62 amendment banned the line-number pin. RULED: frame-citation.scan.test.ts gains the test-file direction, reusing its OWN existing STRICT_RE and flatten (never a second copy of either -- a second copy of a vocabulary is a trap with a delay fuse); the frame extent is COMPUTED the way the ledger computes it, from the width:390px line up to the next font-size:19px label line, never listed; and the violations are held by a two-sided ratchet ceiling that may only be lowered. The scan does not edit other lanes' tests to make itself green -- the ceiling exists so the measurement can land honest.

## Amendment (wave 91): a frame citation in PRODUCTION source carries the same receipt as one in a test file — the backtick-quoted literal, verbatim at the cited line

frame-citation.scan.test.ts fails three ways on main. Eighteen citations in production source (forms.css, review.css ×6, scorecard.css, settings.css ×3, submissions.css ×3, portal/edit.tsx ×2, portal.css.ts, portal/tasks/views.tsx) carry no quoted literal at all, so nothing checks that the rule beneath them still matches the frame line they name. Separately, 87 test-file citations are unreceipted against a ceiling of 14 — which is the real state of the campaign: test/phone-frame-ledger.scan.test.ts reads 53 of 53 CLAIMED on main, but a claim is a citation, and the receipt scan says most of those citations assert nothing. The ledger is therefore not the exit predicate the campaign can rest on; the receipt scan is. This wave closes all eighteen production citations and the SSR test files' share; the remainder is named as the wave-10 backlog rather than papered over by raising the ceiling.

## Amendment (wave 93): a receipt quotes a literal from the child line it came from — not the frame container, not a selector name, never elided

app/src/frame-citation.scan.test.ts measures 2 citations with no backtick quote and 19 whose quote is not verbatim at the cited line, extracted by running the scan's own findCitations/quoteAfter standalone (vitest truncates the arrays to `[ ...(19) ]`). They fall into exactly three shapes, and only the first is a wrong quote: (a) OFF-BY-A-FRAME — eleven quote real frame CSS but name the frame's `width:390px; height:844px` container line instead of the child line the declaration came from (agenda.css cites Agenda.dc.html:129 for text at :130; content.css cites Content.dc.html:254 for the anchor at :256; review.css cites Review.dc.html:413 three times for literals at :441 and :443; settings.css cites :347 for a literal at :349, :275-296 for `{{ g.label }}` at :288, and :393-441/552-575 for a padding run at :450; speakers.css cites :133/:138/:260 for literals at :130/:141/:257). Fix the NUMBER, not the quote. (b) A SELECTOR NAME IS NOT A RECEIPT — four settings.css citations quote `.chq-settings-rail-link-*`, `.chq-settings-panel h2`, `.chq-link-button`; a receipt is a literal the FRAME contains, so the quote is replaced with real frame text and the citation re-pointed at the line carrying it. (c) AN ELIDED QUOTE IS NOT VERBATIM — a quote containing a literal ellipsis (agenda.css's `background:#1B1D17; color:#F4F1E8; ... font-weight:600`, forms.css's `<div style="width:390px; height:844px; ...">`) can never match; quote a contiguous run instead. Also ruled: src/routes/portal/tasks/views.tsx quotes its own template literal `/portal/tasks/${assignment.id}/form` as the receipt for Public and Portal.dc.html:508 — code from the citing file is never a receipt for a frame.

## Amendment (wave 96): A receipt cites a file the surface actually loads — an exemption inside src/** may not name app/src/**

DEC-393's wave-95 amendment corrected a ruling whose own carrier citation was false (app/src/styles.css:1104-1116, a range holding .chq-error and a @keyframes header, corrected to :1134-1139). The same class of error has already recurred one layer out and is sitting on an unmerged branch: v12m-w13-d writes, inside src/routes/public/cfp.css.ts, `tap-floor-exempt: children floored by app/src/styles.css:1134-1139` — an SSR sheet naming the SPA admin bundle, which is never served on /submit/:slug. The correct carrier is in the same diff twelve lines above (src/views/theme.ts:625-630), so the file contradicts itself. An exemption is a receipt only if the rule it names is on the page. RULED: a tap-floor-exempt / overflow-exempt comment inside a src/** sheet may not cite an app/src/ path; the SSR carrier is src/views/theme.ts:347-366 (padding 0.5rem 1rem, inline-flex, align-items:center) plus :625-627 (min-height:44px at max-width:700px), all three legs of DESIGN-RULINGS.md:189. Machine-checked by a one-sided ratchet seeded at 0 — verified 0 on main today, so the tripwire is green now and goes red the moment w13-d lands, which is the point.
