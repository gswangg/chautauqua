# DEC-919: Every public surface narrows a list with ONE idiom: the same search box and the same pill bar

## Amendment (wave 7): a 390 head is reached by RE-LINING, never by removing a control

The Submissions 390 frame (docs/design/Chautauqua Submissions.dc.html:137) draws a two-band head — wordmark row, then title + count on one baseline — and no action buttons at all, while the app's .chq-submissions-head-actions carries Forms / Export CSV / New submission with no phone rule, so three buttons wrap raggedly into a head the frame draws clean. The tempting fix is display:none, and this codebase has already reached for it: submissions.css:808-822 hides the sort select, the track select, the divider, the column picker and every status pill but two. That is the wrong instrument in general — a 390 frame is the same product at a different width, and an organiser triaging on a phone who cannot sort has lost a capability the frame never asked anyone to remove. RULING: a head that the frame draws as two bands is reached by RE-LINING — the action cluster wraps to its own full-width row below the title, each control at the roomy 44px floor, ink where the frame puts it. display:none at phone width is legal in exactly one case: the control governs something that is not on the screen at all (the column picker over a table that has stacked into cards — which is why THAT hide stands and is recorded in DEVIATIONS.md). Everything else re-lines. Losing a control is a divergence from the frame, not a way of matching it.

## Amendment (wave 92): the Submissions 390 filterbar draws a pill strip only — the ColumnPicker hide stands and its contrary pin is reworked

submissions-phone-frames.test.ts:94 forbade a `display:none` on `.chq-submissions-columnpicker` that submissions.css sets, so a wave-8 fix and a pin contradicted. docs/design/Chautauqua Submissions.dc.html:148-151 draws the horizontally scrolling strip containing THREE status pills ("Needs triage", "Accepted", "All 47") and nothing else — no ColumnPicker, no Status caption, no divider. The wave-7 rule (hide is legal only for a control governing something not on screen) is satisfied exactly: once the table stacks into cards at 390 there are no columns to pick. The CSS is right; rewrote the test to assert what :148 draws — overflow-x:auto, flex-shrink:0 pills at min-height:44px/padding 0 13px — and to assert the three hidden tokens per this amendment.

## Amendment (wave 96): A phone rule may hide a NAVIGATION control, never a CAPABILITY — and a multi-select bar is mounted in its quiet state, never conditionally

Two live violations of one rule, both on surfaces the mandate names. (a) src/routes/public/cfp.css.ts:254 hides EVERY button[type="submit"] inside .chq-cfp-actions at step 1, which sweeps up Save draft — the only control that can serve the "Draft" the frame draws beside "Next: about you" at docs/design/Chautauqua Public and Portal.dc.html:1063. DEVIATIONS.md:238-253 files this as UNRESOLVED ERRATA, not a blessed deviation, explicitly saying it needs a cfp-phone-steps pin change nobody owned; v12m-w13-d touched the same file this wave and left it. Step-back (:258) and step-next (:259) are the legal shape — navigation with nothing to reach; a draft-save is a capability and 390 keeps desktop's capabilities. (b) DEVIATIONS.md §2 records a USER RULING 2026-08-16 that bulk-action bars are ALWAYS mounted — idle is a visible quiet state with geometry identical to the armed bar "so first selection never shifts the table" — and closes "the user ruled the no-shift behavior for all multi-select surfaces". Three surfaces implement it (submissions/BulkActionBar.tsx:54-73, contacts/ContactsTable.tsx:53-63, content/SessionList.tsx:182-201); TWO still mount on selection and shift the table on first tick: speakers/TaskView.tsx:429 (the v12 task page, Tier 0) and comms/ComposeWizard.tsx:926, whose own comment still cites DEC-350's wave-51 shape ("only when the selection is non-empty"). RULED: the user ruling supersedes DEC-350 wave-51 for every multi-select surface — both bars mount always, in .chq-bulkbar.chq-bulkbar-idle with one .chq-bulkbar-hint line, reusing the shell tokens already at app/src/styles.css:1279-1313 (never re-declared, DEC-613). And every remaining phone display:none over an interactive selector carries a /* phone-hidden: <reason> */ receipt naming one of the two legal cases (nothing left to navigate to; re-lined elsewhere with the replacement token cited file:line), machine-checked by a one-sided ratchet. 52 phone display:none rules exist on main; a hand-run interactive filter reads 7.

## Amendment (wave 97): /schedule's two page-level acts dock at 390, and the itinerary script's single-id lookup becomes a derived population

`Chautauqua Public and Portal.dc.html:864` ("My schedule · /schedule") draws a dock at `:885` with `Download .ics` (`flex:1`, olive, 48px) and `All sessions` (bordered, 48px, `padding:0 16px`), and a subtitle at `:868` reading `4 saved · 2 overlaps · no account needed`. Today the .ics CTA lives only in `ScheduleRail` (`agenda-rail.tsx:44`), which stacks below the column at 390, and the out-link is a header link reading `Browse all sessions ›`; the subtitle (`agenda.tsx:409`) drops the `· no account needed` clause the frame carries. The blocker is that `#chq-ics-link` is a SINGLE-ID contract driven by `getElementById` (`agenda-itinerary-script.tsx:45-46`) and minted at four render sites, so a dock copy would put a duplicate id on one page. RULED: the script drives `document.querySelectorAll('[data-chq-ics-link]')` / `[data-chq-ics-count]` instead — a derived population, the DEC-808 idiom, and strictly safer than an id that was only ever unique by luck — and every existing site gains the attribute beside its id. Only then does the phone dock render. This is the 390-keeps-desktop's-capabilities half of DEC-919: the rail is desktop chrome, and a capability that only exists inside desktop chrome is removed at 390.

## Amendment (wave 98): a phone-only SHORTER label is one control with two spans, never a second control and never a JS width branch

Several v12 phone frames draw a shorter label than the desktop frame for the SAME control, because the phone head band already carries the context the desktop label repeats. Contacts.dc.html:537 draws `Merge them` where the app's desktop primary reads `Merge into {first} {last}`; Contacts.dc.html:524 draws `‹ Duplicates` where the app renders `‹ Contacts · Duplicates`; Contacts.dc.html:526 pushes the identity into the head subtitle (`1 of 6 pairs · Marcus Okafor`), which is exactly why the footer can drop it. DEC-919's 're-line, never remove' governs the control; this amendment governs its COPY. The legal implementation is ONE element containing two spans, one hidden per width inside the sheet's terminal max-width block — so there is one DOM target, one handler, one accessible name computed per width, and no second Save/Merge path (DEC-547). Illegal: rendering two buttons and hiding one (two targets, ambiguous role queries), or branching on a JS width probe (DEC-385 single-direction — phone work lives in max-width blocks). Controls the frame's phone footer does NOT draw but the desktop does (e.g. `Swap which is kept`) re-line above the dock rather than vanishing.

## Amendment (wave 99): A phone frame's PLACEMENT and its GEOMETRY are two separate claims; a settings section action satisfies both with a phone-only sibling, never a moved DOM node

Chautauqua Settings.dc.html draws the SAME four controls twice: on desktop (:822 `Add a track`, :841 `Add a room`, :984 `Invite someone`, :1145 `New token`) they are plain 13px links inside the section head — exactly what the app ships — and on the 390 drills (:367, :382, :568, :426) they are full-width controls placed BELOW their list, dashed 44px for the two Add actions and filled olive 46px for the two primaries. No CSS can move a node out of `.chq-settings-section-head` and under the sibling `<ul>`, so waves have read this as an architectural gap and deferred it five times. RULED: the capability renders TWICE in the DOM and exactly ONCE on screen — the existing head action gains `display:none` inside the sheet's terminal `@media (max-width:700px)` block, and a phone-only sibling carrying `.chq-settings-phone-action` renders immediately after the list with the frame's own geometry and is `display:none` at desktop. This is the precedent already living in this very panel (`.chq-settings-tracks-rooms-phone-caption`), it keeps DEC-919's own rule (the capability is present at both widths, never removed, never off-screen-but-mounted), it keeps the accessible name unique at each width because the hidden twin leaves the a11y tree, and desktop bytes are untouched. It also closes the two receipts that have been asserting only the frame's own bytes under the label "(gap: read-drilled view does not yet render it)".

## Amendment (wave 100): the desktop half gets the control-label conformance probe the phone half already had, and its sample-data exclusion is a WRITTEN, self-checking predicate

The phone half of this campaign was closed by enumerating every `min-height:4[46]px` control label across all 53 phone frames — 178 controls, 39 unmatched, exactly one real gap after grepping. Nobody has ever run the equivalent over the 108 desktop frames. Measured this wave on 108cc8c1: 122 unique control-shaped labels and 139 unique tertiary-link labels in non-390 frames, of which 16 and 40 respectively appear nowhere in app/src or src. Most are sample data ('Import 214 rows', 'Remind Priya', 'Show all 9') — but real gaps are inside: Settings' 'Invite someone else' and 'Copy the password', the portal-resource 'Add it', the CFP not-yet-open page's 'Browse last year's sessions ›', and the seven B10 edit-view back links. w2-f's desktop-frame ledger answers 'is this frame CLAIMED by a test'; this answers the different and harder question 'does every control this frame DRAWS exist at all'. The exclusion predicate is the load-bearing part and must be written and self-checking (a label is sample data only when it contains a digit run or a seeded proper noun that the pack's own data block defines), asserted against the pack so it cannot quietly grow; every excluded row is NAMED with its reason, never silently dropped, and the residue is a two-sided ratchet.
