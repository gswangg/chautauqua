# DEC-919: Every public surface narrows a list with ONE idiom: the same search box and the same pill bar

## Amendment (wave 7): a 390 head is reached by RE-LINING, never by removing a control

The Submissions 390 frame (docs/design/Chautauqua Submissions.dc.html:137) draws a two-band head — wordmark row, then title + count on one baseline — and no action buttons at all, while the app's .chq-submissions-head-actions carries Forms / Export CSV / New submission with no phone rule, so three buttons wrap raggedly into a head the frame draws clean. The tempting fix is display:none, and this codebase has already reached for it: submissions.css:808-822 hides the sort select, the track select, the divider, the column picker and every status pill but two. That is the wrong instrument in general — a 390 frame is the same product at a different width, and an organiser triaging on a phone who cannot sort has lost a capability the frame never asked anyone to remove. RULING: a head that the frame draws as two bands is reached by RE-LINING — the action cluster wraps to its own full-width row below the title, each control at the roomy 44px floor, ink where the frame puts it. display:none at phone width is legal in exactly one case: the control governs something that is not on the screen at all (the column picker over a table that has stacked into cards — which is why THAT hide stands and is recorded in DEVIATIONS.md). Everything else re-lines. Losing a control is a divergence from the frame, not a way of matching it.

## Amendment (wave 92): the Submissions 390 filterbar draws a pill strip only — the ColumnPicker hide stands and its contrary pin is reworked

submissions-phone-frames.test.ts:94 forbade a `display:none` on `.chq-submissions-columnpicker` that submissions.css sets, so a wave-8 fix and a pin contradicted. docs/design/Chautauqua Submissions.dc.html:148-151 draws the horizontally scrolling strip containing THREE status pills ("Needs triage", "Accepted", "All 47") and nothing else — no ColumnPicker, no Status caption, no divider. The wave-7 rule (hide is legal only for a control governing something not on screen) is satisfied exactly: once the table stacks into cards at 390 there are no columns to pick. The CSS is right; rewrote the test to assert what :148 draws — overflow-x:auto, flex-shrink:0 pills at min-height:44px/padding 0 13px — and to assert the three hidden tokens per this amendment.

## Amendment (wave 96): A phone rule may hide a NAVIGATION control, never a CAPABILITY — and a multi-select bar is mounted in its quiet state, never conditionally

Two live violations of one rule, both on surfaces the mandate names. (a) src/routes/public/cfp.css.ts:254 hides EVERY button[type="submit"] inside .chq-cfp-actions at step 1, which sweeps up Save draft — the only control that can serve the "Draft" the frame draws beside "Next: about you" at docs/design/Chautauqua Public and Portal.dc.html:1063. DEVIATIONS.md:238-253 files this as UNRESOLVED ERRATA, not a blessed deviation, explicitly saying it needs a cfp-phone-steps pin change nobody owned; v12m-w13-d touched the same file this wave and left it. Step-back (:258) and step-next (:259) are the legal shape — navigation with nothing to reach; a draft-save is a capability and 390 keeps desktop's capabilities. (b) DEVIATIONS.md §2 records a USER RULING 2026-08-16 that bulk-action bars are ALWAYS mounted — idle is a visible quiet state with geometry identical to the armed bar "so first selection never shifts the table" — and closes "the user ruled the no-shift behavior for all multi-select surfaces". Three surfaces implement it (submissions/BulkActionBar.tsx:54-73, contacts/ContactsTable.tsx:53-63, content/SessionList.tsx:182-201); TWO still mount on selection and shift the table on first tick: speakers/TaskView.tsx:429 (the v12 task page, Tier 0) and comms/ComposeWizard.tsx:926, whose own comment still cites DEC-350's wave-51 shape ("only when the selection is non-empty"). RULED: the user ruling supersedes DEC-350 wave-51 for every multi-select surface — both bars mount always, in .chq-bulkbar.chq-bulkbar-idle with one .chq-bulkbar-hint line, reusing the shell tokens already at app/src/styles.css:1279-1313 (never re-declared, DEC-613). And every remaining phone display:none over an interactive selector carries a /* phone-hidden: <reason> */ receipt naming one of the two legal cases (nothing left to navigate to; re-lined elsewhere with the replacement token cited file:line), machine-checked by a one-sided ratchet. 52 phone display:none rules exist on main; a hand-run interactive filter reads 7.
