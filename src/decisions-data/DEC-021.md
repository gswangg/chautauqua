# DEC-021: Agenda API and drag-drop UI contract; slot writes bump ics_sequence

The public agenda API and the admin drag-drop UI share one contract: any write to a session's schedule slot bumps that session's `ics_sequence` so downstream calendar subscribers see the change as a real update rather than a silent overwrite.

## Amendment (wave 34): a clamp is an interval operation, not two independent bounds

app/src/pages/agenda/DayGrid.tsx clamps a break's start and end independently against the day window, so a break whose extent does not intersect [dayStartMin, dayEndMin] produces an inverted or negative CSS grid-row. Verified arithmetic at the app's own pinned window (540/1080/15): a 07:00-08:00 break yields `grid-row: 2 / -2` (a negative line index spans nearly the whole day) and a 19:00-20:00 break yields `42 / 38` (end<start, so the spec swaps them and paints a phantom band over unrelated hours). It is directly reachable — src/routes/api/breaks.ts accepts startMin 0..1439 with only a past-midnight cross-check. Both the code's own comment ("clamped to the visible rows so it paints inside the grid") and BreaksPanel's user-facing hint ("the grid shows it greyed rather than dropping it") are false for the fully-outside case, and the existing break-band-flagged test is a CSS-text assertion that passes regardless. RULED: a break that intersects the window keeps today's flagged-and-clamped band; a break with no intersection gets no band at all — it is surfaced as flagged but never given a fabricated row, and the panel's copy must be true of both cases. The interval arithmetic lives once, in gridMath.ts, where it is unit-testable.

## Amendment (wave 36): the Agenda frame's break-hint caption is SUPERSEDED by DEC-021 wave-34, excluded by citation — never by a ceiling raise

`docs/design/Chautauqua Agenda.dc.html:244` draws "A break outside the day's window is kept but flagged — the grid shows it greyed rather than dropping it." DEC-021 wave-34 (commit 487b7fb98) ruled the opposite for the fully-outside case — no band at all — and w34-b correctly rewrote `app/src/pages/agenda/BreaksPanel.tsx:463-464` to be true of both cases. The caption is now unmatched by any app source, and `test/frame-caption-ledger.scan.test.ts` is red. A frame's prose that a later ruling deliberately superseded is a recorded divergence (DEC-380/582), not debt: it leaves the population through the ledger's own SUPERSEDED exclusion table with the ruling sentence quoted verbatim. `FRAME_CAPTION_UNMATCHED_CEILING` stays 0 — the ledger's own error text already forbids a worker raising it mid-lane, and a raise would memorialize the gap instead of closing it.


## Amendment (wave 38): the phone agenda folds breaks through the SAME clampBreakToWindow the desktop grid uses, and a run list never emits backwards time — 'kept but flagged' is a fact about the break RECORD, not a licence to paint outside the drawn day

Verified by reading both twins at main. app/src/pages/agenda/DayGrid.tsx computes `const flagged = brk.startMin < dayStartMin || brkEndMin > dayEndMin;` and then calls `clampBreakToWindow` (gridMath.ts:45, DEC-021 wave-34), which treats [startMin,endMin) as ONE interval and returns null when it does not intersect the day window. app/src/pages/agenda/phoneSlots.ts did neither at the time: it folded `.filter((b) => b.day === day)` straight into the run sweep with no clamp, so a 06:40-07:20 break on an 08:00-18:00 day emitted a `blocked` row ABOVE the day start where desktop draws nothing; and because the cursor advances by `Math.max(cursor, run.endMin)` with no overlap handling, a 12:00-13:00 break overlapping a 12:30-13:30 session emitted two rows whose times ran backwards and swallowed the free gap between them (v12m-w38-i is actively rewriting phoneSlots.ts; both citations above are the drift-proof bare-path shape so they survive that rewrite). That is a desktop/phone divergence inside a campaign whose governing principle is that the phone reflows the desktop and never competes with it, and whose desktop half is frozen — so the phone side is the side that moves. DESIGN-RULINGS' Breaks-editor line ('a break outside the day's window is kept but flagged rather than dropped') is about the break RECORD and its row in BreaksPanel, which is unaffected: a surface that only draws 09:00-18:00 cannot paint 19:00-20:00 anywhere truthful, and desktop already resolves it this way. RULED: phoneSlots imports and calls clampBreakToWindow (DEC-613: never a second predicate) so a non-intersecting break contributes no run and a partially-overlapping one is clipped to the window on both surfaces; runs are merged so the emitted list is strictly non-decreasing in time; and the two code comments that assert the old behaviour (DayGrid's 'clamped to the visible rows so it paints inside the grid' and BreaksPanel's 'the grid shows it greyed rather than dropping it') are corrected in the same commit, since a comment asserting behaviour the code forbids is the fossil shape DEC-903 rules against.
