# DEC-650: The CFP builder's primary content is the QUESTION LIST, and a condition renders the referenced field's LABEL — an id in the UI is an internal handle leaking

## Amendment (wave 130): A modal's primary names the object once, never the branch

`Portal resource · add` (Chautauqua Settings.dc.html:1444-1470) draws ONE primary, `Add it` (:1469), for a dialog whose Kind control switches what is being added. app/src/pages/settings/ResourcesPanel.tsx:327-329 instead swaps the primary's own words (`Add wiki page`/`Upload file`), so the button relabels under the pointer as a radio changes and one act carries two verbs — the exact re-invention DEC-650 ruled against when FieldModal and the remind dialogs were made to reuse one vocabulary. The frame also names the field `Name` with the hint "What speakers see in the list" (:1455-1457) where the app writes `Title` and a placeholder that merely repeats the label. The Kind chips are NOT part of this: the frame draws `File`/`Link` and this product's second kind is a wiki page with stored markdown, which DEC-380's wave-130 amendment records as a deviation rather than letting a lane invent a link kind to match a drawing.
