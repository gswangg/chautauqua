## Amendment (wave 130): A modal's primary names the object once, never the branch

`Portal resource · add` (Chautauqua Settings.dc.html:1444-1470) draws ONE primary, `Add it` (:1469), for a dialog whose Kind control switches what is being added. app/src/pages/settings/ResourcesPanel.tsx:327-329 instead swaps the primary's own words (`Add wiki page`/`Upload file`), so the button relabels under the pointer as a radio changes and one act carries two verbs — the exact re-invention DEC-650 ruled against when FieldModal and the remind dialogs were made to reuse one vocabulary. The Kind chips are NOT part of this: the frame draws `File`/`Link` and this product's second kind is a wiki page with stored markdown, which DEC-380's wave-130 amendment records as a deviation rather than letting a lane invent a link kind to match a drawing.

## Amendment (wave 131): A desktop frame claim asserts what the frame DRAWS, so the resource modal's claim names its single Add it primary — the claim was stale, the code is right

`test/desktop-frames-settings-dialogs.test.ts:148` fails asserting that `ResourcesPanel.tsx` contains `{addingKind === 'wiki' ? 'Add wiki page' : 'Upload file'}`. That expression is gone because v12m-w5-m landed DEC-650's wave-130 amendment this wave: Settings.dc.html:1469 draws ONE primary, `Add it`, for both resource kinds, and the two-verb pair was the divergence. So the failure is a stale CLAIM, not a regression — the frame-claim ledger is asserting the shape the pack does not draw. The correction is to re-derive the claim from the frame: the dialog's claim must name the one primary the pack prints and the `Name` field label with its hint, anchored on CONTENT rather than a line number. The trap to avoid is the one `tautological-assertion.scan` exists to catch — a receipt whose every `expect()` reads `docs/design` is a pack-vs-pack tautology that proves nothing about the app; at least one side of every assertion here must be the app's own source.
