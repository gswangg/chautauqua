# DEC-986: The phone CFP wizard validates before it advances, and conditional visibility un-requires every control in a group

Two independent defects made the phone CFP silently unsubmittable, on the product's primary public conversion path. (1) cfp.css.ts:272 hides `.chq-cfp-step-talk` with display:none on step 2 while its controls keep `required`; cfp-steps-script.tsx's Next handler ran no validation (type=button by design) and "Submit this talk" carried no formnovalidate, so a speaker who advances with an empty required talk field taps Submit and the browser aborts on a non-focusable invalid control — no message, no server hit, no recovery. (2) src/views/form-render.tsx:278 called `wrap.querySelector` (singular) to un-require a hidden field, but Format and Audience render as N radios each carrying `required` and the same data-field-id, so radios 2..N stayed required inside a display:none wrap — the same dead end by a different route.

RULING: (1) must be closed by calling reportValidity() on the step-1 section in the Next handler and refusing to advance when it fails — that converts a silent dead end into the browser's ordinary validation stop and leaves step 2's Submit safe because step 1 was already validated; (2) must be closed with querySelectorAll + forEach in place of the singular querySelector. Neither is a frame change; both are what the frame's two-step flow means.

## Amendment (wave 93): a control that is display:none must not be constraint-validatable

Verified on main 32d33500 (line since drifted to :272 as of 114b4d2c; DEC-976 wave-106 amendment corrected the citation, the ruling itself is unchanged): cfp.css.ts:272 `[data-chq-cfp-step="2"] .chq-cfp-step-talk { display: none; }` hides step 1 while its controls keep `required` (Track radios carry `required` on all N, submit-views.tsx:202-204, inside the .chq-cfp-step-talk section at :587); submit-views.tsx:658's "Submit this talk" has no `formnovalidate` (only Save draft at :665 does); cfp-steps-script.tsx's Next handler calls setStep('2') with no validation. The browser therefore aborts submission on a non-focusable invalid control with no message, no focus and no server hit — a silent dead end on the primary public conversion path. jsdom never runs constraint validation, so the entire suite is structurally blind to this class. RULING: (1) a step transition must un-require every control it is about to hide and restore the original `required` when the step is shown again — the toggle is part of hiding, not a separate concern; (2) "Next" must run checkValidity() over the outgoing step's controls and reportValidity() on the first invalid one BEFORE advancing, so the message lands on a visible field; (3) the guard is authored in the step script, not by adding `formnovalidate` to the real Submit — suppressing validation on the primary action would let an empty required talk field reach the server. Find defects of this class by reading which elements can be display:none while required, never by adding a test.


## Amendment (wave 108): landed — the ruling is implemented in the tree, with receipts

Verified on main 28f00481, before this task's change: cfp-steps-script.tsx's Next handler advanced with a bare setStep('2') (line 33 at that revision) and form-render.tsx:278 un-required with a singular `wrap.querySelector`, so a Format/Audience group's radios 2..N stayed required inside a display:none wrap. DEC-986 ruled all of this fifteen waves ago; the branches its own doc named (v12m-w10-h, v12m-w11-a) never merged. This task (v12m-w4-n) lands the ruling directly:

Clause (1) — un-require what a transition hides, restore it when shown again, original value stashed on the element (never a JS-side map): `src/routes/public/cfp-steps-script.tsx`'s `applyRequiredState(section, visible)` function stashes each control's original `required` on a `data-chq-cfp-required-orig` attribute the first time it is touched, then sets `el.required = visible && orig` on every element `section.querySelectorAll('[required], [data-chq-cfp-required-orig]')` returns; `setStep(step)` calls `applyRequiredState(talkSection, step === '1')` and `applyRequiredState(youSection, step === '2')` on every transition.

Clause (2) — checkValidity()/reportValidity() over the outgoing step, refuse to advance on failure: `cfp-steps-script.tsx`'s `validateSection(section)` function runs `el.checkValidity()` over each control in the outgoing section and calls `el.reportValidity()` on the first failure, returning `false`; the Next click handler reads `if (!validateSection(talkSection)) { return; } setStep('2');`, so a failed validation never reaches `setStep`.

Clause (3) — never `formnovalidate` the real Submit: `src/routes/public/submit-views.tsx`'s "Submit this talk" button (`:659` `Submit this talk`) carries no `formnovalidate` attribute; only Save draft (`:665` `formnovalidate`) does, unchanged from wave 93.

src/views/form-render.tsx:278 now reads `var inputs = wrap.querySelectorAll('[data-field-id="' + r.fieldId + '"]');` followed by `inputs.forEach(function(input){ input.required = visible && input.dataset.required === 'true'; });` — every member of a same-fieldId radio group is un-required together, not just the first DOM match.

Tests: `test/cfp-phone-steps.test.ts`'s "DEC-986: validates before advancing, un-requires what it hides" block asserts the emitted script text (jsdom runs no constraint validation, so this is source-level, mirroring the suite's existing style); `test/form-render-rules.test.ts`'s "apply() un-requires every member of a hidden radio group, not just the first (DEC-986)" block exercises a synthetic 3-radio fixture through the actual emitted IIFE and asserts all three, not just the first, flip `required`.
