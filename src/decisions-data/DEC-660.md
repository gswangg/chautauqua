# DEC-660: Amendment (wave 147): the compose-time unresolvable-merge-field warning is built, not deferred

Three hand-maintained copies exist: MERGE_FIELDS (src/mail/render.ts:5, seven fields), COMPOSE_MERGE_FIELDS (app/src/pages/comms/types.ts:6, five), BULK_EMAIL_MERGE_FIELDS (app/src/pages/contacts/types.ts:90, three) -- plus BULK_EMAIL_RECIPIENT_CAP=100 mirroring MAX_COMPOSE_RECIPIENTS=100. Each set encodes a real server fact: which vars that send path actually supplies, so a chip offering anything else is a control whose only outcome is a preflight rejection (the DEC-608 rule). Hand-copied vocabularies drift, and these are the vocabulary that decides whether an email to a real speaker renders. DEC-002 made pure core node/cf-free precisely so a browser bundle could share it; exactly ONE app-side module crosses the boundary so the blast radius on the bundle budget stays measurable.

## Amendment (wave 142): session_time joins the compose merge-field vocabulary, omitted rather than blank for an unscheduled recipient

`Chautauqua Comms.dc.html:769` — the 'Compose · send blocked' warning — is the second and last unmatched caption at the settled ceiling, and the only one whose referent the app can honestly build. It turns entirely on a `{session_time}` merge field the vocabulary does not carry, which is why the ledger's own note parked it as a genuine gap. The data is already present: RenderTarget.scheduled (DEC-912) carries the FACT of scheduling through the same read the recipient table renders its Slot column from, so the slot's event-local start is one field further along the same query, not a new subsystem. RULED: session_time joins MERGE_FIELDS, MERGE_FIELD_SAMPLES and COMPOSE_MERGE_FIELDS only — not BULK_EMAIL_MERGE_FIELDS (bulk email is contact-scoped, never submission-scoped) and not BLOCK_MERGE_FIELDS (it is one line, so a subject may carry it). buildMergeVars sets the key ONLY when the recipient has a slot, following the `feedback` precedent (DEC-682) and never a blank string, so DEC-019's atomic preflight blocks the send and the existing missing-fields banner names the unscheduled recipients — which is exactly the screen the frame draws. The value is formatted through the same event-local clock helper the Slot column already uses; a second date formatter here would be DEC-613's delay-fused duplicate vocabulary. The frame's warning SENTENCE is a follow-on once the field exists; a lane that adds a vocabulary and its copy in one commit cannot be reviewed for either.

Chautauqua Comms.dc.html:769 draws `Your body uses {session_time}, and three of these speakers have no slot yet. They would receive the literal text "{session_time}".` This row survived four waves of caption residue on a blocker that no longer exists: v12m-w15-ee and w18-b both recorded "no `session_time` merge field exists anywhere in app/src or src", and v12m-w21-c's commit corrects them on the record — DEC-660 wave-142 landed the field, and its own text calls the compose-time warning a follow-on. This is the honest closure of a row that was twice recorded as blocked on a fact that was false.

## Amendment (wave 148): the unresolvable-merge-field warning is PRE-EMPTIVE and ADVISORY on the compose step, and its consequence clause states the refusal the code performs — not the frame's literal-text claim

The wave-147 amendment ruled this warning 'built, not deferred' and nothing landed. Two facts settle HOW. (1) `Chautauqua Comms.dc.html:769` promises unscheduled recipients 'would receive the literal text "{session_time}"'. That is false in this app: `src/mail/render.ts`'s `renderTemplate` THROWS `MergeFieldError` on a missing var, and `src/routes/comms/preview.ts:66` turns that into a whole-batch `ApiError` — the organiser cannot even reach the check step, let alone send literal text. A frame's prose asserting a side effect is graded against BEHAVIOUR, not screen-presence. So the frame's heading half ('One merge field will not resolve for N of the M') is built verbatim, and the consequence clause names the real outcome — those recipients are refused, per DEC-793's existing named-lines banner and its partial-send path. (2) The band is rendered PRE-EMPTIVELY on the compose/template step, computed entirely from state the wizard already holds (`selectedNoSlotCount`, already live at `ComposeWizard.tsx:1118`, plus whether the subject/body text itself contains the merge token) — no new server round-trip, and the refusal semantics of `/compose/preview` and `/compose/send` are UNCHANGED. This also corrects a latent inaccuracy in the existing step-1 note, which says the no-slot recipients 'can still be emailed' without qualifying that a `{session_time}` body makes that untrue. The caption row is therefore disposed SUPERSEDED, not COMPOSED.
