## Amendment (wave 153): A disabled control's tooltip is user-facing copy and is bound by the impersonation vocabulary

DESIGN-RULINGS item 22 rules that the portal-preview affordance "must say it is a read-only impersonation of the portal, or it reads as a login-as", and the ruling's own wording for the control is *Open as a speaker* — never "sign in as". the former PortalSettingsPanel code (removed by multi-portal decision 74) obeys it. the former general /portal/preview page (deleted by multi-portal decision 74) does not: the disabled Download control carries title="Preview only — sign in as this speaker to download", which contradicts the ruling, contradicts DEC-747's own frame reasoning for sanctioning that one disabled control, and contradicts the sentence rendered 46 lines below it on the same page ("To see a real speaker's portal you would have to be them — this preview deliberately cannot"). There is no sign-in-as path anywhere in this product, so the tooltip instructs an organiser to perform something impossible. RULED: a tooltip is copy. The vocabulary rule reaches title/aria-label/placeholder exactly as it reaches visible text, and it gets a sentinel rather than a one-line edit, because a ruling with no gate drifts back. The sentinel must be boundary-aware — "They can sign in as soon as you do this" (PeopleRolesPanel) and "signed in as {email}" (a true statement about the viewer's OWN session) are legal and each gets a negative control.
