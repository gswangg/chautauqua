# DEC-621: The Comms phone landing's draft card renders from a real persisted draft: a frame element wired to a literal null is dead code, not an implementation

docs/design/audit/comms-v12.md finding 1 asked the planner to choose, and the tree makes the choice urgent: app/src/pages/Comms.tsx:303 renders <PhoneDraftCard draft={null} /> unconditionally, so the CENTRE element of the Comms 390 frame (Chautauqua Comms.dc.html:188-193 -- eyebrow, subject, recipient count, "Read the draft") has never rendered once in the shipped app, while PhoneDraftCard.tsx and its unit test both pass against a fabricated prop. That is the DEC-967 wave-57 tautology in component form: a test with a population the product never produces. The alternative -- deleting the card -- loses the frame, and the frame is the authority. RULED: the draft becomes real from the state the wizard already holds. One single-purpose module owns a per-event localStorage record carrying exactly what the frame draws (template name, resolved subject, recipient count, updatedAt); ComposeWizard writes it on step ADVANCE (never on keystroke, so this is not the silent pre-fill DEC-967's wave-54 amendment bans) and clears it on a successful send; Comms.tsx reads it on mount and renders the card from it, rendering nothing when absent. Nothing is fabricated: the frame's "reviewer feedback merged" provenance clause has no source in the app and is NOT invented -- the card renders the recipient count alone. A malformed record throws rather than degrading to a default (fail loudly). DEC-621's chooser deletion is unchanged and is not reopened.
