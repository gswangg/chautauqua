# DEC-029: The portal's last two phone frames: Resources opens rather than downloads, and a rejected co-presenter is told what survived

Two frames wave 4 held for wave 5 on purpose, and both turn on a word the app currently gets wrong. (1) Chautauqua Public and Portal.dc.html:1561 ("Portal · Resources", subtitled "What the organiser wrote, for everyone") draws each row's control as "Open" at 44px; ResourcesPage (src/routes/portal/tasks/views.tsx:510) renders "Download" -- and the label is not cosmetic, because the same route serves wiki resources rendered inline and file resources streamed as attachments, so "Download" is a lie on half the population. RULED: the phone row's control reads Open, the page carries the frame's subtitle ("The same for every speaker · nothing here is about your session") which is the sentence that keeps a speaker from reading a shared resource as personal, and the footer docks the frame's one line. (2) :1304 ("Portal · co-presenter rejected") draws the refusal the server already returns (CO_PRESENTER_DUPLICATE_MESSAGE, src/server/repo/portal-edit.ts:486) as a three-part disclosure: a bordered callout headed "Nobody was added" that names who is already on the session AND states that everything typed is still below, the email field marked at its own left edge, and the field-level sentence beneath it. RULED: that is the shape -- a refusal that does not say what survived reads as data loss, and re-typing four fields on a phone is the cost of guessing wrong. DEC-656's recorded-not-published rule is untouched; nothing about visibility, and no server text, changes.

## Amendment (wave 108): adding a co-presenter is a SECOND SUBMIT of the edit form, not a second form — the speaker's unsaved edits ride along on both paths and are never persisted by the add

src/routes/portal/edit.tsx renders two forms on one page; submitting the participants form discards every unsaved title/abstract/track edit, because the refusal path re-renders answers={data.answers} from the database and the success path redirects. DESIGN-RULINGS.md's own co-presenter section makes the promise the page then breaks — the duplicate banner reads 'Everything you typed is still below', which is a claim about the composed page, not about one section. The narrow fix is available with no new JavaScript: the file already associates a control with a form it does not contain (Save changes carries form='chq-portal-edit-form'), none of the four co-presenter controls carries required, so nothing new can block the page's primary Save, and the add becomes a formaction submit of the one form. The handler then echoes the posted answers on both paths and persists none of them — Save changes stays the only writer, and the success redirect, which is what loses the draft on the common path, becomes a direct render.

## Amendment (wave 114)

Verified on main `ee0a8c44`: `src/routes/portal/edit.tsx`'s POST /submissions/:id/participants re-reads the in-progress answers from the request body with `extractAnswers(data.fields, body, data.answers)` (the wave-108 amendment that closed the mandate's "Add co-presenter discards unsaved edits" item), but then passes `selectedTrackIds={data.selectedTrackIds}` — read from the DATABASE — to both the 400 refusal render (:631) and the 200 success render (:659). Because "Add co-presenter" is a second submit of #chq-portal-edit-form, the body already carries the speaker's `trackIds` checkboxes; a speaker who re-picks their tracks and then adds a co-presenter watches that choice silently revert. RULED: the participants route echoes the typed track selection with the SAME one owner the edit POST uses — `tracksEditable ? extractTrackIds(body) : data.selectedTrackIds` (edit.tsx:524's exact expression, DEC-598's single reader, never a second parser, DEC-613) — on both render paths. The `tracksEditable` guard is load-bearing: when track editing is closed the form renders no checkboxes at all, so the body carries none and the DB value is the only truth. Save changes stays the only thing that PERSISTS a track edit; this route only stops it lying about what the organiser typed.
