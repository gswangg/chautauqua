# DEC-996: The admin-390 tap-floor roster classifies every sighting as EXEMPT or CANDIDATE; a bare count over a mixed population is not a measurement

ADMIN_MOBILE_INTERACTIVE_OFFENDERS_CEILING = 77 is the campaign's Tier 2 44px-floor number, and docs/design/audit/admin-mobile-tap-floor-390-v12.md — the machine-written roster scripts/render-sweep.ts emits — lists all 77 as undifferentiated lines. Reading it on 32436e11b: ~74 are `input.chq-check*` sightings whose operable target is the documented `.chq-check-hit` label wrapper (app/src/styles.css's own tap-floor-exempt comment), 2 are `a.chq-wordmark` on /dev/mailbox (DEC-382 operator chrome, exempted in src/views/theme.ts), and 1 is `a.chq-overview-link-inline` (DEC-393 wave-106's inline-in-prose ruling, pinned by overview-phone-floor.test.ts). Every one of the 77 is already adjudicated somewhere in the tree, and the roster says none of it — so a reviewer reads 77 open tap-floor defects where the honest number is 0, and a genuinely NEW offender would land in that same undifferentiated list and be invisible. This is DEC-903's own ruling generalised: a classification row is re-classified in place so the roster's arithmetic and its measured total both stay honest. RULED: the pure formatter gains a classification argument — an exempt-token set supplied by its caller, never read from disk inside the formatter, so purity holds — labels each line EXEMPT (naming the receipt that reaches it) or CANDIDATE, and prints `Measured total: N (exempt: X, candidate defects: Y)`. The exempt set is DERIVED by the scan test from the tree's own `tap-floor-exempt` / `chq-check-hit` receipts, never hand-listed, and a vacuity control proves an unreceipted selector classifies CANDIDATE.

## Amendment (wave 35): no interactive element on a 390 route may be unreachable by the roster classifier — a bare tag carries its own class token, or the sweep prints its nearest classed ancestor

`classifyAdminMobileOffender` (scripts/render-sweep-lib.ts) resolves EXEMPT by matching class tokens taken from the offender's own selector string; "a selector with no class token ... classifies CANDIDATE". docs/design/audit/public-390-interactive-offenders-v12.md, machine-written by the live gate, therefore reports 22 CANDIDATE rows of which 20 are classless by construction: 6 bare `<a>` and 14 bare `<input type=radio|checkbox>`. Every one of those 14 inputs is wrapped in a `<label class="chq-cfp-option">` that already carries `min-height: 46px` (src/routes/public/cfp.css.ts and src/routes/portal/portal.css.ts) — the label IS the tap target and the roster cannot see it. Meanwhile `SSR_CLASSLESS_ANCHOR_CEILING` reads 0 over the same anchors, because that scan keys a classless `<a>` on its nearest enclosing `chq-` token while the live sweep keys it on the element's own class: two instruments answering the same question with different keys, one green and one red. RULED: the element's identity is the classifier's input, so it must exist. A bare interactive tag on a 390-graded route either (a) carries its own `chq-` class token whose rule holds the floor or the receipt, or (b) is printed by the sweep with its nearest classed ancestor in the selector (`label.chq-cfp-option > input`), which lets the EXISTING pure classifier reach a wrapper receipt with no second predicate (DEC-613). Preference order is (a) for product code the campaign owns and (b) for shapes where the floor genuinely belongs to the wrapper. A ceiling of 0 over a population that cannot express half its own offenders is the campaign's costliest illusion.


## Amendment (wave 38): when a control gains its own class token, every instrument keyed on its old ancestor-scoped selector is re-pointed in the SAME commit — two instruments must never key on different selectors for one control

w35-b gave the agenda day-footer next-day link its own token (`.chq-pub-agenda-day-footer-next`) per DEC-996 wave-35 and moved the `tap-floor-exempt:` receipt onto it. test/ssr-public-anchor-floor-w17-d.test.ts (DEC-393 wave-142) still asserts the receipt sits directly above a `.chq-pub-agenda-day-footer a` rule, and now fails with `expected a tap-floor-exempt comment directly above a real .chq-pub-agenda-day-footer a rule: expected null not to be null`. Nothing is wrong with the control; two instruments simply disagree about which selector names it, and the older one is the stale party. This is the class-keyed/ancestor-keyed blindness the field guide already recorded for SSR_CLASSLESS_ANCHOR versus the render sweep, now firing in the opposite direction — the fix landed and the older reader was not moved with it. RULED: the token-keyed form wins (an instrument must be able to reach a control by the control's own token, DEC-996 wave-35), the ancestor-scoped assertion is superseded rather than duplicated, and a lane that adds a class token to an exempt control greps every test that names the old selector and re-points it in the same commit. A negative control pins that the two instruments now key on the same selector, so this cannot silently re-split.

## Amendment (wave 39): a classless interactive element is graded by the selector that can reach it, and the grading lane is the one that floors it

`docs/design/audit/public-390-request-verdicts-v12.md`'s w35-h roster enumerates 22 visible classless interactive elements across `src/routes/public/**` and `src/routes/portal/**` and closes with an explicit handoff: "A later lane's job is to grade these 22, not this one's." The roster's own caveat is correct — the walk proves only that the ELEMENT carries no class, not that it is unreachable, and several sit under a classed parent that already floors them. That distinction has never been made, so a real 44px population sits ungraded behind green ceilings. RULING: each row resolves to VERIFIED (an ancestor-scoped selector effective at 390 declares min-height >= 44px plus non-zero horizontal padding), EXEMPT with an executable receipt, or OFFENDER — and the same lane floors every OFFENDER inside the terminal phone block, never at desktop. Scope this wave to `src/routes/public/**` only: the portal half is under two in-flight lanes and a second writer there would be the merge train's problem, not a finding.
