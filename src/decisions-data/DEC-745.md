## Amendment (wave 100): a `:disabled` checkbox/radio is B8's FIRST legal use (an inert control) and the register's guard must ACCOUNT for it by name in both mirrors

test/disabled-token-uses.scan.test.ts is red on main with exactly two unaccounted rules — `input[type='checkbox']:disabled, input[type='radio']:disabled` in app/src/styles.css and its byte-mirror `input[type=checkbox]:disabled, input[type=radio]:disabled` in src/views/theme.ts. B8 gives the Disabled register exactly two legal uses, 'an inert control (a pager arrow with no page to go to, a Remove at its lower bound)' and 'a drag handle'. A checkbox that cannot be toggled is the definition of an inert control: it is not de-emphasis, not placeholder ink, not a 'finished' value — the three misuses B8 names and says to distrust. So the correct close is to ACCOUNT for both rules by name with that written reason, in the scan's existing named-account idiom (it already carries e.g. "inert control — the SSR theme's disabled button tiers (B8)"), never a blanket allowlist and never bleaching the control to var(--chq-muted), which would make a disabled tickbox indistinguishable from an enabled one. Because the rule exists twice — SPA and SSR — the account must be written twice and each must name its own file, so deleting one mirror cannot be silently covered by the other's entry.
