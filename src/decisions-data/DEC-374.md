# DEC-374: Amendment (wave 147): SSR stylesheets are inlined COMMENT-STRIPPED — a CSS comment is page content, not source

SSR CSS is injected via dangerouslySetInnerHTML and must be value-free; the per-event accent moves to a validated style attribute on <body>.

## Amendment (wave 147): SSR stylesheets are inlined COMMENT-STRIPPED — a CSS comment is page content, not source

Measured on main e43c0fd7: PUBLIC_CSS is 95,639 bytes of which 60,802 (64%) is comment prose; THEME_CSS is 28,659 of which 14,373 (50%). Every anonymous public page ships ~75 KB of internal design commentary carrying 190 `DEC-*` references and 21 `docs/...` paths to visitors. This is not merely payload: it is what makes the copy gates unsound. `test/portal-placement-grammar.test.ts`'s three failures are caused solely by `src/routes/public/css/empty.css.ts`'s comment quoting `docs/probes/metafid-phoneB-ssr-2026-08-19-medium.md` (I reproduced the exact match), and `test/submit-cfp-frame-copy.test.ts`'s two by `cfp.css.ts` comments quoting real page sentences. v12m-w21-d treats the class as a ratchet to drain (CSS_COMMENT_COPY_LEAK_CEILING=37) and reworded two comments; that manages the symptom forever. RULED: comments are stripped at the `<style dangerouslySetInnerHTML>` inline SITES (serve time), never in the module constants — every source-scanning ratchet (palette, cascade-order, terminal-phone-block, frame-citation, tap-floor exemption grammar) still reads the authored comments verbatim, while no comment can ever reach a reader again. The stripper must be one shared, string-aware helper (DEC-613: never a second derivation), because `content: "/*"` inside a declaration is legal CSS. Brace balance verified stable under a naive strip (268/268 -> 264/264 on PUBLIC_CSS).

## Amendment (wave 152): A source-scanning ratchet reads a comment verbatim ONLY when the comment is its subject; when the subject is a CSS rule or user-facing copy, comments are stripped FIRST

DEC-374's wave-147 amendment ruled that comments are stripped at SERVE time and that "every source-scanning ratchet still reads the authored comments verbatim." That second clause is now producing false reds on main, and I reproduced all four in a detached worktree pinned to 9c39b12e. (1) speakers-phone-floor.test.ts:121 runs /\.chq-speakers-status-dense[^{]*\{([^}]*)\}/ over RAW speakers.css; wave-150 lane v12m-w6-ci opened its rule with a comment naming `.chq-participation-menu-trigger.chq-speakers-status-dense`, so the regex starts inside the comment, runs [^{]* through the comment's tail, and reads the FOLLOWING rule's `min-height:44px` as the dense rule's body. Comment-stripped, ZERO dense rules in that file carry min-height at all — the gate is reporting a defect that does not exist. (2) speakers-phone-tap-floor.test.ts:122's falsifiability control fails on the same comment by bare substring. (3) count-grammar.test.ts (DEC-957) and (4) plural-scan.test.ts (DEC-987) both flag `track(s)` occurrences that are inside `//` and `/* */` comments — while both scans state their own subject in their own headers as COPY ("so new copy is forced through plural()/countOf()"). RULING, in two halves so this is a correction and never a relaxation. A comment is NOT product: when a ratchet's subject is a CSS RULE (selector/body geometry) or USER-FACING COPY, the source is comment-stripped before matching, through ONE shared string-aware helper (DEC-613 — there are already >=4 private copies of a stripper in this tree: cancelled-padding-gap.scan.test.ts:119 exports the canonical one, vocabulary-duplication-ratchet.scan.test.ts:116, display-heading-line-height.scan.test.ts:64, served-content-type-single-source.scan.test.ts copy it verbatim). A comment IS product when the ratchet's subject is the comment itself — copy-leak, citation resolution, exemption-reason grammar, frame receipts — and those keep reading raw text unchanged. Every scan converted under this ruling must gain BOTH controls in the same commit: a positive control proving a violation in a real string literal / JSX text / rule body is still caught, and a negative control proving the same token inside a comment is not. Measured consequence: after comment-stripping, exactly ONE genuine `(s)` offender survives repo-wide — app/src/phone-overflow-scan/checks.ts:121's diagnostic template literal — and it must be reworded, not exempted, so this ruling costs the gates nothing.
