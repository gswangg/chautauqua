# DEC-383: wave-21: the shared .chq-chipstrip token's clipped focus ring is fixed on the sheet that DECLARES the token, never by a page-scoped override

app/src/styles.css`.chq-chipstrip {` declares the token (`display: flex; gap: 8px; overflow-x: auto; -webkit-overflow-scrolling: touch;`). An `overflow-x:auto` container's computed `overflow-y` is forced to `auto`, so the house ring (`:focus-visible { outline: 2px solid var(--chq-brand); outline-offset: 2px }`) is clipped top and bottom on every focusable child, and on the first child's leading edge at scrollLeft 0. docs/design/audit/contacts-v12.md Finding 7 fixed exactly this for the two Contacts-owned strips inside contacts.css's terminal phone block and named `app/src/styles.css` as the owner of the shared token, with "Scheduled owner-lane: none yet". RULED: the fix belongs to the sheet that declares the token — eight-plus consumers draw their ring through it (ContactsApp view tablist, Agenda day tabs, Content worklist/FilesLibrary/DeliverableDetail, Settings PeopleRoles/CallForPapers/Embeds) and a page-local override can only ever correct the strips that page owns outright. The correction is the offset flipping negative inside the ONE terminal `@media (max-width: 700px)` block (DEC-385 single-direction), never `outline: none` (DEC-409 forbids removing an outline) and never a new ring colour or width — the same precedent agenda.css's `.chq-day-grid-cell-btn:focus-visible { outline-offset: -2px }` and contacts.css's two strips already set.
