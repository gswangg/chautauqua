## Amendment (wave 101): the control-font register is a PER-RULE vocabulary contract: the global `button, input, select, textarea` reset does not discharge it, and a control-class rule that sets a type register declares `font-family: inherit` beside it

`app/src/control-font.scan.test.ts` is red at 36 offenders against a ceiling of 34; two of the three new offenders (`.chq-settings-drillrow-add`, `.chq-settings-drillrow-export-download`) arrived with commit f6b54547 in this train. It is worth stating plainly why the fix is not "the reset already covers it": `app/src/styles.css:209-213` does declare `button, input, select, textarea, optgroup { font-family: inherit }`, so most of these controls render correctly today. The contract exists anyway because the register is set LOCALLY — a rule that says `font-size: 13px; font-weight: 600` on a control class and says nothing about family is one refactor (a `<div role="button">`, a span-based chip, an SSR sheet with no reset) away from silently falling to the UA font, and the reader of that rule cannot tell which. RULING: every control-class rule that declares `font-size` or `font-weight` declares `font-family: inherit` in the same body, matching the idiom already used at styles.css:213/593/665/684/713/746/956 — not `var(--chq-font-ui)`, which would pin the wrong family inside display-font contexts. The ceiling is a ratchet: a lane that fixes offenders lowers CEILING to the number its own branch measures, never to a round number and never upward.
