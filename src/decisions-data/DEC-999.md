# DEC-999: A scan's own non-vacuity anchor is keyed on CONTENT, never on a source line number

`app/src/frame-citation.scan.test.ts``c.sourceLine === 116` was the known-good-example guard's pin at the time this ruling was written -- it had previously read `c.sourceLine === 115` for `app/src/phone-page-scaffold.test.ts`'s citation into `Chautauqua Speakers.dc.html:261`. An unrelated edit moved that comment to line 116 and the instrument's own vacuous-population tripwire went red — the scan now reports a defect in the corpus it is grading when nothing in the corpus changed. (Cited here in the drift-proof bare-path-plus-quote shape this ruling itself mandates, per DEC-967 wave-115 -- a contention decomposition later split this file's own source across app/src/frame-citation-core.ts, -frames.ts and -receipts.ts, moving the guard's line number again; the bare-path citation survives that move unbroken, which is the point.) This is DEC-967's line-drift lesson turned inward: the campaign already rules that every citation in prose is repaired by converting to the drift-proof bare-path-plus-quote shape rather than re-pinning a line, and the same reasoning binds harder on an instrument, whose whole value is that it does not lie about the tree. It is also DEC-967's hostage rule one register over (a tripwire must not be anchored on something a legitimate edit falsifies). RULED: every self-referential pin inside a scan — known-good example, positive control, negative control — is keyed on stable content (file identity, frame file, cited FRAME line, a quoted literal), never on the source line the citation happens to occupy today. Re-pinning `115` to `116` is forbidden: it buys one wave and re-breaks on the next edit. Where a line number is genuinely part of the claim, it is the CITED artefact's line (the frame's `:261`), which the frame file makes stable, never the citing file's own.

## Amendment (wave 28)

app/src/check-hit-receipt.scan.test.ts's wave-26 widening added a `labelIsBare` disposition and floored `.chq-visible-toggle` on the strength of it. Its `labelHasRealContent(inner)` strips only `/<input\b[^>]*\/>/`, which cannot span a multi-line JSX `<input>` whose attributes contain `=>`. The planner ran that exact function against both real bare-box sites in the tree at main 1482754fd and it returns TRUE for BOTH -- so the landed predicate can never classify any real site as bare, and its passing synthetic controls prove only the algorithm, never the corpus. The consequence is a live 18x18 tap target at 390: `.chq-contacts-import-review-skip` (ImportWizard.tsx, contacts-panels.css) wraps a bare `.chq-check` with no text sibling and no floor, and no instrument in the tree can see it. RULED: (a) a `<label>` whose only child is a form control and which renders no text of its own is a control, not a wrapper -- it carries the 44px phone floor itself; (b) a predicate that partitions a real corpus must carry an anti-vacuity anchor keyed on CONTENT that names at least one REAL site by a stable token and asserts its classification, so a stripper that silently stops matching fails loudly instead of emptying the population; (c) a JSX tag stripper is brace-depth aware, because `=>` inside an attribute expression is the common case, not the exotic one.
