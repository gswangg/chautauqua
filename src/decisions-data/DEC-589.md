## Amendment (wave 34): a denominator names its own population — the Overview Review row counts STARTED reviews and must say so

src/server/repo/overview.ts`started: sql<number>` computes a `count(*)` over schema.evaluation; the field was originally named `expected` and its comment claimed that number was "every assigned evaluation row, submitted or not" before this ruling's rename below. Verified on main: upsertEvaluation (src/server/repo/review/evaluations.ts:531) is the ONLY insert site into that table and nothing pre-creates a row per assignment, so the count measures reviews SOMEONE STARTED. A plan with 34 assignments and 3 saves therefore renders "3 of 3 evaluations in" (app/src/pages/overview/rows.ts:173), and an event with assignments and no saves renders "No evaluations assigned yet." (app/src/pages/overview/rows.ts) — a claim about assignments the aggregate never read, contradicting /plans/:id/progress, which derives `assigned` from resolved reviewer scope (src/routes/review/plans-progress.ts:93-160: resolveAssignments + assignedExcludingRecused + assignedExcludingSaturated). RULED: (1) the field is renamed evaluationsExpected -> evaluationsStarted through the aggregate, both payload types and the row composer, so its name states its population; (2) the row reads "{submitted} of {N evaluations} submitted" — a row may only speak for what it counted (DEC-936: one row elected to speak for the rest is a lie with a quorum); (3) the empty state becomes "No reviews started yet."; (4) the false clause in the DEC-589 comment is corrected in place. The true assigned denominator stays with /plans/:id/progress and is deliberately NOT re-derived in the Overview aggregate — a second resolver for one count is DEC-613's delay-fuse trap, and the frame (Chautauqua Overview.dc.html:831) grades this row by shape, not by its sample noun.
