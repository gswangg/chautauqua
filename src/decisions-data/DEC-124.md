# DEC-124: Server-side answer length caps in validateAnswers: text-kind answers max 2,000 chars, long_text max 20,000; field-level error 'Too long (max N characters)'

## Amendment (wave 91): a descendant-scoped variant of an allow-listed SPA-only error selector needs its OWN allow-list row — an exemption never covers selectors it does not name

error-vocabulary-parity.scan.test.ts flags '.chq-error-summary a.chq-error-summary-link' as SPA-only and unlisted, even though the bare '.chq-error-summary-link' is allow-listed and error-states-phone.test.ts:149 asserts the parity scan 'still ignores this token'. Two tests reading the same allow-list to opposite conclusions is the signal that the exemption's SCOPE was never stated. Naming it per-selector keeps the allow-list falsifiable (the scan already has a stale-entry test) instead of letting one row silently cover a family.

## Amendment (wave 92): the SPA's phone error-summary link treatment mirrors into the SSR vocabulary

app/src/components/error-states.css:146 declares `.chq-error-summary a.chq-error-summary-link` (a phone-scoped treatment) with no counterpart in src/views/error-states.css.ts, breaking parity. Not cosmetic drift: src/routes/public/submit-views.tsx renders `chq-error-summary-link` on the public CFP error summary, the phone surface a rejected submission lands on, so the SSR side needs the phone treatment MORE. Mirrored the declaration property-for-property into the SSR module rather than allowlisting the divergence — an allowlist here would encode the gap as intended.

## Amendment (wave 134): the whole-payload refusal on EventSettingsPanel gets its own named register above the form, distinct from the field-level error it still keeps

EventSettingsPanel's bare conflict/409 branch (no `fields` map at all — handleSave's catch, the only refusal on this form where the server rejects the WHOLE PATCH rather than attributing it to one key) was rendering as nothing more than a Slug field error; the reader was never told the save was a total loss or that the rest of the form's edits survived. Chautauqua Settings.dc.html:1242-1244 draws a bordered, ink-left-edged panel ABOVE the form for exactly this case — a display-weight `Nothing was saved` over a body sentence that names both halves: what was lost (the slug choice) and what wasn't (every other field, still on the page). Implemented as `.chq-settings-refusal-panel`, rendered as a sibling before `<SettingsEditForm>` so it sits above the form in document order per the frame, and kept alongside — never instead of — the existing Slug `chq-field-error` and its `ErrorSummary` anchor: the panel names what was lost at the level of the whole save, the field error still marks the one control the server actually named.

## Amendment (wave 134): a frame's copy is the authority over an app's paraphrase of the same idea, even when both convey the same information

FilesLibrary.tsx's Files search placeholder was independently re-derived on main between this amendment's assignment and its check-out — `Search filename, session, or speaker` (paraphrase) is already `Search by file or session…` (Chautauqua Content.dc.html:304, verbatim, real ellipsis character) on the checkout sha. No code change was needed; the render test now pins the frame's exact string via `getByLabelText('Search files')`'s `placeholder` attribute so a future paraphrase regresses loudly instead of silently. The general reading: when a v12 frame draws literal copy for a control, that string is the copy authority for the control — an app-authored paraphrase that conveys the same meaning is still a defect under DEC-124, not a stylistic choice.
