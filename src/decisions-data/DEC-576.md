# DEC-576: ONE shell owns chrome geometry: non-scrolling header, flex:1/min-height:0 scrolling body, in-flow phone tab bar; header is a single row with the event as text and the user as initials

## Amendment (wave 7): the shell's .chq-phone-head / -head-drill / -back is the ONE drill-in head, and a page that already draws a breadcrumb band re-classes onto it rather than declaring a second

DEC-576 gave the shell sole ownership of chrome geometry. app/src/styles.css:2190-2256 has shipped .chq-phone-head, .chq-phone-head-drill and .chq-phone-back since wave 1, pinned by phone-page-scaffold.test.ts:106-179 — and NOTHING in app/src or src renders any of them (only .chq-phone-dock, at SubmissionDetailPage.tsx:1870). Meanwhile two Comms sheets carry their own page-local breadcrumb bands (.chq-comms-templates-breadcrumb at TemplatesTab.tsx:198, .chq-comms-history-breadcrumb at HistoryTab.tsx:133) for the same affordance the shell already declares, and the Templates/Send-history 390 frames draw exactly the shell's anatomy: a 44px '‹ Comms' line, a 25px drill title, a 13px muted count, inside one 14px/16px band. RULING: the shell vocabulary is mounted, not re-declared. A drill view wraps its existing breadcrumb button in .chq-phone-head chq-phone-head-drill and ADDS .chq-phone-back to the button's existing class list — desktop keeps its page-local class and its current appearance untouched (neither shell class has a top-level rule, so at desktop widths the band is an unstyled div in normal flow), and the phone geometry arrives from the one place that owns it. A phone class shipped with a pin and no renderer is a green gate over unbuilt work; mounting is what closes it.

## Amendment (wave 96): A phone band mounted beside desktop content is hidden at desktop by a TOP-LEVEL rule; "no top-level rule at all" is safe only under a hidden parent

app/src/styles.css declares .chq-phone-dock ONLY inside the @media (max-width:700px) block at :2267, and app/src/pages/review/ReviewerQueue.tsx:703 mints <div className="chq-phone-dock chq-review-phone-dock"> as a direct child of a desktop-visible container — so at 1600 the reviewer queue gains a stray "Scores stay hidden from other reviewers" line and a live Sign out button no desktop frame draws. The same bare mount exists at app/src/pages/speakers/RosterPanel.tsx:521, harmless there only because its ancestor .chq-speakers-roster-drillin carries display:none at speakers.css:1469. The false premise is stated verbatim in three places: ReviewerQueue.tsx:701-702 ("chq-phone-dock has no rule outside the max-width:700px block, so this is a no-op at desktop"), :192, and app/src/phone-block-visibility.test.ts:11-15, whose rule accepts "NO top-level rule at all — meaning it only exists inside a phone-width query and inherits its parent's hidden state". That inheritance is an assumption about the MOUNT SITE, not a property of the class, and the gate is green over 187 tests while the leak is live. RULED: .chq-phone-dock takes a top-level display:none in app/src/styles.css beside .chq-tabbar's at :381-385 — the precedent .chq-reviewer-plans-phone-note already sets at review.css:2088 — which closes both bare mounts at once and needs no page-sheet rule. .chq-phone-head / -body / -back are ADDITIVE modifiers, always paired with a desktop class (chq-forms-header, chq-section, chq-link-button) on elements the desktop frames draw, and must NOT be hidden.

## Amendment (wave 98): a page-local docked band must DECLARE itself to the shell; tab-bar exclusivity is a contract about the footer region, not about a class name

The shell suppresses the phone tab bar two ways, both keyed on the shared vocabulary: styles.css:2539 declares `.chq-shell:has(.chq-phone-dock) .chq-tabbar` and styles.css:2302 declares `.chq-main:has([data-chq-phone-dock]) ~ .chq-tabbar`. Review's Scorecard legitimately does NOT use the shared class — its frames measure the dock's buttons at 46px where `.chq-phone-dock .chq-btn` bakes in 48px — so it mints `.chq-review-scorecard-dock` instead and, as a consequence, the tab bar stays mounted under it, which neither scorecard 390 frame draws (Review.dc.html:280-350, :934-1138 both end at a docked band with no tab row). DEC-576's wave-86 ruling is that a docked drill-in and the bottom tab bar are never both on screen; that is a statement about the FOOTER REGION, and a page that needs its own geometry must still declare the region. Ruling: any page-local docked band sets `data-chq-phone-dock` on its page root while the band is mounted. This costs one attribute, touches no shell file, and makes the declaration greppable — so the contract can be enforced by a scan instead of rediscovered per page.

## Amendment (wave 101): a phone-scaffold class may carry exactly ONE top-level declaration — `display:none` — and nothing else; the DEC-976 "no top-level rule" contract is a no-PAINT contract, not a no-rule contract

Main is red on a direct contradiction the merge train landed: `app/src/phone-page-scaffold.test.ts:106-109` asserts `.chq-phone-head/-body/-dock/-back` have NO top-level rule in styles.css, while `app/src/phone-dock-desktop-hidden.test.ts` (v12m-w14-c) requires `.chq-phone-dock` to HAVE a top-level rule declaring `display:none` — and styles.css:390 now carries it. Both guards are right about their own concern and cannot both be satisfied as written. The original contract's purpose (wave-96 amendment above) was that a phone scaffold class must not PAINT at desktop: it exists to stop a phone band acquiring desktop geometry, not to stop it being switched off. w14-c's case is real and verified — ReviewerQueue.tsx's drill-in and RosterPanel.tsx mount `.chq-phone-dock` as a bare child of desktop-visible markup, so with no top-level rule the dock's note plus a live Sign out band leak onto frozen desktop. RULING: a `.chq-phone-*` scaffold class may declare, outside every `@media` block, exactly one property — `display: none` — and no other property and no other value; every geometry, colour, spacing and layout declaration stays inside the `max-width` block (DEC-385 single-direction). `phone-page-scaffold.test.ts`'s assertion is narrowed to that rule rather than deleted, so the thing it was actually guarding (a scaffold class acquiring desktop geometry) still fails loudly. Two guards for one rule is the DEC-613 delay-fuse shape; the fix is one rule with one owner, not an exemption on either side.


## Amendment (wave 106): a phone dock that lives in a PORTAL declares itself through a body-rooted :has(), because no shell-rooted selector can cross the portal boundary

app/src/phone-dock-declares.scan.test.ts (w1-f) derives docked phone footers by geometry and asserts each declares itself to the shell so the tab bar is suppressed under it. One offender is exempted by name in KNOWN_UNFIXABLE_BY_ATTRIBUTE and recorded as a to-do in docs/design/audit/phone-dock-declaration-v12.md: `.chq-contacts-import-phone-dock` (contacts-panels.css:1605) is rendered by ImportWizard.tsx through ModalFrame, and ModalFrame createPortals its whole tree to document.body (ModalFrame.tsx:161-177, verified on main 114b4d2c) under a `.chq-scrim` root. Both existing shell idioms are rooted inside the shell -- `.chq-shell:has(.chq-phone-dock) .chq-tabbar` and `.chq-main:has([data-chq-phone-dock]) ~ .chq-tabbar` -- and neither can ever match a node in a sibling DOM subtree, so the audit correctly concluded that no page-local attribute fixes it. It concluded WRONG that the fix needs a ModalFrame rework: `.chq-tabbar` and `.chq-scrim` are both descendants of <body>, so ONE body-rooted rule spans the boundary with no new signal, no body class toggle, no ModalFrame prop and no change to where the modal portals. RULING: the third and last shell idiom is `body:has(.chq-scrim [data-chq-phone-dock]) .chq-tabbar { display: none; }`, authored inside app/src/styles.css's single terminal phone block. It is scoped to `.chq-scrim` deliberately -- only a MODAL dock reaches across the portal; an in-shell dock keeps using the two narrower rules, so this does not become a catch-all that suppresses the tab bar for any attribute anywhere. The declaring page sets the SAME `data-chq-phone-dock` attribute it would set in the shell, so there is one contract for page authors, not two. KNOWN_UNFIXABLE_BY_ATTRIBUTE empties, and the scan gains a positive assertion that styles.css actually carries the body-rooted rule -- otherwise the attribute is decorative and the exemption would have been traded for a no-op.

## Amendment (wave 114)

The mandate deferred this: "Publish schedule survives as the head's full-width action row (DEC-919 remedy). Whether it belongs in the phone dock instead is a frame deviation needing a proper ruling later — the frame's dock draws only Unscheduled + Auto-schedule." Ruling made. `docs/design/Chautauqua Agenda.dc.html:198-200` draws the 390 dock as exactly two controls, each `flex:1` at the 44px floor — `Unscheduled 6` bordered, `Auto-schedule` olive — and the app matches it (`PhoneAgenda.tsx:304` `className="chq-phone-footer-actions"`, :306 Unscheduled, :108 restLabel 'Auto-schedule'). RULED: Publish schedule stays OUT. Three reasons, in order of force: (1) the frame draws the dock's membership as explicitly as its geometry, and DEC-919's "re-line, never remove" licenses re-lining a control the frame has no room for into the head — it does not license injecting a third control into a dock the frame draws closed; (2) a third member re-bases both drawn `flex:1` children, so the injection would break the one piece of dock geometry the frame states numerically; (3) the two docked controls are both scheduling-workbench affordances that act on the day in view, while publishing is a terminal, event-wide act — putting it a thumb's width from Auto-schedule is a mis-grouping, not just a mis-measurement. This wave pins the membership so the question cannot be re-opened by accident.

## Amendment (wave 120): a drill's phone dock is adopted only when every control the frame draws in it has a referent; Pipeline keeps its landed head action rather than mint a phantom Filter

Two Contacts drill frames draw a pinned band and they are not the same case. `Merge · 390` (:536-539) draws `Merge them` at flex:1 and `Not a duplicate` beside it — both are controls MergePage already renders in `.chq-contacts-merge-footer`, so the footer becomes the frame's band verbatim (sticky, `border-top:1px solid ink`, `background:#EFEBDF`, `padding:12px 16px 16px`, `gap:8px`, a ROW not the column the landed phone rule stacks) and the page declares `data-chq-phone-dock` so `.chq-main:has([data-chq-phone-dock]) ~ .chq-tabbar` stands the tab bar down (DEC-576 wave-86: a docked drill and the tab bar are never both on screen). `Pipeline · 390` (:472-475) draws `Add someone` at flex:1 and `Filter` beside it. The app has the first; it has no second, and "Filter" names precisely the affordance the frame itself draws DIRECTLY ABOVE the list on the same screen — the five-stage horizontal scroller at :451-458, landed as `.chq-contacts-pipeline-phone-stages`. Minting a dock control that opens nothing to satisfy a drawing would INVENT capability, the exact inverse of DEC-380 wave-116's finding that a frame's silence removes geometry and not capability, and just as wrong; and relocating the single remaining action buys a dock whose only member already clears the frame's floor where it stands (app/src/pages/contacts/contacts-panels.css`.chq-contacts-pipeline-head > .chq-btn {` -- drift-proof citation, DEC-967 wave-115; the rule declares width 100%, min-height 48px and padding 0 16px). RULED: Merge adopts its dock; Pipeline does not, its one action keeps the landed full-width 48px head placement, and that is recorded as a blessed deviation rather than left as an untracked gap. The general rule this sets, for the drills that follow: adopt the band when the frame's membership is satisfiable from controls the surface already owns; where a drawn control has no referent, keep the app's placement, state which same-screen affordance discharges it, and record it — never a control that is only a shape.
