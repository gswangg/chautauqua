# DEC-144: Wave-154 amendment: the route manifest carries tab and panel sub-states, derived from the pages' own tab unions

`app/src/routeManifest.ts` has 64 rows and ZERO query-string entries (grepped: no `?tab=`, no panel key). Every tabbed or panelled admin surface is therefore visited by the desktop AND the 390 live pass only at its default tab. Consequences measured against the campaign's own record: the mandate counts NINE Settings width:390 frames (Chautauqua Settings.dc.html :275/:316/:347/:393/:444/:481/:510/:552/:578) and the gate renders at most one of them; `/admin/contacts?tab=pipeline` — the exact surface where meta-probe round 3 found a dock MISSING entirely — is never navigated to, which is why no gate caught it and a human probe had to.

RULED: the sub-state population must be derived from each page's own tab/panel key union (Comms.tsx's `isTab`, Contacts.tsx, Settings.tsx's panel union, ContentApp.tsx, the speakers tabs), never hand-listed, and `routeManifest.test.ts`'s parity check must FAIL when a new key has no row — a hand-listed population is not a population.
