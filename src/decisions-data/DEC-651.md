# DEC-651: One dialog HEADER contract: title + optional subtitle + Close, primary action first, and every free-text control in a dialog carries the mock's placeholder — enforced by a source scan, not by habit

## Amendment (wave 7): ModalFrame's header is paired to its CONTAINER's inset at every width, and gains one optional back affordance

DEC-651 made ModalFrame the one dialog header. Its .chq-modal-head (app/src/components/modal-frame.css:38) cancels its container's padding with `margin:-20px -26px 0; padding:0 26px 16px` — correct against the desktop `.chq-modal`/`.chq-drawer` 20px 26px. But at phone styles.css`.chq-drawer` is cut to `padding: 16px;` and only .chq-contacts-drawer-actions is re-paired (styles.css`.chq-contacts-drawer-actions {`), so at 390 the ModalFrame header band starts 10px outside the drawer's left edge and runs 20px wider than the drawer, overhanging both sides, with its title on a 26px gutter against a 16px body. phone-page-scaffold.test.ts:228 pins drawer-to-action-bar and never drawer-to-header. RULING: any negative margin that cancels a container's padding is paired to that container AT EVERY WIDTH — the header, the action bar and the drawer move together or not at all. Second half: the frames draw the drawer's phone head as a drill head whose first line is a '‹ <collection>' return (Contacts.dc.html:409, Comms.dc.html:288/337), so ModalFrame gains ONE optional `back` prop rendering a .chq-phone-back control — the shell class, not a fourth local one — giving that orphan its first renderer and the contact drawer the 44px '‹ Contacts' affordance the campaign has listed as blocking since wave 1.

## Amendment (wave 24): a Modal/Menu/STATE frame is verdicted by operating the control that opens it on the real route — a direct component mount verdicts the component, not the screen

Of the desktop frames wave 24 adjudicates, twenty are not pages: eleven carry the pack's own `Modal` or `Menu` badge (Settings :1271 Invite someone, :1319 the one-time password, :1352 Invite rejected, :1392 Confirm · reversible, :1414 Confirm · irreversible, :1440 Portal resource · add, :1477 Reset a password; Speakers :187 New task, :228 Task response, :288 Participation · open, :491 Review these reminders) and nine more are a page STATE the tree only reaches by being driven into it (Speakers :442 search found nothing, :549 a write failed; Content :434 Upload rejected; Settings :1215 save rejected by the server; the Public/Portal CFP-window and empty states). Mounting `ConfirmDialog`, `RemindPreviewModal` or `ResponseModal` with hand-built props would verdict the component in isolation — and DEC-651's own one-dialog-HEADER contract (title + optional subtitle + Close, primary action first, every free-text control carrying the mock's placeholder) is a claim about what the PAGE hands the dialog, which a direct mount can never falsify: the props under test would be the ones the test author invented. The same holds for a state frame: an error band rendered directly proves the band exists, not that the page reaches it. RULED: a dialog or menu frame is entered from the route that owns it (`SettingsPage` under `MemoryRouter` at `/settings?section=<key>`, `SpeakersPage` at `/speakers`, `ContentApp` at `/content`) by firing the real opening control with `fireEvent`, and a state frame is reached by driving the state itself — a search string that matches nothing, a `mockApi` write that rejects, an empty fixture — never by rendering the state's component directly. Where the frame draws a control the tree does not build (e.g. :1414's `Downloaded 18 times by 12 speakers`, already deferred by DEVIATIONS §6), the verdict is DIVERGES in prose with the deviation cited; no dialog is restyled, re-labelled or re-ordered to match, because desktop is frozen and this wave measures only.

## Amendment (wave 26): a desktop verdict lane is MEASUREMENT ONLY — it files DIVERGES and moves no desktop byte

The mandate freezes desktop (`docs/mobile-campaign.md` hard rules: phone work in max-width blocks only, desktop pins stay green, a desktop-affecting change is legal only when a v12 desktop frame demands it). Every wave-23/24 verdict doc already opens with a STRICTLY MEASUREMENT ONLY paragraph; wave 26 restates it as a rule rather than a convention, because 28 residue frames across seven lanes is the largest single opportunity yet for a worker to 'just fix' a divergence it found. RULING: a verdict lane renders the real route, verdicts what the tree produces, and writes divergences as prose rows. It edits no component, no stylesheet, no route module. Where a divergence looks like a real defect, the row says so and names the cluster that owns the fix — a later wave schedules it, or the planner routes it to DEVIATIONS if the frame's prose asserts behaviour the code deliberately forbids.

## Amendment (wave 29): a Settings 390 drill frame is verdicted by mounting SettingsPage at its ?section= route, never the bare panel

The Settings 390 drill frames draw `‹ Settings` and the section name as the screen's title, and both are rendered by the PAGE, not the panel: app/src/pages/Settings.tsx`<h1 className="chq-page-title chq-settings-drill-title">{phoneDrillTitle}</h1>` is the PAGE's own emission, while the panel's own `<h2>` is de-duplicated at phone by settings.css's terminal block (`.chq-settings-panel > .chq-settings-section-head > h2`, w17-d/DEC-919). A lane that mounts `PublicPagesPanel`/`SavedEmbedsPanel` directly would see an `<h2>` and no back link and file a false H1 divergence. RULING: mount `SettingsPage` at the drilled route, copying `app/src/pages/settings/SummarySection.phone-drill-head.render.test.tsx`'s harness — a direct component mount verdicts the component, not the screen.

EnrollDialog (PipelineBoard.tsx) mounts `<ModalFrame title="Add to the pipeline">` with no subtitle; Contacts :624-625 draws a subtitle under that exact title reading `Aisha Karim · Vector Foundry` — the selected contact's name · org. ## Amendment (wave 9): a refusal state the frame RETITLES takes the frame's title, and the escape the frame draws sits in the actions row

docs/design/Chautauqua Settings.dc.html:1352 draws the duplicate-email invite refusal with the dialog header retitled to `Nobody was invited` (:1359) over the subtitle `The address is already in use` (:1360), and draws all three controls in ONE actions row in the order `Create the account` / `Cancel` / `Open Sam's row` (:1384). PeopleRolesPanel.tsx keeps `title="Invite someone"` through the whole flow and only swaps the subtitle (:454), while the escape route renders inside the error-alert body (ModalFrame's children-before-actions composition), so in DOM order it is FIRST rather than last. DEC-651's dialog-identity contract already rules that a distinct state gets its own header; the subtitle already moves, so the title staying fixed is an incomplete application of the same rule, not a deliberate one. Ruled: while `duplicateUser` is set the invite dialog's title is the frame's, and the escape is the actions row's third (tertiary) control. This is the same shape as the ruling w8-b applied to the CSV file-level refusal at Contacts :770 — a refusal that owns its own identity.
