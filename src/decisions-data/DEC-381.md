# DEC-381: The phone tab bar's fourth slot is contextual and every slot carries its dot above the label

Seven v12 frames spell the tab bar's data verbatim (Contacts.dc.html:1015-1021, Comms.dc.html:970-976, Content.dc.html:501-507, Settings.dc.html:1702-1708, Overview.dc.html:835-841, Speakers.dc.html:871-877, Submissions.dc.html:796-802). They agree on three things the app contradicts. First, slots 1-3 are always Overview / Submissions / Speakers and slot 5 is always More, but slot 4 is the CURRENT section when that section is Contacts or Comms, and Content otherwise -- App.tsx:135's PHONE_TAB_PATHS is a fixed four-path list, so Contacts and Comms can never be the tab you are standing on. Second, the Settings frame draws More as DOT_ON: More is the active slot exactly when the current section is none of the four rendered tabs. Third, the row markup is `flex-direction:column; gap:5px` with the dot span BEFORE the label span, and every one of the five carries a dot -- inactive `background:#BAB6A6` (= var(--chq-border), already `.chq-dot`), active `#4E5C31` (= `.chq-dot.is-on`). App.tsx:315-317 renders the dot after the label and only when active. Because the dot now marks active on every slot, More's existing `anyBadgeLive` signal can no longer be a bare dot: it re-lines (DEC-919, never remove) onto a distinct modifier, and active stays unambiguous because the frame carries it in BOTH the dot colour and the label's 700/ink weight.
