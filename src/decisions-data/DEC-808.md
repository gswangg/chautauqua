# DEC-808: One page measure, finally adopted by the admin SPA

## Amendment (wave 93): a line-numbered citation is a claim and must sit beside its assertion; a file-header pointer names the frame file only

78 test-file phone-frame citations are unreceipted against UNRECEIPTED_CLAIM_CEILING=14, and roughly thirty sit in FILE HEADERS (contacts-phone-frames.test.ts:4-8, phone-page-scaffold.test.ts:5-8, submissions-phone-frames.test.ts:2/6, settings-phone-390.frames.test.ts:13-16, home-phone-frames.test.ts:4/7, review-phone-frames.test.ts:4/5, and others) where no `expect(` can ever be within six lines — the scan's contract is structurally unsatisfiable there, which is why five waves of care never closed them. RULING: a `docs/design/<frame>.dc.html:<line>` citation IS the claim, so it lives immediately above the assertion that pins what that line declares, carrying the line's verbatim backticked literal. A file header may point at the frame FILE with no `:line`, which is a pointer and not a claim. CONSTRAINT that makes this safe: test/phone-frame-ledger.scan.test.ts's CLAIMED_FLOOR=53 is a two-sided ratchet counting frames claimed by exact line-numbered citation, so a header citation must be MOVED (with its quote) to the assertion, never de-lined away, unless the same frame line is still cited elsewhere. Every receipts lane runs test/phone-frame-ledger.scan.test.ts as a targeted test to prove no frame silently un-claimed.

## Amendment (wave 96): An SSR stylesheet is a module that EXPORTS a *_CSS template literal, not a file whose name ends .css.ts

Three probes enumerate the SSR stylesheet tree by filename and all three miss the same file. app/src/phone-horizontal-overflow.scan.test.ts:67 globs src/**/*.css.ts; app/src/phone-block-visibility.test.ts:24 roots at src/routes only and misses src/views/** entirely; the SSR tap-floor scan branch v12m-w13-a built inherits the same glob. src/views/theme.ts exports THEME_CSS at :30 — 600 lines of CSS ending at the backtick on :646, loaded by EVERY SSR surface, and the sheet that actually carries the 44px phone floor for buttons (:625-627 over the base at :347 and :362), the one carrier every SSR *-actions container exemption must cite. A directory is not a population and neither is a suffix. RULED: the SSR population is every src/**/*.ts (tests excluded) whose source declares `export const <NAME>CSS = \``  — 16 modules on main, the 15 *.css.ts sheets plus src/views/theme.ts — enumerated by readdirSync recursion with a vacuous-population tripwire and a positive control naming theme.ts by path. Measured consequence on main: theme.ts contributes ZERO new overflow offenders and zero phone-class rows, so this closes a hole rather than opening a backlog, and no ceiling moves (v12m-w13-f owns the re-seed of OVERFLOW_OFFENDERS_CEILING 65 -> 24 and ANCHOR_FLOOR_OFFENDERS_CEILING 92 -> measured; both assertions are toBeLessThanOrEqual, so re-seeding can only tighten).

## Amendment (wave 99): A design ruling's guard must enumerate BOTH halves of the tree; four B8/Tier-2 scans still root at app/src alone

Wave 95 recorded this exact shape for the tap-floor probe (its sibling overflow probe walked `src/**` and it did not) and wave 96 recorded that a `*.css.ts` suffix glob misses `src/views/theme.ts`, the 600-line sheet every SSR surface loads. The lesson was never generalised, and re-derivation on main cf06f988 finds four more guards with the same defect while their own siblings are already correct: `app/src/status-density-pairing.scan.test.ts` enumerates `app/src/**/*.css` only and reports DIVERGENCE_CEILING 0 with the note that no status token lives in `app/src/components/*.css` — a green zero over a partial population, and Tier-2 mandate bullet 2 has therefore never been measured over the 17 SSR phone frames; `app/src/interaction-states.scan.test.ts` (DESIGN-RULINGS B8 motion standard: no `transition: all`, no `ease-in`, mandatory `prefers-reduced-motion` re-bind) enumerates `app/src` CSS only, while `src/routes/public/css/chrome.css.ts` carries a transition and no reduced-motion block; `app/src/select-caret.scan.test.ts` (B8: the caret is its own element at the control's right edge) walks `app/src/**/*.tsx` only, while `src/views/form-render.tsx`, `src/routes/public/filters.tsx`, `src/routes/portal/tasks/views.tsx` and `src/routes/portal/edit.tsx` all render `<select>`; and `app/src/control-font.scan.test.ts` reads exactly ONE file, `app/src/styles.css`, to enforce a rule about every class that sets a type register on a form control. RULED: each of these derives its population the way `test/disabled-token-uses.scan.test.ts`, `test/phone-wrap-conformance.test.ts` and `app/src/no-fitted-geometry.scan.test.ts` already do — every `*.css` under `app/src` plus every module under `src/` that EXPORTS a `*_CSS` string literal (derived, never a filename glob, never a hand-listed path). Ceilings are re-seeded to the truth measured over the full population and every offender is named in an audit doc; offenders sitting in a sheet an unmerged branch already owns are RECORDED, not edited.

## Amendment (wave 100): DESIGN-RULINGS.md's real population is its NUMBERED RULING ROWS, not its headings — and a **DROP** row is a NEGATIVE claim the guard must assert as ABSENCE

test/design-rulings-ledger.scan.test.ts derives its population from the file's `##`/`###` headings (~30), of which several are admitted section dividers recorded as 'gap' by construction. But the document's actual rulings are the ~38 numbered rows in the A. Extensions and B. Uncovered-surfaces tables (A1–A28, B1–B10), each carrying its own verdict — BLESS, RESTYLE or DROP. Nothing in the tree reads them. This is the third time this campaign has met 'a scan that measures a proxy for its population' (DEC-393 w95 root, DEC-808 w96 sheet-derivation, DEC-808 w99 four app/src-only guards), and it matters more here because DESIGN-RULINGS.md is one of the four authorities the goal names. Two rules land with the population: (1) a BLESS/RESTYLE row is honored only by a cited artifact whose literal exists verbatim, the same contract the heading ledger already enforces; (2) a **DROP** row is the mirror — the guard asserts the dropped capability's named literal does NOT appear in app/src or src outside test files, because a DROP that nobody checks is the one verdict a refactor can silently undo. Verified on main: A6/A8/A9 and B10's public-pages DROP all currently hold, so the guard seeds green and only ever catches a regression.


## Amendment (wave 106): a phone ratchet whose constant sits above its measured truth is a licence; every ceiling in the campaign carries the two-sided companion the frame ledgers already ship

Measured on a clean archive of main 8e5aec96 (SHA re-read after): app/src/phone-scaffold-orphan.scan.test.ts declares ORPHAN_CEILING = 4 while the measured orphan count is 0 (the file passes with the constant forced to 0), and app/src/phone-capability-removal.scan.test.ts declares PHONE_HIDDEN_UNRECEIPTED_CEILING = 10 while the measured count is 7 -- the file's OWN header comment already says 'the seven remaining unreceipted interactive rules'. Both are one-sided ratchets with no companion, which is exactly the failure DEC-808's wave-85 amendment named for CLAIMED_FLOOR and then fixed for the two frame ledgers: a floor that sits below the truth licenses stagnation, and a ceiling that sits above it licenses debt, and neither can be noticed without a test that fails when the constant goes stale. RULING: every campaign ratchet is two-sided. A ceiling gets a companion `it` that FAILS when the measured count falls below the constant, printing the exact replacement line, so the constant is re-tightened in the merge-train batch that landed the fix rather than drifting for twenty waves. The one-sided half is unchanged and still forbids raising. Ratchets are re-measured against the tree, never inherited from a prior wave's audit table. Of the 7 measured capability-removal offenders exactly one lives in a sheet no in-flight lane owns, app/src/pages/settings/settings-lists.css:123-126, and it is not a defect at all: the rule hides the DESKTOP TWINS of `.chq-settings-phone-action` (the phone-only 46px primaries the frames draw at Chautauqua Settings.dc.html:426 and :568), which is DEC-919's receipt shape 1 written in prose instead of in the `/* phone-hidden: ... */` grammar the scan reads. It gets the grammar, not a code change.
