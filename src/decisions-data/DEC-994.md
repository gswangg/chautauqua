# DEC-994: A cascade-blind phone verdict is closed by a load-bearing stylesheet read, never by a `.css` string the predicate happens to see

`app/src/phone-verdict-cascade-read.scan.test.ts`'s predicate is a bare substring test (`.css'` / `.css" anywhere in the source`), so a lane could drop the ceiling from 9 to 0 by adding a dead `const X = 'foo.css';` and the instrument could not tell. That would convert the campaign's last Tier-2 row into a formality. RULED: a member leaves the offender set only when its new read is CONSUMED by an assertion — it extracts the page's own stylesheet, selects the `@media (max-width: 700px)` block that governs the rule by brace-depth (several sheets carry more than one: speakers.css 2, review.css 5, content.css 6, so 'the terminal block' is not a synonym for 'the only block'), and asserts a rule the frame's own phone geometry needs, with the frame line cited in the receipted idiom. A `.css` literal no expect() reads is a defect, not a fix. Reuse `test/helpers/strip-css-comments`'s `stripCssComments` and the brace-depth walk that `app/src/pages/Contacts.frame-verdicts.render.test.tsx` already spells — never a sixth private copy (DEC-613).

## Amendment (wave 28)

test/account-docs-phone-frames.test.ts's "Sign in · 390" pin asserts the frame's 50px input height with a regex spelling out `.chq-auth-card input[type=email],\n .chq-auth-card input[type=password] {` followed by `min-height: 50px`. A wave-26 lane correctly added a third selector (`.chq-input`) to that same rule to close a real 48px-vs-50px offender, and the pin went red although the drawn geometry is now MORE conformant than before. A pin that breaks when the CSS becomes more correct is measuring its author's typing, not the frame. RULED: a frame-geometry pin resolves the DECLARATION that governs a named selector -- parse the sheet's terminal phone block, find the rule whose selector list CONTAINS the selector, assert the declared value -- so adding or reordering a sibling selector can never redden it, and deleting the declaration always does. The repair is never to revert the CSS to fit the regex.
