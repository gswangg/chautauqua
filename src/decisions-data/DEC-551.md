# DEC-551 wave-46 amendment: nosniff's population is every response that DECLARES a Content-Type and carries stored user content - a literal content type is not an exemption

DEC-551 reads "every route that streams stored user content sets X-Content-Type-Options: nosniff", but neither instrument enforces that sentence. test/user-content-nosniff.test.ts's structural half enumerates only handlers whose body comes from `makeFileStore(...).get(...)`, and test/served-content-type-single-source.scan.test.ts checks the nosniff twin ONLY for Content-Type values that are non-literal (its own header says so: the invariant it makes structural is about echoing a DB column). Seven live responses fall in the gap between them, verified against the tree: src/routes/api/exports.ts sets `text/csv` at :66 and :210 and returns `c.json(table.records)` at :206; src/routes/review/plans-progress.ts sets `text/csv` at :250; src/routes/public/index.tsx sets `application/xml` at :307 and `text/calendar` at :427 and :453. All seven emit stored user content - submission titles, contact names and bios, session titles - and the XML feed and both .ics routes are ANONYMOUS and inline-served with cache headers, which is the worst version of the exposure, not the mildest. RULED: (a) all seven sites set X-Content-Type-Options: nosniff alongside the Content-Type they already declare; (b) the guard's population becomes structural and complete - every response under src/routes/** that declares a Content-Type other than text/html is enumerated and must set nosniff in the same header object or the same adjacent c.header run, ratcheted at 0 with the two-sided companion the campaign requires, plus positive and negative controls and a vacuous-population tripwire, so "literal" stops being an accidental exemption; (c) the comment-stripping the scan needs is imported from the existing shared helper, never a third copy (DEC-613); (d) no content type, filename or cache header changes - contentDispositionAttachment already sanitises correctly and is not in scope.
