## Amendment (wave 35): a fast-tier guard that can time out enforces nothing — a hook or test within 25% of its limit gets an explicit, commented timeout

The campaign's exit predicate refuses to grade any row without a `--suite-verified-sha`, so `npm run test:fast` is the one instrument standing between the campaign and a declared-but-unmeasured finish. Measured this wave at main da6cbbf51 (full run, 1400 files / 18,056 tests, 350s): `test/ssr-link-targets-scan.test.ts` passed in 8591ms against vitest's default 10000ms `beforeAll` hookTimeout — a 14% margin on a guard whose whole job is to prove every SSR link target resolves. An independent reviewer observed the same file FAILING that hook under load. A guard that flips between enforcing and timing out depending on host contention produces exactly the red/green oscillation the field guide already records across waves, and its green reading is worthless. RULED: any fast-tier hook or test measured within 25% of its effective timeout is given an explicit timeout argument carrying a comment that names the measured duration and the margin, so the limit is a stated decision rather than an inherited default that a busy machine converts into a silent hole. Raising a timeout is not hiding slowness; leaving a 14%-margin default on a gate is.
