## Amendment (wave 25): fast-tier determinism is bought per-test with a measured receipt, never by a global testTimeout

Wave 23 named the default 5000ms testTimeout as the reason test:fast cannot supply a --suite-verified-sha, but nobody built the fix (v12m-w23-a is ahead=0). I measured the population myself on main at 3361d468 with `npx vitest run --config vitest.fast.config.ts test/*probe*.test.ts --reporter=verbose`: SIX security probes sit between 4116ms and 5135ms against the 5000ms default -- cross-org-object 5135, cross-org-file-bytes 5013, portal-idor-real-rows 4957 (and 5006 in a separate two-file run, i.e. it flips), cross-org-body-id 4769, cross-org-event-scope 4295, review-plan-scope-real-rows 4116. Note what this measurement kills: wave 23's theory that the red is load-dependent parallelism. Two of the six FAIL when only eleven files are running. These tests are simply slower than the default. RULED: each of the six named it() gets an explicit third-argument timeout with a comment receipt naming its measured ms and the sha measured at; NEITHER vitest config gains a `testTimeout` key, because a global raise disarms hang detection for ~16,880 tests to rescue six, and a suite whose hang detector is off cannot be evidence for DEC-069 either. A scan test pins both halves so the cheap fix stays foreclosed.
