## Wave-55 amendment: more than one lane may pay a promotion promise in the same wave, provided each edits only its own constant's key in each registry file and lands ceiling change plus promotion in ONE commit

Three wave-55 lanes (a, b, c) can each clear a parked ceiling's promotion clauses, and wave 54's own lane a is doing the same for PACK_PROSE_MEASURE_DIVERGENCE_CEILING. Serialising them would starve three of four worker lanes for a purely textual conflict: the four campaign-scope registry files are maps and arrays whose entries are line-local, so four lanes adding or deleting four distinct keys conflict only as adjacent-line edits a merge resolves. What is NOT safe is splitting one promotion across two commits — a ceiling driven to 0 whose registry entries still sit in OUT_OF_CAMPAIGN_SCOPE makes assertParkedPromisesAreHonestlyParked throw before a single campaign row prints, which is the dead-judge failure mode that has now cost three consecutive waves. Each lane therefore lands its own ceiling value and its own promotion together, reformats no neighbour entry, and ignores a predicate throw that names a constant it does not own.
