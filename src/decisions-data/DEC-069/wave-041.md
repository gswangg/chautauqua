## Amendment (wave 41): an advisory gate flag needs a promotion rule, exactly as an exclusion table does

DEC-069's wave-36 amendment gave `OUT_OF_CAMPAIGN_SCOPE`'s ten promotion-promising rows a promotion rule after finding none had ever been promoted. The identical shape is live in the render sweep and was never ruled: `scripts/render-sweep-lib.ts` declares three `*_BLOCKING = false` flags — `PUBLIC_MOBILE_OFFENDER_GATE_BLOCKING` ("flipped true in a later wave once a re-confirmed reading settles clean"), `TYPE_ROLE_BLOCKING` and `INTERACTION_STATE_BLOCKING` ("flip per the same DEC-387 rule once a reading has come back all-PASS") — each promising a flip that no rule, registry or instrument can ever force. Two of the three grade DESIGN-RULINGS requirements directly (B8 interaction states; the type scale), so those rulings have never been enforced by anything that can fail. RULED: every `*_BLOCKING = false` constant must appear in a machine-derived registry (never a hand list) carrying a principle-shaped reason and a NAMED promotion predicate — a constant in the same module for the statically decidable case, a named recorded-reading artifact for the live-gate case — and a flag whose predicate is satisfied while it still reads `false` is a failure, not a note. `PUBLIC_MOBILE_OFFENDER_GATE_BLOCKING`'s predicate is `PUBLIC_MOBILE_CANDIDATE_DEFECT_CEILING === 0`, which makes the flip owed to whichever lane drains that ceiling (in flight as w38-e) rather than to nobody.
