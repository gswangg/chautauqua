# DEC-367: An exemption is a grammar, not a punctuation mark — repair `topLevelRulesWithExemption`'s exempt flag and re-seed the ceiling it blinded

app/src/phone-tap-target-scan/core.ts`m[0].trimStart().startsWith('/*')` set the `exempt` flag from the match prefix alone (the file's own header now names it as the predicate this ruling replaced). The optional exemption group `(?:\/\*\s*tap-floor-exempt:[^*]*\*\/\s*)?` is allowed to NOT match, after which the selector group `([^{}]+)` happily swallows any brace-free block comment — so `m[0]` still starts with `/*` and the rule is marked exempt. I proved it on a clean archive: `/* just a normal design comment */\n.chq-x { padding: 0; }` returns `exempt: true`. In a tree where nearly every rule carries a frame-citation comment this exempts a large fraction of the 44px population from FOUR ratchets at once (base tap-target scan, undeclared-height lens, SSR scan, anchor-floor). Measured on a clean archive of main with the one-line repair `const exempt = /\/\*\s*tap-floor-exempt:/.test(m[0] ?? '')`: `UNDECLARED_HEIGHT_OFFENDERS_CEILING` goes 15 -> 28 live offenders, and the base scan's `every sub-44px control has a >=44px phone override or a named exemption` assertion goes from GREEN to 2 offenders. Three of the four 44px defects an independent lens measured live at 390 (`.chq-review-editor-title-input` ~36px, `.chq-speakers-phone-roster-link` 58x21, `.chq-check` 18x18) were invisible for exactly this reason. RULED: an exemption is recognised only by its literal grammar `/* tap-floor-exempt: <reason> */` immediately above the rule; the repair lands with a positive control (an ordinary comment does NOT exempt), a negative control (a real exemption DOES, and does not leak onto the NEXT rule), and both controls live in a new file so they do not contend with the drain lanes. Because this is a PREDICATE REPAIR and not a regression (DEC-989 clause c), `UNDECLARED_HEIGHT_OFFENDERS_CEILING` is RE-SEEDED upward to the value measured under the repaired predicate, in the repairing commit, with a header that names the blind line it replaces.

## Amendment (wave 138): a fixed `width` below the floor is the THIRD evasion mode of the 44px ruling — horizontal padding cannot reach the floor while an explicit width survives

DESIGN-RULINGS:189 names two evasion modes (a shared token that cannot satisfy a dense grid and a 390 card at once; a hardcoded sub-44 `min-height` on a phone token) and states the width mechanism as 'plus horizontal padding — without padding the hit box is only as wide as the text'. `button.chq-pub-search-submit[type=submit]` declares `width:40px; height:40px` at `src/routes/public/css/chrome.css.ts:155`, and its phone override adds `min-height:44px; display:inline-flex; align-items:center; justify-content:center; padding: 0 8px` — every clause the ruling names, and the control still measures 40px wide, because the base `width:40px` survives and border-box makes the padding inert. Every scan in the campaign grades the HEIGHT dimension only, so this reads floored to all of them. The mirror case is `.chq-portal-footer-profile` (`portal.css.ts:835`), which takes `min-height: 44px` and no padding at all and measures 39px wide. Both were filed by independent reviewers and both are live. RULED: a phone override that floors a control which declares an explicit sub-floor `width` must also reset it (`width:auto; min-width:44px`), and a phone override on a shrink-wrapped inline-flex anchor must declare non-zero horizontal padding — the padding clause of the ruling is a requirement, not a suggestion. The live population of the width shape is exactly one rule today, so it is pinned by a targeted receipt rather than a new ratchet; a second sighting promotes it to a scan.
