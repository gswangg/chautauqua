# DEC-367: The disabled token's two legal uses become executable at phone widths

DESIGN-RULINGS.md gives the token exactly two legal uses -- an inert control and a drag handle -- and states why the boundary is not cosmetic: "#8E8A7A on #DDD8C8... fails the 4.5 floor at 3.06:1 on paper, so anything carrying meaning in it is unreadable by someone who needs the contrast", and records that the token escaped into three separate designs in consecutive rounds, each time as "the quiet version of something". test/disabled-token-uses.scan.test.ts exists but the mandate's Tier-2 list still carries "disabled-token compliance (two legal uses) at phone sizes" as unbuilt, and phone blocks are precisely where a de-emphasis reflex reappears (a phone card has no column to recede into, so the temptation is to grey the text). RULED: the existing scan's population is extended, in its own idiom, to every rule inside a max-width <= 700px block across app/src/**/*.css and src/**/*.css.ts; a use there is legal only when its selector resolves to an inert control (:disabled / [disabled] / [aria-disabled]) or to the codebase's own drag-handle token (derived from the source, not guessed); everything else fails carrying the ruling's own sentence and the offending file and selector. De-emphasis stays weight, not lightness: 800 -> 600 at #565A4B. Exemptions structural and two-sided, so a stale one fails with delete-this-line.

## Amendment (wave 94): A cascade shadow is LIVE only when no later declaration that also applies at 390 restores the phone value; the scan counts live shadows and its ratchet goes to zero-tolerance

Both cascade scans compare a phone `@media` declaration only against later TOP-LEVEL rules, never against a later `@media (max-width: …)` block — which is the codebase's own sanctioned repair. Measured on main: all 19 counted pairs are already repaired (app/src/styles.css:2360 restates all 12 by name, review.css:2589 restates both, contacts-panels.css:1646 restates all 3), so the metric reads 19 while the number of declarations that actually lose at 390 is zero. That is why `SHADOWED_CEILING` has gone red in three consecutive waves and why no lane can ever drive it down: under the append-only repair rule, every repair leaves its own pair counted forever, so the metric's floor is the count of repairs, not the count of defects. A two-sided ratchet on a number nobody can move is a permanent red with no owner. RULED: a phone declaration is shadowed only when NO later declaration for the same selector+property, in any block whose media condition still matches at 390px (top-level, or a max-width block with threshold >= 390), restores it. With the correct metric the count is 0, so the ratchet becomes zero-tolerance rather than two-sided, and the falsifiability control changes from "content.css and comms.css read zero" (vacuous once everything reads zero) to a synthetic fixture pair: one sheet with an unrepaired shadow that MUST be flagged, one with the repair appended that must NOT be. Also ruled in the same breath: app/src/phone-cascade-order.scan.test.ts computes block offsets on comment-STRIPPED text and then slices bodies out of the RAW text, so every offset after the first comment is shifted and the app-side scan has been reading the wrong bytes while passing green — the slice must use the same string the offsets were computed on.

## Amendment (wave 120): an UNDECLARED height is the tap-floor scan's blind spot — a control rule that names no height at all is a candidate

`app/src/phone-tap-target.scan.test.ts`'s base scan (`findOffenders`, :92-116) computes `declaredHeightPx(body)` and does `if (height === undefined || height >= TAP_FLOOR_PX) continue` — so a control whose rule declares NO height and NO min-height is dropped from the population before any floor test runs. That is the exact inverse of the truth: a control that declares no height cannot reach 44px except by accident of line-height. `docs/probes/metafid-phoneB-ssr-2026-08-19.md` measured `.chq-review-queue-footer-showall` at 52x30 on a live 390 probe; its rule (app/src/pages/review/review.css`.chq-review-queue-footer-showall {`) is a border/background/padding reset (`border: none`, `background: none`, `padding: 0`, `font-size: 13px`) on a real `<button type="button">` (ReviewerQueue.tsx`className="chq-review-queue-footer-showall"`, PlanEditor.tsx`className="chq-review-queue-footer-showall"`), and both `SSR_TAP_FLOOR_OFFENDERS_CEILING` and `SSR_UNFLOORED_TOKENS_CEILING` read 0 while the base scan's assertion passes green. I measured the whole class on a clean archive of main at 885bceb8 with a throwaway probe reusing the scan's own core helpers: 36 tap-target-tag tokens whose top-level rule declares no height, no min-height, no phone-scoped >=44px override and no named exemption, across 14 sheets — bounded and enumerable, not a flood. The mandate's Tier-2 line for this sweep says "measure, don't grep — the ruling names two evasion modes"; the scan implements neither. RULED: candidacy widens — a token in the base tap-target population (`<input>`/`<select>`/`<button>`/`<a class=chq-btn>`) whose top-level rule declares no height property at all is a candidate. It is cleared by (a) a phone-scoped `min-height >= 44px` reaching the token, (b) COMPOSITION — every markup site carrying the token also carries a token that is itself floored, derived from the TSX class lists, never hand-listed (this is what makes `.chq-btn-primary`/`.chq-btn-secondary` false members), or (c) a named `tap-floor-exempt:` whose reason is a fact about the control. Because this is a PREDICATE REPAIR and not a regression (DEC-989 clause c), it lands as its OWN two-sided ratchet, `UNDECLARED_HEIGHT_OFFENDERS_CEILING`, seeded at the count the repairing branch measures, in a NEW file so it does not contend with the three drain lanes editing the anchor ceiling; its header must say PREDICATE REPAIR, name the blind `height === undefined` line it replaces, and state why the old zero was blind. The name is added to `scripts/exit-predicate.ts`'s `CAMPAIGN_CONSTANT_NAMES` in the same commit — an ungraded ratchet fails `assertCampaignPopulationTotal` loudly, and a new non-zero row that pushes `CAMPAIGN: DONE` further away is the correct outcome when the instrument was lying.
