# DEC-367: A base-scope 44px floor is legal in the portal sheet when its receipt cites DESIGN-RULINGS item 6, and the scan that grades it must strip CSS comments first

test/ssr-tap-floor-scope.scan.test.ts is RED on main at src/routes/portal/portal.css.ts:330 and :344, and the two failures have opposite causes. :344 is `.chq-portal-headshot-pick`'s real `min-height: 44px`, landed by DEC-576 wave-21 to build the frame's bordered pill (Public and Portal.dc.html:541) at top level — deliberately, because DESIGN-RULINGS.md item 6 rules the portal has no separate desktop design, so a phone-scoped floor there would be wrong, not right. The scan's grammar knows only one receipt shape (`/* tap-floor-exempt: */`) and cannot express "this floor is legal at every width", so a correct build reads as a violation. :330 is not a declaration at all: it is the frame literal `min-height:44px` quoted inside that rule's own DEC-576 comment, matched because findViolations runs its regex over raw, un-stripped source — the same comment-blindness DEC-374 already names, here producing a false positive instead of a vacuous pass. RULED, two clauses. (a) findViolations strips CSS comments before matching, importing test/helpers/strip-css-comments.ts's shared stripper rather than minting a second one (DEC-613), with a positive control proving a commented-out 44px is no longer flagged and a negative control proving a real one still is. (b) The grammar gains a SECOND accepted receipt, `/* tap-floor-base-scope: <reason naming DESIGN-RULINGS.md item 6> */`, legal only in src/routes/portal/**; every other SSR sheet keeps the phone-scoped rule unchanged. An exemption reason stays a fact about the surface, never a per-site allowlist.

## Amendment (wave 24)

BUILT. Both clauses land in this wave (task w24-b), plus two adjacent DEC-393-shaped fixes the same red run surfaced:

(a) test/ssr-tap-floor-scope.scan.test.ts's `findViolations` now matches `min-(?:height|width):\s*44px` against a copy of the source run through test/helpers/strip-css-comments.ts's shared `stripCssComments` (never a second private stripper, DEC-613) — never the raw text. That stripper replaces a removed comment's body with the same count of newlines it held, so line numbers computed off the stripped copy still agree with the original file; a `/* tap-floor-exempt: */` or `/* tap-floor-base-scope: */` receipt is therefore looked up by LINE against the ORIGINAL (unstripped) source, checked at both the declaration's own line and its enclosing rule's selector line (a receipt documenting a whole rule sits above the selector; a receipt for a single declaration sits directly above it — both idioms already lived in this file). :330's frame-quoting DEC-576 comment no longer trips the scan; a positive control proves a commented-out 44px stays unflagged and the existing negative controls (a real declaration, an exempt-commented one) are untouched.

(b) The grammar's second receipt shape, `/* tap-floor-base-scope: <reason> */`, is recognised only when the file is under `src/routes/portal/` and the reason names `DESIGN-RULINGS.md item 6` literally — a receipt of any other shape, in any other directory, or naming any other reason still flags. `.chq-portal-headshot-pick` in src/routes/portal/portal.css.ts now carries that receipt directly above its selector, restating in receipt form the fact its DEC-576 comment already states in prose; the DEC-576 citation itself is untouched (DEC-967: never re-point a citation).

Two DEC-393-shaped defects rode along on the same red run, both in src/routes/portal/portal.css.ts: `.chq-portal-preview-banner-link` (preview.tsx's "Back to settings" link) had no floor receipt of its own and a bare `white-space: nowrap` with no overflow escape. Its `white-space: nowrap` is overridden to `normal` inside the sheet's one terminal `@media (max-width: 700px)` block (DEC-385 single-direction: narrow overrides wide, appended last, never edited in place), letting it wrap the way its `flex-wrap` row already does at 390 instead of forcing the row wide.
