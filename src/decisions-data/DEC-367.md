# DEC-367: A base-scope 44px floor is legal in the portal sheet when its receipt cites DESIGN-RULINGS item 6, and the scan that grades it must strip CSS comments first

test/ssr-tap-floor-scope.scan.test.ts is RED on main at two spots in src/routes/portal/portal.css.ts, and the two failures have opposite causes. src/routes/portal/portal.css.ts`.chq-portal-headshot-pick {` is the rule whose real `min-height: 44px;` declaration, landed by DEC-576 wave-21 to build the frame's bordered pill (Public and Portal.dc.html:541) at top level — deliberately, because DESIGN-RULINGS.md item 6 rules the portal has no separate desktop design, so a phone-scoped floor there would be wrong, not right. The scan's grammar knows only one receipt shape (`/* tap-floor-exempt: */`) and cannot express "this floor is legal at every width", so a correct build reads as a violation. The other spot is not a declaration at all: src/routes/portal/portal.css.ts`background:#EFEBDF; min-height:44px; display:flex; align-items:center;` is the frame literal quoted inside that same rule's own DEC-576 comment, matched because findViolations runs its regex over raw, un-stripped source — the same comment-blindness DEC-374 already names, here producing a false positive instead of a vacuous pass. RULED, two clauses. (a) findViolations strips CSS comments before matching, importing test/helpers/strip-css-comments.ts's shared stripper rather than minting a second one (DEC-613), with a positive control proving a commented-out 44px is no longer flagged and a negative control proving a real one still is. (b) The grammar gains a SECOND accepted receipt, `/* tap-floor-base-scope: <reason naming DESIGN-RULINGS.md item 6> */`, legal only in src/routes/portal/**; every other SSR sheet keeps the phone-scoped rule unchanged. An exemption reason stays a fact about the surface, never a per-site allowlist.
