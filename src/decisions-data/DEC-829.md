# DEC-829: The Speakers roster lists every participant of an accepted submission; ACTIVE is the predicate for expansion and access, never for LISTING

## Amendment (wave 110): the speaker-detail rail has its own register -- a rail row is two lines, and a rail empty state is one line

docs/design/Chautauqua Speakers.dc.html:411-425 draws `Across your events` as 10px-padded rows separated by hairlines, each a 14px/600 event name over a 13px muted participation line (`Spoke · Build Caches in Anger`, `Submitted, declined`). Live renders `<li>{e.name}</li>` -- the participation half of the row, which is the only reason the section exists, is missing -- and its empty case reaches for the page-scale EmptyState (24px headline, 44px of top room) inside a 320px rail. RULED: `otherEvents` carries the participation sentence from the server rows that already produce eventName/startDate (no new query); the rail's empty case is one muted 14px line, achieved by scoping the existing component under `.chq-speaker-detail-rail` rather than minting a second empty-state component. This is a desktop change and it is legal: the v12 desktop frame demands it.

## Amendment (wave 112): the speaker rail's section labels are aggregates the frame spells, not raw lengths

Chautauqua Speakers.dc.html:319 ("Speaker detail") spells four section labels literally. Three disagree with the app: the frame draws `Sessions · 1 accepted` where SpeakerDetailPage.tsx:531 prints a raw `sessions.length`; `Tasks · 2 outstanding` where :577-583 prints a three-part `Tasks · N · N outstanding · N overdue`; and `Across your events` with NO count where :686 appends `· {otherEventsCount}`. `Files · 3` already matches, which proves the divergence is not a house idiom but three separate drifts. RULED: each label renders the frame's aggregate. The accepted count derives from `detail.sessions[].status`, already in the DEC-930 payload -- no new query and no new wire field. `otherEventsCount` keeps its reader as the list cap (a declared value with no reader is a lie, DEC-851/988); it simply stops appearing in the label. This is a desktop-affecting change and is legal precisely because a v12 desktop frame demands it.
