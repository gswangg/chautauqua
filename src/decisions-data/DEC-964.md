# DEC-964: wave-21: the Comms compose step rail names the population it can HONESTLY compute at the step it is drawn — a send report's recipient total at step 4, the submission selection before it

docs/design/Chautauqua Comms.dc.html draws the rail's Recipients row detail as `23 accepted speakers` at BOTH step 1 (:376) and step 4 (:469) — a PEOPLE count, matching the step-4 headline `21 of 23 speakers were emailed` (:497-498, which already MATCHES). app/src/pages/comms/ComposeWizard.tsx`stepMeta`'s recipient-detail row computes that detail once, off `selection.selectedIds.size` via `countOf(..., 'submission')`, on every render regardless of step — so at step 4 it still reports the step-1 submission-selection count. docs/design/audit/comms-compose-desktop-v12.md:128-144 records this as "a behavioural gap, not a wording-only residual", explicitly outside DEC-902 waves 8/9/14m, and "Left open, ungoverned". RULED, and the audit row's premise is corrected in the same breath: the frame does NOT change vocabulary across steps — it draws the identical literal at :376 and :469 — so the divergence is that the tree names submissions where the frame names people, at every step. The fix is scoped to step 4 anyway, because of computability, not taste: before a preview runs, the app genuinely does not know the recipient population (expandRecipients has not run and one speaker can carry several submissions), and DEC-652's standing rule is that a value the server has not computed is absent, never invented. So at `step === 'sent'` with a `sendResult` in hand the Recipients detail names the recipient total that send actually addressed (sent + failed + skipped — the same arithmetic the matching headline already uses); at every earlier step it keeps the honest submission-selection count, and that limit is RECORDED in the audit row rather than left as open debt. The frame's `accepted` qualifier is not adopted: it describes the frame's own fixture (a selection drawn from accepted submissions), and compose can address any selection, so the noun follows the send headline's own already-matching `speakers`. Desktop-frozen is not engaged — a v12 desktop frame is what demands this change.
