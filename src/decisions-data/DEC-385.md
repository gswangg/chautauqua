# DEC-385: Amendment (wave 103): a shadow can be load-bearing — a newly-winning phone declaration the frame contradicts is DELETED with the frame line as its receipt, never kept and never re-shadowed

DEC-385 wave-102 already rules that consolidation merges in ascending source order and that "a rule whose meaning changes under the merge is a finding, never a silent edit" — but it never says what the lane DOES with the finding, and this wave merges the four heavy sheets (review.css 11 blocks, styles.css 5, submissions.css 4, detail.css 3) that were deferred precisely because they are the risky ones. Consolidation moves every phone rule after every desktop rule, so a declaration that only ever slept because a later top-level rule beat it starts winning at 390 the moment the wrapper is deleted. Three outcomes exist and two are wrong: keeping it ships a 390 behaviour change no frame asked for, and re-introducing a shadow to suppress it re-creates the exact silent-cascade defect the one-block contract exists to kill. Deleting the declaration and citing the frame line that contradicts it is the only outcome that leaves the sheet single-valued and the removal auditable. Measured basis: all four heavy sheets already END in a phone block, so the fix is a pure forward-merge and every behaviour delta is attributable to a specific unshadowed declaration.

## Amendment (wave 111): a non-terminal phone block is fixed by moving the PHONE block, never by moving the desktop rules above it

Measured on a clean `git archive` of main `1bed0d2c`: `test/phone-terminal-block.scan.test.ts` is the fast tier's ONLY red, 8 of 33 sheets. Seven of the eight carry N>1 phone blocks and are fixed by the established forward-merge (concatenate each earlier block's body into the sheet's LAST top-level construct, in ascending source order, never reordering, never silently deduping — a collapsed duplicate names its discarded declaration in a comment). The eighth, `src/routes/public/css/chrome.css.ts`, is a different shape: it already has exactly ONE phone block, and its defect is purely that a top-level `.chq-pub-searchform` rule (plus a `prefers-reduced-motion` block) follows it. The obvious fix — hoist those trailing rules above the phone block — is ILLEGAL under this campaign: moving a desktop rule earlier changes which desktop declaration wins an equal-specificity tie, and desktop is frozen. Ruling: relocate the PHONE block verbatim to the file's true end; the desktop rules keep their relative order exactly. Same reasoning generalises — the consolidation edit may only ever move phone-layer bytes.

## Amendment (wave 104): a local phone-block-count pin is RETIRED, not satisfied — and the shared terminal-block audit table is edited one row per lane, never its total

Seven consolidation lanes run in parallel this wave over 12 sheets, and two hazards are already visible on main. (1) Local pins that COUNT phone blocks contradict the one-terminal-block contract by construction: `app/src/pages/content/content-phone-floor.test.ts:138` asserts content.css "declares at least two top-level `@media (max-width: 700px)` blocks", and `app/src/components/modal-frame-phone.w7g.test.ts` extracts "the" phone block with a non-greedy `([\s\S]*?)\n\}` and then asserts a bare `.chq-modal-head {` is ABSENT from it — an assertion whose truth depends on there being four blocks. These are the same shape as the `settings-phone-floor` `>=5` pin the merge train retired at `76a24f90`: a lane must DELETE or re-express such a pin against the merged single block, never contort the merge to keep it green. `test/phone-terminal-block.scan.test.ts` is the single owner of block-count truth; a second, disagreeing counter is the defect DEC-385 wave-98 already replaced once. (2) `docs/design/audit/terminal-phone-block-v12.md` is the one file every lane touches, and it carries a hand-written total ("20 sheets are non-conformant") that three in-flight w3 lanes are already rewriting in three different directions. The total is derivable on demand from the scan and is worth nothing that the scan does not already print. So: a lane deletes ONLY the table row(s) for the sheet(s) it owns and appends ONE paragraph naming its task, its sheets, its before/after cascade measurement, and any declaration it deleted under wave-103; it does NOT touch the count sentence, which the merge train re-derives once per batch. This keeps eight concurrent editors conflict-free on the only line all eight would otherwise fight over.

(1) A review lens flagged DEC-385 wave-104's retirement of local phone-block-count pins (content-phone-floor.test.ts:138, modal-frame-phone.w7g.test.ts:33/73, the auth/public indexOf slices) as a test-weakening move. RULED, so the next lane does not merely delete: retiring a block-count pin obliges the SAME test file to keep asserting the declarations that pin was implicitly guarding, anchored on the terminal block, with a last-match rule-extractor. A pin that contradicts the one-block contract is wrong about the count and right about the content; only the count is retired. (2) Ten lanes run this wave against six shared ratchets. RULED: no worker lane edits OVERFLOW_OFFENDERS_CEILING, ANCHOR_FLOOR_OFFENDERS_CEILING, CLAIMED_FLOOR (phone OR desktop ledger), UNRECEIPTED_CLAIM_CEILING, PHONE_HIDDEN_UNRECEIPTED_CEILING, FRAME_RECEIPT_OFFENDER_CEILING, or the hand-written totals in docs/design/audit/*.md. A consequence the desktop lanes must expect: the desktop ledger's two-sided `never claims MORE than CLAIMED_FLOOR` test goes RED on every branch that lands new claims. That redness is the ratchet working, not a failure to fix.

## Amendment (wave 107): the desktop-freeze pin's population is every stylesheet, not styles.css

"Desktop is FROZEN: phone work lives in max-width media blocks (DEC-385 single-direction)" is a non-negotiable hard rule of the mandate, and the only instrument behind it is an it() titled "no min-width media query anywhere in styles.css" — over one file, in a scan about something else. Every other campaign scan long ago learned that one file is not a population and a directory glob is not one either (DEC-808/DEC-367: a `src/**/*.css.ts` glob silently drops src/views/theme.ts, which has no .css.ts suffix). Measured on main: zero `@media (min-width:` exists anywhere in app/src/**/*.css or the SSR *_CSS modules, so widening the pin to the derived population via test/helpers/ssr-css-sources.ts's ssrCssSources() — the same helper the density and cascade scans already share — lands green and costs nothing. It ships with a synthetic positive control and a vacuous-population tripwire so it cannot pass by scanning nothing, which is the failure mode a green one-file pin was one refactor away from.

## Amendment (wave 138): a phone-only inline script gates its own initialization on the breakpoint its stylesheet gates the chrome on — 'the desktop stylesheet never reads this attribute' is not inertness

`src/routes/public/cfp-steps-script.tsx`'s header claims the wizard 'is inert there too' on desktop because the step chrome is `display:none` outside the phone block. The claim is false: `cfp.css.ts` has exactly ONE `@media` (max-width:700px, :214) and every `[data-chq-cfp-step=...]` rule lives inside it, so on desktop both sections stay visible — but the script's unconditional `setStep('1')` at DOMContentLoaded (:95) still runs `applyRequiredState(youSection, false)`, which STRIPS `required` off the visible Name/email speaker controls, and still calls `form.scrollIntoView()`, which jump-scrolls the desktop page past its header on load. A phone affordance is silently deleting desktop form validation on the public CFP — a live breach of the campaign's desktop freeze, and a correctness regression independent of it. RULED: a script that exists to drive a phone-only chrome guards its initialization on `window.matchMedia('(max-width: 700px)')` (and re-evaluates on change, restoring `data-chq-cfp-step="all"` and every stashed `data-chq-cfp-required-orig` when the query stops matching), so that at desktop width the wizard mutates nothing — no attribute, no `required`, no scroll. Inertness is proved by a test at desktop width, not asserted in a comment.
