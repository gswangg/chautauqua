# DEC-385: Amendment (wave 103): a shadow can be load-bearing — a newly-winning phone declaration the frame contradicts is DELETED with the frame line as its receipt, never kept and never re-shadowed

DEC-385 wave-102 already rules that consolidation merges in ascending source order and that "a rule whose meaning changes under the merge is a finding, never a silent edit" — but it never says what the lane DOES with the finding, and this wave merges the four heavy sheets (review.css 11 blocks, styles.css 5, submissions.css 4, detail.css 3) that were deferred precisely because they are the risky ones. Consolidation moves every phone rule after every desktop rule, so a declaration that only ever slept because a later top-level rule beat it starts winning at 390 the moment the wrapper is deleted. Three outcomes exist and two are wrong: keeping it ships a 390 behaviour change no frame asked for, and re-introducing a shadow to suppress it re-creates the exact silent-cascade defect the one-block contract exists to kill. Deleting the declaration and citing the frame line that contradicts it is the only outcome that leaves the sheet single-valued and the removal auditable. Measured basis: all four heavy sheets already END in a phone block, so the fix is a pure forward-merge and every behaviour delta is attributable to a specific unshadowed declaration.

## Amendment (wave 104): a local phone-block-count pin is RETIRED, not satisfied — and the shared terminal-block audit table is edited one row per lane, never its total

Seven consolidation lanes run in parallel this wave over 12 sheets, and two hazards are already visible on main. (1) Local pins that COUNT phone blocks contradict the one-terminal-block contract by construction: `app/src/pages/content/content-phone-floor.test.ts:138` asserts content.css "declares at least two top-level `@media (max-width: 700px)` blocks", and `app/src/components/modal-frame-phone.w7g.test.ts:33,73` extracts "the" phone block with a non-greedy `([\s\S]*?)\n\}` and then asserts a bare `.chq-modal-head {` is ABSENT from it — an assertion whose truth depends on there being four blocks. These are the same shape as the `settings-phone-floor` `>=5` pin the merge train retired at `76a24f90`: a lane must DELETE or re-express such a pin against the merged single block, never contort the merge to keep it green. `test/phone-terminal-block.scan.test.ts` is the single owner of block-count truth; a second, disagreeing counter is the defect DEC-385 wave-98 already replaced once. (2) `docs/design/audit/terminal-phone-block-v12.md` is the one file every lane touches, and it carries a hand-written total ("20 sheets are non-conformant") that three in-flight w3 lanes are already rewriting in three different directions. The total is derivable on demand from the scan and is worth nothing that the scan does not already print. So: a lane deletes ONLY the table row(s) for the sheet(s) it owns and appends ONE paragraph naming its task, its sheets, its before/after cascade measurement, and any declaration it deleted under wave-103; it does NOT touch the count sentence, which the merge train re-derives once per batch. This keeps eight concurrent editors conflict-free on the only line all eight would otherwise fight over.

## Amendment (wave 105): a retired local pin is REPLACED, not deleted; and ratchet constants plus audit-doc totals are merge-train property for the whole batch

Two rulings, one subject: what a worker lane may not decide alone. (1) A review lens flagged DEC-385 wave-104's retirement of local phone-block-count pins (content-phone-floor.test.ts:138, modal-frame-phone.w7g.test.ts:33/73, the auth/public indexOf slices) as a test-weakening move. Verified against v12m-w4-b: the retirement there is done correctly -- the `>=2 blocks` sanity `it()` is deleted, but every downstream assertion is re-anchored on the terminal block and the file's `ruleBody` helper was changed to return the LAST equal-specificity match, because after a forward-merge one selector can legitimately be declared twice in one block and source order decides which reaches the browser. RULED, so the next lane does not merely delete: retiring a block-count pin obliges the SAME test file to keep asserting the declarations that pin was implicitly guarding, anchored on the terminal block, with a last-match rule-extractor. A pin that contradicts the one-block contract is wrong about the count and right about the content; only the count is retired. (2) Ten lanes run this wave against six shared ratchets. RULED: no worker lane edits OVERFLOW_OFFENDERS_CEILING, ANCHOR_FLOOR_OFFENDERS_CEILING, CLAIMED_FLOOR (phone OR desktop ledger), UNRECEIPTED_CLAIM_CEILING, PHONE_HIDDEN_UNRECEIPTED_CEILING, FRAME_RECEIPT_OFFENDER_CEILING, or the hand-written totals in docs/design/audit/*.md. The merge train re-measures each ONCE per batch (DEC-385 wave-93, exercised at 9e7a54b4). A consequence the desktop lanes must expect: the desktop ledger's two-sided `never claims MORE than CLAIMED_FLOOR` test goes RED on every branch that lands new claims. That redness is the ratchet working, not a failure to fix.
