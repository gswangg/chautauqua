# DEC-939: A rating scale is a radio group of EQUAL segments filled in brand, read at the product measure, and the conflict declaration comes AFTER the work

A review rating scale renders as a radio group of equal-width segments filled in the brand colour and read at the product's own measure; any conflict declaration a scorer must make is asked after the scoring work, not before it.

## Amendment (wave 148): the admin header's page-owned portal slot carries a wizard's step breadcrumb, desktop-only, from the wizard's own step state

`Chautauqua Comms.dc.html:757` draws 'Comms · Compose · step 3' in the 1600 header band between the wordmark and the event name. This DEC's own amendment created `#chq-header-slot` as a page-owned portal target inside the header identity group (`app/src/styles.css:2118-2123`) precisely so a page can inject header content without editing the shell — `app/src/pages/review/Scorecard.tsx:583-605` is the working precedent (createPortal, `!isPhone`, renders nothing when the node is absent). This amendment extends that idiom from a progress counter to a wizard breadcrumb, with two constraints: the step index comes from the wizard's EXISTING `step` state (never a second counter, DEC-613), and the mount is desktop-only because the 390 Comms frames draw no header breadcrumb — a phone mount would put the string in the DOM where no frame asks for it. This is a desktop-affecting change legal under the freeze only because a v12 desktop frame demands it; no shell file (`App.tsx`, `styles.css`) is edited.
