# DEC-702: Wave-59 amendment: a seeded per-entity fixture value indexed by a GLOBAL counter is not per-entity variation — index by the entity

scripts/seed.ts indexes the 8-item EVAL_COMMENTS array with a single global evalCounter, so any two evaluations by the same reviewer whose call-count gap is a multiple of 8 receive byte-identical comment text; the fresh-seed re-derivation recorded in docs/eval-findings.md item 13 shows seed_evaluation_0002/0058 and 0003/0059 colliding for reviewer seed_user_0004 (gap 56). A fixture whose whole purpose is to give a judge distinguishable review prose fails silently in exactly the persona the eval reads hardest. This is the same family as DEC-702's own wave-10 amendment about hand-computed offsets into a shared id space silently colliding when an earlier section's row count changes. RULED: the comment selection is keyed on the evaluating entity (reviewer id, or reviewer id combined with the submission), not on a global monotonic counter, so two evaluations by one reviewer can never draw the same string while the array has unused members; the DEC-707 cap-saturation fixture on plan 4 and the DEC-854 four-distinct-reviewer fixture on plan 3 are load-bearing and must survive byte-for-byte in row COUNT and scope, only the comment text varying.
