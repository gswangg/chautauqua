Adjudicated: the DESKTOP frame (Content.dc.html:308) draws `Other · 5` while the PHONE frame (:344-346) draws NO residual chip over the SAME 31-file library — the pack contradicts itself about whether the chip exists. Precedent is settled (Speakers :57 vs :469): a pack-internal inconsistency is a captioned ruling, not a defect. ## Amendment (wave 8): An additive control is not a divergence to fix; a control the frame draws and the app omits is

Four carried audit rows are all of one shape — the tree draws MORE than the frame: Content's status band adds a `Request changes` secondary and its title row adds `Edit title and abstract ›`/`Revision history ›` (content-agenda-desktop-v12.md :111); Overview keeps `Open` beside the two decisions; Content Files names each `LIBRARY_KIND` where the frame compresses to `Other · N`. Removing any of them is capability removal — and in the Files case the pack contradicts itself outright (desktop :308 draws the residual chip, the PHONE frame :344-346 draws none over the same 31-file library, the Speakers :57/:469 precedent). Ruled: a frame's control list is a FLOOR, not a ceiling. An extra control that adds real capability is blessed and its row is retired with a caption; a control the frame draws that the app cannot fire is the gap, and that is the only shape that buys a lane. The upload-refusal band (:434) resolves the same way in the other direction: the tree renders `src/domain/files.ts`'s own server-enforced refusal rather than the frame's bespoke sample prose, which DEC-967's 'frame sample data is not product copy' already settles.

## Amendment (wave 14m): a wording-only residual against a desktop frame is adjudicated, never deferred to the freeze

Roughly fifteen open rows are pure copy residuals against a v12 desktop frame -- Contacts' footer primary reading 'Add to the pipeline' where the frame draws 'Add to pipeline' (frame :661 vs :624), the merge back link reading '< Contacts · Duplicates' where the frame draws '< Duplicates' (:359), the merge consequence line naming the record where the frame writes 'the kept record' (:388), the EnrollDialog's absent per-contact subtitle (:625), the Comms attachments panel dropping 'and merge fields' (:96), Contacts-import's heading wording, Settings' embed-edit H1. Every one of them is currently parked with the same non-verdict: 'filed here as measurement; not fixed (desktop is frozen)'. That reading of the freeze is wrong. docs/mobile-campaign.md's rule is that PHONE work lives in max-width blocks and must not move desktop, and that 'a desktop-affecting change is legal only when a v12 desktop frame demands it' -- a frame's own drawn literal is the paradigm case of a frame demanding it, not an exception to it. RULED: there is no third disposition for a wording-only row. Either (a) the tree adopts the frame's literal in the same commit, when the tree's wording carries no more information than the frame's (article count, word count, abbreviation); or (b) the tree's wording is blessed with a one-sentence reason, when it carries MORE information than the frame's -- it names the record instead of a generic noun, names the real vocabulary instead of a three-item sample, or states a live count instead of a static sentence -- which is DEC-902's own floor-not-ceiling axis applied to copy. 'Measurement only, desktop is frozen' is not an adjudication and does not close a row. Scope guard: this ruling reaches WORDING and nothing else; a geometry, track-set or control-count residual keeps its existing disposition under DEC-902 waves 8/9 and DEC-902 wave-12m.
