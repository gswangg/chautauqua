# DEC-681: A conditional rule's value is TYPED by its trigger field's kind, and the browser toggler computes the same transitive fixed point as the server — one matcher, parity-locked

## Amendment (wave 93): a visibility rule un-requires the whole radio group, not its first member

src/views/form-render.tsx:278 reads `wrap.querySelector('[data-field-id="..."]')` — singular — and toggles `.required` on that one node, but the CFP renders Format/Audience as N radios that each carry `required` and the same `data-field-id` (submit-views.tsx:288, :317). When a rule hides that field, radios 2..N stay `required` inside a `display:none` wrap and produce the same unsubmittable form as DEC-986's wave-93 amendment. The sibling read path at :241 already handles the group correctly (querySelectorAll, then look for `.checked`), so the file already knows a data-field-id is one-to-many; only the WRITE path assumed one-to-one. RULING: any DOM write keyed by `data-field-id` iterates querySelectorAll; a singular querySelector is legal only for a read whose group semantics make it unambiguous.
