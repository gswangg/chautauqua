# DEC-422: Free-text caps and the public rate limiter extend to the two write paths DEC-417's scope does not reach

Registry note: `src/decisions-data/part3.ts` has carried the `DEC_422` constant with this title since its original wave, but no `decisions/DEC-422.md`/`src/decisions-data/DEC-422.md` file was ever committed alongside it — a parity gap this file closes. The original ruling's full prose was not recovered; this file backfills the header from the standing constant so the decision has a body to amend, and records the wave-51 amendment below as new, verified content.

## Amendment (wave 51): a multipart part arriving as a File under a text field's name is REFUSED, not stringified — String(raw) on the public CFP persists the literal "[object File]"

src/lib/submit-core.ts:154's readSingleFormValue refuses arrays (`if (Array.isArray(raw)) return { ok: false }`) but coerces every other non-string with `String(raw)`. On the unauthenticated public CFP door a multipart part posted as a file under a text field's name (field_<title>) therefore becomes the 15-character string '[object File]', which validateAnswers sees as a well-formed answer and the repo persists. The function's own sibling readSingleFilePart already models the correct discipline for the inverse case, and the docstring's stated contract is 'reads a single-valued (text/select/textarea) answer part' — a File is not one. RULING: readSingleFormValue refuses any non-string, non-undefined value the same way it refuses an array, so the four doors that consume it (public submit, save-draft, portal edit, portal task form) surface REPEATED_ANSWER_MESSAGE's sibling per-field refusal instead of storing a coercion artefact. The wrong-part-type input class gets its own test; no test exercised it before.
