## Amendment (wave 22): Overview §01 overdue row is FOUR independently-hooked fields; each width's frame owns its pairing through grid placement, never through wrapper nesting

The two frames pair the SAME four fields differently. Desktop (docs/design/Chautauqua Overview.dc.html:80-87) draws name+company in column 1 and task+late in column 2. Phone (:220-224) draws name|late space-between on line 1, then `{{ row.task }} · {{ row.company }}` as ONE joined 13px muted string on line 2. Overview.tsx renders two ANONYMOUS wrapper <div>s hard-coding the desktop pairing, which is why docs/design/audit/overview-390-v12.md correctly recorded that no CSS-only fix inside overview.css's terminal max-width block can repair it: the two mis-paired fields sit inside the same wrapper as their line-mate, so no selector can move one without its sibling. RULED: the four fields render as four directly-classed spans (.chq-overview-row-name / -company / -task / -late) as direct children of .chq-overview-row-overdue, and each width expresses its own pairing by grid placement on that one container. Desktop reproduces the frame's `1fr 1.15fr auto` two-line columns with byte-identical rendered geometry (a DOM restructure whose desktop RENDER does not move is not a desktop change; the frozen-desktop rule protects the drawn result, not the wrapper count). Phone places name/late on line 1 and task·company on line 2 inside the terminal @media (max-width:700px) block only (DEC-385 single-direction), the separator drawn as a `::before { content: ' · ' }` on .chq-overview-row-company so the two fields read as the one joined string :224 draws. Any desktop pin asserting the anonymous wrappers is re-anchored on the new field hooks in the SAME commit (DEC-997: a raw pin falsified by a CORRECT product change is re-anchored, never loosened).
