# DEC-896: A width the pack draws on a field CONTAINER is a declared width the code must carry, not an absence of a comparable fact

docs/design/audit/desktop-field-width-v12.md files row 11 (the saved-embed Name/Surface/Format/Track 2x2 grid, drawn `max-width:620px` at Chautauqua Settings.dc.html:1021's frame) as UNRESOLVED with the adjudication "there is no declared value to compare the drawn 620px against… an honest absence of a comparable fact". Verified on 32436e11b: app/src/pages/settings/settings.css`.chq-settings-embed-field-pair` declares `display:grid; grid-template-columns:1fr 1fr; gap:12px` and no max-width at any width, so at the 820px settings measure the grid spans the full column — which is exactly the failure DESIGN-RULINGS B10 names in one sentence, "Field width follows content, not the column." An absence on the CODE side of a width the FRAME declares is a divergence, not an absence of a fact; grading it UNRESOLVED lets a real B10 miss hide inside an instrument-completeness bucket. RULED: `.chq-settings-embed-field-pair` carries the frame's `max-width: 620px` at top level (a desktop-affecting change the v12 desktop frame demands, the one exception the campaign's desktop freeze allows), the phone rule inside settings.css's single terminal max-width block is untouched, and the change is pinned by a CSS-shape assertion citing the frame line. This lane does NOT move the field-width ledger's join or its ceilings — the sibling lane owning that file measures the drain.

## Amendment (wave 49): the pack's prose-measure register is the next unmeasured geometry axis: 26 drawn `ch` clamps across 10 values against 9 served across 7, and five drawn measures the product never declares at all

Wave 48 probed every inline property in the pack against the served CSS and settled grid-template-columns as the last divergent axis. Re-running that histogram at main 405a4518b confirms its result (gap/align-items/justify-content/flex-direction/white-space/overflow all measure zero unmatched; box-shadow's 157 misses are the frame's own preview-card chrome `0 18px 44px rgba(27,29,23,0.13)`; width's 173 are frame device widths 1600/390/620; aspect-ratio's 5 are a normalisation artefact, `16/9` vs `16 / 9`) -- but it also shows the histogram's own blind spot: it grades a VALUE vocabulary, so a property the product barely declares at all reads as nearly clean. max-width is that property. The pack draws 26 `ch` clamps in 10 distinct values (52ch x10, 64ch x6, 70ch x2, 60ch x2, 78ch, 76ch, 62ch, 56ch, 54ch, 46ch); the tree declares 9 in 7 values, two of which (34ch, 32ch) the pack never draws, and 52ch -- the pack's single most-drawn measure -- is served exactly once. 70ch, 78ch, 76ch, 56ch and 46ch are drawn and never served anywhere. A prose block the frame clamps to a measure and the product renders to the full column is a fidelity divergence on BOTH widths, and no instrument in the tree can see it. RULED: the axis is MEASURED before it is repaired -- an audit doc and a two-sided ratchet keyed on the pack's drawn measure per frame extent, joined to the product's declared max-width for the block that renders it, with a vacuous-population tripwire on the drawn count; the lane moves NO CSS byte (desktop is frozen and several of these blocks are desktop-only), and the ceiling is registered OUT_OF_CAMPAIGN_SCOPE as a newly-derived population with a PARKED_FIDELITY_PROMISES row, per the same discipline every fresh measurement in this campaign has followed.
