## Amendment (wave 130): Settings edit-view head: the back link names the section it returns to, the H1 names the edit

DEC-896 already ruled that a shared settings shell owns the SLOTS but not the WORDS. The same defect now sits one level up, in the head: app/src/pages/Settings.tsx`&lsaquo; Settings` is the ONE hard-coded back label the shell renders for both drill levels (the entity, not the literal glyph — DEC-613's arrow-vocabulary point above), and :131 puts the section's own name in the H1. Every B10 edit view in the pack draws the opposite split — the section name is the BACK link and the H1 names the EDIT: `‹ Call for papers`/`Edit the form` (Chautauqua Settings.dc.html:632-633), `‹ Event`/`Edit the event` (:723-724), `‹ Tracks and rooms`/`Edit tracks and rooms` (:813-814), `‹ Speaker portal`/`Edit the speaker portal` (:894-895), `‹ People and roles`/`Edit people and roles` (:975-976), `‹ Your data`/`Edit your data settings` (:1136-1137). Verified on 9fa38009: none of those seven back labels occurs anywhere in app/src or src. The frame's two-level model needs no new state — editing is already pure URL state (`?section=<key>&edit=1`, Settings.tsx:128-129), so leaving an edit view is dropping `edit=1`, and a back link that names the section is then also HONEST about where it goes. Public pages gets no edit title (the pack's own DROP) and the :1046 saved-embed drill stays DEVIATIONS §6 deferred. This is a desktop-frame-demanded change, which the freeze explicitly permits.


## Amendment (wave 132): The settings row hint's right flush is a TRACK fact, not a text fact -- and a hint is prose, so it wraps

`text-align:right` occurs ZERO times in the entire Settings pack, yet `settings.css:1142` declares it top-level on `.chq-settings-row-hint`, together with `white-space:nowrap`. The frame's own row (Chautauqua Settings.dc.html:68-74) puts the note at the right EDGE by layout -- `justify-content:space-between` in the value cell -- while the note span declares neither property; the app reaches the same edge honestly through `.chq-settings-row`'s `170px 1fr auto` grid. So both declarations are improvisation that can only change what the frame never draws: the ragged edge of a wrapped hint, and whether it wraps at all. `white-space:nowrap` on a prose hint is additionally the exact overflow hazard `app/src/phone-horizontal-overflow.scan.test.ts:210` names by this selector, and it forced two counter-declarations into the phone block whose only job is to undo the base. RULED: the top-level rule drops both; the `auto` track keeps the right flush AND the collapse-when-absent, and the phone block drops the counter-declarations it no longer needs. The pin that asserted `text-align:right` under the title 'the meta column right-flushes its content so it collapses to nothing when absent' was asserting the wrong mechanism for a true claim -- it is re-derived onto the track, plus the absence of both properties on the hint.
