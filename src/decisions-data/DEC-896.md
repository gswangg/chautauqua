# DEC-896: A settings row is label / value / hint, and the rail names the section actually in view

## Amendment (wave 130): Settings edit-view head: the back link names the section it returns to, the H1 names the edit

DEC-896 already ruled that a shared settings shell owns the SLOTS but not the WORDS. The same defect now sits one level up, in the head: the shell rendered ONE hard-coded back label for both drill levels (the entity, not the literal glyph — DEC-613's arrow-vocabulary point above), and :131 puts the section's own name in the H1. Since this amendment landed the head composes that label from the section vocabulary instead — app/src/pages/Settings.tsx`{editingSection ? editingSection.label : viewingEmbeds ? 'Public pages' : 'Settings'}`. Every B10 edit view in the pack draws the opposite split — the section name is the BACK link and the H1 names the EDIT: `‹ Call for papers`/`Edit the form` (Chautauqua Settings.dc.html:632-633), `‹ Event`/`Edit the event` (:723-724), `‹ Tracks and rooms`/`Edit tracks and rooms` (:813-814), `‹ Speaker portal`/`Edit the speaker portal` (:894-895), `‹ People and roles`/`Edit people and roles` (:975-976), `‹ Your data`/`Edit your data settings` (:1136-1137). Verified on 9fa38009: none of those seven back labels occurs anywhere in app/src or src. The frame's two-level model needs no new state — editing is already pure URL state (`?section=<key>&edit=1`, Settings.tsx:128-129), so leaving an edit view is dropping `edit=1`, and a back link that names the section is then also HONEST about where it goes. Public pages gets no edit title (the pack's own DROP) and the :1046 saved-embed drill stays DEVIATIONS §6 deferred. This is a desktop-frame-demanded change, which the freeze explicitly permits.


## Amendment (wave 132): The settings row hint's right flush is a TRACK fact, not a text fact -- and a hint is prose, so it wraps

`text-align:right` occurs ZERO times in the entire Settings pack, yet `settings.css:1142` declares it top-level on `.chq-settings-row-hint`, together with `white-space:nowrap`. The frame's own row (Chautauqua Settings.dc.html:68-74) puts the note at the right EDGE by layout -- `justify-content:space-between` in the value cell -- while the note span declares neither property; the app reaches the same edge honestly through `.chq-settings-row`'s `170px 1fr auto` grid. So both declarations are improvisation that can only change what the frame never draws: the ragged edge of a wrapped hint, and whether it wraps at all. `white-space:nowrap` on a prose hint is additionally the exact overflow hazard `app/src/phone-horizontal-overflow.scan.test.ts:210` names by this selector, and it forced two counter-declarations into the phone block whose only job is to undo the base. RULED: the top-level rule drops both; the `auto` track keeps the right flush AND the collapse-when-absent, and the phone block drops the counter-declarations it no longer needs. The pin that asserted `text-align:right` under the title 'the meta column right-flushes its content so it collapses to nothing when absent' was asserting the wrong mechanism for a true claim -- it is re-derived onto the track, plus the absence of both properties on the hint.

## Amendment (wave 133): a Settings edit view carries TWO kinds of consequence text — one head-level line AND the per-section footers/field hints its frame draws; the head slot is not a bin for a folded-up section footer

`SettingsEditForm` exposes exactly one `consequence` prop, rendered as `.chq-settings-edit-consequence` right-flushed on the H1 baseline. The frames draw two distinct registers. `Chautauqua Settings.dc.html` head lines: `Renaming does not change the public URL` (Event, :726), `Only organisers can change roles` (People and roles, :978). Section-level lines, drawn INSIDE their `<section>` as the last child or as a field's hint: `Shown on the public pages and in calendar invites` under Venue (:768), `The swatch is how a track reads on the agenda and the public pages · a track in use cannot be removed — retire it instead and it stops appearing on the form` closing the Tracks section (:835), `Seats are advisory — the agenda flags an over-capacity room but never blocks it` closing the Rooms section (:852), `Takes the full measure · appears above the task list` under the Welcome note (:906), `Title and abstract stay organiser-only — a speaker editing them after acceptance would change what the committee accepted` closing 'What speakers may edit' (:919), `You cannot remove or demote yourself · a reviewer's scope limits which tracks they are assigned` closing the People section (:1003). Today `TracksRoomsPanel.tsx:152` folds :835 and :852 into ONE head consequence and `PeopleRolesPanel.tsx:404` puts :1003 in the head, so the section that causes the consequence never says so and the head says something the frame puts two screens away from its H1. RULED: a section-scoped consequence renders inside its own section (a `.chq-settings-edit-section-note` last child, or the field's existing `hint` slot for a field-scoped line), verbatim from the frame; the head `consequence` prop carries only the line the frame draws on the H1 baseline. A panel that has no head line in its frame passes no `consequence`.

## Amendment (wave 134): the Your-data view carries BOTH registers at once, and a section's own closing footer is not a bin for the head consequence either

Verified on `881eace7`: `YourDataPanel.tsx` already renders the wave-133-shaped head consequence (`Chautauqua Settings.dc.html:1139` "Retention applies to every event in this org", `.chq-settings-edit-consequence`, landed by DEC-781) — this amendment does not touch it. What was still missing is the SECTION-scoped half wave 133 ruled for: `Settings.dc.html:1164` closes the API-tokens section (inside `<div style="padding:30px 34px 36px…">`'s Tokens section, after the `sc-for` token list) with its own footer, "A token's secret is shown once, when it is created — after that only the prefix. Revoking takes effect immediately and cannot be undone." `ApiTokensPanel.tsx` used to draw two unrelated intro sentences ("The token is shown once, when you create it." / "Revoking takes effect immediately and cannot be undone.") ABOVE the create form, which is neither the frame's wording nor its position. RULED (mirrors wave 133's ruling, this time for a panel with no `SettingsEditForm`): the closing footer renders verbatim as the LAST content of `ApiTokensPanel`'s own `<section>`, after the token table, reusing `.chq-settings-edit-section-note` — the same class TracksRoomsPanel and the Rooms section already use for their own closing notes, per wave 133's ruling that this class is the shared home for every section-scoped register, not a new one per panel. A settings edit view with two frame-drawn registers (one head-level, one section-level) renders both, in both places; neither slot substitutes for the other.
