# DEC-896: A settings row is label / value / hint, and the rail names the section actually in view

## Amendment (wave 130): Settings edit-view head: the back link names the section it returns to, the H1 names the edit

DEC-896 already ruled that a shared settings shell owns the SLOTS but not the WORDS. The same defect now sits one level up, in the head: app/src/pages/Settings.tsx:293-297 renders ONE hard-coded `‹ Settings` for both drill levels, and :131 puts the section's own name in the H1. Every B10 edit view in the pack draws the opposite split — the section name is the BACK link and the H1 names the EDIT: `‹ Call for papers`/`Edit the form` (Chautauqua Settings.dc.html:632-633), `‹ Event`/`Edit the event` (:723-724), `‹ Tracks and rooms`/`Edit tracks and rooms` (:813-814), `‹ Speaker portal`/`Edit the speaker portal` (:894-895), `‹ People and roles`/`Edit people and roles` (:975-976), `‹ Your data`/`Edit your data settings` (:1136-1137). Verified on 9fa38009: none of those seven back labels occurs anywhere in app/src or src. The frame's two-level model needs no new state — editing is already pure URL state (`?section=<key>&edit=1`, Settings.tsx:128-129), so leaving an edit view is dropping `edit=1`, and a back link that names the section is then also HONEST about where it goes. Public pages gets no edit title (the pack's own DROP) and the :1046 saved-embed drill stays DEVIATIONS §6 deferred. This is a desktop-frame-demanded change, which the freeze explicitly permits.
