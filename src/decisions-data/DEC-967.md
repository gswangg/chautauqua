# DEC-967: A send is irreversible, so it asks once and names what it is about to do

## Amendment (wave 99): A frame receipt that only reads the frame proves nothing — an assertion must terminate in a repo artefact

`app/src/tautological-assertion.scan.test.ts` enforces DEC-967 by catching `expect(X).toBe(X)` with identical literals, and its header says there is exactly one offender in the tree with no allowlist by design. It cannot see the shape the mobile campaign actually produces: an `it()` that cites `docs/design/<file>.dc.html:<line>`, calls a `verbatimLine()` helper to prove the quote matches the DESIGN FILE byte for byte, and then asserts a regex against THAT SAME DESIGN-FILE STRING. Every such test passes forever no matter what the app renders. Two of them exist in `app/src/pages/settings/settings-phone-390.frames.test.ts` (:236, :260) and say so in their own titles — "(gap: read-drilled view does not yet render it)" — so the campaign has been shipping green receipts that document unbuilt work, which is precisely the pin-with-no-renderer failure DEC-576 was written against. RULED: the scan gains a second derived check. For every `it()` block anywhere under `app/src/` or `test/` whose body contains a `docs/design/*.dc.html:<line>` citation, at least one `expect()` in that block must take a subject that derives from a repo artefact — a `readFileSync` of a path outside `docs/design`, an imported module's value, or a render/DOM query — and never only from a design-file read. Seeded as a named two-sided ceiling with every offender printed, never an allowlist.

## Amendment (wave 100): DEVIATIONS.md is a set of CLAIMS ABOUT THE TREE and decays like one — it gets the derived ledger the frames and the rulings already have

DEVIATIONS.md is the third authority the goal names and the only one with no instrument at all. Every entry asserts something about the code — 'the app keeps the recorded A20 ruling', 'the Sort <select>'s phone display:none was DELETED', '.chq-submissions-columnpicker's phone display:none STANDS', 'NO STATUS CODE CHANGED' — and audits are told to cite this file INSTEAD of re-flagging, which means a stale entry silently suppresses a real finding. Decay is already demonstrated: §5 'Pending adjudication' is answered verbatim by §6's recorded adjudication and two waves re-read it as open work, and the 'v12 frame errata' CFP entry is being removed by an in-flight lane. Ruling: a derived ledger over the bullet entries of §1/§2/§3/§6, each with a verdict (honored / superseded-by-a-later-section / gap) and a cited artifact literal, two-directional so neither a new entry nor a removed one drifts. It must NOT edit DEVIATIONS.md (in-flight lanes own it) and must NOT transcribe rows out of the errata section, so the in-flight deletion cannot turn the ledger red.

## Amendment (wave 101): a derived ledger's EXCLUSION list is part of the derivation: a heading another lane deleted fails as absent, and the fix is to drop the exclusion — never to restore the heading to satisfy a test

`test/deviations-ledger.scan.test.ts` (landed by v12m-w3-e in this same merge train) asserts that both of its EXCLUDED_HEADINGS are genuinely present in DEVIATIONS.md, precisely so a renamed or moved heading fails loudly instead of silently widening coverage. It is now red because v12m-w14-b — whose own job was to close the `## v12 frame errata` CFP step-1 draft-dock item — landed in the same train and DELETED that section, exactly as w3-e's own header comment predicted it would. The guard is working as designed; what is wrong is the exclusion list, which now names a section that no longer exists. RULING: when an excluded heading disappears because its content was CLOSED, the exclusion entry is deleted and the presence assertion narrows to the headings that remain (`## 5. Pending adjudication` only). The heading is never re-added to DEVIATIONS.md to make the scan green — that would re-open a closed deviation in prose. The same rule applies to every document ledger in the tree (DESIGN-RULINGS, mobile-campaign): an exclusion that stops resolving is a work item that closed, not a regression.
