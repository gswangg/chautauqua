# DEC-967: Amendment (wave 103): a live-offender sentinel is DELETED when its population empties — never re-pointed at another live offender

app/src/tautological-assertion.scan.test.ts carries an it() block named `known-good: settings-phone-390.frames.test.ts:236 is a known offender inside the seeded ceiling (guards against the scan going silently empty)`. v12m-w2-l fixed that receipt 68 seconds before this wave was measured, and the guard went red for succeeding — main's newest red is a test failing because the campaign made progress. The tempting repair is to re-point the sentinel at one of the three surviving portal offenders, which would make the campaign's own exit condition depend on preserving a defect as a fixture: the last three tautological receipts could never be fixed without breaking the scan that finds them. The scan already writes a synthetic offender to a tmpdir in its POSITIVE control and a synthetic non-offender in its NEGATIVE control; those prove the detector still fires and still discriminates without needing a real defect to survive in the tree. So the live sentinel is redundant the moment zero is reachable, and it is deleted with a comment naming the synthetic controls as the anti-vacuity guard.

## Amendment (wave 104): a frame-receipt guard whose population is read from TITLES alone is evacuated by the very receipting protocol DEC-976 mandates — the population reads the it() body too, and widening a population is not raising a ceiling

`app/src/tautological-assertion.scan.test.ts:472` decides membership in the frame-receipt tautology population with `citationText = [block.title, ...enclosing.map(d => d.title)]` — TITLES only. DEC-976's wave-87/102 receipting protocol tells every lane to move citations OUT of describe/it titles and INTO an it()-body comment immediately above an `expect(`. The two rules cancel: every block the receipting campaign fixes also leaves the tautology guard's population, and `FRAME_RECEIPT_OFFENDER_CEILING`'s own comment records this happening ('the two settings-phone-390.frames.test.ts offenders left the population when DEC-976 wave-87 receipting moved their citations from the describe titles into it()-level comments'). A ratchet that falls because its population left is not progress. The proof landed on main 90 seconds before this wave measured: the merge-train repair at `02177950` restored the Settings :316 phone claim with a new `it()` at `app/src/phone-page-scaffold.test.ts:173` whose every `expect(` subject is a `docs/design` read compared to another `docs/design` read (`styleOf(settings[333])` vs `styleOf(speakers[277])`) — a pack-vs-pack assertion that carries a phone-ledger claim and is invisible to the guard because its citation is in a comment. Ruling: `citationText` includes the block BODY. Measured blast radius on `02177950`: the widened population adds exactly ONE offender, the block above; the other three are the portal frame containers `v12m-w3-m` is already fixing. Corollary, mirroring DEC-989 wave-95's 'a ratchet ceiling is re-measured in the change that reads it': widening a guard's POPULATION is not raising its ceiling — but where the widened truth still fits under the standing ceiling, the ceiling is left alone so the in-flight lane that is lowering it does not conflict.

## Amendment (wave 105): an anti-vacuity canary is the LAST offender closed, and never by the page lane that happens to own its sheet

`app/src/phone-horizontal-overflow.scan.test.ts:445` pins `.chq-review-scorecard-grid`'s fixed 1120px tracks as the scan's named live-offender canary, precisely so a regex that silently stops matching fails loudly instead of passing over an empty set -- and its comment records that the PREVIOUS canary (`.chq-speakers-grid` min-width) stopped serving the moment a lane exempted it. Wave 5 puts a lane inside scorecard.css for the first time since. RULED: a page lane may NOT close a rule that the scan names as its own canary; doing so turns the tripwire red and buys a one-offender reduction with the instrument's credibility. `.chq-review-scorecard-grid` is closed only in a commit that also re-points the canary at another verified live offender, authored by the lane that owns the scan file -- i.e. the merge train or a dedicated instrument lane, never a CSS sweep. The same rule generalises: before fixing any rule, check whether a scan cites it by name as a positive control, a known-good example, or a vacuity canary. This is the same failure DEC-967 wave-103 recorded when it DELETED the `settings-phone-390.frames.test.ts:236` live-offender sentinel rather than re-pointing it at another live offender.


## Amendment (wave 106): DEVIATIONS.md may not contradict itself, and a frame that draws an action the domain has no verb for is an unbuilt feature, not an open finding

DEVIATIONS.md is named by docs/mobile-campaign.md as an authority the audits cite instead of re-flagging, and it currently disagrees with itself: §5 'Pending adjudication (not yet blessed -- sweep should verdict)' still lists the tracks-and-rooms save model as needing a verdict, while §6 'Adjudications recorded' already states 'Tracks-and-rooms save model: per-row dirty-reveal BLESSED (G13 srv1 adjudication)'. An authority that answers the same question twice, differently, is worse than one that is silent, because a reader who stops at the first answer schedules work the second answer forbids. Second, docs/design/audit/portal-v12.md §2 records that 'Portal · Your tasks' (docs/design/Chautauqua Public and Portal.dc.html:476-501) draws a fixed dock at :492 holding 'Mark the release signed' + 'Later'. The profile half of that finding is being built by v12m-w15-b, but 'Later' has no verb behind it: grep over src/routes/portal/**.tsx returns zero matches for snooze, defer or later, and the portal task model exposes only complete-or-not. Building it would mean inventing a dismissal subsystem (what 'Later' persists, when the task returns, whether an organiser sees it) that no frame draws. RULING: §5's stale row is deleted -- an adjudication recorded in §6 is settled and §5 holds only genuinely open questions. The 'Later' control is recorded in §6's 'Unbuilt features (no data model or endpoint behind the drawing)' list, with the same shape as the Review 'Swap' row (DEC-745 wave-98): the frame's GEOMETRY for the dock is legitimate and may be built for whatever primary the page already renders, but the second button's copy is not manufactured. portal-v12.md §2 is amended to point at the ruling instead of staying open.
