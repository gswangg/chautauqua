# DEC-037: Wave-48 amendment: the outbound email card's masthead is TWO lines, and the second one is the event's own dates and venue

docs/design/Chautauqua Comms.dc.html:712-713 and docs/design/Chautauqua Speakers.dc.html:520-521 independently draw the 560px email card's masthead as a wordmark (19px/700/Familjen Grotesk/-0.025em) over a 12px #565A4B line reading `12-14 May 2027 . Moscone West, San Francisco`, above the #E1DDCE rule. src/mail/shell.ts renders only the wordmark; the second line exists in no outbound email this product has ever sent. Verified: grepping the whole tree for `Public and Portal.dc.html`/`Comms.dc.html:713` returns nothing, and the only two graders of this masthead (test/desktop-frames-comms.test.ts's `:712` it(), test/mail-shell-frame.test.ts's `renders the card, masthead, and body values from the frame`) assert the wordmark and stop. The data exists (src/db/schema/event.ts carries startDate, endDate, location) and the grammar exists (src/routes/public/shell.tsx's eventDatesLine composes exactly this string through formatEventDayRange, the ONE server-side calendar-day range grammar per DEC-918) -- so this is a missing render, not a missing capability. RULED: (a) EmailShellOptions gains `eventMeta?: string | null`, rendered as a second row inside the existing masthead table above its bottom rule, at the frame's 12px/MUTED_COLOR register, escaped, emitting nothing at all when absent or blank; (b) the composer is LIFTED, not copied -- dayMs+eventDatesLine move to a pure src/domain/event-meta.ts that both the public shell and the mail shell read, because a second copy of a date-range vocabulary is DEC-613's trap with a delay fuse; (c) every renderEmailHtml call site holding the event row passes it, and every site that does not names in one line which row it lacks; (d) the mail card stops being the campaign's last ungraded surface -- the whole drawn card extent gets an exact, extent-clipped ledger in test/mail-shell-frame.test.ts (no ratchet: an exactly-enumerable population needs a table, not a ceiling). Consequence recorded, not acted on: DEC-441's wave-7 premise for RemindPreviewModal's subject-header substitution ("no such data exists on a send") becomes FALSE the moment (c) lands; that file is w47-b's this wave.

## Amendment (wave 52)

MEASURED at main cdad55da5: `npx vitest run 390 phone Phone frame-verdicts.render frame390.render` is 3 files / 15 tests RED (was 0 RED at wave 48/49). Root cause, proven by standalone run: `src/routes/public/submit-post.tsx:555` calls `eventDatesLine(event)` unguarded; `dayMs` (`src/domain/event-meta.ts:22`) does `iso.split("-")` and throws TypeError when the day field is absent, so POST /submit/:slug returns `Internal server error` AFTER the submission row is persisted -- the exact duplicate-submission failure mode the surrounding DEC-547 comment forbids. `src/routes/public/submit-views.tsx:585` already declares the correct runtime guard (`hasEventDates`) for the same data on the same surface, so the codebase already treats these fields as possibly-absent regardless of the repo type. RULING: (a) `dayMs` must honour its own documented contract -- non-string input yields NaN, never a throw; (b) `eventDatesLine` accepts nullable day fields and returns the empty string when either is missing, never the literal "Invalid Date"; (c) every call site renders the line only when it is non-empty. The line is decorative masthead copy; it is never a reason to fail a write. Fixing the test fixtures instead is forbidden -- that papers over a live 500 on the unauthenticated public CFP.
