# DEC-393: The 44px floor's third evasion is the row-action anchor: a bare <a>/<Link> is on the floor, and reaching it takes min-height AND horizontal padding

DESIGN-RULINGS.md:189 names the evasion verbatim ("padding alone does not reach the floor, and without padding the hit box is only as wide as the text"), and an independent reviewer measured it live: /admin/review's per-plan Progress/Results/Edit links render 21px tall at 390 because review.css:117 gives .chq-review-plan-actions only display/gap/font and its three react-router <Link>s declare no height and no padding. The instrument that should have caught it cannot see it: app/src/phone-tap-target.scan.test.ts's tapTargetTagTokens collects tokens from <input>/<select>/<button> and from <a> ONLY when the class list also carries chq-btn -- so the exact shape the ruling calls out is the one shape outside its population, and the scan has been green throughout. RULED: (a) an anchor or <Link> that is a row's affordance is an interactive element on the 44px floor regardless of whether it wears chq-btn; (b) reaching the floor means min-height >= 44px AND centred flex AND non-zero horizontal padding, all three, declared inside a max-width <= 700px block -- any one alone is non-conformance, not a partial pass; (c) the scan's population is EXTENDED BY ENUMERATION to bare anchors and to the *-actions row containers the codebase actually styles (derived from the CSS, never hand-listed), guarded by a vacuous-population tripwire; (d) offenders are held by a two-sided ratchet const that may only be LOWERED, never an allowlist read off the failure output (the house rule stated verbatim at phone-tap-target.scan.test.ts:30-32); (e) exemptions are STRUCTURAL inline comments beside the rule they exempt, never a file:line ledger (DEC-967 wave-62). Desktop is untouched: the floor is a phone rule and the fix lives in a max-width block.

## Amendment (wave 7): a flush row-action anchor reaches the 44px floor by growing its own box and absorbing the padding with an equal negative inline margin

DESIGN-RULINGS.md:189 requires min-height:44px PLUS centred flex PLUS horizontal padding, and names the two evasions (padding alone; a text-width hit box). But the row actions this app ships are <Link>/<a> elements that must stay optically flush with their row's left edge or the drawn grid moves — which is why 92 measured selectors still evade the floor and why every previous attempt either shifted the ink or added padding without height. RULING: the anchor itself takes `min-height:44px; display:flex; align-items:center; padding-inline:10px; margin-inline:-10px` inside a max-width:700px block. The hit box grows in both axes; the negative margin cancels the padding so nothing shifts — the same 'replaces padding rather than adding to it' technique B8 already blessed for the selected-row 3px olive edge. Two limits: it is applied to the ANCHOR, never to a container (a padded container with a text-width child still fails); and it is NEVER applied to a dense matrix-cell token — B8 pairs dense/roomy by density, and raising a dense speakers-grid cell to 44px breaks the 178px column the pair exists to serve.

## Amendment (wave 90): the 92-offender tap-floor backlog is closed SHEET BY SHEET in each sheet's true-terminal phone block, and a token declared in styles.css is never given a second phone rule by a cluster

w5-c enumerated 92 row-action-anchor offenders into docs/design/audit/tap-floor-v12.md and fixed only the four files it owned; the other 88 have had no owner for three waves because no ruling said WHO closes them or WHERE. Two failure modes are now live risks. First, five different cluster sheets each list `.chq-pill` / `.chq-modal-actions` / `.chq-bulkbar-actions` as offenders — tokens whose base rule lives in app/src/styles.css. If each cluster lane declares its own phone override, the tree gains five copies of one vocabulary (DEC-613: a second copy of a vocabulary is a trap with a delay fuse) and the shell lane's eventual fix silently loses or wins by source order. RULED: a cluster sheet fixes only the tokens IT declares; a token whose only top-level rule is in styles.css is recorded as a finding for the shell lane and left alone. Second, six of the eight sheets in scope have top-level rules declared AFTER their existing `@media (max-width:700px)` block (comms.css 1849/2054, contacts.css 846/919, settings.css 1368/1439, speakers.css 1274/1441, agenda.css 889/1276, overview.css 447/543), so a fix dropped into the EXISTING block can be shadowed on arrival by the same class of bug DEC-385 already ruled against. RULED: the fix is a NEW block appended at the true end of the file, after every top-level rule, never an edit inside the existing block and never a reorder — forty-plus worktrees hold hunks in these sheets and only an append survives them. The conforming shape stays exactly the one the wave-7 amendment set (`min-height:44px; display:flex; align-items:center; padding-inline:10px; margin-inline:-10px`), applied to the ANCHOR, never to its container; the only legal non-fix is a `/* tap-floor-exempt: <reason> */` comment sitting immediately above the top-level rule it exempts, and the only reasons that qualify are a dense matrix cell (B8's dense/roomy pair exists to serve the 178px column) or an element that is not a target at all.

## Amendment (wave 92): the docs pager's 44px pin is a FLOOR — the frame's own 46px satisfies it, and the assertion is reworked to an inequality

`test/docs-site-phone.test.ts` asserts /min-height:\s*44px/ on the docs Previous/Next pager pair, but docs/design/Chautauqua Docs.dc.html:201-202 draws both at `min-height:46px`, and docs-site.css.ts:280-290 correctly implements 46px with flex:1, centring and the frame's border/radius/background. The CSS is conformant and the pin is the divergence: DEC-393's floor was never an equality, and a frame that draws taller satisfies it. Reworked the assertion to accept the frame's literal — assert min-height is present and >= 44px, quoting :201 — rather than degrading conformant geometry to match a regex.

## Amendment (wave 93): the shared .chq-link-button gets a roomy phone variant; ink stays where the frame draws it

app/src/styles.css:815 declares `.chq-link-button { padding: 0 }` with no phone variant anywhere in the file, and it is reused verbatim as a real row/nav target at 390 — contacts names, Overview's "All 9 - oldest 119 days" and "Open the grid", Review's "Remind laggards (2)" and "See all 30 results", the Delete view control — measuring 14-26px tall. DESIGN-RULINGS.md:189 names this exact evasion ("a shared token used verbatim in a dense desktop grid and a 390 card cannot satisfy both, so pair them") and :115 rules that anywhere a row can carry a real target gets the roomy variant, identical in colour and weight, differing only in geometry. RULING: the pairing is authored ONCE on the base token, in a terminal `@media (max-width: 700px)` block at true EOF of app/src/styles.css, using the geometry review.css:2606-2612 already proved — `min-height: 44px; display: flex; align-items: center; padding-inline: 10px; margin-inline: -10px` — so the hit box grows in both axes while the equal-and-opposite margin keeps the ink exactly where the frame draws it and no desktop pin moves. A genuinely dense phone context opts out with a named modifier class, never by re-declaring the base.

## Amendment (wave 94): The tap-floor scan's `(no CSS rule)` bucket is a token-resolution artifact, and an `*-actions` container is exempted by naming the anchor rule that carries the floor

Two shapes in the 61 live offenders are not defects and must stop being counted as them. First, `findAnchorFloorOffenders` decides a token is "owned" only if some TOP-LEVEL rule declares it, so a token whose only rule lives inside a conforming `@media (max-width: 700px)` block is reported as `(no CSS rule)` — five tokens sit in that bucket today and at least one (`.chq-review-plan-action-link`, already 44px/inline-flex/padded inside review.css's terminal block) is fully conformant. A phone-only token is the CORRECT authoring shape under DEC-385 single-direction; flagging it inverts the rule. RULED: resolution considers narrow-media rules too — a token whose narrow rule meets min-height + centred flex + horizontal padding is conformant wherever its rule lives; only a token with no rule anywhere at all is an offender. Second, roughly half the offenders are `*-actions` container rules (`.chq-comms-preview-actions`, `.chq-content-detail-actions`, `.chq-forms-header-actions`, `.chq-modal-actions`, …). DEC-393's wave-7 amendment already ruled the floor is reached by the ANCHOR and never by its container, so a container can never be fixed on its own terms — its only two honest outcomes are a descendant rule that reaches its anchors, or a `/* tap-floor-exempt: … */` comment. RULED: the exemption comment on a container must NAME the rule that carries the floor for its children, with file:line, so the exemption is a receipt rather than a shrug — and a container whose children are `.chq-btn`-family controls cites app/src/styles.css:1104-1116, which already carries the floor.
