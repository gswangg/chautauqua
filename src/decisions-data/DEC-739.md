# DEC-739 wave-46 amendment: a generated repo-root artifact that concurrent test workers read is PUBLISHED by temp+rename, never written in place

scripts/seed.ts writes `.seed.sql` and `.seed-manifest` with a bare writeFileSync onto a fixed repo-root path (scripts/seed.ts:3299-3300), and scripts/perf-seed.ts does the same for `.perf-seed.sql` (:752). Sixteen test files spawn `npx tsx scripts/seed.ts` and seven of them readFileSync that same path, under vitest.fast.config.ts's `pool: "threads"` at vitest's DEFAULT worker count (the config's own comment says it deliberately does not cap workers). A reader can therefore observe a half-written file. This is not theoretical: `test/reviewer-progress-cap-denominator-seed.test.ts` was reported failing all three tests for a plan that IS present in `.seed.sql`, and it passed clean in my own fast-tier run at f91d8a863 - i.e. it is intermittent, which is the signature of the race and not of a defect in the seed. This matters to the campaign specifically, not just to hygiene: scripts/exit-predicate.ts refuses to grade ANY row without a `--suite-verified-sha` whose suite passed, so a fast tier that cannot be trusted to reproduce is the single mechanical blocker between an all-zero ceiling table and campaignDone. RULED: (a) every scripts/** write whose target is a repo-root path any test reads goes through ONE shared helper, `writeFileAtomic(path, data)`, which writes `<path>.tmp-<pid>` in the SAME directory and renameSync()s it onto the target - one owner, never a second copy (DEC-613); (b) the pid suffix is load-bearing, because two workers can be mid-generation simultaneously and a shared temp name would let one clobber the other's partial write; (c) seed CONTENT is not touched - SEED_NOW stays as it is, no shared/cached seed is introduced, and no spawning test is edited, because the defect is publication, not generation; (d) a scan derives the population (scripts/** writeFileSync targets that test/** reads back) at test time and ratchets the non-atomic count at 0, so the next generated artifact cannot re-open the hole.
