# DEC-065: A task file's authoritative assignment link is consulted or the request is refused — the reverse fileId link is a fallback for UNLINKED files only

src/server/repo/files-authz.ts's getTaskFileScope gates its fallback on `if (!assignmentRow)` — the authoritative lookup returned no row — rather than on `if (!fileRow.taskAssignmentId)` — the file carries no authoritative link. The two differ exactly when a file NAMES an assignment that no longer resolves (deleted or reassigned): the code then falls through to the taskAssignment.fileId reverse link, which the helper's own docstring says is "NOT guaranteed to resolve the same assignment ... different speaker", and canAccessTaskFile grants the download to that other assignment's assignmentContactId. RULED: the reverse link answers only for files with no task_assignment_id of their own. A file whose stated link is dangling returns null and the download is refused — fail loudly beats silently borrowing another speaker's authorisation (the repo's Fail Loudly principle, and DEC-843's silent-fallback rule). The DEC-558 total-order note on assignmentBy stays: it is about determinism within one link, not about which link is consulted.
