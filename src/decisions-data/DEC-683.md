## Amendment (wave 68): the printable programme is a PROJECTION, so it carries its source's limits and its source's vocabulary

src/routes/public/programme.tsx calls getPublicAgenda(db, event) and destructures only `{ items }`, discarding `total`. getPublicAgenda is capped at MAX_PUBLIC_ROWS (=1200, src/server/repo/public/bounds.ts) and returns the true unwindowed `total` precisely so a caller can tell it was truncated -- AgendaContent renders "Showing the first N of M scheduled sessions." for exactly this reason. The one surface a producer PRINTS and hands to attendees is the worst possible place for a silent drop, so the programme must render the same sentence, byte-identical, when items.length < total. Same file, same class of drift: the programme prints `row.item.roomName` raw inside a .filter(Boolean), so a session with no room assigned loses its room clause entirely, while DEC-666 pins publicRoomLabel() as "the ONE place a nullable room name becomes public-facing prose" (-> "To be announced") and every other public surface obeys it. SPEC's field wisdom is explicit that TBD is a real value, not an absence. A projection may reformat its source; it may not quietly disagree with it. Corollary for the perf gate: the programme is the only public HTML GET with no per-day and no per-page bound (every other one is day-scoped or paginated at PUBLIC_PER_PAGE), so it is the public read that scales hardest with the event and it has no budget in scripts/perf-smoke.ts -- SPEC section 7 says budgets that aren't enforced are decoration.

## Amendment (wave 125: a phone content column has exactly ONE gutter owner — a page whose body declares its own 16px cancels the shell `main` padding for that page, scoped by `:has()` in the page's own sheet)

The CFP column measures 290px against the 358px budget and the probe correctly named the root cause: src/views/theme.ts`main { padding: 26px 34px 34px; }` and `.chq-cfp-body { padding-left/right: 16px }` (cfp.css.ts:215) both claim the gutter, so 390 − 68 − 32 = 290. Every previous fix of this shape narrowed the inner element, which treats a stacking bug as a sizing bug and leaves the second owner in place to bite the next page. The rule is ownership, not arithmetic: one element pays the phone gutter and the other pays zero. It has to be the BODY that keeps its 16px, because the frame's header band is full-bleed and its own padding is drawn at 16px too, so cancelling the shell's padding lines both up on one edge. And it has to be scoped from the page's own stylesheet — `main.chq-measure:has(.chq-cfp-body)` inside cfp.css.ts's terminal max-width block — because src/views/theme.ts is a shell file the mandate reserves for the shell lane, and because a bare `main { padding-inline: 0 }` at 390 would silently re-gutter every other SSR surface. This is the same body-rooted `:has()` reasoning DEC-576 wave-106 used to cross the portal boundary: one selector, no new signal, no shell edit.

## Amendment (wave 146): the public wide shell adopts the pack's 44px side gutter and 40px bottom, and the admin SPA's same-named token is a different contract

`docs/design/audit/desktop-frame-ledger-v12.md` files this as an open, named divergence rather than a fix: every 1600-canvas public container in the pack draws `padding:26px 44px 40px` and `max-width:1268px`, and the app ships `26px 34px 34px` / 1248.
