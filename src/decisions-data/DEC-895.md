# DEC-895: A suggested placement is sized by the session's own format, and no two suggestions in one payload claim the same room-minute

The agenda placement suggester sizes each candidate slot by the session's own declared format duration, never a fixed default, and two suggestions returned in the same payload may never claim the same room-minute.

## Amendment (wave 148): the unplaced REMAINDER's duration claim is served by the payload, never inferred client-side from the five rows that were sent

`Chautauqua Overview.dc.html:164` draws '3 more unplaced · all need 120 minutes'. `app/src/pages/overview/AgendaWorkSection.tsx:39-46` builds only the count half, and the residue doc's recorded blocker ('no duration field reaches the unplaced-row payload') is now HALF false — `UnplacedRow.durationMin` has existed since this DEC — but true where it matters: the unplaced detail query is `LIMIT ROW_CAP` (5), so the client holds no data at all about the rows the caption is describing. The client must therefore never derive the remainder's duration from the rows it CAN see; that would be a universal asserted over a sample (DEC-936's 'one row elected to speak for the rest'). `agendaWork` gains `unplacedRemainderDurationMin: number | null`, computed server-side over the unplaced set MINUS the capped ids, non-null ONLY when every remainder row carries a `session_format` answer AND all of them parse to the same duration through the one `parseFormatDurationMin`. Mixed, partial, or unparseable ⇒ null, and the caption renders its count half alone. The existing 'Place the other N ›' link (DEC-919 wave-129's reversal) is untouched.

## Amendment (wave 33): the phone agenda's clash card carries the frame's one-tap resolution, computed client-side through the SAME nextFreeSlot the Overview suggestion uses, with one shared label vocabulary

Agenda.dc.html:171 draws a filled control as the last child of the clash card — `Move DFC-047 to 11:30`. `PhoneAgenda.tsx`'s `slot.kind === 'clash'` branch renders the flag and the tappable session list and stops; the only move path is arm-then-tap-a-free-slot, two gestures whose targets do not even appear until something is armed. The capability already exists and is already designed: `AgendaWorkSection.tsx` renders exactly this control off `conflict.resolution`, composed server-side by `buildConflictResolutionFor` (`src/server/repo/overview/scheduling.ts`) over `nextFreeSlot` (`src/domain/schedule.ts`, pure core). RULED: the phone agenda computes the same resolution CLIENT-SIDE from data it already holds — no payload change, no new endpoint, no new capability — picking the LATER of the clashing pair exactly as `pickLaterConflictEntry` does, excluding that session from `existing` so it cannot block its own search, and passing the day's real breaks through `blocked` (threaded from the parent, never defaulted to empty: a suggestion that lands inside lunch is worse than no suggestion). It renders NOTHING when `nextFreeSlot` returns null — the UI never invents a time. The label and its caption move into `src/domain/schedule-copy.ts` as pure helpers that BOTH the server composer and the phone card call, so the two surfaces cannot drift into two wordings of one sentence (DEC-613).


## Amendment (wave 32): the phone agenda's fourth slot kind — a break is drawn as a blocked, untappable row, not as free time

docs/design/Chautauqua Agenda.dc.html draws four slot treatments inside `sc-for slots`; app/src/pages/agenda/phoneSlots.ts's `PhoneSlot.kind` union is `'placed' | 'clash' | 'free'` — three. The missing one is `slot.blocked`: a 44px bordered row (`border:1px solid #E1DDCE`, uppercase 11px/600/0.06em `#6B6F5C`) carrying `{{ slot.note }}`. This is not a speculative fourth state: the frame's OWN demo data supplies it as `{ time: '9:45', blocked: true, note: 'Break · 15 min' }` and `{ time: '12:00', blocked: true, note: 'Lunch · 60 min' }`, so a blocked slot IS a scheduled break and the note is `<label> · <duration> min`. The data is already in hand — PhoneAgenda.tsx takes `breaks?: ScheduleBreakRow[]` and already maps it to `BlockedInterval[]` for computeClashMove, precisely so a suggestion never lands inside lunch — but `buildPhoneSlots` never sees it, so at 390 a break renders as a `free` run with a 'Place here' target and a producer can place a session inside lunch by tapping it. The frame forbids that by drawing a visually distinct, non-target row. RULED: BUILD, as a fourth `kind`, carving out of the free runs in start order and carrying its note; it is the one slot kind that is not a tap target, so it takes no 'Place here anyway' sibling either.
