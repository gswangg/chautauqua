# DEC-937: A stylesheet may only reference tokens that EXIST, and a button base rule always names its own face -- both scan-locked

## Amendment (wave 110): a phone card's field caption is drawn by the frame or it is not drawn at all

DEC-937's `td[data-label]::before { content: attr(data-label) ': ' }` fixed a real bug (position-keyed labels) but was then applied as a universal. The Contacts 390 frame (docs/design/Chautauqua Contacts.dc.html:200-208) draws NO captions: it composes the same cells into a reading order that labels itself -- name 16px/600, `company · role` on one 13px nowrap-ellipsis line, tags as 11px/700/0.06em uppercase. Live prints `COMPANY: ` and `LABELS: ` above those lines and stacks company and title as two rows. RULED: the attr(data-label) SOURCE rule is untouched and stays the only legal way to produce a caption (the ban on positional literals in app/src/phone-label-source.scan.test.ts stands); but a caption is rendered only where its frame draws one. Where the frame composes fields into a labelled-by-position line, the caption is suppressed inside that sheet's terminal phone block and the frame's composition is matched instead. The suppression is CSS-only and desktop bytes do not move.

## Amendment (wave 111): the `attr(data-label)` caption renders only where the frame draws it — Comms Templates is the second scoped exception

Wave 110 (w6-a) established that DEC-937's `attr(data-label)` micro-caption is the right SOURCE rule everywhere and the wrong RENDER on Contacts 390, whose frame composes the row without a caption. The identical divergence exists one cluster over and is unowned: `comms.css`'s `.chq-comms-templates-table td[data-label]::before { content: attr(data-label) ': ' }` prints `NAME: Acceptance` on the phone card, while `docs/design/Chautauqua Comms.dc.html:286-320` ("Templates · 390") draws each row as three stacked unprefixed lines — name, detail, used — with an `Open` control at the row's right. Note the sheet ALREADY carries a per-cell `content: none` exception for Last-used, so the mechanism is established; this extends it to Name. Ruling: suppress the caption for this table and match the frame's three-line composition; rewrite any pin positively (assert the frame's shape) rather than deleting it, and leave the generic DEC-937 rule untouched for every table whose frame does draw the caption.

## Amendment (wave 121): Cancelled padding is a FACE-scoped idiom: only an unpainted control may carry it

DEVIATIONS.md:340-351 blesses `padding-inline:N` + equal-and-opposite `margin-inline:-N` for the QUIET-ACTION families (`.chq-link-button`, `.chq-btn-tertiary`, the status chips) — bare-text controls whose ring shrink-wraps the glyphs. DEC-393's tap-floor recipe then propagated the same four declarations onto controls that are PAINTED, and nobody checked the face. Measured at 17deea82: 24 cancelled-padding rules; `agenda.css:1508` applies it to `.chq-agenda-head-actions .chq-btn` / `.chq-breaks-add-actions .chq-btn` / `.chq-breaks-row-actions .chq-btn` / `.chq-phone-footer-actions .chq-phone-footer-btn` (`.chq-btn-primary` = `background: var(--chq-brand)`, `.chq-btn-secondary` = `background: var(--chq-surface-sunk); border: 1px solid`, styles.css:546/565), `overview.css:643` to `.chq-overview-btn` (`border: 1px solid var(--chq-border-strong); background: var(--chq-surface-sunk); padding: 9px 16px`, overview.css:358), `speakers.css:1813` to `.chq-speaker-detail-actions a` (`<a class="chq-btn chq-btn-secondary">`, SpeakerDetailPage.tsx:538) and `contacts.css:985` to `.chq-contacts-title-actions a` (`<a className="chq-btn chq-btn-secondary">` Export CSV, ContactsApp.tsx:385). On a painted control the idiom does two wrong things at once: `padding-inline:10px` OVERRIDES the face's own 16px inline padding (the drawn box narrows by 12px) and the negative margin then drags the PAINTED box 10px past its layout edge on each side. agenda.css's own sibling rule at :1616 states the premise the file then violates 100 lines above it — "the family is borderless, so cancelled padding is safe". RULED: a rule declaring `padding-inline:N` with `margin-inline:-N` may only target a control whose RESOLVED FACE is unpainted — no `border`/`border-width`/`border-style` other than `none`/`0`, and no `background`/`background-color` other than `none`/`transparent`, resolved across the key compound's class tokens in its own sheet and then app/src/styles.css. A PAINTED control reaches the 44px floor with `min-height: 44px; display: flex; align-items: center` and KEEPS its own inline padding — the hit box grows vertically, the ink stays where the frame draws it, and nothing bleeds into the gutter. Machine-checked by a new two-sided ratchet, `PAINTED_CANCELLED_PADDING_CEILING`, graded by the campaign exit predicate; an element-key selector (`a`, `button`) resolves its face through an allowlist entry that must name a component path and a className literal the scan itself re-greps (DEC-991's receipt shape), never a bare assertion.
