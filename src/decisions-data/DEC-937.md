# DEC-937: A stylesheet may only reference tokens that EXIST, and a button base rule always names its own face -- both scan-locked

## Amendment (wave 110): a phone card's field caption is drawn by the frame or it is not drawn at all

DEC-937's `td[data-label]::before { content: attr(data-label) ': ' }` fixed a real bug (position-keyed labels) but was then applied as a universal. The Contacts 390 frame (docs/design/Chautauqua Contacts.dc.html:200-208) draws NO captions: it composes the same cells into a reading order that labels itself -- name 16px/600, `company · role` on one 13px nowrap-ellipsis line, tags as 11px/700/0.06em uppercase. Live prints `COMPANY: ` and `LABELS: ` above those lines and stacks company and title as two rows. RULED: the attr(data-label) SOURCE rule is untouched and stays the only legal way to produce a caption (the ban on positional literals in app/src/phone-label-source.scan.test.ts stands); but a caption is rendered only where its frame draws one. Where the frame composes fields into a labelled-by-position line, the caption is suppressed inside that sheet's terminal phone block and the frame's composition is matched instead. The suppression is CSS-only and desktop bytes do not move.

Wave 110 (w6-a) established that DEC-937's `attr(data-label)` micro-caption is the right SOURCE rule everywhere and the wrong RENDER on Contacts 390, whose frame composes the row without a caption. Ruling: suppress the caption for this table and match the frame's three-line composition; rewrite any pin positively (assert the frame's shape) rather than deleting it, and leave the generic DEC-937 rule untouched for every table whose frame does draw the caption.

## Amendment (wave 121): Cancelled padding is a FACE-scoped idiom: only an unpainted control may carry it

docs/design/DEVIATIONS.md`Focus/hover ring GEOMETRY on bare-text controls: cancelled inline padding.` (drift-proof citation, DEC-967 wave-115) blesses a `padding-inline` + equal-and-opposite `margin-inline:-N` for the QUIET-ACTION families (`.chq-link-button`, `.chq-btn-tertiary`, the status chips) — bare-text controls whose ring shrink-wraps the glyphs. DEC-393's tap-floor recipe then propagated the same four declarations onto controls that are PAINTED, and nobody checked the face. Measured at 17deea82: 24 cancelled-padding rules; the shared cancelled-padding rule near the start of agenda.css's terminal phone block applied it to `.chq-agenda-head-actions .chq-btn` / `.chq-breaks-add-actions .chq-btn` / `.chq-breaks-row-actions .chq-btn` / `.chq-phone-footer-actions .chq-phone-footer-btn` (task w12-o later removed the first three of these from that rule's own selector list -- app/src/pages/agenda/agenda.css`.chq-breaks-row-actions .chq-btn,` is what remains there, drift-proof citation per DEC-967 wave-115) (`.chq-btn-primary` = `background: var(--chq-brand)`, `.chq-btn-secondary` = `background: var(--chq-surface-sunk); border: 1px solid`, app/src/styles.css`.chq-btn-primary {` and app/src/styles.css`.chq-btn-secondary {`, both drift-proof citations per DEC-967 wave-115), and app/src/pages/overview/overview.css`.chq-overview-row-actions .chq-overview-btn,` maps to `.chq-overview-btn` (`border: 1px solid var(--chq-border-strong); background: var(--chq-surface-sunk); padding: 9px 16px`, overview.css:358), app/src/pages/speakers/speakers.css`.chq-speaker-detail-actions a` (`<a class="chq-btn chq-btn-secondary">`, SpeakerDetailPage.tsx:538) and app/src/pages/contacts/contacts.css`.chq-contacts-title-actions a` (`<a className="chq-btn chq-btn-secondary">` Export CSV, ContactsApp.tsx:385). On a painted control the idiom does two wrong things at once: `padding-inline:10px` OVERRIDES the face's own 16px inline padding (the drawn box narrows by 12px) and the negative margin then drags the PAINTED box 10px past its layout edge on each side. agenda.css's own sibling rule at :1616 states the premise the file then violates 100 lines above it — "the family is borderless, so cancelled padding is safe". RULED: a rule declaring `padding-inline:N` with `margin-inline:-N` may only target a control whose RESOLVED FACE is unpainted — no `border`/`border-width`/`border-style` other than `none`/`0`, and no `background`/`background-color` other than `none`/`transparent`, resolved across the key compound's class tokens in its own sheet and then app/src/styles.css. A PAINTED control reaches the 44px floor with `min-height: 44px; display: flex; align-items: center` and KEEPS its own inline padding — the hit box grows vertically, the ink stays where the frame draws it, and nothing bleeds into the gutter. Machine-checked by a new two-sided ratchet, `PAINTED_CANCELLED_PADDING_CEILING`, graded by the campaign exit predicate; an element-key selector (`a`, `button`) resolves its face through an allowlist entry that must name a component path and a className literal the scan itself re-greps (DEC-991's receipt shape), never a bare assertion.

## Amendment (wave 123): painted-face remediation runs FIRST and shrinks the companion-gap population; an unpainted container's declared phone gap is the frame's rendered gap plus 2N

DEC-937's wave-121 amendment already rules HOW a painted control reaches the floor (`min-height:44px; display:flex; align-items:center`, keeping its own inline padding, never cancelled padding). What was never ruled is the ORDER and the arithmetic. Measured on main at `0c27bf92`: 8 painted offenders and 17 companion-gap offenders, and six of the seventeen containers (`.chq-agenda-head-actions`, `.chq-breaks-add-actions`, `.chq-contacts-title-actions`, `.chq-overview-row-actions-inline`, `.chq-overview-row-actions-column`, `.chq-speaker-detail-actions`) are gap offenders ONLY because their members carry the idiom on a painted face. `deriveContainers` derives the gap population from the cancelled-padding members, so deleting the idiom from a painted face removes the container from BOTH populations -- widening its gap first would bake a 20px hole into a layout that is about to stop needing one. RULED: (a) remove the idiom from every painted face before touching any gap; (b) for a container that legitimately keeps the idiom (an unpainted quiet-action family), the declared phone `gap` becomes the frame's own rendered gap PLUS 2N, never a bare 2N -- DEVIATIONS.md`the rule owning their separation adds the cancelled` padding back, so the RENDERED separation must stay what the frame draws, and a bare `gap:20px` would silently redraw an 8px frame gap as 8px-visible-but-different-elsewhere; (c) a `gap` on a non-flex box is not a fix -- the three `gap=NONE` containers must be made real flex rows or the idiom removed from their members.

## Amendment (wave 126): a face resolution reads only the RESTING face, and a class token matches only at its full name

Main was red on `PAINTED_CANCELLED_PADDING_CEILING` (2 offenders vs ceiling 1) and both offenders are false, produced by two predicate defects in the shared scanner. (a) `core.ts`'s `selectorMentionsToken` is `new RegExp(`\.${token}\b`)`; `-` is a non-word character, so `\b` fires inside a hyphenated class and resolves `.chq-speakers-task-edit-panel` as the face of `.chq-speakers-task-edit`, and `.chq-btn-primary` as the face of `.chq-btn`. A hyphen-extended class is a DIFFERENT class; the boundary is `(?![\w-])`. (b) `resolveTokenFace` reads every top-level rule mentioning the token, including `:disabled`/`[aria-disabled]` STATE rules — not the resting box a negative margin drags past its layout edge. Hand-verified against the tree: `BreaksPanel.tsx` renders `.chq-breaks-row-actions`' children as `chq-btn chq-btn-tertiary`, and `.chq-btn-tertiary` is `background:none; border:none` — agenda.css's own comment above the rule already says the row is not painted, and the lens contradicted it. With both repairs the true offender count is 0, which closes the campaign row rather than papering it.

## Amendment (wave 127): the class-boundary repair is a POPULATION, not a site — every predicate matching `.token` against selector text takes the (?![\w-]) boundary

Wave 126 repaired selectorMentionsToken's `\.token\b` in app/src/phone-tap-target-scan/core.ts because `-` is a non-word character, so `\b` fires INSIDE a hyphenated class and `.chq-btn-primary` resolved as the face of `.chq-btn`. That fix landed. Its sibling did not: hasExemptionForToken (same file) still builds `...\.${escapeRe(token)}\b[^{}]*\{`, so a `tap-floor-exempt:` comment written for `.chq-bulkbar-hint-action` also exempts the token `chq-bulkbar-hint`, and any token that is a hyphen-prefix of an exempted class inherits an exemption nobody granted. I patched it and re-measured all four tap lenses on main: counts are unchanged today (0/0/0/0), so this is a LATENT grant of exemption, not a live miscount — which is exactly when it is cheap to fix and exactly the shape (DEC-843: a silent fallback has siblings in other files) that has cost this campaign eight saturated-ratchet lies. RULED: the boundary repair is applied to every `.token` matcher in phone-tap-target-scan/, and core-token-boundary.test.ts carries a case per matcher so a ninth sibling cannot be introduced silently.

## Amendment (wave 131): A className mounted in markup is a declared control face and owes a rule — the one-time-password eyebrow takes the frame's own micro-label treatment

Two independent scans fail on main for one cause: `app/src/css-contract.scan.test.ts` and `test/design-system.test.ts` both report `pages/settings/PeopleRolesPanel.tsx: chq-settings-people-password-eyebrow` as a className with no matching CSS rule. v12m-w5-l landed the frame's reveal eyebrows (`Their password · shown once`, `New password · shown once`) this wave and mounted the class without declaring it, so the words currently paint in whatever the surrounding block inherits. The frame is unambiguous about what that register is — Settings.dc.html:1333 and :1491 both draw the eyebrow as `font-size:11px; font-weight:800; letter-spacing:0.1em; text-transform:uppercase; color:#565A4B`, the same uppercase micro-label the pack uses for every field eyebrow in the same modals. So this is not a choice: the rule is transcribed from the frame, in the sheet that already owns the settings vocabulary, using the existing `--chq-ink-2`/muted token rather than the literal hex (DEC-383's colour-literal closure). The general clause worth recording is that a class in a `className` is a CONTRACT with the stylesheet, and a lane that mounts one without declaring it ships a control whose face is an accident of its ancestors.

## Amendment (wave 141): A filled phone state restates border-color, or it reads outlined-plus-filled

`src/routes/public/css/agenda.css.ts`'s terminal phone block sets `.chq-pub-day-pill-active { background: var(--chq-ink); }` while its companion `.chq-pub-day-pill` phone rule draws `border: 1px solid var(--chq-border)`. The frame (Public and Portal.dc.html:379-ish day switcher) draws a single filled pill; the built control draws a border in the idle border colour around an inked fill. RULED: any phone rule that flips a control to a filled face must restate `border-color` to the fill token in the same rule whenever a companion rule paints a border — a background-only override is a half-applied face, and the painted-face predicate (DEC-941/DEC-833 lineage) grades the resting face, not the fill alone.
