# DEC-936: A roster row that covers two of the event's sessions carries BOTH participations; a lowest-id pick is not an answer to "which of your talks"

## Amendment (wave 115): the portal home subline is the same question asked of the SPEAKER — it enumerates every placed session, or it is a lowest-row pick wearing a friendlier sentence

`scheduledSubline` in src/routes/portal/index.tsx took its slot from a `.find()` over the placed sessions, and its own comment defended the truncation — "the first such placed session is used — the portal home states one line, not a per-session list". A judge with two accepted, scheduled sessions read "DevFlow Conf 2027 · you speak Thu 13 May, 09:30 · Main Stage" and had no way to learn the second slot existed; the sentence is not ambiguous, it is false, because "you speak &lt;when&gt;" asserts a complete answer. The data was never the problem: `getMySessions` (`src/server/repo/portal/sessions.ts:66-141`) has no LIMIT and already returns `PortalSession[]`, and `test/portal-overlap.test.ts` seeds a three-session speaker against it. This is exactly the defect DEC-936 named on the organiser's roster — an elected "primary" row standing in for a person who disagrees with themselves across sessions — landed on the one surface the speaker reads about their own commitments, where the cost of the omission is a missed talk.

RULED: the subline names every placed session — src/routes/portal/index.tsx:210 now reads `const placed = sessions.filter((s) => s.day !== null && s.startMin !== null);`. One placed session keeps the frame's exact sentence (`docs/design/Chautauqua Public and Portal.dc.html:421`, "&lt;Event&gt; · you speak &lt;placement&gt;") unchanged — the frame draws that line and nothing here moves it. Two or more become "&lt;Event&gt; · you speak &lt;countOf(n,'time')&gt; — &lt;slot&gt;; &lt;slot&gt;", the frame's sentence extended rather than replaced. The slot separator is "; " and not "·" because `formatPlacement` (DEC-777/w13-d, the ONE portal placement grammar) already spends "·" on its own room clause, and a second meaning for the same mark would make the list unparseable — the grammar itself is composed, never re-typed. The count phrase goes through `countOf` (DEC-925/DEC-987, the one pluralization vocabulary). When the placed sessions span two events no single name can lead the line, so DEC-988's wave-74 rule is preserved by giving each slot its own event name instead of captioning Event B's placement with Event A's name.
