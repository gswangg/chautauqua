# DEC-180: Every field label the pack draws is a population, and until this wave nothing graded it

The three divergences DEC-613 rules on were found by hand, not by any instrument — which is the finding. Derived on 32436e11b across all 13 *.dc.html files: 155 desktop and 127 phone drawn labels sit in the pack's field register (an 11px/12px label span immediately preceding an input-shaped `border:1px solid #BAB6A6` box), and no scan in test/ or app/src/ grades any of them. The two saturated frame ledgers measure CITATION; the two control-label ledgers measure control-shaped populations; the field-width ledger uses labels only as a join key and files a miss as UNRESOLVED. A universal needs a population (DEC-180), and this one was never enumerated. RULED: a new instrument derives that population from the frames themselves — never a hand list — joins each drawn label to a real `FormRow label=` / `SettingsField label=` / `<label>` text / `aria-label` call site in comment-stripped non-test source, and grades MATCHES / DIVERGES / UNRESOLVED with a two-sided ratchet per side, seeded by forcing each to -1 and reading the printed rows on the measuring branch. It MEASURES AND FILES ONLY — it moves no product byte and repairs no row, because a lane that both widens a population and drains it can always drain by narrowing. Its audit doc must name every in-flight lane repairing a row it counts, so the merge train's re-measure is expected rather than surprising.
