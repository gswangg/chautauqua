# DEC-180: Login rate limiter counts only failed attempts; success resets the per-email window

## Amendment (wave 153): A population keyed on class tokens excludes every classless element — the SPA half of that hole is still open

app/src/phone-tap-target-ssr-classless-anchor.scan.test.ts exists because SSR_UNFLOORED_TOKENS_CEILING is keyed on class tokens taken from markup, so an `<a>` under src/routes/** with no class attribute contributed no token and was "ungradeable by construction". That hole was found, instrumented, and drained to 0. The identical hole on the SPA side was never instrumented: ANCHOR_FLOOR_OFFENDERS_CEILING and UNDECLARED_HEIGHT_OFFENDERS_CEILING are likewise token-keyed, and app/src's own audit (docs/design/audit/phone-tap-floor-links.md) opens by saying its population is "every chq-* token appearing in a className on <Link>, <NavLink> or <a>" — a classless one appears in neither. My own count over `git ls-files app/src` (*.tsx, non-test): 96 anchor-shaped tags, 21 with no class/className attribute, of which ~19 are real markup. An independent live probe at 390 reported "4 real 44px-floor violations — all bare <a> tags with no padding/min-height applied" while every static tap-floor ratchet in the tree read 0; those two facts are the same fact. RULED: build the SPA mirror of the SSR scan, reusing phone-tap-target-scan's exported helpers rather than deriving a fifth private copy (DEC-613), seed its ceiling at the count read back with the constant forced to -1, and register it OUT_OF_CAMPAIGN_SCOPE so a newly-visible population cannot move the campaign's goalposts mid-convergence. Widening a population into visibility and draining it are separate acts.
