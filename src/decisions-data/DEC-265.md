# DEC-265: Participant API responses carry the contact's name and email server-side: an optimistically appended row must render identically to a reloaded one

## Amendment (wave 110): an optimistic rollback reverts the one write that failed, never the snapshot it started from

app/src/pages/speakers/OnboardingGrid.tsx captures `previous` (the whole grid) before a cell flip and, on failure, calls `setGrid(previous)`. A slow failure therefore silently un-does every concurrent write that succeeded in the meantime, or replays a previous page/filter's rows over the current view -- while the banner names only the one row that failed. That is precisely the state DESIGN-RULINGS.md:283 error rule 11 forbids: the user is told what broke and not told what was reverted underneath them. RULED: rollback is a functional update that restores ONLY the failed assignment's cell (or the failed participant's inviteStatus) from the value captured before that flip. Concurrent successes and a page/filter change survive it. The banner's claim about what survived becomes true by construction rather than by luck of timing.

## Amendment (wave 126): an optimistic overlay is released by SERVER TRUTH, never by the write's own resolution — and never left standing after it

Two mirror defects, both live and both on the landed v12 work. (a) `SubmissionsTable.tsx:269/:303` deletes the `statusOverrides` entry the instant `apiPost` resolves, while `submissions.data` still holds the pre-write payload (the SWR refetch is asynchronous and DEC-700 wave-121 deliberately leaves `data` untouched on a bump) — so every SUCCESSFUL triage or bulk accept visibly reverts to the old status for one round trip, indistinguishable from a failed write and exactly the "turns a rollback into a flicker" state the rulings forbid. (b) `OnboardingGrid.tsx`'s `applyCellStatus` (:598) and `applyInviteStatus` (:696) never clear `optimisticOverride` on success, and `grid = optimisticOverride ?? gridRead.data` (:382), so after the first cell toggle the whole roster is pinned to a pre-write snapshot: the server-computed column-head aggregate ("7 of 12 done", declared EVENT-WIDE and never counted from rows) and the counts panel silently stop updating — a Tier-0 fidelity break on the v12 speakers redesign. Every other write handler in that file already does `setOptimisticOverride(null); await gridRead.refetch()`. Release on server truth, not on the promise resolving.
