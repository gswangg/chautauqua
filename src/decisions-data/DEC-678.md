# DEC-678: A loading indicator is DELAYED, and an empty state never renders while a load is in flight

## Amendment (wave 91): the filtered empty-state voice has ONE home (app/src/pages/speakers/narrowing.ts); a component that inlines a second copy is the defect the module-reachability orphan is reporting

narrowing.ts exports activeFacet/ActiveFacet and is imported by nothing — test/module-reachability.scan.test.ts reports it as the tree's only orphan, in both directions. It is orphaned because OnboardingGrid.tsx inlined its own narrowingDescription at :251 and lost the single-facet voice, which is exactly why two OnboardingGrid.render.test.tsx cases fail looking for 'No speakers match "Zzyx".'. The orphan and the wrong copy are one defect, and the honest repair is re-wiring rather than deleting the module or allow-listing it: deleting it leaves the inlined duplicate as the de facto voice with no test naming it.


## Amendment (wave 108, mandate D21): the SWR cache is scheduled as a subsystem, not a library half — a cache with no reader is a declared knob with no reader

The mandate scheduled a stale-while-revalidate cache on lib/api.ts keyed on URL plus the existing mutation-bump counter, with cross-page tests for contacts, speakers and submissions. Landing only the cache layer this wave would produce exactly the failure this codebase already has a name for — a declared capability nothing reads — because the visible half of the ruling ('no skeleton when a cached payload exists') lives in each page's own loading branch, not in the client. It also touches the single API client that one-api-client.scan guards and the bump counter that api-mutation-bump.scan guards, so the invalidation contract has to be settled before any page is rewired. It goes out as a decompose so a sub-planner splits the client contract from the per-page adoption and both land as readers of each other.

## Amendment (wave 108, mandate D21, v12m-w4-t): `loading` means "nothing to render", never "a request is in flight" — no skeleton when a cached payload exists, and the empty state stays reachable only from a settled load

This is the visible half of D21 and it lives in each page's own loading branch, not in the client — which is exactly why the client half may not land without a page reading it. The shared hook (app/src/lib/useCachedRead.ts) returns `{ data, loading, error, refetch }` with `loading` defined as `path !== null && data === undefined && error === null` — "there is nothing to put on screen and nothing to say about why". Consequences, all deliberate: (1) a cold first read renders PageSkeleton exactly as today, so app/src/admin-first-paint.render.test.tsx (which mounts every page with fetch stubbed to a never-resolving promise and asserts a chq-skeleton element on first paint, plus zero chq-empty elements while loading) keeps passing unchanged; (2) a revisit with a cached payload renders the rows on the FIRST frame with no skeleton — the mandate's headline; (3) a background revalidation over rendered data leaves `loading` false, so no page flashes a skeleton after a write; (4) a FAILED cold read leaves `loading` false with `error` set, which is byte-for-byte today's behaviour (app/src/pages/contacts/ContactsTable.tsx:47 computes `settledEmpty = !loading && items.length === 0`) — this definition was chosen specifically so no page task has to edit ContactsTable.tsx, which branch v12m-w10-j owns. A null `path` (page has no eventId yet) makes the hook fully inert — `{ data: undefined, loading: false, error: null }` — preserving each page's existing event-gate. Pages must re-express any "settled" predicate as `data !== undefined`, never as `!loading` (SubmissionsTable.tsx was the one that had to change: its zero-row gate read `showEmpty = loaded && !loading && items.length === 0`, and once the page adopted the cached-list read it became SubmissionsTable.tsx:339 `showEmpty = submissions.data !== undefined && items.length === 0`), so an empty state is still only reachable from a settled load.

## Amendment (wave 109): A filtered-empty grid renders the empty block alone; the table's footer chrome goes with the table

`docs/design/Chautauqua Speakers.dc.html:442-483` draws the 'Speakers · search found nothing' screen in full: header, H1 with its aggregate line, the filter strip that produced the exclusion, then a single empty block -- 26px headline, a 52ch sentence naming the excluding facet by the row it excluded, and one 'Clear the overdue filter ›' action. After that the card ends. There is no `<thead>`, no legend row and no pager. The app keeps the table's footer chrome (legend plus a disabled pager) beneath the empty block, which is B7 rule 6's own fingerprint one level out: the pattern DEC-678 retired for the row area, surviving in the furniture around it. RULING: when a loaded grid has zero rows, the empty block replaces the whole table region including its footer chrome. This is a desktop change and it is legal precisely because a v12 desktop frame demands it -- the campaign's goal names the landed speakers redesign being frame-complete, and this is one of its named edges.
