# DEC-253: Wave-154 amendment: the live 390 pass measures every interactive element, not a class vocabulary

The mandate's Tier 2 says the 44px sweep must MEASURE, not grep — and `scripts/render-sweep.ts` is the only instrument that measures. But `MOBILE_CONTROL_SELECTOR` (:179) and `ADMIN_MOBILE_CONTROL_SELECTOR` (:208) are both class-token keyed (`.chq-btn`, `.chq-input`, `.chq-select`, `.chq-tabbar a`, `header nav a`), and the public one's own comment says it "deliberately excludes secondary inline links". A bare `<a>` is therefore invisible to the measuring instrument for exactly the same reason it is invisible to the static ones — which is why a hand-run live probe found four real floor violations, all bare `<a>`, while `ADMIN_MOBILE_PASS_BLOCKING` has been true since wave 12 and the gate stayed green. Second defect in the same evaluator: `visitMobileRoute`'s page.evaluate (:1173-1195) keeps only the MINIMUM height/width, so a drain is serialised one element per route — fix the smallest and the next appears.

RULED: the population becomes derived (a[href], button, input, select, textarea, summary, [role=button], focusable [tabindex]), visible-only, with an exemption predicate that may only name a FACT about the element (ancestor-provided hit area such as `.chq-check-hit`, a display:none ancestor, a `.chq-visually-hidden` no-JS fallback behind an auto-submitting select) and never a scheduling note — the DEC-991 rule already written for KNOWN_CLIP_EXCEPTIONS.


## Amendment (wave 155): the live 390 pass reports EVERY offending control on a route, not the route's minimum — one min per route is a gate that goes green with the fix and blind to the rest

scripts/render-sweep.ts is the only instrument the campaign mandate calls authoritative ('measure, don't grep'). Its admin mobile pass already grades the right POPULATION — DEC-367/DEC-808 w7-dd repointed it at INTERACTIVE_CONTROL_SELECTOR, and ADMIN_MOBILE_PASS_BLOCKING is true — but its in-page evaluation keeps only `minControlHeight` / `minControlWidth`, a single scalar per route plus one descriptor. A route with twelve sub-44px controls reports one; fix that one and the row goes green with eleven live violations behind it, which is exactly how a hand probe found four real bare-`<a>` floor violations on a page the gate passed. The plumbing to fix it already exists and is DEAD: `deriveInteractiveOffenders` is exported and unit-tested in scripts/render-sweep-lib.ts, is called from nowhere in scripts/render-sweep.ts, MobileRouteResult carries no offender field, and ADMIN_MOBILE_INTERACTIVE_OFFENDERS_CEILING sits at the -1 sentinel its own comment says must be replaced 'in the same commit that wires this ceiling in' — a commit that never came. DEC-967's 'an instrument's dead branch looks exactly like a clean pass', in the one instrument the mandate defers to. RULED: visitMobileRoute collects EVERY visible interactive control's measured rect, MobileRouteResult carries the full offender list, evaluateMobileRoute reports it, and the run prints it; the admin pass's blocking decision reads the ceiling, seeded from a real live pass in the wiring commit or left at -1 with the sentinel intact if no live pass could be run — never a fabricated count. The minimum-control scalars STAY beside the list: they are DEC-253's own public-pass contract for a different population and a different question.
