## Amendment (wave 130): A frame's drawing does not create a data model — four drawn controls are RECORDED, never minted

DEC-380 wave-116 ruled that a frame's SILENCE removes geometry and not capability. The mirror, needed now: a frame's DRAWING does not create a data model, and a control minted only to satisfy a shape is the same error inverted (DEC-576 wave-110: a second control is never manufactured just to fill a band). Four measured divergences have no honest build. (a) The plan editor's `Save as draft`/`Open the plan` pair with its caption "You can save this as a draft plan and open it later" (Review.dc.html:919-921) names a plan lifecycle state the schema has no column for: openness is derived from `openDate` alone and `isPlanOpen(null, null, …)` reads an UNSET open date as open NOW (PlanList.tsx:33-45), so "save without opening" is literally unrepresentable and the caption would be a lie. (b) The portal-resource modal's Kind pair `File`/`Link` (Settings.dc.html:1463-1464) names a link kind the product does not have. (c) `Browse last year's sessions ›` (Public and Portal.dc.html:1543) names a previous edition the product has no model of. (d) The Comms fresh empty state's count-bearing copy (Comms.dc.html:577-578) needs a decided-submission count that surface never loads. Each becomes a DEVIATIONS bullet with its own transcribed ledger row, because an untracked gap is re-found and re-planned every wave — this planner has now spent three passes rediscovering (a).

## Amendment (wave 133): the mirror of wave 130 — a caption with NO live referent is always buildable and is BUILT verbatim; only a caption naming data the schema lacks is RECORDED

DEC-380 wave-116 ruled that a frame's SILENCE removes geometry, not capability; wave-130 ruled that a frame's DRAWING does not create a data model, and recorded four controls with no honest referent. Both halves have been used, twice, to defer static prose that needs no data at all. The distinction is now explicit: a caption whose text contains no live referent — no count, no name, no date — is static copy that any component can render today, so it is BUILT, not recorded. Measured members on `1885bfff`, each verified absent from `app/src/**` and `src/**`: `Drag to a slot · drag back to unschedule` (Agenda.dc.html:113, closing the Unscheduled tray), `Only "Invited" sends anything — the other two just record what you already know` (Speakers.dc.html:311, closing the participation menu), `Two to six · results show how the picks fell, never an average` (Review.dc.html:524/771, beside a choice criterion's `Add an option`), `Three to start with — two scored 1–5 and one recorded as a spread. Rename them, change the type or the weights, or remove any you don't want.` (Review.dc.html:738), `No sends on this event` (Comms.dc.html:571, the page-head state line beside the `Comms` H1), `Never shown publicly` / `Goes to the venue team only` (Public and Portal.dc.html:963/968). Contrast with the genuinely unbuildable, which stay recorded: `23 submissions have a decision and nobody has been told` (Comms.dc.html:576, already recorded under wave-130 clause (d)) needs a decided-submission count `RecentSends` never loads. RULED: a static caption is a lane's work, not a DEVIATIONS bullet; a DEVIATIONS bullet is reserved for the referent, and a bullet that defers static prose is a defect in the bullet.

## Amendment (wave 137): "If it hasn't arrived, check spam." is buildable — DEC-377 governs data-traced captions, not conditional troubleshooting — and it renders only on the branch where something was actually sent

Chautauqua Public and Portal.dc.html:1084 draws `If it hasn't arrived, check spam.` on the 390 Submitted confirmation, and src/routes/public/submit-views.tsx:768-770 refuses it with a comment citing DEC-377. But DEC-377 reads 'Mock figures are illustration: every number and caption on a redesigned screen must trace to an existing endpoint field' — it governs numbers and data-traced captions. `If it hasn't arrived, check spam.` contains no number, traces to no field, and asserts nothing about delivery timing; it is conditional troubleshooting predicated on non-arrival. The refusal was written against a DIFFERENT sentence (an arrival-window promise) and over-reached to the whole line. DEC-380 has now been sighted five times on the same shape (w116/w130/w133/w135): a caption with a live referent on screen is ALWAYS buildable, and deferring it is a defect in the deferral. RULED: build it verbatim, and the DEC-377 comment is amended IN PLACE to name what it actually refuses (an arrival-timing or delivery-window promise) rather than being deleted — the narrower refusal is real and must survive. One condition, because the frame draws only the happy path: the line renders on the `emailDelivered` branch ONLY. On the couldn't-send branch nothing was sent, so telling the reader to check spam would be a falsehood the frame never asked for. Same wave, same rule: Chautauqua Submissions.dc.html:298's `A new co-presenter is emailed a portal link · the lead presenter is not changed` sits beside a co-presenter add row the app already renders and states a consequence nothing else on screen states — it is a build, not a residue row.

## Amendment (wave 139): the wave-137 co-presenter ruling was wrong on the merits — a caption asserting a SIDE EFFECT is graded against the app's actual behaviour, not merely against whether it has a live referent, and this one is SUPERSEDED

Wave-137's closing paragraph ruled `Chautauqua Submissions.dc.html:298`'s `A new co-presenter is emailed a portal link · the lead presenter is not changed` a BUILD, reasoning only that it "sits beside a co-presenter add row the app already renders and states a consequence nothing else on screen states." That reasoning weighed the live-referent test alone and never checked what the app actually does. `app/src/pages/submissions/SubmissionDetailPage.tsx:1854` deliberately renders the opposite claim — "Adding a co-presenter here sends no email — sending a portal invite is a separate, explicit action. The lead presenter is not changed." — under the DEC-604 wave-70 amendment, because `src/routes/api/submissions.ts:6` states, and a source-scan test enforces, that the submissions routes never import a mailer: adding a participant cannot send anything. `SubmissionDetailPage.render.test.tsx:1421-1427` pins the app's sentence verbatim and its own comment calls the frame's version "the stale DEC-900 'emails them' claim." Building the frame's sentence would ship a lie about the mailer and break a landed pin.

The wave-116/130/133/135/137 live-referent rule governs STATIC prose — a caption naming no count, no name, no date, nothing the app must compute. It was never meant to reach a caption whose entire content IS a claim about a side effect (does this action send an email, yes or no). RULED, correcting wave-137 on this one row only (its other holdings — the "check spam" line, the general shape of the live-referent test for static prose — stand): a caption that asserts a side effect is graded against the observed behaviour, not the live-referent test alone. `Chautauqua Submissions.dc.html:298` is SUPERSEDED, not built — recorded in DEVIATIONS.md §3 under the pre-existing DEC-909 wave-134 bullet (which reached the correct disposition all along), and entered in `test/frame-caption-ledger.scan.test.ts`'s exclusion taxonomy as the first member of a fifth named class, SUPERSEDED, alongside EXPLAINER / FIXTURE / EXEMPLAR_ARTICLE / COMPOSED.
