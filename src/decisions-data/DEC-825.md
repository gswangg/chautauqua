# DEC-825: Approving content requires content: the Approve verb is absent, and both content-status doors refuse, when a submission has no file version

`app/src/pages/content/SessionList.tsx:436`'s per-row Approve is gated only on `item.contentStatus !== 'approved'`, so a row whose Latest file cell renders the already-shipped honest `No files yet` empty state (`latestFile === null`) approves straight to `Approved` with nothing uploaded — filed by an eval judge against a live session and confirmed in the tree. The v12 Content frame draws Approve inside an `sc-for` row template with no file-state fork, so the frame neither demands nor forbids the control on an empty row; the ruling comes from DESIGN-RULINGS A1's own reasoning (`Only re-uploads are pre-ticked ... a file nobody has opened is the batch that needs friction`) — approval is a judgment ABOUT a file, and there is nothing to judge. Ruling: (1) the per-row control is ABSENT, never disabled, when `latestFile` is null — the identical idiom the file's own w1-f comment already states for the approved case; (2) both server doors refuse `contentStatus: 'approved'` for a submission with no file row, set-based (one query over the requested ids, never read-then-write per id), with `ApiError('invalid', ...)` naming the count — fail loudly, no silent skip; (3) the other content statuses are untouched. Desktop and phone are identical here (markup-only, DEC-385).
