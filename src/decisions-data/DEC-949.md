# DEC-949: A budget that only guards the write door is not a budget — the read door answers the same question

GET /claim/:token (auth-claim.tsx:30) and GET /reset/:token (auth-reset.tsx:207) read the KV grant and branch 200-vs-410 with no rate-limit call; the per-IP failure budget exists only on the POST twins (:63, :250) and is refunded the instant a token resolves. So token guessing runs on unauthenticated, CSRF-free GETs at zero cost and the budget is never spent — and the reset GET additionally discloses the target account's address (auth-reset.tsx:227) on a hit. RULED: both GETs spend the same scoped budget under the same consume-then-refund shape the POSTs use, so a speaker following a real link is never throttled while a prober is.

## Amendment (wave 10): A password reset revokes the target's bearer tokens too, and SAYS HOW MANY — a compromise sweep that leaves one credential class live is not a sweep

POST /api/v1/users/:id/reset-password performs the sweep almost completely: revokeResetTokenForUser before the hash write (wave-43 amendment), updateUserPasswordHash, deleteUserSessions. It never deletes the target's api_token rows, so every chq_ bearer token that user minted keeps full organizer authority — and its CSRF exemption — after "reset + signed out everywhere"; DELETE /api/v1/tokens/:id cannot clean up either, since it requires the cookie session the reset just destroyed. The schema already attributes tokens: api_token.created_by_user_id carries its own index (src/db/schema/org-admin.ts), so "the target's tokens" is a well-defined set, not a guess. RULED: (a) the reset deletes api_token rows where createdByUserId equals the target, in a repo helper beside deleteUserSessions; (b) the revocation is DISCLOSED — the 200 body gains a revoked-token count — because a bearer token is often a shared integration credential and a silent revocation is worse than the gap it closes; (c) no SPA panel copy changes in this lane (PeopleRolesPanel.tsx is concurrently owned), so the disclosure lands on the wire first.
