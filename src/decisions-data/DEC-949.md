# DEC-949: A budget that only guards the write door is not a budget — the read door answers the same question

GET /claim/:token (auth-claim.tsx:30) and GET /reset/:token (auth-reset.tsx:207) read the KV grant and branch 200-vs-410 with no rate-limit call; the per-IP failure budget exists only on the POST twins (:63, :250) and is refunded the instant a token resolves. So token guessing runs on unauthenticated, CSRF-free GETs at zero cost and the budget is never spent — and the reset GET additionally discloses the target account's address (auth-reset.tsx:227) on a hit. RULED: both GETs spend the same scoped budget under the same consume-then-refund shape the POSTs use, so a speaker following a real link is never throttled while a prober is.
