# DEC-730: Status tokens pair by density and a banner never changes a status vocabulary: the "a write failed" frame is stale, and the pairing becomes executable

Two open questions with one answer. (1) docs/design/audit/speakers-v12.md finding 1 asks for a design call and has carried unowned for four waves: Chautauqua Speakers.dc.html:549 draws a FILLED olive Complete pill, an ink-outlined Overdue and an outlined Pending, while :28/:129, :598 and :665 in the SAME file draw the v12-inverted DONE/PEND/LATE constants, and the app implements the inverted set everywhere. Taking :549 literally would mean the grid renders one status vocabulary normally and a second, older one only while a rollback banner shows. RULED: :549's status cells are STALE -- the section was not re-cut when the inversion landed elsewhere in the same document -- the inverted vocabulary governs, and a write-failure banner is a banner, never a vocabulary switch. No status code changes; the audit finding closes citing this amendment. (2) DESIGN-RULINGS.md B8 states the pairing rule ("Colour and weight are identical in both; only geometry differs... Both must be edited together: changing one alone is what put a bordered Pending box back on three phone frames") and nothing in the tree enforces it. RULED: the pairing is machine-checked -- families derived by enumerating chq-* status stems across app/src CSS (never a hand-listed pair table), members classified as roomy or dense by their OWN geometry, then asserted identical in colour and weight, different only in min-height/padding/border/radius, with no dense member reachable from inside a max-width:700px block, because a phone row is always a real target.
