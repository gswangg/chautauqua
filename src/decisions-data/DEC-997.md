# DEC-997: A raw-source pin falsified by a CORRECT product change is re-anchored on the render receipt that already exists — never loosened to a substring, never deleted

`test/desktop-frames-settings-dialogs.test.ts:81` asserts `PeopleRolesPanel.tsx` contains the literal `title="Invite someone"`. That literal is gone because the panel grew a duplicate-email refusal state and now reads `title={duplicateUser ? 'Nobody was invited' : 'Invite someone'}` — the product got MORE correct and the pin got falsified, which is the one case where 'fix the test' is right and 'fix the code' is wrong. The two tempting repairs are both bad: loosening to `toContain('Invite someone')` would pass on a comment, and deleting the case would drop a desktop frame claim. `app/src/pages/settings/PeopleRolesPanel.invite.render.test.tsx:293` already asserts `getByRole('heading', { name: 'Invite someone' })` and its sibling asserts the refusal retitle. RULED: the pin moves to the live ternary literal — which carries strictly more information than the old one, encoding both the frame's drawn title and the refusal retitle — and the case's comment names the render receipt that proves it reaches the DOM. Corollary, binding on the citation lens: `src/decisions-data/DEC-967.md`'s `test/desktop-frames-settings-dialogs.test.ts:81` citation is repaired in the SAME commit, in drift-proof bare-path form, so the decision doc and the test it cites can never again disagree about which line carries the claim.
