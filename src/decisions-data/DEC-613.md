# DEC-613: The Sessionboard importer is one endpoint whose dry run and real run are the same planner

## Amendment (wave 93): a cluster sheet exempts a shell vocabulary and names its owner; it never mints a fifth copy

docs/design/audit/tap-floor-v12.md lists `.chq-pill`, `.chq-modal-actions` and `.chq-bulkbar-actions` as offenders under content.css, review.css, settings.css, speakers.css, forms.css, contacts-panels.css AND app/src/styles.css, because app/src/phone-tap-target.scan.test.ts evaluates each token per FILE that declares it top-level. A cluster that satisfies its own row by declaring a phone rule mints a fifth copy of a shell vocabulary — the delay-fused trap DEC-613 exists to forbid. RULING: for a token whose base rule lives in app/src/styles.css, a cluster sheet closes its audit row with `/* tap-floor-exempt: <token> is shell vocabulary owned by app/src/styles.css (DEC-613); the roomy phone pairing is declared there, never re-declared per cluster */` immediately above the rule, and the shell lane owns the actual geometry. Only tokens a cluster genuinely owns get a real phone rule in that cluster's sheet.

## Amendment (wave 94): One token cannot serve two densities: `.chq-overview-link-btn` splits into a roomy row-action token and an inline prose token

`docs/design/audit/phone-tap-floor-links.md:102-105` filed this as needing a design decision and no wave has made it. `.chq-overview-link-btn` is used at eight sites in Overview.tsx and AgendaWorkSection.tsx: seven are row actions standing alone on their own line beside a real `.chq-overview-btn`, and one — Overview.tsx:498, the `/e/${eventSlug}` public URL — sits INLINE inside a sentence, where DESIGN-RULINGS.md's 44px floor would break the line box. The sheet currently gives the single class a phone rule at overview.css:510 and :589, so whichever treatment wins is wrong at one of the two shapes. This is exactly the failure DESIGN-RULINGS.md:189 names ("a shared token used verbatim in a dense desktop grid and a 390 card cannot satisfy both, so pair them") and B8's density-pairing rule answers: colour and weight identical, geometry different. RULED: the roomy token keeps `.chq-overview-link-btn` and takes the DEC-393 wave-7 geometry in overview.css's terminal phone block; the inline prose site takes a new `.chq-overview-link-inline` that declares the same colour, size and weight and NO height or padding, with a `/* tap-floor-exempt: inline inside a sentence — a 44px box breaks the line box */` comment above its top-level rule. This is a split, not a fifth copy of a shell vocabulary: both rules live in the sheet that already owns the token, and DEC-613's wave-93 rule against minting a duplicate is untouched.

## Amendment (wave 96): One control keeps ONE accessible name at every width — the frame's abbreviated label is a drawing, not a second vocabulary

Chautauqua Public and Portal.dc.html:1063 letters the CFP step-1 dock's secondary "Draft"; :520, :1004 and :1290 letter the same control "Save draft" at every other width in the same file. A control whose accessible name changes with the viewport is the second-copy-of-a-vocabulary trap DEC-613 exists to name, one layer out — screen-reader users and the docs would have two names for one action, and the phone name is the one no test or doc uses. RULED: the label is "Save draft" at every width. What binds from :1063 is its GEOMETRY (min-height:48px; inline-flex; align-items:center; padding:0 16px; font-size:13px; font-weight:600; 1px border; radius 6px) and its PLACEMENT (auto width beside the flex:1 primary), which the frame's own dock has room for — 390 minus 32px dock padding minus 8px gap leaves 350, and "Save draft" at 13px/600 plus 32px padding is under 100. DEC-650 wave-82's split applies: a drawing's geometry binds, its placeholder lettering does not when it contradicts the same control's name elsewhere in the same pack.

## Amendment (wave 104): a shared phone class is not forked for one frame's type register — wire the shared class, cite the geometry it implements, file the register delta

`docs/design/Chautauqua Settings.dc.html:326` draws the Event drill's field values as a bordered readout box (`border:1px solid #BAB6A6; border-radius:6px; background:#FAF8F2; min-height:46px; display:flex; align-items:center; padding:0 13px; font-size:15px`); `app/src/pages/settings/settings.css:1889` already implements exactly that box as `.chq-settings-drill-field-row .chq-settings-row-value` inside the terminal phone block, opted into by CallForPapersPanel and PortalSettingsPanel — and NOT by EventSettingsPanel, whose rows render as bare text at 390. The shared rule declares `font-size: 14px` because `Settings.dc.html:452` (the CFP drill's twin box) draws 14px while :326 draws 15px. Two responses exist and one is wrong: minting a per-drill variant to carry 15px mints a fourth copy of a vocabulary DEC-613 exists to keep single, and buys a 1px register difference at the cost of a class every future drill must choose between. Ruling: the lane wires the SHARED class, cites :326 for the geometry it does implement (border, radius, background, min-height, padding, flex centring), and files the 15px-vs-14px register delta as a finding under docs/design/audit/ for DEC-643's register ruling to settle. A frame's type register is a question for the register owner, not for the drill lane that happens to arrive first.


## Amendment (wave 106): a CSS pin asserts the DECLARATION, never the presence of a name, and the phone-block reader is one shared vocabulary

DEC-385 wave-98's one-terminal-block contract forward-merges every sheet's phone blocks into one, which drags the provenance comments that used to sit OUTSIDE each block INSIDE rule bodies. Those comments quote CSS inline -- braces (`.chq-main{padding}` appears 10 times in app/src/styles.css alone), commas, and the literal `@media` -- and this broke a family of pins in two ways I measured on main: (1) comment-blindness, where a naive brace walker desynchronises and returns ZERO phone blocks (test/tap-target-floor.test.ts's phoneMediaBodies returns no match at all against styles.css, which is why all ten vocabulary tokens report a missing 44px floor that is in fact declared at :2355-2390), and a comma inside a comment hides the rule beneath it from an exact-selector match (app/src/components/error-states-phone.test.ts sees 1 of 3 `.chq-detail-content-link` bodies); (2) name-presence used as a proxy for a property, where 'the string X never appears under the breakpoint' was fair while each block held one concern and is now false for unrelated reasons (the three settings panel pins assert `not.toContain('chq-settings-…')` over a block that names nearly every token in the sheet). RULING: a pin over a stylesheet strips comments before it walks braces or splits a selector list; it reads the phone block with a depth-counting reader that throws when the sheet has no phone block (a pin that scans nothing must fail loudly, never pass vacuously); and it asserts the DECLARATION it cares about on the rules whose selectors mention the token, never the absence of a substring. That vocabulary lives in exactly one module, app/src/test-utils/phoneBlock.ts, exporting stripCssComments / phoneBlockText / phoneBlockRulesMentioning -- two functions claiming the same semantics must end in the same helper, and a second copy of a parser is a trap with a delay fuse.

## Amendment (wave 107): when two scans of one population disagree, the one whose predicate matches the artefact wins and the other is deleted

app/src/phone-scaffold-orphan.scan.test.ts and the orphan describe inside app/src/phone-page-scaffold.test.ts enumerate the same `.chq-phone-*` population and return different answers: 0 against ORPHAN_CEILING = 0 (two-sided), and 1 against ORPHAN_CEILING = 5 (one-sided). I read both predicates rather than trusting either count. The dedicated scan strips the leading dot (`token.slice(1)`) before asking source files whether they render the class; the copy inside phone-page-scaffold does not, so it searches `.tsx` markup for `.chq-phone-head-drill` — a string className attributes never contain. Its single "orphan" has four real renderers (RosterPanel.tsx:465, FormsPage.tsx:326, HistoryTab.tsx:156, TemplatesTab.tsx:203); the four classes it passes, it passes only because some source file happens to spell the dotted form in prose. A literal match is not a population (DEC-941/DEC-989), and a ceiling of 5 over a broken measure of 1 hides the fact that the test's own failure message — "the v12 mobile campaign is not done while it is above 0" — is measuring nothing real. RULED: the duplicate describe, its constant and its two helpers are DELETED outright, with no deprecation stub and no re-export (house rule: delete the old code). The dedicated scan absorbs the regression control that would have caught this — synthetic markup carrying the bare token reads zero orphans, while a dotted-selector matcher over the same markup fabricates one — asserted through the scan's own helper so the PREDICATE is pinned, not just the count.


## Amendment (wave 108): two independently-authored scans of one population is one scan too many — prove containment, port what is unique, delete the loser

app/src/phone-cascade-order.scan.test.ts and test/phone-cascade-order.scan.test.ts implement the same rule (a phone declaration shadowed by a later equal-specificity top-level rule) over the same population. Both measure 0. The test/ copy has an honest two-sided SHADOWED_CEILING = 0 and derives its SSR half from ssr-css-sources.ts; the app/src copy carries a one-sided ceiling of 20 over a population that is already clean — twenty units of slack guarding nothing, and a second implementation that will drift from the first the moment either is edited. Deletion, not reconciliation, is the answer this campaign already reached for the duplicate orphan scans. The one obligation before deleting is proof: the survivor's file population must be shown to be a superset, measured, not inherited from the survivor's own header comment.

CONTAINMENT MEASURED (task w4-p): app/src/phone-cascade-order.scan.test.ts's population is 40 files (27 `*.css` under app/src via `readdirSync(APP_SRC_ROOT, {recursive:true})`, filtered to exclude `.css.ts`, plus 13 `*.css.ts` under src/routes). test/phone-cascade-order.scan.test.ts's population is 43 files (the same 27 app/src `*.css` files, plus 16 SSR `*_CSS` modules from test/helpers/ssr-css-sources.ts, which walks all of src/ rather than just src/routes). Every one of the app/src copy's 40 files appears in the test/ copy's 43; the 3 extra are src/views/bare-page.css.ts, src/views/error-states.css.ts and src/views/theme.ts — SSR `*_CSS` modules that sit outside src/routes/ and that the app/src copy's `src/routes`-only walk could never reach. Superset confirmed by direct enumeration (both file lists computed and diffed), not inherited from either file's own header comment. Both files measured 0 shadowed pairs on this branch before deletion.

PORTED: the app/src copy's `isSelectorHeader` exclusion (a header containing `$` or a backtick, or blank after trimming, is not a selector) was added to test/phone-cascade-order.scan.test.ts's `classify()`, applied to both the nested (phone-block) and top-level rule walks. Proof it mattered: src/routes/public/css/agenda.css.ts:523 declares `.${ACCENT_BOUND_CLASSES[1]} { min-height: 44px; }` inside its terminal phone block. Before porting the filter, test/'s unfiltered `parseTopLevelBlocks` treated the interpolation's own `${`...`}` as a spurious brace pair, corrupting that one block's header/body split and silently dropping the declaration from both `mediaDecls` and `topDecls` (recoverable only by accident, via an empty-header block whose `extractDecls` short-circuits on zero selectors) rather than by an explicit, documented exclusion. With the ported filter the exclusion is intentional and can only under-count, never fabricate a shadow, matching the app/src copy's own documented guarantee. The test/ copy's ratchet already carried the two-sided falsifiability control (content.css/comms.css read exactly 0) that the app/src copy also had, so nothing further needed porting there.

DELETED: app/src/phone-cascade-order.scan.test.ts outright, no deprecation stub, no re-export (house rule). Citations re-pointed at test/phone-cascade-order.scan.test.ts in docs/design/audit/terminal-phone-block-v12.md and test/phone-terminal-block.scan.test.ts's comments; DEC-367.md and DEC-393.md's mentions are historical bug/precedent narratives about the now-deleted file at the time they were written and are left as history, not corrected forward.

## Amendment (wave 114)

One server rule — skip anyone reminded within the last hour — is captioned four times in the SPA. Three agree: `Overview.tsx:334` `Skips anyone reminded in the last hour` and `OnboardingGrid.tsx:1031` `Skips anyone reminded in the last hour` both render that caption, and `RemindPreviewModal` reports "...reminded in the last hour". One disagrees: `TaskView.tsx:451` renders "A reminder names only this task · skips anyone emailed in the last hour · ...", with the same wobble repeated in its comment at :246 and pinned by `TaskView.render.test.tsx:220`. "Emailed" and "reminded" are not synonyms in this domain — the app sends plenty of email that is not a reminder, and Comms history counts both — so the one screen that says "emailed" is telling an organiser a broader rule than the server implements. DEVIATIONS §4's standing voice rule bans exactly this ("synonym wobble on domain terms"), and this DEC's own finding is that a second copy of a vocabulary is a trap with a delay fuse. RULED: "reminded in the last hour" is the one phrase, TaskView adopts it, and the four call sites stop being four independent string literals — the phrase gets one exported owner and a scan that fails when a fifth copy appears or an existing one drifts.
