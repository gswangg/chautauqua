# DEC-613: The frame's drawn FIELD label is the product's field label; a code-side shortening is a second copy of the pack's vocabulary

No ledger in the campaign grades drawn FIELD labels. test/desktop-control-label.scan.test.ts and test/frame-control-label.scan.test.ts both derive control-shaped populations (footer bands, 44px anchors, painted spans); the field-width ledger reaches field labels only as a JOIN KEY and, when the join misses, files an honest UNRESOLVED. docs/design/audit/desktop-field-width-v12.md says so in its own Adjudications: rows 4 and 5 are "a genuine label-text mismatch, not a width finding" and "a words-only ledger is the correct instrument for that fact, not this one" — and no such instrument was ever built. Measured against the frames on 32436e11b: `Chautauqua Settings.dc.html`:735/:752/:756 draw "Event name", "Starts", "Ends"; app/src/pages/settings/EventSettingsPanel.tsx renders "Name", "Start date", "End date". `Chautauqua Comms.dc.html`:102 draws "From which plan"; ComposeWizard.tsx:1453 renders "Evaluation plan". Every sibling panel (CallForPapersPanel, PortalSettingsPanel) already matches its frame verbatim, so these are outliers, not a register. RULED: where a v12 frame draws a field label as product copy — an 11px label span over an input-shaped box, not an interpolation and not stored field data — that string is the label the product ships, at the frame's own capitalisation. A code-side shortening is DEC-613's second copy of a vocabulary. CARVE-OUT, ruled here so no lane re-litigates it: Settings.dc.html:739's "Public URL" is NOT adopted, because the frame's row renders a composed origin+slug value (`chautauqua.cc/e/devflow-conf-2027`) while the control edits the slug alone; renaming the label without building the prefix presentation would name the field something the input does not accept. That row goes to DEVIATIONS as a recorded, reasoned divergence.
