# DEC-613: The Sessionboard importer is one endpoint whose dry run and real run are the same planner

## Amendment (wave 93): a cluster sheet exempts a shell vocabulary and names its owner; it never mints a fifth copy

docs/design/audit/tap-floor-v12.md lists `.chq-pill`, `.chq-modal-actions` and `.chq-bulkbar-actions` as offenders under content.css, review.css, settings.css, speakers.css, forms.css, contacts-panels.css AND app/src/styles.css, because app/src/phone-tap-target.scan.test.ts evaluates each token per FILE that declares it top-level. A cluster that satisfies its own row by declaring a phone rule mints a fifth copy of a shell vocabulary — the delay-fused trap DEC-613 exists to forbid. RULING: for a token whose base rule lives in app/src/styles.css, a cluster sheet closes its audit row with `/* tap-floor-exempt: <token> is shell vocabulary owned by app/src/styles.css (DEC-613); the roomy phone pairing is declared there, never re-declared per cluster */` immediately above the rule, and the shell lane owns the actual geometry. Only tokens a cluster genuinely owns get a real phone rule in that cluster's sheet.

## Amendment (wave 94): One token cannot serve two densities: `.chq-overview-link-btn` splits into a roomy row-action token and an inline prose token

`docs/design/audit/phone-tap-floor-links.md:102-105` filed this as needing a design decision and no wave has made it. `.chq-overview-link-btn` is used at eight sites in Overview.tsx and AgendaWorkSection.tsx: seven are row actions standing alone on their own line beside a real `.chq-overview-btn`, and one — Overview.tsx:498, the `/e/{slug}` public URL — sits INLINE inside a sentence, where DESIGN-RULINGS.md's 44px floor would break the line box. The sheet currently gives the single class a phone rule at overview.css:510 and :589, so whichever treatment wins is wrong at one of the two shapes. This is exactly the failure DESIGN-RULINGS.md:189 names ("a shared token used verbatim in a dense desktop grid and a 390 card cannot satisfy both, so pair them") and B8's density-pairing rule answers: colour and weight identical, geometry different. RULED: the roomy token keeps `.chq-overview-link-btn` and takes the DEC-393 wave-7 geometry in overview.css's terminal phone block; the inline prose site takes a new `.chq-overview-link-inline` that declares the same colour, size and weight and NO height or padding, with a `/* tap-floor-exempt: inline inside a sentence — a 44px box breaks the line box */` comment above its top-level rule. This is a split, not a fifth copy of a shell vocabulary: both rules live in the sheet that already owns the token, and DEC-613's wave-93 rule against minting a duplicate is untouched.

## Amendment (wave 96): One control keeps ONE accessible name at every width — the frame's abbreviated label is a drawing, not a second vocabulary

Chautauqua Public and Portal.dc.html:1063 letters the CFP step-1 dock's secondary "Draft"; :520, :1004 and :1290 letter the same control "Save draft" at every other width in the same file. A control whose accessible name changes with the viewport is the second-copy-of-a-vocabulary trap DEC-613 exists to name, one layer out — screen-reader users and the docs would have two names for one action, and the phone name is the one no test or doc uses. RULED: the label is "Save draft" at every width. What binds from :1063 is its GEOMETRY (min-height:48px; inline-flex; align-items:center; padding:0 16px; font-size:13px; font-weight:600; 1px border; radius 6px) and its PLACEMENT (auto width beside the flex:1 primary), which the frame's own dock has room for — 390 minus 32px dock padding minus 8px gap leaves 350, and "Save draft" at 13px/600 plus 32px padding is under 100. DEC-650 wave-82's split applies: a drawing's geometry binds, its placeholder lettering does not when it contradicts the same control's name elsewhere in the same pack.
