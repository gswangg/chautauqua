# DEC-268: The documented zero-setup Quickstart must produce a working /admin: predev builds the SPA bundle, render-sweep builds before boot, and a missing admin shell fails loudly instead of returning a bare 404

Verified structurally on main today (not inherited): `public/admin/` is gitignored (.gitignore:3), the only thing that writes it is `vite build --config app/vite.config.ts` (package.json "build"/"dev:app"), and NOTHING in the README Quickstart (`npm i && npm run db:migrate && npm run seed && npm run dev`) or in `predev` ("tsx scripts/ensure-dev-vars.ts") runs it. src/routes/root.tsx:34,45 serve the admin console via `fetchAsset(c, "/admin/index.html")` against the ASSETS binding, so on a literal fresh clone an organizer or reviewer logs in and gets an empty HTTP 404 for /admin and every /admin/* deep link -- J1, J3-J6, J8-J9, J11-J12 unreachable through the documented path. This is exactly what docs/verification-log/task-w2-g-fresh-clone.md Finding 1 reported, and unlike its Finding 2 it is still true at HEAD. scripts/render-sweep.ts has the same hole: it spawns `npx wrangler dev` directly (line 271) after migrations+seed (lines 265-268) with no build step, so the render-sweep gate also only passes in a worktree where someone happened to run `npm run build` earlier. Fix on three fronts: (1) predev = ensure-dev-vars + `vite build --config app/vite.config.ts` (vite only, no tsc, to keep `npm run dev` ~1s slower and no more); (2) render-sweep runs the same build before booting; (3) the admin-shell fetch asserts a 200 and otherwise throws with an actionable message, because a silent empty 404 is the worst possible failure mode under the house fail-loudly rule. The README's four-command block stays byte-identical (DEC-257 evaluates it verbatim); only prose is added. Contract tests lock predev's content, render-sweep's build call, and the loud-failure path.

## Amendment (wave 31): a licence claim is a claim — it gets a file and a contract test

SPEC §8 ships the repo MIT and README.md:11 states 'Licensed MIT', but the tree has no LICENSE file and package.json carries no license field, so the grant does not legally exist — and the customer's stated interest is reusing the code ('we'd like to use your code if you win', docs/clarifications.md). DEC-268 already pins the repo's documented claims (quickstart paths) with a contract test; this is the same class. Ruling: a standard MIT LICENSE at the repo root, copyright 'the Chautauqua contributors', package.json "license": "MIT", a README pointer to the file, and one contract test asserting all four agree so they cannot drift apart. Copyright year and holder are set here rather than left to a worker's guess.
