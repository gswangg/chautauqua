# DEC-065: Task-assignment upload files are served through GET /files/:fileId via a task-file scope: organizer org-match or the owning speaker

Portal file_request uploads insert file rows with submissionId null and kind 'handout' (DEC-029) linked back via task_assignment.file_id, but getFileScope 404s submission-less files and getResourceFileScope requires kind 'resource', so no route can ever serve them — the producer OnboardingGrid renders a dead paperclip and J6 artifacts are write-only. Decision: keep the DEC-029 data model unchanged; add getTaskFileScope(db, fileId) in src/server/repo/files.ts (file with submissionId null + kind 'handout' joined through task_assignment.file_id -> task -> event to org and assignment contact; null when no assignment references the file) and pure canAccessTaskFile (organizer org-match, or speaker whose contactId equals the assignment contact or uploader). GET /files/:fileId tries submission scope, then resource scope (DEC-047), then task scope. The OnboardingGrid paperclip becomes a real link to /files/<fileId>.
