# DEC-502: A paged JSON feed returns ONE page window; HTML's cumulative show-more is not the feed's contract

`boundedRowLimit(page, perPage)` returns `page * perPage` (src/server/repo/public/bounds.ts:27) and getPublicSessions/getPublicSpeakers apply it as a bare SQL LIMIT with no OFFSET (sessions.ts:326-336, speakers.ts:68). That is correct for the HTML surfaces, which re-render pages 1..N as one growing list. It is wrong for `/embed/:slug/{sessions,speakers,gallery}.json`, which hands those cumulative rows into an envelope that labels them `perPage` (src/routes/public/index.tsx:264-298, envelope at src/routes/public/feeds.ts:12-18): `?page=2&limit=12` returns 24 items labelled `perPage: 12`, so any consumer walking pages duplicates every earlier item and can never reconstruct the list. The DEC-484 envelope is a published contract, so the feed layer slices the repo's cumulative result to `[(page-1)*perPage, page*perPage)` — `items.length <= perPage` becomes an invariant — with no extra query, no repo signature change, and no change to the HTML surfaces. Truncation stays detectable exactly as designed: `total` is the true count, and a window past the MAX_PUBLIC_ROWS ceiling honestly returns an empty page.
