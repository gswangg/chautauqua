# DEC-425: DEC-417's caps reach the last three uncapped free-text writes: reviewer scorecard text + comment, API-token name, upload filename

DEC-417 scoped itself to "every admin JSON mutation route" and DEC-422 added the two public/speaker SSR paths. Three writes are outside both and take unbounded client free text straight into D1, each the same SQLITE_TOOBIG-500 class the reviewers found on PATCH /api/v1/submissions/:id. (1) src/routes/review/reviewer.ts:206 writes `comment: typeof body.comment === "string" ? body.comment : null` into evaluation with no length check, on a reviewer-authenticated route at SPEC's 10-50-reviewer scale. (2) src/domain/evaluation.ts's validateEvaluationScores checks a 'text'-kind criterion only for required/non-blank (evaluation.ts:208-215) -- a 10MB criterion answer serialises into scores_json unchecked. (3) src/routes/api/tokens.ts:61-73 requires `name` to be a non-empty string and caps nothing. (4) src/domain/files.ts's validateUpload checks kind, extension and byte size but never filename length, and src/routes/files.ts:135 writes the attacker-controlled multipart file.name into file.filename. Rule: the caps are the ones already exported from src/forms/validate.ts -- MAX_LONG_TEXT_LENGTH for the scorecard comment and text-criterion values, MAX_NAME_LENGTH for the token name and the filename -- so no lane invents a fourth vocabulary; the length check for a criterion value lives in pure-core validateEvaluationScores (not the route) so the route, the SPA and the unit tests share one rule; and oversized input is a 400 naming the field in the existing envelope, never a 500.
