# DEC-867: Blank is ABSENT for every field kind, and `ne` never fires on an absent trigger

VERIFIED, two holes in src/forms/rule-match.ts, both duplicated verbatim in the browser twin RULE_MATCH_JS so neither can surface as a client/server mismatch. (a) The number branch (lines 39-43) runs `Number(value)` with no empty/null guard, so '' and '   ' canonicalize to 0 and null canonicalizes to 0 — contradicting the function's own contract at lines 20-23 and the text branch's explicit ''→undefined at line 50. A rule `number eq 0` therefore fires on a field nobody touched, showing (and requiring) a dependent field under a trigger with no answer. (b) The `ne` branch (lines 71-74) has no `actual === undefined` guard, unlike eq (line 68) and in (line 76): `undefined !== 'Workshop'` is true, so a dependent field stays visible AND required under a dead rule chain — the exact server-side gate SPEC §6 names, and the transitivity DEC-532 claims but enforces only by deleting hidden triggers' answers. Decision: an absent answer is undefined for EVERY kind (number gains the null/undefined and blank-string guards) and an undefined actual satisfies NO operator, `ne` included — the three operators now agree, and 'the trigger was never answered' can never make a dependent field required. The checkbox kind is deliberately unchanged: an absent checkbox canonicalizes to false, not undefined, so 'show unless the box is ticked' keeps working — RULE_MATCH_CASES already pins that case and must stay green. Both twins change together and the shared case table grows the new blanks, since parity is proven only by that table.
