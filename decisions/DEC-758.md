# DEC-758: A contact is deleted only when nothing depends on it; the refusal names the counts, and merge is the answer for a contact with history

There is no contact deletion anywhere on main — no DELETE route in src/routes/api/contacts/crud.ts and no affordance in ContactDrawer.tsx, which offers only Save/Email/Add to event. J11 makes the org directory the durable asset across events, so a contact created by a typo or a bad import row is currently permanent, and the only escape (merge) requires a second record to merge into. Deletion must not become a quiet way to destroy evidence, so the rule is: delete succeeds only for a contact with zero references (no participant row, no task_assignment, no pipeline entry, no linked user account); otherwise it fails with a 409 whose message names what depends on it ("3 submissions and 1 task"), because a refusal that does not say why reads as a bug. That keeps the contact -> speaker -> publicly-visible ladder intact (a speaker with a talk can never be deleted out from under the agenda), makes merge the correct instrument for a duplicate that carries history, and keeps the destructive act honest by stating its scope before it runs.
