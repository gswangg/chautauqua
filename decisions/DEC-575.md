# DEC-575: On CSV import UPDATE, a blank cell means "no value supplied" and never clears an existing value; custom fields merge key-by-key

mapImportRow (src/domain/contacts.ts) yields "" for a mapped-but-empty cell, and resolveImportUpsert's update branch tests `!== undefined`, so "" reaches updateContactForImport and wipes the stored value. A producer importing a 300-row list with an email+company sheet therefore erases every speaker bio, title and phone the portal collected — silently, with a cheerful "300 updated". Worse, patch.customFields replaces the whole customFieldsJson blob, so any custom field not present in the file is deleted too. Blank is absence of data, not an instruction to delete: on update, blank-after-trim fields are omitted from the patch and custom fields merge into the stored object key by key. Create is unchanged (blank stays blank — there is nothing to lose). Clearing a field stays an explicit edit in the contact editor, which is the only place the intent is unambiguous. This is the "export dropping custom answers is the lock-in forbidden" rule pointed the other way: an import that deletes what it did not carry is the same betrayal.
