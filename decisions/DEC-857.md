# DEC-857: A reviewer's queue row names the action it offers and the session's shape; nothing organizer-scoped mounts before the shell knows who is signed in

VERIFIED, three residues of the DEC-845 landing. (a) ReviewerQueue.tsx:123-126 renders `item.ref` twice — once in the .chq-review-queue-ref span and again inside the link text — so every row prints its own reference twice. (b) The action link at :139-144 reads 'Score this' unconditionally, including on rows the same envelope has just labelled SCORED 4.5; a control that names an action the reviewer already took is the same defect DEC-853 fixed on a placed agenda card. (c) The row states nothing about the session it is asking someone to judge — no format, so a reviewer cannot tell a 10-minute lightning talk from a 120-minute workshop before opening the scorecard, which is exactly the click-depth the mandate's turn-budget audit says costs more than features. Decision: the ref appears once (in its own span; the link carries the title). The action reads 'Change your score' when alreadyRatedByMe, 'Score this' otherwise. ReviewerQueueItem gains `format: string | null` — the raw SESSION_FORMAT answer LABEL, which already carries its own '(N min)' suffix (parseFormatDurationMin reads that suffix; DEC-772), so the row prints the stored label verbatim and no second duration formatter is minted. Format is a session-shape fact, not a speaker-identity fact, so it stays visible under anonymization. Second half, same principle at the shell: RoleGate (app/src/App.tsx:258-266) renders its children while `me` is still loading, so a reviewer's login lands on /overview, mounts OverviewPage and fires organizer-only fetches that 403 before the redirect resolves. The gate renders the sanctioned delayed-loading block until the identity is known — a shell must not ask an organizer's question on a reviewer's behalf.
