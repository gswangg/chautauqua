# DEC-377: Mock figures are illustration: every number and caption on a redesigned screen must trace to an existing endpoint field

The mocks carry one consistent demo dataset (47 submissions, 23 accepted, 12 accepted speakers, 6 unplaced, 2 clashes, 318 contacts, 'DevFlow Conf 2027', persona names and sbek-* emails taken from docs/fixtures/) and several captions that read like product facts. Two rules bind simultaneously: the NO-EVAL-GAMING invariant (no product file may contain a fixture name, email, event name or count; fixture data lives only in the seed script) and handoff copy rule 3 (never assert what no endpoint stores). Where a mock caption has no backing field, the lane drops the caption rather than inventing a value or computing a client-side estimate. Where a mock shows a count the API already returns (Comms lastSentAt and 7-day total, Contacts duplicate and segment counts, Review submitted/expected evaluations), it renders from that field, with the zero and empty states designed too — the mocks only show the full state. Captions that state a constraint the user needs before acting are kept verbatim because each names real implemented behaviour: 'Skips anyone reminded in the last hour', 'Kept across pages · sent in batches of 100', 'Clashes are flagged, not blocked', 'Mean of submitted reviews · recusals excluded', and the 100-recipient cap.
