# DEC-411: Gate scripts must survive tsx/esbuild keepNames: a raw-string __name shim goes into every Playwright page before any evaluate, and the phone manifest is the whole phone product, not one route of the portal

The render-sweep gate has measured nothing at 390px since DEC-401 landed. docs/verification-log/task-w7-e-render-sweep-redesign.md records 35 of 35 mobile rows (15 public/portal blocking + 20 admin advisory) failing identically with `ReferenceError: __name is not defined`, before any overflow or control-height number is computed -- because DEC-401 introduced the first named inner closure inside a page.evaluate body (`const describe = (el) => ...` at scripts/render-sweep.ts:276) and tsx runs esbuild with keepNames, which rewrites it to __name(fn, "describe"); Playwright then serializes that text into a page context where no __name exists. So four waves of "mobile passes" have been instrument failures reported as numbers. The fix is one raw string -- addInitScript({content: ...}) is never itself passed through esbuild, so the shim cannot be rewritten by the very transform it defends against -- installed after each context.newPage() in both visitRoute and visitMobileRoute, with the constant exported from render-sweep-lib.ts so it is unit-testable without a browser. Second half: MOBILE_ROUTE_MANIFEST visits /portal and stops, while ROUTE_MANIFEST carries five more speaker portal routes plus /account/password. The speaker portal IS the phone surface of this product; measuring one sixth of it and calling the pass green is the same class of lie the clip was. Gate lanes stay log-only (DEC-384): this lane fixes the instrument and the manifest, never product CSS, and never flips ADMIN_MOBILE_PASS_BLOCKING -- DEC-387's rule is that it flips in the wave AFTER the pass first reads all-PASS.
