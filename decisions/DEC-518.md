# DEC-518: A cross-file manifest is DERIVED in a test, never hand-mirrored — including the test that guards a manifest

Third instance of the DEC-503/511/513 shape, and the first one where the guard itself is the desync risk. `test/docs-route-coverage.test.ts:33-58` protects the judge-facing `/docs/api` page by hand-mirroring `src/index.ts`'s `app.route()` calls in a local `buildApiApp()`, with a comment admitting it mirrors rather than imports; a new sub-app mounted in index.ts and forgotten here would leave its endpoints undocumented AND leave the test green — the exact failure the test exists to prevent. Separately, `app/src/pages/settings/ExportsPanel.tsx:7-13` hand-copies the five export kinds that `src/server/repo/exports.ts:25` already exports as `EXPORT_KINDS`; they agree today, with nothing making them agree tomorrow. Both are verified as currently CORRECT — this decision buys the invariant, not a bug fix, which is precisely the standing field-guide rule that enumeration means a re-runnable artifact scanning the source, never a hand-picked sample. Decision: the docs coverage test derives its mount list by parsing `src/index.ts`'s `app.route(<prefix>, <ident>)` calls and resolving each identifier through that file's imports, failing loudly and by name on any sub-app it cannot resolve (no allowlist that can silently absorb a new module); and a second test asserts ExportsPanel's kind list equals `EXPORT_KINDS` in both directions.
