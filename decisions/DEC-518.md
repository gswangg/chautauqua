# DEC-518: A cross-file manifest is DERIVED in a test, never hand-mirrored — including the test that guards a manifest

Third instance of the DEC-503/511/513 shape, and the first one where the guard itself is the desync risk. `test/docs-route-coverage.test.ts:33-58` protects the judge-facing `/docs/api` page by hand-mirroring `src/index.ts`'s `app.route()` calls in a local `buildApiApp()`, with a comment admitting it mirrors rather than imports; a new sub-app mounted in index.ts and forgotten here would leave its endpoints undocumented AND leave the test green — the exact failure the test exists to prevent. Separately, `app/src/pages/settings/ExportsPanel.tsx:7-13` hand-copies the five export kinds that `the former src/server/repo/exports.ts:25 (now split across src/server/repo/exports/)` already exports as `EXPORT_KINDS`; they agree today, with nothing making them agree tomorrow. Both are verified as currently CORRECT — this decision buys the invariant, not a bug fix, which is precisely the standing field-guide rule that enumeration means a re-runnable artifact scanning the source, never a hand-picked sample. Decision: the docs coverage test derives its mount list by parsing `src/index.ts`'s `app.route(<prefix>, <ident>)` calls and resolving each identifier through that file's imports, failing loudly and by name on any sub-app it cannot resolve (no allowlist that can silently absorb a new module); and a second test asserts ExportsPanel's kind list equals `EXPORT_KINDS` in both directions.

## Amendment (wave 32): SPA module reachability is enumerated, not assumed — a component whose only importer is its own test is a finding

The field guide records the shape A SHARED COMPONENT WITH ONLY ITS OWN TEST AS CONSUMER MARKS THE SHAPE NOBODY BUILT: a wave built a shared surface, wrote its render test, and never wired it into a page, and nothing failed. DEC-518's parse-source/resolve-imports technique (already reused by test/ssr-link-targets-scan.test.ts and by DEC-550's mount enumeration) is exactly the tool that makes recurrence impossible. Scoped deliberately to app/src/** — one entry point, a bounded population, and the only place the shape has actually occurred. Ruling: a scan builds the app/src import graph from source text and fails on any non-test module unreachable from the SPA entry; the ENTRY/allowlist is two-directional. An orphan is deleted (house rule: no dead code, no compat shims) or wired; it is never left silent.

## Amendment (wave 33): a decision's own file-path references are ENUMERATED against the tree — a path that no longer exists is either corrected or marked historical in the prose

DEC-518's rule is that a cross-file claim is derived by a re-runnable scan, never trusted; its wave-32 amendment applied that to SPA module reachability. The same technique applies to the decision corpus itself, which is the repo's primary index of intent: 1000 decision files carry file:line references written across dozens of refactors, and at least two monoliths have since been split into directories (the former src/routes/api/contacts.ts (now split across src/routes/api/contacts/) -> contacts/, src/routes/portal/tasks.tsx -> tasks/), so decision prose written before those splits now points at files that are gone. A reader who greps decisions/ first (the field guide's standing instruction) is then handed a dead pointer. RULING: a scan asserts every src/, app/src/, scripts/, migrations/ and test/ path token in decisions/*.md either exists on disk or sits in a sentence explicitly marking it historical (former/formerly/was at/superseded/deleted/renamed/moved to/replaced by). Deliberately no allowlist array: an exemption must be a WORD IN THE PROSE, where the next reader of that decision will see it, rather than a line in a test file they will never open. The scan also asserts a non-trivial population so a broken regex cannot pass vacuously.

## Amendment (wave 35): every source-text scan ships a NEGATIVE CONTROL — a proof nobody has ever shown a violation to is not a proof

Twice now a scan that reads as rigorous has turned out to be unfalsifiable: email-shell-sweep's "every send site is accounted for" test asserts the identical predicate in both arms of its branch (six files declared against eight real send sites), and the route-authz enumeration accepts a CSRF guard as an authorization guard. Both passed continuously while the invariant they claim to hold was false. DEC-518 already rules that a cross-file manifest is DERIVED in a test rather than hand-mirrored, including the test that guards a manifest; this amendment extends that to the predicate itself. RULING: a scan's detection logic must be a pure function over source text (fileText, repoRelPath) -> violations, and the scan file must contain at least one test that feeds it a synthetic VIOLATING snippet and asserts the violation is reported, plus one compliant snippet asserting silence. Where a scan compares a declared list against a discovered population, BOTH directions are asserted — declared-but-absent and discovered-but-undeclared — and two branches asserting the same predicate is a bug, not a style. A scan without a negative control is treated as unproven.

## Amendment (wave 36): the rubric-coverage claim is a DERIVED, two-directional ledger, not sha-pinned prose

docs/verification-log/task-w13-g-rubric-coverage-stage1.md tables all 116 `- id:` rows of docs/eval-rubric/*.yaml with a file:line + test citation each, RESULT: PASS — and it is frozen at sha 0578511. It is the single largest CURRENT-tense claim about the tree in the repo and nothing checks it; its own prose already records that src/routes/review.ts (formerly a monolith, now decomposed) and src/server/repo/public.ts (formerly a monolith, now decomposed) were split under it, which is precisely the drift DEC-518's decision-path scan was written to catch (test/decision-path-references.scan.test.ts, scoped to decisions/*.md only). DEC-459 set the precedent for exactly this move — replacing pinned route-authz prose with a scan that re-derives the population at test time. Same shape here: population re-derived from the yaml, ledger in the test file, exact in both directions, every cited artifact path must resolve on disk, waivers must name a DEC. A frozen evidence log stays frozen (historical documents may point at moved files); what becomes executable is the coverage claim, carried forward into a live artifact.

## Amendment (wave 39): a rendered whole-set count comes off the envelope — an enumerated, two-directional SPA ledger with named exclusions

Two independent surfaces this wave and last were caught reporting a page as the whole: ReviewerQueue.tsx derives "N left to score" from res.items after the server clamped to 200, and MergePage.tsx reports res.items.length as the pair total. Fixing instances leaves the family. DEC-518's own discipline (a claim becomes a scan that re-derives its population at test time, in both directions, shipping a negative control) is the right closure: every non-test module under app/src/pages/** that reads a paged list endpoint carries exactly one ledger verdict — `envelope` (counts read from res.total/res.count), `page-scoped` (the number is deliberately about the visible rows and the source says so, e.g. FilesLibrary's "Download all N"), or `unpaged` (the endpoint returns the whole set by contract) — and every ledger row names a live file. Exclusions are named with their owning task in the file header, never silently omitted, so the ledger is honest rather than short.

## Amendment (wave 41): the count-source population is every reader of a PAGINATED ENVELOPE, whichever helper fetched it

test/spa-count-source-ledger.scan.test.ts derives its population as 'app/src/pages/** modules calling apiList', and states in prose that MergePage.tsx 'is the one place this codebase calls apiGet against a paginated list route'. That claim is false on the current tree: app/src/pages/content/FilesLibrary.tsx calls apiGet<EventFilesEnvelope>('/events/:id/files?...') against a page/perPage route (src/routes/files.ts:241-244) — it happens to behave correctly, which is precisely why nobody noticed the population is blind to that whole family. A scan whose own honesty prose is untrue is the same class of defect as a decision with no code. Ruling: the ledger population is derived two-sidedly — paginated envelope routes enumerated from src/routes/** (handlers returning {items, total, ...}), SPA modules enumerated by the URL literals they fetch with EITHER helper — so a future count lie told through apiGet is caught, and the false 'one place' sentence is corrected rather than left standing.

## Amendment (wave 42) — the /docs/api endpoint table is a cross-file manifest of the router and must be DERIVED-CHECKED in both directions, not hand-mirrored

J12 sells the REST API as the premise ('No lock-in is not a feature of this product; it is the premise'), and src/routes/docs.tsx hand-types ~90 endpoint rows (180 method:/path: lines) while test/docs-page.test.ts only greps a handful of strings. test/helpers/registered-routes.ts already enumerates every registration under src/routes/** + src/index.ts resolved to its full mounted path, so the population exists and the doc table is exactly the hand-mirrored manifest DEC-518 bans. RULING: the endpoint rows move to a JSX-free module src/routes/docs-endpoints.ts exporting `API_DOC_ENDPOINTS: { method: string; path: string; role: string }[]`, docs.tsx renders from that single source, and a scan asserts both directions against the derived /api/v1 population — every documented row names a live registration, every live /api/v1 registration is documented or carries a reasoned row in a small DOCS_OMITTED ledger. Drift found by the scan is fixed in the data, never by loosening the scan.
