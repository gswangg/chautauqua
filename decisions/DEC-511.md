# DEC-511: The LIKE-escaping invariant is locked by a globbed enumeration over the repo layer, not by the spot checks that let it rot three times

DEC-506 has now landed and is correct: src/server/repo/like.ts is the single escape-only helper (no case folding), both former duplicates are deleted, and every call site pairs the pattern with `ESCAPE '\\'` — including the two unauthenticated public search boxes that previously returned the whole roster for `?q=%`. But this invariant has been broken and re-established repeatedly precisely because it was only ever asserted by hand-picked behaviour tests: at DEC-333/335 two copies existed and three sites had neither escaping nor an ESCAPE clause, and nothing failed. The field guide's own standing rule is that enumeration means a re-runnable ARTIFACT scanning the expression, never a const's existence or a sampled call site. Decision: a source-scanning test globs every src/server/repo/**/*.ts and asserts, naming file:line, that (a) exactly one module exports likeContains and it never case-folds, (b) every sql template containing LIKE also contains ESCAPE '\\', (c) no file imports Drizzle's like/ilike helper, which emits no ESCAPE clause, and (d) every LIKE-bearing template is case-consistent — it carries either COLLATE NOCASE or lower(), so a folded pattern never meets an unfolded column. No hand-listed allowlist: the file set is derived, so a new repo module is covered the day it is written.
