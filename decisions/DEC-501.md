# DEC-501: An answer never outlives the rule that made it askable: the writer deletes what the validator hid

validateAnswers strips rule-hidden answers from `cleaned` entirely (src/forms/validate.ts:47-50), and saveSubmissionEdits only upserts the keys present in `cleanedAnswers` (src/server/repo/portal-edit.ts:275-299). The only `delete(schema.submissionAnswer)` in the tree is the field-delete cascade (src/server/repo/forms.ts:344). So a speaker switching format Workshop->Talk leaves the orphaned 'workshop length' row in submission_answer, where it still renders in the organizer submission detail, the reviewer's sessionAnswers (src/server/repo/review/submissions.ts:354), and every CSV/JSON export — stale data presented to a decision-maker as current. The removal set is computed by the same function that strips them: validateAnswers' success result additionally reports `hiddenFieldIds`, and saveSubmissionEdits takes it as a REQUIRED parameter and deletes those rows set-based. Two implementations of one visibility rule means one of them is wrong; there is exactly one.
