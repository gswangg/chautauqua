# DEC-902: The library counts its kinds in ONE grouped query, and a chip for a kind nobody has is not offered

app/src/pages/content/FilesLibrary.tsx:95-105 fires one GET per LIBRARY_KIND (plus a base call) purely to label the filter chips — the standing anti-pattern in its exact form: a per-kind count re-scanning per kind is N scans where one GROUP BY answers everything, and it re-runs on every keystroke-settled search. Rule: GET /events/:id/files returns kindCounts in its own envelope, computed by ONE `group by kind` query in src/server/repo/files-library.ts against the same predicate (including q) the list uses, so the printed number and the list arithmetic are the same query; the client's fan-out is deleted, not merely memoized. A kind whose count is zero renders no chip at all (offering a filter that can only empty the list is a dead control), and the library gains the page header the frame shows — breadcrumb, H1 'Files', the total/size stat ON the header row — with the search box to the LEFT of the chips it narrows, and a VERSION column showing the file's own version number.
