# DEC-902: The library counts its kinds in ONE grouped query, and a chip for a kind nobody has is not offered

app/src/pages/content/FilesLibrary.tsx:95-105 fires one GET per LIBRARY_KIND (plus a base call) purely to label the filter chips — the standing anti-pattern in its exact form: a per-kind count re-scanning per kind is N scans where one GROUP BY answers everything, and it re-runs on every keystroke-settled search. Rule: GET /events/:id/files returns kindCounts in its own envelope, computed by ONE `group by kind` query in src/server/repo/files-library.ts against the same predicate (including q) the list uses, so the printed number and the list arithmetic are the same query; the client's fan-out is deleted, not merely memoized. A kind whose count is zero renders no chip at all (offering a filter that can only empty the list is a dead control), and the library gains the page header the frame shows — breadcrumb, H1 'Files', the total/size stat ON the header row — with the search box to the LEFT of the chips it narrows, and a VERSION column showing the file's own version number.

## Amendment (wave 41): the content view switch is a DESTINATION on the title row, not a tab band; both content tables share ONE 2px ink header rule

ContentApp renders a persistent .chq-toolbar band (Worklist/Files pills + Refresh) above every content view; frame 05 has no such band — the title row carries "All files" and "Refresh" as buttons. Two views of one surface reached by a link are a destination, not a tablist, and role=tab/aria-selected on a pair that swaps the whole page body is a false promise to AT. Ruling: /content's title row renders [All files][Refresh]; ?view=files renders [Worklist][Refresh]; ?view= URL state, the reload-on-switch and the deep-link behaviour are unchanged. Separately, the worklist and the library are ONE table vocabulary (.chq-content-table): the 2px ink header rule the speakers matrix took in w39 is declared once on .chq-content-table thead th and is owned by the worklist lane, so the library lane must not declare a second.

## Amendment (findings wave 4): in the files library FILE is the elastic column; SESSION/VERSION/SIZE are fixed

docs/design/Chautauqua Content.dc.html:311 is explicit: `1fr 190px 108px 92px auto` at gap 16 — the filename column takes whatever is left and every other column is pinned. On main only VERSION (64px) and SIZE (90px) carry widths; FILE and SESSION are both auto, so the browser hands SESSION whatever its longest title wants and starves the filename column, which is why filenames wrap mid-token. Pinning SESSION at 190 and leaving FILE unpinned is the whole fix, and it also corrects the two widths that were guessed.

## Amendment (wave 18): the files-library table is fixed-layout — two unwidthed columns means the last one eats the measure

content.css:818-822 declares widths for Session (190), Version (108) and Size (92) and states "File carries no width class -- it takes the remainder (the 1fr)". That assumption is false: the trailing actions column is ALSO unwidthed, and under table-layout:auto the remainder lands on the last unwidthed column — the fleet measured FILE at 127px against ACTIONS at 923px, i.e. filenames truncated so a Download link could have a fifth of the screen. The frame's grid is 1fr 190px 108px 92px auto (docs/design/Chautauqua Content.dc.html:311). RULE: `.chq-content-files-table` is `table-layout: fixed`; the actions column carries an explicit hug width via its own class on both the th and the td, leaving File as the single remainder column; the stale comment is replaced by the rule, not amended with another paragraph.


## Amendment (wave 20): every admin list table declares table-layout:fixed with frame-derived column widths and exactly ONE remainder column; the phone card reflow is never fixed-layout

Gate-8 measured the failure on the files library (FILE 127px while ACTIONS absorbed 923px) and w18-d fixed that ONE table (content.css:812 table-layout:fixed). The same defect class is untouched everywhere else: .chq-submissions-table (submissions.css:186) and .chq-contacts-table (styles.css:1129) are width:100% auto-layout with ZERO column widths, and both frames give exact tracks — Submissions.dc.html:103/107 `28px 74px 1fr 150px 130px 108px 92px 118px 64px` and Contacts.dc.html:97/101 `26px 1fr 130px 118px auto`. Submissions is the worst case: it has TWO trailing unwidthed action columns and a ColumnPicker that adds columns at runtime, so the allocation is not merely wrong, it is unstable. RULING, binding on both lanes so neither invents its own: (1) table-layout:fixed; (2) per-column widths transcribed from the frame's grid tracks; (3) exactly ONE column — the title/identity column that carries the 1fr — is left unwidthed; (4) trailing action columns take width:1px so they hug their content; (5) each ColumnPicker custom column takes the frame's own custom-column track (118px), one stated width rather than a per-field guess; (6) under table-layout:fixed the first row governs, so per-<th> class hooks are sufficient and no <td> needs to change; (7) the <=700px card reflow must stay auto-layout — scope the fixed rule above the phone breakpoint or reset it inside the existing phone block, and assert that in the test. This is anatomy, not a schema or data change.

## Amendment (wave 23): the column contract, generalized, with two reasoned exemptions

Every admin `<table>` carrying a `chq-*-table`/`chq-*-grid` hook must pin its geometry one of exactly two ways. (i) TABLE IDIOM: `table-layout: fixed` declared at top level (outside any @media) plus a declared width on every column but exactly ONE remainder; a hug/action column takes `width: 1px; white-space: nowrap` (the shape already landed at settings.css `.chq-settings-tokens-col-actions` and review.css `.chq-review-results-col-decision`), and the remainder column carries NO class hook, since a className with no rule behind it is what DEC-976 forbids. (ii) ROW-GRID IDIOM: the page sheet declares one `grid-template-columns` shared by `thead tr` and `tbody tr` (`.chq-detail-page .chq-participants-table`, detail.css:641). Verified still-unpinned members at this tip: `.chq-comms-templates-table` (styles.css:1297, `width:100%` only, 2 columns), `.chq-contacts-import-review-table` (contacts-panels.css:930, 4 columns), `.chq-settings-exports-table` (settings.css:464, 3 columns), `.chq-settings-sessionboard-mapping` (settings.css:536, no widths). Two exemptions, stated as reasons and never as an allowlist populated from failure output: (1) a table whose COLUMN COUNT is data-driven — the speakers matrix is one column per task, and README `## Widths` says those tracks split the measure evenly — pins only its identity column under fixed layout; (2) the phone reflow block (`display:block` cards) never carries width or `table-layout` rules, because table layout is moot there.

## Amendment (wave 61): the files library issues waves, not a ladder

DEC-902 already ruled that the library counts its kinds in ONE grouped query rather than a per-kind fan-out — the client-side N+1 is gone. The server-side ladder that replaced it was never audited: src/server/repo/files-library.ts runs eight awaited statements with zero Promise.all anywhere (event row -> kindCounts -> deliverable roots -> sizes -> page rows -> version chains -> contact names -> headshot versions). Locally that is invisible; over the wire it is the whole measured 117-145ms, and it grows with every column the library learns to show. Ruling: the reads split into two declared waves — wave 1 is everything keyed only on (eventId, params) and wave 2 is everything keyed on the PAGE's resolved ids — and nothing else changes: the same predicates, the same ordering, a byte-identical envelope. The kindCounts query keeps sharing the list's predicate (including q), which is DEC-902's original point and must not be traded away for concurrency.
