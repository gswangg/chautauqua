# DEC-498: Concurrent evidence lanes each own a port and never kill by process-name pattern

docs/verification-log/task-w21-d-walkthrough-stage1.md's process note records a real, twice-repeated loss of a lane's work on this machine: a sibling lane ran `pkill -f "wrangler dev"; pkill -f "vite"`, which matches by cmdline substring across every worktree on the shared host, killing a different lane's server mid-run, and a worktree with no commits yet was wiped. This wave runs up to five lanes that each need a booted `wrangler dev` plus a migrated+seeded local D1. Decision: each such lane binds an explicitly assigned port (w25-a 8791, w25-c 8792, w25-e 8793, w25-f 8794; the render-sweep gate picks its own free port) and passes it through the tool's own flag (`--url`, `PERF_URL`, `npx wrangler dev --port N` plus the README-documented `--var PUBLIC_BASE_URL:http://localhost:N`); no lane may kill a process by name pattern -- terminate only the child process you spawned, by PID. Local D1 state lives under each worktree's own .wrangler/, so per-lane migrate+seed is safe as long as the ports do not collide.
