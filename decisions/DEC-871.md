# DEC-871: A <td> is a table cell, never a flex container

VERIFIED. content.css sets `display:flex` on `.chq-content-row-session` (69), `.chq-content-row-latest-file` (84) and `.chq-content-actions` (58), and SessionList.tsx applies all three to the `<td>` itself (127, 141, 164). A td with display:flex stops generating a table-cell box, so its border-bottom is laid out against its own box instead of the row's: separators land at different y per column and baselines drift — the Content GATE-1 "BROKEN: worklist row separators STAGGERED". Decision: the td keeps its default table-cell display and every multi-line cell wraps its content in an inner div that carries the flex column; the class names the existing render tests query keep matching the same text. Generalized as a scan: no rule that targets a class applied to a `<td>` may set display:flex, asserted by a test over content.css + SessionList.tsx so the next five-column IA edit cannot reintroduce it.
