# DEC-388: D1 bind values are primitives: a timestamp comparison inside a raw sql template interpolates epoch milliseconds, never a Date

Verified on main: src/server/repo/overview.ts:324 builds the DEC-370 overdue-task cutoff as sql`${schema.task.dueDate} is not null and ${schema.task.dueDate} < ${new Date(now)}`. Drizzle passes a raw-template interpolation straight through as a bind param, and D1 rejects object-typed values outright (D1_TYPE_ERROR: Type 'object' not supported), so GET /api/v1/events/{eventId}/overview throws on every call for any event that has task rows -- which is every seeded event and every real one. /admin/overview has therefore been broken for every organizer since DEC-370 landed, and it is the first route the render sweep visits, which is why the wave-3 gate measured 0 of 34 desktop routes. The rule: inside a raw sql template, a timestamp comparison takes the numeric epoch-ms value the function already holds (`< ${now}`), matching both the column's storage mode (integer(..., {mode:'timestamp_ms'}) in src/db/schema.ts) and the correct idiom already in src/server/repo/tasks.ts:238. Column-mapped writes through Drizzle's typed builders keep passing Dates -- those go through the column's mapToDriverValue and are fine; the ban is specific to raw templates, where nothing encodes the value. This is invisible to the current unit tests by construction: the overview suite's fake db is a chainable object whose `then` pops a queued response, so no bind ever happens. The rule therefore comes with a source-level guard rather than a behavioural one.
