# DEC-820: Every portal page says who is signed in

VERIFIED PortalLayout (src/routes/portal/shared.tsx:44-98) takes an optional speakerName and renders it beside the wordmark, but only /portal passes it (index.tsx:269). The six subpages — profile, edit, tasks, task detail, submissions list, submission detail — render the event wordmark alone, so the moment a speaker leaves the home page the portal stops telling them whose account they are in. DEC-777 correctly removed the welcome tagline from subpages because it displaced identity; it never restored the identity it was displacing. Decision: every PortalLayout call site passes the signed-in contact's name, which speakerGate has already resolved on each of those routes, and a scan test ENUMERATES the `<PortalLayout` occurrences under src/routes/portal asserting each one carries speakerName — so a new subpage cannot ship anonymous.
