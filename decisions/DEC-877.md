# DEC-877: The frame's reading column is 820px CENTERED: a single-column page clamps BOTH its header row and its content column to one token; a page with an aside clamps nothing

styles.css already defines --chq-measure: 820px and a .chq-measure class, but .chq-main has no max-width and Overview's root is a bare .chq-page, so every Overview section renders 43-67% wider than the 1240 frame's 820px content column. The CFP builder is the mirror failure: .chq-forms-content clamps with var(--chq-measure) while .chq-forms-header spans the full width, so Preview/Save float over dead space and the page reads as two documents with two left edges. A defined token nobody applies clamps nothing. Rule: a single-column organizer page (Overview, the builder, Settings) carries the shared measure on its header row AND its content column, from the one token — never a page-local literal, never a second variable. A page that carries an aside (Contacts, Agenda, Content, Submissions detail) fills the frame and clamps nothing; .chq-page must NOT be clamped globally because two-column pages share that class. This supersedes sweep-A's provisional "exempt the builder" note: the gate-1 fleet measured the frame directly and the 820 token is frame-true.
