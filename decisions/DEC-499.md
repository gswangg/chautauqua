# DEC-499: iCalendar parameter values are sanitized at the serializer: CN strips DQUOTE and every control character

src/mail/ics.ts:102 `sanitizeCn` strips only `"`. It is the ONLY sanitizer applied to `ORGANIZER;CN=` (ics.ts:121, fed from `event.name`) and `ATTENDEE;CN=` (ics.ts:125, fed from a contact's first/last name, which is unauthenticated public-CFP `text` input with no newline check in src/forms/validate.ts). `escapeText` is deliberately not applied to parameter values (they are RFC 5545 quoted strings, not TEXT), and `foldLine` folds per already-assembled line, so a submitter named `Ada\r\nX-EVIL:1` emits a raw CRLF inside a content line and injects an arbitrary iCalendar property into every `/e/:slug/agenda.ics`, `/e/:slug/schedule.ics`, and every REQUEST attachment the comms compose sends. RFC 5545's QSAFE-CHAR is "anything but CTL and DQUOTE", so the sanitizer strips exactly that set: DQUOTE plus C0 controls plus DEL. Fixing at the serializer, not at the three separate input paths, because the serializer is the single choke point and one of the inputs is a public form we do not control. `;` and `:` remain legal inside the quoted value and must be preserved — over-stripping is its own bug.

## Amendment (wave 23): sanitizeCn's rule extends to the ICS address half, from one shared sanitizer

src/mail/ics.ts:143 and :148 emit `ORGANIZER;CN="…":mailto:${opts.organizer.email}` and the ATTENDEE equivalent. sanitizeCn correctly strips `"` and control bytes from the CN parameter, but the mailto address is interpolated unguarded — the same asymmetry DEC-996 fixes in the MIME serializer. Ruling: both serializers share ONE exported address sanitizer rather than each growing its own copy (the codebase has already paid for hand-copied sanitizers twice: see the field guide's SCAN BINDS ONE CALL SHAPE MISSES SIBLING and DUPLICATED ENUM MESSAGE DRIFTS shapes). Both files stay pure-core (DEC-002), so the shared helper must import nothing beyond Web APIs.
