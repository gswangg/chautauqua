# DEC-038: Scoped KV rate limiter in src/lib/rate-limit.ts; login/claim limits

SPEC §6 requires rate limits on auth, and unthrottled login burns a 600k-iteration PBKDF2 per guess (brute-force plus cheap DoS). New pure module src/lib/rate-limit.ts (Web APIs + plain KV interface only, DEC-002): scopedRateLimitKey(scope, id, windowStartMs) -> `ratelimit:{scope}:{id}:{windowStart}`, checkAndIncrementScopedLimit(kv, scope, id, now, {windowSeconds, max}), and requestIpFromHeaders(header) (cf-connecting-ip, then first x-forwarded-for hop, else 'unknown'). POST /login: scope 'login', per-IP, 20 attempts/15 min, checked before password verify, 429 with an on-page error. POST /claim/:token: scope 'claim', same params. The existing submit limiter in submit-core.ts is frozen legacy — sanctioned duplication until a later cleanup wave migrates it, so parallel wave-5 tasks never contend for the same file.
