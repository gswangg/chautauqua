# DEC-407: The walkthrough runs every area and prints a summary; one area's failure never hides another's, and J2 asserts the word the shipped copy keeps

SPEC §9 calls the persona walkthrough "the real bar", but scripts/walkthrough.ts:62-66 returns on the first area with a non-zero exit, so the w6-g gate log records review/speaker/public/data as "NOT RUN" — four of five areas have gone unmeasured for the whole redesign phase because of one stale string. That is a harness defect, not a product one: scripts/walkthrough/producer.ts:378 asserts /Submissions close/i, but the open CFP header renders "Call for papers · closes {date}" (src/routes/public/submit.tsx:247), which matches the design mock verbatim (docs/design/Chautauqua Public and Portal.dc.html:468) — the product copy is right and the assertion is wrong. So: the orchestrator runs all five modules regardless of failure, records {area, status}, prints a PASS/FAIL summary table, and exits non-zero iff any area failed (a spawn error is a FAIL for that area, not an abort); the pure formatting lives in scripts/walkthrough-lib.ts and is unit-tested. And the J2 assertion is re-pinned to /\bcloses\b/i — the one token both the current copy and DEC-408's timezone rewrite keep — so an assertion never again encodes chrome wording that the design owns.
