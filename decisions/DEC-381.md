# DEC-381: The phone tab bar's five destinations are Overview, Submissions, Speakers, Content, More; the More sheet carries Sign out; the header identity block stops depending on :last-child

DEC-369 named the five tab-bar destinations, but the landed App.tsx derives them as `tabSections.slice(0, 4)` over a filter list that includes `/review/*`, and since NAV_SECTIONS orders Review third the phone tab bar currently reads Overview, Submissions, Review, Speakers — Content is missing from the tab bar entirely and Review is wrongly promoted for organizers who mostly never open it. Fix by building the primary tabs from an explicit ordered path list `['/overview', '/submissions', '/speakers', '/content']` intersected with the role-filtered sections, so the set can never drift with NAV_SECTIONS order again; a reviewer (one section) shows Review alone and no More control. The active tab carries `<span className="chq-dot is-on" aria-hidden="true" />` (inactive items carry no dot), and More carries a plain `.chq-dot` when either exception badge is live, which is the mock's exception dot. The More sheet lists Review, Agenda, Comms, Contacts, Settings AND Sign out — today it omits Sign out, which at phone width is unreachable because the header identity block is off-screen — and it renders as `.chq-scrim` + `.chq-modal` per DEC-378. Two structural corrections come with it: `.chq-tabbar` and the More sheet move OUT of `<header>` and become siblings inside `.chq-shell`, and the identity block gets an explicit `.chq-header-identity` class, because styles.css right-aligns the header's identity via `.chq-header > *:last-child` and the tab bar being a header child silently steals that selector at phone width.
