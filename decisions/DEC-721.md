# DEC-721: The session content screen shows one deliverable at a time: a chip scopes both the version list and the single thread

A submission can carry several deliverables — slides, a recording, a workshop pack — and each is its own version chain with its own thread (DEC-244/DEC-573). The current screen stacks a section per FILE_KIND, each with its own thread, which reads as 'here is everything' while showing several disconnected conversations with no way to tell which chain a reply belongs to. The design pack names the resolution: a chip per deliverable that has files ('Slides · 3 versions'), one selection scoping the versions AND the notes, and a caption saying so. Because the thread belongs to the chain rather than to a person, it is titled after the deliverable — a session can have several speakers, and 'Files for ‹session›' over a single chain promises every file and shows one.
