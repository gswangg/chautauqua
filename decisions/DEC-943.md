# DEC-943: A hub event row's meta names its SHAPE while it is live and its SIZE once it is past

docs/design/Chautauqua Home.dc.html is authoritative and shows two different meta grammars on the org hub: current and upcoming rows read "Three tracks · five formats", archive rows read "48 sessions · three tracks". src/routes/root.tsx prints `sessionsLine(publishedSessionCount)` on all three row shapes instead. The frame is right and the build is wrong for a reason: a published-session count on an event whose programme is not out yet is either zero — in which case the row silently drops its meta and says nothing at all — or a number that tells a stranger nothing about whether the event is worth opening. Shape answers that; size only makes sense in retrospect. Rule: the hub reader (src/server/repo/public/home.ts, listHubEvents) carries `trackCount` and `formatCount` per event alongside `publishedSessionCount`, each from ONE grouped query over the whole page's event ids — never a query per event (DEC-078) — and each counting only tracks/formats that appear on a PUBLICLY VISIBLE session, composing the same `visibleSessionConditions()` the session count already uses, so the row can never claim more than /e/:slug/sessions shows (the DEC-767/DEC-816 rule, applied to the hub). openCfp and published rows render "N tracks · M formats"; past rows render "N sessions · M tracks"; both go through root.tsx's existing spellCount grammar and drop a clause whose count is zero.
