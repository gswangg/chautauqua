# DEC-907: One date grammar for the admin app, in one formatter — and 'who wrote this' is a name and a relative time

app/src/lib/dates.ts:44 and :77 are bare toLocaleDateString()/toLocaleString(), so every admin surface prints '4/2/2026' while every frame in the pack reads '19 Feb', '2 Mar – 20 Mar', 'sent 2 Apr'. Nine separate mandate lines complain about date grammar on six different pages; they are one defect in one function, and fixing them page by page would install six grammars. Rule: formatDate returns '<D> <Mon>' with the year appended only when the date falls outside the current year, formatDateTime returns '<D> <Mon>, HH:MM', and a new formatRelative renders recent instants as '2 days ago' (falling back to the absolute grammar past a week, because 'in 47 days' is not a date). Callers are not touched — the grammar lives in the formatter, which is the point. The timezone-aware event formatter (dates.ts:148 / src/lib/event-time.ts) is explicitly OUT of scope this wave: it is correctly zoned and shared with server-rendered surfaces, and a half-migrated grammar is worse than a consistent old one. The first consumer of formatRelative is the content comment thread, where an organizer's own note currently reads as a raw email plus '(organizer)' plus an absolute stamp — it becomes 'You · 2 days ago' for the signed-in author and the author's display name otherwise.
