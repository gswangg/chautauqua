# DEC-950: Every dialog field is a FormRow, and the rule is a scan, not a habit

DEC-685 made FormRow (app/src/components/ModalFrame.tsx:57) the ONE form-row skeleton every dialog field is built on — label above control at the modal's full measure, `.chq-form-row-control` giving each input the same width, `.chq-form-row-error` giving each message the same glyph-and-weight treatment (DEC-367: never colour alone), `optional` rendering the one OPTIONAL_SUFFIX grammar (DEC-917). NewContactModal.tsx never got the memo: all five of its fields are bare `<label>Text<input class="chq-input">` pairs with `<span class="chq-field-error">` messages, which is why the gate report reads 'new-contact modal unstyled' — it is not unstyled, it is speaking a vocabulary the rest of the product retired. It is the only ModalFrame consumer that does. Rule: NewContactModal's five fields become FormRows (Company and Title carry `optional`; field errors go through FormRow's `error` prop, never a sibling span), and a scan test enumerates every module under app/src that imports ModalFrame and fails any that contains a `<label>` with no className — the sixth dialog cannot regress the way the first one did. In the same pass the import wizard's file input takes the shared `.chq-file` control (DEC-894's rule, already honoured by the contact drawer, the resources panel and the Sessionboard importer, and the one raw input[type=file] left in the SPA).
