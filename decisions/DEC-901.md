# DEC-901: A deliverable detail is headed like every other detail page, and a version row always names its number

app/src/pages/content/DeliverableDetail.tsx renders no breadcrumb, no H1 and no status band (grep for 'breadcrumb'/'CONTENT STATUS'/h1 finds nothing), so the one screen where an organizer decides a session's content opens without saying which session it is or where the reader came from. And app/src/pages/content/VersionList.tsx:66 labels the newest file 'Latest' INSTEAD of its version number, so the row that matters is the only row whose position in the chain cannot be read. Rule: the page is headed '‹ Content' back link above a session-title H1, a subtitle 'Speaker · CODE · slot, Room', a sunk CONTENT STATUS band naming when it changed and by whom, and a DELIVERABLES section rule over the files — the same header anatomy the rest of the product already uses. The newest row reads 'v<N> · Latest' (number AND marker, never the marker alone); a row superseded by a later upload carries REPLACED; a version uploaded after a changes-requested decision says so. Decision buttons take their frame hierarchy — 'Ask for changes' is the primary with its helper line BELOW the row, not beside it.
