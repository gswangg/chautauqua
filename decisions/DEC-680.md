# DEC-680: A list's `total` is a count(*), never the length of a materialized scan; and 'accepted speaker' is ONE predicate

src/server/repo/files-library.ts:478-485 computes the headshots tab's `total` by SELECTing every distinct contact id in scope and taking `totalRows.length` — an unbounded read that grows with the speaker roster (600 at the mandated aie scale) purely to produce a number, while its sibling listing in the same file (:147) already does `Number(count(*))`. The field-guide pagination rule is one shape + count* + `id asc`; a page that materializes its own total is the same read the page window exists to avoid. Second, :451-455 hand-copies the 'submission accepted AND participant invite status active' definition that src/server/repo/tasks.ts's listAcceptedContactIds already owns and that src/routes/api/contacts/{crud,import}.ts both import — a second copy of a scoping rule that can drift out of sync the moment acceptance changes. Two readings of 'is this an accepted speaker?' must end in one exported condition builder.
