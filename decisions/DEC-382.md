# DEC-382: The three operator surfaces (/, /docs/api, /dev/mailbox) share one TOOLS_CSS module and the shell pattern; they are chrome, not designed screens

DEC-371 listed root, docs and the dev mailbox among the SSR surfaces, but wave 2's four lanes cover only public, portal, CFP and auth, so these three still carry ad-hoc inline `<style>` text children and browser-default `<h1>/<dl>/<table>` bodies — and the dev mailbox is the stage-1 email sink an evaluator is explicitly told to open. They are not in the design pack (no frame exists for them), so no layout may be invented: they take the established shell pattern — 1px-ink header with the lowercase wordmark, `<main className="chq-measure">`, `.chq-section-label` over a 2px rule, `.chq-table`, `.chq-kv`, `.chq-pager`, `.chq-btn` tiers — and nothing else. One co-located module `src/routes/tools.css.ts` exports `TOOLS_CSS: string` (classes prefixed `.chq-tool-*`, never restating a token and never redefining a THEME_CSS class, per DEC-373) plus `ToolsStyles()` rendering it through `dangerouslySetInnerHTML` per DEC-374, and each of the three shells renders exactly `<ThemeStyles />` followed by `<ToolsStyles />`. Behaviour is untouched: the `shouldMountDevMailbox` DEV_MODE guard, the `sandbox=""` srcdoc iframe that keeps recipient HTML out of the mailbox's own DOM (SPEC §6), the .ics download route and the /admin ASSETS proxy all stay exactly as they are.

## Amendment: an operator surface must be DOCUMENTED as one — a designed 404 that the docs send judges to is an operator-docs defect

DEC-382 named `/`, `/docs/api` and `/dev/mailbox` as chrome. Wave 67 correctly reclassified the "/dev/mailbox 404s" finding as not-a-product-defect: the route is mounted behind `guardDevMailbox` (`src/server/app.ts:90-103`) and 404s unless `DEV_MODE==='1'` (DEC-005/DEC-546). But it then left the operator docs unchanged, so two eval runs sent judges to a path that is DESIGNED to fail on a deployed build — and judges read the docs. Ruling: naming a surface as operator-only is half the decision; the docs must say so at every mention, or the design is invisible and reads as breakage. Same clause covers `PUBLIC_BASE_URL`, which the prod-like load test found load-bearing on deployed origins (`resolveBaseUrl` fails loudly; bulk-email 500s without it): a variable whose absence 500s a user-facing send belongs on the deploy parity checklist, not in a perf report appendix.

## Amendment (wave 3): the /docs site is a designed public surface with its own chrome; the API reference keeps TOOLS_CSS behind a named leaving link, and an unknown slug is a 404

DESIGN-RULINGS.md:298-316 makes /docs a NEW user-facing route and explicitly declines to revise DEC-382 for /docs/api — the seam is named, not hidden. RULING, so the shell cannot be invented twice: the site is SSR under src/routes/docs-site.tsx (exporting docsSiteRoutes), styled by its own src/routes/docs-site.css.ts in the src/routes/public/home.css.ts idiom over ThemeStyles, never the SPA sheet. It mounts in src/index.ts AFTER the existing app.route('/', docsRoutes) so GET /docs/api keeps resolving to the TOOLS_CSS reference. GET /docs renders one section per DOCS_GROUPS entry in declared order, titled from DOCS_GROUP_META, and a group with no articles renders the codebase's named empty state — never a bare empty bucket. GET /docs/:slug renders one article; an unknown slug is a 404, never a redirect to the index. Measures: prose 680, figures 900 (the one sanctioned measure break, :304); on phone figures go edge-to-edge with the caption inset. A figure block renders a NAMED PLACEHOLDER frame carrying its shotId plus its caption until the freeze-time shoot fills it — never an `<img>` pointing at a file that does not exist, because screenshot rule 1 forbids showing a screen that is not there.

## Amendment (wave 9, sha 3323a7b7): docs search is a QUERY on GET /docs, never a new route, and the index carries the API-reference leaving row the ruling names

The Docs frame draws a search control in two places — the index intro block (`docs/design/Chautauqua Docs.dc.html:136`, max-width 420 / 15px) and the compact header cluster on the article and element-library sheets (`:39`, `:237`, min-width 260 / 13px) — and the built site (`src/routes/docs-site.tsx` `DocsHeader`, `DocsIndexPage`) has neither. Ruling: the search surface is `GET /docs?q=` rendering a results state on the SAME route, never a new `/docs/search` registration — the public route surface stays exactly what `PUBLIC_ROUTE_GROUPS` and the README evaluator table already have to describe, so shipping search costs no manifest churn and no cross-task coupling; it is also the no-JS-correct shape, a GET form whose action is the page it came from. Separately, `DESIGN-RULINGS.md:306` requires the API reference to be labelled "Leaves the docs — an operator surface" IN THE INDEX as well as in the header, and the frame draws it as the last row of the "Running the software" group (`:436`); the built index renders only `DOCS_ARTICLES` rows, so that half of the ruling is unbuilt. Both halves land from the ONE existing `DOCS_API_LEAVING_LINK` constant — never a second hand-typed label/href (DEC-613's two-vocabularies trap).
