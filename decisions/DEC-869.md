# DEC-869: A menu of states names each state's consequence, marks the one in force, and emphasizes the only item that sends mail

DEC-830 landed the participation MENU (app/src/pages/speakers/ParticipationMenu.tsx) and the eval mandate's remaining Speakers residue names what the frame (04-speakers--05-participation-open) has that it doesn't: per-item consequence captions, a NOW mark on the current state, an identity header, and olive emphasis on the action. Today one shared caption ('Invited and Declined hide this speaker from the public pages and pause their uploads') sits above four bare labels, and the current state is marked by CSS class alone — invisible to a screen reader and to anyone reading the row quickly. It is also imprecise: 'none' (Not invited) is an ACTIVE invite status, so a not-invited speaker IS on the public pages — the single caption cannot say that, and per-item captions must. Decision: PARTICIPATION_CONSEQUENCE_CAPTION is replaced by an exhaustive `PARTICIPATION_STATE_CAPTIONS: Record<InviteStatus,string>` (a Record so a new state cannot ship caption-less), with exactly this copy — none: 'Nothing has been sent. They still appear on the public pages.'; invited: 'Records that the invite went out. Hidden from the public pages until they confirm.'; accepted: 'Public pages and uploads are open.'; declined: 'Hidden from the public pages, uploads paused.' The panel opens with the speaker's name as an identity header; the four state items become role="menuitemradio" with aria-checked (they are a single choice, and the frame's NOW badge is that fact rendered) and the current one carries a NOW badge; 'Send portal invite' stays role="menuitem", keeps PARTICIPATION_FOOTER_CAPTION beneath it, and is the only olive-emphasized item — it is the only one that sends anything. No behavior, vocabulary or PATCH changes.
