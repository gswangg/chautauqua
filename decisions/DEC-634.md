# DEC-634: A public list filter is a query predicate, never a post-page sieve

?day= on the sessions surface is applied AFTER the SQL window in both twins — src/routes/public/dispatch.tsx:39 and src/routes/public/index.tsx:300 filter the already-fetched page and then report `total` as the length of that filtered page. Below one page it looks right; past it the surface silently drops sessions and states a total that contradicts the count, breaking exactly the truncation-detection contract DEC-484 built `total` for and re-committing the class DEC-594 was closing. Decision: `day` becomes an argument to getPublicSessions and enters BOTH the id query and the count query, so items and total come from one WHERE; the predicate reuses the same event-window rule that decides whether hydrateSessions reports a day at all (a slot outside the window is unscheduled and matches no day filter), because two readings of one fact end in one helper.
