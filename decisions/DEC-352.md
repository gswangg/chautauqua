# DEC-352: Gate evidence is invalidated only by a change that can alter what that gate asserts; wave 22's exit set is exactly one build/test lane

DEC-343, DEC-347 and DEC-349 each pushed the walkthrough and perf gates one wave later because every wave's product lanes branch from the same tip the gates measure. That regress does not terminate on its own — wave 22 would owe the same three gates for wave 21's lanes, and so on forever. Break it with a stated, checkable rule rather than a fourth deferral. A gate log stops being authoritative only when a later commit can change something that gate actually asserts. Wave 21's two product lanes cannot. task-w21-d is confined to app/src/**, and the six walkthrough modules are HTTP-level scripts that never load the admin bundle (their sole /admin assertion is scripts/walkthrough/producer.ts:798's unauthenticated 302), while perf:smoke times API and SSR routes only; its SPA coverage lives in npm test's render tests. task-w21-e changes only the column list of two SELECTs behind /progress and /remind under DEC-351's byte-identical-response contract, which can only make those routes faster and carries its own route test. Both DO change compiled code, so build/test/tripwires must be re-run. Therefore: task-w21-b's walkthrough log and task-w21-c's perf log are the authoritative stage-1-exit evidence for those two gates; wave 22's exit set is exactly ONE lane — npm run build + npm test + the four test/ tripwires + the fresh-migration/seed proof at a tip containing task-w21-a..e — and the first planner that can read task-w21-a/b/c at RESULT: PASS with OPEN ITEMS: 0, task-w21-d/e merged, and that wave-22 lane green returns zero tasks with goalComplete: true. If task-w21-d or task-w21-e turns out to alter a wire shape or a walkthrough-visible route, the owning lane must say so in its commit message and the walkthrough + perf gates return to wave 22's set — this shortcut is void in that case. A FAIL in any wave-21 gate yields a narrow wave over the cited file:line only; DEC-315's anti-padding rule survives intact.
