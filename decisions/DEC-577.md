# DEC-577: Native controls are styled once in the shell lane; converting a select into a segmented control is per-page markup and stays with that page's redesign

input[type=file], input[type=date] and <select> were never styled anywhere, which is why a judge's first sighting of the Content page is a browser-default grey "Choose File" button next to a fully designed table. That is a shell-lane defect (DEC-368: app/src/styles.css owns the shared .chq-* components) and gets fixed once, for every consumer, with .chq-file / .chq-input / .chq-select treatments on the frozen tokens. The other half of the finding — decision panel, task Kind, add-to-event and pipeline MOVE-TO becoming pills/segmented/buttons — is not styling but markup surgery inside four different page modules with four different data shapes; it belongs to each page's own redesign task and is deliberately NOT bundled here, so a CSS wave cannot silently rewrite four pages' interaction models. Portal and public surfaces render server-side with their own CSS modules (portal.css.ts, cfp.css.ts, public.css.ts) and are out of this decision's lane.

## Amendment (wave 44): a control class that sets its own type register must also set font-family — `font` never crosses a `<button>` boundary

app/src/styles.css:606 `.chq-pill` declares font-size 12 / font-weight 600 and no font-family. No UA inherits font-family into a form control, so every `<button class="chq-pill">` (submissions view tabs, content library type chips, deliverable chips, the speakers Overdue-only toggle) computes Arial beside Figtree neighbours — one missing declaration, visible on five surfaces. The rule is per-class `font-family: inherit`, NOT a blanket `button { font: inherit }`, because a blanket reset would silently repaint the classes that deliberately choose their own family. Enforced by a scan over the parsed stylesheet so the next control class cannot regress it.
