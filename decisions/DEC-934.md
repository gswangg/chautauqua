# DEC-934: A roster row the product will never chase says so IN the cells it leaves blank

DEC-829 deliberately widened the Speakers roster to every participant of an accepted submission, including 'invited' and 'declined', so their status is visible and fixable. Task expansion (DEC-278/283) just as deliberately covers only ACTIVE_INVITE_STATUSES. The two correct decisions meet in a row that renders an entire strip of empty task cells with nothing explaining why -- and DEC-932's back-fill will, correctly, still skip it, so the emptiness is now permanent by design rather than by accident. A promised column needs an answer on EVERY row. Rule: a row whose participation is 'invited' or 'declined' renders ONE muted cell spanning the task columns, reading "Not chasing - invite <status>. Set participation to Confirmed to assign this event's tasks.", instead of N blank cells; the row's own participation control stays live, because it IS the fix. The grid's outstanding/overdue summary already excludes these rows (overdueAssignmentConditions composes acceptedSpeakerExistsForContact) and must keep doing so -- a test asserts the printed summary and the rendered strip agree on the same set.

## Amendment (wave 44): the invite link renders only on a row that can still be invited

app/src/pages/speakers/OnboardingGrid.tsx:584 gates "Send portal invite" on `!row.contact.hasAccount` alone, so the link renders on every account-less row including rows already invited. Two costs: the producer cannot see at a glance who still needs inviting (the only question the matrix exists to answer), and the extra control is what wraps those rows and breaks the frame's uniform row pitch. DEC-934 already established that a row whose state removes the work renders a quiet marker instead of live controls; invite state is the same axis as participation state.

## Amendment (wave 4): a not-chasing row KEEPS its cells, and the roster names the filter it is under

OnboardingGrid replaces every task cell of a non-Confirmed speaker with a colSpan strip (OnboardingGrid.tsx:694), so an organiser cannot see what is outstanding for the people most likely to need chasing -- run-4 files this as a P2 against the organiser's core job. DEC-934's intent was to stop the product from PRETENDING it will chase someone unconfirmed, not to hide the facts. Ruling: the cells render, quiet and non-actionable (no assign/complete affordance), and the not-chasing sentence becomes the row's caption in plain prose that names the invite state. Same amendment: when a task/status/overdue filter is active the roster prints one caption stating the active narrowing, so a shorter list never reads as missing data.
