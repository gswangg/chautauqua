# DEC-934: A roster row the product will never chase says so IN the cells it leaves blank

DEC-829 deliberately widened the Speakers roster to every participant of an accepted submission, including 'invited' and 'declined', so their status is visible and fixable. Task expansion (DEC-278/283) just as deliberately covers only ACTIVE_INVITE_STATUSES. The two correct decisions meet in a row that renders an entire strip of empty task cells with nothing explaining why -- and DEC-932's back-fill will, correctly, still skip it, so the emptiness is now permanent by design rather than by accident. A promised column needs an answer on EVERY row. Rule: a row whose participation is 'invited' or 'declined' renders ONE muted cell spanning the task columns, reading "Not chasing - invite <status>. Set participation to Confirmed to assign this event's tasks.", instead of N blank cells; the row's own participation control stays live, because it IS the fix. The grid's outstanding/overdue summary already excludes these rows (overdueAssignmentConditions composes acceptedSpeakerExistsForContact) and must keep doing so -- a test asserts the printed summary and the rendered strip agree on the same set.
