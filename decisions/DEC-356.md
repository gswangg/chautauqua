# DEC-356: CSV import never loads the org's whole contact table: the upsert lookup is chunked and keyed on the file's own emails, behind a 2,000-row per-import cap

src/server/repo/contacts/import.ts:33-36 selects every contact row of the org before applying a single line, so an import into a mature speaker network (SPEC §0: multiple events per year sharing one contact network) pays for the whole table to insert ten rows — the same class DEC-335/DEC-336 already retired for the submissions and contacts lists, left standing on the write path. Rule: build the set of normalized (trimmed, lowercased) emails present in the parsed rows, look them up with a chunked `where org_id = ? and lower(email) in (...)` over ID_CHUNK_SIZE batches (src/lib/chunk.ts, DEC-078), and keep the byEmail map updated on create so within-file duplicate emails still collapse onto the same created contact — the DEC-011/DEC-026 semantics, skip reasons, row ordering and ImportResult shape do not change. A single import is additionally capped: MAX_IMPORT_ROWS = 2000, checked before any DB work, rejected with ApiError('invalid') naming the row count and the cap and telling the producer to split the file (fail loudly rather than issue an unbounded write burst).
