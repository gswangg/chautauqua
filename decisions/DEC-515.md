# DEC-515: Exports carry the substance, not just the identifiers: submissions gain `description` + one column per custom form field; speakers gain bio/headshot/social links

Verified at file:line on current main. `src/server/repo/exports.ts:64-98` SUBMISSIONS_HEADER is ref/title/status/contentStatus/tracks/speakers/speakerEmails/createdAt and `exportSubmissions` (:145-156) never selects `submission.description` and never reads `submission_answer` at all; `exportSpeakers` (:231-287) emits firstName/lastName/email/company/title/acceptedSessions/visible and never reads `contact.bio`, `contact.headshotUrl`, or `contact.socialLinksJson` (columns confirmed at `src/db/schema.ts:76-78`). `description` is a LOCKED, always-required built-in (`src/forms/types.ts:41`), so today the abstract text of every talk — the single most important artifact of a CFP — leaves no export at all, and neither does any custom question's answer. SPEC J12's premise is "No lock-in is not a feature of this product; it is the premise of the competition", and J3 already makes "any form answer as a column" a table feature the admin SPA implements (`app/src/pages/submissions/types.ts:47,75` + repo `includeAnswers` at `src/server/repo/submissions/list.ts:216-244`) — the export is the one surface that drops it. task-w27-d's own walkthrough artifact flagged this in passing ("does not emit any custom-field answer as a column today, so this check is trivially true"). Decision, so no worker re-decides shape: (a) existing columns keep their current names and ORDER/index; every new column APPENDS, so existing consumers and snapshots shift by addition only. (b) Submissions append `description`, then one column per non-locked form_field across all of the event's forms, ordered by (form, field position), deduped by field id, values read from submission_answer keyed by field id. (c) A dynamic column is named by the field's label; if that label is empty, duplicated, or collides with a fixed column name, the column name gets a ' (<fieldId>)' suffix so every header cell is unique and the JSON `records` object never loses a key. (d) Speakers append bio, headshotUrl, then four explicit columns twitter/linkedin/github/website (the fixed SocialLinks keys at `src/domain/contacts.ts:223`) — never a raw JSON blob in a cell. (e) Answer fetching is chunked like every other id fan-out (chunkIds), because this runs at the 2k-submission scale target.
