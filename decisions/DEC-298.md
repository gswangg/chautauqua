# DEC-298: Auto-schedule parameters are a bounded, integer-validated allowlist; the greedy loop asserts its own termination invariant

src/routes/agenda.ts:125 numberOrDefault accepts any finite number, so an organizer-authenticated POST of {"gridMin":0} (or a negative grid, or dayEndMin: 1e12) reaches src/domain/schedule.ts:154-157's `for (startMin = dayStartMin; startMin + duration <= dayEndMin; startMin += gridMin)` as a non-terminating loop and burns the Worker to its CPU limit. Nothing catches it because the SPA sends {}. Fix at both layers, per house fail-loudly: the route validates each present key as an integer within bounds (gridMin 1..480, defaultDurationMin 1..1440, dayStartMin 0..1439, dayEndMin 1..1440 with dayEndMin > dayStartMin) and rejects violations with a 400 ApiError naming the offending fields — absent keys keep today's DEFAULT_AUTO_SCHEDULE_PARAMS behavior exactly; and autoSchedule itself asserts the invariants on entry, so no future caller can reintroduce a loop that cannot advance. Clamping silently was rejected: a producer who asks for a 0-minute grid deserves to be told, not quietly given 15.
