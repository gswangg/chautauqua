# DEC-914: A back link names the route it LANDS on, and the portal has one back-link grammar

src/routes/portal/profile.tsx:142 renders `<a href="/portal">← Back to My Submissions</a>` — the label promises the submissions list and the href delivers the portal home. Two lines away, src/routes/portal/index.tsx:480 writes '← Your portal' for the same destination and :422 writes '← Back to My Submissions' for /portal/submissions, so the product has three strings for two routes and one of them is false. The field guide already states the rule that was violated ('a link is the route it LANDS on'), which means the fix is not to retype the string on profile.tsx — a hand-written label per page will drift again the next time a route moves. Rule: shared.tsx exports ONE PortalBackLink taking the destination path and resolving its label from a single table (/portal → 'Your portal', /portal/submissions → 'Your submissions', /portal/tasks → 'Your tasks'), rendered as '‹ <label>'. No portal page writes a back-link string. Same pass: profile.tsx's page heading is an <h2> on a page with no <h1> — the portal's heading level follows the page, not the visual size.

## Amendment (wave 16): a server-rendered href is scanned against the route table, the same way an in-app target already is

DEC-914 gave the portal a back-link table because a link must name the route it lands on, and DEC-837's scan enforces that for every react-router target in app/src. Neither reaches src/routes/**/*.tsx -- the public, portal, auth, account and docs surfaces build hrefs as string/template literals with no guard at all, and the field guide already records this exact bug class twice ('GUESSABLE URL 404 IS DEAD END', 'LINK LABEL RIGHT, HREF A ROUTER PATTERN NOT A ROUTE'). The SSR side is where a dead link costs most: an anonymous visitor has no nav memory to recover with. Every literal internal href emitted by an SSR surface must resolve to a route pattern registered in that same tree (path params matched by shape), or be allowlisted with a reason (external, mailto, in-page anchor).
