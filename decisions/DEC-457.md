# DEC-457: KV keys never carry raw external input: scopedRateLimitKey bounds its id at construction

src/lib/rate-limit.ts:11 builds `ratelimit:${scope}:${id}:${window}` from ids that are wholly attacker-controlled and unbounded: the login form's email (src/routes/auth.tsx:161 -> :177/:181/:195/:199/:207) and the first hop of a client-supplied x-forwarded-for (src/lib/rate-limit.ts:109-114, used at auth.tsx:252 and src/routes/public/submit.tsx:485/:575). Cloudflare KV caps keys at 512 UTF-8 bytes, so a 1KB email or a 4KB x-forwarded-for turns POST /login, POST /claim/:token, POST /submit/:eventSlug and its draft endpoint into unauthenticated 500s with the limiter bypassed -- against DEC-425's standing rule that oversized input is 400, never 500, and it hollows out the ledger row "Rate limits on auth + public submission | VERIFIED" (task-w16-f-spec-audit-stage1.md:85), which was graded from the presence of the call. The repo already has the right pattern twice: src/auth/claim.ts:44 and src/lib/draft.ts:53 key off a hash, never the raw token. Apply it here without going async (scopedRateLimitKey is sync and exported): a new exported boundRateLimitId(id) returns id unchanged when its UTF-8 byte length is <= MAX_RATE_LIMIT_ID_BYTES (128) -- so every real email and IP keeps its existing bucket -- and otherwise returns a short deterministic FNV-1a-32 hex token. Collision resistance is a non-issue because only ids over 128 bytes share that space and all of them are garbage. Fix the key builder only; no route file changes.
