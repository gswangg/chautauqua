# DEC-633: The reviews are readable where the decision is made

DEC-596 put every evaluation behind GET /api/v1/submissions/:id/evaluations and rendered it on submission detail, which closed half of the judge's MAJOR 'reviewer comments are write-only' finding. The other half stands: Results — the ranked screen that owns Accept/Decline — still shows numerics only, so the organiser decides without the one artefact the round produced. Decision: a results row expands in place to the evaluations the existing endpoint returns, rendering exactly what the server sent, including its reviewer field verbatim (DEC-622 decided anonymity server-side; no surface re-decides it, and a withheld name reads '(anonymized)', never blank). Comments render at full length — chrome is terse, sentences are for people.

## Amendment (wave 25)

**An expanded band inherits its parent's column grid**

Rulings A27 + B8 make one rule out of three per-surface improvisations and close the user-filed state-band P2. The results table's review disclosure stops rendering a colSpan free-float list: each evaluation renders as a real `<tr>` in the SAME table, so every value lands under the column it belongs to (reviewer name under Title, that reviewer's blended score under Score, plan/round under Reviews), a recused reviewer's cells read em-dash, and a footer row states that recused scores are excluded from the mean. Band chrome is the B8 token set — #FAF8F2 fill with 1px #E1DDCE top and bottom rules and 16px content insets — not a new per-surface treatment. Doing it as real table rows rather than a hand-copied grid template means the band CANNOT drift from the header when a column changes.
