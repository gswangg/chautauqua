# DEC-160: CNT-14 bulk ZIP export: pure-TS STORE-only ZIP builder in src/lib/zip.ts plus POST /events/:eventId/files/archive returning latest versions, folder-per-session naming, hard cap 50

CNT-14 needs multi-select bulk download of latest file versions with a generation confirmation ('download start' passes). A STORE-method (no compression) ZIP is ~100 lines of pure TypeScript — local file headers, CRC-32 table, central directory, EOCD — so src/lib/zip.ts stays pure-core per DEC-002 (no node:/cloudflare imports, Uint8Array in/out) with `buildZip(entries: {name: string, data: Uint8Array}[]): Uint8Array` that throws on empty input or duplicate entry names (fail loudly). Endpoint: POST /api/v1/events/:eventId/files/archive (organizer, csrfJson) with {fileIds: string[]} (1-50; every id must resolve to a deliverable in that event or the whole request 404s — no silent skips); each id resolves to its chain's LATEST version, bytes read from R2, response application/zip with Content-Disposition attachment. Entry names are '<seq>-<slugified submission title>/<filename>' — the folder-per-session grouping the rubric counts as bonus evidence and a collision-free namespace (residual collisions throw). Cap and store-only keep worst-case memory bounded on the local Workers runtime.
