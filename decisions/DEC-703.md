# DEC-703: A ranked result names the human and the track, and the export carries the table's columns in the table's order

Mandate 34 (r2-Review) is confirmed against app/src/pages/review/ResultsTable.tsx: the ranked results table has ref/title/score/count and per-criterion columns but no SPEAKER and no TRACK, so the one screen where an organizer decides who is on the programme cannot answer "who is this and where does it go" without leaving the page. Both facts already exist server-side; they are added to the ResultsRow the server builds (src/routes/review/shared.ts buildResults) with ONE batched lookup keyed to the page's submission ids — a paged read touches only its page (field guide) and never scans. The CSV export is not a second opinion about what a result is: it carries the same two columns, in the same order, from the same builder, per the standing "export = same where clause everywhere" rule.
