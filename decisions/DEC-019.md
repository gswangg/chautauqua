# DEC-019: Deliberate-notify compose pipeline: recipients, atomic preview, 100-cap, feedback attach

J5's core rule is decide != notify; this fixes the send pipeline so the server task and SPA agree. Templates: GET/POST /api/v1/events/:eventId/templates, PATCH/DELETE /api/v1/templates/:id with { name, subject, bodyText } (merge fields per DEC-006 whitelist). Compose: POST /api/v1/events/:eventId/compose/preview and .../compose/send take { templateId | subject+bodyText, submissionIds: string[], includeFeedback?: boolean }; recipients expand to one per (participant contact x submission). Preview returns every recipient fully rendered [{ contactId, submissionId, email, name, subject, text }]. Sends are atomic-or-nothing: every recipient's template must render (all merge fields resolvable) BEFORE the first send; any failure rejects the whole batch as 'invalid' listing the missing fields — no half-sent batches. More than 100 recipients -> 'invalid' telling the producer to narrow the batch (the cap lives in the compose service per DEC-006). Merge vars per recipient: speaker_name (contact first+last), talk_title (submission.title), event_name, portal_link (/portal when a user exists for the contact email, else a fresh DEC-014 claim link), feedback = that submission's evaluation comments as a bullet list with reviewers anonymized ('Reviewer 1: ...'); zero comments renders the defined value 'No reviewer feedback was recorded.' (a stated value, not a silent blank). Every send is one email_log row via the DEC-006 dev sink; the Comms history tab reads the email-log list endpoint. Status changes still never send email — compose is the only producer-initiated send path.
