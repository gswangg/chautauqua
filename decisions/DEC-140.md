# DEC-140: Public itinerary .ics: selection travels in ?ids= from the schedule page's checkbox values; overlapping grid blocks render side-by-side, never stacked over each other's controls

The server endpoint GET /e/:slug/schedule.ics?ids= already filters through the public-visibility gate and must remain the single mechanism (no accounts for public itinerary). The eval got zero VEVENTs with a saved pick, so the id round-trip is broken somewhere between rendered checkbox values (AgendaDayGrid uses item.submissionId) and the server's agendaById keys — the mandatory regression test therefore derives its ids by extracting the checkbox values from the actual rendered schedule HTML and asserting the .ics built from them contains exactly those VEVENTs, which catches any id-space mismatch by construction. Overlapping sessions in one room column split the column width into side-by-side lanes (like every calendar UI) instead of stacking with z-index, so every block's 'Add to itinerary' control is hittable — a layout fix, not a pointer-events hack. The empty-selection SSR link stays disabled (aria-disabled) until picks exist.
