# DEC-409: The 2px olive focus ring is declared in both stylesheet roots, and no rule may remove an outline

The mandate is explicit — "Focus: 2px olive outline, 2px offset" — and the accessibility section rests the AA claim partly on it. app/src/styles.css:82-85 has it; `grep -rn focus-visible src/` returns nothing, so every server-rendered surface (the five public event pages, /submit/:slug, /portal and its five sub-routes, /login, /account/password, /docs/api, /dev/mailbox) falls back to whatever the browser draws — which on the oat/olive palette is neither the designed treatment nor reliably visible. The public CFP form is a keyboard-navigated form filled by strangers with no account; it is the last surface that should be guessing. The rule goes in THEME_CSS beside the a:hover rule (outside the 700px block, so it applies at every width), and a conformance guard in the same shape as test/phone-wrap-conformance.test.ts asserts both roots declare it and that no scanned stylesheet contains `outline: none` or `outline: 0` — the only way this regresses is someone silencing the ring, so that is the thing the test watches. app/src/styles.css and src/views/theme.ts remain ONE lane (DEC-368/372/404); styles.css needs no edit, but the lane owns it so nothing else touches it this wave.
