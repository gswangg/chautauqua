# DEC-625: A locked built-in field is unconditionally visible; a visibility rule can never be attached to one

src/routes/api/forms.ts guards only required/kind/section on field.locked (:211) and writes rule unconditionally (:252). A false-evaluating rule on the locked email/title field makes it hidden; src/forms/validate.ts:50-56 strips hidden answers WITHOUT validating them, so the public CFP persists an empty title and an empty email — bypassing isValidEmail (DEC-454) and collapsing every such submitter onto one shared empty-email contact via findContactByEmail(db, orgId, ''). The API rejection alone would leave already-corrupted rows exploitable, so the invariant lives in the pure core too: resolveHiddenFieldIds never hides a field lockedFieldName() recognises. Conditional visibility is a FIXED POINT with locked fields pinned visible.
