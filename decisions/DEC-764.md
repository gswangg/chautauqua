# DEC-764: Add-to-event creates a real, named session -- the model has no contact-to-event roster to create instead

The eval finding asks that add-to-event "create NO session by default". Verified against src/db/schema.ts: `participant` (submission_id, contact_id) is the ONLY contact-to-event link; there is no contact-event table, and `listAcceptedContactIds` defines "on the roster" as "active participant on an accepted submission". SPEC §5's ladder (contact -> speaker -> publicly visible, never collapsed) is built on exactly that row. So a rosterless add-to-event is not expressible without inventing a second roster concept the whole product would then have to learn. Decision: keep creating the session, but stop FABRICATING it -- AddToEventModal.tsx:26 drops the `Invited: {name}` prefill, the field is labelled "Session title" and is REQUIRED (primary disabled until filled, placeholder only), and the dialog states the consequence before the click: it creates an accepted session on that event and sends no email. The confirmation names the role actually chosen instead of the hardcoded "was added as an accepted speaker." The defect was never "a session exists"; it was that a session appeared that nobody typed.
