# DEC-517: ONE `isEpochMs` predicate home, and a CFP form / evaluation plan may never be saved with its close date before its open date

DEC-509 landed a strict `parseEpochMs` in `src/routes/review/shared.ts:184-193` (`Number.isInteger` or explicit null). One module away, `src/routes/api/forms.ts:102-115` still accepts any `typeof body.openDate === 'number'` for the CFP form's open/close dates — two implementations of one invariant, which the w24 lesson says means one of them is wrong. Worse, neither surface checks ORDER. `src/lib/submit-core.ts:24-32` opens a form only when `now >= openDate && now <= closeDate`, so a producer who transposes the two fields (a one-keystroke mistake on the J1 "launch a CFP in an afternoon" path) saves a 200 and gets a public form that can never accept a submission, with no error anywhere — the same silent-death shape as DEC-509's `maxEvaluations: 0`. Decision: `src/routes/api/validators.ts` (already the ONE home for boundary predicates since DEC-510's `isIsoDate`) gains `isEpochMs(value: unknown): value is number` and `isEpochOrderValid(open, close)` (true when either side is null/undefined). `review/shared.ts`'s parseEpochMs is rebuilt on the predicate rather than duplicating it; forms.ts adopts it. Both PATCH surfaces evaluate ordering against the MERGED post-patch state (the loaded form/plan record supplies the side that wasn't sent), not against the request body alone, so patching one date into a bad order is a 400 rather than a silent trap. Rejected: clamping or swapping the dates — that hides producer error and violates fail-loudly.

## Amendment (wave 42) — isEpochMs is a DATE predicate, not an integer predicate: bounded to the range whose day label satisfies DEC-510's isIsoDate

src/routes/api/validators.ts:60 is `Number.isInteger(value)` with no range bound, and DEC-527 binds EVERY ms-epoch boundary in the route layer to it. So `closeDate: 1e18` is accepted and persisted by PATCH /api/v1/forms/:formId (forms.ts:112); src/lib/timezone.ts dayLabelToYmd only rejects non-finite (line 102), so it yields "NaN-NaN-NaN", zonedMinutesToUtc throws inside isFormClosed, and GET/POST /submit/:eventSlug, save-draft and the portal edit-lock 500 permanently for that event. The same predicate gates evaluation-plan dates (review/shared.ts:205) and task due dates (tasks.ts:236/320). RULING: isEpochMs accepts an integer ONLY when it lies in the closed range whose UTC day label is a 4-digit-year YYYY-MM-DD — MIN_EPOCH_MS = -62135596800000 (0001-01-01) through MAX_EPOCH_MS = 253402300799999 (9999-12-31T23:59:59.999Z), exported as named constants from validators.ts. The invariant is the AGREEMENT of the two boundary predicates: any value isEpochMs accepts must produce a day label isIsoDate accepts. No stored-value fallback is added anywhere (fail loudly stands); the fix is at the boundary, and dayLabelToYmd's guard is tightened to throw on an out-of-range instant too, so the invariant is asserted at both ends. One predicate change closes every call site DEC-527 enumerates.
