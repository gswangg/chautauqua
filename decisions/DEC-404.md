# DEC-404: At phone width no user-supplied string may widen the page: `overflow-wrap: anywhere` belongs to the shell's one 700px block, in the SPA and the SSR theme both

An unbroken talk title, contact email, portal-claim URL or .ics line is the most likely cause of the residual admin overflow (/admin/comms measured 131px, /admin/submissions 40px in the w5-i log) because `white-space: pre-wrap` on the compose preview body and default `overflow-wrap: normal` everywhere else let one token set the min-content width of a grid track. Three page lanes already found this independently and patched their own files (detail.css x4, content.css) — that is whack-a-mole, and comms/submissions/review/speakers/settings/forms never got the memo. `overflow-wrap` is an inherited property, so one declaration on the shell's content container inside the EXISTING 700px block covers every descendant including page classes, and confining it to phone leaves desktop typography untouched. app/src/styles.css and src/views/theme.ts are ONE lane again (DEC-368/372; DEC-394's split was for wave 6 only), so both halves land together.
