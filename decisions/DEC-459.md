# DEC-459: A ledger row phrased with a universal quantifier is graded from an enumeration of the whole population, never from a sample

Every defect this wave fixes sat under a row that a prior ledger graded VERIFIED from one citation: "Rate limits on auth + public submission" cited one call, "Public submission validates server-side against form schema" cited one function, "Authz + object-level ownership" cited one middleware plus one IDOR test out of ~157 route registrations across 35 files under src/routes. DEC-453 already forbids grading a MEASURED row from code presence; this generalizes it to QUANTIFIED rows. Any ledger row whose claim contains "all", "every", or "never" must be backed by an artifact that enumerates the full population -- every route, every list endpoint, every ingress -- with a per-member verdict and citation, and names the members it could not confirm. Producing that enumeration is a lane of its own, and its log is the ledger's evidence rather than the ledger re-deriving it. Two such enumerations run this wave (route authorization, unauthenticated-surface input handling); an enumeration lane MAY land a missing guard in a route file it owns, but must record rather than fix anything in a file another lane owns this wave.

## Amendment (wave 21): the route-authorization enumeration is executable — a markdown table is pinned to the sha it was written at

DEC-459 requires any 'all/every/never' claim to be graded from an enumeration of the whole population, and the route-authz enumeration it mandated exists: docs/verification-log/task-w18-d-route-authz-inventory-stage1.md, 157 registrations across 35 files, 135 GUARDED, 22 PUBLIC-BY-DESIGN, 0 GAP. But it is prose, pinned to sha d034a9e0, and its runtime companion (test/route-authz-inventory.test.ts) probes three route files and says so in its own header: "a representative set". The enumeration therefore stops being true the moment a route is added — the same defect the anonymous-route probe had before wave 18 taught it to compose from src/index.ts's real mount list. Ruling: the population is re-derived AT TEST TIME. One scan enumerates every route registration under src/routes/**, classifies each as GUARDED (a role middleware in the chain, or an ownership marker in the handler) or PUBLIC-BY-DESIGN via a ledger seeded from the doc's own PBD rows with their reasons; every mutating registration must additionally name a CSRF guard; a ledger entry matching no live registration fails as stale; and a registration-count tripwire keeps the regex from silently matching nothing. The doc becomes the ledger's evidence, not the guard.

## Amendment (wave 32): a guard's NAME in a scan is not a refusal at runtime — a speaker session and a reviewer session are driven against every /api/v1 registration

DEC-459's enumeration classifies a route GUARDED when the registration text names a role guard or an ownership marker. That proves a guard was written, not that a non-organizer actor is refused: SPEC §6 requires role + event grant on every admin/API route, and the review lens has only ever sampled this by hand (four probes on four ids). requireOrganizer/requireReviewerOrOrganizer refuse synchronously off c.var.auth, so a throwing-db stub makes the invariant crisp: a speaker or reviewer session must get 401/403/404 with zero db access. Ruling: a runtime probe drives every /api/v1 registration (all methods) with a speaker session and with a reviewer session; each must refuse without touching the db, or appear in a two-directional ROLE_REACHABLE ledger naming the actor, why that actor legitimately reaches it, and the existing test that covers its object-level ownership check. An entry with no named covering test is a finding, never an absorption.
