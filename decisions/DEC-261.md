# DEC-261: Wave 3 is campaign-2's last product-touching wave; wave 4 re-runs the DEC-256 eight-section battery and is the only place stage 1 is declared

This campaign has oscillated for many rounds: a battery freezes a sha, finds one or two real defects, the next wave fixes them, and the fix voids the freeze so the battery must run again. That loop only terminates if a wave is designated the last one allowed to move product code. Wave 3 is that wave: five browser-persona lanes over the J-areas with the weakest evidence, plus the one genuine requirement gap (DEC-258), plus the wave-2 fix list.

After wave 3 merges, wave 4 runs the DEC-256 battery unchanged (eight sections, freeze-by-rule, identical FROZEN SHA literal, OPEN ITEMS: 0) and NOTHING else — the only product commits permitted from wave 4 onward are fixes for defects that make a battery section FAIL. Discretionary polish, new nice-to-haves from SPEC section 10 (whose own precondition is "only after J1-J12 are green", which the battery has never yet certified), and speculative refactors are closed. Stage 1 is declared in wave 4 or later, never in wave 3.
