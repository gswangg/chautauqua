# DEC-774: The sessions surface filters on the facets it displays

The EMB probe scored 72% on missing capability, first item: "Sessions facets beyond track (format/location)". src/routes/public/sessions.tsx renders a track filter bar only, while every card already prints the session's format and room -- src/server/repo/public/sessions.ts:442 hydrates `format` and :441 `roomName`. A surface that shows an attribute and refuses to filter on it makes the visitor scroll. Decision: `?format=` and `?roomId=` join `?trackId=`/`?q=`/`?day=` as server-side predicates on getVisibleSubmissionIdsOrdered AND countVisibleSubmissions (never a post-filter over the page -- the count and the list are one query pair), parsed in src/routes/public/query.ts beside parseTrackId, rendered as chips in the existing .chq-pub-filter-bar, and composing with each other and with show-more. Sessions with no slot are excluded when a room filter is active, because "in Room 2A" is a claim about a placement.

A read that is conditional today (grandTotal only when a filter is active; dayCounts/cfpWindow only when !embed, DEC-683's chromeless-closed rule) stays conditional inside the wave — a skipped read is never fetched-then-discarded, and the total statement count must be identical to today's for both the embed and non-embed shapes.
