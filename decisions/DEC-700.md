# DEC-700: A badge is a live claim: exception counts refetch on navigation and after every mutating request

app/src/lib/useNavExceptions.ts:31-54 fetches /events/:id/overview once per (eventId, role) and never again, so "1 CLASH" and "N LATE" survive the very actions that resolve them — the user found a badge still showing after the clash was fixed. The design rule the badge exists to serve is "a badge only when something is wrong"; a stale badge is a false alarm, which is worse than no badge. Rather than teach every mutating call site to invalidate (a hand-maintained list that will desync, per the field guide), the invalidation is derived: app/src/lib/api.ts is the ONE place a mutating request is issued, so a successful apiPost/apiPatch/apiPut/apiDelete bumps a module-level version that the hook subscribes to, plus a refetch on route change. One signal, no per-caller bookkeeping.

## Amendment (wave 53): every mutating wire helper bumps the mutation signal — enumerated from api.ts, not remembered

DEC-700's own text says "app/src/lib/api.ts is the ONE place a mutating request is issued" and then names four helpers by hand: apiPost/apiPatch/apiPut/apiDelete. Two more mutating helpers in that same file bypass the shared `request()` on purpose and therefore bypass the bump: `apiUpload` (`app/src/lib/api.ts:206-230`, the multipart POST behind every deliverable/headshot/resource upload) and `apiPostBlob` (`:174-200`). `bumpMutationVersion` has exactly one call site (`:124`). So a deliverable upload that reopens content review — the route itself reports `contentReviewReopened` (`src/routes/files.ts:246`) — leaves the nav's exception badges asserting a stale claim, which is the precise failure DEC-700 was written to kill. RULING: apiUpload bumps on success, and the four-name list is replaced by an enumeration over api.ts's own exported functions: every exported helper that issues a non-GET fetch must reach `bumpMutationVersion()` (directly or via `request()`) or appear in an EXEMPT list carrying a written reason. `apiPostBlob` is the one exemption — a POST whose body is a filter, not a write (the bulk-download door); naming it as an exemption is what makes it reviewable instead of accidental.
