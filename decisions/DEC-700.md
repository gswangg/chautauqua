# DEC-700: A badge is a live claim: exception counts refetch on navigation and after every mutating request

app/src/lib/useNavExceptions.ts:31-54 fetches /events/:id/overview once per (eventId, role) and never again, so "1 CLASH" and "N LATE" survive the very actions that resolve them — the user found a badge still showing after the clash was fixed. The design rule the badge exists to serve is "a badge only when something is wrong"; a stale badge is a false alarm, which is worse than no badge. Rather than teach every mutating call site to invalidate (a hand-maintained list that will desync, per the field guide), the invalidation is derived: app/src/lib/api.ts is the ONE place a mutating request is issued, so a successful apiPost/apiPatch/apiPut/apiDelete bumps a module-level version that the hook subscribes to, plus a refetch on route change. One signal, no per-caller bookkeeping.
