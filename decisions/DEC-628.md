# DEC-628: Security middleware coverage is enumerated from the source, not spot-checked

SPEC §6 requires CSRF on every mutating route and rate limits on auth + public submission. Today both hold, but they are held by 90-odd hand-written registrations and three spot tests; a route added without csrfJson is a silent CSRF hole that nothing would catch. Hand-listed manifests desync — enumerate in a test: scan every registration in src/routes/** and fail loudly, naming file:line, when a mutating route carries no CSRF middleware or an unauthenticated write path carries no scoped limit. Deliberate exceptions live in a named allowlist with a stated reason, never as silence.

## Amendment (wave 46): a security exemption is keyed by route IDENTITY, never by a line number

CSRF_EXEMPT in test/security-invariants.test.ts pins its one entry to `public/submit.tsx` line 286. A line number is a cursor that moves: any edit above the handler shifts it, the scan then reports the exempt route as an uncovered CSRF hole, and the repair is a mid-merge-train patch to a security allowlist ('re-point DEC-628 CSRF exemption 266->286') made under time pressure and outside review. The mechanism intended to make widening the exemption loud instead makes NOT widening it noisy, which trains everyone to re-point the number reflexively — the one edit that should always be scrutinised becomes routine. Decision: RouteRegistration gains a `path` field (the first string literal in the registration's own header slice) and CSRF_EXEMPT entries are keyed { file, method, path, reason }. Identity is stable under unrelated edits and changes only when the route itself changes, which is exactly when a human should look. The existing 'every exempt entry names a real registration' and 'the exempt CFP post still performs the in-body double-submit check' assertions stay and are re-keyed; the exemption set does not grow in this wave.

## Amendment (wave 17): the CSRF guard's form side — a POST form carries the token under the imported constant, never a re-typed cookie name

test/security-invariants.test.ts enumerates the SERVER half (every mutating registration carries csrfJson/csrfForm/csrfFormOrHeader, with a reasoned exempt list) but nothing enumerates the RENDERED half. src/routes/portal/shared.tsx:152 emits `name="chq_csrf"` as a string literal instead of the imported CSRF_COOKIE_NAME — a second copy of a name whose single source is src/auth/cookies.ts:9; the day that constant changes, portal sign-out 403s silently and only a human clicking it finds out. The form side gets the same enumerate-from-source treatment DEC-628 already gives the route side: every `<form method="post">` in server-rendered JSX must contain a hidden input whose name is the constant expression, with reasoned allowlist entries for anything else.
