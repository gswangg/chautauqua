# DEC-929: Deleting an evaluation plan states its blast radius from ONE read, and takes the recusals with it

app/src/pages/review/PlanEditor.tsx renders <ConfirmDialog title="Delete evaluation plan" confirmLabel="Delete plan" destructive .../> with NO body at all -- while the Reset-password dialog eleven lines below it names its own consequence, and DEC-886 made 'an irreversible action names what goes' the house grammar. What that silent dialog actually triggers: deletePlan (src/server/repo/review/plans.ts) deletes plan_reviewer, then EVERY evaluation for the plan -- including submitted reviews, the very rows DEC-886 refuses to let a session delete destroy -- then the plan. It also never deletes review_recusal, whose plan_id column makes it a third table the plan owns, so the cascade is simultaneously too silent and incomplete. Rule: GET /api/v1/plans/:id/delete-preview (organizer, plan-owned, writes nothing) returns EXACTLY {planId, name, counts:{reviewers, evaluationsSubmitted, evaluationsDraft, recusals}}, each from ONE grouped query over the plan and never one per reviewer; the dialog fetches it when it opens and its body states those numbers in prose, submitted reviews first, plus the sentence that the plan's results table and CSV export go with it. deletePlan additionally deletes review_recusal for the plan. Deletion stays allowed -- a plan is the organizer's own round and abandoning it is legitimate -- but it is never silent. The new route is added to src/routes/docs.tsx's ROUTE_GROUPS, because test/docs-route-coverage.test.ts derives the mounted /api/v1 set from src/index.ts's own source and fails on any undocumented route.
