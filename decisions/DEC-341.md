# DEC-341: The J8 content worklist is server-driven: contentStatus filter and worklist ordering move into SQL, deliverable counts are hydrated page-bounded, and the per-row client fan-out is deleted

app/src/pages/content/ContentApp.tsx:34-52 loads GET /events/:id/submissions and then issues one apiList('/submissions/:id/files') PER ROW inside a Promise.all — its own comment concedes 'no bulk-counts endpoint exists on the submissions list'. That is 51 authenticated Worker+D1 round trips to paint one screen, against SPEC §7's 'One round trip per view: each screen's data loads in a single joined query/endpoint — no client-side request waterfalls'. Worse, app/src/pages/content/worklist.ts applies BOTH the tab filter (filterByContentStatus) and the worklist priority ordering (sortForWorklist) in the browser over a single default page of 50 rows sorted newest-first by the server, so at the SPEC's 2,000-submission scale the 'Changes requested' tab silently omits most matching rows — a correctness defect, not merely a slow one, and exactly SPEC §2.2's 'demos at 10 rows, dies at 2,000'. Binding contract: (a) GET /api/v1/events/:eventId/submissions gains a contentStatus filter (repeatable/CSV, same tolerant parsing as status: unknown tokens dropped) pushed into the WHERE of DEC-335's single paginated statement; (b) a new sort order 'worklist' = CASE content_status WHEN 'changes_requested' THEN 0 WHEN 'pending' THEN 1 ELSE 2 END, then title asc, then seq asc as the DEC-335 tiebreaker; (c) SubmissionListItem gains deliverableCounts: { presentation: number; poster: number; handout: number }, always present, hydrated by ONE grouped query over the page's submission ids (chunkIds per DEC-078) counting file rows with previous_file_id IS NULL and kind in the three deliverable kinds — chain roots only, preserving DEC-247. Cost stays bounded by page size, so this is consistent with DEC-335 rather than a regression of it. The SPA drops the Promise.all fan-out, passes tab -> contentStatus and sort=worklist to the server, and gains a pager driven by the envelope's total.
