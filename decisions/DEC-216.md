# DEC-216: DEC-199 stage-1 disposition: no schema migration for case-insensitive email uniqueness; app-level normalization plus the existing raw unique index are sufficient

Review-lens flagged that the unique index user_email_idx is on the raw email column while the ci dup-check is app-level, leaving a theoretical race. Verified analysis: after DEC-199, every write path lowercases at the API boundary (users.ts:57) and createUser asserts its input is lowercase (fail-loudly), so two concurrent creates of the same address normalize to IDENTICAL strings and the raw unique index itself catches the race; case-variant duplicate rows can only arise from rows that predate normalization, which cannot exist in stage-1's migrate+seed lifecycle (seeds are lowercase, local DBs are rebuilt from scratch). A lower(email) expression-index migration would add churn to migrations/ (DEC-015 append-only, spec-audit greps DROP-free) for a hole that is unreachable in stage 1. ACCEPTED as-is for stage 1; revisit only if stage 2 introduces long-lived production databases.
