# DEC-051: Calendar invites in compose: attachIcs flag + per-submission ics_sequence (migration 0008 reserved)

SPEC §3/§9/§10 require working .ics in speaker comms with the swyx flow: initial invite (no room) then an update with the SAME UID and bumped SEQUENCE when the room lands. One mechanism, not two: compose preview/send gain attachIcs?: boolean. A new submission.ics_sequence INTEGER NOT NULL DEFAULT 0 column (migrations/0008_w7_ics_sequence.sql — filename reserved; append idx-8 entry to migrations/meta/_journal.json per the 0007 pattern) tracks the RFC 5545 SEQUENCE. Send uses the stored value for every recipient of that submission (UID from src/mail/ics.ts uidFor — stable per SPEC §5), attaches via the existing RenderedEmail.ics field (filename chq-<submissionId>.ics), then bumps the stored value exactly once per submission per send call; preview NEVER bumps. Slot local→UTC conversion reuses the exact helpers GET /e/:slug/schedule.ics uses — never duplicated. Preflight is atomic per DEC-019: attachIcs with any selected submission unscheduled rejects with ApiError('invalid', …, {<submissionId>:'not scheduled'}) before any send; LOCATION is emitted only when a room is assigned (that IS the initial-invite-without-a-room flow). Public schedule.ics stays as-is (regenerated snapshot calendars, sequence 0) — do not 'fix' it.

## Amendment (findings wave 8): compose step 1 states each recipient's slot, because the slot is what decides whether a calendar invite can be attached

DEC-051 already rules that the ids the server refuses for attachIcs ('not scheduled') are surfaced literally rather than pre-filtered client-side. It surfaces them at step 3, after the organizer has chosen an audience and written a message — the most expensive moment to learn that three of the twenty-three cannot take the invite. The vendored frame puts the fact at step 1: docs/design/Chautauqua Comms.dc.html:157 draws the recipient row as a five-track grid whose last content column is the slot, with the frame's own data carrying 'Tue 10:00' for scheduled rows and 'No slot yet' in the ink micro-label register (SLOT_NONE at :819) for unscheduled ones, and the step's primary sitting in a footer row rather than loose under the table. Our step-1 table (ComposeWizard.tsx:629-667) has four columns — select, Title, Speakers, Status — and a bare button at :700. This is error-rule 13, 'pre-flight the irreversible', applied one step earlier than DEC-051 currently applies it. RULING: the submissions LIST payload gains the slot the submission DETAIL payload already carries ({day, startMin, endMin, roomName} | null, DEC-780's shape, reused verbatim so there is one slot shape in the SPA), sourced from ONE left join on schedule_slot + room in the list query — never a per-row lookup, since this is the 2,000-row admin query the perf budget is measured on. Compose step 1 renders it as the frame's last column, event-local, through the clock/day formatters that already own those grammars; unscheduled prints 'No slot yet' in the ink micro-label register, never a dash pile. The step's primary moves into a footer row. The step-3 refusal stays exactly as it is: step 1 informs, it does not gate.
