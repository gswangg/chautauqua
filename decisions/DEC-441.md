## Amendment (wave 52)

The remind REVIEW dialog reports the cap remainder, not just the dedupe skips — preview and send report the same three numbers.

POST /events/:id/onboarding/remind/preview returns {drafts, skipped, remaining} (src/routes/tasks.ts:590 -> previewRemindNow, src/server/repo/tasks/reminders.ts:543-547), where `remaining` is Math.max(eligibleTotal - MAX_REMINDER_BATCH, 0) — the eligible contacts this batch will NOT reach. OnboardingGrid.tsx:486-491 reads `drafts` and `skipped` and DISCARDS `remaining`, so an organiser reviewing 100 drafts is never told 40 more people are outstanding; the SEND path already says it (describeSendResult prints '4 still outstanding — run it again to continue', app/src/lib/sendResult.ts). DEC-441 made the preview the thing you approve; a preview that under-reports the batch is the codebase's own silent-truncation defect (MAX_ACCEPTANCE_TASK_ASSIGNMENTS, EXPORT_MAX_ROWS and auto-schedule's write_cap_reached all name their cap). RULING: the review dialog states all three facts — how many will be emailed, how many were skipped and why, and how many stay outstanding because of the 100-contact batch cap — using the SAME sentence family the send toast uses, so approving and reporting never disagree.
