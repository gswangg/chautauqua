# DEC-480: ONE perPage clamp, and 'every list endpoint' is graded by an executable enumeration test, never by prose

DEC-465 collapsed five per-route perPage helpers into listPerPage and that landed -- but three repo/route-layer copies of the same DEFAULT_PER_PAGE=50 / MAX_PER_PAGE=200 rule survived untouched because DEC-465's population was a hand list of route files: src/routes/tasks.ts:105-117, src/server/repo/contacts/query.ts:17-35, src/server/repo/submissions/query.ts:21-49. This is DEC-466's lesson happening a second time to its own successor, which is the proof that a hand-enumerated population is not a population. DEC-473 asked for an enumeration ARTIFACT; a document decays the moment the next route lands, and w17-f's audit, DEC-460's list and DEC-466's list each went stale within two waves. So the artifact becomes a test: a source-scanning conformance test in the established house style (test/query-scoping-invariant.test.ts, test/d1-bind-safety.test.ts) that re-derives the population on every run, asserts every `return c.json({ items` under src/routes carries total/page/perPage in the same literal, asserts src/lib/pagination.ts is the only place the clamp rule is defined, and fails with the offending file:line list. An enumeration that runs in CI cannot be inherited, narrated, or believed -- only re-run. This discharges DEC-473's artifact duty in a form that survives the next wave.
