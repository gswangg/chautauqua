# DEC-214: Speaker-side kind gates on PATCH /api/v1/task-assignments/:id: an owning speaker may only complete 'form' with a saved response and 'file_request' with an uploaded file; organizer overrides stay unrestricted

The generic PATCH (src/routes/tasks.ts:252-278) authorizes the owning speaker but never checks task kind, so must-have form tasks (hotel stay, flight reimbursement) and file_request tasks can be marked complete via JSON API with responseJson/fileId null — bypassing the portal gates (portal/tasks.tsx:277,342) and silently corrupting the J6 who-owes-what grid. Rule: when the actor is the owning speaker (not an organizer) and status === 'complete', a kind 'form' assignment requires its stored response_json to be non-null and a kind 'file_request' assignment requires file_id non-null; violations throw ApiError('invalid', ...) directing the speaker to the portal form/upload flow. 'general' tasks complete freely; setting 'pending' is always allowed; organizers marking any assignment complete is a deliberate manual-override capability of the J6 grid and remains ungated. The walkthrough script never PATCHes task-assignments, so no gate regression.
