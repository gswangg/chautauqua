# DEC-883: A toggle that needs a companion choice reveals the choice and WAITS; the merged reviewer feedback is a quoted block in the PREVIEW, never in the sent body

app/src/pages/comms/ComposeWizard.tsx:241-244 calls runPreview({includeFeedback:true}) the instant the checkbox flips, before any plan can be chosen; composeBody (line 140) only sets feedbackPlanId when one is selected, and DEC-682's server guard rejects includeFeedback without a plan — so the toggle's FIRST effect is always a 400 and the organizer never reaches the feature at all. Rule: flipping the toggle ON with no plan selected reveals the plan select, renders the note "Choose a plan to merge its feedback.", and issues ZERO requests; the preview fires on the plan choice (handleFeedbackPlanChange, already correct) and on flipping OFF (which also clears feedbackPlanId so a stale plan can never ride along). Separately, docs/design "Chautauqua Comms.dc.html":130-133 renders the merged feedback inside the preview as a left-ruled block under an uppercase "Reviewer feedback, merged" eyebrow. That block is PREVIEW CHROME ONLY: the email body stays exactly the plain text renderTemplate produced (the mailer sends text), and the preview identifies the block by matching the recipient's own already-returned vars.feedback value inside the rendered body — the feedback text is never formatted, re-derived, or fetched a second time (one pure source, per the standing shared-predicate rule).
