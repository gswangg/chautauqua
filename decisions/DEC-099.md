# DEC-099: Public cache hits must be re-served with the client-facing Cache-Control (public, max-age=60, stale-while-revalidate=300); max-age=86400 is internal to the stored copy only (amends DEC-083)

servePublicGet (src/server/pubcache.ts:68-69) returns the stored hit verbatim, whose Cache-Control was overwritten to "public, max-age=86400" before cache.put — so every client that gets a hit caches public/embed HTML for 24h and never observes a purge, contradicting DEC-022/DEC-083's own 60s client contract and SPEC §7/J10 "always current". Ruling: export CLIENT_CACHE_CONTROL = "public, max-age=60, stale-while-revalidate=300" (byte-identical to setCacheHeaders in the former src/routes/public.tsx:61 (now split across src/routes/public/)); on a hit, construct a new Response from the cached one (cached headers are immutable) with Cache-Control replaced by CLIENT_CACHE_CONTROL. The stored-copy 86400 override and the versioned-key purge design are unchanged — long internal TTL is what makes version-swap purge work.

## Amendment (wave 34): a response whose SERVING PATH branches on the session cookie must say so — Vary: Cookie

publicCacheMiddleware skips BOTH cache.match and cache.put when a chq_session cookie is present (src/server/pubcache.ts:452-456, DEC-083's wave-26 amendment), so the public/embed HTML's serving path is cookie-dependent by construction — yet setCacheHeaders (src/routes/public/shell.tsx:93-96) emits `public, max-age=60, stale-while-revalidate=300` with NO Vary. The organiser's own browser, and any shared proxy, may therefore hand the signed-in producer the anonymous copy for 60s, defeating exactly the guarantee that amendment exists to give. src/routes/root.tsx:423 already sets `Vary: Cookie` on `/` for precisely this reason, proving the idiom was known and skipped everywhere else. RULE: `Vary: Cookie` is set inside setCacheHeaders — ONE door, never re-declared per route — so every public/embed GET carries it; root.tsx's now-duplicate line is DELETED and its comment reworded (no compatibility shims). The EDGE copy must not fragment: servePublicGet DELETES Vary from the copy it stores in caches.default and RE-ASSERTS `Vary: Cookie` on the copy it restores from a hit, exactly as it already overrides Cache-Control at pubcache.ts:191/198. That is sound because the stored population is anonymous-only by construction (the cookie branch returns before any put), so one shared entry stays correct while the client-facing contract becomes truthful.

## Amendment (wave 35): the Vary: Cookie universal gets a DERIVED population — one door proven by two unit tests is not proof about every public GET

DEC-099's wave-34 amendment landed correctly (`src/routes/public/shell.tsx:103-107` sets `Vary: Cookie`; `src/server/pubcache.ts:196,210` strip it from the stored copy and restore it on every hit) and is proven by `test/pubcache.test.ts:132-167`. But those tests exercise `servePublicGet` and the `setCacheHeaders` FUNCTION — not the claim the amendment actually makes, which is about every public/embed GET. `setCacheHeaders(c)` is a hand-placed call at roughly fifteen sites across `src/routes/public/index.tsx` (:168,199,206,213,227,248,271,292,328,342,360,404), `src/routes/public/programme.tsx:152`, `src/routes/public/saved-embed.tsx:56` and `src/routes/root.tsx:426`; a newly registered public GET that sets its own `Cache-Control` — the `.ics` and `.json`/`.xml` feed shapes already differ from the HTML ones — would ship cacheable-without-Vary and nothing would fail. This is the same shape DEC-550 fixed for authz: a hand-placed guard is not an enumeration. RULING: the claim is proven by a runtime enumeration over the composed route table, asserting one closed rule in both directions — a response whose `Cache-Control` is anything other than `no-store` MUST carry `Vary: Cookie`, and a response carrying `Vary: Cookie` MUST be cacheable. The path list is derived from the composed app's own route table (never hand-typed) and its count asserted against a floor so it cannot silently narrow. A violating route is fixed in the route; there is no allowlist.

## Amendment (wave 37): the cacheability population has an AUTHENTICATED half, derived the same non-hand-typed way, and it ships a negative control

DEC-099's wave-35 amendment ruled that ONE DOOR IS NOT A POPULATION and proved it: building the derived public population (/e/*, /embed/*, /) found a real violation nobody had suspected — forced no-store responses still carrying the Vary: Cookie that setCacheHeaders had set earlier in the same handler. The complementary universal, that an authenticated surface is never shared-cacheable, is today asserted only by six hand-picked doors in test/cache-control-default.test.ts:68-161 — the same shape of claim the amendment already rejected. Wave 37 derives that population from src/index.ts's own mounts via the enumerators that already exist (test/helpers/registered-routes.ts's enumerateRegisteredRoutes, test/helpers/index-mounts.ts's parseIndexMounts), asserts one closed predicate (Cache-Control is no-store AND no Vary: Cookie AND no public/s-maxage/stale-while-revalidate directive), and ships a NEGATIVE CONTROL: a synthetic route that sets `public, max-age=60` must be reported as a violation by the same predicate. A universal with no failing case is not a measurement. Because wave 37 is frozen, any real violation is recorded in a RATCHET keyed by file:line and owner — an entry that fails when the route is fixed as well as when it regresses — never an allowlist that hides it.

## Amendment (wave 40): the verification-log header contract gets a corpus test with a shrink-only ratchet and a plain-hyphen negative control

A universal with no failing case is not a measurement. scripts/exit-predicate.ts's HEADER_RE (:36) requires an EM DASH U+2014 and a trailing `@ <sha>`; a section header written with an ASCII hyphen, or without a sha, is not parsed as a section at all — it is silently absorbed as body text of the PREVIOUS section, and the slot it was meant to fill reads MISSING with no error anywhere. test/exit-predicate.test.ts exercises the parser against fixture strings only, so nothing today measures the real corpus. RULING: a test-only lane derives the population — every file under docs/verification-log/index/ — and asserts that each file whose first line matches the header contract yields exactly one section in the assembled docs/verification-log.md, with the set of NON-conformant index files recorded as a frozen RATCHET that may only shrink, never an allowlist that may grow. Negative controls ship with it: a header with a plain hyphen parses to zero sections, `classifyScope('render-sweep')` is null, and each of the five canonical literals classifies to its own slot. This is what turns a wave-40 lane's typo into a red test at merge time instead of a MISSING slot in the exit verdict.

## Amendment (wave 41): the RESULT token and the scope literal are a machine-checked contract over the whole verification-log corpus, with a shrink-only ratchet and fixture negative controls

`scripts/exit-predicate.ts:217` grades `result.startsWith("PASS")` and `:145` classifies scope by keyword, returning null rather than guessing. Two silent failure modes follow and both have already cost a slot: wave-36's spec-audit section ends `RESULT: QUALIFYING`, which grades FAIL mechanically (that slot could never read satisfied regardless of the product), and a scope like `stage-1 exit ledger` classifies to null so its slot reads MISSING. A third mode is structural: `HEADER_RE` at `:36` requires U+2014, so one ASCII hyphen makes an entire section parse as the PREVIOUS section's body and disappear from the verdict. Per this DEC's own rule that a universal needs a negative control and that violations live in a RATCHET rather than an allowlist: the corpus under `docs/verification-log/index/` gets a test that derives the population at test time, asserts the header shape, the classifiability of gate scopes and the PASS/FAIL first token, pins today's legacy violators (the wave-36 `RESULT: QUALIFYING`, the w21-f `RESULT: NOT ...`) in a shrink-only array, and proves each assertion can fail using fixture strings rather than the real corpus.

## Amendment (wave 42): scope-literal discipline — exactly one lane may use a scope string that classifies to a required slot

`classifyScope` (scripts/exit-predicate.ts:145-153) is a keyword classifier over the header's free-text scope: any scope containing `triage` claims the triage-closure slot, and `gradePredicate` takes the LAST such section in document order. An advisory lane that types `triage` (or `perf`, `walkthrough`, `spec audit`, or both `build` and `test`) into its scope silently hijacks a required slot and can flip the whole predicate. RULING: only `task-w42-a` uses a required-slot literal, and it uses EXACTLY `triage-closure`. Every other wave-42 scope must classify to null: `stage-1 exit ledger`, `contacts-integrity adjudication`, `content-lifecycle adjudication`, `gate-gap adjudication`, `tier-1 fidelity recheck` — each verified against the classifier's five regexes before use. The header itself must match `## 2026-08-15 <branch> — <scope> @ <sha>` with an EM DASH U+2014 (an ASCII hyphen makes the whole section vanish into the previous section's body, per `test/exit-predicate-corpus.test.ts`'s negative control), and the RESULT line's first token must be the literal `PASS` or `FAIL` (slotOutcome grades `startsWith("PASS")`; `RESULT: QUALIFYING` grades FAIL — the wave-36 trap).

## Amendment (wave 44): the exit predicate's slot tie-break is newest MEASURED TREE first, append order only among shas with no ancestry relation

`gradePredicate` (`scripts/exit-predicate.ts:186-208`) reverses the section list and takes the first ancestry-valid, verdict-bearing candidate — i.e. the last-APPENDED section wins. `0216` proved that rule can read a strictly older measurement as authoritative: `0215` (task-w40-g @ `2e99b272`) outranked `0210` (task-w42-a @ `e01f237e`) purely by filename sequence, even though `2e99b272` is an ANCESTOR of `e01f237e` — `0215` measured an older tree and described a polling attempt against a `main` tip (`9f78158b`) that predates the section it displaced. The instrument reported FAIL where the newest reading of the tree said PASS. Under DEC-620 an instrument that cries wolf is a broken gate, and repairing it is a precondition of a truthful reading, not a code merge that invalidates one.

RULING: among the ancestry-valid, verdict-bearing candidates for a slot, discard any whose sha is a PROPER ANCESTOR of another candidate's sha (it measured a strictly older tree), then take the last-appended of what remains. The rule is content-independent and direction-independent — it would have demoted a stale PASS exactly as readily as this stale FAIL — and it makes no reference to any section's text, branch or wave. To express it, the injected oracle generalises from `isAncestorOfProductSha(sha)` to a single `isAncestor(ancestorSha: string, descendantSha: string) => boolean`, with the product-sha check becoming `isAncestor(productSha, section.sha)`; the CLI supplies the git-backed implementation and every existing test is updated to the one-oracle shape. No compatibility shim, no second optional parameter.

Deliberately recorded so it cannot be mistaken for tuning the gate to pass: this change is NOT load-bearing for wave 44's own verdict. Wave 44's triage-closure section (`0225`) carries both the newest measured sha AND the highest sequence number, so the old append-order rule and the new recency rule select the same section. The fix is landed because the defect is real and already cost a wave, not because this wave's reading depends on it. Separation of hands is binding: the instrument lane (task-w44-g) writes no verification-log section, and the ledger lane (task-w44-h) does not touch `scripts/exit-predicate.ts` — the reader and the instrument stay separate hands.


## Amendment (wave 45): A SLOT IS CLAIMED BY NAME AND BY LABEL — a keyword-matched, unlabelled section must never decide a DEC-069 gate slot

Two live instrument defects, derived at file:line at my own runtime, not inherited from any ledger.

(i) `scripts/exit-predicate.ts:88-113` computes `qualifying` (true iff a body line is exactly `QUALIFYING`, DEC-069's wave-28 label for an allow-listed gate section) and returns it on `LogSection` — and then `gradePredicate` (`:186-209`) and `slotOutcome` (`:211-218`) NEVER READ IT. The label the whole freeze discipline is built on is parsed and discarded. Any section can decide a gate slot whether or not it claims to be a gate.

(ii) `classifyScope` (`:145-153`) is a loose keyword matcher: `/perf/` alone claims the perf-smoke slot. Two REAL sections in the corpus match it and are not perf gates — `0176-...-task-w29-a-onboarding-grid-perf-1d274c8b.md` (scope "onboarding grid TIER-0 perf") and `0184-...-task-w31-a-files-library-perf-39634fe8.md` ("files library headshot join perf"). They are ancestry-stale today, so this has not yet decided a verdict — but it is the same shape as the `0215`-over-`0210` artifact that DID decide wave 42's verdict, and it is one merge away from mattering.

RULING. A section is a CANDIDATE for a DEC-069 slot only if BOTH hold: it carries a bare `QUALIFYING` line, and its scope names that gate by its canonical name as a whole token — `triage-closure`/`triage closure`, `spec-audit`/`spec audit`, `perf-smoke`/`perf smoke`, `walkthrough`, or `build` and `test` both present as whole words. A non-candidate is skipped entirely: it contributes neither a PASS/FAIL verdict nor a `sawStaleVerdict` VOID. This is a narrowing of an existing rule, not a new contract — DEC-069's wave-40 amendment already told every gate lane to use exactly those literals, and this makes the instrument enforce what the amendment already required. No compatibility shim and no second code path (house rule).

COROLLARY, binding on this wave: every wave-45 section uses a scope literal that classifies to NONE of the five slots under BOTH the current and the tightened classifier — `review-integrity adjudication`, `comms-integrity adjudication`, `onboarding-lifecycle adjudication`, `agenda-publication adjudication`, `crm-directory adjudication`, `content-approval adjudication`, `log-header contract repair`, `slot-claim instrument repair` — and carries the advisory label `QUALIFYING (advisory to the DEC-069 predicate — this scope classifies to none of the five slots)` on ONE line, which correctly leaves `qualifying` false. A wave-45 section can therefore never hijack a wave-44 slot, whatever its `RESULT`/`OPEN ITEMS` lines say.

HARD ABORT, because an instrument repair that moves a verdict is indistinguishable from eval gaming: the implementing lane runs `npm run exit:predicate -- --product-sha <newest first-parent product-code-bearing sha>` before and after its change, records both tables verbatim in its section, and if ANY of the five slots changes status it lands only the half that does not, and FILES the other half with the before/after tables and a named wave-46 owner.


## Amendment (wave 46): an unresolvable header sha is NOT-ANCESTOR, never a crash; the perf-smoke slot is claimed only by an explicit perf-smoke literal; `qualifying` stays advisory

Three separate instrument rulings, all re-derived against `scripts/exit-predicate.ts` at my own runtime. (1) CRASH. `isAncestor` (`:289-310`) maps git exit status 1 to false and RETHROWS everything else. `git merge-base --is-ancestor <bad-sha> X` exits 128 with `fatal: Not a valid object name`, so a single ancient, garbage-collected header sha anywhere in the log aborts `gradePredicate` before it can grade ANY slot — the instrument produces nothing at all rather than a graded VOID row. That is not fail-loud, it is fail-blind: the failure is total and tells the reader nothing about the four healthy slots. RULING: an unresolvable git object resolves to NOT-AN-ANCESTOR, and the degradation is made loud PER SECTION (one `console.warn` naming both shas and the section header) rather than fatal for the run. The invariant that matters — a section only counts when the product sha is genuinely an ancestor of it — is preserved exactly: an unresolvable sha cannot be proven an ancestor, so it must not count. (2) SLOT CLAIM BY LABEL. `classifyScope` (`:145-153`) tests a bare `/perf/`, so `0179`'s scope "files library perf fix" — a wave-29 fix report, not a gate — classifies to `perf-smoke` and would decide that slot outright if its sha were ancestry-valid. This is the identical shape to the `0215`-over-`0210` artifact that already cost wave 42 a slot. RULING: `perf-smoke` is claimed only by an explicit `perf-smoke` / `perf smoke` / `perf:smoke` / `perf_smoke` literal; a scope that merely uses the word `perf` descriptively classifies to null, which is the correct, honest 'this is not a gate section' answer the classifier was built to give. (3) QUALIFYING. `parseLogSections` populates `LogSection.qualifying` and `gradePredicate` never reads it. That is deliberate and is now recorded so it is not 'fixed' into a grading input: `QUALIFYING` is the human label this DEC's own wave-28 amendment invented for gate sections written under a frozen product, and every section published before wave 28 lacks it. Promoting it to a grading precondition would retroactively void the entire pre-wave-28 corpus to add zero information. It stays parsed, advisory, and covered by a test that asserts a section WITHOUT the label still grades normally.

## Amendment (wave 76): an exemption's reason may never be a BRANCH NAME — a branch-parked exemption expires when the branch lands or dies, and a machine check enforces it

Two guards in this tree hold exemptions whose entire justification is an in-flight branch. `app/src/confirm-primary-object.scan.test.ts:17-19` reads `// FieldModal/FormsPage delete affordance is owned by unmerged branch task-w66-i at wave 68 -- re-check when it lands.` above `const EXEMPT_DIRS = ['pages/forms/']`, and a test at `:85-87` PINS that list (`expect(EXEMPT_DIRS).toEqual(['pages/forms/'])`), so the exemption cannot lapse quietly and the scan can never grow to cover the directory. `task-w66-i` is eight waves gone — absent from loose refs and from `.git/packed-refs`. What the exemption hides is a live violation of DEC-941's own wave-68 rule: `app/src/pages/forms/FormsPage.tsx:462` renders `confirmLabel="Delete"`, a bare member of the disallowed-verb set the scan exists to forbid. The second member is `app/src/refusal-rendering-ledger.scan.test.ts:109-115`, whose `pages/forms/FormsPage.tsx` row reads `'owned by task-w53-e (?cascade=1 refusal UI); ledger row filed, proof pending that branch landing'` — a wave-55 parking ticket on a branch equally long gone. RULING: a branch is a schedule, not a principle; an exemption reason that names one is void the moment the branch is no longer live, and nothing in the tree re-checks that. So (a) both entries are re-derived now against main — deleted if the thing they excused has landed, restated with a principled reason if it has not — and (b) a machine check makes the rule self-enforcing: no EXEMPTIONS/ledger reason string anywhere under `test/` or `app/src` may match `/task-w\d+-[a-z]/`. ## Amendment (wave 4): an exemption reason may not be schedule-shaped, not just branch-shaped

Wave 76 banned a reason: string matching a branch token after one hid a live bare confirmLabel for eight waves. The same parking ticket keeps arriving with the name filed off — "a sibling task in this wave owns this", "a later wave", "unmerged", "being converted on a parallel branch", "unreviewed — filed for a later wave". A branch is a schedule; so is a wave, a sibling and a for-now. A reason must name the INVARIANT that makes the exemption correct forever, or the exemption must go.
