# DEC-692: A content worklist row names the session, the speaker, the LATEST artefact and its status, and carries exactly two actions

Verified: app/src/pages/content/SessionList.tsx:80-88 renders Session · Deliverables · Content status · Content actions, where Deliverables is three per-kind chips including explicit absences, and the row offers both Approve and Ask for changes. The design v4 mock (docs/design/Chautauqua Content.dc.html:73-89) specifies Session · Speaker · Latest file · Status with a single "Open" control beside Approve, and the v4 README places Ask-for-changes on the session screen — because asking for changes requires reading the file you are objecting to, and a worklist row cannot show it. The reason the current table shows kind-counts instead is that ContentSubmissionListItem (app/src/pages/content/types.ts:33-40) carries deliverableCounts and nothing about the newest file; the fix is a `latestFile` field computed the way the counts already are — one batched query keyed to the page's submission ids in src/server/repo/submissions/list.ts:190-210 — never a scan of every file in the event (DEC-686). Speaker gets its own column because "who owes this" is the question the worklist answers.
