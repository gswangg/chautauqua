# DEC-386: Phone cards come from CSS on the same markup, and a phone card shows exactly the desktop row's cells

The mocks draw every admin list as a card stack at 390px, and there are two ways to get there: transform the existing table in CSS, or render a second phone-only DOM branch and display:none one of them. The tree already contains one instance of the second (`.chq-speakers-cards` vs `.chq-speakers-grid-wrap` in speakers.css) and it is the right call exactly there — the onboarding grid is a speaker x task matrix, which has no CSS degradation. Everywhere else the transform is the rule: `thead` hidden, each `tr` a card, each `td` a block, one DOM, one accessibility tree, no duplicated row rendering on the volume screens (2,000-row tables, SPEC 0 scale targets). No new duplicated phone branch may be introduced. Second half of the rule: a phone card shows exactly the cells the desktop row shows — no cell is hidden to make the card fit, and no action is added that the desktop row lacks. Concretely the Submissions phone frame's per-row Accept/Decline/Read buttons are DROPPED, for the reason DEC-380 dropped 'move DFC-047 to 11:30': row-level triage on a paginated table whose selection spans pages and whose bulk path deliberately refetches rather than restoring a snapshot (DEC-193) needs its own optimistic/rollback semantics, and a layout lane must not invent them. Overview keeps its row actions because Overview is a worklist whose rows leave on success, which is a different contract.
