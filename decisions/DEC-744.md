One token (`--chq-measure: 820px`) declared in :root and consumed by `.chq-measure` makes the measure a fact instead of four opinions, and a source-scan test in the established app/src/shell-geometry.test.ts style keeps a future page from re-inventing a literal. ## Amendment (wave 40)

**A clamp is only a clamp if the box can reach it: max-width + auto side margins on a flex-column CHILD shrink-wraps, so one clamp per page, at the root**

Verified on main: app/src/styles.css:875 makes .chq-page a flex column; app/src/pages/forms/forms.css re-clamps three of its children (.chq-forms-header:25-28, .chq-forms-content:60-63, .chq-forms-settings:260-262) with max-width: var(--chq-measure) plus margin-left/right: auto. Auto cross-axis margins disable align-items: stretch, so those boxes size to their CONTENT, not to the measure — the CFP builder's header measures 275.5px and its content 617px inside an 820px column, which is the fleet's 'builder shrink-wraps its children' P1 and a regression of the gate-2 'header 820-aligned' fix. The measure is a property of the PAGE (DEC-989: it lives on the page root as a class), so a page-lane stylesheet re-declaring it is not redundancy, it is a second opinion that loses. RULING: a page carries exactly one clamp, on its root element, via the .chq-measure* classes; page-lane CSS never re-clamps a child of that root. Where a nested box genuinely needs its own narrower measure (the Comms template editor inside the 1440 Comms page), it must declare width: 100% alongside the max-width so it fills before it caps. An enumerating scan in css-contract.scan.test.ts makes both halves a build error.
