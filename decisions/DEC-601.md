# DEC-601: Attribution is resolved by the route that owns the row; a client-side 'Unknown' fallback is the symptom, not the fix

GET /submissions/:id/files returns uploadedByContactId and never a name, so VersionList's `v.uploaderName ?? 'Unknown uploader'` renders 'Unknown uploader' on every version of every file in the product. The list routes resolve contact names in one batched lookup and return uploaderName; where the uploader genuinely cannot be resolved (a row with no contact, e.g. an organiser-side import) the surface names what it does know rather than printing 'Unknown', and the client keeps no invented fallback string.
