# DEC-830: Participation status is a MENU of named states, each stating its consequence; the portal invite is an ACTION in that menu, not a state it writes

VERIFIED OnboardingGrid.tsx:221-240 CYCLES the status on click (nextInviteStatus) with no menu, and docs/design/README.md:289-291 requires a caret menu in the identity column — organiser-driven states, unlike the speaker-driven task cells that toggle. But the design's other sentence (README:315, 'Send portal invite … sets this to Invited') cannot be taken literally: src/domain/acceptance.ts:114-127 makes 'invited' NOT active and NOT publicly visible, and DEC-317 makes it portal-READ-only — so mailing a claim link would simultaneously unpublish the speaker and forbid them to upload anything through the link they were just sent. Decision: the menu writes participation status only, in the meanings the product already has — Not invited (none) · Invited (invited) · Confirmed (accepted) · Declined (declined) — with a one-line consequence caption naming what the chosen state does ('Invited and Declined hide this speaker from the public pages and pause their uploads'; Confirmed creates their onboarding tasks, which PATCH already ensures per DEC-813). 'Send portal invite' sits in the SAME menu as an action, keeping DEC-805's send exactly as built and writing NO status, so the send has one writer and cannot half-fail into a lie; the footer reads 'Only Send portal invite sends anything — the other three record what you already know'. Rows at Not invited keep their existing inline Send-portal-invite link, and the control reuses the DEC-730 shapes so the grid keeps one visual vocabulary.

## Amendment (wave 19): the participation menu panel is the vendored frame's 420px three-band panel, not the event-switcher dropdown

DEC-830 recorded the panel as "a plain anchored dropdown matching event-switcher.css's menu pattern" and the build implements that (app/src/pages/speakers/speakers.css:372-386: min-width 260px, panel-level padding 8px, gap 2px, rows at 6px/8px with a 13px label and an 11px caption). The vendored pack draws something else: docs/design/Chautauqua Speakers.dc.html:296-317 is a 420px panel with THREE bands and no panel-level padding -- an identity header (padding 16px 20px, 17px display name over a 12px muted company/account line, closed by a 1px ink rule), a body band (padding 8px 0) whose rows run edge to edge at padding 11px 20px with a 15px label over a 12px/1.45 muted detail and the NOW marker pushed right in olive 11px/800/0.09em caps, and a footer band (border-top 1px #D3CFC0, background #EFEBDF, padding 14px 20px, 12px muted). The frame also gives the "Send portal invite" row its own detail line ("Emails a claim link and sets this to Invited") in the olive weight; the build renders that row with no caption at all, so the one row that SENDS is the only row that does not state its consequence -- the exact thing DEC-830's title promises. Per the mandate's standing rule the vendored pack outranks a research render, and here the pack and the build disagree on the artifact itself, not on a measured pixel.

## Amendment (wave 29): a caret inside a control that paints its own background inherits the control's ink

`.chq-participation-menu-caret { color: var(--chq-muted) }` (app/src/pages/speakers/speakers.css:390-395) measures contrast 1.02 — fg rgb(86,90,75) = `--chq-muted`, bg rgb(78,92,49) = `--chq-brand` — on both `/admin/speakers` and `/admin/speakers/seed_contact_0001`. The trigger's `complete` modifier is a filled olive pill that repaints its own ink (`.chq-speakers-status-complete { color: var(--chq-on-brand); background: var(--chq-brand) }`, `:296-300`), so the LABEL follows the fill while the caret keeps the resting-surface muted token and vanishes. The outline modifiers (`-pending`/`-overdue`/`-none`/`-neutral`, `:303-343`) each set their own colour too. RULING: a caret or affordance glyph inside a control that paints a background declares `color: inherit`, so it travels with every register of that control. On the outline variants `inherit` reproduces today's appearance exactly, so this is a strict fix with no desktop pixel moved elsewhere. A `*-caret` class that must keep a named token carries an inline exemption comment citing this amendment and the resting background it was measured against — otherwise the rule is mechanical and scanned.
