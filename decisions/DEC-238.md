# DEC-238: Mailer failure taxonomy: system sends are per-recipient best-effort; organizer-triggered batch sends return a structured {sent, failed} summary, never a 500

The mailer port logs an email_log row with status 'error' before rethrowing (src/mail/email-binding.ts:60-82), so callers own the failure policy. Three classes: (1) system-initiated sends — public submit confirmation, cron due reminders (sendDueRemindersForEvent), account-creation notices — catch per recipient, console.error, continue; one bad recipient must never abort the loop or the primary action. (2) organizer-triggered batch sends — comms compose/send, plan remind, CRM bulk email, bulk task reminders — catch per recipient and respond 200 with {sent: n, failed: [{email, message}]} so the organizer who clicked send sees exactly what failed; a provider failure is never a 500. (3) internal invariant violations still throw. This forecloses both silent swallowing and all-or-nothing aborts.
