# DEC-991: A clip exception names the ELEMENT's nature; a branch-ownership note or a deferred visual pass is not a reason, and the map holds exactly one entry

DEC-620's clip probe is the guard against silently truncated content, and scripts/render-sweep.ts's KNOWN_CLIP_EXCEPTIONS now silences it on 34 route/selector pairs. Eight of those read "owned by another in-flight branch" — a task-scheduling note from a wave long merged, hardened into a permanent exemption, which is precisely the failure DEC-985 named for HTML_ROUTE_EXCLUDED. Another twenty read "line-height tighter than font metrics; needs a visual pass", which is a defect with a comment: .chq-portal-hero declares line-height:1.05 and .chq-pub-header-title line-height:1 against a display face whose rendered line box is taller, so the glyphs overflow their box on the portal, every public surface, the CFP form and the account card. The only reason that may stand in this map is one about the element itself — the agenda card's deliberate -webkit-line-clamp truncation, where the card scrolls and nothing is lost. Every other entry is deleted, and the headings it covered declare a line-height at or above the font's line box; a scan over the reasons is what stops the list growing back. The same file's dead .chq-pub-gallery-tile/.chq-pub-gallery-name rules — defined by the stylesheet, used by no markup — go with them: scan BOTH directions.

## Amendment (wave 27): a display-font heading NEVER declares line-height <= 1 — delete the declaration, don't substitute a tighter number, and scan both stylesheet trees

DEC-991 already ruled that KNOWN_CLIP_EXCEPTIONS is not a parking lot and that every clip it used to cover "was a real line-height-vs-font-metrics bug and has been fixed at its CSS source". The one surviving genuine offender in the newest truthful-probe receipt (docs/verification-log.md:3569-3571, task-w25-a @ 1950921d: desktop 59/60, `div.chq-forms-header-titles`/`h1` clip=3px) is exactly that bug, unfixed. Measured at this tip, three rules declare the display face together with `line-height: 1`: `app/src/pages/forms/forms.css:44-51` (`.chq-forms-header-titles h1`, 28px, THE gate offender), `app/src/pages/comms/comms.css:240-247` (`.chq-comms-send-report-headline`, 30px, same latent shape), `src/routes/auth.css.ts:56-63` (`.chq-auth-wordmark`, 28px, the false-positive of task-w17-d that is still a latent clip wherever an ancestor clips). RULING: a display-font heading either OMITS `line-height` — `normal` is by definition the font's own line box and therefore cannot clip its glyphs, which is what the shared reference `.chq-page-title` (app/src/styles.css:432-439) already does — or declares a value >= 1.08, the measured floor already in the tree at `src/routes/public/cfp.css.ts:58`. `line-height: 1` on the display face is banned outright. For these three the fix is DELETION, not substitution: 1.08 at 28-30px buys ~2.2px of headroom, inside the clip probe's own 2px tolerance, so it is not provably clear. The rule is enforced by a scan over `app/src/**/*.css`, `src/**/*.css.ts` and `src/views/theme.ts` keyed on the display face (`var(--chq-font-display)` or the literal `'Familjen Grotesk'`), so UI-font rules the vendored pack explicitly specifies at line-height 1 (`.chq-nav`, docs/design/README.md:151; caret/time-label micro-labels) are untouched, and the vendored Overview-headline exception (lh 1.04, docs/design/README.md:66) is unaffected because it is > 1.
