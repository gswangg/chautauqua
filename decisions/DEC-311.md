# DEC-311: The 390x844 no-overflow bar extends to /docs/api and /dev/mailbox, and both join MOBILE_ROUTE_MANIFEST

Section d correctly noted that neither route is in DEC-253's named surface list and flagged them anyway under the general bar. Adopt them rather than argue scope: /docs/api is a public, no-login, README-linked page (DEC-056) and /dev/mailbox is stage 1's entire substitute for a real inbox per docs/clarifications.md:31-33 — it is the only way a local operator can read a sent email or its .ics, so it is a surface a human opens, sometimes on a phone. The causes are different and both are cheap: src/routes/docs.tsx:242 sets `table { width: 100% }` around long unbreakable `<code>` paths so the tables' intrinsic width (~761px) drives the 371px overflow, while src/routes/dev/mailbox.tsx has NO `<meta name="viewport">` at all and no stylesheet, so the page lays out at the default ~980px viewport — that missing meta tag is the 96px, not the table. Fix pattern is DEC-253's: a scrollable wrapper plus the viewport meta, never a re-layout of the content. Both routes join scripts/render-sweep.ts's MOBILE_ROUTE_MANIFEST so `npm run gate:render-sweep` enforces this permanently; the sweep boots `wrangler dev` with DEV_MODE=1 from .dev.vars (test/wrangler-config.test.ts:57-63), so /dev/mailbox is mounted, and scripts/render-sweep-lib.ts:131 already treats a page with no primary controls (`minControlHeight === null`) as a pass, so no decorative `<nav>` may be added to manufacture one.
