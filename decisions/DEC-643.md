# DEC-643: The type scale is a token set, and Overview's key type roles are asserted by COMPUTED weight in the render sweep

DEC-421's type invariant is a floor — nothing below 10px — and a floor cannot see a 600 where the design says 700. The README typography table currently lives as per-component px/weight literals (app/src/pages/overview/overview.css alone repeats it a dozen times), which is how a design system drifts one component at a time; the user's manual-QA pass found exactly that on Overview. Roles become `--chq-type-*` tokens so the table is the single source, and the sweep grows an advisory computed-style pass over the four load-bearing Overview roles (headline 44/700/-0.042em, section label 11/700/0.12em, deadline value 30/400 with EXACTLY ONE at 700, row title 600) so drift fails loudly instead of being noticed by eye.

## Amendment (wave 25): the type-role nearest-deadline expectation must accept a tie set

The gate's type-role row demands exactly one `.chq-overview-deadline-value` at weight 700 and observed two, filed as a product defect. It is the instrument that is wrong: DEC-611's wave-2 amendment already ruled nearest-deadline emphasis a SET — a tie marks every cell sharing the minimum rather than an arbitrary first-wins pick — and app/src/pages/overview/rows.test.ts:180-189 pins that behavior. RULING: the expectation becomes 'at least one cell at 700, and every 700 cell shares the minimum deadline value'; a non-nearest cell at 700 still fails. An instrument expectation that contradicts a recorded product ruling is a defect in the instrument, and reconciling it is not weakening the gate.
