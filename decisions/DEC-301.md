# DEC-301: A newly created event ships a submittable CFP: creation provisions a default 'General' track, and track choice is required only when the form actually offers tracks

src/routes/api/events.ts:217 provisions the default form at event-create time when the event has zero tracks, so /submit/<slug> renders an empty 'Track *' fieldset and every POST 400s on src/lib/submit-core.ts:45's unconditional 'Select at least one track.' — a dead end with no in-app explanation, hit by the first submitter of any event a producer creates in the product (only the seeded event escapes, because the seed makes tracks). Two complementary changes, both required: creation also inserts one track named 'General' (SPEC section 2.1 — settings get defaults, not wizards; the producer renames it in Settings and gets working track colors and track-scoped review assignment for free), and validateTrackChoice treats an EMPTY offered set as 'no track requirement' so events created before this change, or a form deliberately narrowed to zero tracks, are submittable rather than bricked. An empty selection against a non-empty offered set still errors exactly as today. The public submit page renders no Track fieldset at all when nothing is offered, instead of an empty required block.
