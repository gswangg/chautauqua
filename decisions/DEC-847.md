# DEC-847: A subject is one line: a block merge field is body vocabulary, and an inline stated-absence value carries no terminal period

VERIFIED: scripts/seed-lib.ts:314 seeds Content Reminder with subject 'Reminder: {task_list} due {due_date}', and {task_list} is a multi-line block rendered by formatTaskLines — so the seeded template's preflight produces PARAGRAPH subject lines, and for a recipient with nothing outstanding it produces 'due No due date: No outstanding tasks..' because NO_TASKS_TEXT (src/domain/compose.ts:16) already ends in a period the template supplies again. COMPOSE_MERGE_FIELDS (src/mail/render.ts:28) is one flat vocabulary with no notion of shape. Decision: the vocabulary is typed by shape — BLOCK_MERGE_FIELDS = {task_list, feedback} may appear in a body only, SUBJECT_MERGE_FIELDS = COMPOSE_MERGE_FIELDS minus the block set — and compose preview/send reject a subject referencing a block field with a loud 400 naming it ('{task_list} is a list; it cannot go in a subject'), the same shape as the DEC-793 named preflight errors. A value substituted INLINE carries no terminal punctuation (NO_TASKS_TEXT becomes 'No outstanding tasks'); the template owns its own sentence. NO_FEEDBACK_TEXT stays a full sentence because feedback is a standalone block paragraph. The seeded template is then rewritten to conform rather than being grandfathered — a seeded template whose tokens the path rejects is the landmine DEC-792 was minted to remove.
