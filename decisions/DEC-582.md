# DEC-582: GET / is an anonymous surface: signed-in visitors are redirected by role, and it is styled from the public CSS family — revising DEC-382 for / only

Today GET / never reads c.var.auth and shows an operator link farm ('Admin', 'Speaker portal', 'Dev mailbox') to everyone including strangers. The v2 handoff makes / the org's event hub — the masthead carries the ORG's name, the product is named exactly once in a footer GitHub attribution, and the only auth affordance is a quiet Sign in. It therefore only ever renders for anonymous visitors: organizer and reviewer sessions redirect to /admin, speaker sessions to /portal, matching the redirects /admin already performs. DEC-382 filed /, /docs/api and /dev/mailbox together as 'chrome, not designed screens' sharing TOOLS_CSS; that verdict is now wrong for / alone, which draws ThemeStyles + the public CSS family + its own HOME_CSS module. /docs/api and /dev/mailbox stay chrome under DEC-382 unchanged. The dev-mailbox link disappears from / rather than being auth-gated: the only role that could see it now redirects away before the page renders.
