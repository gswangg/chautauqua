# DEC-018: Review API contract, criteria kinds, reviewer UX, and /api/v1/me

J4 has a producer side and a reviewer side built by two parallel tasks, so the wire contract is fixed here. Criteria (evaluation_plan.criteria_json): [{ id, label, kind: 'rating'|'dropdown', weight?, options? }] — 'rating' requires weight>0 and numeric scores within scale_json {min,max}; 'dropdown' requires options: string[] and stores the chosen string; free text is evaluation.comment. Aggregation (computeWeightedScore/aggregateSubmission from src/domain/evaluation.ts) consumes rating criteria only. Producer endpoints (requireOrganizer + csrfJson): GET/POST /api/v1/events/:eventId/plans; GET/PATCH/DELETE /api/v1/plans/:id; POST/DELETE /api/v1/plans/:id/reviewers { userId, trackId?, submissionId? } (DEC-017 scope semantics); GET /api/v1/plans/:id/progress -> per-reviewer { userId, email, assigned, completed }; GET /api/v1/plans/:id/results -> { submissionId, ref, title, count, average, perCriterion } sorted by buildResultsRows, ?format=csv streams CSV via toCsv; POST /api/v1/plans/:id/remind sends a nudge via the DEC-006 mailer to reviewers with incomplete queues. Progress and results are organizer-only — reviewers never see aggregates. Reviewer endpoints under /api/v1/review/* accept role 'reviewer' OR 'organizer' via an inline check (requireReviewer's semantics are NOT widened): GET /api/v1/review/plans; GET /api/v1/review/plans/:id/queue — ordered by buildReviewerQueue (fewest-ratings-first), capped by needsMoreRatings, gated by plan open/close dates, and when plan.anonymized the server strips speaker names and speaker-section answers (anonymizeForReviewer; never client-side); GET /api/v1/review/submissions/:id?planId= (404 outside the reviewer's assignment); PUT /api/v1/review/plans/:planId/evaluations/:submissionId { scores, comment } upserts (unique per plan+submission+reviewer+round), validates against criteria/scale, 'conflict' when the plan is closed or the cap is reached. Bootstrap: GET /api/v1/me -> { userId, email, role, orgId, contactId? } (401 unauthenticated) so the SPA can role-gate; reviewers see only the Review nav section and land on /review.
