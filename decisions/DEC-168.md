# DEC-168: .ics methods and role properties per RFC 5546 (amends DEC-007)

Verified: buildIcsCalendar hardcodes METHOD:REQUEST with no ORGANIZER/ATTENDEE; RFC 5546 requires both for REQUEST and Gmail/Outlook mishandle such invites, undermining the explicit standards-compliant-.ics requirement. Rule: buildIcsCalendar/buildIcsEvent take opts { method: 'REQUEST'|'PUBLISH'; organizer: {name,email}; attendee?: {name?,email} }; assert (fail loudly) REQUEST has an attendee and PUBLISH has none; every VEVENT emits ORGANIZER;CN="<name>":mailto:<email> (embedded double quotes stripped from CN), and REQUEST additionally emits ATTENDEE;CN;ROLE=REQ-PARTICIPANT;PARTSTAT=NEEDS-ACTION;RSVP=TRUE:mailto:<recipient>. Compose email attachments use REQUEST with the recipient as attendee (preserving the UID/SEQUENCE update flow); the public /e/:slug/schedule.ics download uses PUBLISH. Stage-1 has no real from-address, so ORGANIZER email is the exported constant ICS_ORGANIZER_EMAIL='noreply@chautauqua.local' with CN = event name; stage 2 may substitute a real sender. All other DEC-007 rules (UID, SEQUENCE, folding, escaping, UTC) stand.
