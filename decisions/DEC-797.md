# DEC-797: Test isolation is a harness guarantee, not a per-file habit

VERIFIED vitest.config.ts declares no setupFiles at all, so DOM cleanup between render tests depends on each file remembering its own afterEach(cleanup) — MergePage.render.test.tsx does clean up and still fails only in the whole-app run, which is the signature of leaked DOM or module state from a NEIGHBOUR file. An order-dependent red randomly breaks merge-train validation, which taxes every future wave, so the fix belongs in the harness rather than in whichever file the failure surfaces. Decision: one setup file registers afterEach(cleanup) globally for DOM environments (guarded so node-environment suites, which must not import testing-library, are unaffected), and the config points every project at it; per-file cleanup calls become redundant rather than load-bearing. Root-causing means the whole-app subtree run passes repeatedly, not that a retry went green.
