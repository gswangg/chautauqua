# DEC-731: A call for papers is published by its window, not a flag: the builder states the live state and writes open/close dates

The CFP grader wants an explicit publish affordance, but form.open_date/close_date already decide public visibility via formWindowState — adding a `published` column would create a second source of truth that can disagree with the dates the public form enforces. So the builder names the derived state ('Open · closes 16 Aug' / 'Not yet open' / 'Closed') and offers 'Open the call now' / 'Close the call now', which write open_date/close_date. Close-before-open is refused server-side in the PATCH validator and surfaced at the field, not as a quiet banner — a validation the user cannot see is a validation that does not exist.

## Amendment (wave 44): a window has one possible next move — the CFP editor renders the control that changes the current state, not both

DEC-731 established that a call for papers is published by its WINDOW, not a flag. The editor currently offers "Open the call now" and "Close the call now" side by side, so one of the two is always a no-op dressed as an action. The affordance grammar is conditional-and-quiet: controls render only when their action is possible. Which control is possible is read from the same formWindowState the rest of the surface already reads — never a second reading of the window.
