# DEC-121: Portal submission edit: locked speaker fields prefill from the contact row; first/last name sync back to the contact on save; email is read-only with stored-value carry-over

loadEditableSubmission surfaces only LOCKED_SESSION_FIELDS (title/description) into answers, so the always-required locked speaker fields (first_name/last_name/email, rendered by the speaker section at src/routes/portal/edit.tsx:141) appear empty on GET, force re-typing on POST, and saveSubmissionEdits then discards them (lockedFieldName filter at portal-edit.ts:167) — breaking J2/J7 ('never re-enters data', edits appear on the producer's record); scripts/walkthrough/scale.ts:483-485 currently works around the bug by re-typing them. Ruling: prefill all three from the contact row (loadEditableSubmission already receives contactId); first_name/last_name remain editable inputs and sync to contact.firstName/lastName in saveSubmissionEdits (which gains a contactId parameter); email renders as static read-only text (same treatment as file fields, excluded from the input set) and extractAnswers carries the stored contact email into answers exactly like the DEC-109 file carry-over so required-validation passes. Email stays immutable here because it is the contact-matching identity key for public submit and comms — changing it belongs to contact merge (DEC-101), not a submission edit. This is walkthrough-compatible: posted field__email is simply ignored, and same-value name re-posts are no-op syncs.
