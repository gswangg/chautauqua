# DEC-024: SPA shared modules for wave 3: useCurrentEvent, useMe, api.ts as sole wire

Five wave-3 SPA tasks each need the current event and the caller's role; without one contract each would invent its own. app/src/lib/useCurrentEvent.ts exports useCurrentEvent(): { eventId: string | null, loading: boolean, error?: string } — resolution order: ?eventId URL param -> localStorage 'chq.currentEventId' (same key w2-f's stand-in uses) -> fetch GET /api/v1/events and take items[0].id, persisting it; errors surface loudly, no silent null. app/src/lib/useMe.ts exports useMe(): { me: { userId, email, role, orgId, contactId? } | null, loading } via GET /api/v1/me. Any wave-3 SPA task that finds either file missing on its branch creates it exactly to this contract (declared overlap; the merge train dedupes identical intents). All SPA API traffic goes through app/src/lib/api.ts (apiGet/apiList/apiPost/apiPatch/apiDelete, landed) — pages never call fetch() directly; the one extension allowed is an appended apiUpload(path, formData) helper (sets x-chq-csrf, credentials include, no manual content-type) owned by the Content SPA task for multipart uploads. The submissions-local useCurrentEventId.ts hook stays untouched until a cleanup wave. App.tsx role gating (reviewers see only Review, land on /review) is owned by the Review SPA task.
