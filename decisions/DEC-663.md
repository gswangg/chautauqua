# DEC-663: A CSV import is PLANNED before it is applied: one dry run names, per row, what it will do, which stored non-blank fields it will replace, and which existing contact it may duplicate under a different address -- and the organizer's per-line skips bind the real run

Two confirmed data paths converge here. (1) src/server/repo/contacts/import.ts dedupes strictly by normalized email, so re-importing the same person under a second address silently creates a duplicate while the summary reads "Created 1, updated 2, skipped 0" -- the org already owns a name+company duplicate rule (findDuplicateGroups, src/domain/contacts.ts:76, DEC-143) that the import path simply never consults. (2) resolveImportUpsert (src/server/repo/contacts/query.ts:109-114) writes any non-blank incoming bio/title/company straight over a curated stored value with no warning (mandate Tier 0 #5's third data-loss path). Both are the same defect: the organizer is asked to commit before being shown the consequence. The contract is fixed here so the server and the wizard can be built in parallel: POST /api/v1/contacts/import accepts `dryRun?: boolean` and `skipLines?: number[]`; with dryRun:true it performs NO writes and returns { rows: Array<{ line, email, action: 'create'|'update'|'skip', reason?, contactId?, overwrites?: Array<{ field, from, to }>, possibleDuplicates?: Array<{ contactId, name, email, company }> }>, created, updated, skipped } where those three counts are INTENT; on a real run the counts stay what they are today -- counted AFTER commit -- and every line in skipLines appears in `skipped` with an explicit reason. A field is an `overwrite` only when the incoming value is non-blank, the stored value is non-blank, and they differ after trim (a blank cell remains ABSENT DATA, unchanged). Duplicate candidates use the SAME normalization findDuplicateGroups uses and are restricted to contacts whose normalized email differs from the row's; they are fetched in the same chunked pre-pass style applyImportRows already uses for emails, never a whole-org scan.
