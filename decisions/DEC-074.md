# DEC-074: Portal speaker edit validates track selection with the same validateTrackChoice gate as public submit, after dedupe

The portal edit POST saves extractTrackIds(body) with only a non-empty check (src/routes/portal/edit.tsx:190), letting a speaker attach any track id from any event/org — corrupting track-scoped review assignment, admin filters, and public track chips — and duplicate ids 500 via the submission_track composite PK. loadEditableSubmission already returns offeredTrackIds, and src/lib/submit-core exports validateTrackChoice used by the public submit path; the edit POST must dedupe then validate selected ids against offeredTrackIds and re-render 400 with trackError on failure. One validator for both entry points, no second opinion.
