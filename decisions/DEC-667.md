# DEC-667: A run reports what it declined to do: auto-schedule's result names the pre-existing clashes it left in place alongside what it placed

app/src/pages/Agenda.tsx:100 renders "Auto-schedule placed N session(s). M unplaced, C conflict(s)." -- a bare conflict count that reads as though the run created C clashes, when in fact the scheduler deliberately never touches pre-existing placements (SPEC J9 / steal-mandate item 1: warn, never block). The sbek judge flagged exactly this ambiguity. The result must say so in words, and when nothing was placed it must name why using the typed reasons the domain already returns (describeUnplaced, src/domain/schedule.ts:89) rather than a silent zero.
