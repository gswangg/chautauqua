# DEC-410: The interactive-control class guard lands repo-wide now, and the lane that adds it also closes any straggler; app/src only, because SSR is covered at the element level

DEC-406 deliberately deferred its guard to this wave so three parallel lanes could each fix a third of the vocabulary without a guard landing red. Those lanes (submission detail, compose steps 1-2, forms FieldModal) are in wave 8's merge train, so the tree the guard is cut from is clean. The guard is a source scan in the shape test/table-class-conformance.test.ts and test/phone-wrap-conformance.test.ts already established: every opening <button/<input/<select/<textarea in app/src/**/*.tsx (excluding *.test.tsx) must carry a class from DEC-406's fixed vocabulary -- chq-btn plus a tier, chq-link-button, chq-input, chq-select, chq-textarea, chq-check, chq-checkbox-label, or a page-prefixed chq-<area>-* -- with <input type="hidden"> the one exemption. Scope stops at app/src: src/views/theme.ts styles bare button/input/select/textarea at the ELEMENT level (theme.ts:95-129), so a server-rendered control without a class is still on the design system, while an SPA control without one is not (app/src/styles.css tiers by class). The lane that adds the guard also fixes whatever it names -- a guard that ships with an allowlist of survivors is not a guard -- and it may add only classes that already have a rule in app/src/styles.css or the page's co-located <area>.css (DEC-368: never redefine a shared class, never edit the shell stylesheet from a page lane).
