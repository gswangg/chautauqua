# DEC-718: A validator rejects what the persistence layer cannot carry: number answers must be finite, and every accepted answer survives a JSON round trip

src/forms/validate.ts:112 rejects only NaN, so 'Infinity', '-Infinity' and '1e400' validate as ok and are then written by JSON.stringify at src/server/repo/submit.ts:320 as the literal string 'null'. A public CFP submitter sees the success confirmation while a REQUIRED number answer has silently vanished — an unhandled input class on the one unauthenticated write path (SPEC §6: the endpoint validates against the server's form schema). Patching the number branch alone repeats the pattern that produced it. The invariant that actually holds is broader and testable per-kind: whatever validateAnswers accepts must deep-equal itself after JSON.parse(JSON.stringify(...)). Enumerated over the FieldKind union rather than a hand-listed set, that test outlives the next new field kind.
