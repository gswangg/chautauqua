# DEC-676: A plan's criteria are a weighted, guided, freezable list; the editor states each criterion's share and names the lock

docs/eval-findings.md's appended plan-editor interaction spec (orchestrator-drafted, user-reviewed) is unimplemented. src/domain/evaluation.ts's criterion type carries id/label/weight and no one-line guidance; app/src/pages/review/PlanEditor.tsx renders inline criterion rows but no computed weight share, no 'Scores average by weight.' caption, no soft cap, and a brand-new plan starts with an empty criteria list; app/src/pages/review/Scorecard.tsx has nowhere to show guidance. Most importantly DEC-213 already enforces the freeze server-side (a criteria change that alters a round with evaluations is rejected) and the editor says NOTHING about it — the organizer discovers the rule as a save error instead of reading it on a locked row. A rule the server enforces and the UI never states is a trap, not an invariant: the locked row must name its reason and its count. Weights stay relative and plan-wide (never per-criterion scales, never forced sum-to-100) because computeWeightedScore already normalizes by total weight; rendering the derived share is the honest way to show that.
