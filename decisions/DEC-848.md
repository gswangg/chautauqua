# DEC-848: Two plans open at once, sharing one reviewer, is seed data — a scoped queue nobody can see scoped proves nothing

VERIFIED in scripts/seed.ts: plan 1 (Program Committee Review) is open and carries the reviewer persona; plan 2 (Developer Experience Track Review) closed before SEED_NOW with only synthetic reviewers; plan 3 (Late-Stage Program Review) opens AFTER SEED_NOW and carries the reviewer persona but, being upcoming, contributes no queue. So sbek-reviewer has exactly ONE live queue, and DEC-845's whole reason for existing — 'a reviewer assigned to several plans cannot tell which queue they are in' — is invisible to any grader or probe. Decision: the seed adds a FOURTH plan, open now (opens SEED_NOW-5d, closes SEED_NOW+35d), scoped to a different track from plan 1, with the reviewer persona assigned and a MINORITY of its queue already scored, so the reviewer lands on two simultaneously-open, differently-scoped, differently-progressed queues. Plan 3 keeps its upcoming window untouched (DEC-668's not-yet-open state is still the only example of that state), and plan 2 keeps its closed window. Per the standing rule that a seed must satisfy every read: a feature no grader can see through the seed fails its read regardless of how correct the code is.
