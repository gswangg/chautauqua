# DEC-778: A role you can see is a role you can change

app/src/pages/settings/PeopleRolesPanel.tsx:186 renders "Change" permanently `disabled` with a comment explaining there is no server route -- a control that can never fire, which the affordance rule forbids and which leaves an organizer unable to promote a reviewer without a database. SPEC §4 makes role grants a first-class part of the auth model and J4 depends on reviewers existing; the missing half is one route. Decision: PATCH /api/v1/users/:id { role: 'organizer' | 'reviewer' }, organizer-only, own-org only (same scope check as POST /users/:id/reset-password, DEC-215), refusing loudly when the change would remove the org's LAST organizer and when the caller targets their own row (privilege changes are not self-service). Sessions are not revoked -- a role change is not a compromise. The panel's Change becomes a real inline control, and the route is added to the hand-listed API surface in src/routes/docs.tsx in the same commit so the docs page cannot desync.
