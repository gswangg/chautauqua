# DEC-860: One saved embed is created one way: the builder is the only save path, and the row that lists an embed can delete it

VERIFIED on main. app/src/pages/settings/SavedEmbedsPanel.tsx:159-184 renders its own create <form> that POSTs `{name, surface, format:'iframe', options:{}}` — a second, lower-fidelity save path beside EmbedsPanel.tsx's real builder (which owns every knob, a Name field, an 'Editing · <name>' heading and a 'Save embed'/'Save changes' primary). The consequence is not cosmetic: the row it creates then renders a recipe through formatEmbedRecipe (line 121) that the organizer never chose — 'Sessions · iframe' asserted as a decision when it was a default. docs/design/README.md:281 is explicit that 'the builder becomes an editor of one saved embed', i.e. ONE lifecycle. Decision: the quick-save form is deleted, not fixed; SavedEmbedsPanel gains an `onBuild?: () => void` prop and renders a single 'Build an embed' control that discloses the builder PublicPagesPanel already mounts behind `embedOpenState` (PublicPagesPanel.tsx:176/183-187), so the create path and the edit path are the same screen. Separately, DELETE /api/v1/embeds/:id exists (src/routes/api/embeds.ts:239) with no caller anywhere in app/src — a saved embed can be turned off forever but never removed, so the list grows monotonically. The row gains a Delete action behind the shared ConfirmDialog (DEC-631 contract), naming the embed and stating the same consequence the panel footer already states — an embed is live HTML on somebody else's site, so removing it breaks that site and cannot be undone.
