# DEC-391: The two mock affordances DEC-380 and DEC-386 dropped are settled, not deferred

Both were recorded as DROPPED with no owner, which reads as an untracked gap. Verified against the tree, the capability exists by another route in both cases, so there is nothing to schedule. (1) The agenda phone frame's 'move DFC-047 to 11:30' is not missing function: PhoneAgenda.armFromPlaced makes a placed card's own button arm that session, and placeArmedAt then writes the same {day, startMin, endMin, roomId} the desktop drag writes -- arm-then-tap already moves a placed session, and the mock's label was one wording of that gesture, not a second one. (2) The Submissions phone card's per-row Accept/Decline/Read: 'Read' is tapping the row title, which is already a Link to /submissions/:id; Accept/Decline is the bulk bar, whose selection spans pages and sends in batches of 100. Adding per-row status buttons would either give the phone an action the desktop row lacks (against DEC-386's card==row rule) or put decision buttons on every row of a 2,000-row desktop table, which is a change to the highest-traffic admin screen that the desktop mock itself does not make. No future wave reintroduces them; if a producer wants one-tap triage on a phone it is a new product decision with its own optimistic/rollback contract, not a layout follow-up.
