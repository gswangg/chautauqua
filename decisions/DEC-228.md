# DEC-228: CSRF and draft cookies get HttpOnly + conditional Secure via shared builders in src/auth/cookies.ts; the duplicated isSecureRequest helpers are consolidated there

SPEC.md:309 mandates HttpOnly/Secure/SameSite=Lax cookies, but chq_csrf is hand-minted as '<name>=<token>; Path=/; SameSite=Lax' at 7 call sites (src/routes/auth.tsx:51, account.tsx:42, portal/index.tsx:45, portal/edit.tsx:48, portal/profile.tsx:114, portal/tasks.tsx:64, public/submit.tsx:74) and the KV draft cookie at public/submit.tsx:355 likewise lacks flags. Verified safe to harden: no app/src code reads document.cookie or chq_csrf (JSON mutations use the static x-chq-csrf header; HTML forms carry the token as a server-rendered hidden field, compared server-side). Design: add buildCsrfCookie(token, {secure}) (Path=/) and buildDraftCookie(name, token, {secure}) (Path=/submit) to src/auth/cookies.ts, both emitting HttpOnly; SameSite=Lax and appending Secure iff the request is https — matching buildSessionCookie's conditional-Secure behavior so plain-http localhost dev keeps working. Export isSecureRequest(url) from src/auth/cookies.ts and DELETE the duplicated local copies in auth.tsx/account.tsx (no-backcompat house rule); all eight mint sites switch to the builders.
