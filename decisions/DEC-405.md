# DEC-405: No stylesheet hides horizontal overflow at the document level; a region that must be wider than the viewport gets its own scroller

src/views/theme.ts:75 `html, body { max-width: 100%; overflow-x: hidden; }` is the only such rule in the tree and it applies to every SSR surface (public, portal, CFP, login, tools). It does not remove overflow, it makes it unreachable — the exact failure docs/design/README.md's phone pattern calls out for chip strips ('with overflow:hidden the last chip becomes unreachable') — and it silently neuters the gate, which is why the public mobile pass reads a suspiciously perfect 15/15 while the unclipped admin pass reads 3/20. The clip goes; DEC-404's wrap rule replaces its real job. Exposure is bounded: the one legitimately wide public region, the agenda day grid, already sits in `.chq-pub-agenda-day-scroll { overflow-x: auto }` (public.css.ts:150). If the next sweep does surface a newly-honest number on an SSR route, the fix is an `overflow-x: auto` container in that surface's OWN stylesheet in a later wave, named by DEC-401's offender line — never a document-level clip again.
