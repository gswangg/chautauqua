# DEC-932: Every active accepted speaker holds an assignment for EVERY task the event owns: activation BACK-FILLS, it never snapshots

createTask (src/server/repo/tasks/crud.ts, DEC-746) expands a new task to every accepted speaker AT CREATION TIME and there is no opt-out -- but the only other assigner in the product, planAndPersistOnboardingTasks (src/server/repo/submissions/status.ts), plans exclusively the five DEFAULT_ONBOARDING_TASKS templates through the pure planAcceptance (src/domain/acceptance.ts:155). So a contact who becomes an active accepted participant AFTER a custom task was created -- via bulk accept, via a co-presenter invite, or via the Speakers participation menu flipping 'invited' to 'accepted', all three of which already call ensureOnboardingTasks -- never receives that task: the Speakers grid renders their row with a permanently blank cell in that column, their portal never lists it, the reminder cron never chases it, and no UI can assign it (the SPA calls neither PATCH nor POST on /tasks/:id/assign). This is the SPK grader's "task assignment misses portal-linked rows" defect, and it is a data invariant, not a rendering nit. Rule: planAndPersistOnboardingTasks gains a SECOND pass, after the template pass and inside the same call, enforcing the invariant "an active accepted participant of this event holds a task_assignment for every task row the event owns" -- ONE select of the event's task ids, ONE chunked select of the existing (task_id, contact_id) pairs for exactly those contact ids, ONE chunked insert with onConflictDoNothing on the (task_id, contact_id) uniqueIndex (DEC-556). Never a query per contact and never a query per task. An existing assignment row is NEVER touched (a completed one stays complete) and none is ever deleted; the planned write count is checked against DEC-528's MAX_TASK_ASSIGNMENT_WRITES before the first insert and refused loudly if it exceeds it. The narrower ACTIVE_INVITE_STATUSES gate (DEC-278/283) is unchanged -- an 'invited' or 'declined' participant is still not chased.
