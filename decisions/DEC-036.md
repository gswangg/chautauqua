# DEC-036: Form window semantics: open_date enforced via formWindowState

form.open_date is persisted (migration 0003) but never checked, so a CFP silently accepts submissions before it opens — a contract violation of the form-window input class. Canonical helper in src/lib/submit-core.ts: formWindowState(openDate, closeDate, now) -> 'not_yet_open' | 'open' | 'closed'; null openDate = open immediately, null closeDate = never closes. Public GET renders an 'opens on <date>' page and POST/save-draft reject server-side unless state is 'open'. isFormClosed stays exported unchanged — other modules (portal edit lock) key off it and must not churn.
