# DEC-408: Public dates render in the event's own timezone, never UTC; one pure helper, and it throws rather than falling back

src/routes/public/submit.tsx renders every date with Date.toUTCString() — :247 the open CFP deadline, :161 the closed-window line, :176 the not-yet-open line, :186 the draft banner — so a Pacific submitter reads "closes Mon, 01 Mar 2027 23:59:00 GMT" for a deadline the producer set in America/Los_Angeles. J2's bar is that the speaker "sees event branding + deadline", and the mock states it as "closes Sun 16 Aug, 23:59 Pacific". The event row already carries a validated IANA timezone (src/db/schema.ts:111, isValidTimezone at src/routes/api/validators.ts:21) and the public event repo already exposes it (src/server/repo/public/event.ts:16), so nothing new is stored. One pure helper, src/lib/event-time.ts `formatEventDateTime(ms, timeZone)` — Web APIs only, no node:/cloudflare: import (DEC-002) — formats via Intl.DateTimeFormat('en-US', {timeZone, weekday:'short', day:'2-digit', month:'short', year:'numeric', hour:'2-digit', minute:'2-digit', hour12:false, timeZoneName:'short'}). House style applies to the failure mode too: an empty or invalid timeZone throws, it does not quietly render UTC — a silently-wrong deadline is worse than a loud 500 on a misconfigured event. The header keeps the literal word "closes", which is what DEC-407 pins the walkthrough to; the two decisions are the two halves of one contract.
