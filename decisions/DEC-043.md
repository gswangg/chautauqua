# DEC-043: Org user directory + reviewer provisioning API (/api/v1/users)

J4 requires a producer to assign reviewers without knowing raw user ids, and stage 1 has no inbox for invite links. New organizer-only endpoints: GET /api/v1/users (org-scoped, optional ?role= filter, standard list envelope) and POST /api/v1/users {email, role in ('reviewer','organizer')} which generates a random password (crypto.getRandomValues, format xxxx-xxxx-xxxx from the base32 id alphabet), hashes via src/auth/password hashPassword, returns {id,email,role,password} exactly once (201), and logs a text-only welcome email through the mailer port (html via textToHtml only, per DEC-037). Duplicate email throws ApiError('conflict'). Lives in src/routes/api/users.ts + src/server/repo/users.ts, mounted only in src/index.ts.
