# DEC-807: The event switcher is one quiet control

USER-REPORTED and VERIFIED at app/src/components/event-switcher.css:27-37: .chq-eventswitcher-menu-btn carries `border: 1px solid var(--chq-border)` at rest beside .chq-eventswitcher-name, which is plain text — so the header reads as a label with a small outlined box glued to it rather than as one control you can press. The affordance grammar in the mandate is explicit: quiet controls take their border on hover/open, not at rest. Decision: the current event name and its caret are one control — the name is inside the button (or the button is visually seamless with it), the resting state has no border, and hover/open take the surface-sunk background and the border. Nothing about the menu's semantics, aria wiring or eventSwitcherState logic changes; this is chrome fidelity, and chrome fidelity never deletes a capability.
