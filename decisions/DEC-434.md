# DEC-434: One dev-mode predicate: DEV_MODE === "1" and nothing else, spelled once

src/server/context.ts:51 selects the real mailer on `env?.EMAIL && !env.DEV_MODE` -- truthiness -- while every other dev gate requires the exact string: src/routes/dev/mailbox.tsx:24 and src/server/origin.ts:97 both test `=== "1"`. The divergence has a concrete failure: DEV_MODE="0" is falsy-for-one-gate and not-"1"-for-the-others, so a deployment set that way silently picks DevSinkMailer (every row written status:sent, provider:dev) while /dev/mailbox correctly 404s -- nothing is delivered and nothing surfaces the failure, against docs/clarifications.md:31 ("emails must actually send on an MVP basis"). The remedy is a single exported isDevMode(env) in src/server/env.ts that all three call sites delegate to; "1" is the only dev-mode value. Deliberately NOT added: a throw for "not dev mode and no EMAIL binding". Route tests construct env fixtures without DEV_MODE and must keep receiving the dev sink; introducing a new failure mode in the same change would convert a predicate bug into a hundred red tests and obscure whether the predicate fix worked. The defect is the divergence, not the sink default.
