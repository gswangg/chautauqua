# DEC-395: A reviewer session never requests organizer-only aggregates: the nav-badge hook gates on role, not on catch()

app/src/lib/useNavExceptions.ts:35 fetches GET /events/:eventId/overview unconditionally for every authenticated admin-shell role, but src/routes/api/overview.ts mounts it behind requireOrganizer, so a reviewer gets a correct 403 on every /admin/review* page load. The hook's .catch() keeps React quiet, but the browser still logs a failed-resource console error, and the render sweep's zero-console-error criterion is what turned all three reviewer routes FAIL in the w4-j log -- a self-inflicted red that hides real ones. Swallowing an expected 403 is also the fallback-shaped code the house rule warns about: the honest statement is 'this data is organizer data', not 'this request might fail'. Rule: the hook reads useMe() and issues no request unless the resolved role is 'organizer'; while me is still loading it issues none either; a reviewer's exceptions are {late:null, clash:null} by construction, which is already what the nav renders as 'no badge'. The endpoint's authz does not change -- the client stops asking for what it may not have.
