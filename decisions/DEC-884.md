# DEC-884: The portal header prints the EVENT's name as the event writes it: "chautauqua" is the only lowercase wordmark, and the tagline leaves the header

src/routes/portal/shared.tsx:76 wraps branding.eventName in .chq-wordmark, whose src/views/theme.ts:294 `text-transform: lowercase` exists for the literal product wordmark on the three operator surfaces (GET /, /docs/api, dev mailbox — see src/routes/tools.css.ts). The consequence is that every speaker portal page renames the customer's event to "devflow conf 2027". A shared class is shareable only where every member wants every DECLARATION: the event identity wants the wordmark's family/size/weight/tracking and not its casing, so it gets its own .chq-eventmark in THEME_CSS with no transform, and .chq-wordmark keeps lowercase for the operator surfaces that mean it. Separately the v5 portal frames carry no tagline in the header — identity shares that line with the speaker's name — so PortalLayout's showTagline prop and its single opt-in call site are DELETED rather than defaulted off (a prop with one caller is a setting nobody sets; DEC-777's header placement is superseded by the frame). The organizer-authored welcome note is real content, not chrome: it renders as the first body block of /portal's <main>, and Settings still edits it.
