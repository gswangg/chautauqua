# DEC-267: Every FK column is indexed, enforced by a schema tripwire test (closes all three spec-audit open items)

SPEC section 7 says 'D1 indexes on every FK' without qualification; task-w2-e found five attribution FK columns with no index (uploaded_by_contact_id, author_contact_id, author_user_id, created_by_user_id, editor_user_id) and no decision authorizing the exception. Rather than re-auditing this every wave, the rule becomes self-enforcing: a new test/schema-fk-indexes.test.ts walks every exported table via drizzle's getTableConfig, and for every column whose SQL name ends in '_id' and is not the primary key asserts that some index on that table has it as its FIRST column; any deliberate exception must be an explicit entry in an EXCEPTIONS map with a written reason, so silence is never the default. The missing indexes are added to src/db/schema.ts plus migrations/0016_w4c2_fk_indexes.sql - 0015 is RESERVED for wave-3's DEC-258 participant-attribution migration so the two waves cannot collide on a filename (a collision here would break the fresh-clone bootstrap, which is the one gate that catches it). The other two spec-audit open items are closed by inspection, not code: prefetch-on-hover/focus EXISTS at app/src/App.tsx:50-54 and 78-95 (pageLoaders + prefetchByPath + onMouseEnter/onFocus on every nav link), and SPEC's '(event_id, slug)' composite is satisfied by the event.slug index given the actual schema shape - event has no event_id column.
