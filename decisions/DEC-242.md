# DEC-242: Speaker deliverable self-service: completed file_request tasks show the current file, a replace-file form, and the file's comment thread in /portal/tasks

CNT-05 requires the feedback loop in both roles, and the P3 'completed task collapses to plain text' means a speaker cannot even see their own upload without an organizer flipping status. The portal tasks SSR page renders, for a completed file_request assignment: the current filename linking through the existing authenticated file route, a replace form posting to the same upload endpoint (which chains versions per DEC-240), and the file_comment thread (read + reply) gated by the existing canAccessTaskFile scope so speakers only ever reach their own threads. The organizer side of the same thread is the existing DeliverableDetail CommentThread once DEC-240 links the file to a submission — one table, two views, no parallel comment system.
