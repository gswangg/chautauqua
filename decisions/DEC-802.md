# DEC-802: A merge preview reads BOTH records, names the record it discards, and strikes only what is really thrown away

VERIFIED src/domain/contacts.ts:386 — previewMerge's custom-field loop iterates `duplicate.customFields` only, so a label that exists solely on the KEPT record never appears in the preview at all, and MergePage.tsx:238 builds its Labels row from that same one-sided list. VERIFIED MergePage.tsx:204 heads the third column with the literal word 'Discard' though the page knows the discarded record's name, and :226 renders a blank duplicate-side value as an em dash inside the struck 'drop' class — telling the organiser something was thrown away when that record simply never had the field. Merge is irreversible, so every one of these is a lie told at the worst moment. Decision: labels and notes are COMBINED, not chosen (docs/design/README.md), so their preview rows are computed over the UNION of both records' keys and shown as the combined keep value; the compare table's third column is headed by the discarded record's own name (or 'N other records' for a 3+ group); a struck value means a real value was dropped, and an absent one renders a plain em dash with no strike (DEC-748's row still appears — it is the styling that stops lying); and the page states the consequence before the button, 'N submissions and M tasks move to <keeper>', counted server-side in the same preview response, because the thing that actually moves is history, not fields.
