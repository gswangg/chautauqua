# DEC-334: Card numbers are SQL aggregates, never materialized rows: the overview comms card is one COUNT/MAX query and aggregateCommsCounts is deleted

src/server/repo/overview.ts loads every email_log row for the event (:199-206) purely to produce two integers, then computes lastSentAt with Math.max(...sentTimestamps) at :78 — an unbounded argument spread that throws RangeError once the argument count reaches V8's stack limit, and an O(all rows) read of the fastest-growing table in the product (per-recipient logging plus the 15-minute reminder cron) long before that. DEC-030 makes this the producer's FIRST screen, and SPEC §7 puts admin reads at p95 < 50 ms with 'one round trip per view'. Rule: any overview/dashboard number that is a count, max, min or sum is computed by a SQL aggregate over an indexed predicate; the repo never pulls rows to reduce them in JS. email_log.sent_at is integer timestamp_ms (the former src/db/schema.ts:730 (now split across src/db/schema/)), so the 7-day cutoff is bound as a raw number, never a Date. aggregateCommsCounts and its describe block are DELETED rather than left as a dead pure helper (house rule: no back-compat shims); the other pure helpers in that module keep their tests because they still reduce genuinely row-shaped data.
