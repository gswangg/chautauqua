# DEC-711: The contacts directory is a table plus a rail, and every figure the page states is endpoint-backed

The rail (Where they work / Saved segments / Possible duplicates) is what makes Contacts a CRM rather than a list -- the user calls it the core of the design, and prod currently ships a KPI trio and a full-width companies block instead. Rebuilding it as the mock's 1.5fr/1fr grid also forces an honesty question, because the mock's summary reads '318 people · 41 speakers · 6 possible duplicates' and the rail states a count per company, per segment and for duplicates. Rather than illustrate those numbers, each becomes a real aggregate: the stats endpoint gains speakerCount and duplicateCount, and the segments list gains a count computed with the SAME segment-rule where clause the directory list uses. DEC-377 stands: a number the API cannot produce does not appear.
