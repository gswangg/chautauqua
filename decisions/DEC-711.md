# DEC-711: The contacts directory is a table plus a rail, and every figure the page states is endpoint-backed

The rail (Where they work / Saved segments / Possible duplicates) is what makes Contacts a CRM rather than a list -- the user calls it the core of the design, and prod currently ships a KPI trio and a full-width companies block instead. Rebuilding it as the mock's 1.5fr/1fr grid also forces an honesty question, because the mock's summary reads '318 people · 41 speakers · 6 possible duplicates' and the rail states a count per company, per segment and for duplicates. Rather than illustrate those numbers, each becomes a real aggregate: the stats endpoint gains speakerCount and duplicateCount, and the segments list gains a count computed with the SAME segment-rule where clause the directory list uses. DEC-377 stands: a number the API cannot produce does not appear.

## Amendment (wave 4): the directory header states THREE clauses, orders its actions Import / Export / New, and the pager states the matching count on the left

The contacts header prints five clauses (including a "0 returning speakers" that reads as a defect) and orders Export before Import; the pager splits "Showing 1-25 of 39" between its arrows. DEC-711 already binds every figure to an endpoint; this amendment binds the GRAMMAR: three clauses (people, speakers, possible duplicates), Import/Export/New order, count left and Previous/Next together right. Same amendment covers the two other statements the row makes about itself: the search input must be wide enough to render its own placeholder, and the filter-rules row must state "N of M match" and offer "Save as a segment" (DEC-868 promised the count; the row never printed it).

## Amendment (wave 33): every figure a stats endpoint COMPUTES must have a rendering consumer — a number calculated for nobody is a hot-route tax, not harmless dead weight

DEC-711 bought the forward direction: every figure the Contacts directory STATES is endpoint-backed. The converse has drifted. getContactStats (src/server/repo/contacts/stats.ts:51-75) runs a count(*) over `event` for eventCount and a GROUP BY/HAVING join across contact -> participant -> submission -> event for returningSpeakers on every Contacts directory load, while app/src/pages/contacts/ContactsApp.tsx:260-263 records that both were dropped from the header and ContactsApp.render.test.tsx:179-185 asserts 'Returning speakers' is not rendered at all. Two multi-table aggregates per page load with zero readers, on a route SPEC §7 budgets at p95 < 50 ms, in a codebase whose house rule is delete-the-old-code rather than leave-a-stub. RULING: dead payload fields are deleted end-to-end (query, interface member, serializer, SPA type, test fixtures) — never left computed 'in case', never re-exported for compatibility — and a source scan binds every remaining ContactStats field to at least one non-test app/src consumer, so the next figure computed for nobody fails the build instead of quietly costing a join forever.

## Amendment (wave 40): the Duplicates tab states the envelope's total and can reach every group it counts

DEC-711 made every figure the contacts directory states endpoint-backed, and the header's duplicate count comes from GET /contacts/stats' duplicateCount (server-computed over the whole org). The Duplicates TAB then states a second, different number from its own page: app/src/pages/contacts/DuplicatesView.tsx:54 fetches `/contacts/duplicates` with no perPage (server clamps to listPerPage's 200, src/routes/api/contacts/crud.ts:196-201 pages a materialized array and reports the TRUE total in the envelope) and line 92 renders `· {visibleGroups.length}` — the page's length. Past 200 groups the tab contradicts the header it sits under, and worse, groups 201+ have no pager and no link, so they can never be opened or merged at all: an org accumulates duplicates it is told about and cannot act on. RULING: the tab requests an explicit perPage, keeps the envelope's `total`, states `total` minus the pairs dismissed in this session (a dismissal removes exactly one real group server-side, DEC-770), and carries the DEC-845 "Showing X of N · Show all N" affordance that pages the remainder in, so every counted group is reachable. The rail preview's bounded fetch (ContactsApp.tsx:223) is unchanged — it is a preview by construction and says so.
