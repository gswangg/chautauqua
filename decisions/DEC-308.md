# DEC-308: The drizzle-orm advisory is fixed by upgrading to ^0.45.2, not accepted; drizzle-kit and drizzle.config.ts are DELETED

DEC-302 already ruled that a devDependency-only advisory is accepted for stage 1 but an advisory affecting a PRODUCTION dependency is a red that fails the section. drizzle-orm is one of exactly two packages in the Worker bundle, so GHSA-gpj5-g38j-94v9 (SQL injection via improperly escaped SQL identifiers) is squarely a red. The tempting alternative — declare it non-exploitable because the repo never passes user input as a SQL identifier — is precisely the self-declared scope narrowing a reviewer flagged in the w7-c gate log and that DEC-302 exists to forbid; a claim like that would have to be re-audited on every future dependency change, whereas an upgrade is verifiable by one command. Target `drizzle-orm@^0.45.2` (the advisory's fixed line). While the lockfile is open, delete drizzle-kit and drizzle.config.ts: DEC-263 already deleted the `db:generate` script, README.md:49-53 explicitly forbids running `drizzle-kit generate` against the stale meta/ snapshot chain, and test/migration-parity.test.ts is the actual guard — so the package's only remaining effect is audit surface and a foot-gun. House rule is delete, not deprecate. Acceptance is mechanical: `npm audit --omit=dev` prints 'found 0 vulnerabilities', and `npm run build` + `npm test` stay green with no compatibility shims.
