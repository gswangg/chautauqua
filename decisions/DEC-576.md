# DEC-576: ONE shell owns chrome geometry: non-scrolling header, flex:1/min-height:0 scrolling body, in-flow phone tab bar; header is a single row with the event as text and the user as initials

The phone tab bar is position:fixed and .chq-main compensates with a guessed 84px of bottom padding, which fails on every page family that scrolls its own region or ends in a control (Settings sections, Content files pagination, Submissions detail and form builder all clip). The README's pattern removes the guess: .chq-shell is a flex column, header and tab bar are flex-shrink:0 in-flow regions, .chq-main is flex:1; min-height:0; overflow-y:auto, and content can never sit under the bar because the bar is not over it. Same file, same wave, the desktop header collapses to the designed single row (.chq-header currently flex-wraps into two bands at content width): wordmark · nav · event name as PLAIN TEXT with a menu button (not the raw <select> EventSwitcher renders) · user as "J. ALVAREZ · SIGN OUT" in 11px/700/0.1em uppercase. That needs a human name, so GET /api/v1/me gains `name: string|null` from the signed-in user's linked contact, with the email local-part as the fallback — the header must never render a bare email or the word "undefined".


## Amendment (wave 13) — a shell region's position is its DOM order, not its border: the phone tab bar is the LAST child of .chq-shell

docs/design/README.md's "Phone pattern" specifies three regions — fixed header, flex:1/min-height:0/overflow-y:auto body, fixed footer — and a "Five-item bottom tab bar". Verified on main: Header() in app/src/App.tsx returns a fragment of <header class="chq-header">, then <nav class="chq-tabbar">, then the More sheet, and App() renders <Header/> before <main class="chq-main">. .chq-shell is display:flex/flex-direction:column and app/src/styles.css contains NO `order:` declaration anywhere, so at <=700px the tab bar paints directly under the header — a TOP bar. Its own rule already declares `border-top: 1px solid var(--chq-ink)`, which is the bottom-bar intent written down and contradicted by the markup. RULING: the tab bar's position is settled in the DOM, not by CSS order and not by a border: .chq-shell renders header, then the scrolling main, then the phone tab bar, in that order. DEC-576's existing contract (in-flow, never position:fixed, .chq-main the only scrolling region) is unchanged — only the region order is fixed, and the invariant becomes executable as a DOM-order assertion rather than a declaration read.
