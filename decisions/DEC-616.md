# DEC-616: The contact drawer is a record, not a form: labelled facts, one history section, one action bar

docs/design/Chautauqua Contacts.dc.html §'Contact · drawer' specifies an identity header (name at display size, 'Company · Title', Close), label→value rows on a 130px/1fr grid with uppercase labels, an 'Across your events' section fed by the history the API already returns on GET /contacts/:id, and a single bottom action bar Save · Email · Add to event. Editing stays in place — we do not add a second edit surface — but the default reading is a record. The field list is derived from the same ContactDetail the table row uses, because two renderings of one person must not disagree about which facts they have.

## Amendment (wave 4): the drawer shows the facts it HAS -- empty rows sit behind one disclosure, and the reserved travel key is labelled DIETARY

The record drawer renders 17 field rows, nine of them '-', in a 418px box (frame: 520px, five populated rows). A record that prints nine empty facts buries the four that matter and is the reason the drawer feels overstuffed. Ruling: populated rows render; the empties collapse behind ONE 'Show all fields' disclosure inside the record section; the reserved travel custom-field row is labelled DIETARY (the word the frame and the speaker-facing form use); action-bar buttons never wrap. The record-row grid template (`minmax(0,1fr)` + `width:100%`) and the headshot field rules are untouched -- that is the orchestrator's landed overflow fix (9ba85315) and re-litigating it re-opens a BROKEN.

## Amendment (wave 4)

Implemented verbatim: `.chq-drawer` is 520px (`app/src/styles.css`); each fixed field plus every custom-field row is now a `{key, hasValue, node}` record entry in `ContactDrawer.tsx`, filtered to populated rows (or the row currently being edited, so a freshly added blank custom field or a value the reader just cleared doesn't vanish mid-edit) unless the reader has expanded the section. The hidden count renders on the single `.chq-contacts-show-all` disclosure ("Show all fields (N hidden)" / "Show fewer fields" to collapse back). The reserved travel custom field's row label is now "Dietary" (its storage key stays `travel_logistics` — `src/domain/contact-labels.ts`'s `TRAVEL_KEY` is unchanged, and `customFields.ts`'s reserved-key error message still reads "Travel & logistics field above", which is now stale text outside this task's file list — flagged, not fixed here). `.chq-contacts-drawer-actions` is `flex-wrap: nowrap` with `white-space: nowrap; flex-shrink: 0` on each button, and `overflow-x: auto` on the bar itself so a tight viewport scrolls the action bar in its own box rather than wrapping a button's label or widening the drawer. `.chq-btn-tertiary:focus-visible`'s olive ring (DEC-366) was already in place — no change needed there, only a new render-test lock.

## Amendment (wave 15): the contact drawer's Save is always in view, and the record says how it saves

The drawer is a record whose rows turn into inputs on click and whose ONLY commit control sits after every row, below the fold of a long scrolling panel — the re-measure watched agents scroll and tab hunting for it, and a control you cannot see reads as auto-save. Ruling: the action row is a persistent footer pinned to the drawer's own scroll container, and the record carries one quiet caption naming the mechanism ('Click a row to edit it — nothing is saved until you press Save'). Save semantics are untouched.
