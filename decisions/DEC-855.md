# DEC-855: A submission's tracks live ONLY in submission_track: the frozen scalar is neither written nor read, and a scan enumerates it

VERIFIED on main, and worse than the mandate recorded. scripts/seed.ts:810-814 writes `track_id: null` with the comment 'DEC-017: frozen legacy — never written', and every canonical consumer (public/detail.ts:125-133, exports/*.ts, submissions/list.ts:96, review/submissions.ts, agenda.ts:222) reads `submission_track`. But FOUR readers still join `schema.track` on `schema.submission.trackId` — portal/data.ts:229 (the portal submission DETAIL's track, exactly the mandate's 'template renders detail.trackName but the query returns NULL'), portal/sessions.ts:44, portal/submissions.ts:45 and overview.ts:196/374 (the Overview triage row's empty track segment, whose only fix so far was cosmetically dropping the dangling '· ·'). Each returns NULL for every submission in the product. And the Sessionboard importer WRITES that dead column on both paths (import/sessionboard.ts:371 insert, :439 update) and never inserts a submission_track row — so an imported programme's tracks are invisible on the public agenda, in every export, in review track scoping and in the submissions ?trackId= filter, while showing up only in the four broken readers. Decision: submission_track is the single source; `schema.submission.trackId` (and `additionalTrackIdsJson`) may appear nowhere in src/ except the schema definition itself. ONE new helper loads names for a set of submissions ordered by `track.position asc, track.id asc` (the ordering public/detail.ts already uses, so the portal, the Overview and the public site cannot disagree about which track is 'the' track); a single-track slot renders that ordering's first element. The importer resolves trackName to a submission_track row. A scan test fails by file:line on any other reference, because a column half the codebase treats as dead and half still writes is how this survived twelve waves.
