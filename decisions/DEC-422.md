# DEC-422: Free-text caps and the public rate limiter extend to the two write paths DEC-417's scope does not reach

DEC-417 is scoped to 'every admin JSON mutation route'. Two write paths outside that set take unbounded client free text on this tree. (1) POST /submit/:eventSlug/save-draft (src/routes/public/submit.tsx:465-508) is fully public and has NO rate limit at all — unlike POST /submit/:eventSlug in the same file, which has carried the DEC-057/DEC-072 scoped limiter since — and writes extractAnswers' output straight into KV via saveDraft, so an unauthenticated caller buys unmetered KV writes and can push a value past KV's size ceiling into an uncaught 500. SPEC §6 says 'Rate limits on auth + public submission'; a draft save is a public submission write. (2) POST /portal/profile (src/routes/portal/profile.tsx:252-287) writes firstName/lastName/title/company/bio and four social links to `contact` with no length check whatsoever — the identical D1 SQLITE_TOOBIG 500 DEC-417 names, on a speaker-authenticated route DEC-417 will not touch. Rule, stated once: the caps are the ones ALREADY exported from src/forms/validate.ts (MAX_TEXT_LENGTH for single-line values, MAX_LONG_TEXT_LENGTH for bio/long text) so the portal, the public form and the admin API agree on what 'too long' means and no lane invents a third vocabulary; an SSR form post reports oversize by re-rendering ITS OWN page with an error naming the field at HTTP 400 (never a JSON error envelope, never a 500, never a silent truncation); and save-draft takes the same checkAndIncrementScopedLimit the real submit uses, under its own scope, so a draft flood cannot bypass the submit budget.
