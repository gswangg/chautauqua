# DEC-199: User emails are stored lowercase; duplicate detection is case-insensitive

Login (src/routes/auth.tsx:113,144) lowercases the input and exact-matches schema.user.email, but POST /api/v1/users (src/routes/api/users.ts:57) stores the email only trimmed — any account created with a capital letter is permanently unable to log in, and the exact-match duplicate check (src/server/repo/users.ts:50) admits case-variant duplicates that then collide in the lower()=lower() lookups used everywhere else (submit.ts:142, comms.ts:197, contacts.ts:727). Fix at the only offending write boundary: the route normalizes with trim().toLowerCase() before validation; repo createUser asserts the caller passed a lowercase email (fail loudly) and its duplicate check compares lower(column) = input so legacy mixed-case rows also 409. No data migration and no login-side fallback: local DBs are reseedable and the claim path (auth.tsx:265) already lowercases — per house rules, no back-compat shims.
