# DEC-655: A plan_reviewer row selects WITHIN the plan's filtered universe: the per-submission branch intersects plan.filters.trackIds like every other reader, and an out-of-universe assignment is refused at write time

src/server/repo/review/submissions.ts:332-341 returns true on event match alone for an explicit-submissionId assignment, while the unrestricted branch (:317-325), the track branch (:346) and buildPlanScopeConditions (:165-180) all intersect plan.filters.trackIds. A per-submission assignment outside the plan's filters is therefore invisible in the reviewer's queue yet readable via GET /api/v1/review/submissions/:id, scoreable via PUT .../evaluations/:submissionId, and downloadable via reviewerCanAccessSubmissionFile (src/server/repo/files-authz.ts:144 delegates straight to this function) -- and the resulting evaluations are then silently discarded because buildResults reads listPlanFilteredSubmissions. Two readings of "is this in scope" must end in one resolver. The plan's filters define the universe; an assignment picks inside it. A row that could never be scored is refused at POST time with the reason named, not written and quietly ignored.
