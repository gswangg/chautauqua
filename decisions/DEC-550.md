# DEC-550: Every GET route is authz-gated or on a declared public-by-design list, proven by an anonymous probe over the composed app's own route table — not by a markdown inventory

The only authz manifest this codebase has is prose: docs/verification-log/task-w18-d-route-authz-inventory-stage1.md hand-lists 157 routes and 22 "public by design" exceptions. DEC-546 shows what that costs — three of those 22 entries were wrong, and nothing failed. test/route-authz-inventory.test.ts probes three representative rows; test/w10-verify-no-blanket-wildcard.test.ts probes one leak shape. Neither enumerates. This is the standing rule ("hand-listed manifests desync — enumerate in a test"; "glob boundary validators rather than hand-picking call sites") applied to the one manifest where being stale is a data breach. Decision: a new test composes every sub-app src/index.ts mounts, in src/index.ts's exact order and including guardDevMailbox, over a db stub that THROWS on any access and an env of `{}` (DEV_MODE unset, so the dev-mailbox routes correctly 404 and DEC-546's dev-mode-on authz is covered by its own test instead). It enumerates the composed app's own route table, probes every GET with no session, and requires each route to either (a) appear in an exported PUBLIC_BY_DESIGN list carrying a one-line reason, or (b) answer without ever touching the db. The allowlist is asserted EXACT in both directions: an unmatched entry is as much a failure as an ungated route, so a deleted public route cannot leave a permanent hole behind. A route may only be allowlisted if its own source documents it as intentionally no-login (citing its DEC); anything else is reported as a finding, never absorbed.

## Amendment (wave 18): the anonymous authz probe composes from src/index.ts's own source — a hand-typed mount list is not an enumeration

test/anonymous-route-probe.test.ts's header claims it 'composes every sub-app src/index.ts mounts, at the same prefixes, in the same order', and it is the codebase's ONLY exhaustive authz guard. Its buildAnonymousApp (line ~223) is a hand-copied list that omits six of the mounts src/index.ts actually registers — importRoutes, publicSurfacesRoutes, embedsRoutes, breaksRoutes, contentNoteRoutes, mailStatusRoutes (src/index.ts:52,55,57,59,62,63) — so those routes have never been probed while the guard reported green. This is the field guide's 'A GUARD THAT QUIETLY NARROWS IS WORSE THAN NONE' in its purest form, and the fix is the technique this repo already uses elsewhere (DEC-518, reused by test/ssr-link-targets-scan.test.ts): parse every `app.route("<prefix>", <ident>)` out of src/index.ts, resolve the identifier through that file's own imports, dynamically import the module, mount it at the exact prefix. The real exported `app` (src/index.ts:90) cannot be used here because the probe must inject a throwing db through middleware registered BEFORE the routes. RULING: the probe derives its mount list; the parsed-mount count is asserted against a floor so it can never silently narrow again; guardDevMailbox is invoked immediately before the devMailboxRoutes mount, as src/index.ts does.
