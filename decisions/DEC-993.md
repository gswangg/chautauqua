# DEC-993: One 'Insert a field' control per composer, and the merge-field sample values live beside the vocabulary they describe

Six bordered chips under a body field read as six competing buttons, and the compose wizard and the template editor each render their own row of them (ComposeWizard.tsx:584, TemplatesTab.tsx:216) from COMPOSE_MERGE_FIELDS. v6 replaces both with a single "Insert a field ▾" control whose open state lists each token beside a sample value, so a writer can tell {task_list} from {feedback} without sending a test email. The sample values are part of the merge-field vocabulary, not of either screen, so they live in src/mail/render.ts next to COMPOSE_MERGE_FIELDS/BLOCK_MERGE_FIELDS and reach the SPA through app/src/lib/merge-fields.ts — the ONE module DEC-660 allows to cross the app/→src/ boundary for this vocabulary. Typing the samples as a Record over MergeField makes a missing sample a compile error, so the vocabulary and its examples can never drift. The existing constraints are unchanged and still enforced by the control: DEC-847 keeps task_list/feedback out of the subject picker, and the feedback token stays conditional on the event having plans.

## Amendment (wave 19): a select caret is an element with its own class at the control's right edge, never the last glyph of the label -- and the disclosure toggle is a named exemption

DESIGN-RULINGS.md B8 fixes the caret: "always sits at the right edge of the control in muted ink (#565A4B), never as the last glyph of the label", with a 6px gap for a content-width control -- and the vendored frames render it that way everywhere (e.g. docs/design/Chautauqua Speakers.dc.html:68-70, :91 all use `<span style="color:#565A4B; padding-left:6px">▾</span>`). app/src/components/EventSwitcher.tsx:237 already complies via `.chq-eventswitcher-caret`. Two sites do not: app/src/pages/comms/InsertFieldMenu.tsx:35 and app/src/pages/speakers/ParticipationMenu.tsx:98 both emit `{label} <span aria-hidden="true">▾</span>`, where the caret is a bare glyph separated by a literal space text node, inheriting the label's ink and weight. This is unguarded prose today, so it drifts back; the amendment makes it a scanned contract. The leading disclosure toggles (`{expanded ? '▾' : '▸'} {count}` at app/src/pages/review/ResultsTable.tsx:446 and app/src/pages/submissions/SubmissionDetailPage.tsx:1171) are a DIFFERENT affordance -- a caret that PRECEDES its label is a disclosure, not a select -- and are exempted by name with that reason, in the repo's existing allowlist idiom.
