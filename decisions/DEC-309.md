# DEC-309: Perf grading gets SPEC §7 route classes measured against a /health overhead floor; schedule.ics is class `public`, not an admin read

Section c's OPEN ITEM (schedule.ics 51.9ms vs 50ms) compares two different quantities, and the harness already says so: scripts/perf-smoke-lib.ts:5-8 documents that SPEC's 50ms is SERVER time while the local probe measures wall-clock HTTP, which is why DEC-034 set a flat 150ms. Neither 'it missed by 1.9ms' nor 'the flat 150ms covers it' is knowable under the current instrument — the ambiguity IS the defect, and the fix is to instrument rather than argue. perf-smoke will measure a per-run client/transport overhead floor (p50 of 30 `GET /health` samples, a no-DB route) and grade `adjusted = max(0, rawP95 - floor)` against SPEC §7's own three numbers by declared route class — read 50ms, write 100ms, public 150ms — while KEEPING the raw 150ms figure as a second unconditional ceiling, so the gate can only get stricter, never looser. Class assignment is a planner decision so no worker re-litigates it: `/e/:slug/schedule.ics` is registered on publicRoutes at src/routes/public/index.tsx:182 and is unauthenticated with public cache headers, so by SPEC's own taxonomy it is a public response (150ms), not an admin read (50ms) — section c graded it as an 'admin read (export path)' by analogy, and the analogy is wrong. This closes the OPEN ITEM on classification, which would be a dodge on its own; DEC-310 pairs it with the real algorithmic defect the probe was circling.
