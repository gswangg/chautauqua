# DEC-940: The participation trigger resets ONLY what a chip cannot inherit, and the test asserts the chip, not the reset

Third collision on this rule, and this time a test is holding the defect in place. `.chq-participation-menu-trigger` (speakers.css:216) declares `appearance:none; background:none; padding:0; font:inherit; cursor:pointer` and lands textually AFTER the four `.chq-speakers-status-*` modifiers at equal specificity, on a button that carries BOTH class families (ParticipationMenu.tsx:58). `background:none` erases `.chq-speakers-status-complete`'s `background: var(--chq-brand)`, leaving light `--chq-on-brand` text on paper — the CONFIRMED pill is invisible on every seeded row, which is what burned agent turns at the gate SHA. `padding:0` erases the shared `3px 8px` box on all four states and `font:inherit` erases the shared 11px/700. DEC-880 fixed only `border:none` and app/src/pages/speakers/speakers-css.test.ts now REQUIRES the three surviving resets by name — a regression test that asserts the bug. Rule: the reset is exactly `appearance: none; cursor: pointer;` and nothing more — the trigger may never reset a property the chip family declares; `.chq-speakers-status` additionally declares `font-family: var(--chq-font-ui)` so the chip never inherits the UA button face (DEC-937's face rule, applied to a class that is not named `-btn`); and speakers-css.test.ts is rewritten to assert the OUTCOME for each of the four states — the fill, box and type the chip needs are the ones that survive the cascade — instead of asserting the reset's contents. A test that pins an implementation detail one lane owns is how the same pixel breaks three times.
