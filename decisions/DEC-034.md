# DEC-034: CI (typecheck + tests) plus a 2k-row perf harness that boots wrangler dev locally — budgets enforced, zero secrets

SPEC §7: 'budgets that aren't enforced are decoration', measured at scale-target row counts, and §8 requires CI typecheck + unit tests; all of it runs secret-free on Miniflare so it is stage-1 scope. scripts/perf-seed.ts (tsx) writes .perf-seed.sql: one synthetic event (fixed id seed_perf_event, slug perf-2k) with 2,000 submissions, participants/contacts, submission_track rows, and answers, reusing scripts/seed-lib.ts helpers with a distinct seed_perf_ id namespace so the demo seed is untouched; applied via wrangler d1 execute like the existing seed. scripts/perf-smoke.ts logs in as the seeded organizer against PERF_URL (default http://localhost:8787), runs 30 warm iterations each of: submissions list page 1, submissions list with q= search, submission detail, and /api/v1/events/:id/overview if present, reports a p95 table, and exits nonzero over budget — 150 ms p95 local-HTTP threshold (the 50 ms SPEC budget is server time; localhost adds client overhead, and 150 ms local still catches N+1s and full scans at 2k rows). npm scripts: perf:seed, perf:smoke. .github/workflows/ci.yml: npm ci, npm run build (tsc + vite), npm test; a second job applies migrations, seeds perf, starts wrangler dev in the background, waits on /health, runs perf:smoke. No deploy, no secrets — stage 2 owns deployment CI.

## Amendment (wave 51): the perf smoke's write coverage is ENUMERATED from SPEC §7's named actions, never sampled

SPEC §7 names four high-frequency actions that must render optimistically and reconcile -- drag-drop placement, status pills, task check-offs, ratings -- and scripts/perf-smoke.ts measures exactly one of them (the rating PUT). SPEC's own 'budgets that aren't enforced are decoration' applies to the LIST of measured endpoints as much as to the numbers: the bulk status change (POST /events/:id/submissions/status) is the most N+1-prone mutation in the product at J3's 2,000-row triage scale and nothing measures it; PUT /submissions/:id/slot and PATCH /task-assignments/:id are likewise unmeasured. Rule: every action SPEC §7 names carries a cls:"write" check against the 2k-row perf profile, and each probe is written to be REPEATABLE -- it toggles between two equally valid states rather than advancing a lifecycle -- so a smoke run never changes the seed's shape and never triggers the J6 acceptance expansion (which would measure a different thing every iteration).
