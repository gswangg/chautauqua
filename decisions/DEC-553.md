# DEC-553: Public read surfaces send Access-Control-Allow-Origin: * ; the cookie-authenticated /api/v1 never does

The organizer-side embed builder (app/src/pages/settings/embedSnippet.ts:12) offers four output formats, of which "json" resolves to /embed/:slug/:surface.json and whose "snippet" is the bare URL — "nothing to embed inline, just a link to fetch" (buildSnippet:93-95). There is not one Access-Control-* header anywhere in src/. A browser on ai.engineer therefore cannot fetch that feed at all: the one surface whose entire purpose is cross-origin consumption is blocked by the same-origin policy. That contradicts J10 ("Embed generator produces copyable iframe/snippet per surface"), the technical-teammate job ("Wants the data to flow outward"), J12's no-lock-in premise, and EMB-15's manual bar ("fetch each endpoint and confirm the JSON contains session/speaker data"). These routes are already anonymous, already unauthenticated, already edge-cached, and already deliberately frameable (DEC-022: "No frame-blocking headers are ever set in this file") — a wildcard ACAO grants a scripted reader exactly the bytes an <iframe> already renders, so it adds no disclosure.

Decision: (a) the ONE shared helper every public handler already calls, setCacheHeaders (src/routes/public/shell.tsx:25-27), also sets `Access-Control-Allow-Origin: *`. Because it runs before the response is built, the header is on the copy publicCacheMiddleware stores in caches.default, so cache HITS carry it too — no second, order-sensitive middleware. (b) The Cache-Control string at shell.tsx:26 is NOT touched: pubcache.ts:56 requires it stay byte-identical. (c) Scope is exactly the /e/* and /embed/* surfaces this helper serves — HTML, the .json feeds, and both .ics routes. /api/v1 is deliberately excluded and stays same-origin-only: it is cookie-authenticated, and a wildcard ACAO there would be both useless (credentials are forbidden with "*") and an invitation to widen it wrongly later. (d) No OPTIONS handler, no Access-Control-Allow-Credentials, no Access-Control-Allow-Headers: a plain cross-origin GET with no custom request headers is a CORS "simple request" and never preflights, so anything more is unearned attack surface.
