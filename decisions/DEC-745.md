# DEC-745: The plan editor is the v4 shell: the plan's NAME is the page title, Duplicate + Save sit on the title row, rounds are waves not a field, and the anonymise switch moves into "Who reviews what"

docs/design/Chautauqua Review.dc.html:251-327 draws the whole screen: back-link + plan name as the 27px title, Duplicate and Save on that row, a 2x2 field grid (Opens / Closes / Reviews per talk / Rating scale + "Applies to every criterion in this plan"), the criteria section that already landed, and a section headed "Who reviews what" whose rule carries "Assign a reviewer", whose rows read name/email · track · "6 talks" · Remove, and which ends with "A reviewer never sees a talk they are recused from." Main still renders a NAME field, INSTRUCTIONS, ROUNDS, an Anonymize checkbox, "Reviewer assignment" and a page-bottom Save/Delete. Two removals would cost capability, so they are redirected rather than deleted: the name becomes the editable title (renaming survives), and ROUNDS goes because POST /plans/:id/waves already exists as "Start a new wave" — a number input that can disagree with the wave action is a second source of truth. Anonymisation is a reviewing rule, so its control moves into "Who reviews what" as one checkbox above the footnote; SPEC's blind review (§5.7, J4) must stay reachable even though the mock omits it. Delete stays a quiet tertiary at the very end of the document, never beside Save.

## Amendment (wave 49)

Plan editor: FIELDS draft behind Save, ACTIONS apply immediately; a dirty editor never navigates away silently. Verified open today: app/src/pages/review/PlanEditor.tsx holds name/dates/criteria AND the anonymize checkbox (:1382-1383) in local `draft` state committed only by `save` (:822/:836), while Assign-a-reviewer/Distribute/Remove/Duplicate fire their own APIs on click; a grep of app/src for `dirty|beforeunload|isDirty` returns only settings/TracksRoomsPanel — there is NO navigation guard anywhere in the SPA. The mandate records this costing a scored critical (an eval agent checked anonymize and never clicked Save; the "critical" was an unsaved draft). Two conventions were on the table; ONE is picked: every FIELD is draft state committed only by Save, every ACTION applies immediately and is labelled with an immediate-effect verb. Anonymize stays a FIELD rather than becoming instant-apply, because it sits inside the same 2x2 field grid as name/dates and an instant toggle inside a field grid is exactly the inconsistency being removed; the DEC-799 ratchet confirm therefore fires at Save time when anonymize goes true->false, not at click time. A dirty editor must block in-app navigation with a confirm that NAMES what is unsaved, and register a beforeunload warning.
