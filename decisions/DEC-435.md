# DEC-435: formatRef is the only place a record ref is built; the Airtable sync's hardcoded SES- prefix is a stage-1 SPEC §5 repair, not stage-2 wiring

src/sync/airtable.ts:169 builds `SES-${String(s.seq).padStart(3,"0")}` instead of formatRef(event.recordPrefix, seq) (src/domain/ids.ts:20-26), so every event whose prefix is not SES pushes a wrong human ref into the customer's base -- a silent violation of SPEC.md:301's "per-event record prefixes (SES-014)" invariant. This is repair of code already in the tree, unit-tested against a fake fetch client, requiring no account, no secret, and no deploy; the sync remains OFF unless AIRTABLE_TOKEN and AIRTABLE_BASE_ID are both set (airtable.ts:112). It is therefore in stage-1 scope in the same sense any other §5 invariant is. Explicitly OUT of scope and left to stage 2: making the sync live, credentials, base/table setup, and the whole-table unscoped SELECT at airtable.ts:114/125 -- paging that read is a volume design that cannot be validated without a real base and a real tick, and the batching to Airtable is already chunked at 10. A guard test pins the invariant so it cannot regress: no padded-ref literal may be constructed anywhere in src/ outside src/domain/ids.ts.
