# DEC-705: A merge preview is the merge function's own output: every field the merge will change, in the words of what it will do

src/domain/contacts.ts:243-302 fills blank primary fields from the duplicate, APPENDS the duplicate's notes behind a '\n\n---\n\n' separator and UNIONS customFields — and app/src/pages/contacts/MergePage.tsx:27 diffs exactly name, email and company, so every field where the merge actually does something surprising is the field the organizer cannot see before committing an irreversible, set-based action. The preview must therefore not be a second implementation of the merge rules (which would drift the moment DEC-266's append rule changes); it is a server endpoint that runs mergeContacts over the real records and reports, per field, the kept value, the discarded values and which rule applied (keep / fill / append / combine). One function decides both the preview and the write, so the screen cannot lie about the outcome.
