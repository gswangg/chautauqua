# DEC-908: Submission detail is the frame's three-and-three: ABSTRACT/FORM ANSWERS/REVIEWS reading left, DECISION/SPEAKER/HISTORY in the rail — editing sinks below the reading order and Meta dies

app/src/pages/submissions/SubmissionDetailPage.tsx renders eight equal-weight sections down one column (Session details, History, Tracks, Format, Participants, Answers, Reviews, Meta) with only Speaker and Decision in the aside, an H1 of '<REF>: <title>' and a position control made of bare chevrons. The frame (docs/design/Chautauqua Submissions.dc.html:207-299) is a different shape entirely: a ref ROW carrying '‹ All submissions', 'DFC-033 · 33 of 47' and TEXT '‹ Previous / Next ›'; an eyebrow naming track and format over an H1 that is the title alone; then exactly three reading sections; then a rail of Decision, Speaker, History. The decision panel itself (DEC-878) and the real history timeline (DEC-892) already landed — what never landed is the ORDER, and order is what makes a detail page readable: an organiser triaging reads abstract, answers, reviews, and decides. Rule: the three frame sections lead the main column in that order; the organiser's editing surfaces (Tracks, Format, Participants) survive intact but collect into ONE trailing SESSION DETAILS section, so no capability is lost and none of it competes with the reading. History moves into the rail on the frame's 96px 'when | what' grid — the grid IS the separator, so the literal ' | ' text goes. Meta is deleted outright: created/updated/accepted are three facts the HISTORY timeline already states, and a page that says the same thing twice drifts. FORM ANSWERS is curated by exclusion, not by a hand-listed allow-list: any answer whose field is a locked built-in (title/abstract/name/email) is rendered elsewhere on this page and must not appear again, and a blank answer is silence, not a row.

## Amendment (wave 41): FORM ANSWERS enumerates the FORM'S FIELDS, not the answers map

buildAnswerRows (app/src/pages/submissions/detailRows.ts:50-69) iterates the stored `answers` object and drops any row whose formatted value is empty, so a question the organiser ASKED and the speaker left blank vanishes from the record — which is why frame 02 shows 'Accessibility needs: None' where the app shows nothing at all. This is the enumerate-vs-sample defect the field guide already names ('rows graded from ENUMERATION never sample'): the FORM ANSWERS block is the record of what was ASKED, so it is graded from the submission's own form field list. Ruling: enumerate the form's non-locked fields in position order, rendering the em dash for one with no stored answer; answer keys with no matching field (a question since deleted) still render after the enumerated set, in raw key order; locked built-ins stay excluded (DEC-908's exclusion 1 is unchanged). This is a READ rule only — DEC-908's write rule ('submitted blank CLEARS, absent key is silence') is untouched.

## Amendment (wave 9) — ONE session-shape display vocabulary in pure-core: src/lib/session-vocabulary.ts, imported by BOTH the SSR public views and the admin SPA

Verified at file:line on main: the parenthetical->comma transform for a session format exists in exactly one place, app/src/pages/review/ReviewerQueue.tsx:27 (`formatMetaLabel`, 'Talk (30 min)' -> 'Talk, 30 min'), and Scorecard.tsx:14 imports it. Three other readers print the same field RAW: app/src/pages/overview/AgendaWorkSection.tsx:151 (`joinSegments([row.speakerName, row.format, row.ref])`), and src/routes/public/cards.tsx:53-56 (`FormatChip`) + :65-78 (`SessionTagLine`), the latter inside `.chq-pub-session-tag` which is `text-transform:uppercase` (src/routes/public/css/cards.css.ts:58) — so a public sessions row prints TALK (30 MIN) where frame 10--00 reads TALK, 30 MIN. Audience level has the same shape with no formatter at all: src/server/repo/review/submissions.ts:716 returns the stored label verbatim by design, the seed writes Title Case (scripts/seed.ts:428 ["Beginner","Intermediate","Advanced"]), and ReviewerQueue.tsx:180/:226 + Scorecard.tsx:385 print it raw, so the queue row reads 'Talk, 30 min · Advanced' where frame 03--03 reads '· advanced'. RULING: the display vocabulary is ONE pure module, src/lib/session-vocabulary.ts, exporting `sessionFormatLabel(raw: string): string` (strip a trailing parenthetical into a comma clause; otherwise verbatim) and `audienceLevelLabel(raw: string): string` (lowercase the stored label; otherwise verbatim). It lives in pure-core rather than being duplicated per bundle because the SPA already imports src/lib/* directly in five places (ReviewerQueue.tsx:21, CallForPapersPanel.tsx:17-18, EventSettingsPanel.tsx:19, SubmissionDetailPage.tsx:8) — the 'app/src cannot reach src/lib' comment in gridMath.ts:65 is falsified by its own line 21. `formatMetaLabel` is DELETED and every call site repointed; no re-export shim (house style). The WIRE contract is untouched: format and audienceLevel still arrive verbatim (DEC-857/DEC-986); only the display layer reformats. This is one decision because two tasks would otherwise each have to answer 'where does the vocabulary live and what is it', which is exactly the question a planner must not delegate.

## Amendment (wave 20): the locked-built-in exclusion is a WIRE rule, not a page rule -- the reviewer scorecard is the second reader that never inherited it

DEC-908 established that FORM ANSWERS skips locked built-in fields (title/description/first_name/last_name/email) because they already have dedicated columns and must never double-render -- and app/src/pages/submissions/detailRows.ts:76,111 enforces it through the ONE lockedFieldName helper (src/forms/types.ts:89). The reviewer surface never got the manners: src/server/repo/review/submissions.ts:754 returns every submission_answer row joined to its form field with no exclusion, src/routes/review/reviewer.ts:282-283 splits them into speakerAnswers/sessionAnswers untouched, and app/src/pages/review/Scorecard.tsx:302 concatenates both into the FORM ANSWERS block. Result: the scorecard's reading column prints the title and abstract, and the FORM ANSWERS block underneath prints them AGAIN as label|value rows (gate-5's "FORM ANSWERS re-prints title/abstract + exposes name/email rows"). Locked answers really are stored -- detailRows.test.ts:85 exercises the per-form-PK spelling `form1:first_name`. Ruling: the exclusion belongs on the wire, in src/routes/review/reviewer.ts, applied through lockedFieldName before the speaker/session split, so a reviewer client cannot render a locked built-in even if it wanted to. Format and audience level are unaffected (they resolve through SESSION_FORMAT_FIELD_ID/AUDIENCE_LEVEL_FIELD_ID, which are not locked names).
