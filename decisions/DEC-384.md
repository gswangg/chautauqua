# DEC-384: The wave-3 render-sweep gate is log-only; its open items become wave-4 tasks, never in-lane patches

The redesign rewrote every rendered surface in the product across two waves and thirteen parallel lanes, and nothing has yet loaded a single one of them in a real browser. The render sweep is the only instrument that sees what unit tests cannot: a console error from a lazy chunk whose CSS import 404s, a 390px page that scrolls sideways because a chip strip lost `flex-shrink: 0`, a control that fell under the 40px tap floor. Following the wave-23 gate convention that already produced six PASS logs on main, this lane owns exactly ONE file — `docs/verification-log/task-w3-i-render-sweep-redesign.md` — and never touches product code or tests, because a gate that patches what it measures reports on itself. It records the exact commands run, the SHA measured, the desktop and 390px PASS/FAIL tables, `RESULT:` and `OPEN ITEMS: N` with one actionable line each. If the sweep cannot run at all (missing Playwright browser, unbuildable bundle) the log says so in those words and reports FAIL — a gate that cannot measure never records a PASS.
