# DEC-893: A number answer is a finite decimal number or it is an error -- never a silent reinterpretation, never a silent blank

src/forms/validate.ts:118-125 rejects only Number.isNaN, so "1e999" -- a value <input type="number"> accepts and submits -- validates as Infinity, and src/server/repo/submit.ts's JSON.stringify then writes null: a REQUIRED answer becomes blank, on the unauthenticated public CFP path, with no error anywhere. The same coercion silently reinterprets "0x1f" as 31 and "  7 " as 7. Number() is a parser for JavaScript literals, not for a form field. Rule: a number answer is accepted only when the submitted string matches a decimal grammar (optional sign, digits, optional fraction, optional decimal exponent) AND Number.isFinite holds on the parse; hex/octal/binary literals and the Infinity/NaN spellings are field errors ('must be a number'), not conversions. Because a validator that admits a non-serializable value is a bug that only surfaces in the database, the persistence path additionally asserts every cleaned answer survives a JSON round-trip before it writes -- fail loudly at the boundary that would otherwise write null.
