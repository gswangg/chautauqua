# DEC-462: Manual session creation is the last unvalidated contact.email write, and DEC-454 covers it: reject at the route with 400, normalize with the one canonical function

DEC-454's rule landed at the public CFP (via validateAnswers), the contacts API and the CSV import, but POST /api/v1/events/:eventId/submissions (src/routes/api/submissions.ts:105-114) still accepts any non-blank string as contact.email, and findOrCreateContact (src/server/repo/submissions/create.ts:46) only does trim().toLowerCase() before inserting it. An organizer creating an invited talk with a typo'd address mints a contact that no portal link, claim token, decision email or bulk send can ever reach, and DEC-456's identity-by-contact_id doesn't help because the address itself is unusable. "Every contact.email write" includes this one. The organizer typed it, so the route answers 400 with fields["contact.email"] (not a conflict, not a silent skip like the CSV importer's per-row skip), and the value stored is normalizeEmail's output so exactly one normalization function exists in the product.
