# DEC-539: No source file may contain a raw control byte, because every invariant in this repo is guarded by a globbed source scan and a file ripgrep calls binary is invisible to all of them

`src/server/repo/exports.ts` contains a literal NUL byte (ripgrep: `binary file matches (found "\0" byte around offset 18895)`), almost certainly written as a composite-map-key separator in `shapeEvaluationsExport` (around the `${r.planId}<NUL>${criterionId}` key at :517), where the sibling expression twelve lines later uses a plain `:`. TypeScript compiles it fine, which is exactly the danger: this codebase's entire correctness strategy since DEC-511 is globbed source-scan tripwires (DEC-518's manifest guard, DEC-523's adversarial route-order test, DEC-527's isEpochMs boundary glob, DEC-528's insert-site glob), and ripgrep skips binary files by default. A file that reads as binary silently exits the population every one of those tests enumerates over -- and exports.ts is precisely a file those tests care about. Decision: (a) the separator becomes an explicit escape or the same `:` its sibling uses -- the file must contain no raw control bytes; (b) a new tripwire globs `src/**/*.{ts,tsx}` and `app/src/**/*.{ts,tsx}` (derived, zero hand-listed paths) and asserts no file contains a byte in 0x00-0x08, 0x0B-0x0C or 0x0E-0x1F, with the rationale in the test's own header so the next reader understands it is protecting the guards, not the compiler.
