# DEC-144: Two permanent render gates: a Playwright chromium route-sweep script (scripts/render-sweep.ts) driven by an authoritative route manifest, plus jsdom+RTL component render smokes with fixture-shaped API mocks; render-sweep becomes a required DEC-069 gate section

Three SPA render crashes passed 898 unit tests and the API walkthrough because nothing ever rendered the SPA against real data — the systemic gap the mandate ranks highest. Layer 1: scripts/render-sweep.ts boots a freshly seeded wrangler dev (port-allocation pattern from the walkthrough gates), drives Playwright chromium (devDependency 'playwright', chromium via npx playwright install chromium — no accounts, no secrets, stage-1 clean), and for every route loads it as the correct persona asserting HTTP 200, non-empty #root (admin SPA) or non-empty main (SSR), and zero console-error/pageerror events. The route list is app/src/routeManifest.ts — a typed array of {path, role, paramsFrom} covering every admin path (including nested Review/Content sub-routes) plus portal and public patterns; a vitest coverage test extracts path="..." literals from app route files and fails on any path missing from the manifest, so new routes cannot dodge the sweep without a compile-visible edit. Runs serially as its own gate lane (never inside parallel worker lanes) and joins the DEC-069 exit battery as a sixth required section per DEC-139. Layer 2: parallel-safe component render smokes — app/src/test-utils/ provides a fetch-mocking harness whose mock payloads mirror the REAL endpoint envelopes ({items,total,page,perPage} lists, the single-object /events/:id/forms shape, nullable date fields); each admin page gets a *.render.test.tsx asserting it mounts without throwing. Workers run these locally as the first-line filter.
