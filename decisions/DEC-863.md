# DEC-863: A speaker name typed into the New submission dialog is never silently dropped, and no placeholder in the product advertises a test-harness identity

VERIFIED, two defects in app/src/pages/submissions/NewSubmissionModal.tsx. (a) Line 75 builds the contact as `trimmedEmail ? { email, ...splitSpeakerName(speakerName) } : null` — so an organizer who types 'Jordan Alvarez' into the Speaker name field and leaves Speaker email blank creates a submission with NO participant at all, and is told nothing. The typed name is discarded on the way to the wire. That is the inverse of DEC-810, which closed the same wound from the other side by refusing to FABRICATE a session title: a field whose value is silently dropped unless a different optional field happens to be filled is a control that lies about what it does. Decision: a non-empty Speaker name with an empty Speaker email is a field-level error on the email row ('Add an email — a speaker record needs one'), rendered through FormRow's existing `error` prop and blocking submit; email-without-name stays legal (an email-only contact is a real record), and both blank stays legal (an unattributed placeholder session is the documented invited-talk case). (b) Line 176's placeholder is `sbek-organizer@example.com` — the eval harness's ORGANIZER login, offered as the example value for a SPEAKER's email, in shipped product chrome. It is the only such leak in app/src or src (demo-identities.ts and README are legitimate). It gets replaced with a neutral example matching the Speaker name placeholder already above it.
