# DEC-322: Speaker social links are a public surface, and every externally-supplied URL passes a pure http/https allowlist before it can become an href

SPEC.md:141 states speakers edit 'bio/social links/headshot and the changes appear on the public site'. Bio and headshot do; social links do not. contact.social_links_json is written by the portal profile form (src/routes/portal/profile.tsx:189-201) and by the admin contact drawer (DEC-152, the former src/routes/api/contacts.ts:213 (now split across src/routes/api/contacts/)), and is read back by exactly two places — the portal's own edit form and the CRM merge helper. No query in src/server/repo/public.ts selects the column and PublicSpeaker/PublicSpeakerDetail have no field for it, so a speaker who fills in LinkedIn sees it nowhere public. Add it to PublicSpeakerDetail only — the drill-in page at /e/:slug/speakers/:contactId — not to the list payload, which is fetched in bulk and does not render links. The security half is the load-bearing part and is why this is a decision rather than a task detail: neither writer validates the URL scheme (both accept any string), so naively emitting href={link} would put a stored `javascript:` payload one click from every public visitor — the first user-supplied href anywhere in this codebase. Gate it with a pure src/domain/contacts.ts helper safeExternalUrl(raw): string | null that trims, parses via URL() inside a try/catch (an external-input boundary, the sanctioned exception to fail-loudly), and returns the href ONLY for protocol http:/https:, null otherwise. A rejected link is dropped entirely — never rendered as inert text, which would just relocate the confusion. Anchors carry rel='noopener noreferrer nofollow' and target='_blank'. Validating at render rather than at write means links already stored by earlier waves are covered without a migration.

## Amendment (wave 30): a brand image source gets its own allowlist (safeImageSrc), applied at both write doors and every read that lifts a stored logo into render props

DEC-322's stated contract is that a non-http(s) URL "can never reach an href/src attribute" (src/domain/contacts-parts/types.ts:10-17), and speaker social links honour it in the repo read (src/server/repo/public/detail.ts:158). branding.logoUrl / portal_settings.logo_url honour nothing: src/routes/api/events.ts:134-141 and src/routes/api/portal-config.ts:100-105 validate type and length only, and the raw stored value is rendered straight into <img src> at src/routes/public/shell.tsx:205, src/routes/public/submit-views.tsx:493 and src/routes/portal/shared.tsx:140 — the same public pages where social links ARE gated. safeExternalUrl itself is the wrong function to reuse (it rejects the root-relative same-origin paths a self-hosted logo legitimately uses), so the ruling is a sibling with its own contract: absolute http(s) via URL parse, OR a root-relative path starting with a single '/', never protocol-relative '//', never any other scheme. Validate on write (fail loudly with a fields error, the DEC-371 normalize-on-write precedent) AND sanitize on read (legacy rows already stored).

## Amendment (wave 78): event.branding_json has ONE parser, it always returns a present object, and it sanitizes at the read

One column, three parsers, two shapes. src/server/repo/events.ts:52-54 declares a module-private toBranding returning EventBranding|null with NO safeImageSrc sanitization; src/routes/public/shell.tsx:109-115 and src/routes/public/submit-views.tsx:45-51 are byte-identical hand-parses that re-declare the shape inline, return {} for absent, and DO sanitize; app/src/pages/settings/EventSettingsPanel.tsx:70 re-declares it a fourth time with a null arm, and three SPA mocks emit branding: null. This is w76's social_links_json and w77's custom_fields_json one table over — a serializer without a parser is half a contract, and the wire is the last place a parser goes missing. Ruling: src/domain/event-branding.ts is the single home for the EventBranding type and parseEventBranding(json), which ALWAYS returns a present object and always passes logoUrl through safeImageSrc (the wave-30 sanitize-at-the-read rule applies to every reader, including the admin API, not just the two public ones). EventRecord.branding loses its null arm on the wire and the SPA type loses it too; the mocks stop emitting a value the server cannot produce.
