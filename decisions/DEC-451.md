# DEC-451: "Every Drizzle read carries a WHERE" becomes a scanning test with an empty, deliberate allowlist

The Airtable defect survived sixteen waves of audits, two spec-audit ledgers and an external review lens because nothing mechanically enforced the invariant that every read is scoped -- reviewers verified endpoints, not queries. The codebase already carries scanning conformance tests (test/d1-bind-safety.test.ts is the model), so the enforcement mechanism is proven and costs one file. The allowlist ships empty and is the point of the design: a future genuinely-global read is not forbidden, it is made deliberate and reviewable at the moment it is written, rather than discovered by a perf lane two campaigns later. The scanner must exclude subquery builders (exists(db.select()...), .as()) and any chain that does contain .where(), and must document each exclusion, because a conformance test that cries wolf gets deleted by the next worker who trips it.

## Amendment (wave 23): the scoping invariant is two-sided — a top-level write chain needs a WHERE too

test/query-scoping-invariant.test.ts enforces that every top-level `select(...).from(schema.X)` chain in src/** carries a `.where(`, because DEC-450 shipped four unscoped reads in src/sync/airtable.ts that read every org's rows. There is no write-side twin: 73 `.update(schema.X)` and ~55 `.delete(schema.X)` call sites exist across src/** and nothing asserts any of them is scoped. An unscoped write is strictly worse than an unscoped read in a multi-tenant app, and SPEC §6 names object-level ownership on every fetch-by-id as a hard requirement. Ruling: the same walker, the same exclusion rules, the same two-directional allowlist discipline, applied to update/delete chains — with count tripwires so neither the regex nor the ledger can quietly narrow the population (the field guide's TRIPWIRE COUNTING FILES != COUNTING MATCHES lesson). This is deliberately a presence-of-WHERE invariant, not an ownership-predicate invariant: the codebase's convention is load-then-write behind an org-scoped requireOwned* guard, and a scan cannot decide that a delegate guard is real (ALLOW-LIST REASON NAMING A DELEGATE IS A CLAIM).
