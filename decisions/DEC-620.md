# DEC-620: Vertical clipping is a measured gate: content taller than its own box, with nothing able to scroll, is a failure

render-sweep already asserts zero horizontal overflow, and it still could not see the agenda bug where card content bled 29-190px past a fixed-height box. Add a clip probe: elements where scrollHeight > clientHeight + 2 AND computed overflow-y is 'visible' or 'hidden'. A scroll container is not a bug and is excluded, the same way overflow-x:auto containers are already excluded from the horizontal measurement. Offenders are reported with selector and magnitude, worst-first, and evaluated by a pure function in render-sweep-lib.ts so the rule is testable without a browser. An offender that cannot be fixed this wave is NAMED in a known-exceptions list with a reason — never absorbed by widening the tolerance.

## Amendment (wave 25): a clip needs a clipper — the vertical-clip probe reports only content that is actually cut off

The freshest MEASURED gate on this tree (docs/verification-log/task-w17-d-render-sweep.md, 14 open items @ 408af6fc) is dominated by rows that are correct by construction: `label/button.chq-visually-hidden` clip=18px on every public and embed surface, where the rule is the standard deliberate collapse (src/routes/public/css/chrome.css.ts:22-32 `position:absolute; width:1px; height:1px; overflow:hidden; clip:rect(0,0,0,0)`); `div.chq-pub-speaker-list-photo` clip=4px, where cards.css.ts:156-165 declares `object-fit: cover` (an intentional crop); and `h1.chq-auth-wordmark` / `div.chq-forms-header-titles`+`h1` clip=3px, where neither src/routes/auth.css.ts:56-63 nor app/src/pages/forms/forms.css:33-51 nor any ancestor declares an overflow at all — `line-height: 1` display type overflows its content box by font metrics and nothing on screen is cut. A gate that cries wolf on eleven of thirteen desktop rows is not a gate; it is why waves 18-24 stopped reading it. RULING: an element is a clip offender only when (i) it or an ancestor establishes a real clipping context (computed overflow-x/y in hidden|scroll|auto, or a clipping clip/clip-path), AND (ii) it is not the deliberate visually-hidden collapse (clientHeight <= 1px), AND (iii) the overflow is not a replaced-content crop (overflowing child is img/video or declares object-fit). The decision logic lives in scripts/render-sweep-lib.ts so it is unit-testable; a row surviving all three exemptions stays a FAIL and is recorded, never silently fixed by widening the exemption.
