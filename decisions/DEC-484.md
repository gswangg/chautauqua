# DEC-484: The public JSON feed envelope carries the same paging truth as the HTML surface, and honors ?limit= identically

DEC-468 established that a cap the UI cannot see LIES and that `total` must be rendered. That obligation is stronger, not weaker, for machine consumers, and the JSON feed is currently the worst surface in the product on this axis: src/routes/public/index.tsx:264/271 destructures `const { items }` and throws away the `total` its own repo call already computed, so /embed/:slug/speakers.json returns 12 of 800 speakers with nothing in the envelope to indicate truncation — while the HTML page at least prints '12 of 800 speaker(s)' and a Show-more link. The same function also ignores ?limit=, which src/routes/public/dispatch.tsx:29 honors for the HTML embed, so one surface has two page sizes depending on the extension. The DEC-289 envelope gains page/perPage/total alongside items; agenda and schedule are unpaged, so they report page=1 and perPage=total=items.length rather than omitting the keys — a uniform shape that cannot lie by omission. This is J12's 'the data stays theirs' and EMB-15, not a new feature.
