# DEC-033: Form builder SPA at /admin/submissions/forms consuming the landed w2-c API; no new server endpoints

J1's producer-facing form builder is the last unowned admin surface: the API landed in wave 2 (GET /api/v1/events/:eventId/forms, PATCH /api/v1/forms/:formId, POST /api/v1/forms/:formId/fields, PATCH/DELETE /api/v1/fields/:fieldId, POST /api/v1/forms/:formId/fields/reorder) and the builder pure core is src/forms/builder.ts — the SPA task writes zero server code. Route: '/submissions/forms' added to App.tsx (DEC-005 'Submissions incl. Forms tab'); page app/src/pages/forms/FormsPage.tsx with components under app/src/pages/forms/. Surface: pick the event's form (default form preselected); ordered field list with locked built-ins (DEC-008/016) rendered non-editable/non-removable; add/edit field modal (section, kind text|long_text|dropdown|checkbox|number|file, label, help text, required, options editor for dropdown, conditional rule builder: show when <prior field> eq|ne|in <value> per form_field.rule_json); up/down reordering posting the full ordered id list; form settings strip (title, description/intro, open/close dates, tracks offered from the event's tracks); a copyable public link 'https://<origin>/submit/<eventSlug>'. Submissions.tsx gains one 'Forms' tab-style link in its header (small declared overlap with w4-g's toolbar additions).

## Amendment (wave 72): the builder's framed Save is real — the Opens/Closes strip is the CFP window editor, validated once, on the server

Frame 04 draws the builder header as `Preview` + an olive `Save`; FormsPage.tsx:222-226 renders Preview alone, and the page's own measure test still calls that block "the Preview/Save row". A control without its save is a picture, but so is a Save with nothing to write — fields already persist per action, so a bare Save would be the lie in the other direction. Ruling: the Opens/Closes cells of the strip become the page's editable CFP window (date inputs styled as the strip's 22px display value; Received stays a read-only fact), and Save PATCHes `{openDate, closeDate}` to `/forms/:formId` — the SAME endpoint and the SAME payload keys CallForPapersPanel already uses. Two screens, ONE writer and ONE validator: the server's close-before-open refusal (DEC-731/DEC-517) stays the only place the rule lives, and its field errors render on the strip cell they name. Save is present from load and disabled until the strip differs from the loaded form, so it never claims work it has none of. Settings › Call for papers is unchanged — the builder does not gut it, and the existing cross-link stays.


## Amendment (wave 84, v12 mobile campaign w2): The CFP form builder at 390 is one question per row with a 44px drag handle, and the dock carries Save over Preview

`Chautauqua Submissions.dc.html:468` ("CFP form · 390", captioned "Reorder and edit one question at a time") is the only frame in the pack no lane has ever owned; the mandate names it explicitly and says schedule it. It draws a drill-in: head `‹ Submissions` + `CFP form` + `Closes 16 Aug · 47 received`; body a list in which each question is ONE row carrying a `⋮⋮` handle, the label, a `{{f.type}} · {{f.req}}` meta line and a right-flushed `Edit`; then `Add a question`; dock `Save the form` (filled) over `Preview` (bordered). Two things the frame forces that the desktop builder does not have. First, the reorder handle must be a real 44px target at 390 — DEC-715 already rules the handle IS a button, so this is a size change inside the phone block, not a new affordance, and it lands ahead of Tier 2's 44px sweep rather than waiting for it. Second, editing is a per-question drill rather than an inline column; the frame says so in words in its own caption, which is copy and therefore binds. Ruling: adopt both, phone-only. The desktop builder, the full-set reorder echo (DEC-488), the field cap and the wire shape are untouched — the frame's `3 of 6`-style counters are placeholder content and bind nothing (the two-kinds-of-number rule).
