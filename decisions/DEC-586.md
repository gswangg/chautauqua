# DEC-586: A reviewer's landing is their work, never a picker: /review renders queues across every assigned open plan, headed by plan only when there is more than one

ReviewerQueue renders a PlanPicker whenever the URL carries no planId, so a reviewer's first screen is a list of plan names — an administrative noun standing between them and the only thing they came to do. In the common case there is exactly one plan, so the picker is a mandatory click that conveys nothing. /review therefore fetches the reviewer's plans and their queues and renders one page of work: with one plan, no plan heading at all; with several, one section per plan in plan order. The picker component is deleted rather than hidden — no backwards-compatibility stub. Two invariants survive intact: the server already orders each queue fewest-ratings-first with completed work last (DEC-018/DEC-561) and the client must render it exactly as delivered, never merging or re-sorting across plans; and the recusal list stays attached to the plan it belongs to, since a recusal is scoped to a plan-and-submission pair.
