# DEC-401: The mobile pass measures the truth and names the offender: max element right edge as well as scrollWidth, plus the widest overflowing elements and the shortest control's selector

Three sweeps have now reported bare numbers ('horizontal overflow 131px', 'control height 21px') with no way to act on them, so every phone-layout fix has been guesswork or whack-a-mole (detail.css and content.css each independently discovered `overflow-wrap: anywhere`; comms.css did not). Worse, the measurement can lie: src/views/theme.ts:75 sets `html, body { overflow-x: hidden }`, which clamps document.scrollingElement.scrollWidth to the viewport, so the public/portal mobile pass reads a clean 15/15 while content past 390px may be clipped and unreachable — the same failure DEC-385 forbids for chip strips, at page level. The observation therefore takes overflowPx = max(scrollWidth, max element getBoundingClientRect().right) - viewportWidth, and when it fails it names up to three offenders as tag + class list + width/right (structure only, never text — logs must not carry seed or user content) and reports which selector produced minControlHeight. Thresholds and PASS/FAIL semantics are unchanged (44px, 1px slack): this decision buys diagnosis, not a new bar.
