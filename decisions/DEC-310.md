# DEC-310: schedule.ics must query the requested ids, not hydrate the entire published agenda

Independent of any budget argument, src/routes/public/index.tsx:195 calls `getPublicAgenda(db, event)` — which at src/server/repo/public.ts:707-760 selects EVERY visible scheduled slot for the event and then hydrates all of them (tracks and speakers included) — and only afterwards filters down to the <=300 ids the caller actually asked for. Cost is O(entire event agenda) for a request whose answer is O(requested ids), and the perf corpus (300 accepted) is small enough that it registers as ~2ms of slack rather than as the scale bug it is; at a 2000-session event the same route would be the first thing to fall over. This is exactly the class of defect DEC-105's chunk-sweep work was created to eliminate, missed because the route reuses a page-shaped query. Add an id-scoped sibling `getPublicAgendaByIds` with the IDENTICAL visibility gate (`visibleSessionConditions()`) and chunking (DEC-078 `chunkIds`) so the silent-drop semantics for hidden or unscheduled ids are unchanged, and leave `getPublicAgenda` alone for the agenda page where the whole list genuinely is the answer. The DEC-080 300-id cap check stays ahead of the query.
