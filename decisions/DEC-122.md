# DEC-122: Compose preview and send hard-fail on unmatched submission ids (400 invalid listing the unknown ids) before any render or ics preflight; ics preflight runs only after the full-set match

src/server/repo/comms.ts:127's contract says 'the caller validates the full set matched before proceeding', but neither the preview handler (src/routes/comms/preview.ts) nor the send handler (:316) does — stale or cross-event ids are silently excluded and /compose/send reports success while emailing fewer speakers than selected, violating DEC-019's atomic no-silent-skips rule and the fail-loudly principle; additionally both handlers run preflightIcsSchedule on the raw unvalidated ids. Ruling: in both handlers, after loadComposeSubmissions, compute the set difference between requested and matched ids; if non-empty throw ApiError('invalid', 'One or more submission ids do not belong to this event', { submissionIds: 'unknown ids: <list>' }). Reorder so preflightIcsSchedule runs only after this check passes. A shared local helper in comms.ts keeps the two handlers identical.
