# DEC-696: Organizer-authored prose renders through ONE escape-first Markdown renderer; a track fieldset uses the CFP option vocabulary and its own copy

src/server/repo/portal.ts:652 documents the current behaviour outright — "Wiki content renders as escaped paragraphs" — so a resource whose body an organizer wrote as "## Travel" shows the literal hashes to every speaker (mandate item 39's Markdown bug). The renderer must escape FIRST and then apply a closed allow-list (ATX headings, paragraphs, unordered lists, emphasis, http(s) links), never the reverse, because a sanitize-after-render pipeline is how every XSS in this class happens; it lives in src/lib as a pure, dependency-free module so it is testable without a DOM and reusable by any other prose surface. Separately src/routes/portal/edit.tsx:155-168 renders the track fieldset as bare `<label><input type=checkbox>` with the legend "Track *", while the public CFP form already owns the styled chq-cfp-option vocabulary and DEC-579's copy ("Tracks *" with "Choose all that apply"); the same question asked on two surfaces gets the same control and the same words, or the speaker learns the two surfaces are different products.
