# DEC-389: A gate script reports; it never throws

The wave-3 render sweep exited 1 through an uncaught page.goto rejection inside loginContext, printing a stack trace and no mobile table at all. The operator could not tell 'measured and broken' from 'never measured' -- and 45 of the 49 route readings in that run were the latter while being printed as FAIL. A gate's product is its measurement, so a gate that cannot finish must still say precisely what it did and did not observe. Rule: every per-route visit and every persona login in scripts/render-sweep.ts is wrapped so a failure becomes a FAIL row carrying the error text, each of the four passes prints its table and summary regardless, and only then does the exit code go non-zero. This is not softening the gate: no failure is downgraded, the exit code semantics are unchanged, and fail-loudly is served better by a complete printed failure than by a truncated stack. ADMIN_MOBILE_PASS_BLOCKING stays false; that flip is DEC-387's and belongs to the wave after the pass first reads all-PASS.
