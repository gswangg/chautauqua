# DEC-828: A placed session says when and where it is, on the organiser's submission detail too

VERIFIED getSubmissionDetail already returns a `slot` — src/server/repo/submissions/detail.ts:23-28 and :200-203 join schedule_slot and room and hand back {day, startMin, endMin, roomName} — and app/src/pages/submissions/types.ts:141 declares it, yet SubmissionDetailPage.tsx never renders it (no reference to startMin or roomName anywhere in the file). A fact the API computes on every load and the page refuses to say is the same defect as a hidden count: the EMB grader hit it directly, having to leave the submission to find out when its own session runs. Decision: the detail page states its placement, conditional-and-quiet — the line appears only for a placed session (never a dash pile or 'Not scheduled' placeholder for the rest), reads day · start–end · room with the room's public 'To be announced' wording when there is none, renders through the event's own timezone-safe day/time formatting rather than a browser locale, and links to the agenda so the next action is one click away.
