# DEC-677: The send reporter is the ONLY sender vocabulary: every send flow renders describeSendResult and no surface prints its own count

DEC-664 landed app/src/lib/sendResult.ts and wired the three REMINDER flows (Overview, ProgressPanel, OnboardingGrid) — and stopped there. The product's two actual bulk-EMAIL flows still print bespoke strings: app/src/pages/comms/ComposeWizard.tsx:511 renders `Sent {sentCount} email(s).` and app/src/pages/contacts/BulkEmailModal.tsx:225 renders `Sent {sent} email(s).`. Both type the response as `{ sent: number }` and therefore DISCARD the `failed[]` array the servers already compute and return (src/routes/comms/send.ts and src/routes/api/contacts/bulk-email.ts:177 both return `{ sent, failed, items }`, and bulk-email.ts:156-175 explicitly collects per-recipient failures under DEC-238 so a partial outcome can be reported). So a batch where three of eleven recipients fail shows the organizer 'Sent 8 emails.' with no mention of the three — the exact family of dishonesty the sbek judge scored as MAJOR and mandate item 17 names. One reporter is only one reporter if it is the ONLY one: a source scan must forbid a component composing its own 'Sent N ...' sentence.
