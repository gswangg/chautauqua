# DEC-957: One count grammar, on both sides of the app/ boundary — '(s)' is not a plural

DEC-925 made app/src/lib/plural.ts the ONE count-phrase helper for the SPA and banned the hand-copied ternary there. It stops at the app/ boundary, and everything on the other side of that boundary still prints the parenthesised suffix the design's copy rules forbid: 'N of M session(s)' (src/routes/public/sessions.tsx:205), 'speaker(s)' twice (public/speakers.tsx:102, :148), '"X" has N collected answer(s)' and 'N dependent question(s)' (routes/api/forms.ts:249, :285), 'N evaluation(s) were submitted under anonymity' (review/plans-crud.ts:192), 'Unknown track id(s)' (api/submissions.ts:116) — and worst, 'You have 1 submission(s) left to review' inside the reviewer nudge EMAIL BODY (review/plans-progress.ts:232-234). A person reads every one of those. Rule: the implementation of plural/countOf moves to pure core at src/domain/count-copy.ts (no node:/cloudflare imports, DEC-002), and app/src/lib/plural.ts becomes the ONE named crossing that re-exports it — the same shape DEC-660 blessed for the merge-field vocabulary, so no SPA import changes and there is still exactly one implementation. Every '(s)' a person reads goes through it. The scan test widens to fail the regex /[A-Za-z]\(s\)/ across src/ and app/src (excluding src/routes/dev/, scripts/ and test fixtures) — a pattern that cannot false-positive on `.map((s) =>`, where the character before is '(' and not a letter. Scope held deliberately: the `? '' : 's'` idiom ban stays app/src-only this wave, because the largest server cluster of it is in src/routes/comms/index.ts, which an in-flight branch owns.
