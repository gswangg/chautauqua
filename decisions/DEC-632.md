# DEC-632: A results row carries the decision the server holds

ResultsTable renders Accept/Decline from a local `decisions` map only; the wire row (src/domain/evaluation.ts ResultsRow, app/src/pages/review/types.ts) has no status field, and buildResults (src/routes/review/shared.ts:297) never selects one. So the organiser's own decisions vanish on reload, the same submission can be silently re-decided, and the DEC-193 comment claiming a failed write 'refetches server truth' is false — the refetched rows cannot carry the truth. A screen that renders a state the server never sent is the optimistic-UI version of printing a total you did not count (DEC-606). Decision: the results row carries the submission's status, the screen renders the server's value with the optimistic write as a transient overlay cleared by every refetch, and the results CSV gains the same column so the download and the screen tell one story.
