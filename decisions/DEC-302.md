# DEC-302: npm audit advisories: dev-dependency-only advisories are accepted for stage 1 and must be recorded, not waved off, by the wave-11 build-test section

task-w7-c's pre-battery gate log recorded '9 audit advisories (moderate/high, unrelated to this gate — not investigated per scope)' with no tracking mechanism, which a reviewer correctly flagged as an unreviewed severity hand-wave. The stage-1 runtime dependency surface is exactly two packages (hono, drizzle-orm); everything else — vite, esbuild, playwright, wrangler, vitest — is a devDependency that never ships in the Worker bundle, so an advisory there cannot reach a user of the deployed product. Rule: a devDependency-only advisory is ACCEPTED for stage 1 and does not block the exit predicate; an advisory affecting a production dependency is a red that fails the section. To make that checkable rather than assumed, the wave-11 build-test section records the verbatim output of `npm audit --omit=dev` in its log alongside the plain `npm audit` count. No lockfile churn this wave: an `npm audit fix` on the eve of a frozen battery risks a build break for zero product benefit.
