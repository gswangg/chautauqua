# DEC-181: POST /logout requires CSRF via a new csrfFormOrHeader guard; portal sign-out form carries the double-submit token

POST /logout (src/routes/auth.tsx:156) is the only mutation with neither csrfForm nor csrfJson, so any cross-site top-level form POST force-logs-out users (SameSite=Lax does not block that). Two legitimate callers exist with different capabilities: the admin SPA already sends the x-chq-csrf: 1 header (app/src/App.tsx:66), and the portal SSR sign-out form (src/routes/portal/shared.tsx:47) can only carry a hidden field. Therefore add one middleware, csrfFormOrHeader, to src/server/middleware.ts: pass if x-chq-csrf === '1' (custom headers cannot be set cross-site), else enforce the existing chq_csrf double-submit cookie/field rule. PortalLayout gains a required csrfToken prop rendering a hidden input in the sign-out form; every portal page passes the token it already obtains (or newly obtains) via ensureCsrfCookie. No SPA change needed.
