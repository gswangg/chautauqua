# DEC-003: Canonical D1 schema: table names, ID strategy, enum literals

Snake_case singular tables mirroring SPEC §5: org, user, auth_session (renamed from 'session' to avoid collision — the talk-session IS the submission row), contact, event, form, form_field, submission, submission_answer, participant, evaluation_plan, plan_reviewer, evaluation, track, room, schedule_slot, task, task_assignment, portal_settings, resource, file, file_comment, email_template, email_log. Primary keys: text, 20-char lowercase base32 from crypto.getRandomValues via newId() in src/domain/ids.ts. Timestamps: integer ms epoch, created_at/updated_at. Submission status literals (exact strings everywhere): 'pending' | 'accept_queue' | 'decline_queue' | 'accepted' | 'declined' (column is text; custom statuses allowed later). Other enum literals: task.kind 'general'|'file_request'|'form'; file.kind 'presentation'|'poster'|'handout' with previous_file_id version chain; participant.invite_status 'none'|'invited'|'accepted'|'declined'; submission.content_status 'pending'|'approved'|'changes_requested'. Human refs: event.record_prefix (default 'SES'), submission.seq integer unique per event, display ref = `${prefix}-${String(seq).padStart(3,'0')}` (SES-014). event.slug globally unique; event.timezone is an IANA string. submission carries accepted_at (nullable, guards idempotent acceptance) and ics_sequence integer default 0. Indexes: every FK, (event_id,status) on submission, unique (event_id,seq), unique event.slug.
