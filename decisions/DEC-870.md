# DEC-870: The armed no-room affordance lives inside the grid column, never as a sibling grid item — the Unscheduled tray is never displaced

VERIFIED on main. app/src/pages/agenda/DayGrid.tsx returns a FRAGMENT: `<>{grid}{armed && <button className="chq-day-grid-noroom-btn">}</>` (lines 396-406), and app/src/pages/Agenda.tsx renders `<DayGrid/>` and `<UnscheduledTray/>` as the two direct children of `.chq-agenda-layout` (Agenda.tsx:293-318), whose CSS is `grid-template-columns: 1fr 268px` (agenda.css:67-73). So the moment a card is armed the fragment donates a THIRD child: the no-room button takes the 268px sidebar cell and the tray reflows to row 2, off-screen — the mandate's top Agenda item ("arming EVICTS the Unscheduled tray"). The bug is structural, not cosmetic: a component that returns a fragment into a grid donates every extra child as a grid ITEM. Decision: Agenda.tsx wraps the desktop DayGrid in ONE `<div className="chq-agenda-main">`, so `.chq-agenda-layout` has exactly two children in EVERY armed/unarmed state (main column, tray); DEC-794's strip stays DayGrid's own last child and is therefore full-width within column 1, below the grid, with the tray pinned. Pinned by a render test that asserts the layout's direct-child list is identical armed and unarmed. Same commit closes the two armed-state legibility MAJORs, because they are the same "while armed" code path: the armed cell ring (agenda.css:158-162, brand-on-cream at z-index 6) must clear 3:1 against BOTH the cream cell and the quieted ink clash card (agenda.css:170-174, currently 1.80:1), armed cells gain :hover feedback, and the clash card's text must stay legible rather than being struck through by the cell rules painted over it.
