# DEC-964: A row inside a group prints what DIFFERS, and the column that identifies it gets the width

app/src/pages/comms/RecentSends.tsx's BatchRecipients (:96-99) renders, for every recipient of an expanded batch, formatDateTime(row.sentAt) and row.subject — both of which the batch's own header row (:173-174) has already printed once. At the 100-recipient cap this screen prints the same subject 101 times and 101 timestamps that differ by seconds, while the only field that identifies the row, the address, is an unclassed <span> given the narrowest fixed track in the grid (comms.css:292 — 150px for the timestamp, 1fr for the repeated subject, minmax(0,170px) for the email). That is a volume-first failure (SPEC §2.2) on the one comms screen that must survive the product's own send cap, and it is the same 'show every DIFFERING field' rule the merge view already follows. The subject is not simply deletable: merge fields mean a per-recipient subject genuinely CAN differ from the batch's. Rule: a recipient row leads with the recipient as its identifying column at 1fr with the truncation treatment, then status, then the disclosure; it prints its own subject ONLY when that subject differs from the batch's, on its own line, labelled; it does not repeat the batch timestamp — instead the 'Show what was sent' disclosure, which is the audit record (DEC-833), prints that recipient's own sentAt so nothing auditable is lost. The batch header row is unchanged.
