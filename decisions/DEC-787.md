# DEC-787: A directory filter is a SET of rules; the rail composes with it, never replaces it

CRM-02 was judged on a multi-facet rule builder. VERIFIED app/src/pages/contacts/ContactsTable.tsx:12-23 — `rules` and `onChangeRules` are documented as "kept, unused" props, so the rule-builder UI no longer exists anywhere; the only writer of `rules` is ContactsApp.tsx:301, where clicking a company in the rail REPLACES the whole rule set with `[{field:'company',op:'eq',value}]`. The backend already supports AND over company/title/custom.* (src/domain/contacts.ts matchesSegment) and the pure helpers already describe and evaluate a rule set (app/src/pages/contacts/segments.ts). Decision: a FilterRulesPanel owns the rule set as a list of removable chips over the fields the server already understands, the company rail ADDS or updates its own company rule instead of discarding the others, and "Save as segment" keeps persisting exactly the active set (non-lossy, unchanged). A filter the user can only ever set one facet of is a search box wearing a rule builder's clothes.
