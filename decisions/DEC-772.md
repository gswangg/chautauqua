# DEC-772: A session's length is its format's, not the grid's default

VERIFIED: the former src/server/repo/agenda.ts:549 (now split across src/server/repo/agenda/) builds every AutoScheduleSessionInput with `durationMin: params.defaultDurationMin`, so autoSchedule places a Keynote, a Workshop and a Lightning talk as identical blocks -- the AIA probe's "auto-schedule ignores format durations". The data to do better is already stored and already read: the seeded session-format options are "Keynote (45 min)", "Talk (30 min)", "Lightning Talk (10 min)", "Workshop (120 min)", "Panel (45 min)" (docs/fixtures/sample-data.json:13) and src/server/repo/public/sessions.ts:405 already hydrates that answer per submission in one batched query. Decision: a pure `parseFormatDurationMin(label: string | null): number | null` in src/domain/schedule.ts reads the parenthesised minutes out of the format label; ONE hydration helper in repo/agenda.ts maps submissionId -> durationMin (format's minutes, else the organizer's defaultDurationMin), and BOTH runAutoSchedule and the Overview placement suggestions (repo/overview/scheduling.ts) consume it. A duration nobody reads is a form answer the product collected and then ignored; the fallback stays the explicit default, never a guess.
