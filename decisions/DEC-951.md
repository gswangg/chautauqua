# DEC-951: The public CFP keeps the multi-track model and speaks the product's one optionality grammar; the frame's radio group is refused with reason

The v5 public frame draws the submit form's track control as radio buttons, and the build renders a checkbox fieldset. The frame is wrong and the build is right: DEC-015 is explicit that 'talks are submitted to one or more tracks' and models it as a real join (submission_track, composite primary key), which reviewer assignment by track, the ?trackId= facets (DEC-774), the agenda's track lanes and assign-by-track all key on. A radio group would silently discard a second track at the only point in the product where the author, not the organizer, knows the answer. This decision refuses the radios WITH REASON so the item stops being re-filed, and fixes what the frame is actually right about. What the build gets wrong is the marker: `<legend>Tracks *</legend>` (src/routes/public/submit-views.tsx:122) is the last asterisk in the product, and DEC-917 established one optionality grammar with no asterisks anywhere — required rows carry no marker at all, skippable rows carry the identical ' · optional' suffix that both renderers import from src/domain/form-copy.ts. The public CFP is the one surface a stranger judges the product by and the one still marked in a retired dialect. Rule: the legend reads 'Tracks' with no marker, the help line stays ('Choose all that apply.'), the options render as a one-column list at the form's measure, and a test asserts the rendered CFP HTML carries no '*' required marker on any label or legend. Separately the page names itself ONCE: the header's form title is the page's single <h1> and the intro drops its second heading, keeping its lede paragraph.
