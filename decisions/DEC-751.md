# DEC-751: Recent sends live under Compose as well as in History — one component, two mounts, four rows and a link

docs/design/Chautauqua Comms.dc.html:146-155 ends the compose column with a "Recent sends" section whose rule carries an "All history" link and whose rows read when · subject · N sent · template. On main that list exists only inside the History tab (app/src/pages/comms/HistoryTab.tsx:98), so an organiser composing a send cannot see what already went out — the exact context that prevents sending the same batch twice. The list is extracted into one presentational component fed by the existing GET email-log (?groupBy=batch) and mounted in both places; the compose mount is capped at four rows, is read-only (no recipients disclosure — that belongs to the full history), and its "All history" link switches the DEC-710 ?tab= URL state rather than navigating away. Failed and partially failed batches appear here exactly as History renders them: an attempted send is auditable whatever the transport did.

## Amendment (wave 41): a Recent Sends row is five columns, and the count column states SENT, appending failures only when they exist

The row today prints when / subject / N recipients / a full per-status tally / a toggle — two count columns and no template, against frame 07's [time][subject][N sent][Template][Open]. Ruling: five columns. The count column states the SENT count and appends '· N failed' when and only when a failure exists, so an all-failed batch still renders as an auditable row (DEC-751's own honesty clause) without every healthy row carrying a zero. The template column names the template that produced the batch (via the templatesById map the component already accepts) or an em dash — never a fabricated name. 'Open' is the row's own recipients disclosure on the History mount and a link into History on the Compose mount, preserving DEC-751's two-mounts-one-component rule.


## Amendment (wave 1)

Falsified by measurement at gate-4 and confirmed by reading main: RecentSends takes an OPTIONAL `templatesById` prop (RecentSends.tsx:160) and the compose mount (Comms.tsx:186) does not pass it, so identical rows render template names in History and an em dash under Compose. An optional prop nobody passes is a second reader wearing the first one's clothes. Same defect class in the same row: the compose mount's `Open` calls `onSeeAll()` (RecentSends.tsx:240-247), which sets `?tab=history` and discards the batch the organiser clicked. Ruling: the templates map is fetched ONCE at the Comms level and passed to both mounts (the prop stops being optional), and `Open` carries its batch key in the URL (`?tab=history&batch=<key>`) which the History mount expands on arrival. One fetch, one lookup, one row identity.

## Amendment (wave 15): both Recent-sends mounts drill IN PLACE; 'All history' is the only handoff

One component with two behaviours selected by whether a callback was passed is two components wearing one name: the History mount's 'Open' expands the batch's recipients, the compose mount's 'Open' navigates to another tab. A reader who asks about the row in front of them should get that row. Ruling: 'Open' always toggles the same BatchRecipients disclosure; `onSeeAll` shrinks to the section-head 'All history' link; History keeps `expandBatchKey` so a ?tab=history&batch=<key> deep link still lands expanded. The compose mount keeps its display cap and changes nothing else.

## Amendment (wave 21): the expanded recipients band repeats the batch row's five tracks — one grid serves both mounts

DEC-751 made Recent sends one component with two mounts (Compose and History). Its collapsed row is a real five-track grid (`.chq-comms-batch-row`, comms.css:549-557, `150px 1fr 130px 150px auto`), but the band it discloses is not: `.chq-comms-batch-recipients .chq-comms-recipient-row` (comms.css:608-614) declares its own three-track grid `1fr 130px auto` inside an 18px-indented wrapper. That is precisely what B8 forbids — 'an expanded or selected band inherits its parent's column grid... it never spans the measure with its own free-floating layout' — and the frame draws the inheritance explicitly: docs/design/Chautauqua Comms.dc.html:649,653,664 repeats the send row's five tracks on the band's head, on each recipient row and on its footer line, with the first and last cells empty so Recipient sits under Subject and Result under the count. Two consequences I rule now so the lane does not have to decide them: (1) the band renders FIVE cells per row (leading and trailing empty), inherits the parent tracks, drops the wrapper indent, and takes B8's disclosure treatment — `--chq-surface` fill with a 1px hairline top and bottom — instead of a bare bottom border; (2) the collapsed row KEEPS its current `150px 1fr 130px 150px auto` for BOTH mounts. The frame's History variant (`150px 1fr 108px 150px 88px`) differs from its Compose variant only in the two trailing tracks; minting a second grid would fork the one component DEC-751 exists to keep single, and the load-bearing rule here is the inheritance, not eight pixels. The phone block (comms.css:858-905) stays as it is.
