# DEC-244: Portal deliverable panel mechanics (implements DEC-242)

Completed file_request assignments must not collapse to plain text (prod finding, CNT-05/D). Concrete contract so portal and organizer Content stay ONE system: (1) /portal/tasks renders, for each completed file_request assignment, an inline panel with the deliverable's current filename + uploaded time; (2) new GET /portal/tasks/:assignmentId/file serves the CHAIN-LATEST version (follow previous_file_id forward from the assignment's completion file via the files repo, so organizer-side replacements are honored) with Content-Disposition attachment, authz identical to the upload route (assertOwnAssignmentOr403 + org scope) — do NOT reuse the organizer /files route; (3) Replace is a plain re-post to the existing POST /portal/tasks/:assignmentId/upload, which already accepts complete assignments and chains previous_file_id per DEC-240; (4) comment thread reuses the file_comment table anchored to the chain-latest file id (same anchor rule as organizer DeliverableDetail, which shows comments[latest.id]); speaker posts via new POST /portal/tasks/:assignmentId/comments (csrfForm) inserting authorContactId=speaker contact AND authorUserId=speaker user, body trimmed, non-empty, capped at 4000 chars, redirect back to /portal/tasks. One thread, two surfaces.
