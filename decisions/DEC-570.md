# DEC-570: Desktop agenda placement is keyboard-first: arm-then-place, mirroring the phone; drag stays as an extra pointer affordance

app/src/pages/agenda/DayGrid.tsx renders placed sessions as `div draggable` and empty cells as bare `div`s with onDragOver/onDrop only, so the desktop grid exposes ZERO interactive elements — a 40-press Tab walk reaches none, and the sbek judge (which drives the a11y tree) cannot place a session at all. WCAG 2.1.1 failure, twice verified. PhoneAgenda.tsx already solved this with arm-then-tap over real <button>s calling the same onPlace(submissionId, roomId, startMin, endMin). Port that model to desktop rather than inventing a second one: every session card becomes a real <button> (arm on click, or place-the-armed-session-here when something is armed — conflicts are surfaced, never blocked, DEC-010/DEC-021), and empty cells render as buttons named "Place <ref> at HH:MM in <room>" ONLY while a session is armed. Always-on cell buttons would add ~200 tab stops to a 5-column × 15-minute day; armed-only keeps the resting tab order to the cards. Drag-and-drop is kept, not replaced — it is the faster pointer path and already works.
