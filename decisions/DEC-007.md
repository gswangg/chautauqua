# DEC-007: .ics generation rules (stable UID, SEQUENCE bumps)

UID = 'chq-<submission_id>@chautauqua' — derived from the immutable row id, so it never churns (SPEC §5 invariant). SEQUENCE comes from submission.ics_sequence, bumped by the caller on schedule-affecting changes (room/time), enabling the swyx flow: initial invite without room, later update same UID + bumped SEQUENCE. METHOD:REQUEST; LOCATION included only when a room is assigned; no video links (per clarifications); DTSTART/DTEND in UTC converted from event.timezone; lines folded at 75 octets per RFC 5545; DTSTAMP from injected clock for testability. One VEVENT per file for session invites; the /e/:slug/schedule itinerary export emits one VCALENDAR with multiple VEVENTs using the same per-session UIDs.
