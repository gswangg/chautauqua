# DEC-638: Tracks are editable wherever they are read; a capability the API has and no screen exposes is a dead endpoint

PATCH /api/v1/submissions/:id already accepts trackIds as a validated full-set replace (DEC-598), and a speaker can change tracks on their own submission from the portal — but the organiser's submission detail renders tracks as read-only chips, so the person who owns track-scoped reviewer assignment, the public track filter and the agenda's track identity cannot set a track from the record that shows it. Track only ever arrives through the public CFP form or the quick-create modal. Decision: the Tracks section on submission detail is editable in place — a multi-select over the event's tracks (the model is multi-track per DEC-579), saved as the full set through the existing endpoint, optimistic with loud rollback and a refetch on failure, with the empty set a legal clear.
