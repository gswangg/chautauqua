# DEC-380: Agenda phone flow: arm-then-tap over one room, 30-minute default placement, and no slot the API cannot describe

The handoff calls the phone agenda one of the redesign's two structural changes, and maps it onto the existing `PUT /submissions/:id/slot` body `{day, startMin, endMin, roomId}` — dragging was only the desktop's way of naming those four values. Contract: `app/src/lib/useIsPhone.ts` exports `useIsPhone(): boolean` backed by `window.matchMedia('(max-width: 700px)')` (subscribed via addEventListener('change'), returning false when matchMedia is undefined so jsdom tests keep the desktop tree); AgendaPage renders DayGrid + UnscheduledTray above that breakpoint and a new PhoneAgenda below it, both calling the SAME handlePlace/handleUnschedule — no new endpoint, no change to the optimistic write-then-reconcile semantics. PhoneAgenda shows the active day (the existing day chip strip), a horizontally scrollable room chip strip (rooms + TBD, `flex-shrink: 0` chips so the last room stays reachable, active chip ink-filled per DEC-372, a `.chq-flag` CLASH on a room holding a conflicted session), and time down the page as slot rows derived by a pure helper `buildPhoneSlots()` in app/src/pages/agenda/phoneSlots.ts. Arming is explicit: tapping an unscheduled session (from the footer's `Unscheduled N` sheet) or a placed card arms it, the footer shows `Placing · tap a free slot` with the session's title and ref plus Cancel, and tapping a free run writes the slot. THREE things the mock shows are deliberately NOT built, because no endpoint stores them: the `Break · 15 min` / `Lunch · 60 min` blocked rows (the agenda payload has rooms, placed, unscheduled and conflicts — there is no break entity), the `Move DFC-047 to 11:30` suggestion (already omitted by DEC-370), and the `lightning talk, 10 min` duration on an unscheduled session — `UnscheduledAgendaSession` carries no duration, so an unscheduled session places as a 30-minute block, exactly matching DayGrid's existing `durationForDrag` fallback, while re-arming a placed card preserves its own endMin-startMin. Conflicts stay flagged, never blocked: a slot holding two sessions renders as the inverted `.chq-panel` block captioned `Two sessions in this slot`, and placement never refuses.

## Amendment (wave 12) — the phone agenda is capability-equal to the desktop grid: any slot is a target while armed, and every count-bearing caption counts

PhoneAgenda.tsx today renders a free run as the ONLY tap target while a session is armed (`if (!armed) return null` on 'free' slots; 'placed'/'clash' rows only re-arm), so a producer on a phone cannot place a session into an occupied slot — the desktop DayGrid can, and SPEC J9 / DEC-010 say conflicts are surfaced, never blocking ("a tool that says 'no' loses to a spreadsheet"). A phone surface that refuses a write the desktop accepts is a different product, not a reflow. Same file lies about arithmetic: the clash panel hardcodes "Two sessions in this slot" while slot.sessions is unbounded. Ruling: while armed, EVERY slot row offers a placement control (occupied rows read "Place here anyway"), re-arm stays the not-armed gesture, and every caption naming a number derives it from the collection it describes. No desktop rule may change; new classes are chq-phone-* prefixed, hidden at top level, enabled in the existing 700px block.
