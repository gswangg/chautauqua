# DEC-607: One clipboard helper: a copy either confirms in a live region or admits it failed and reveals the text

Five surfaces each call navigator.clipboard.writeText and flip a local `copied` flag; when the write rejects — no permission, insecure context, headless driver — the promise is unhandled and the button silently lies by not changing at all, which is exactly what the EMB-8 re-verification observed on the embed builder. Copying is a boundary with the outside world, so it is a legitimate catch: one helper returns success or failure, the caller announces the result through an aria-live region, and on failure the text is selected so a human can still take it.
