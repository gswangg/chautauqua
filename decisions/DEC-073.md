# DEC-073: schedule_slot.roomId must belong to the submission's event, validated at write; public room lookups are event-scoped

upsertSlot persists any string roomId (src/server/repo/agenda.ts:330-363) and getPublicAgenda resolves room names by bare id with no event filter (src/server/repo/public.ts:354-359) — an organizer can reference another org's room and leak its name onto public pages, violating SPEC §6 server-side filtering. Fix both layers: the PUT /api/v1/submissions/:id/slot route rejects a non-null roomId that does not belong to ownership.eventId (new repo helper roomBelongsToEvent; ApiError 'invalid' with fields.roomId — fail loudly, not silently null), and the public agenda's room-name query additionally filters room.eventId = event.id so even pre-existing bad rows can never leak cross-org data.
