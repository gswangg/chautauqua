# DEC-387: The render sweep gains an admin mobile pass, advisory in the wave that introduces it

The existing mobile pass (DEC-253) measures only the no-login surfaces plus /login and /portal — every admin route, which is where the redesign's phone frames actually live, has never been measured at 390px by anything. Adding those routes is the instrument that makes DEC-385 checkable. But `gate:render-sweep` is its own CI job with a non-zero exit, so turning a never-measured surface into a blocking assertion in the same commit that introduces it would redden CI for reasons unrelated to the change. The admin pass therefore lands advisory: it visits the organizer and reviewer entries of ROUTE_MANIFEST (the `/admin/*` catch-all excluded) in 390x844 contexts, evaluates them with the existing `evaluateMobileRoute` against its own control selector (`.chq-tabbar a`, `.chq-tabbar button`, `.chq-btn`, `.chq-input`, `.chq-select`, `header nav a`, visible only), prints its own PASS/FAIL table and summary, and contributes to the exit code only when `ADMIN_MOBILE_PASS_BLOCKING` is true. That constant is `false` on landing with the flip rule stated in its comment: it becomes `true` in the wave after the pass first reads all-PASS. This is a documented ratchet with a named switch, not a silent tolerance — the numbers are printed either way.
