# DEC-438: The completion ledger names the sha it audited and splits open items into FAIL-unowned versus PENDING-OWNED

Both recent ledgers reached a FAIL that was already false when it was written: task-w11-f-spec-audit-stage1.md audited sha a3dbba69 ("scribe wave 11", its own branch point) and FAILed on the save-draft rate limit and the portal/profile caps, both of which DEC-422 already owned and which landed in the same wave. A ledger cut from main at wave start structurally cannot see its own wave's fixes, so grading them as unowned gaps is a category error that costs a whole wave. The remedy is not to serialize the ledger behind every other lane -- that starves five lanes to save one -- but to make the ledger report ownership: each open item is classified either FAIL-unowned (no decision, no dispatched task) or PENDING-OWNED, naming the DEC id and the task branch that owns it. RESULT is PASS only when both lists are empty. goalComplete is licensed by a ledger with an empty FAIL list AND an empty PENDING-OWNED list, cited file:line at its own audited sha -- never by a wave summary, and never by inheriting a previous ledger's verdict.

## Amendment (wave 11): a mandate clause closes on a NAMED EXECUTED TEST and is annotated, never deleted

The mandate's standing rule is that items close on measurement or runtime evidence, never on code-reading (a wave-43 read-based closure was falsified at gate-4). This wave re-probed ~20 mandate clauses by reading and found them all closed — which is exactly the evidence class the rule refuses. Decision: a swarm lane may record a behavioral clause as closed ONLY by appending, in place, `— CLOSED-VERIFIED (wave N, <test file>::<test name>)` to that clause in docs/eval-findings.md, where the named test is one the lane actually ran and that fails if the behavior regresses. Never delete a clause (the external probe/scribe process owns pruning, and deletion fights its updates); never annotate a pixel/measure/fidelity clause (no worker can measure those); if the test falsifies the read, the lane fixes the code and says so instead. This keeps the mandate honest without letting reading masquerade as evidence.

## Amendment (wave 16): a residue item closes on a NAMED EXECUTED TEST or it stays open -- reading the file is not closure

docs/eval-findings.md's own standing rule says items close on measurement, never on code-reading, after a wave-43 closure was falsified by a later measurement. Three planning passes have now re-read the same residue list and found item after item already implemented at file:line -- which is exactly the evidence the rule refuses to accept, and the reason the same forty items get re-read every wave. The fix is to spend the reading once and convert it into executed assertions: one test file whose cases each name the finding they close, then an APPEND-ONLY 'CLOSED-VERIFIED (wave 16)' block in docs/eval-findings.md citing file::test per item. Append, never prune or reorder -- the file is the orchestrator's, and a swarm agent that rewrites the mandate has changed the mandate.
