# DEC-599: A completed task response can be reopened, and the control says what it does instead of implying an email

The Task-response modal is read-only; the design gives it 'Mark complete' and 'Ask for more'. Both map onto the PATCH /task-assignments/:id status write that already exists (pending | complete — there is no 'waive'), so 'Ask for more' is a write back to pending that returns the task to the speaker's portal worklist. Nothing emails, per the house invariant that status changes never auto-send, so the modal must carry that constraint next to the button rather than letting an organiser infer a message was sent.
