# DEC-953: The portal speaks the frames' task vocabulary: To do / Done, while the wire keeps pending | complete

docs/design/Chautauqua Public and Portal.dc.html is authoritative and renders the portal task state as 'To do' / 'Done' (lines 779-783, TODO_S/DONE_S: 11px/700/0.09em uppercase olive) with due grammar 'Due 10 Apr' / 'Was due 1 Apr'. src/routes/portal/tasks/views.tsx:155 renders 'Completed' / 'Pending' and :279 renders 'N of M complete'. The design README is equally explicit that the STORED vocabulary is 'pending | complete only — no waive', so this is a display-vocabulary decision and nothing else: the DB column, the PATCH body, the API shape, the organiser grid's own words and every test that asserts them stay exactly as they are. Rule: in the speaker portal the assignment state pill reads 'To do' or 'Done' and the summary reads 'N of M done'; the class hooks (.chq-flag / .chq-portal-flag-done) are unchanged so the styling follows; no route, repo, or serialized value is renamed. A speaker reading their own list and an organiser reading the grid may legitimately use different words for the same row — what may not differ is the row's state.
