# DEC-295: A 304 from the ASSETS binding is a successful admin-shell fetch, not a missing bundle

src/routes/root.tsx:36-45 fetchAdminShell re-fetches /admin/index.html by cloning c.req.raw, which carries the browser's If-None-Match — and that ETag matches, because the outer /admin response is a byte-for-byte proxy of index.html including its ETag. assets.fetch() correctly answers 304; res.ok is false for 304, so the route throws the DEC-268 'bundle missing' ApiError and the single most important route in the README alternates 200/500/200/500 for any client that honors conditional GETs (reproduced 4/4 by task-w8-g-c2-fresh-clone.md). Passing the 304 through is the correct HTTP outcome — the browser then renders its cached shell, which is the same bytes — and it preserves the fast path rather than stripping conditional headers and re-sending the whole bundle every navigation. So: success is res.ok OR res.status === 304; every other status keeps failing loudly with the existing DEC-268 message, because a genuinely missing bundle must still be a legible 500 rather than a blank page.
