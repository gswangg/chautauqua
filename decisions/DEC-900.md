# DEC-900: The agenda's page actions live on its title row; a control offered when its action is not needed is clutter

app/src/pages/Agenda.tsx:239-253 stacks a .chq-toolbar band under the title carrying the summary, Auto-schedule, Publish schedule and an 'Add a room or track' link — roughly 170px of chrome the 06-agenda frame does not have, and a direct violation of the standing grammar (primaries never float in their own band; they belong to the title row or a form footer). Rule: the summary and both actions move onto the title row, right-aligned, exactly as every other page's head reads; the toolbar element is deleted, not restyled. The summary states '<N> unplaced · <M> conflicts · <P>% placed' with only the conflict count bolded, since bolding everything ranks nothing. 'Add a room or track' does not survive as a permanent link: rooms and tracks are Settings' job and the nav already reaches it, so the link renders ONLY in the grid's empty state (an event with no rooms cannot place anything, which is the one moment the organizer needs it) — conditional-and-quiet, not a fourth control competing with Publish.

## Amendment (wave 39): the agenda speaks ONE time grammar — zero-padded 24-hour — in the gutter, on cards, in aria names and in toasts

One surface currently speaks three grammars. `formatMinutes` renders '1:00pm' (gridMath.ts:41), `formatTimeLabel` strips the meridiem for the row rail giving a bare '1:00' that a reader cannot place in the day (DayGrid.tsx:43-45), and the placement cells' accessible names use the full meridiem form — so the visible gutter, the spoken gutter and the toast disagree about the same instant. The meridiem-strip was reasoned from "the rail is anchored by its own am/pm hour markers", an argument the v6 frames refuse: they label the gutter '13:00'. Ruling: `formatMinutes` returns zero-padded 24-hour `HH:MM`; `formatTimeLabel` is deleted rather than left as a wrapper; every aria-label, toast and card time reads the one function. This is a grammar ruling for the ADMIN agenda canvas; the public surfaces already speak 24-hour and are untouched.

## Amendment (wave 41): the agenda summary belongs beside the TITLE; head-actions hold only actions, and a tray card is flat

The '.chq-agenda-summary' figure is stacked inside .chq-agenda-head-actions above Auto-schedule / Publish (Agenda.tsx:229-234), so the page's state reads as a caption on its buttons; frame 06 puts it 16px right of the 'Agenda' title. Same stroke, the unscheduled tray: cards are flat (1px border, no accent stripe) and carry no ⋮⋮ handle (unframed chrome, and click-to-place is the sanctioned path), state '· N min' duration, and the tray heads 'Unscheduled' with a right-aligned count; the tray's instruction is ONE line, and a PLACED card's hint says 'choose a new slot' (a move), never the unplaced card's 'choose a time slot'.

## Amendment (wave 72): ONE overlay tier over the day grid — the armed lattice never paints above any overlay, and the tier is a token with a counted guard

This is the SAME bug DEC-900's wave-39 amendment already fixed twice — for `.chq-day-grid-clash-card` and `.chq-day-grid-placed-card`, both raised to 9 — and it reappeared on the new element class because the fix was written per-instance ("raise THIS card") instead of as a tier. ## Amendment (wave 7)

**The speaker rail history line gets its writer: submissionsThisYear + lastSpokeYear, computed batched, omitted (not zeroed) when unknown.** app/src/pages/submissions/SubmissionDetailPage.tsx:168-175 renders "N submissions this year - spoke in YYYY" from two fields that app/src/pages/submissions/types.ts:101-106 documents as "Optional -- no server route populates these yet". A reader with no writer is a line that never renders. Semantics fixed here so no worker has to guess: submissionsThisYear = the count of submissions in the SAME ORG on which this contact is a participant whose owning event's start date falls in the same calendar year as THIS submission's event (read through src/lib/event-time.ts against the owning event, per the house date rule), this submission included. lastSpokeYear = the most recent calendar year strictly BEFORE that year in which the contact was a participant on a submission that reached an accepted-and-scheduled state; the property is ABSENT (not null, not 0) when there is none, matching the myEvaluation/myRecusal convention already in this codebase. Both are computed in ONE batched query keyed on the detail's participant contact ids -- a per-row count is N scans.

## Amendment (findings wave 13): audienceLevel and participant role are WIRE KEYS the server must parse — the SESSION DETAILS section's selects are dead controls until it does

DEC-900's wave-25 amendment declared SESSION DETAILS a fourth numbered section carrying "FORMAT and AUDIENCE LEVEL as narrow selects" and a participants table with "Make co-presenter". The SPA half shipped; the server half never did. Verified on current main: app/src/pages/submissions/SubmissionDetailPage.tsx:660 sends PATCH /api/v1/submissions/:id {audienceLevel}, and :720 sends PATCH /api/v1/submissions/:id/participants/:participantId {role:'co-presenter'}. src/routes/api/submissions.ts parses NEITHER — the first body falls through to the guard at :339 and 400s "At least one of title, description, trackIds, or format is required" with fields.title set; the second hits the guard at :564 and 400s "visible or inviteStatus is required" with fields.visible set. So both controls refuse every change AND mis-name the field they refuse, which the SPA then paints onto the wrong control (its own AUDIENCE_LEVEL_FIELD_ANCHORS/PARTICIPANT_FIELD_ANCHORS tables at :84-91 assert the server names exactly `audienceLevel` and `role`). RULING: PATCH /api/v1/submissions/:id accepts `audienceLevel` with EXACTLY the format contract DEC-755's wave-10 amendment fixed — validated against the audience_level-role field's own options on the event's default form (getFieldOptionsByRole), `null` clears the answer, a form with no such field is a 400 {audienceLevel:'Not configured'}, and the write goes through the same submission_answer writer as format, generalized to take a role rather than duplicated. PATCH .../participants/:participantId accepts `role`, validated against PARTICIPANT_ROLE_OPTIONS (src/domain/participant-roles.ts) exactly as the POST sibling at :491-497 already does; the LEAD is never retargeted from this route (a request naming the lead row, or naming the lead role as its new value, is a 400 keyed `role`). Both empty-patch guards are re-worded to name every key they accept. A refusal must always be keyed on the field the caller actually sent.

## Amendment (wave 60) — minutes-from-midnight has ONE owner and exactly TWO named grammars

The wave-39 amendment recorded 'one time grammar for the admin agenda' and factored it into gridMath.formatMinutes. Eleven implementations of that two-line arithmetic now exist across both bundles, in two grammars. Zero-padded HH:MM: app/src/pages/agenda/gridMath.ts:45, app/src/pages/overview/AgendaWorkSection.tsx:26, app/src/pages/submissions/schedule.ts:21, app/src/pages/speakers/SpeakerDetailPage.tsx:59, app/src/pages/content/SessionList.tsx:24, app/src/pages/content/DeliverableDetail.tsx:69, src/routes/portal/index.tsx:367, src/server/repo/exports/table.ts:47. Unpadded H:MM: app/src/pages/agenda/gridMath.ts:59, src/routes/public/cards.tsx:139, src/server/repo/overview/scheduling.ts:22 — whose own comment states the anti-rule in prose ('each rendering context owns its own clock format per this file's existing per-context pattern'). SessionList.tsx's comment even names two of its siblings. Nothing has drifted yet; that is the only thing eleven copies guarantee. RULING: src/domain/clock.ts is the single owner, exporting exactly `clockHHMM(minutesFromMidnight)` and `clockHMM(minutesFromMidnight)`; both fail loudly (throw) on a non-integer minute or one outside 0..1440; app/src/lib/clock.ts is the ONE named app/->src/ crossing for them (the app/src/lib/room-label.ts precedent); every other declaration is deleted and its call sites re-pointed. No rendered string changes anywhere — this is a refactor with a scan, not a redesign.
