# DEC-952: Every rendered page names itself exactly once, and the innermost mounted view owns the <h1>

Three surfaces violate this in three different ways, all verified on main. (1) The public event pages have NO <h1> at all: src/routes/public/shell.tsx wraps children in <main class="chq-pub-main"> and puts the event name in a <span class="chq-pub-header-title">, so sessions.tsx:161, speakers.tsx:91/141, agenda.tsx:423/577 and detail.tsx:46/99 all lead with <h2> and the document has no top-level heading — on the five surfaces a stranger and an evaluating agent read first. (2) The portal is inconsistent with itself: portal/index.tsx:281 and :482 and portal/profile.tsx:143 render <h1 class="chq-portal-hero">, while portal/index.tsx:430, portal/tasks/views.tsx:238/275/336 and portal/edit.tsx:140/154 render <h2 class="chq-portal-hero"> — the same class, the same visual role, two different tags, which means five portal pages are unnamed. (3) app/src/pages/content/ContentApp.tsx renders <h1>Content</h1> unconditionally at :267 while FilesLibrary.tsx:202 renders <h1>Files</h1> and DeliverableDetail.tsx:257 renders <h1>{title}</h1>, so two of the three /admin/content states emit two <h1>s. DEC-944 already made this the rule for the auth family ('each page wraps its card in <main> and names itself with exactly one <h1>'); DEC-662 already made it the rule for Speakers. Rule, product-wide: exactly one <h1> per rendered page, owned by the INNERMOST view that is actually mounted — a container renders its own title only in the states where no child view is mounted; headings below it step down one level at a time, never skipping. Corollary that must be honoured in every application: promoting a tag changes its SIZE (UA h3 1.17em -> h2 1.5em -> h1 2em), so the class that carries the visual treatment is pinned in CSS BEFORE the tag changes — a heading fix that resizes a page has failed.
