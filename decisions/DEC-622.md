# DEC-622: Reviewer identity resolves in ONE place, and every surface that can name a reviewer ends in it

GET /api/v1/submissions/:id/evaluations nulls the reviewer exactly when the plan is anonymized (src/server/repo/review/evaluations.ts:226, DEC-596), while GET /api/v1/events/:id/export/evaluations selects schema.user.email with no anonymized check at all (src/server/repo/exports/exports/evaluations.ts:134/143/186) — two readings of the same rows disagree about blind-review integrity, and the CSV is the one a judge downloads. Two functions claiming the same semantics must END in the same helper: a pure resolveReviewerIdentity(row) returns null iff the owning plan is anonymized, and both call sites consume it. The export renders a null identity as the literal '(anonymized)' rather than an empty cell, because a blank cell reads as missing data and a CSV must say why a value is withheld.
