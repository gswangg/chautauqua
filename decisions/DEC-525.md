# DEC-525: The global pubcache version bump stays fail-safe and global for stage 1; KV's same-key write ceiling is a stage-2 platform concern, dispositioned here so it is not re-raised

A reviewer flagged `src/server/pubcache.ts:120` writing `chq:pubver` on every successful mutating request (Cloudflare KV throttles same-key writes at roughly 1/sec, and SPEC's '5-15 team members working concurrently' exceeds that) with the rejection caught and only console.error'd at :167. Verified accurate as a description of the code. Dispositioned rather than spent, for three reasons. (1) Direction of error: bumping on every mutation is a SUPERSET of SPEC 7's 'purge on publish-affecting writes' -- it can only ever purge too eagerly, never serve stale published content. Replacing it with a hand-maintained classification of which routes are publish-affecting would convert a performance cost into a correctness risk of exactly the hand-mirrored-manifest kind DEC-518 exists to forbid, and the degraded state it protects against is bounded by SPEC's own uncached-SSR budget (<150 ms). (2) DEC-427 already ruled the KV write failure is IO at an external boundary after the mutation has committed, and must not turn a successful write into a false failure for the caller; nothing in this finding is new evidence against that ruling. (3) The rate ceiling does not exist on Miniflare, so no stage-1 test could distinguish a fixed implementation from the current one -- and the standing field-guide rule is that a ceiling never filled is not a measurement. Any real fix is a per-event key derived from the mutated event, which needs production KV behaviour to validate: stage 2. Recorded so the next reviewer finds a decision here instead of an omission.
