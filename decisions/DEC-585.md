# DEC-585: The SSR half of the native-control fix lives once in THEME_CSS; surface CSS modules never restyle a bare control selector

DEC-577 fixed input[type=file] / input[type=date] / select for the admin SPA in app/src/styles.css and explicitly put the server-rendered surfaces out of its lane, noting they carry their own CSS modules. Left there, the same fix would be written three times — cfp.css.ts, portal.css.ts, public.css.ts — and would diverge on the fourth surface, which is how a judge ends up seeing a browser-default grey 'Choose File' button on the CFP form beside fully designed type. But those three modules are not the shared layer: src/views/theme.ts is, and it already owns the bare selectors for text inputs, selects and textareas on every SSR page (every SSR shell renders ThemeStyles before its own module). So the file/date/checkbox/radio treatments and the select chevron go there, once, on the frozen tokens; surface modules may only style .chq-* classes from now on. This is the SSR mirror of DEC-577, not a competitor to it, and like DEC-577 it excludes markup surgery — turning a select into a segmented control remains that page's own redesign.
