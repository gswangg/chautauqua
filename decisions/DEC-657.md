## Amendment (wave 57): a portal refusal names the field in the words on the speaker's screen and counts the overage — never a request-body key, never a bare 'too long'

src/routes/portal/profile.tsx:329 refuses an over-long field with `${field} is too long.`, where `field` is the raw request-body key from the `capped` table ('firstName', 'twitter', 'bio') — a speaker reads "twitter is too long." with no idea by how much, on a form whose own label says "Twitter". The v9 error-and-validation standard is explicit on both points: count against limits ("212 characters over") and say what was kept. The same file already does the hard part right — it re-renders with the speaker's typed values rather than the stored row — so the only thing missing is the vocabulary. The refusal names the on-screen label, states the overage through the existing countOf helper (no new pluralizer, DEC-925/DEC-957 hold), and the inputs declare their maxLength from src/forms/validate.ts so the cap is visible before it fires.
