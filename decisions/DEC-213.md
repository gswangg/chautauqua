# DEC-213: Per-round criteria freeze: PATCH /api/v1/plans/:id must reject any roundCriteria change that alters the RESOLVED criteria of a round that already has evaluations; future rounds without evaluations stay editable

The DEC-123 guard (review.ts:284-297) freezes body.criteria/body.scale once any evaluation exists, but body.roundCriteria passes through unguarded at :309 — PATCHing a round override after that round has recorded evaluations orphans them into exactly the 500ing-results state the guard exists to prevent. A blanket plan-level freeze on roundCriteria would be wrong: defining round-2 override criteria after round-1 evaluations exist is a legitimate DEC-147 workflow. Rule: when body.roundCriteria !== undefined and planHasEvaluations, compute for each round r in a new repo helper listRoundsWithEvaluations(db, planId): Promise<number[]> (SELECT DISTINCT round FROM evaluation WHERE plan_id = ?) the before-resolution criteriaForRound(plan.criteria, roundCriteriaJsonOf(plan), r) and after-resolution (using the parsed new map, null meaning cleared, falling back to the — already frozen — base criteria); if not deepEqual, throw the same 409 conflict message the DEC-123 guard uses. Identical no-op overrides pass, preserving full-object SPA PATCHes. The existing plan-level criteria/scale freeze is unchanged.
