# DEC-733: An action that cannot apply to a row is ABSENT, not disabled — and a library states only endpoint-backed figures

Conditional-and-quiet is the design's affordance rule (it is why the Response link and per-person Remind are conditional). Content violates it: Approve renders on already-approved rows, and undocumented Deliverables/Headshots tabs sit half-built. A disabled control is a promise the app will not keep; delete it or make it real. The files library's stat line and deliverable chips must come from the list endpoint's own counts (never a client-side count of the current page), and 'Download all' must be backed by the existing zip path rather than a decorative button.

## Amendment (wave 63): a slow operation's own button is its progress indicator, and it is the only thing disabled

DESIGN-RULINGS.md:155-161 names exactly four non-optimistic slow operations (bulk send, CSV import, file upload, auto-schedule) and rules the wait: the button's label swaps to the present participle plus the count so far, it takes cursor:progress at its rest colour, it is the ONLY disabled control, under 300ms nothing changes at all, a count that cannot be counted is one unmoving line, never a fake percentage, and completion is reported by the RESULT PANEL — the button never says 'Sent!'. Measured on main, none of it exists: `Agenda.tsx:322` reads 'Auto-scheduling...', `UploadZone.tsx:125` renders 'Uploading…' as a separate span beside the control, and there is no shared grammar at all. Ruled: one helper owns the grammar and declares the four operations as a constant, so a fifth slow operation cannot be added without joining it; the 300ms floor reuses `useDelayedFlag(active, 300)` rather than a second timer (the 250ms default is the skeleton's, not this one's).
