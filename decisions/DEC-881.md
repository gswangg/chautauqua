# DEC-881: "Re-uploaded" counts re-uploads: the worklist's status cell and the header's number read ONE predicate

ContentApp.tsx's header prints the mock's "5 need a decision · 2 re-uploaded" but computes the second figure as a bounded aggregate filtered on contentStatus=changes_requested — that is the count of sessions AWAITING a re-upload, the exact opposite of what the label claims, and no worklist row can ever display the frame's status vocabulary at all (the cell renders Pending/Approved/Changes requested). docs/design "Chautauqua Content.dc.html" rows read "Re-uploaded" and "Not reviewed", and its header arithmetic is 5 = 2 re-uploaded + 3 not reviewed. Define the predicate once: a submission is RE-UPLOADED when its latest deliverable file's version_no > 1 (a replacement landed). The row's status cell resolves in a fixed precedence — approved -> "Approved"; re-uploaded -> "Re-uploaded"; changes_requested -> "Changes requested"; otherwise "Not reviewed" — and the header's count is that same predicate as a server-side list filter, so the printed number and the rows it summarizes cannot disagree. The default worklist tab becomes "Needs a decision" per the mock, with an honest empty state that links to All; this narrows DEC-665, whose "all" default existed only to avoid landing on a "0 submissions" screen.


## Amendment (wave 6): the re-upload predicate is ONE server reader that the worklist row, the header aggregate and the deliverable band all read — no surface may pass a literal

DEC-881 made worklistStatusLabel(contentStatus, reUploaded) the single content-status vocabulary, and src/server/repo/submissions/list.ts:47 holds the single SQL predicate (reUploadedSql). The deliverable detail band then calls worklistStatusLabel(pill, false) with a hardcoded literal (app/src/pages/content/DeliverableDetail.tsx:359, with the deferral written into the comment at :351-353) because GET /submissions/:id never projected the flag. The result is two surfaces disagreeing about the same row — gate-4 measured the band saying PENDING for the session the worklist labels RE-UPLOADED — which is the house's recurring sibling-predicate bug wearing a literal instead of a second query. Ruling: the submission-detail read projects the re-upload flag through the SAME reUploadedSql() the list and the header aggregate compose (never a second derivation, never a client-side guess), the band passes the real value, and the literal plus its deferral comment are deleted. Emphasis follows the frame: RE-UPLOADED takes bold ink and NOT REVIEWED stays muted, expressed as ONE class mapping both the worklist cell and the band consume.
