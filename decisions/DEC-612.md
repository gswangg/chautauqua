# DEC-612: External record identity is one namespaced external_ref column per imported table, unique inside its own owner scope

Idempotent re-import needs a stable key that is THEIRS, not ours. One nullable TEXT column `external_ref` on `contact`, `submission` and `track`; the value is always `"<source>:<their id>"` (lower-snake source, e.g. `sessionboard:12345`), never a bare id, so two sources can never collide and a ref always says where it came from. Uniqueness is scoped to the row's own owner — contact(org_id, external_ref), submission(event_id, external_ref), track(event_id, external_ref) — and SQLite treats NULLs as distinct, so hand-created rows are untouched by the constraint. A uniqueIndex is a contract: it exists in schema.ts AND in the migration (test/migration-parity.test.ts enforces both directions). Any read that filters on external_ref must handle NULL explicitly — a nullable column inside a negated set predicate silently skips NULL rows.
