# DEC-532: Conditional-field visibility resolves to a FIXED POINT: a field gated on a hidden field is itself hidden, because a hidden field has no answer

`isVisible` (src/forms/visibility.ts:7) takes only (field, answers) and reads the RAW submitted answer map, so it can never know whether the field its rule points at is itself hidden. Chain: Format(dropdown) -> "Workshop length" (rule: Format=Workshop) -> "Projector?" (rule: Workshop length=3 hours). A speaker who switches Format from Workshop to Talk and resubmits gets: "Workshop length" correctly hidden and stripped (validate.ts:44-54, DEC-501), but "Projector?" still evaluates VISIBLE because answers["Workshop length"] is still "3 hours" in the raw map. Two live consequences, both on the public CFP that J2 says must not gate on invisible questions: (a) if the grandchild is required, validateAnswers emits `required` for a question the speaker cannot see, and the submit button is a dead end with no reachable error field; (b) if it is optional, its stale answer survives DEC-501's cleanup and is served to reviewers (review/submissions.ts sessionAnswers), the organizer detail, and every export as current -- exactly the failure DEC-501 was written to kill, one level deeper. DEC-501 fixed depth 1 and stopped. Decision: (a) `src/forms/visibility.ts` gains `resolveHiddenFieldIds(fields, answers): Set<string>`, a MONOTONE fixed point -- repeat until stable: a field is hidden when `!isVisible(field, effectiveAnswers)` where effectiveAnswers omits every currently-hidden field's key, or when its `rule.fieldId` names an id absent from `fields`. Fields only ever move visible->hidden, so it terminates in at most `fields.length` passes and a rule CYCLE resolves deterministically to hidden-on-both (an unsatisfiable rule is not an exception -- an organizer misconfiguration must still render the form). (b) `isVisible` stays exactly as it is and stays the ONE single-field predicate; resolveHiddenFieldIds is its only new caller. (c) `makeVisibilityPredicate(fields, answers)` returns a closure with the existing `(field, answers) => boolean` shape so `src/views/form-render.tsx`'s prop type is UNCHANGED and the three render sites are a one-line swap. (d) Every render site builds the predicate from the FULL field list, never the per-section slice, because a session field can gate a speaker field.
