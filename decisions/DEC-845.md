# DEC-845: A queue headed by a plan carries the plan's facts on its own wire, including the reviewer's own score

The v5 pack (docs/design/README.md 'Review — the queue is scoped to a plan') requires the reviewer queue to head itself 'Review · <plan>' over a count, with '<scope> · closes in N days' beneath, rows reading SCORED 4.5 / NOT SCORED, and the scorecard's back link naming the plan. VERIFIED absent: app/src/pages/review/ReviewerQueue.tsx:173 renders the bare plan name as h1 with no count, no scope, no progress; rows show 'N ratings so far' (everyone else's work) with a 'Complete' pill; Scorecard.tsx:165 says '← Back to your queue'. The missing facts are per-reviewer and cannot be re-derived client-side: the reviewer's OWN blended score, and the track their plan_reviewer row scopes them to. Decision: GET /api/v1/review/plans/:id/queue's envelope gains planName: string, scopeTrackName: string | null (the caller's own plan_reviewer scope; null = all tracks) and closeDate: number | null, and each item gains myScore: number | null computed by the SAME weighted blend already in src/domain/evaluation.ts (never a second formula, per the weighted-score decision the results table and the scorecard already share). alreadyRatedByMe stays as the boolean; myScore is what the row PRINTS. One wire shape, so the queue heading, the row state and the scorecard eyebrow cannot disagree with each other or with the results table.
