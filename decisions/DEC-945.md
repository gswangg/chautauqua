# DEC-945: One 404 card, three renderers — and it never prints the path it failed to match

The product has three not-found renderers and they disagree. src/server/not-found.tsx (no route matched) already draws the design's card through AUTH_CSS. src/routes/public/not-found.tsx — the one /e/<bad-slug>, an unknown session and an unknown embed surface all land on — draws a bare `<main style="max-width:520px">` with hand-written inline styles and no card at all. app/src/pages/NotFound.tsx (the SPA catch-all) draws neither: a full-width `.chq-measure` 820 column, a body sentence that inlines `<code>{location.pathname}</code>`, and two `.chq-btn-tertiary` links separated by a literal `{' '}` so they jam together. The frame is one card: eyebrow, 28px title 'That page isn''t here', a 15px/24.5 body line, and a row of ‹-suffixed links — and it does NOT restate the URL, because a person who mistyped a link learns nothing from being shown their own typo and an evaluating agent reads the links instead. Rule: all three renderers draw the SAME card at the same numbers — 520 max-width, content-hugging (never viewport-stretched), 35px padding, 28px title, 15px/1.63 body, links in one flex row. The two server-side renderers reach it by importing AUTH_CSS (one string, no second ad hoc card layout); the SPA page owns a co-located app/src/pages/not-found.css that repeats the numbers and names this decision so any drift is visible in a diff. The attempted pathname is not rendered anywhere. A link is still the route it lands on (Overview and Submissions for the SPA, the hub for the public surface).
