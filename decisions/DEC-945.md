# DEC-945: One 404 card, three renderers — and it never prints the path it failed to match

The product has three not-found renderers and they disagree. src/server/not-found.tsx (no route matched) already draws the design's card through AUTH_CSS. src/routes/public/not-found.tsx — the one /e/<bad-slug>, an unknown session and an unknown embed surface all land on — draws a bare `<main style="max-width:520px">` with hand-written inline styles and no card at all. app/src/pages/NotFound.tsx (the SPA catch-all) draws neither: a full-width `.chq-measure` 820 column, a body sentence that inlines `<code>{location.pathname}</code>`, and two `.chq-btn-tertiary` links separated by a literal `{' '}` so they jam together. The frame is one card: eyebrow, 28px title 'That page isn''t here', a 15px/24.5 body line, and a row of ‹-suffixed links — and it does NOT restate the URL, because a person who mistyped a link learns nothing from being shown their own typo and an evaluating agent reads the links instead. Rule: all three renderers draw the SAME card at the same numbers — 520 max-width, content-hugging (never viewport-stretched), 35px padding, 28px title, 15px/1.63 body, links in one flex row. The two server-side renderers reach it by importing AUTH_CSS (one string, no second ad hoc card layout); the SPA page owns a co-located app/src/pages/not-found.css that repeats the numbers and names this decision so any drift is visible in a diff. The attempted pathname is not rendered anywhere. A link is still the route it lands on (Overview and Submissions for the SPA, the hub for the public surface).


## Amendment (wave 40)

**The v6 auth measures supersede 520/450/640, the card hugs its content, and there is no card border**

Verified on main: src/routes/auth.css.ts:28 sets body { display: flex; justify-content: center } with the default align-items: stretch, so every SSR auth card renders exactly viewport-tall (227-521px of dead space under the content); .chq-auth-card caps at 640 with a 1px --chq-rule border and 6px radius, .chq-auth-card-narrow at 520, and the control column at 450. The v6 frames measure the login form column at 732 (the 820 reading column inset 44px) and the password/not-found surfaces at the full 820, and draw NO card border on any 11-account frame — the border plus the stretch is what makes the dead space read as an empty rectangle. RULING: align-items: flex-start on the auth body; the border and radius come off; .chq-auth-card (the form card) is 732 and .chq-auth-card-narrow (the plain card: password, 404) is 820, with the 450px control-column cap deleted; ‹ Back and the h1 sit flush at one x (the 36px margin-left on .chq-auth-titlerow .chq-auth-title goes). The modifier keeps its now-inaccurate name for one wave and carries a comment saying so: renaming it would touch five call sites that two lanes are editing this wave, and a rename is not worth a merge conflict in a security-adjacent route file.

## Amendment (wave 6): an unknown path under a role shell is a 404 for EVERY role — /portal/* never redirects an organizer into /admin

DEC-945's wave-53 amendment already ruled that an unknown /admin path is a real 404 (chromeless card, HTTP 404, no route leak) rather than a 200 with the SPA's catch-all. Its mirror never landed: gate-4 measured an organizer at /portal/nope getting HTTP 200 on /admin/overview, because src/routes/portal/shared.tsx:41 redirects every non-speaker to /admin before anything asks whether the path exists. A speaker at the same URL correctly gets the designed 404 card, so the product currently answers the same question two ways depending on who asks — and the organizer's answer invents a page. Ruling: path existence is decided before role redirection on the portal shell exactly as it is on the admin shell; an unknown /portal path returns the shared NotFoundDocument at HTTP 404 for every role, and the speaker path stays byte-identical. Corollary already in the mandate: the admin-404 card's links are role-aware (`Overview ›` + `Submissions ›` for a signed-in organizer), never a hardcoded homepage/Log-in pair that sends a signed-in producer to the wrong door.

## Amendment (wave 25)

**The auth card is 460 wide and its actions are a footer row, not a full-column bar**

The V8 intake redrew 11-account--00 ("a card, not a stretched phone") and explicitly SUPERSEDES the pair-6 box-math ruling that trued the app up to 732 content / 820 box. DESIGN-RULINGS' governing corollary names the exact defect we shipped: full-column buttons and one-field-per-row stacking are phone anatomy, and a centred card is not a desktop design just because it is centred. So: `.chq-auth-card` max-width 460px, 1px rule + paper fill + 8px radius, padding 36/34/32, gap 22; `.chq-auth-card-narrow` 520px; the submit button loses `width:100%` and becomes an intrinsic-width olive control (min-height 46, padding 0 22px) inside a footer ROW that is space-between when a tertiary link sits at its left and flex-end otherwise. Every measure test pinning 732/820/818/888 for the auth card is now WRONG and gets updated with the change (field-guide rule: where a test contradicts the current design authority, the test is wrong).
