# DEC-067: /headshots/:fileId is gated: 404 unless a contact currently references it; unauthenticated serving requires the public-visibility predicate; org members and the owner get a private-cache fallback

getHeadshotFileScope checks only kind='headshot', so headshots of hidden/declined/never-accepted speakers are publicly fetchable with a 1y immutable cache — violating SPEC §6 server-side filtering and DEC-028's own premise. Decision: the serve scope resolves the owning contact by reverse lookup (contact.headshotUrl = '/headshots/<fileId>'); no referencing contact (superseded upload) -> 404 for everyone. Unauthenticated requests are served only when the contact is publicly visible under the exact repo/public.ts predicate (participant.visible=1 on >=1 submission with status='accepted' AND content_status='approved'), keeping the existing public immutable cache header (DEC-059 unique-key rationale stands; visibility revocation tolerates the cache TTL). Otherwise an authenticated session is required: organizer with matching orgId, or speaker whose contactId is the owner, served with 'Cache-Control: private, max-age=0'. All other cases 404 (never 401/403 — don't leak existence).
