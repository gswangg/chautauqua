# DEC-672: /embed is a CLOSED surface: every link an embed page renders resolves inside /embed, and every path it renders is a registered route

DEC-594 introduced SurfaceBase and threaded it through the sessions surface only; src/routes/public/index.tsx:214-218's own comment admits the partial ("currently sessions' search form, track-filter pills, and drill-in title links"). renderSurfaceContent (src/routes/public/dispatch.tsx) accepts `embed` and passes it to SessionsContent alone -- SpeakersContent, GalleryContent, AgendaContent and ScheduleContent take no base, so surfacePath()/speakerDetailPath()/sessionDetailPath() fall through to the "/e" default: inside /embed/:slug/speakers every card link, the name-search form action and "Show more" all navigate the host page's iframe to the full-chrome site, as do the agenda/schedule drill-ins (src/routes/public/agenda.tsx:124,182) and the hardcoded /e/<slug>/schedule.ics anchor (:369). All five surfaces are advertised by the organizer embed builder, so this is reachable from a shipped feature. Worse in the other direction: there is NO /embed/:eventSlug/sessions/:sessionId or /embed/:eventSlug/speakers/:contactId route at all (only /embed/:eventSlug, /embed/:eventSlug/:surface{...json} and /embed/:eventSlug/:surface), so the one link that DOES honour base today -- SessionCard's title in embed mode (src/routes/public/cards.tsx:137) -- 404s inside the iframe. Closing the surface means both halves: add the two detail routes, and thread base everywhere. A closed surface is proved by ENUMERATION, not by inspection: a test renders every /embed page and asserts every same-origin href/action it emits begins with /embed (the one deliberate exception, the .ics download, must carry target=_blank so it cannot replace the frame).
