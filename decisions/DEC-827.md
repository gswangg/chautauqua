# DEC-827: Import lives in Contacts; Speakers links to it with the event already chosen

Two prior decisions point in opposite directions and the eval sits in the gap: DEC-662/746 put CSV import in Contacts (OnboardingGrid.tsx:104 says so in a comment, and the Speakers title row deliberately carries no Import CSV button), while the SPK-03 scenario looks for import in the speakers area and scores its absence. Building a second importer would give the product two ways to do one thing and two places for the dedupe rules to diverge. Decision: Speakers carries a WAYFINDING LINK, not a second capability — a quiet toolbar link into the Contacts import wizard with this event preselected, so the imported people land on this event's roster in one hop. The wizard opens from URL state (?import=1), matching the ?tab= grammar DEC-710 already set for that page, because a screen a link must be able to reach has to own its URL. ImportWizard already accepts an eventId; nothing about the import contract changes.
