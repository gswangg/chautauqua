## Amendment (wave 48)

**The 44px tap floor is PHONE-scoped in THEME_CSS; desktop SSR controls are sized by padding.** THEME_CSS is the shared stylesheet behind every server-rendered surface (public event pages, CFP, portal, auth, the hub). Its comment reads 'Every interactive element is >=44px tall on phone … DEC-367' but the declarations sit in the BASE rules, not in a media query: min-height: 44px is unconditional on text inputs (theme.ts:168), .chq-input/.chq-select/.chq-textarea (:180), date (:197), file (:210), the file-selector button (:224), select (:266) and button/.chq-btn (:290). So every public control is 44px tall on a 1440 desktop. The vendored README states the rule with its scope attached: 'Every interactive element is ≥44px on phone (min-height:44px plus centred flex, not padding). Desktop rows use padding:8–10px 14–18px' — and the eval mandate's CLASS 6 files the 44px desktop control as the deviation ('the 44px tap target is phone grammar on desktop'). RULING: the min-height moves into a single @media (max-width: 700px) block that re-asserts it for the same selector list; desktop keeps the existing padding, landing controls at ~34px, which is what the frames measure. Where an existing test pins a 44px desktop height on an SSR surface, the test is wrong. Per-surface 44px overrides outside THEME_CSS are NOT in scope this wave and the new scan must not reach them.

## Amendment (wave 50): the 44px tap floor is phone-only on the PUBLIC surfaces too — the wave-48 fix bound THEME_CSS and missed the four public CSS modules

docs/design/README.md §Controls is explicit: 'Every interactive element is >=44px on phone (min-height:44px plus centred flex, not padding). Desktop rows use padding:8-10px 14-18px.' The wave-48 amendment moved THEME_CSS's whole 44px block inside @media (max-width:700px) (src/views/theme.ts:492-529) and wrote the rule down in its comment — but bound only the selectors it enumerated. Verified at the file on main, four public modules still declare the floor at BASE scope, so every one of these renders at 44px on a 1600px desktop: .chq-pub-save, the per-card Save/Saved pill on every public session card (src/routes/public/css/rail.css.ts:109); .chq-pub-view-toggle-option, the List|Grid segmented control (src/routes/public/css/cards.css.ts:114); the agenda day-pill segment, .chq-pub-itinerary-row and .chq-pub-itinerary-cta (src/routes/public/css/agenda.css.ts:295, 326, 331); and .chq-cfp-option.chq-cfp-pill (src/routes/public/cfp.css.ts:79). RULING: the floor moves into each module's existing @media (max-width:700px) block, mirroring THEME_CSS's structure so one rule reads the same everywhere; on desktop the control sizes from its own padding. A scan test asserts no customer-facing public CSS module declares min-height:44px (or min-width:44px) outside a max-width:700px block. Per the standing rule, any existing measure test pinning 44px at desktop width is the thing that is wrong and is re-pinned to the phone rule. Scope is the public family only: portal.css.ts is deliberately out of scope, as is the 460 sign-in card.


## Amendment (wave 57) — A DIRECTORY IS NOT A POPULATION: the 44px tap floor is phone-only across EVERY SSR stylesheet, not just src/routes/public/

test/public-tap-floor-scope.scan.test.ts (wave 50; since renamed to test/ssr-tap-floor-scope.scan.test.ts) bans a base-scope `min-height: 44px` — but only inside `src/routes/public/**/*.css.ts`. Its own header records why it was written that way: "the wave-48 fix only touched THEME_CSS and missed four public modules precisely because nothing swept the whole directory." It then swept ONE directory. Seven base-scope 44px declarations sit outside it today and nothing sees them: src/routes/auth.css.ts:93 (.chq-auth-back), :236 (.chq-auth-footer-links a), src/routes/portal/portal.css.ts:53 (.chq-portal-back), :101 (.chq-portal-footer-resources), :110 (.chq-portal-footer-profile), :213 (.chq-portal-actions .chq-btn), :294 (.chq-portal-signout-btn). docs/design/README.md:92 is unambiguous — ">=44px on phone (min-height:44px plus centred flex, not padding). Desktop rows use padding:8-10px 14-18px" — and the mobile-queue governing principle says phone grammar is a TRANSLATION of desktop affordances, never a desktop rule. This is not theoretical: gate-9 measured the /admin/* 404 card at body->links 46.5 against the frame's 26.5, and the mechanism is readable in the source — .chq-auth-footer-links a's unscoped 44px box applies to the notice card's links too, and auth.css.ts:97-103 then fights its own box back with `align-items: flex-start` plus `margin-bottom: -13px`. A desktop rule patched by a negative margin to undo a phone rule is the tell. RULED: the tap floor lives inside `@media (max-width: 700px)` in every SSR CSS module, the compensations it forced are deleted with it, and the scan's population is derived from the SSR stylesheet set rather than from a directory name. Exemptions carry STRUCTURAL reasons only, never a branch note (the wave-56 exemption-list ruling applies here identically).
