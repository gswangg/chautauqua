# DEC-978: The event switcher is an organiser control: it fetches nothing and renders nothing for a reviewer

app/src/components/EventSwitcher.tsx sits in the admin shell on every route including /review, and its mount effect (:174-178) calls apiList('/events') unconditionally. That endpoint is requireOrganizer, so every reviewer session fires a 403 on first paint and lands in the component's error state — a signed-in reviewer is shown a failure caused only by the shell asking a question they are not allowed to ask. The component already knows better one screen down: :235 gates 'New event…' on me?.role === 'organizer' with the note that 'a reviewer must never see a control whose only outcome is a 403', and App.tsx confines reviewers to /review, where switching events is not a thing they can do. This is the affordance grammar the mandate states — controls render only when their action is possible — applied to the request as well as the button. Rule: EventSwitcher takes `loading` from useMe alongside `me`, issues the /events fetch only once identity has resolved AND me.role === 'organizer' (a gate must not act while identity loads), and renders null for every other role, so a reviewer's admin shell makes no organiser-scoped request and shows no event control at all.
