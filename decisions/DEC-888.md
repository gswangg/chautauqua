# DEC-888: A Settings edit view speaks the same form vocabulary as every other form: no browser bullets, no native fieldset, and no off-palette colour widget

app/src/pages/settings/TracksRoomsPanel.tsx renders its edit view as bare <h3>/<ul>/<li> with no classes, so it ships browser bullets, default heading sizing, and Delete link-buttons colliding with the value text; its new-track control is a raw <input type="color"> defaulting to #4f46e5, an indigo that exists nowhere in the product palette. app/src/pages/settings/CallForPapersPanel.tsx:347 wraps 'Tracks offered' in a native <fieldset><legend> inside a .chq-settings-row, so the browser's own box and legend cut across the settings grammar, and the status line beneath is orphaned from the control it describes. Rule: a settings edit view is built from the settings row vocabulary (.chq-settings-row label ‖ value, list-style:none lists whose rows are a name ‖ meta ‖ actions grid so an action can never collide with a value), and a colour is chosen from ONE exported enumeration of the product's track swatches — the same list supplies the picker, the default, and the swatch preview, so the palette can never desync from what a picker offers.
