# DEC-253: Mobile bar for public, submit and portal surfaces (390x844), enforced by the render-sweep gate

SPEC J10 requires mobile-friendly public surfaces, and §9 names a phone pass as part of the real bar and lists mobile rendering as a known eval blind spot we cover anyway — yet nothing in the entire history of this repo has ever measured a viewport (grep of docs/verification-log finds no mobile/390/viewport check). The bar, now explicit: at a 390x844 viewport there is NO page-level horizontal overflow (document.scrollingElement.scrollWidth <= window.innerWidth + 1) on /submit/:slug, all five /e/:slug surfaces, session/speaker detail pages, /embed/:slug/:surface, /portal and /login; the public agenda time grid (currently `grid-template-columns: 70px repeat(N, 1fr)` at src/routes/public/agenda.tsx:41, which collapses to ~20px columns at the 15-room scale target) scrolls inside its own `overflow-x:auto` container with `repeat(N, minmax(140px, 1fr))` so it stays legible; primary nav/filter/tap targets are >= 40px tall. Implementation stays CSS-only inside the SSR shells (no client framework, per DEC-022), and the rule is enforced by a second viewport pass in scripts/render-sweep.ts so it is a gate, not decoration.

## Amendment (wave 25): the phone floor binds two named surfaces — /portal/tasks must not scroll sideways at 390, and a 26px search field is not a tap target

Two measured phone failures are real product defects, not instrument artifacts. (1) `/portal/tasks` at 390x844 has 170px of horizontal overflow, widest offender `main.chq-measure w=560px` — `--chq-portal-measure: 560px` (src/views/theme.ts:112) is applied unconditionally by `.chq-portal-shell > .chq-measure` (src/routes/portal/portal.css.ts:291-293), and the phone block at :395-435 sets the three-region column and overflow-y but never constrains the inline size, so the speaker portal — the surface a busy speaker opens on a phone — does not fit a phone. (2) `.chq-submissions-filterbar-search { min-height: 26px }` (app/src/pages/submissions/submissions.css:78-84) is a 26px target against the 44px floor DEC-367 already set. RULING for both: the fix is an additive `@media (max-width: 700px)` override that moves no desktop pixel (scan-lock), and each is pinned by a scan so it cannot drift back — width constraints for the portal column, and a mechanical tap-floor scan over app/src for the rest.
