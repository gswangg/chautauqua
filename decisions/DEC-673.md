# DEC-673: The embed builder speaks the SERVER's vocabulary and never asks the organizer to type an internal id

Three drifts in one panel. (1) app/src/pages/settings/embedSnippet.ts:20 hand-copies the card-field allowlist as five names; the server's src/routes/public/query.ts:56 ALL_CARD_FIELDS is six (DEC-592 added `format`). test/public-embed-config.test.ts:325 pins the SERVER list and nothing binds the SPA's copy to it, so the builder can never produce an embed that shows Format, and any partial selection silently switches Format off too (buildEmbedUrl only omits ?fields= when all FIVE are ticked). The field guide's own rule -- hand-copied vocabularies drift, IMPORT them -- and DEC-660's precedent (one named app/->src/ boundary module) settle the shape: the allowlist moves to pure core and reaches the SPA through one boundary module. (2) EMBED_KNOBS_BY_SURFACE (embedSnippet.ts:38) omits `day` for sessions even though DEC-634 made day a real SQL predicate on that surface, and omits `q` everywhere though every surface honours it -- the table must name what the server actually honours. (3) EmbedsPanel.tsx:147-158 renders "Track ID" as a free-text box the organizer is expected to paste a ULID into, the exact handle-leak DEC-659 closed in the plan editor; the event's tracks are already a fetchable list. Same rule for the accent field's non-palette placeholder and the raw lowercase field keys used as checkbox labels.
