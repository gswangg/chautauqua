# DEC-727: Test tiers are DERIVED by predicate, never hand-listed, and parallelism is capped in config (not the environment)

eval-findings items 72/73 are unfixed on main: vitest.config.ts sets no worker cap (VITEST_MAX_THREADS does not bind the forks pool) and package.json has only `test` + `test:targeted`. The suite must split into `test:fast` (pure domain, scan-lock and enumeration tests — no jsdom, no miniflare, <60s) and `test:full`. The field guide's standing lesson is that hand-listed manifests desync, so tier membership must be computed from an exclusion predicate over the test tree (a file is SLOW iff it matches the jsdom environmentMatchGlobs or imports miniflare/wrangler/unstable_dev/playwright/jsdom) and locked by a test that recomputes it and names offenders. Caps live in vitest.config.ts (`maxWorkers: 2`, `poolOptions.forks.maxForks: 2`) because that is the only place that binds both pools; every full-suite invocation keeps going through scripts/with-test-lock.sh.
