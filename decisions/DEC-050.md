# DEC-050: Per-form locked field ids ('<formId>:<name>') with lockedFieldName() normalization; event creation provisions the default form

form_field.id is a global PK and createDefaultForm inserts the literal ids 'title'/'description'/'first_name'/'last_name'/'email' — already taken by the seeded form — so any second event's Forms page or public CFP crashes, and POST /events creates no form at all. Fix: newly created locked rows use PK `${formId}:${name}`; a pure helper lockedFieldName(id) in src/forms/types.ts (strips an optional prefix up to ':', returns the locked name or null — ':' appears in neither newId output nor locked names) replaces every LOCKED_FIELD_IDS.has(x) membership test; the single row→FormFieldSpec conversion in src/server/repo/forms.ts presents locked fields to the render/validate/submit/edit engine under their canonical short ids so all existing answer-map keys ('title', …) keep working, and seeded plain-id rows remain valid with no data migration. POST /api/v1/events calls createDefaultForm so a fresh event is submittable immediately.
