# DEC-878: The per-submission decision rail is a triage ACTION, not a status picker: Accept is the primary, Decline|Waitlist the secondary pair, and the caption says deciding sends nothing

docs/design "Chautauqua Submissions.dc.html" lines 265-273 render the pending detail rail as an "Awaiting triage · 6 days" eyebrow, a full-width olive Accept, a Decline|Waitlist pair, and the caption "Deciding sends nothing. Notify from Comms." The build (SubmissionDetailPage.tsx:44, 967-991) renders a four-way segmented Status group over ['pending','accepted','declined','waitlisted'], which weights every state equally, demotes the one action the screen exists for, and renders "Pending" as something an organizer chooses rather than the absence of a decision. New rule: the rail offers only the decisions NOT currently in force. Pending -> Accept primary + Decline|Waitlist pair. Already decided -> a stated decision line ("Accepted · <date>", event-timezone), the two other decisions as the secondary pair, and exactly one quiet "Back to pending" link as the only un-decide path. The caption renders in every state, because the no-email invariant is true in every state. The bulk worklist keeps accept_queue/decline_queue; those pipeline states are never set from this rail. This narrows DEC-577/DEC-699 to the control's shape only — the four decidable states and the PATCH they issue are unchanged.
