# DEC-872: A role is a fact about a USER: a note with no user has no role, and the viewer's own note says "You"

VERIFIED. src/server/repo/files-comments.ts:204 writes `authorRole: user?.role ?? "unknown"`, and a portal-posted speaker note has authorContactId set with authorUserId null — so every speaker note renders "(unknown)" at app/src/pages/content/CommentThread.tsx:52. DEC-757 already ruled "an author is a PERSON, never Unknown" and fixed the NAME (throwing when it cannot be resolved) while leaving the ROLE with a fabricated fallback; the sentinel string is the defect, not the missing user. Decision: FileCommentRow.authorRole becomes `string | null` (null exactly when the row has no author user) and the row gains `authorUserId: string | null`; CommentThread omits the parenthetical entirely when the role is null. The viewer's own note reads "You" instead of a raw email, decided by ID (`authorUserId === me.userId` via useMe) and never by comparing display strings (DEC-858's rule). Timestamps become relative through ONE reader: the private `${days} days ago` helper at the top of content/SessionList.tsx moves to app/src/lib/dates.ts as `formatRelativeDays(ms, now)` and both call sites import it, because a second copy of a relative-time formatter is the hand-listed-twin defect in miniature.
