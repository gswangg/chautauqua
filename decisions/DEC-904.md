# DEC-904: A saved view is private until its author shares it

app/src/pages/submissions/ViewTabs.tsx:106-108 records the current state as a deliberate punt — 'saved_view has no owner column (event-scoped only), so sharing is a static caption, not a checkbox toggle the store can't persist' — and the 02-submissions save-view frame carries a real 'Share it with the other organisers' checkbox. A caption standing in for an affordance is the decoration-instead-of-control pattern the affordance grammar forbids, and sharing every organizer's scratch view with every colleague is a behaviour, silently chosen. Rule: saved_view gains created_by_user_id (nullable) and shared (integer, NOT NULL, DEFAULT 1) — the default makes every EXISTING row shared, which is exactly today's behaviour, so the migration changes no user's world; new rows write the author and the checkbox, which is UNCHECKED by default. listSavedViews takes the viewer's user id and returns `shared = 1 OR created_by_user_id = <viewer>` as ONE SQL predicate (never a post-fetch filter), the create route reads the author from requireAuth, and the tab row marks a private view with a quiet 'Only you' micro-label in the DEC-730 family so the reader can tell which of their tabs a colleague can see.
