# DEC-060: Persona verification is modular: scripts/walkthrough/<area>.ts standalone runnables; verify-and-fix tasks repair only their named files

SPEC §9 makes persona walkthroughs the real acceptance bar, and wave 8 executes them. Running one monolithic script from five parallel workers would make scripts/walkthrough.ts (DEC-053, branch task-w7-e still queued at planning time) a five-way merge collision. Decide: each verification area gets its own standalone runnable — scripts/walkthrough/producer.ts, review.ts, speaker.ts, public.ts, data.ts — invoked as `npx tsx scripts/walkthrough/<area>.ts --url http://localhost:8787`, using the same conventions as DEC-053 (cookie jar per persona, form login carrying the chq_csrf cookie value, 'x-chq-csrf: 1' header on JSON mutations, hard exit(1) with a named failing check — fail loudly, no soft warnings). Area tasks never edit scripts/walkthrough.ts or package.json (orchestrator wiring is a later single-owner change). Fix rule: a verification task repairs defects only inside its task-listed files; defects found outside that surface are documented in the commit message body for the next planner, never patched cross-area — this keeps five parallel workers off each other's files.
