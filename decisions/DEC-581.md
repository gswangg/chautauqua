# DEC-581: The hub's visibility predicate and grouping live in ONE pure module; the repo returns candidates, the pure function decides what a stranger may see

docs/design/README.md §Open decisions specifies exactly which events GET / may list (open CFP, or a published programme — never a not_yet_open CFP, never an event with nothing published) and exactly which facts may ride a row (name, dates, venue, CFP deadline, published-session count; NEVER submission counts, review progress, speaker-task health). That is a privacy predicate, and a privacy predicate that lives inside a SQL WHERE clause cannot be exhaustively tested and will be re-derived — differently — the next time someone adds a surface. So src/lib/home-hub.ts owns HubEvent, groupHubEvents(events, nowMs) -> {openCfp, published, past} and hubState(sections) -> 'full'|'between_cycles'|'fresh', as pure functions importing nothing node:/cf; src/server/repo/public/home.ts fetches candidate rows and applies nothing but scope. Grouping is fixed: past when the event has ended; else openCfp when formWindowState(open, close, now, tz) === 'open'; else published. Order: openCfp by soonest close then soonest start; published by soonest start; past newest-first — every tie broken by id so the order is TOTAL (the LIMIT rule). listHubEvents returns {items,total} and the page states the cap when total exceeds it, because a cap the UI can't see lies.
