# DEC-581: The hub's visibility predicate and grouping live in ONE pure module; the repo returns candidates, the pure function decides what a stranger may see

docs/design/README.md §Open decisions specifies exactly which events GET / may list (open CFP, or a published programme — never a not_yet_open CFP, never an event with nothing published) and exactly which facts may ride a row (name, dates, venue, CFP deadline, published-session count; NEVER submission counts, review progress, speaker-task health). That is a privacy predicate, and a privacy predicate that lives inside a SQL WHERE clause cannot be exhaustively tested and will be re-derived — differently — the next time someone adds a surface. So src/lib/home-hub.ts owns HubEvent, groupHubEvents(events, nowMs) -> {openCfp, published, past} and hubState(sections) -> 'full'|'between_cycles'|'fresh', as pure functions importing nothing node:/cf; src/server/repo/public/home.ts fetches candidate rows and applies nothing but scope. Grouping is fixed: past when the event has ended; else openCfp when formWindowState(open, close, now, tz) === 'open'; else published. Order: openCfp by soonest close then soonest start; published by soonest start; past newest-first — every tie broken by id so the order is TOTAL (the LIMIT rule). listHubEvents returns {items,total} and the page states the cap when total exceeds it, because a cap the UI can't see lies.

## Amendment (wave 69): an event is "already happened" only when its last day ENDS where the event happens, and the hub asks for shape aggregates only about rows a stranger can see

groupHubEvents (src/lib/home-hub.ts:68) tests `event.endDate < nowMs`, and endDate is a UTC-midnight DAY LABEL (home.ts's parseDayLabelMs) — so a three-day conference archives itself at 00:01 UTC on its own final day, which is the evening BEFORE that day in every American zone. On the deployment's front door, the running event drops out of "Programme published" (losing its "Browse sessions" action) while attendees are on site. The house rule already exists: dates go through the OWNING EVENT's tz; src/lib/timezone.ts's dayLabelEndInstant(dayLabelMs, timeZone) is the exact expansion the CFP rail already uses. Second half: listHubEvents runs two grouped aggregate scans (distinct tracks over submission_track, distinct formats over submission_answer) across ALL up-to-100 candidate events, including every event the very next step drops — and the 404 eyebrow (src/server/not-found.tsx's resolveNotFoundEyebrow) pays that bill on every bad link and bot probe. Those counts feed only the row shape/size lines of rows that survive grouping. The visibility predicate must not be re-derived in the repo to scope them, so home-hub.ts exports it once (isHubVisible) and both grouping and the repo's scan scope read that one definition.

## Amendment (findings wave 11): the archive bucket cannot inherit a visibility predicate it has no action for, and an unseeded deployment's front door is still a door

Two halves, both verified on main. (1) `isHubVisible` admits an event on `cfpOpen || publishedSessionCount > 0`, and `groupHubEvents` then buckets by date first — so an event that has ENDED, has zero publicly visible sessions, and still has an open CFP window (an organiser who never closed the form: the common case) lands in `past`. In that bucket the cfpOpen half of the predicate is meaningless: an archive row's only action is 'browse the programme', and there is no programme. A stranger gets a link to an empty page — precisely what docs/design/README.md's hidden-rule and DEC-581's own opening paragraph forbid. Ruling: an event enters `past` only when `publishedSessionCount > 0`; otherwise it is dropped from every section. `isHubVisible` keeps its signature and meaning, because src/server/repo/public/home.ts scopes its shape-count scans through it (wave-69 amendment) — the correction belongs to the bucket, not the predicate. (2) `rootRoutes.get('/')` throws ApiError('internal') when `getHubOrg` returns null. No migration inserts an org row (migrations/ contains no INSERT), and `npm run deploy` (package.json:21) is migrations + `wrangler deploy` with no seed — so a freshly provisioned instance 500s on `/`. hubState already has a `fresh` state whose whole definition is 'nothing has ever been published'; a deployment with no org is the limit case of that, not an internal error. Ruling: render `fresh` with empty sections. The masthead names the org, and there is no org to name, so this one state carries the product wordmark — the single exception to 'Chautauqua is named once, in the footer', justified because the alternative is a 500.
