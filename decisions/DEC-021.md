# DEC-021: Agenda API and drag-drop UI contract; slot writes bump ics_sequence

J9's server and UI ship in one task but the shapes bind future callers (.ics, public agenda). GET /api/v1/events/:eventId/agenda returns ONE payload (one round trip per view, SPEC §7): { days (YYYY-MM-DD from event.startDate..endDate inclusive), rooms, tracks (with colors), placed: [{ submissionId, ref, title, trackIds, speakers, roomId, day, startMin, endMin }], unscheduled: [same shape sans placement, accepted-only], conflicts (findConflicts output), summary { unplaced, conflicts } } — conflicts computed server-side from src/domain/schedule.ts. PUT /api/v1/submissions/:id/slot { day, startMin, endMin, roomId? } upserts the schedule_slot (only accepted submissions; else 'invalid'); DELETE unschedules; both bump submission.ics_sequence (DEC-007 caller duty) and return refreshed { conflicts, summary }. Conflicts NEVER block writes (DEC-010). POST /api/v1/events/:eventId/agenda/auto-schedule { dayStartMin=540, dayEndMin=1080, defaultDurationMin=30, gridMin=15 } runs the greedy autoSchedule() over unplaced accepted sessions against existing placements, persists results, returns the full agenda payload. UI: day tabs; CSS grid columns=rooms, rows=15-minute increments; unscheduled tray as drag source with count; HTML5 drag-drop for place/move/unschedule rendered optimistically with rollback on ApiError; per-card conflict warning chips; live 'N unplaced · M conflicts' counter; track colors as card accents.

## Amendment (wave 55): unscheduling must have a non-drag path -- the armed placed card carries an explicit Unschedule action

UnscheduledTray's onDropUnschedule fires exclusively from a drop handler, and the tray's own footer hint says so ('Click a session, then click a time slot - drag back to unschedule'). Placing already has a keyboard/click path (arm a card, click a slot); removing does not, so a keyboard-only or pointer-imprecise organiser can place a session and never take it off. HTML5 drag-and-drop is not keyboard-operable, and this repo enforces 44px targets, visible focus rings and aria elsewhere -- a drag-only mutation is the one hole left in that policy. Ruling, following the house conditional-and-quiet affordance grammar (controls render only when their action is possible): arming a PLACED card reveals an Unschedule action in the already-reserved armed bar, next to the move affordance, and the tray becomes a click target for an armed placed card. Drag keeps working unchanged -- this adds a path, it does not replace one -- and the tray hint is updated to name both paths, since a hint that omits the accessible path is the same lie as a comment claiming a check.

## Amendment (wave 60): the post-write agenda reconcile reads PLACED sessions only, and every agenda-scale scan is bounded

DEC-021 makes the agenda payload one round trip, but the drag-drop write path reconciles through getConflictsAndSummary (the former src/server/repo/agenda.ts:528-557 (now split across src/server/repo/agenda/)), which calls loadAcceptedSessions — an UNBOUNDED select of every accepted submission in the event (:222-226, no limit) plus three chunked fan-outs over all of them (tracks, participants, slots) — to build a set it then immediately filters down to the ones holding a slot. Every drag, drop and unschedule therefore pays a cost proportional to the whole accepted set, not to the placed set, against a SPEC section 7 budget of writes p95 < 100 ms at 500-5,000 submissions per event; and src/server/repo/overview.ts:363-375 repeats the same uncapped read on the dashboard. Every other scan of this class in the tree already refuses loudly at a named ceiling (MAX_REMINDER_SCAN, MAX_CONTACT_DIRECTORY_SCAN, EXPORT_MAX_ROWS) — this one has none, so at the top of the design range it silently degrades instead of saying so. RULING: (1) ONE exported MAX_AGENDA_SCAN ceiling applied to both the accepted-session scan and the placed-slot scan, refusing with a named ApiError rather than truncating; (2) getConflictsAndSummary stops loading the accepted set at all — it drives from schedule_slot joined to accepted submissions, hydrates only those ids' active participants, and takes scheduleSummary's totalAccepted from a count(*), so the highest-frequency producer action costs O(placed) + 1 count. getAgendaPayload keeps loading the accepted set (it owns the unscheduled tray) and only gains the ceiling. Conflict prose and payload shapes are byte-identical — this is a read shape change, never a semantics change.

## Amendment (wave 65): a break an organiser cannot create is a seed artefact — the agenda page owns break CRUD

Wave 63 landed the whole break stack except the way in: `schedule_break` in the schema, `src/server/repo/breaks.ts` (list/count/create/ownership/delete, capped at MAX_BREAKS_PER_EVENT with a loud refusal), `src/routes/api/breaks.ts` (organizer-only, org-scoped through the owning event, csrfJson on writes, day-within-event-range validation), mounted at src/index.ts:59 and documented at src/routes/docs.tsx:204-206. There is no UI: grepping app/src for `break` returns only `word-break`/`line-break` CSS. So the only writer of a break row is the seed, and wave 64's public agenda is about to render "COFFEE · FOYER · 15 MIN" rules that no producer can add, move or remove — a decision with no code, in the direction that is hardest to notice because the demo data hides it. Ruling: the organiser's agenda page (DEC-021's own surface) gains a quiet Breaks section scoped to the selected day — list, add, remove — driven entirely by the existing three endpoints, with per-field errors surfaced from the API's `{error:{code,message,fields}}` envelope. The hard boundary in src/server/repo/breaks.ts's header is restated and enforced by scope: a break is not a submission, so this touches neither the placement math, nor the conflict engine, nor auto-schedule, nor any export/.ics/feed path. Rendering breaks as bands inside the organiser day grid is deliberately NOT in this ruling — the grid's row-map arithmetic is load-bearing and gets its own wave.

## Amendment (wave 67): the organiser's day grid RENDERS breaks (read-only), while placement stays warn-never-block

`app/src/pages/agenda/BreaksPanel.tsx:8-14` states its own deferral verbatim: "Rendering breaks as spanning bands inside the day grid is deliberately out of scope this wave." The result is that the producer types lunch into a panel beside the grid and the grid shows nothing — the same 'stack lands where its consumers learn of it' failure wave 66 found in the scheduler, one surface over. RULING: the day grid renders each break as a full-width spanning quiet band, positioned by the SAME `gridMath` start/duration arithmetic placed cards use, carrying the label in small caps. It is presentation only: it is not a drop target, it is not a submission, it never enters the conflict engine, auto-schedule, the unscheduled tray, or any export path, and the cells beneath it stay droppable — J9 is warn-never-block, so the HAND may still place over a break even though (per wave 66's DEC-010 amendment) the MACHINE may not. Corollary: the day's break list becomes ONE read owned by `Agenda.tsx` and passed to both the grid and the panel, so a create/delete updates both in the same tick rather than two components polling the same endpoint.

## Amendment (wave 69): a break stranded outside the event window by a date move keeps a way in — the Breaks panel lists out-of-window rows in their own named group

POST /events/:id/breaks validates day within the event range (src/routes/api/breaks.ts:105), so the only way to strand a break is to MOVE the dates — which wave 68 just made visible by returning breaksOutsideWindow from PATCH /events/:id and naming it in Settings. But the only screen that can delete a break scopes itself to the day the grid is showing (app/src/pages/Agenda.tsx:119 fetches ?day=<activeDay>, and activeDay comes from the payload's computeDays window), so the rows the notice names are unreachable and undeletable in the product. A report that names a kind of thing must be answerable; the fix is one whole-event read (GET /events/:id/breaks is already unscoped and bounded by MAX_BREAKS_PER_EVENT) partitioned client-side, and a second quiet group that renders only when it has rows.

## Amendment (wave 72): the breaks EDITOR is a disclosure on the head row, not a band that displaces the canvas

Gate-4 measured `.chq-breaks-panel` (label + rule + rows + a 4-field add form) sitting between the agenda head and the grid, costing 308px: the frame shows ~687px of grid at a 900px viewport against the app's 333px. v7 designed the PUBLIC breaks display, never an admin editor, so this is a real design gap rather than a fidelity slip — and the capability must not be deleted (w69-c's outside-window group is the only screen that can remove a stranded break). Ruling: the agenda canvas is a canvas; a secondary editor for a non-session object lives behind a disclosure on the head row and opens in the ONE shared dialog frame (ModalFrame, DEC-651), keeping the panel's component and props byte-identical so the day-scoped list, the outside-window group and the shared refetch are untouched. The control renders whenever the panel itself would have rendered (a selected day OR a non-empty outside-window set), so the stranded-break path keeps its way in. The day-tab row regains the frame's two full-width rules, bleeding by absence per DEC-989.


## Amendment (wave 6): the day grid draws ONE lattice tone at 30-minute pitch, and the gutter prints the frame's unpadded 24h grammar

DEC-021 owns the agenda grid's geometry. Gate-4 recorded the 30-minute pitch as exactly frame-correct (44.0) but measured the lattice drawing 36 horizontals where the frame draws 18, in two tones (#D3CFC0 at the 30-minute lines, #E1DDCE at a 15-minute midpoint) against the frame's single #EDE9DD — the rows are right and the rules are wrong, which reads as a denser grid than the design. The same report closes the three-time-grammar defect but records the residue that the gutter zero-pads (`09:00`) where the frame reads `9:00 / 9:30 / 10:00`, in both the visible label and the aria text. Ruling: one rule tone, one rule per 30-minute row (the 15-minute midpoint rules are dropped — placement arithmetic still resolves to 15-minute increments, only the painted lattice changes), and ONE gutter formatter with no zero pad feeding both the label and its aria string. The z-index token contract (DEC-900, pinned by agenda-overlay-zindex.test.ts's total-declaration count) and the frozen phone media blocks are out of scope and must be left untouched.
