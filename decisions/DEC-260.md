# DEC-260: Multiple CFP forms per event stays out of stage 1; one form with track options is the shipped model

docs/clarifications.md reads "Single CFP form with track options is right; multiple forms creatable after." SPEC J1 correspondingly says the producer "opens the default submission form" (singular) and sets "one or more tracks on the form". The code matches: src/routes/api/forms.ts exposes GET /events/:eventId/forms, PATCH /forms/:formId and the field CRUD, with no create-form route, and one form is auto-created per event.

Recording this as a decision so that no wave-3 lane reads the clarification as an unimplemented requirement and invents a form-creation surface (new public /submit/<slug>/<form> routing, a form picker, per-form close dates and track sets) at the end of the campaign, where the regression risk to the most-exercised path in the product vastly exceeds the value. Track options on the single form satisfy swyx's stated need ("talks are submitted to one or more tracks").
