# DEC-985: HTML_ROUTE_EXCLUDED holds only routes that render no HTML or cannot be visited idempotently — every other GET route is in ROUTE_MANIFEST

test/audit-claims.test.ts's exclusion list carries four entries whose stated reason is a PRE-EXISTING GAP flagged for a follow-up task that was never scheduled, and one of them is GET / — the anonymous event hub the v2 design handoff added (DEC-581/582, src/routes/root.tsx), the largest new public surface in the product, which gate:render-sweep has therefore never once visited. The other three (/portal/resources, /dev/mailbox/:emailId, /embed/e/:embedId) each named missing seed data as the obstacle; the tree has since grown all of it — scripts/seed.ts seeds email_log rows (seed_email_log_0001) and, since DEC-887, two saved-embed rows (seed_embed_0001, enabled). An exclusion list is a promise about a route's nature, not a parking space for work: the only reasons that may stand in it are "provably renders no HTML" (binary/JSON/ICS/302) and "cannot be visited idempotently" (/claim/:token mints a single-use grant and burning it would corrupt the seed). Everything else takes a manifest entry with a deterministic seed literal, so the sweep's coverage assertion is what discovers the next unswept page.
