# DEC-850: A saved embed's single URL serves its SAVED format; a recipe that stores a format and always answers HTML is lying about the recipe

VERIFIED: the embed row carries `format` from the closed EMBED_FORMATS vocabulary (iframe|element|link|json|xml|ics, src/lib/embed-formats.ts) and PATCH /api/v1/embeds/:id validates it, but GET /embed/e/:embedId (src/routes/public/saved-embed.tsx) never branches on it — it always calls renderSurfaceContent and returns c.html(EmbedShell). Meanwhile SavedEmbedsPanel.tsx builds its row snippet with buildSnippet(url, surface, format), so an embed saved as `json` shows a bare-URL snippet pointing at a URL that answers an HTML document. Decision: the saved id resolves in its saved format. iframe/element/link render inline as today. json/xml/ics answer a 302 to the canonical per-surface feed route the generic builder already targets — `/embed/<slug>/<surface>.json`, `.xml`, and (per DEC-289, mirrored in buildEmbedUrl) the fixed `/e/<slug>/agenda.ics` — carrying the saved options as query params. A redirect rather than a second inline implementation, because the feed routes are the ONE place each envelope is built and a saved embed must not become a fork of them.
