# DEC-289: Public/embed URL contract: shared query params on both /e/ and /embed/, output format is a PATH SUFFIX, and every knob is a validated allowlist that degrades to today's behavior

EMB-15 needs 'output format, branding/colors, content filters, and field selection' and three separate tasks must produce mutually consistent URLs without talking, so the contract is fixed here. QUERY PARAMS (parsed in src/routes/public/query.ts, all optional, an invalid value parses to null/default and NEVER throws or 500s; absent param == today's behavior exactly): `q`, `trackId`, `page` unchanged; `limit` = integer 1..100, sessions surface only, overrides PER_PAGE (shell.tsx:15); `day` = /^\d{4}-\d{2}-\d{2}$/, agenda + schedule surfaces only, filters the already-fetched item array (no repo change); `fields` = comma list from the allowlist {track,time,room,speaker,description}, sessions surface cards only, unknown names ignored, absent-or-empty == all five (title and its detail link ALWAYS render and are not in the allowlist); `accent` = 3- or 6-digit hex WITHOUT '#' matching /^[0-9a-fA-F]{3}$|^[0-9a-fA-F]{6}$/, normalized to '#rrggbb' lowercase, honored by EmbedShell ONLY (it overrides event branding's accentColor for --chq-accent) and ignored on PublicShell — anything that fails the regex parses to null so no unvalidated text ever reaches a style attribute. OUTPUT FORMAT IS A PATH SUFFIX, never a ?format= param, so Content-Type and cache keys stay unambiguous and the existing /e/:eventSlug/schedule.ics precedent (src/routes/public/index.tsx:130) is followed: `/embed/:eventSlug/:surface` = HTML (unchanged), `/embed/:eventSlug/:surface.json` = JSON, `/e/:eventSlug/agenda.ics` = the full published agenda as iCal. JSON envelope is `{ event: {slug,name,timezone,startDate,endDate}, surface, generatedAt, items: [...] }` — flat `items` per the house convention, items reusing the existing PublicSession/PublicSpeaker/agenda shapes verbatim. NO XML and NO <script> loader: the sanctioned format set is iframe HTML + plain link + JSON + iCal, four formats, all of which are real endpoints we can test, rather than a fifth that needs a served JS asset and its own CSP story. Every feed route reads src/server/repo/public.ts exactly like the HTML surfaces, so the visibility gate (accepted + content-approved + participant.visible + inviteStatus) is single-sourced and a feed can never leak what a page hides.
