# DEC-071: {portal_link} always resolves to an absolute URL built from the request origin

Decision emails (src/routes/comms.ts:218-229) and CRM bulk email (the former src/routes/api/contacts.ts:346-351 (now split across src/routes/api/contacts/)) resolve {portal_link} to bare '/portal' or '/claim/<token>' — dead links in any real mail client, while the submit confirmation already does it right with `${origin}/claim/...` (src/routes/public/submit.tsx). Rule: resolvePortalLink takes an origin parameter; routes compute it as new URL(c.req.url).origin; rendered links are `${origin}/portal` or `${origin}/claim/${token}`. Stage 2 may later pin a canonical base URL via config; stage 1 uses the request origin, matching the existing precedent.
