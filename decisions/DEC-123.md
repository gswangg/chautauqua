# DEC-123: Plan criteria and scale are immutable once any evaluation exists on the plan: PATCH /api/v1/plans/:id returns 409 conflict, with a deep-equal no-op exemption

PATCH /api/v1/plans/:id (the former src/routes/review.ts:193 (now split across src/routes/review/)) accepts a criteria (or scale) replacement with no guard; once evaluations exist, buildResults -> aggregateSubmission throws 'missing score for criterion' (src/domain/evaluation.ts:92) and GET /plans/:id/results plus the CSV export (J4/ABS-10) 500 for every round, with no recovery path. Criteria and scale define the semantics of recorded scores, so replacing them after scoring corrupts existing evaluations' meaning. Ruling: add repo helper planHasEvaluations(db, planId) (any round, LIMIT 1); when the PATCH body contains criteria or scale and evaluations exist, reject with ApiError('conflict', ...) (409, code already in ApiErrorCode) UNLESS the submitted value deep-equals the plan's current value (JSON-normalized compare) — the exemption keeps full-object PATCHes from the admin SPA working for benign edits (name, dates, instructions, etc., which all remain editable). Recovery for a producer who genuinely needs different criteria is a new plan or deleting the evaluations, both already supported.
