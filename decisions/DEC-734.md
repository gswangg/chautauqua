# DEC-734: A duplicate group carries the identity fields the merge screen shows, and 'Keep both' is a first-class outcome

Verified on main: MergePage draws the group from GET /contacts/duplicates and the merge preview from the server's own fold (DEC-705 — keep that), but the duplicates payload has no company/title, so the merge page's identity columns render '—' while the directory shows values. The fix belongs in the payload, not in a second by-ids fetch. And a duplicates list with only 'Merge' forces a wrong irreversible action: 'Keep both' (dismiss the pair) and a pair counter are what make the tab workable. Add-to-event's ROLE control (absent for a third cycle) uses the app's own imported role vocabulary per DEC-714 — a hardcoded role is an invisible policy.
