# DEC-454: One canonical email rule (src/domain/email.ts), applied at every contact.email write and every lookup by email

Verified on main: there is NO email-format check anywhere in src/ (repo-wide grep for a validator returns only src/routes/api/contacts/bulk-email.ts, which is an unrelated match). src/forms/validate.ts has no `email` field kind and src/forms/types.ts's FormFieldKind is text|long_text|dropdown|checkbox|number|file, so the locked CFP `email` field is validated only as free text; src/routes/public/submit.tsx:652 then does String(...).trim().toLowerCase() and hands the result to findContactByEmail (src/server/repo/submit.ts:112-128, `lower(contact.email) = lower(email)`). A whitespace-only address therefore becomes "", the first such submitter mints a contact with email "", and every later blank submitter is bound to that same contact -- inheriting its portal and its claim token. Separately src/routes/api/contacts/crud.ts:88 stores `body.email` verbatim, so "Alice@Example.com " (trailing space) never matches the lower()-compared CFP lookup and silently forks a duplicate contact. The remedy is ONE rule stated once so no worker invents a second one: a new pure-core module src/domain/email.ts exporting MAX_EMAIL_LENGTH = 254, MAX_EMAIL_LOCAL_LENGTH = 64, normalizeEmail(raw) = raw.trim().toLowerCase(), and isValidEmail(raw) which tests the NORMALIZED form against /^[^\s@]+@[^\s@.]+(?:\.[^\s@.]+)+$/ plus the two length caps. "a@b" (no dot) is invalid on purpose -- this is a public CFP, not an intranet directory. Every ingress that writes contact.email or looks a contact up by email validates with isValidEmail and stores normalizeEmail: the CFP path (through validateAnswers, keyed on lockedFieldName(field.id) === "email"), POST/PATCH /api/v1/contacts, and the CSV import. src/domain/email.ts is pure core under DEC-002: no node:/cloudflare/drizzle imports.
