# DEC-037: Email HTML built only via escapeHtml/textToHtml in src/mail/render.ts

Five send sites interpolate user- or producer-controlled text into HTML bodies raw (comms.ts:259, api/contacts.ts:411, public/submit.tsx:398, review.ts:309, repo/tasks.ts:498); the dev-mailbox iframe sandbox masks it in stage 1 but the stored body_html is delivered verbatim once the Resend adapter lands. Canon: src/mail/render.ts exports escapeHtml(s) (escapes & < > " ') and textToHtml(text) (escape, then blank-line-separated <p> blocks with <br/> for single newlines). Every mailer.send html field is built from these; renderTemplate must never be called with an HTML template whose vars carry user content. Anchors are built by callers with both href and text escaped.

## Amendment (wave 24)

HTML is the sixth wire format, and it gets one escaper owner (src/lib/html-escape.ts) like the other five. Wave 23 pinned ICS, MIME, XML, CSV and Markdown-to-HTML to one serializer each. HTML escaping — the output language every one of those five ultimately shares a page with — has THREE definitions: src/mail/render.ts:155 (escapeHtml, the DEC-037 sanctioned one), src/lib/markdown.ts:16 and src/server/http.ts:209 (escapeHtmlText). They are byte-identical today, which is exactly the state that precedes drift: the field guide already records SECOND READER INHERITS NO MANNERS and HAND-TYPED LIST FORGETS 3RD MEMBER, and this codebase has twice shipped a security-relevant escaping rule to one copy and not its siblings. All three feed dangerouslySetInnerHTML or a raw HTML string, so a future rule (stripping C0 controls, escaping backtick) applied to one copy and not the others is a live hole. Ruling: one pure owner at src/lib/html-escape.ts; mail/render.ts keeps textToHtml and becomes a consumer; DEC-037's 'only sanctioned path' clause now names the owner, not the mail module. No compatibility re-export (house rule) — the two importers of escapeHtml-from-mail/render move. src/routes/public/feeds.ts's escapeXml stays separate and ledgered: different entity set (&apos;) plus XML 1.0's control-byte stripping.
