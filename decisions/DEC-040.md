# DEC-040: Form-answer file uploads: file rows kind 'attachment', answer = file id

J1 promises a file question type, but the public form posts without enctype and extractAnswers stringifies File objects, so file answers are silently broken. Design: the submit form posts multipart/form-data; file-kind answers upload only at final submit (KV drafts never persist file selections); each upload is validated with validateUpload (src/domain/files.ts allowlist + size caps, stated in the UI), stored via makeFileStore under a random key, and recorded as a file row with kind 'attachment', submissionId, and uploadedByContactId; the submission_answer value is the file.id string that forms/validate.ts already expects. Serving goes through the existing authenticated /files route — never a new unauthenticated path. 'attachment' joins presentation/poster/handout/headshot as the fifth file.kind.
