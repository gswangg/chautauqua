# DEC-766: Every send ATTEMPT writes an email_log row; failure is a status, not an absence

VERIFIED: src/routes/comms.ts:507-510 catches a mailer rejection, console.errors it, and pushes to a `failed` array -- nothing is written to email_log, because DevSinkMailer only writes the row AFTER a successful send. A fully-failed batch therefore leaves "0 total" in history, which the SPK grader hit. SPEC J5 says "every message logged per-recipient in history" and product principle 4 makes communications deliberate and auditable; the case where the audit matters most is precisely the one that currently leaves no trace. Decision: on a per-recipient failure the sender writes an email_log row with the same batchId, the rendered subject/body, provider, and status:'failed' (plus the error text), so listEmailBatches' statusCounts reports it and the batch appears in history with an honest tally. Same rule for the contacts bulk-email fan-out. This is not defensive error-swallowing -- the failure still surfaces loudly in the response; the row is the record that it happened.
