# DEC-639: The Sessionboard importer gains a fourth entity, `participants`, whose identity is the resolved (submission, contact) PAIR — it mints no external_ref of its own

steal-mandate §5 layer 1 requires "contacts + submissions + tracks + participants"; the tree ships only the first three (src/domain/sessionboard.ts:20), so an imported event today has sessions with no speakers — empty public /speakers, no speaker double-booking to detect, no comms recipients. The `participant` table has no external_ref column and already carries a uniqueIndex on (submission_id, contact_id) (DEC-556, migration 0019), so the database already names the identity: resolve the row's session ref through submission.external_ref and its speaker ref through contact.external_ref (or email), and let the pair be the key. Minting a third namespace would mean a migration plus a second truth for an identity the schema already enforces.
