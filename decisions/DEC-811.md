# DEC-811: A malformed cookie is external input, not an invariant — parseCookies never throws

VERIFIED src/auth/cookies.ts:60 calls decodeURIComponent(value) unguarded, and src/server/middleware.ts:201's sessionLoader runs parseCookies on EVERY request. One stray percent-escape in ANY cookie on the domain (`foo=100%`, set by anything on that host) throws URIError and turns every route — including anonymous /e/:slug public pages and /embed — into a 500 the visitor cannot clear. The house rule is fail loudly for INTERNAL invariants; a browser-supplied Cookie header is a system boundary, the textbook exception. Decision: the decode is attempted per cookie, and a cookie whose value will not decode keeps its RAW value — that one cookie only, never abandoning the header. This is not a silent default: every value we mint (session token, csrf token, draft token) is base64url or hex, so the raw value is byte-identical to the decoded one for everything we own, and the fallback only ever applies to values some other writer put on the domain. No route-level catch is added anywhere; the fix lives in the one parser.
