# DEC-615: Auto-schedule reports a reason per unplaced session, from a closed vocabulary with one renderer

autoSchedule returns { placed, unplaced: { submissionId, reason }[] } where UnplacedReason is a closed union: 'no_rooms_configured' | 'duration_exceeds_day' | 'no_free_slot' | 'speaker_double_booked'. Prose lives in exactly one describeUnplaced(reason, labels) sitting beside describeConflict — the enum never carries prose and the renderer never invents a reason. Placement behaviour is unchanged (same greedy order, same output placements); this is reporting only. Copy rule: name the constraint, promise nothing — 'No free 45-minute slot in any room on any day', not advice about widening the day.

## Amendment (wave 43): the unplaced COUNT and the unplaced REASON LIST are one population — an out-of-range slot is unplaced for the placer too, under a named reason

Ledger 0195 (`task-w36-f`, AIE scale battery) graded `autoSchedule320` FAIL: `unplacedTotal=298` vs `reasons.length=237`, 61 accepted sessions unplaced with no reported reason, owner `src/server/repo/agenda/auto-schedule.ts`. Wave 36 filed it; waves 37-42 never picked it up. Root cause, located at my own runtime: `runAutoSchedule` builds `existing` from `s.slot !== null` (auto-schedule.ts:58-59) and `unscheduledAccepted` from `s.slot === null` (:70), so a session holding a slot whose day falls OUTSIDE the event's [startDate, endDate] window is credited as already-placed and never enters the placer — while `getAgendaPayload` classifies that same session as `unscheduled` (payload.ts:59, via `isDayWithinEventRange`), and DEC-318's SQL twin `slotWithinEventRange` (`public/gates.ts:65-67`) already rules such a slot must never publish. Two readers, one rule, three spellings. RULING: the day-range gate is the ONE predicate that decides placed-vs-unplaced for every reader. `runAutoSchedule` splits `accepted` into three buckets: in-range slots (`existing`, fed to the placer as today), out-of-range slots (never fed to the placer — re-placing would require overwriting an existing `schedule_slot` row, which DEC-552/DEC-492's `onConflictDoNothing` deliberately forbids — instead reported as `UnplacedSession` with a NEW reason literal `slot_outside_event_range`), and slotless sessions (fed to the placer as today). `unplacedReasons` therefore covers the whole unplaced population and `runAutoSchedule` asserts `unplacedReasons.length === payload.summary.unplaced` (fail loudly; both sides now derive from one `loadAcceptedSessions` read and one predicate). The superset caveat in `AgendaPayload.unplacedReasons`'s docstring (`agenda/types.ts:54-58`) survives only for the plain GET, which returns `unplacedReasons: []` because it never ran the placer — it is no longer true of a POST run, and the docstring must say so. Non-destructive by choice: the stale slot row is left in place and named, not deleted, so the organizer is told what to fix rather than having a placement silently removed.
