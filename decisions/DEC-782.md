# DEC-782: A public detail page owes the reader every action its card offered, and the same date grammar

VERIFIED src/routes/public/detail.tsx:18-21 — sessionTimeLabel returns `${day}, ${formatMinutes(...)}`, i.e. the raw ISO day ("2027-05-12, 09:00") the EMB probe reported, even though the same module's sibling ./cards.tsx already exports formatDay and every list card uses it. VERIFIED the same file renders NO itinerary control on SessionDetailContent although the /sessions card has carried Save/Saved since DEC-683 (cards.tsx:165-173) — the EMB missing-capability shortlist names "session DETAIL page lacks the Save/itinerary control its list card has". Decision: SessionDetailContent renders the SAME `.chq-itinerary-toggle` + `.chq-pub-save-off`/`.chq-pub-save-on` markup the card uses and mounts ItineraryScript itself when base === "/e" (never inside /embed — mirrors sessions.tsx:176, where an embed's links must not break its iframe), and every day printed on either detail page goes through formatDay. One markup vocabulary, one store, one script: a second checkbox implementation would be a second source of truth for the visitor's picks.
