# DEC-254: Wave-1 browser persona passes: lane-scoped fix authority, a regression test per fix, greppable log

SPEC §9.1 makes persona walkthroughs — not the scripted harness — the highest-authority verification layer, and the last browser-driven pass (docs/eval-findings.md, live production) ran BEFORE the section-A/B/C fixes landed; those fixes were verified afterwards only by unit/contract tests, the swarm's own walkthrough script, and the render-sweep gate — all of which test what the swarm believes it built. Every browser-agent finding in the last round (reviewer assignment 'User not found', queue links to /submissions/undefined, silent no-op CRM merge) was invisible to those gates. So each J-area gets one lane that drives a real chromium browser against its OWN freshly migrated+seeded `wrangler dev` (own git worktree, own port 88NN so lanes never share .wrangler state or ports), logging in with the fixture personas from docs/fixtures/sample-data.json against event devflow-conf-2027, and clicks the job through as that persona would. Fix authority is scoped to the files named in the lane's task; any defect needing another lane's files, a schema/migration change, or a new design decision is LOGGED, not fixed. Every fix ships a regression test; `npm run build` and `npm test` must be green before finishing. Each lane commits exactly one new log file docs/verification-log/task-w1-<x>-<scope>.md, headed '# task-w1-<x> — <scope> @ <sha>' (DEC-129 homonym guard) and ending with machine-greppable 'OPEN ITEMS: <n>' and 'RESULT: PASS|FAIL — <summary>' lines. A clean PASS with zero open items is a fine outcome — the deliverable is evidence, not invented work. No lane edits decisions/, src/decisions.ts, field-guide/ or docs/eval-findings.md.
