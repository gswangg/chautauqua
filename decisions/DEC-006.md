# DEC-006: Mailer port, dev sink, merge-field rendering

Port: interface Mailer { send(m: RenderedEmail): Promise<void> } with RenderedEmail = { to: { email, name }, subject, text, html, ics?: { filename, content }, templateId?, eventId, contactId }. Stage 1 ships exactly one implementation, DevSinkMailer, which takes an injected EmailLogWriter port and writes one email_log row per recipient with full rendered content inline (columns: subject, body_text, body_html, ics_text, provider='dev', status='sent', sent_at) — viewable at /dev/mailbox. Merge fields are single-brace '{name}' placeholders rendered server-side from an explicit whitelist: {speaker_name}, {talk_title}, {event_name}, {portal_link}, {due_date}, {task_list}, {feedback}; rendering an unknown placeholder or a missing value THROWS (fail loudly) — no silent blanks in emails to real speakers. The 100-recipient cap and per-recipient preview live in the compose/send service, not the port. Resend is a stage-2 second implementation of the same interface.
