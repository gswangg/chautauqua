# DEC-770: "Not a duplicate" is a persisted fact about a pair, not a session mood

VERIFIED: app/src/pages/contacts/DuplicatesView.tsx:41-45 keeps dismissals in React state with an explicit comment that there is no persisted store; "Keep both" makes zero network requests and reverts on reload, and MergePage's "Not a duplicate" only passes one-shot nav state. A control whose effect vanishes on reload is decoration, and a duplicates tab that keeps re-proposing a pair the organiser has already judged is a tab organisers stop reading. Decision: a `contact_duplicate_dismissal` table keyed on the org plus the ORDERED (lower id, higher id) contact pair, with a unique index on that triple; both controls POST it, and findDuplicateGroupsForOrg excludes dismissed pairs server-side (never a client filter -- the count and the list must agree). Merging a dismissed pair is still allowed; deletion of either contact makes the row inert. This is the wave's only schema change, deliberately, so the drizzle snapshot numbering has one owner.

## Amendment (wave 48): a dismissal names a PAIR — when either side stops existing the row is deleted, and every contact-referencing column is enumerated against the merge/delete manifests

`contact_duplicate_dismissal` (src/db/schema/crm.ts:81) is written and read ONLY by src/server/repo/contacts/merge.ts. It is absent from `buildMergeRepointOps`' seven-table repoint set AND from `deleteContact`'s cascade (src/server/repo/contacts/crud.ts:256-268), so deleting or merging a contact leaves dismissal rows naming a contact that no longer exists, and `loadDismissedPairKeys` reads those stale rows on every duplicates scan forever. A dismissal is a judgement about a PAIR, so once one side is gone the fact is meaningless: DELETE it, never repoint it onto the keeper (the user never judged that pair). The generalisable rule is the manifest one, not the hand list: `contact_duplicate_dismissal` is a table added four waves after the original seven-table set and slipped past both paths silently. Going forward, the set of contact-referencing columns must be ENUMERATED against the schema (a query or lint over `crm.ts`'s `references(() => contacts.id)` columns, not a literal array), and any column found in neither the merge-repoint set nor the delete-cascade set fails the check rather than being silently skipped.
