# DEC-708: A person is named by their contact, resolved from the account by ONE batched rule; an unresolvable account shows its email, never an invented name

Reviewer rows render raw emails because the progress route only has user rows. The product already owns the account<->contact rule in findAccountUserId/findAccountUserIds (contact id, else org-scoped email match, DEC-530); the missing direction is its inverse. Adding batchUserDisplayNames as the single batched account->contact resolver keeps the rule single-sourced and bidirectionally contract-testable, and forbids the two tempting shortcuts: a per-row query (N+1) and a fabricated name derived from the email's local part. When no contact resolves, the email IS the identity -- absence is rendered as absence.

## Amendment (wave 5): every actor line renders a display name, never a raw email, and a history entry carries a time

CNT graders measured file comments and session history rendering "sbek-organizer@example.com" with date-only stamps. The batched display-name reader already exists and is already the single source for reviewer names (repo.batchUserDisplayNames, used by /plans/:id/progress and /remind). Any surface that names a person joins that reader rather than falling back to the login identifier, and any timestamp that records an action prints the time as well as the day -- a same-day sequence is unreadable otherwise.
