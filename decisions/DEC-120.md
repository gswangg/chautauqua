# DEC-120: Task-assign contact org-scoping: POST /api/v1/tasks/:id/assign rejects contactIds outside the caller's org (400 invalid, atomic, chunked batch check)

src/routes/tasks.ts:229 passes client-supplied contactIds straight to assignTask's blind insert with no ownership check, violating SPEC §6 'object-level ownership checks on every fetch-by-id (no IDOR)': an organizer can attach another org's contacts to a task, leaking their PII into the onboarding grid and targeting them with reminders. Fix at the route boundary, before any insert (DEC-019 atomicity): dedupe the requested ids, batch-load them via a new repo helper findContactsForOrg(db, ids, orgId) in src/server/repo/contacts.ts (chunked via chunkIds per DEC-078/104), and if any requested id is missing from the result throw ApiError('invalid', ..., { contactIds: 'unknown ids: <list>' }) — no partial assignment ever occurs. assignTask itself stays unchanged; scoping is the route's job, matching the existing pattern at src/routes/api/submissions.ts:152.
