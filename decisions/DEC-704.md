# DEC-704: A bulk action's label states the scope it actually SENDS; the deadline strip's order is fixed and only the nearest is emphasised

Overview.tsx:255-261 renders "Remind all {payload.overdueTasks.total}" but posts `rows.map(r => r.taskId)` — the ROW_CAP'd page, not the total. That is the same class as the field guide's "a cap the UI can't see LIES": the honest fix is that the button names its own scope and the section separately states how many more exist and where to see them, so no label ever over-promises the request behind it. Second, app/src/pages/overview/rows.ts:67-90 SORTS the four deadline cells nearest-first, so the strip's columns move under the reader between visits; the mock fixes the order (CFP, Tasks, Review wave N, Doors) and uses weight — not position — to say which is nearest, because a strip whose columns migrate cannot be read at a glance. 'Review wave' also carries its round number: a label that omits the one number distinguishing this wave from the next is not naming anything.
