# DEC-747: Every Settings section is a read view with ONE action on its rule; the rail is SEVEN, and Import from Sessionboard is a row inside Your data

DEC-728 established the summary/drill-in pattern and w1-b landed SummarySection.tsx, but only EventSettingsPanel consumes it — Tracks and rooms, Public pages, Speaker portal, People, Exports and Tokens are still edit-everything forms, which is the mandate's single most divergent surface. docs/design/Chautauqua Settings.dc.html:103-233 fixes each section's read view exactly: Tracks and rooms = two columns of name + count with "Add" on the rule; Public pages and embeds = name · path · state · "Embed code" per row; Speaker portal = Welcome note / Speakers can edit (pills) / Onboarding tasks / Resources (name · detail · Replace, plus "Add a resource") / Access, with "Open as a speaker" on the rule; People and roles = name+email · role · scope · "Change" per row with "Invite someone" on the rule; Your data = Exports (four pills) / API tokens (name · mask · last used · Revoke + "New token") / API docs link. The pack has no eighth section, so "Import from Sessionboard" becomes a labelled row inside Your data that drills into the existing three-step panel, and the rail renders exactly seven entries in the pack's order. No control renders disabled (DEC-733) and no section dumps raw markdown — a wiki resource's read row names the page and its size, never its body.
