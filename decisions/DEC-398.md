# DEC-398: A form task's form is picked from the event's own forms and validated server-side; findFormForEvent means the DEFAULT form

Three defects, one root cause -- a form id is treated as an opaque string nobody owns. (1) src/routes/tasks.ts:169 and :245 accept any string as formId with no kind cross-check and no event/org check, and src/server/repo/tasks.ts persists it verbatim: blank plus kind='form' yields a REQUIRED task the speaker can never complete (src/routes/portal/tasks.tsx:395 throws 'This task is not a form task'), and a foreign id renders another event's form fields to that speaker at :400. app/src/pages/speakers/TaskModal.tsx:110 asks a non-technical producer to type that id into a free-text box and sends undefined when blank -- against the clarifications' explicit 'not technical at all' buyer, and against docs/design/Chautauqua Speakers.dc.html:182-196, whose New task modal has Task / Due date / Kind / Required and no id field at all. (2) DEC-015 and DEC-111 mean an event genuinely has several forms (the default CFP form plus one per acceptance form-task title), yet src/server/repo/forms.ts:72 findFormForEvent selects `where eventId` limit 1 with no isDefault predicate and no ordering, so getOrCreateForm -- the organizer form builder's source and deleteTrack's referential guard -- is asking SQLite to pick a form by luck. Rules: findFormForEvent filters isDefault = true and is the DEFAULT form's accessor, full stop; a new listFormsForEvent(db, eventId) returns every form as {id, title, isDefault}, default first then title; GET /api/v1/events/:eventId/forms keeps its shape and gains one additive `forms` key carrying that list (no new route, no authz change, DEC-366 respected); POST /events/:eventId/tasks requires formId when kind==='form' and requires it to resolve to a form whose eventId equals the path event (same 400 with fields.formId either way -- no existence leak across orgs), and forbids formId when kind is not 'form'; PATCH /tasks/:id applies the same pairing against the task's own eventId (already returned by getTaskOwnership) and refuses to null out a form task's form. The producer picks a form by NAME from a select; the client never types or invents an id.
