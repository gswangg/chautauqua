# DEC-012: Server composition: Hono sub-apps, request context, middleware names, thin handlers

Six wave-2 tasks wire routes in parallel; without one composition contract each would invent its own app plumbing. Contract: src/server/env.ts exports type Bindings = { DB: D1Database; FILES: R2Bucket; KV: KVNamespace; DEV_MODE?: string } and type AppEnv = { Bindings; Variables: { db: ReturnType<typeof makeDb>; auth?: { userId: string; role: 'organizer'|'reviewer'|'speaker'; orgId: string; contactId?: string } } }. Every route file exports a named Hono<AppEnv> sub-app; src/index.ts is the ONLY place that mounts sub-apps (app.route()). src/server/context.ts: makeDb(env) = drizzle(env.DB, { schema }); per-request ports: mailer = new DevSinkMailer(d1EmailLogWriter(db)) per DEC-006, fileStore over env.FILES, clock = () => Date.now(). src/server/middleware.ts names (binding): sessionLoader (always-on: parse chq_session cookie, look up auth_session by SHA-256 token hash per DEC-004, set c.var.auth), requireOrganizer, requireReviewer, requireSpeaker (401 when no session, 403 on wrong role), csrfJson (x-chq-csrf: 1 header per DEC-004), csrfForm (double-submit chq_csrf). Handlers stay thin: parse/authz -> repo function in src/server/repo/*.ts (drizzle-typed) -> pure domain core -> response; repo functions are the only code that touches drizzle row types (DEC-002 keeps cores schema-free). Testing strategy: vitest covers pure cores plus middleware/cookie/CSRF/token logic against tiny fakes (KVNamespace and the ports are small interfaces); full-route verification happens against wrangler dev (seed + adversarial lens), not vitest — no workers-pool test dependency in stage 1. Worker-side SSR uses hono/jsx: root tsconfig sets jsx 'react-jsx', jsxImportSource 'hono/jsx', and excludes app/ (the SPA keeps its own React tsconfig per DEC-001). Login UX: GET /login is an SSR form; POST /login is form-encoded with csrfForm; success rotates the session and redirects organizer/reviewer to /admin, speaker to /portal.
