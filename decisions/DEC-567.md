# DEC-567: The reviewer feedback a speaker reads is the round that decided THEM — latest evaluated round per plan, event-scoped, totally ordered — and the unbatched reader is deleted

src/server/repo/comms.ts:235-256 filters `listFeedbackCommentsForSubmissions` on submissionId alone: no event, no plan, no round. J5's `includeFeedback: true` (src/routes/comms.ts:314-326) therefore concatenates EVERY reviewer comment from EVERY evaluation plan and EVERY prior round into the speaker-facing `{feedback}` merge var, and `formatFeedback` numbers them 'Reviewer 1..N' positionally across that mixture. DEC-087 requires round-scoped SQL filtering at every evaluation call site, and this is the one path that puts evaluation comments in front of a speaker. The naive fix — filter on `evaluation_plan.current_round` — is wrong: a talk dropped in round 1 of a plan the organizer has since advanced to round 2 would get an EMPTY feedback block, silently. Decision: the speaker reads the last round in which their submission was actually evaluated, per plan. `listFeedbackCommentsForSubmissions(db, eventId, submissionIds)` takes eventId as a required second parameter, inner-joins `evaluation` -> `evaluation_plan` on planId, and filters in SQL: `evaluation_plan.event_id = :eventId` AND `evaluation.round = (select max(e2.round) from evaluation e2 where e2.plan_id = evaluation.plan_id and e2.submission_id = evaluation.submission_id and e2.submitted_at is not null)`, keeping the existing submittedAt-not-null / non-blank-comment filter. Order is total and reproducible per DEC-562/DEC-564: `(evaluation_plan.id asc, evaluation.created_at asc, evaluation.id asc)` in SQL AND re-applied as a JS sort over the accumulated chunks, since DEC-078 chunking dissolves a SQL order. Cross-plan comments stay grouped by plan rather than interleaved, so 'Reviewer N' numbering is stable. The singular `listFeedbackComments` (:219-226) has ZERO src callers — only test mocks — so it is DELETED along with every mock key naming it (house rule: no dead helpers, no compatibility re-exports). buildRenderTargets passes `event.id`, which it already holds.
