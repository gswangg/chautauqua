# DEC-853: A write that succeeds says what it did, in the vocabulary its automated twin already uses — including the clash it just created

VERIFIED asymmetry: handleAutoSchedule (app/src/pages/Agenda.tsx:113ff) reports placed counts, typed unplaced reasons and ' N pre-existing conflict(s) left in place.' through the existing chq-toast; handlePlace (Agenda.tsx:73-90) and handleUnschedule (99-111) reconcile the refreshed conflicts summary into a header number and say NOTHING. SPEC §2.3's warn-never-block rule means a clash is allowed — it does not mean it is unannounced, and the swarm's own standing rule is that a write which changes what the public sees says so at the moment of choice. Decision: a successful manual placement/move/unschedule sets the same toast, naming the ref, room and time, and appends a clash clause ONLY when the refreshed summary's conflict count ROSE against the pre-write summary — computed from the server's own two numbers, never re-derived client-side. Second half of the same rule at the other end of the gesture: SessionCard's accessible name (SessionCard.tsx:53-55) appends '— click to select, then choose a time slot' to EVERY selectable card, including already-placed ones where the gesture is a MOVE; a placed card says 'choose a new slot'. A control that names the wrong action is the same defect as a write that names no result.
