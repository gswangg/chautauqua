# DEC-572: A reviewer track assignment is previewed and confirmed, and the preview count comes from the same predicate the reviewer queue uses

POST /api/v1/plans/:id/reviewers with a trackId writes one plan_reviewer row that silently expands to every plan-filtered submission in that track — the producer sees no number before or after. A fan-out the UI can't see is the same class of defect as a cap the UI can't see (field guide: "a cap the UI can't see LIES"). The count must not be re-derived: resolveReviewerSubmissions (src/server/repo/review/submissions.ts) already encodes the scope semantics (plan filters_json trackIds ∩ scope, EXISTS over submission_track), so the preview and the queue must end in ONE shared condition builder — two functions claiming the same semantics must end in the same helper. Bounded selection is offered from that same preview list (per-submission plan_reviewer rows, posted in ≤100-row batches) so a producer can assign nine of forty without hand-typing submission ids, which is what the current free-text "Submission id" input demands.
