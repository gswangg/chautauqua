# DEC-393: 44px is the phone tap-target floor everywhere, and the render sweep's MIN_TAP_TARGET_PX enforces it rather than a laxer 40

docs/design/README.md is unambiguous ('Every interactive element is >=44px on phone (min-height:44px plus centred flex, not padding)'), DEC-367 records it as a floor and DEC-385 restates it as a phone metric -- but scripts/render-sweep-lib.ts:130 grades at MIN_TAP_TARGET_PX = 40, so a control between 40 and 43px reads PASS while violating the mandate. Two such controls exist and are the measured minimum on every public and portal route in the w4-j log: src/views/theme.ts:182 `.chq-nav a { min-height: 40px }` (the SSR header nav shared by /e/*, /embed/* and /portal via shell.tsx and portal/index.tsx) and its duplicate at src/routes/portal/portal.css.ts:29. A floor that is not the mandate's floor is decoration, so the constant moves to 44 and the two rules move with it in the same change -- raising the bar without the fix would just manufacture a red gate, and fixing without raising leaves the rule unenforced. Guard: a source-level test asserts the literal `min-height: 40px` appears in no stylesheet under app/src or src (theme.ts, *.css, *.css.ts), so the old floor cannot creep back the way the stray breakpoints did.

## Amendment (wave 7)

DESIGN-RULINGS.md:189 requires min-height:44px PLUS centred flex PLUS horizontal padding, and names the two evasions -- padding alone, and a hit box only as wide as its text. 92 selectors across the tree evaded the floor because they are flush row-action anchors: an anchor drawn flush against its row cannot take padding without moving the ink it draws. The technique: the ANCHOR itself takes `min-height: 44px; display: flex; align-items: center; padding-inline: 10px; margin-inline: -10px` inside a `max-width: 700px` block -- the box grows in both axes, the negative margin cancels the padding, nothing shifts. Same instrument B8 already blessed for the selected-row 3px olive edge ("replaces 3px of the row's left padding rather than adding to it").

Two limits, both load-bearing:

1. Apply this to the ANCHOR, never to a container. A padded container with a text-width child still fails the floor -- the technique only closes the gap when it is spent on the element the pointer actually targets.
2. Never apply this to a dense matrix-cell token (e.g. `.chq-speakers-status-dense`/`-roomy`). B8 pairs dense and roomy by density alone, with colour and weight identical in both members of the pair; raising a dense cell to 44px destroys the narrow column the pair exists to serve. The roomy variant is already the phone-appropriate member of that pair and must not be collapsed into the dense one or replaced by this technique.

Applied wave 7 to `app/src/pages/speakers/speakers.css` and `app/src/pages/speakers/task-view.css` (w7-h); w7-b and w7-c apply the same technique to their own lanes' selectors.

## Amendment (wave 90): the tap-floor backlog is closed sheet by sheet in each sheet's true-terminal phone block, and a token declared in styles.css never gets a second phone rule from a cluster

The tier-2 tap-floor audit (`docs/design/audit/tap-floor-v12.md`, 92 offenders) named no owner per row, so `w5-c`/`w5-d` fixing only the files they already owned left the remaining rows ownerless for three waves. Closing the backlog needs two rules, one per half:

(a) A shared token whose base rule lives in `app/src/styles.css` (`.chq-pill`, `.chq-modal-actions`, `.chq-bulkbar-actions`) is the shell lane's to fix ONCE. A cluster sheet that declares its own phone-width copy of a shell-owned token mints a second vocabulary for the same class name (DEC-613) -- the two rules can drift, and nothing catches the drift because each cluster only ever reads its own file. `.chq-bulkbar-actions` is named explicitly in the audit under the Comms cluster and stays out of `comms.css` for exactly this reason.

(b) The fix for everything the cluster DOES own is a NEW `@media (max-width: 700px)` block APPENDED at the sheet's TRUE END -- never an edit inside an existing phone block, never a reorder of existing rules. Six of the eight sheets in the tier-2 scope declare top-level rules AFTER their own existing phone `@media` block (source order beats media-query specificity, DEC-385 wave-7 amendment), and forty-plus worktrees hold live hunks against these files -- an in-place edit or a reorder is a merge-conflict generator for no reason, where an appended block is additive and conflict-free against every one of them.

Applied wave 90 to `app/src/pages/comms/comms.css` (w8-c): the tap-floor fix lands on each row-action container's anchor/interactive child (never the container, per the wave-7 amendment's limit 1), and the 358px-overflow fixes for `.chq-comms-compose-col-slot`, `.chq-comms-compose-table td:last-child` and `.chq-comms-send-report-skipped-retry` land in the same appended block. `.chq-insert-field-menu-item-token` is left `white-space: nowrap` under a `tap-floor-exempt`-style inline comment (`overflow-exempt: a merge-field token truncated is a token misread`) rather than truncated, since an ellipsized merge-field token is a token a composer can no longer identify.

## Amendment (wave 139): the 28 widened SSR anchors are dispositioned by THREE named classes, and the class is chosen from the MARKUP, never from the class name

DEC-393 wave-138 ruled the SSR `<a>` population widened and each anchor disposed of "by a named exemption, never by a silent drop", but did not say which anchors earn a floor and which earn an exemption — and two lanes drain the 28 in parallel this wave, so an unstated taxonomy is two lanes deciding one question. RULED, three classes and no fourth: (a) REAL FLOOR — the token IS the tap target, so its sheet's terminal `@media (max-width:700px)` block gains `min-height:44px` + `display:flex; align-items:center` + non-zero `padding-inline` on the element-qualified selector; this is the default and every reviewer-filed row takes it (`.chq-pub-session-title` measured 358x27 as the only route into session detail, `.chq-docs-wordmark` 112.6x28, `.chq-home-footer-link`). (b) COMPOSITION-EXEMPT — every markup site of the token also carries a sibling class this sheet already floors; the rule takes `/* tap-floor-exempt: composition — <sibling class> at <the markup site> */` and names both. (c) MODIFIER-EXEMPT — the token is a colour/state modifier never applied alone (`.chq-pub-accent-link` is an `ACCENT_BOUND_CLASSES` member, `.chq-docs-nav-link-active` and `.chq-pub-day-pill-active` are state faces); same grammar, naming the base class it always accompanies. The class is chosen by GREPPING the markup for each token, never inferred from the name — DEC-937's resolveTokenFace read a state branch as a resting face for exactly this reason, and DEC-576 requires the element-qualified form because one token rendered as button, anchor and read-only span is not one control.


## Amendment (wave 42): rung 3 of the inline-prose grounding ladder is a CHECKABLE citation, and a DEVIATIONS section number that resolves to the wrong section is not a grounding

DEC-393's wave-35 amendment rules the inline-in-prose tap-floor exemption a grounding claim repaired down a three-rung ladder (floor / same-surface floored twin / DEVIATIONS entry), and docs/design/DEVIATIONS.md section 10 records the three rung-3 outcomes. But `judgeInlineReceipt` (test/inline-prose-exemption-premise.scan.test.ts:193) implements ONLY rung 2 -- it looks for a companion `.chq-*` class and grades everything else UNVERIFIABLE -- so a receipt correctly grounded at rung 3 by a recorded, user-blessed override is graded identically to one that argues nothing at all. That is why `INLINE_PROSE_UNVERIFIABLE_CEILING` reads 11, one of only three non-zero exit-predicate rows, and why its own audit doc can call the population 'ten UNVERIFIABLE rows' while the constant says 11. Worse, four live receipts cite the WRONG section: src/routes/public/submit-views.tsx:633 and :799, src/routes/tools.css.ts:77 and src/routes/docs.tsx:64 all cite 'DEVIATIONS.md section 9's Nth entry', while section 9 is 'Wave 34 rulings (DEC-021 wave-34 amendment)' about BreaksPanel and the entries they mean live in section 10 (DEVIATIONS.md:1093). The thunderdome medic repaired only the cfp.css.ts copy of this mistake. RULED: a receipt is GROUNDED-BY-DEVIATION only when its reason cites docs/design/DEVIATIONS.md with a section number that resolves to a real `## N.` heading AND that section's own text names the receipt's own `chq-` class token. A citation into the override authority that lands in the wrong section is a false grounding, not a weak one.
