# DEC-935: One session's content lives at its own URL: /admin/content/:submissionId, not a query parameter on the worklist

docs/design/README.md:221 is explicit and authoritative: "Two screens, not one. /admin/content is the worklist ... One session's deliverables, versions and notes live on their own route, /content/:submissionId, opened from a row." The build instead keeps the detail behind ?submissionId= on the worklist route (app/src/pages/content/ContentApp.tsx:37-42), so the deliverable detail is not a route, does not appear in app/src/routeManifest.ts, and is not a URL an evaluating agent can be handed -- the same turn-diet cost DEC-930 just removed for speakers. Rule: /admin/content/:submissionId becomes a real React Router route rendering the deliverable detail; /admin/content stays the worklist and keeps ?tab= and ?view= for its own state; the ?submissionId= reading is DELETED, not kept alongside (no backwards-compatibility shim, house rule), and every link that used it -- worklist rows, the Overview section-03 rows, and anything else `submissionId=` greps up -- is repointed at the new path. routeManifest.ts gains the entry with a deterministic seed id so the render sweep visits it, and test/link-targets-scan.test.ts keeps holding that a link is the route it lands on.
