# DEC-996: The production mailer is Resend over HTTP behind RESEND_API_KEY; the send_email binding is deleted rather than mis-typed

wrangler.jsonc:27-31 declares Cloudflare Email Routing's `send_email` binding, whose runtime API is send(new EmailMessage(from, to, rawMime)) and which only delivers to VERIFIED destination addresses — never an arbitrary speaker inbox. src/mail/email-binding.ts:41 calls env.EMAIL.send({to, from, subject, html, text, attachments}), a shape that binding does not have, and src/server/env.ts:19 self-types EMAIL as our own EmailSender interface, so the mismatch compiles, every test runs DevSinkMailer, and nothing anywhere can observe that production email cannot send at all. A decision with no code is a lie; an adapter that cannot work is worse, because it reads as done. SPEC.md §4 (line 239) names the stage-2 adapter as Resend, and docs/clarifications.md line 31 requires that emails actually send on an MVP basis — so the honest adapter is a plain fetch to https://api.resend.com/emails with an injected fetch (pure, testable, no key needed to compile or test), selected when RESEND_API_KEY is present. Provisioning that key and the sending domain stays operator/stage-2 work and is explicitly NOT in this scope; what lands is the adapter, the binding's removal, and a makeMailer that throws loudly in production when neither dev mode nor a key is configured rather than selecting a mailer that silently fails.
