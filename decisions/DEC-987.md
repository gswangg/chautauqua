# DEC-987: One pluralization vocabulary per package, and the scan that enforces it carries no legacy allow-list

DEC-925 banned hand-copied `? '' : 's'` ternaries under app/src and then shipped a LEGACY_ALLOWLIST of thirteen files "flagged for a follow-up conversion" — so the scan currently certifies the rule while exempting most of the code that breaks it, and the same class of copy bug ("1 events", a guessed 's' on an irregular noun) keeps reaching the screen from exempted files. The server package has the same helper (src/domain/count-copy.ts's plural, cited by DEC-957) and NO scan at all, which is why src/routes/tasks.ts:544 still prints a raw "event(s)" inside the cron's aggregate failure message and src/routes/dev/mailbox.tsx:66 a raw "message(s)". A scan proving one package is one direction of two. Rule: both packages get the same scan with an EMPTY exemption list beyond the helper module and its own test; every count phrase in either package goes through that package's plural()/countOf(); the allow-list is deleted, not extended, so the next hand-rolled ternary fails a test instead of joining a list.
