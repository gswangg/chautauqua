# DEC-837: A link is the route it lands on: an in-app target is basename-relative, and a link into a URL-state page carries that page's state

VERIFIED two links that do not go where they say. (a) app/src/pages/contacts/NewContactModal.tsx:177 renders <Link to={`/admin/contacts?openContact=${id}`}> inside <BrowserRouter basename="/admin"> (app/src/App.tsx:291), so React Router prepends the basename again and the duplicate-hint — the one affordance DEC-800 added at CREATION time, at the exact moment a duplicate is cheapest to avoid — navigates to /admin/admin/contacts and 404s. ContactsApp.tsx:154-160 already consumes ?openContact= and strips it, so the destination is real; only the path is wrong. (b) app/src/pages/contacts/BulkEmailModal.tsx:245 renders <a href="/admin/comms">View in Comms history</a>, but Comms.tsx:19-39 makes the tab URL state ('compose' | 'templates' | 'history', absent/unknown falls back to compose), so the link that promises history reliably lands on Compose. Decision: a router target inside the SPA is always basename-relative (never begins '/admin'), and any link naming a sub-view of a ?tab=/?section= page carries that param — a destination named in the label and not in the URL is a broken link that happens to render. Both rules are proved by ENUMERATION over the source, not by two spot fixes: a scan test walks every app/src/**/*.tsx, fails on any react-router `to=`/`navigate(` string literal starting with '/admin', and fails on any in-app href to a URL-state page (/admin/comms, /admin/contacts, /admin/settings) whose link text names a tab/section the href does not set.

## Amendment (wave 16): the link scan's tab/section vocabulary is DERIVED from each surface's own table, never a typed copy of it

Wave 15 ruled (DEC-678) that a scan with a hand-typed file list measures the files someone remembered. test/link-targets-scan.test.ts:108 holds the second instance of that shape: TAB_SURFACES hand-copies the label sets of Settings.tsx's SECTIONS, Comms.tsx's TABS and ContactsApp.tsx's PANEL_LABELS, and its own comment admits the copy ('taken from the surface's own tab strip / rail'). The copy is accurate today; the day someone adds a settings section, the scan silently stops policing links that name it -- a guard that quietly narrows is worse than no guard, because its green tick is read as coverage. Derive the three label sets by parsing those three files at scan time, with a non-vacuous count tripwire per surface, and keep the deliberate synonyms ('Comms history', 'Duplicates tab') as an explicit additive list so an intentional extra label stays visible as intent rather than hiding inside a parse.

LANDED (wave 16, task w16-b): test/link-targets-scan.test.ts's TAB_SURFACES now sources its `labels` from `parseSettingsSectionLabels()`, `parseCommsTabLabels()`, and `parseContactsPanelLabels()` -- regex parses of Settings.tsx's `SECTIONS` array, Comms.tsx's `TABS` array, and ContactsApp.tsx's `PANEL_LABELS` map, run at scan time, each with a `throw` if its anchor regex fails to match (a renamed/reshaped table fails loudly, not silently-empty). Each parse also carries a floor-count vacuous-scan tripwire test (settings >= 7, comms >= 3, contacts >= 4, matching today's counts). 'Comms history' and 'Duplicates tab' remain a separately named additive array (`COMMS_EXTRA_LABELS`, `CONTACTS_EXTRA_LABELS`) merged onto the parsed set, not folded into the parse. Verified byte-identical violation set (empty) before and after: all 192 `it()`s in the file still pass, and the three parsed label arrays were diffed against the prior hand-typed lists and match exactly.

## Amendment (wave 17): an /admin href resolves to a DECLARED SPA route, checked against the route table App.tsx actually registers

test/link-targets-scan.test.ts enforces two rules — no basename-doubled router target, and a tab-labelled link carries its ?tab= — but never asks whether the path EXISTS. A plain `<a href="/admin/comms?tab=compose&template=...">` (BulkEmailModal's forward path for an unsendable template) or a `to="/contacts?import=1&eventId=..."` typo passes both rules and 404s at runtime. The declared set must be derived from app/src/App.tsx's own ROUTES keys and NAV_SECTIONS paths (`:param` a wildcard segment, trailing `/*` a wildcard tail), never re-typed, so adding a page automatically extends the guard rather than narrowing it.
