# DEC-785: A saved embed is a named record whose disabled state is a 404, not a grey pill

EMB-15's full-credit list names saved, named, enable/disable-able embeds, and the EMB probe separately reports "no enable/disable/revoke for public surfaces". The builder today mints a snippet and forgets it (app/src/pages/settings/EmbedsPanel.tsx). Decision: an `embed` row (id, org_id, event_id, name, surface, format, options_json, enabled, created_at/updated_at as epoch-ms NUMBER per the D1 primitives rule) is the addressable unit: its snippet points at /embed/e/:embedId, which renders that surface with those saved options, and a disabled or deleted embed returns the DESIGNED 404 (DEC-740's page), not a silently-served page. Enable/disable must therefore have a visible public effect — a toggle whose only consequence is a pill in Settings is decoration, and the field guide already records that a control whose effect dies on reload is decoration. The list lives in a new SavedEmbedsPanel rendered by PublicPagesPanel, reusing that panel's row grammar (name · path · state pill · row action), so no new visual vocabulary is invented.

## Amendment (wave 41): a saved-embed row is a pinned grid, and the embed editor's third action is Preview

The embed row has now failed the same wrap at three consecutive gates: in the 820 column the descriptor ('Sessions · iframe · AI Engineering · 6 fields') wraps to two lines and the ON/Edit/Get code/Turn off/Delete cluster runs flush to the column boundary. A row that reflows differently per event data is not a row, it is a paragraph. Ruling: the row is an explicit grid — descriptor column min-width 0 with the descriptor clamped to ONE line, actions right-flushed with an inset from the column edge — proven by a width test at the 820 column, not by eyeballing. The editor gains Preview (Save changes · Copy snippet · Preview) which opens the saved embed's own URL in a new tab: an embed whose disabled state is a 404 (DEC-785) needs the one control that shows what a visitor gets. FIELDS SHOWN is ONE pill row, not six stacked checkbox rows, and the SAVED EMBEDS eyebrow carries the right-flushed 'Turning one off breaks it wherever it is pasted' caption plus the 'N on · M off' count.


## Amendment (wave 1)

Resources, People and roles, Exports, API tokens and Saved embeds all render a count or a caption whose contents only appear after clicking Change, which turns a read view into a menu and makes "what is configured?" a two-click question on the one screen that exists to answer it. Ruling: each of those sections renders its actual rows at rest (names, roles, formats, token labels, embed recipes + on/off state) and Change switches to the EDITOR for them; the public-pages read row is the frame's four columns — `Sessions | /path | LIVE | Embed code`. This is a rendering rule, not a data-model change: every list is already fetched or one existing endpoint away, and no read view may show a fact the surface does not already publish.

## Amendment (wave 4): saved embeds render at rest, and the builder sits UNDER the list

SavedEmbedsPanel is mounted only inside PublicPagesPanel's editing branch (PublicPagesPanel.tsx:219), so the four saved embeds are invisible until an organiser clicks Change — and when the builder does open, EDITING renders above SAVED EMBEDS, inverting the frame. A named record whose disabled state is a real 404 (the original DEC-785) is a first-class object and belongs in the read view; the builder is the subordinate surface and reads as an edit of the list above it. Same amendment settles the builder's shape: two-up NAME|SURFACE and FORMAT|TRACK pairs and a plain eyebrow instead of a native fieldset legend, so the editor speaks the settings vocabulary rather than the browser's.

## Amendment (wave 15): ONE drill per settings section — the public-pages editor mounts with the drill, and SavedEmbedsPanel drops its nested Change/Back

Two independent read/edit toggles govern one section today: the section's own `?section=public-pages&edit=1` drill AND SavedEmbedsPanel's local `showEditor` (SavedEmbedsPanel.tsx:130-132, the 'Change'→'Back' relabel the delta-2 probe saw). The builder (EmbedsPanel) only mounts on `embedOpen`, which the drill never sets, so arriving at the drilled URL renders zero form controls — the section claims to be in edit mode while its editor is still one unlabelled click away. Ruling: when the section drill is open, the builder mounts and the saved-embeds rows render their Edit/Turn on-off/Delete/Build affordances directly; the panel's own nested toggle is deleted. At rest the summary stays read-only exactly as DEC-815 requires.
