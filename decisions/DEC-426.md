# DEC-426: WCAG AA contrast becomes the third measured design invariant -- desktop-only, advisory, offender-naming, in its own module

docs/eval-findings.md:51 makes "WCAG AA on every text/background pair" part of done alongside the 10px floor and the 44px tap target, and docs/design/README.md:207 states it as a shipped property of the palette ("anything lighter failed and was raised during review"). The other two invariants are now instrumented (MIN_TAP_TARGET_PX, DEC-421's font floor); contrast has zero matches anywhere under scripts/ -- a claimed acceptance property measured by nothing, and the one most likely to have drifted since the tokens landed, because a page lane adding a muted-on-muted pairing breaks it invisibly. It lands as a fourth pass over the DESKTOP visit only: contrast is a colour property, the desktop pass already visits all 42 routes under all four personas, and running it again at 390px doubles cost for information the phone media queries (layout and size, not colour) do not change. Threshold 4.5:1, relaxed to 3:1 for WCAG "large text" (computed font-size >= 24px, or >= 18.66px at weight >= 700). Effective background is the nearest self-or-ancestor with a non-transparent background-color, defaulting to white. It lands ADVISORY (CONTRAST_BLOCKING=false, DEC-387's flip rule: blocking in the wave after it first reads all-PASS) because a brand-new pass that gates on its first run converts an unmeasured claim into a build break rather than into evidence. Its pure helpers and evaluator live in a NEW module scripts/render-sweep-contrast.ts with tests in test/render-sweep-contrast.test.ts, so it adds a call site to render-sweep.ts rather than restructuring the two files DEC-424 is editing in the same batch. It inherits DEC-411 (page.addInitScript shim before any page.evaluate) and DEC-419 (instrument failure is reported as instrument-blocked, never transcribed as a number).

## Amendment (wave 29): the disabled register is EXEMPT from the AA contrast floor by citation, and two probes that disagree about one element are one broken probe

The render sweep failed `label.chq-review-checkbox-label` at ratio 3.09, fg rgb(125,120,105) on bg rgb(221,216,200) — exactly `--chq-disabled` (#7D7869) on `--chq-disabled-bg` (#DDD8C8) as declared at app/src/pages/review/review.css:1695-1701. WCAG 2.1 SC 1.4.3 explicitly excludes "inactive user interface components" from the 4.5:1 minimum, so darkening the token to chase 4.5 would change the product to satisfy a rule the standard does not make — and DEC-436's wave-25 amendment already moved this token once. RULING: the contrast probe classifies a measured pair equal to the disabled token pair as `EXEMPT-BY-RULE (WCAG 2.1 SC 1.4.3, inactive component)` and prints that citation in the row — an exemption is recorded, never silently passed and never failed. Second, the SAME sweep reported `.chq-review-field-disabled .chq-review-checkbox-label` as `instrument-blocked: selector never resolved` on the SAME route where the contrast probe resolved that element and read those exact disabled colours (docs/verification-log/task-w27-d-perf-rendersweep-ceda66f2.md:134-142). Two probes cannot disagree about whether one element exists: both resolve it by the same path.
