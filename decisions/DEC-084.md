# DEC-084: Server-side headshot dimension gate (amends DEC-059): pure PNG/JPEG header sniffing rejects uploads over 2048px max edge

DEC-059's client-canvas downscale covers only the portal profile page; API-direct uploads store arbitrarily large images served with a 1-year immutable header — the review correctly called this a narrowing of §7's "headshots thumbnailed at upload". workerd still has no image codec, but rejecting oversized images needs only header parsing: new pure module src/lib/image-dims.ts exports readImageDims(bytes, contentType) (PNG IHDR; JPEG SOF marker scan; throws on malformed input) and MAX_HEADSHOT_EDGE_PX = 2048. The headshot upload handler rejects png/jpeg uploads exceeding it with an actionable "please upload a smaller image" error; the normal browser path never hits it because the DEC-059 downscale runs first. Other allowlisted types (if any) remain covered by the existing 8MB cap. scripts/seed-r2.ts asserts seeded fixture headshots pass the same gate, closing the seed path. Full server-side thumbnailing remains stage-2 (Cloudflare Images).
