# DEC-370: Overview worklist payload v2: exact contract, action-endpoint mapping, and the suggestions that are deliberately omitted

Overview stops being a directory of six counts and becomes the work itself, which means a server lane and a client lane must agree on a payload without talking. GET /api/v1/events/:eventId/overview (organizer-only, unchanged authz) returns v2: { deadlines: { formCloseDate, nextTaskDueDate, planCloseDate, eventStartDate } (epoch ms or null), overdueTasks: { total, rows: [{ assignmentId, contactId, contactName, company, taskId, taskTitle, dueDate, daysLate }] }, triage: { total, oldestSubmittedAt, rows: [{ submissionId, ref, title, speakerName, trackName, format, submittedAt }] }, contentApproval: { total, reuploadedCount, rows: [{ submissionId, ref, title, speakerName, fileName, uploadedAt, reuploaded }] }, agendaWork: { unplacedTotal, conflictTotal, conflicts: [{ day, startMin, endMin, roomName, kind, entries: [{ submissionId, ref, title, speakerName }] }], unplaced: [{ submissionId, ref, title, speakerName, durationMin }] } } PLUS the v1 aggregate keys triage-counts/review/speakers/content/agenda/comms RETAINED verbatim so the nav badge (DEC-369) and any other reader keep working. Every rows array is capped at 5 server-side with the true count in `total`; queries stay chunked/joined (no N+1) and inside the SPEC §7 p95<50ms read budget. Row actions bind to EXISTING endpoints only: Accept/Waitlist/Decline -> POST /api/v1/events/:eventId/submissions/status with status 'accepted' | 'accept_queue' | 'declined' (Waitlist is the mock's label for the accept_queue lane — deciding still never emails); Approve / Ask for changes -> POST /api/v1/submissions/:id/content-status; Remind -> POST /api/v1/events/:eventId/onboarding/remind { taskIds: [taskId] }, surfacing all three of {sent, skipped, remaining} and keeping the caption 'Skips anyone reminded in the last hour' (MANUAL_DEDUPE_WINDOW_MS) next to the control; Mark complete -> PATCH /api/v1/task-assignments/:id { status: 'complete' } (organizer override path, DEC-214). DELIBERATELY OMITTED because no endpoint stores them (handoff copy rule 3): the conflict row's 'Move DFC-047 to 11:30 / Next free slot in Room 2A' suggestion and any published-at or send-schedule copy — section 04 links to the grid instead. The 'No action needed' section is derived client-side by a pure helper from the retained aggregates, never asserted by the server.

## Amendment (wave 56): Overview's unplaced number is a SQL count, not a filter over every accepted submission id

getOverviewPayload (src/server/repo/overview.ts:305-312) SELECTs id/seq/title for EVERY accepted submission of the event with no LIMIT, on the landing page, purely to produce (a) one integer (agenda.unplaced, computeAgendaSummary at overview/aggregate.ts:35-44) and (b) at most ROW_CAP=5 named unplaced rows (overview.ts:391-392). At SPEC section 7's 2,000-submission scale that is hundreds of rows read to render five, on the slowest read in the product. The placed set is already event-scoped and bounded by the agenda itself (overview.ts:341-351), and it can carry seq/title on its own join, so the accepted-id array has no remaining reader. Cap the QUERY, not the array (DEC-461): a NOT EXISTS count for the number, a LIMIT ROW_CAP query ordered by seq for the rows, and the placed join for the conflict-card titles.

## Amendment (wave 5): Overview quiet rows are ONE two-column grid, and a quiet row states itself in a single summary clause

The surviving gate-4 overview MAJOR is a single row: Review and Comms hold the frame's strict 220.5px value-column offset at 14px, while Public pages sits at 304.3px and 12px because it enumerates six surfaces plus a URL instead of summarising. A quiet row's job is to say the state is fine in one clause ("17 sessions live, with speakers and schedule"); enumeration is what the section behind it is for. One grid, one type size, one clause -- no per-row layout.

## Amendment (wave 47): a brand-new event's Overview is ONE fresh state, not five 'Nothing…' stubs, and EmptyState grows exactly one optional secondary link

On an event with nothing in it, Overview.tsx today renders the deadline table plus five section headers each carrying its own muted line ('No overdue speaker tasks.', 'Nothing waiting for triage.', 'Nothing waiting on content approval.', …) — five apologies where the vendored frame draws one block. docs/design/Chautauqua Overview.dc.html carries the authority ('Overview · a brand-new event / Nothing has happened yet', the frame at lines ~429-470): h1 'Overview' with the summary '‹event name› · nothing scheduled', then a single block — 'Nothing needs you yet' over 'This event has no submissions, no speakers and no schedule. It starts when the call for papers opens.' — with a filled primary 'Set up the call for papers' and a tertiary 'Add a speaker by hand ›'. No deadline table, no numbered sections. Ruling: (1) the predicate is read from the payload the page already has and is stated once — every worklist section empty AND triage-counts.pending + accept_queue + decline_queue === 0 AND overdueTasks.total === 0 AND contentApproval.total === 0 AND agendaWork.unplacedTotal === 0 AND agendaWork.conflictTotal === 0 AND publishedSessionCount === 0; a partially-empty event keeps today's per-section lines, because 'this section is clear' and 'this event has not started' are different facts. (2) When it holds, Overview renders the frame's block through the shared EmptyState ('fresh'), and renders neither the deadline table nor any section. (3) EmptyState gains ONE optional prop, `secondary?: { label: string; to: string }`, rendered as a tertiary link beside the primary and permitted only on the 'fresh' variant (it throws when passed with 'filtered', matching the component's existing fail-loud guards) — the fresh block is 'one primary action' plus, where the frame draws it, one quiet way out; the component owns that so no page hand-rolls a second button. Targets are the app's existing routes only (the settings Call-for-papers section for the primary, /speakers for the secondary) — no new route is invented. app/src/components/EmptyState.tsx is owned by this decision's task alone this wave; the three B7 conversion tasks are call sites and must not edit it.

## Amendment (wave 51): the Overview headline spells its count — the spelled-number rule binds the sentence, not just the button label

DEC-370's wave-5 amendment already rules that a count from 0-10 is spelled out in a UI label ('Remind all three'), never a bare numeral, and app/src/pages/overview/rows.ts exports spellSmallNumber for exactly that. headlineText — the 44px h1 on the product's first screen — still prints '5 things need your attention' while the frame reads 'Four things need your attention', and Overview.tsx calls spellSmallNumber one line below the headline it skipped. Ruling: counts 1-10 in the Overview headline are spelled and sentence-capitalized ('One thing needs your attention', 'Four things need your attention'); counts above ten stay numerals; the zero case keeps its existing branch untouched (the fresh-event block owns that screen and no frame draws a spelled zero). Capitalization comes from one exported helper, never a second word list. The existing tests asserting the numeral are the thing that is wrong.

## Amendment (wave 57): the overview wire contract is nullable where the SERVER is nullable — agendaWork.conflicts[].roomName is `string | null` on both sides and the contract test carries no Omit

src/server/repo/overview/types.ts:100 types ConflictRow.roomName `string | null` and src/server/repo/overview/scheduling.ts:51 genuinely emits null for a conflict whose slot has no room (a speaker_overlap between two unroomed slots), while app/src/pages/overview/types.ts:68 types it `string` and app/src/pages/overview/AgendaWorkSection.tsx:100 prints it bare — so the one case that produces null renders an empty meta line. Worse, test/overview-payload-contract.test.ts:33-52 DISARMS its own deep bidirectional assignability check with an `Omit<..., "roomName">` on both sides and documents the gap in a comment, which is exactly the drift the contract test exists to catch (w55's shape: A CONTRACT TEST THAT DOWNGRADES ITSELF TO GET GREEN IS THE DRIFT IT WAS BUILT TO CATCH). The client type follows the server, the renderer routes the null through the ONE room-absence label (DEC-666's publicRoomLabel), and the Omit is deleted so the next nullability divergence fails to compile. The sibling ConflictResolution.roomName and PlacementSuggestion.roomName are non-null on BOTH sides (scheduling.ts:101/:167 fall back to slot.roomId) and stay as they are.

## Amendment (wave 3): an empty state's first line is display register, not body copy

app/src/styles.css:1665 sets `.chq-empty-what` to 15px/600 and `.chq-empty-reason` to 14px. The v9 empty-state frames draw the 'what' line at the ~24-25px display register with the reason at 16-17px: the zero state is the only thing on the surface, so its headline carries the page's weight. At 15px it reads as a caption under absent content, which is exactly the 'headers over nothing' failure B7 was written to end. Because EmptyState is one shared component (app/src/components/EmptyState.tsx) mounted on every zero state in the SPA, this is one rule that re-scales the whole class. RULING: `.chq-empty-what` = 24px, weight 600, `var(--chq-font-display)`, line-height 1.2; `.chq-empty-reason` = 16px, line-height 1.6, muted ink. No per-surface override is permitted — a zero state that wants a different size is a zero state that should not be using the shared component. Guard: a parsed-CSS assertion in EmptyState.render.test.tsx pinning both numbers, so the next 'small tweak' to styles.css shows up as a failing pin rather than a silently re-shrunk class.


## Amendment (wave 61): an independent validation read joins the wave even when an earlier refusal may discard it — refusal ORDER is source order, never issue order

Three routes measured this wave are strict ladders of independent statements: PUT /submissions/:id/slot (4 waves), GET /review/submissions/:id (8 sequential awaits, six of them mutually independent) and listEventDeliverableFiles (8 awaits, zero Promise.all). Every one of them is sequential only because an EARLIER statement can refuse, and the author treated 'might not need it' as 'must not issue it'. At real-D1 cost (10-30ms per statement over the wire, confirmed by the overnight prod-like run) that thrift buys nothing and costs a round trip per link. Ruling, binding on every route lane this wave: reads whose inputs are all available at the same point issue as ONE wave (Promise.all, or settleInDeclarationOrder when more than one can reject with a user-facing ApiError); refusals are then evaluated in the EXACT source order they have today, so no error message, code or precedence changes. A discarded read is cheaper than a serialized one. This does NOT license parallelizing a write with a write, or a read with the write it observes — DEC-155's hard constraint stands.

## Amendment (wave 62): a page's hydration is ONE dependency level — count waves, not queries, and keep the array order the sequential order

The wave-61 amendment ruled that an independent validation read joins the wave even when an earlier refusal may discard it. Four more read paths were measured at plan time and are ladders of the same shape, all on high-traffic screens: getOnboardingGrid (src/server/repo/tasks/grid.ts, 9 sequential statements, P2-perf 142-225ms), getPortalData + getPortalSubmissionDetail (src/server/repo/portal/data.ts, 4 and 5 sequential, P2-perf 107-353ms), listSubmissions (src/server/repo/submissions/list.ts, 4 head statements + 6 sequential per-page hydration loops = up to 10 round trips on the organizer's most-used screen) and src/server/repo/contacts/crud.ts (count-then-page, and four capped independent reads). Over real D1 each await is a 10-30ms round trip; the dependency GRAPH of every one of these is only 2-3 levels deep. RULING: a repo read function issues one Promise.all per dependency LEVEL, and a statement joins the earliest level whose inputs it already has; per-page hydration (every read keyed by the page's id set) is ONE level, chunk loops included. Refusals, fail-loud invariants and their exact messages are evaluated in SOURCE order after the wave resolves — a discarded read is cheaper than a serialized one. Payload keys, row order, filters and counts never change (the load test's NO-REGRESSION rule). Two mechanical constraints, both already house style: keep the Promise.all array in the EXACT order the sequential awaits ran (src/server/repo/overview.ts:62-64 documents why — call-order-based test mocks stay valid), and where a second statement differs only by a WHERE its predecessor would supply, prefer a join over a wave (w61's fake-dependency rule).
