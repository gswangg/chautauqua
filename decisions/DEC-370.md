# DEC-370: Overview worklist payload v2: exact contract, action-endpoint mapping, and the suggestions that are deliberately omitted

Overview stops being a directory of six counts and becomes the work itself, which means a server lane and a client lane must agree on a payload without talking. GET /api/v1/events/:eventId/overview (organizer-only, unchanged authz) returns v2: { deadlines: { formCloseDate, nextTaskDueDate, planCloseDate, eventStartDate } (epoch ms or null), overdueTasks: { total, rows: [{ assignmentId, contactId, contactName, company, taskId, taskTitle, dueDate, daysLate }] }, triage: { total, oldestSubmittedAt, rows: [{ submissionId, ref, title, speakerName, trackName, format, submittedAt }] }, contentApproval: { total, reuploadedCount, rows: [{ submissionId, ref, title, speakerName, fileName, uploadedAt, reuploaded }] }, agendaWork: { unplacedTotal, conflictTotal, conflicts: [{ day, startMin, endMin, roomName, kind, entries: [{ submissionId, ref, title, speakerName }] }], unplaced: [{ submissionId, ref, title, speakerName, durationMin }] } } PLUS the v1 aggregate keys triage-counts/review/speakers/content/agenda/comms RETAINED verbatim so the nav badge (DEC-369) and any other reader keep working. Every rows array is capped at 5 server-side with the true count in `total`; queries stay chunked/joined (no N+1) and inside the SPEC §7 p95<50ms read budget. Row actions bind to EXISTING endpoints only: Accept/Waitlist/Decline -> POST /api/v1/events/:eventId/submissions/status with status 'accepted' | 'accept_queue' | 'declined' (Waitlist is the mock's label for the accept_queue lane — deciding still never emails); Approve / Ask for changes -> POST /api/v1/submissions/:id/content-status; Remind -> POST /api/v1/events/:eventId/onboarding/remind { taskIds: [taskId] }, surfacing all three of {sent, skipped, remaining} and keeping the caption 'Skips anyone reminded in the last hour' (MANUAL_DEDUPE_WINDOW_MS) next to the control; Mark complete -> PATCH /api/v1/task-assignments/:id { status: 'complete' } (organizer override path, DEC-214). DELIBERATELY OMITTED because no endpoint stores them (handoff copy rule 3): the conflict row's 'Move DFC-047 to 11:30 / Next free slot in Room 2A' suggestion and any published-at or send-schedule copy — section 04 links to the grid instead. The 'No action needed' section is derived client-side by a pure helper from the retained aggregates, never asserted by the server.
