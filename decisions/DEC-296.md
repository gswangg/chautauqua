# DEC-296: Stage-1 dev links: .dev.vars.example ships PUBLIC_BASE_URL=http://localhost:8787, and under DEV_MODE an observed loopback origin outranks a loopback PUBLIC_BASE_URL

wrangler.jsonc's routes/custom_domain: chautauqua.cc entry (human stage-2 wiring, left untouched) makes new URL(c.req.url).origin resolve to the live production host under wrangler dev, so DEC-252's final fallback (src/server/origin.ts:98) emits http://chautauqua.cc/claim/<token> in the fresh-clone quickstart whenever no loopback Origin/Referer header is present — a judge following the README literally gets a claim link that does not resolve on their machine (task-w8-g OPEN ITEM 2, task-w8-f). Two changes, both in app-owned files, neither touching the operator's deploy config. (1) .dev.vars.example — the tracked template scripts/ensure-dev-vars.ts copies to the gitignored .dev.vars on first predev — gains PUBLIC_BASE_URL=http://localhost:8787, so the zero-secret default path is correct by construction and stays consistent with SPEC section 6's '.dev.vars gitignored'. (2) Because a checked-in default cannot know the port, DEC-252's precedence is amended for the dev branch ONLY: when DEV_MODE === '1' and the configured PUBLIC_BASE_URL is itself a loopback origin, an observed loopback origin among [request URL origin, Origin header, Referer origin] wins over it. A non-loopback PUBLIC_BASE_URL always wins and production (no DEV_MODE) is byte-identical to today, so an attacker-supplied header still can never poison a real mailed link. Battery lanes that pass --var PUBLIC_BASE_URL:http://localhost:<their port> keep working under both rules.
