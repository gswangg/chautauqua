# DEC-374: SSR CSS is injected via dangerouslySetInnerHTML and must be value-free; the per-event accent moves to a validated style attribute on <body>

hono/jsx HTML-escapes text children — DEC-110 already records this for JSON — and the escape set is & < > " '. THEME_CSS as landed on main contains `font-family: 'Familjen Grotesk'` and `url('/fonts/FamiljenGrotesk-var.woff2')`, so every SSR surface currently ships &#39;-mangled @font-face and font-family declarations and the redesign's self-hosted fonts never apply anywhere off the SPA; DEC-253's unquoted-attribute-selector workaround only papered over the double-quote case and says nothing about apostrophes or `>` combinators. Fix it once at the injection point: ThemeStyles() and every DEC-373 surface module render their string via `dangerouslySetInnerHTML: { __html: CSS }` — the same mechanism src/views/form-render.tsx already uses — which also unblocks quoted family names and child combinators. The safety condition is that a raw-injected string must be a module-level constant with NO interpolation of runtime data. The per-event accent therefore stops being interpolated into CSS text: it is applied as a style attribute on the shell's <body> (`style={"--chq-brandable-accent: " + accent}`), where hono escapes attribute values, and the value first passes a strict /^#[0-9a-fA-F]{6}$/ guard falling back to the brand olive. A test asserts a rendered SSR page contains the literal `'Familjen Grotesk'` and contains no &#39; / &quot; / &gt; between <style> and </style>.

## Amendment (wave 14): every server-rendered document declares its doctype, and exactly one module emits an <html> root

VERIFIED DEFECT: 21 `<html lang="en">` JSX roots across 12 files under src/routes and src/server are handed to `c.html()` with no doctype prefix, so every public page, every embed iframe, the portal, the CFP, login/reset/claim, /docs and the 404 are served in BROWSER QUIRKS MODE. Hono 4.13.1's `c.html()` serializes the JSX verbatim (node_modules/hono/dist/context.js:378-381) and adds nothing. The repo's only doctypes are raw strings in src/server/http.ts:308 (fallback error page) and src/mail/shell.ts:69 (email) — so this is drift, not a decision, and no test asserts it. Quirks mode changes the box model and scrollHeight semantics, which means (a) every pixel measurement the fidelity gates have taken on public surfaces was taken in the wrong layout mode, and (b) EmbedShell's auto-resize script (shell.tsx:293) posts a scrollHeight computed under quirks rules to the host page. RULING: one new module — `document.tsx`, under `src/server/` — exports `HtmlDocument` (a hono/jsx component that emits `raw("<!doctype html>")` followed by `<html lang=...>`), and it is the ONLY place in src/ where a `<html` JSX root may appear; every shell delegates. The two existing raw-string emitters keep their inline doctype and are named, with reasons, in the scan's exemption set. A scan lock plus per-family render assertions make the rule falsifiable, because 80+ waves of self-review missed this precisely because nothing checked it.

## Amendment (wave 18): A verbatim design-pack quote inside a test file is EVIDENCE, not the product's own vocabulary or markup

DEC-374's subject test already says a comment is page content and must be read verbatim or stripped; the same test decides who OWNS a quoted string. `app/src/pages/Speakers.desktop-frame-verdicts.render.test.tsx` records a DIVERGES verdict by quoting the frame byte-for-byte — `Chautauqua Speakers.dc.html:697`'s `skips anyone emailed in the last hour` and `:341`'s `Confirmed<span style="color:#565A4B; padding-left:6px">▾</span>`. Two product scans read those quotes as product: `app/src/pages/speakers/remind-skip-vocabulary.scan.test.ts:89` (DEC-613's one-vocabulary ratchet, which the tree deliberately spells `reminded`) and `app/src/select-caret.scan.test.ts:212` (DESIGN-RULINGS B8's caret-element rule). Both are red at ceiling 0 on a file that contains no product markup at all, so the campaign's regression detectors currently punish the one artefact that proves the divergence. RULED: a `▾`/vocabulary occurrence is FRAME EVIDENCE, and excluded from a product scan, exactly when (a) the file is a test file, and (b) the smallest backtick span or string literal enclosing the occurrence appears verbatim (trimmed) in some line of a `docs/design/*.dc.html` file. Byte-identity against the pack is unfakeable, so the exclusion cannot be spent on real product copy; scoping it to test files keeps the product guard at full strength. One implementation, in `test/helpers/frame-evidence.ts`, imported by both scans — never a second copy (DEC-613's own lesson). Prose that PARAPHRASES a frame (an `it()` title reading "Confirmed ▾", which is byte-identical to nothing in the pack) is NOT evidence and is reworded rather than excluded.
