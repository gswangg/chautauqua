# DEC-707: Reviewer progress speaks three states, and a reminder's label names the scope it actually sends -- from ONE predicate both the route and the SPA import

"3 of 8 · not done" collapses two different situations an organizer acts on differently: a reviewer who has started and a reviewer who has not. The mock's vocabulary is DONE / N TO GO / NOT STARTED, and its action reads "Remind the 4 not started" -- a label that is a lie unless the send targets exactly those four. DEC-704 already established that a bulk label states the scope it sends; this applies it to Review by moving the classification into src/domain/evaluation.ts (reviewerProgressState + selectRemindTargets) so the /plans/:id/remind route and the label that counts them are the same function. A hand-copied predicate in app/ and another in src/routes/ is exactly the drift the field guide warns about.

## Amendment (wave 61): a reviewer nudge is addressable and actionable, and targets the round it was labelled from

POST /plans/:id/remind (plans-progress.ts:222-241) sends `to: {email, name: email}` with the body "You have N submissions left to review in \"<plan>\"." -- no recipient name (the same handler's sibling GET /progress already resolves display names through repo.batchUserDisplayNames), no deadline, and, decisively, NO LINK. The one job of a laggard nudge is to put the reviewer back in their queue; a message with no URL makes the volunteer hunt for the product. This is DEC-707's rule ("a reminder's label names the scope it actually sends") extended from the label to the message. Second, smaller half: /progress honours `?round=` while /remind hardcodes `plan.currentRound`, so on a multi-round plan the count that labelled the button and the set the button reaches are resolved against different rounds -- latent today only because the SPA never passes the param. RULING: the nudge addresses the reviewer by resolved display name (falling back to email), links `${resolveBaseUrl(c)}/admin/review/plans/${plan.id}`, states the plan's close date via formatCalendarDate when the plan has one (a DEC-522 day label, never re-zoned), and resolves completion against the round named in the request (same parse as /progress), defaulting to currentRound. Also delete the dead `makeMailer` try/catch -- DEC-547's wave-43 amendment made makeMailer total; the honest-failure path is the per-recipient catch below it.
