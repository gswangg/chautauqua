# DEC-414: A 390px overflow is closed by giving the wide region its own scroller or letting it wrap -- never by hiding overflow, never by shrinking a control below 44px

Two admin routes have carried a measured phone overflow since wave 4 and no lane has ever owned fixing one: /admin/comms at 131px (widest visible element .chq-step inside .chq-steps) and /admin/submissions at 40px (.chq-submissions-filterbar). Both figures predate DEC-404's phone overflow-wrap and DEC-405's no-document-clip rule, and the sweep has measured nothing since (DEC-411), so the fixing lane must RE-MEASURE before it changes anything -- the offender may have moved, and fixing a stale offender is how a gate stays red while a lane reports success. The fix rule is stated once so it is not re-litigated: a region wider than the viewport gets overflow-x: auto with flex-shrink: 0 children (the mandate's chip-strip pattern), or it wraps; it never gets overflow: hidden, which makes the far end unreachable (DEC-405), and it never gets there by dropping a control under the 44px tap floor (DEC-393). The shared shell stylesheet app/src/styles.css and src/views/theme.ts remain ONE lane, and that lane is the one doing this work, so .chq-steps can be fixed where it is defined rather than shadowed from a page stylesheet.
