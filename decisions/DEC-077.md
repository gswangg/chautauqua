# DEC-077: Wave-16 gate lanes are code-frozen and fully parallel; scribe bookkeeping commits (field-guide/, decisions/*.md, src/decisions.ts registry appends) are non-code-bearing under DEC-069

The wave-15 single code barrier's target (task-w14-g walkthrough conversion) merged at a05f17f before this wave was planned, so no code is outstanding and DEC-076's barrier degenerates to zero: all five DEC-069 gates run in parallel from main @ 0ba550c or later. Hard rule: a gate lane that finds a defect records RESULT: FAIL (or an open item in triage) and NEVER commits product/test/script/config changes, because any code commit would sha-invalidate every sibling gate and force a fourth full re-run. Interpretive extension of DEC-076's "code-bearing" ruling: scribe/bookkeeping commits touching only field-guide/index.md, decisions/*.md, and string-constant appends to src/decisions.ts are NOT code-bearing — every wave's scribe commit touches src/decisions.ts, so without this ruling the previous wave's green gates would be permanently invalidated each wave and the exit predicate could never evaluate true. Fix work for any gate failure belongs to wave 17, followed by a re-run of only the failed gate (plus any gates invalidated if the fix is code-bearing).
