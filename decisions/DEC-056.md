# DEC-056: Public API docs page at GET /docs/api (hand-maintained SSR)

SPEC §10.6 plus the §3 own-your-data pitch: the technical teammate persona needs to see the API surface without reading source. A no-login Hono JSX SSR page in a new src/routes/docs.tsx (sub-app, mounted only in src/index.ts per DEC-012) documents: bearer auth (Authorization: Bearer chq_…, minted at Admin → Settings → API tokens, cookie sessions also accepted), the DEC-013 error {error:{code,message,fields?}} and list {items,total,page,perPage} envelopes, and a hand-maintained method/path/role table of the main /api/v1 resource groups (events, forms, submissions, review, tasks, comms, agenda, contacts, exports, tokens). Hand-maintained beats runtime introspection for architectural simplicity; it documents no secrets so it is public. Linked from the SSR landing page and the README evaluator table.

## Amendment (wave 68): /docs/api documents the PUBLIC read surfaces too, in their own group, with their own coverage assertion

DEC-056's hand-maintained page (src/routes/docs.tsx) documents /api/v1 only, and test/docs-route-coverage.test.ts diffs ROUTE_GROUPS against the mounted API sub-apps so that table cannot drift. But J12 and swyx's stated bonus ("an API", "embeds on ai.engineer", data flowing outward) are served just as much by the no-login read surfaces -- the .json/.xml feeds under /embed/:eventSlug, the two .ics endpoints, the chromeless /embed twins, /embed/e/:embedId, the printable programme and /submit/:eventSlug -- and NOTHING documents their URL shape anywhere. A technical teammate can only discover them by reading the source or copying a builder snippet. They go in a SECOND exported constant (PUBLIC_ROUTE_GROUPS) rendered by the same page, so the existing ROUTE_GROUPS-vs-/api/v1 diff stays exactly as it is and the new group gets its own assertion against publicRoutes' registered GETs. Paths only, no knob tables: the per-surface knob set is being changed in another lane this wave and a documented knob list would drift the day it landed.

## Amendment (wave 71): every public GET the Worker serves appears in the docs table AND the README evaluator table, enforced by mounting every sub-app that registers one

The docs page's `PUBLIC_ROUTE_GROUPS` is guarded by `test/docs-route-coverage.test.ts`, but that test mounts only `publicRoutes` + `publicSubmitRoutes` — so `GET /` (the anonymous event hub landed in wave 69, and the first URL a judge opens) and `GET /docs/api` itself are documented nowhere, and the README's "For evaluators" surface table (required verbatim by SPEC §8) lists neither the hub nor the printable programme. Two hand-maintained lists of the same facts, both stale by exactly the routes most recently shipped. The coverage test must mount `rootRoutes` and `docsRoutes` too, with a named non-public exclusion list (`/admin`, `/admin/*`), and the README table must be pinned to `PUBLIC_ROUTE_GROUPS` by test so it can never again lag a shipped surface.

## Amendment (wave 31): /docs/api is enumerated from the router, not hand-maintained on trust

The public API docs page is a J12 deliverable and a public claim about the product, but it is hand-written SSR and test/docs-page.test.ts only spot-checks a handful of substrings, so an endpoint added in any of thirty waves can be undocumented (or documented but deleted) and nothing fails. The repo already owns a source-level router enumerator — test/pubcache-purge-classification.test.ts resolves src/index.ts mount prefixes and nested app.route composition to full paths — and DEC-627 already proved the closed-two-list shape works. Ruling: that enumerator moves to test/helpers/registered-routes.ts (one owner, two consumers) and a new test requires every registered /api/v1 route to be either documented on the page or named in an in-file exclusion list WITH a stated reason, and every /api/v1 path on the page to match a registered route (no ghost endpoints). Path params are compared normalised (:eventId ~ :id) so the docs keep readable names.

## Amendment (wave 82): GET /docs is a user-facing site with its own stylesheet; /docs/api stays an operator surface behind a labelled leaving link

`src/routes/docs.tsx` serves only `/docs/api` and `docs/design/DESIGN-RULINGS.md:298-316` is opinionated that the user-facing `/docs` is entirely new work, grouped BY ROLE not by screen, prose at 680 and figures at 900 (the one sanctioned measure break). It is equally explicit that this does NOT revise DEC-382: `/docs/api` and `/dev/mailbox` keep TOOLS_CSS chrome, and the API reference is presented as a leaving link (↗, muted, "Leaves the docs — an operator surface"), because the seam is real and naming it beats hiding it. Consequences that bind implementers: the new site gets its OWN stylesheet module (never an edit to `home.css.ts`, which is another lane's this wave, and never TOOLS_CSS); every new GET must be added to `src/routes/docs-endpoints.ts` because `test/docs-api-manifest.scan.test.ts` diffs that table against the live router in both directions; and figures are placeholder slots until the scripted shoot runs against the frozen build, because a doc showing a screen that does not exist is worse than no screenshot.
