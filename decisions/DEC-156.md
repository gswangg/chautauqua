# DEC-156: Push-to-event (CRM-10/J11): 'Add to event…' from the directory creates an organizer-invited submission — status 'accepted', content_status 'pending', editable default title, the contact as visible participant — via POST /api/v1/contacts/:id/add-to-event {eventId, title}; no email sent

SPEC J11 requires contacts attach to events, and there is no contact-event link table by design: the contact -> speaker -> publicly-visible ladder runs through participant -> submission. An invited accepted submission is the smallest honest representation: the contact appears immediately in that event's Speakers module with profile data carried over (rubric requirement), content approval still gates public visibility (nothing leaks), and no auto-email fires (deliberate-comms invariant). Reuses existing submission-create + participant plumbing rather than a parallel path.
