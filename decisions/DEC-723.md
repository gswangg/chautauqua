# DEC-723: An evaluation read carries its plan's criteria and the plan's own weighted score; a review is never rendered from bare criterion ids

GET /api/v1/submissions/:id/evaluations returns scores as Record<criterionId, value>, and the detail page renders the id as the label — the raw-id leak the field guide already names ('raw id leaks — render LABELS'), and the reason the judge called reviewer comments write-only even after DEC-596 landed. The organizer also has no score: the weighted mean is computed for the queue, the results table and the scorecard, but not here, so three surfaces state a number and the fourth states none. Both are the same omission — the read carries the evaluation without the plan shape that gives it meaning. Adding criteria (id, label, weight for that item's round via criteriaForRound) and score (computeWeightedScore) to the item makes every consumer render from the one formula instead of re-deriving it, and the plan lookups batch over the distinct planIds rather than per row.
