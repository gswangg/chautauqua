# DEC-227: A required checkbox means the box must be CHECKED: validateAnswers rejects required checkbox fields unless the value is exactly true

Review-lens verified live: src/forms/validate.ts:45-50 treats false as an answered value and the checkbox case (:75-77) coerces anything to Boolean, so the builder-accepted required:true on checkbox fields (src/routes/api/forms.ts:161) is a silent no-op — violating J1/J2 'required flags gate progress'. Required-checkbox semantics are consent/acknowledgment style (e.g. code-of-conduct): the submitted value must be === true; false or absent yields the existing error string "required". The fix lives ONLY in validateAnswers (src/forms/validate.ts) so public /submit, portal edit, and portal form-task flows (which coerce unchecked to false and all call validateAnswers) inherit it with no route changes. Unchecked NON-required checkboxes remain valid with cleaned value false, and visible-if conditions on false answers are unaffected.
