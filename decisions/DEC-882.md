# DEC-882: A frozen round reads as TEXT, the criteria table names its columns, and the lock card explains below what the rows already show

PlanEditor already computes activeRoundIsLocked from server truth (evaluationCountsByRound, DEC-213/676) but keeps rendering the same input rows in a disabled state. A control that cannot act must not render as a control — that is the standing affordance rule, and a disabled text input is the least honest form of read-only. The Review frame renders a locked plan's criteria as read-only text rows beneath a CRITERION | GUIDANCE | WEIGHT header row, with the lock explanation BELOW the rows so a reader sees what the criteria ARE before being told why they cannot change, and the page header reading "Open · N of M reviews in" from the plan's own progress aggregate rather than a second count derived in the component. The weight-to-percentage vocabulary ("Weight N · NN%") belongs to the scorecard decision that a concurrent lane owns; this surface prints the raw weight only, so one formatter is never written twice.
