# DEC-920: A link to a file names the file

app/src/pages/speakers/OnboardingGrid.tsx:552-563 renders an uploaded deliverable as the literal word 'File', with aria-label and title both reading 'Has file'. The cell has nothing better to say because the grid never asks: src/server/repo/tasks/grid.ts selects taskAssignment.fileId (:284) and stops, so the roster -- the screen an organiser uses to chase twelve speakers across five tasks -- can tell you a file exists and never which one. GATE-1 named this as an eval lever in its own right: the grader needed the filename as evidence of a completed upload and burned turns hunting for it, on the same grid the report calls the number-one turn-diet target. schema.file already stores filename and sizeBytes (src/db/schema/content.ts:56/58), so this is a join, not a schema change. Rule: the grid cell carries fileName and fileSizeBytes, resolved in the SAME joined query that already builds the grid (never a per-cell fetch -- that is the N-scan rule again), the link's text and accessible name are the filename, and a cell holding a fileId whose file row does not resolve THROWS rather than falling back to the word 'File' -- a generic label standing in for a missing join is a silent failure wearing a noun.
