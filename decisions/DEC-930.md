# DEC-930: A speaker has ONE event-scoped detail page at /admin/speakers/:contactId, served by ONE bounded GET

The GATE-1 SBEK report names the Speakers grid the number-one eval lever with a measured -11 and asks for 'a per-speaker detail row the agent can read in one snapshot': today the answer to 'what does this person owe me, and where is the evidence' is spread across 27px grid cells, a response modal, a participation menu and the Contacts drawer, none of it addressable by URL. Decision -- the wire contract, which neither implementing task may change: GET /api/v1/events/:eventId/speakers/:contactId (requireOrganizer + the file's existing assertEventOwnership; 404 for a contact who is not on this event's roster, existence-hiding like every other nested read) returns EXACTLY {contact:{id,name,email,company,title,hasAccount}, participation:{participantId,submissionId,inviteStatus}, sessions:[{submissionId,ref,title,status,contentStatus,role,scheduled:{day,startMin,endMin,roomName}|null}], tasks:[{assignmentId,taskId,title,kind,required,dueDate,status,completedAt,file:{id,filename,sizeBytes,versionNo}|null}], counts:{outstandingRequired,overdue}}. Every array comes from ONE query for the whole set -- the file join is the same join the DEC-920 grid cells already carry, never a query per task -- roster membership composes rosterParticipantConditions (DEC-829) and overdue composes the existing DEC-801 effective-due-date predicate rather than re-typing its grace window. The SPA renders it as a page whose rows are links (session -> /admin/submissions/:id, deliverable -> its download, form response -> its response view), so every action the grid offers is one click from one snapshot, and the grid's name cell becomes the link into it.

## Amendment (wave 41): the speaker detail page is TABLE class and prints every status as a pill in the product's existing vocabulary

The per-speaker page is the turn-diet surface sbek reads in one snapshot, and it currently prints participation, submission status, content status and task status as bare text inside a .chq-measure (820) column holding two tables. Ruling: page root takes .chq-measure-table (DEC-989's own test — two scanned tables, not one composed thing); participation reuses the matrix's .chq-speakers-status* four-state face (guarded by speakers-css.test.ts) so the roster and the detail can never disagree about what 'invited' looks like; session status / content status / task status use the shared .chq-flag (DEC-367: type only, never colour alone). SLOT/ROOM prints through the app's ONE day+time grammar (lib/dates formatDayLabel + zero-padded 24h clock, matching DeliverableDetail's formatDetailTrailer), never the raw ISO day the page shows today.

## Amendment (wave 54): the per-speaker detail page states status in the pill vocabulary it already owns

SpeakerDetailPage renders session status, content status and task status as `.chq-flag` (lines 133/136/177) — a bare uppercase micro-label — while the participation row two elements above already renders a real pill via participationStatusClass/.chq-speakers-status. Rule: reuse the EXISTING .chq-speakers-status pill base (never mint a fourth pill vocabulary, never copy its declarations) with a neutral modifier for the non-invite enums, and keep DEC-367 — outline/fill and type carry the meaning, never per-status colour. The render test that currently asserts `.chq-flag` on these three cells is asserting the shape being replaced and must be updated, per the mandate's 'where a test contradicts the design copy, the test is wrong'.

## Amendment (wave 19): speaker detail is a minmax(0,1fr)/320px pair at gap 34, and its three sections are header-ruled row grids, not tables with theads

docs/design/Chautauqua Speakers.dc.html:351 lays the speaker-detail body out as `grid-template-columns: 1fr 320px; gap: 34px` inside a 1440 container padded 26/34/36 -- 1018px of main column. app/src/pages/speakers/speakers.css:780-785 declares `minmax(0, 820px) 300px; gap: 60px`, which clamps the main column ~200px narrower than the frame and widens the gutter by half again. Separately the frame renders Sessions (:357), Tasks (:370) and Files (:384) as row grids under a 2px ink section head with NO column-header row -- `1fr 150px 130px`, `1fr 150px 130px auto`, `52px 1fr 150px auto` -- while app/src/pages/speakers/SpeakerDetailPage.tsx:317-425 renders three `<table className="chq-table">` each with a `<thead>`. Column headings over three short, self-describing sections on a one-person page are exactly the chrome the pack removes; this is the long-carried "speaker-detail grid 1018/34/320 + drop theads" item, now cited against current main rather than inherited.

## Amendment (wave 22): a row grid that replaced a table carries the table's semantics

DEC-930's wave-19 rebuild moved the speaker detail page's Sessions, Tasks and Files sections from `<table>/<thead>` markup to plain `<div>` row grids (SpeakerDetailPage.tsx:332/363/405) to match the frame, which draws header-ruled rows and no column-header row (Speakers.dc.html:357/370/384). The frame is right and the row grid stays -- but the native table semantics went with it and nothing replaced them: no role=table, no role=row, no accessible name, and the wave's own test only asserted the ABSENCE of `<thead>`. A screen reader now reads three sections of undifferentiated text. The neighbouring PeopleRolesPanel.tsx:315 shows the half-applied form of the same idiom: a role=row header with role=columnheader cells floating outside any role=table container, over a `<ul>` whose `<li>` rows carry no role at all -- an orphaned row role is invalid ARIA and worse than none. Ruling: any list that renders tabular data as a row grid wraps in role=table with an aria-label naming the section, marks each row role=row and each row cell role=cell, and marks a header row's cells role=columnheader only when a header row is actually drawn. Semantics are added in markup only -- not one pixel of the frame geometry moves.

## Amendment (wave 24): a structure role never lands on a control

DEC-930 requires a row grid that replaces a table to keep table semantics. `app/src/pages/speakers/SpeakerDetailPage.tsx` buys that by writing the role onto the elements that ARE the controls: `<Link ... role="cell">` (:334), `<button ... role="cell">` (:374 and :387) and `<a href="/files/..." role="cell">` (:422). An ARIA role REPLACES an element's implicit role, so the row's only link and its two buttons are announced as cells -- they stop being a link and buttons in the accessibility tree, and the sbek judge drives via that tree (docs/mandates/findings-archive-2026-08-12.md:22: the single a11y-tree item that gated every scheduling scenario). The correct shape already exists in this codebase: `PeopleRolesPanel.tsx:329-354` puts `role="cell"` on a wrapper `<div>`/`<span>` and lets the control inside keep its own role. Ruling: the cell is a wrapper element; `row`/`cell`/`columnheader`/`rowheader`/`gridcell` never appear in the same JSX open tag as `a`/`button`/`input`/`select`/`textarea`/`Link`. Geometry does not move (the wrapper becomes the grid item, one wrapper per former child). Scan-locked across app/src and src.

## Amendment (wave 160): a narrowing strip is a named group — its visible caption IS the group's accessible name, never a loose span beside unnamed buttons

DEC-930's wave-24 amendment is this codebase's ruling on how roles land in the accessibility tree; it says what a structure role must never do and is silent on what a control GROUP must carry. The Contacts 390 head now has two narrowing strips and neither is announced: `.chq-contacts-filter-chipstrip` has a visible `All of` caption with no programmatic tie to the chips it captions, and `.chq-contacts-segment-pills` has no role and no name at all — while the panel strip one element away in the same file has carried `role="tablist" aria-label="Contacts view"` since it landed. RULED, extending that amendment: a strip of controls that narrows a list is a `role="group"`, and it is NAMED. Where the frame draws a caption the group takes aria-labelledby pointing at that caption's own node — never a duplicated aria-label string, which forks the announced name away from the drawn ink the moment either is edited. Where the frame draws no caption, the group takes an aria-label. The id is minted with React's useId, because these components mount many times over in the render tier and a hardcoded id is invalid the second time. No structure role is added anywhere: `group` on a container is what this calls for and is outside the population DEC-930's wave-24 amendment bans.
