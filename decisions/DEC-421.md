# DEC-421: The 10px type-floor becomes a measured, offender-naming render-sweep pass — advisory on the wave it lands

docs/eval-findings.md:70-74 is the binding mandate for this round and names exactly TWO cheap design invariants to add to the render sweep. The 44px tap-target one shipped (MobileObservation.minControlHeight, MIN_TAP_TARGET_PX). The other — 'no computed font-size below 10px anywhere in the rendered admin/portal/public routes' — never did: `font-size|fontSize|MIN_FONT|10px` has zero matches anywhere under scripts/. docs/design/README.md:74 makes 10px 'the absolute type floor anywhere in the UI, including placeholder labels' and :207 repeats it under Accessibility, so this is a stated acceptance criterion measured by nothing. It lands as a third pass over BOTH the desktop and 390px visits (the mandate says 'anywhere', not 'on phones'), reporting like DEC-401 does — the smallest computed px plus up to three structural offender descriptors, never text content. It lands ADVISORY (FONT_FLOOR_BLOCKING=false beside ADMIN_MOBILE_PASS_BLOCKING, same DEC-387 flip rule: blocking in the wave after it first reads all-PASS), because a brand-new pass that gates on its first run converts an unmeasured claim into a build break rather than into evidence. It inherits DEC-411 without exception: any page.evaluate it adds runs after page.addInitScript(PAGE_EVALUATE_KEEPNAMES_SHIM), and an instrument failure is reported as instrument-blocked, never transcribed as a number.
