# DEC-970: The server-rendered stylesheets join the CSS contract: no undefined token, no class the markup uses and no rule defines

DEC-937's css-contract.scan.test.ts enumerates every *.css under app/src and proves two things — a bare var(--chq-…) resolves to a real declaration, and a button face declares its own font-family. It stops at the app/ boundary. Everything an anonymous visitor sees is on the OTHER side: src/views/theme.ts's token block plus src/routes/public/public.css.ts, cfp.css.ts, home.css, auth.css.ts, portal/portal.css.ts and tools.css.ts, none of which is scanned at all — and an undefined var(--chq-*) resolves to transparent silently, which is precisely how the overview gate lost a wave to --chq-sunk. The second direction is unscanned on BOTH sides and has already cost a frame: .chq-pub-session-tag is defined in public.css.ts and referenced by no markup, so the frame's meta grammar sat unbuilt behind a rule that looked implemented. Rule: test/ssr-css-contract.scan.test.ts ENUMERATES (never hand-lists) every SSR stylesheet module under src/ and asserts (A) every bare var(--chq-…) in them resolves to a token declared in the theme's :root block or locally in the same module, and (B) every chq-* class name appearing in a class attribute in src/**/*.tsx has at least one matching class selector in the union of those stylesheets. Violations are FIXED, not allowlisted; where a class is genuinely emitted by an inline script or is a documented no-style hook, the scan carries a NAMED exception with the reason beside it, never an open list. The reverse direction (a rule no markup uses) is deliberately NOT part of this scan this wave — DEC-968 is adopting the one known instance, and a dead-rule check landing first would fail on a defect another lane is fixing.
