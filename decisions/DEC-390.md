# DEC-390: The phone card transform adds no markup by default; ambiguous cells get a data-label mirrored from their own th

DEC-386 fixed that phone cards come from CSS on the same markup, but not how a cell keeps its meaning once thead is hidden. Wave-4's Submissions lane answered it one way (order/nth-child on the existing tds, zero markup) and three more lanes -- forms, contacts merge/import, review results -- are about to answer it again. Settle it once. Default: reflow with `order`/`nth-child` on the existing tds and add nothing to the DOM; a title, a name or a status pill is self-describing and a micro-label above it is noise. Escape hatch, for values that are meaningless without their column header -- the Review results table's per-criterion score columns are the clear case, since its column count is dynamic (4 + one per rating criterion + one per dropdown criterion) and every added cell is a bare number: the component sets a `data-label` attribute on the td from the same string it passes to that column's th, and the page stylesheet renders it through `td::before` at the DEC-367 10px type floor. Attributes only -- no wrapper elements, no cell hidden, no phone-only DOM branch (DEC-386 stands). Mirroring the th string rather than hard-coding a second copy is the point: one edit renames both.
