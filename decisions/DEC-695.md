# DEC-695: A thrown render is a DESIGNED error state, never a blank page: one route-level error boundary, asserted per role

Mandate item 33 names this THE CLASS after the third instance: Overview's undefined.length (DEC-370), then the shared shell's badge fetch against an organizer-only endpoint, each of which produced a completely empty body for a whole role rather than any visible failure. Verified on main: the data-side fix landed (app/src/lib/useNavExceptions.ts:31-38 now gates the /overview fetch on role === 'organizer'), but the CLASS did not — a filesystem scan of app/src finds no ErrorBoundary, no componentDidCatch, nothing between a page's throw and React unmounting the tree. That is the opposite of the house rule: failing loudly means the failure is VISIBLE, and an empty document is the quietest failure a web app can produce. One boundary wrapping the routed content, rendering a designed state (label, heading, the message, a reload control, a way back), converts every future undefined.length from a silent P0 into a bug report the operator can read. It composes with, and does not replace, the per-role render sweep — the sweep proves non-empty, the boundary makes non-empty achievable.
