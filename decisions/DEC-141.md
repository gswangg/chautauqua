# DEC-141: Reviewers can list events: GET /api/v1/events returns plan-assignment-derived events for role=reviewer; event mutations stay organizer-only; queue UI distinguishes plan-not-open from queue-empty

The reviewer persona's event selector 403s because the events list route is blanket organizer-only, which breaks the whole reviewer surface (their SPA cannot resolve a current event). Contract: for role=reviewer, GET /api/v1/events returns the org-scoped events reachable via their plan_reviewer rows (join plan_reviewer -> evaluation_plan -> event, deduped); organizers keep the full org list; speakers remain excluded; POST/PATCH /events and all tracks/rooms routes remain organizer-only. Separately, ReviewerQueue currently renders 'Nothing left in your queue' when the server says open:false — it must instead say the plan is not currently open (with dates), because conflating 'done' with 'closed' is exactly what misled the eval and would mislead a real reviewer.
