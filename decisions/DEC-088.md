# DEC-088: Perf-probe seed contract: pinned literals for schedule, evaluation plan, and 12 reviewers in the seed_perf_ namespace

DEC-086's perf probes need schedule, plan, and reviewer data the 2k-row perf seed lacks. Pinning exact literals here lets the seed task and the smoke task stay file-disjoint (smoke hardcodes these values instead of importing new lib exports). Contract: 10 rooms with ids seedId("perf_room",1..10); ALL 300 accepted submissions get schedule_slot rows — 100 per day across 2028-06-01..03, 30-minute slots starting 09:00 (startMin 540), room assigned round-robin, slot ids seedId("perf_slot",n); one evaluation_plan id "seed_perf_plan_0001" (= seedId("perf_plan",1)), name "Perf Review Plan", rounds 1, scale_json {"min":1,"max":5}, criteria_json [{"id":"overall","label":"Overall","weight":1}], anonymized 0, open/close/filters/max_evaluations all NULL; 12 reviewer users ids seedId("perf_reviewer",1..12), emails perf.reviewer.<i>@example-perf.test (i unpadded), password "PerfReviewer!2027" hashed via the same hashPassword scripts/seed.ts uses (DEC-004), role reviewer, org seedId("org",1); 12 plan_reviewer rows (ids seedId("perf_plan_reviewer",i)) all with track_id/submission_id NULL (full-plan scope); 600 round-1 evaluations (ids seedId("perf_eval",n)), reviewers round-robin over the first 600 submissions, scores_json {"overall":(n mod 5)+1}, submitted_at set. INSERTs must NEVER name current_round, so the seed works with or without the 0009 migration. Idempotent deletes extended children-before-parents: evaluation, plan_reviewer, evaluation_plan, schedule_slot, room (all via event/plan/id LIKE 'seed_perf_%'), and user WHERE id LIKE 'seed_perf_%'.
