# DEC-495: A ceiling that is never filled is not a measurement: the perf seed reaches SPEC's 800-speaker top end

docs/verification-log/task-w23-f-public-ceiling-measured-stage1.md said it plainly against its own interest: "this run does not itself exercise an 800-speaker event (the perf seed's public-visible speaker count for perf-2k is 300, bounded by its 300 accepted+scheduled submissions, not by the paging ceiling)". SPEC.md:73-76 names 200-800 speakers and SPEC.md:324-326 requires every number be "measured at scale-target row counts", so the top of the stated range is unmeasured on the one surface (the public speakers list + its .json twin) where the range is the design constraint. The realistic shape of an 800-speaker/300-session event is co-speakers, not more sessions: scripts/perf-seed.ts:212-224 attaches exactly one visible participant per submission. Decision: the perf seed attaches additional visible, accepted-invite participants to the existing accepted submissions, drawn from the existing perf contact pool, so that the count of DISTINCT publicly-visible speakers on accepted + content-approved + scheduled submissions is >= 800 -- without changing PERF_SUBMISSION_COUNT (2,000) or the accepted-submission count (300), so every existing perf check keeps its meaning. The reachable count is asserted by a pure unit test over the seed's own helpers, and the deepest public speakers page is then re-measured against its 150 ms public-class budget.
