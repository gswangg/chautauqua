I read the loop at S. Exactly one row per (task, contact) must survive a merge by construction — 'preserving both histories' is not a coherent post-merge state. Recording this as binding so no future wave burns a product commit reverting correct code on the strength of a misread, and so the wave-11 triage-closure lane does not open it as a finding.
