# DEC-780: The organiser's submission detail carries the format and the placement

Two probe findings share one cause. CNT: the New-submission dialog now writes `format` (DEC-755 validates it on POST and PATCH /submissions/:id alike, src/routes/api/submissions.ts:112-128) but no organiser surface EDITS it afterwards, so a mis-picked format is unfixable. EMB: the organiser's submission detail omits date/time/room for a session that is placed on the agenda -- the detail payload never selects schedule_slot at all (no reference to scheduleSlot anywhere under src/server/repo/submissions/). Decision: the detail payload gains the session's slot (day, startMin, endMin, roomName; null when unplaced) from the SAME schedule_slot row the agenda writes, and the detail page renders one placement line in the event's timezone plus a Format control whose change PATCHes the already-validated `format` field. No new writer, no second source of truth: the server rule for a legal format value stays parseFormatField.
