# DEC-030: Overview is a worklist: one GET /api/v1/events/:eventId/overview payload, six cards, every number links to the screen that clears it

SPEC §2.3: dashboards are worklists, not reports, and §7 demands one round trip per view. GET /api/v1/events/:eventId/overview (organizer-only) returns one payload from joined queries in src/server/repo/overview.ts: { triage: { pending, accept_queue, decline_queue }, review: { plans, evaluationsSubmitted }, speakers: { contactsOwing (distinct contacts with a pending task_assignment in this event), overdueAssignments (due_date < now, status pending) }, content: { awaitingApproval (accepted submissions with content_status='pending') }, agenda: { unplaced (accepted without schedule_slot), conflicts (count from src/domain/schedule.ts findConflicts over this event's slots) }, comms: { sentLast7Days, lastSentAt } }. The SPA Overview page renders six cards in nav order, each with the count, one plain-language line ('14 submissions waiting for triage'), and a link into the owning section (/submissions?status=pending, /review, /speakers, /content, /agenda, /comms); zero states say what to do next ('Open your CFP form' etc.). No charts, no trend graphs — this screen answers 'what needs my attention' and nothing else.
