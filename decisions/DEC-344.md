# DEC-344: The central files library becomes a server-paginated, server-filtered list; chain and lead-speaker resolution are page-bounded; the quadratic participant scan and the whole-event load in resolveLatestVersions are deleted

Read live on main. src/server/repo/files-library.ts:74 listEventDeliverableFiles(db, eventId) loads EVERY submission in the event (line 83) before it looks at a file at all, then every file row, then every participant row, and src/routes/files.ts:198 hands the whole thing back under a fake envelope `{ items, total: items.length, page: 1, perPage: items.length || 1 }` — the same lie DEC-342 named on the reviewer queue. app/src/pages/content/FilesLibrary.tsx:26 fetches it once with no page, no filter and no search and renders every row. Cost is a function of the event's total submissions and files, never of page size — squarely DEC-333's stage-1 rule and a direct violation of SPEC §7 'Server pagination + filtering on all admin lists'. files-library.ts:131 additionally runs `participantRows.find(...)` INSIDE a loop over participantRows, which DEC-342 already called a defect on sight, and resolveLatestVersions (:187) calls listEventDeliverableFiles and then re-loads every file of the event a second time to serve a <=50-id ZIP request. DEC-342 deferred this item only because the perf seed wrote no file rows; task-w20-d closes that gap in the same wave, so the conjunctive test in DEC-333 is met and the fix lands now. Binding contract: (a) listEventDeliverableFiles(db, eventId, params) where params = { page, perPage, kinds, q } returns { items, total, page, perPage }; (b) the page is selected by ONE statement over `file` with `previous_file_id IS NULL` (chain roots only, preserving DEC-247) inner-joined to `submission` on submission.event_id = :eventId, with kinds pushed in as an inArray and q as DEC-336's AND-across-tokens x OR-across-columns over lower(file.filename), lower(submission.title) and a correlated EXISTS over participant JOIN contact on lower(first || ' ' || last), each `like ... escape '\\'`, plus a companion count(*) over the identical WHERE for `total`; (c) deterministic order file.created_at DESC, file.id ASC so OFFSET paging is stable; perPage default 50, max 200 via clampPage/clampPerPage (src/lib/pagination.ts); (d) version chains, versionCount and the latest-version metadata are hydrated ONLY for the page's submission ids (chunkIds per DEC-078), so cost is bounded by page size; (e) the lead speaker is resolved in a single pass building Map<submissionId, {order, name}> keeping the minimum participant.order among role='speaker' — the .find-inside-a-loop is deleted, not optimised; (f) resolveLatestVersions stops calling listEventDeliverableFiles entirely: it loads only the requested file rows, asserts each one's submission belongs to eventId (preserving DEC-160's whole-request-404s rule, no silent skips), loads the files of just those submissions, and returns submissionTitle alongside id/filename/contentType/r2Key so the archive route stops re-scanning the event for titles. Filter/paging semantics are event-wide: `total` is the count of matching chains in the event, never the page length.
