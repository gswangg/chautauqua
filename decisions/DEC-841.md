# DEC-841: The error surface follows the REQUEST's path, not the middleware that happened to run — one predicate shared with the 404 handler

VERIFIED: htmlSurface is set in exactly two places (src/server/middleware.ts:258 csrfForm, :302 csrfFormOrHeader), both form-POST CSRF middlewares, so every server-rendered GET that throws — /portal/*, /e/:slug/*, /submit/:slug, /login, /files/:id — is answered by registerErrorHandler (src/server/http.ts:161) with a raw {"error":{...}} JSON blob rendered into a browser window. The app already owns the correct rule one file away: registerNotFoundHandler (src/server/not-found.tsx:71-81) branches on API_PREFIX — JSON inside /api/v1, an HTML page outside it. Decision: that IS the rule, and it lives in ONE exported predicate (isApiPath(path)) consumed by both handlers; an error's shape is decided by the route it happened on, never by which middleware ran first. The existing htmlSurface flag survives only as an explicit override for a form post (a browser form POST to /api/v1 is still HTML), it is no longer the sole source of truth. This is the fixed-point rule the codebase already applies to 404s, extended to 400/403/409/500 — a full-page navigation never ends as a JSON envelope, and an /api/v1 fetch never gets HTML.

## Amendment (wave 54): the error page's back link compares ORIGINS, not just parses a URL

safeReferrerPath (src/server/http.ts:221-229) returns `url.pathname + url.search` from an arbitrary Referer header and never compares hosts, falsifying its own line-218 comment ("Only a same-origin path is ever used"). A referer of `https://evil.tld//evil.tld/x` yields `href="//evil.tld/x"` — a protocol-relative off-site link — on every HTML error page rendered by registerErrorHandler, which is every failed plain form post and every non-API GET. Rule: the helper takes the REQUEST url alongside the referer, returns '/' whenever the origins differ, and additionally refuses any pathname beginning with '//' even same-origin; a comment claiming a check is not a check.

## Amendment (wave 14) — one error responder for the whole app; a sub-app onError may change headers, never the body shape

src/server/http.ts:241 implements the app-wide rule that an HTML navigation never ends as a JSON blob (htmlSurface, or any non-API-path request, gets renderHtmlError). src/routes/public/index.tsx:98 then installs its own onError purely to force Cache-Control: no-store (DEC-324) — and, because Hono wraps a sub-app's handlers with the sub-app's own handler, it takes over the body shape too. Result: a thrown error on an anonymous HTML surface (/e/:slug/*, the over-cap schedule.ics?ids= case its own comment cites, or any 500) shows a raw JSON envelope to a visitor. Ruling: http.ts exports the single responder, errorResponse(c, err), which registerErrorHandler delegates to; the public sub-app keeps its header override and delegates the body. A scan test enforces that no sub-app under src/routes/** builds its own error envelope inside .onError.

## Amendment (wave 16): a PUBLIC HTML navigation never ends as a naked document either -- the public 5xx wears the public shell

DEC-841's rule is that the error surface follows the REQUEST's path and an HTML navigation never ends as a JSON blob; src/server/http.ts:242 now honours that with renderHtmlError. But renderHtmlError is a deliberately minimal <p role=alert> + 'Go back' document, and src/routes/public/index.tsx:98 routes every thrown error on the visitor-facing surfaces through it. The same path's 404 renders publicNotFound -- full chrome, event identity, real navigation. So a visitor who hits a 404 gets the product and a visitor who hits a 500 gets a white page with two words, on the surface SPEC principle 5 calls the product's output. The envelope decision was inherited; the chrome decision was never made. Public HTML surfaces get an error card in the PublicShell at the same status, no-store preserved. Feed/file extensions (.ics/.xml) are not HTML navigations and keep today's envelope -- decided by the ONE existing predicate, never a second one.

## Amendment (wave 16): landed -- publicErrorDocument reuses publicNotFound's own card, no forked shell

Landed at src/routes/public/not-found.tsx (publicErrorDocument, sibling of publicNotFound, same NotFoundDocument/resolveNotFoundEyebrow helpers, role="alert" on the message, a link back to `/e/:eventSlug/sessions` ahead of the anonymous home/login pair) and src/routes/public/index.tsx (publicRoutes.onError: Cache-Control: no-store set first per DEC-324, then a `\.(ics|xml)$` pathname check keeps feed/file-extension requests on http.ts's errorResponse unchanged, everything else asks the ONE predicate -- now exported as wantsHtmlResponse(c) from src/server/http.ts, factored out of errorResponse itself so no second copy of the htmlSurface/isApiPath check exists -- and renders publicErrorDocument at the ApiError's own status, or 500 for an unexpected throw). NotFoundDocument gained optional title/heading/alert props (defaulted to the existing 404 copy, so every prior 404 call site is byte-unchanged) rather than a forked component. Verified by test/public-error-shell.test.ts: an HTML surface's thrown Error and thrown ApiError both render the public chq-auth-card chrome with role="alert" and no `{"error":` body; schedule.ics over the id cap still gets today's bare renderHtmlError page, proving the feed-extension carve-out.

## Amendment (wave 17): the feed predicate is one derived list — .json fell out of it, so a machine feed answers a human card

publicRoutes.onError's FEED_EXTENSION_PATH is the hand-typed regex /\.(ics|xml)$/ (src/routes/public/index.tsx:108). The public sub-app registers THREE machine surfaces: /embed/:slug/:surface{[a-z]+\.json}, the .xml twin, and schedule.ics/agenda.ics. .json is missing, so an error on a JSON feed now renders the full public HTML card to a consumer that called JSON.parse on it. And the branch the regex does catch falls through to errorResponse, which for a non-/api/v1 path returns http.ts's bare HTML page — so no feed actually gets the envelope the amendment claimed. One exported FEED_EXTENSIONS list drives the predicate, feed paths answer with the DEC-013 envelope through the existing errorEnvelope helper (never a second builder), and a test walks publicRoutes.routes so a future .csv feed cannot be forgotten the way .json was.
