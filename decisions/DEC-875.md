# DEC-875: The open review plan carries a real per-talk cap: null is not a neutral default when three surfaces read it

VERIFIED: both seeded evaluation_plan rows set `max_evaluations: null` (scripts/seed.ts:1153, 1288), so the Reviews-per-talk field, the "· N reviews each" subtitles and the distribute/shortfall summary all render empty on a fully-seeded database — the mandate calls this the highest-leverage Review seed change, because one column restores three surfaces at once. Verified safe by enumeration of the seeded evaluations: track-0 submissions get one evaluation each (7 of 10), track-2 one each, track-1 two each (reviewerB + reviewerD) — the maximum per submission is 2, so a cap of 3 removes nothing from any queue (needsMoreRatings is `ratingsCount < cap`) and turns the shortfall arithmetic into real, non-degenerate numbers. Plan 2 stays null: it is closed and fully evaluated, and a finished plan has nothing left to cap. The seed's own test asserts the cap by reading the emitted SQL, so a future seed edit cannot silently drop it back to null.
