# DEC-917: One optionality grammar for every form row in the product: no asterisks, '· optional' on the skippable, and a prop that renders nothing is deleted

DEC-909 fixed this for src/views/form-render.tsx (public CFP, /portal/edit, /portal/tasks): required fields carry NO marker, optional fields append ' · optional', because a submitter's real question is what they may skip. The admin half of the product never got the rule and is worse than unmarked -- app/src/components/ModalFrame.tsx:52 destructures a `required` prop and never uses it, so seven call sites (EventSwitcher.tsx:97/107/121/132/144, NewSubmissionModal.tsx:117, PipelineBoard.tsx:306) pass a flag that renders literally nothing, while the genuinely skippable rows beside them (Venue, Due date, Why them, Speaker name/email, Company, Bio) say nothing either. A decision with no code is a lie, and a dead prop is a decision with no code that seven callers still believe in. Meanwhile Scorecard.tsx:387 prints a bare ' *' on required text criteria -- an asterisk is a legend the page never prints. Rule: FormRowProps.required is DELETED (no shim, no deprecation); FormRow takes `optional?: boolean` and renders the identical suffix string form-render.tsx uses, so the two renderers cannot drift; each call site declares optionality from what its OWN submit handler actually accepts as blank, read not guessed; and no surface in the product marks a field with an asterisk.
