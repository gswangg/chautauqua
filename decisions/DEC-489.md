# DEC-489: Every embed knob is honored identically by a surface's HTML and its .json twin, from one declared surface->knob table

DEC-484 landed the total/page/perPage half but inverted the asymmetry it was written to kill. src/routes/public/index.tsx:270-280 (getSurfaceFeedPage) now honors ?limit= for speakers and gallery, while src/routes/public/dispatch.tsx:53,62 still hard-codes PUBLIC_PER_PAGE for the same two surfaces: /embed/x/speakers?limit=50 renders 12 and /embed/x/speakers.json?limit=50 returns 50 -- one surface, two page sizes depending on the extension, which is verbatim the defect DEC-484 names. Symmetrically ?day= filters agenda/schedule in HTML (dispatch.tsx:70,75) and is dropped entirely by the JSON feed. And ?day= on the sessions surface is accepted and carried forward into search/Show-more links (src/routes/public/sessions.tsx:35,47) while filtering nothing -- a knob the URL advertises and the query ignores, against DEC-289's own definition (src/routes/public/query.ts:39: "day = agenda/schedule filter"). The table, decided here once: sessions = trackId, limit, fields, accent; speakers/gallery = q, limit, accent; agenda/schedule = day, accent. Both renderers honor exactly that set and nothing else, graded by an executable surface x knob parity test rather than by prose.
