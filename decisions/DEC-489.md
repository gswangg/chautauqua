# DEC-489: Every embed knob is honored identically by a surface's HTML and its .json twin, from one declared surface->knob table

DEC-484 landed the total/page/perPage half but inverted the asymmetry it was written to kill. src/routes/public/index.tsx:270-280 (getSurfaceFeedPage) now honors ?limit= for speakers and gallery, while src/routes/public/dispatch.tsx:53,62 still hard-codes PUBLIC_PER_PAGE for the same two surfaces: /embed/x/speakers?limit=50 renders 12 and /embed/x/speakers.json?limit=50 returns 50 -- one surface, two page sizes depending on the extension, which is verbatim the defect DEC-484 names. Symmetrically ?day= filters agenda/schedule in HTML (dispatch.tsx:70,75) and is dropped entirely by the JSON feed. And ?day= on the sessions surface is accepted and carried forward into search/Show-more links (src/routes/public/sessions.tsx:35,47) while filtering nothing -- a knob the URL advertises and the query ignores, against DEC-289's own definition (src/routes/public/query.ts:39: "day = agenda/schedule filter"). The table, decided here once: sessions = trackId, limit, fields, accent; speakers/gallery = q, limit, accent; agenda/schedule = day, accent. Both renderers honor exactly that set and nothing else, graded by an executable surface x knob parity test rather than by prose.

## Amendment (findings wave 12)

DEC-489 declared one surface→knob table "graded by an executable surface x knob parity test rather than by prose", and DEC-490 put the SPA's copy of it in app/src/pages/settings/embedSnippet.ts:66-81. That copy has since drifted three times by comment (DEC-783/804 added trackId+q, DEC-851 made trackId a HIGHLIGHT and removed format from agenda entirely, DEC-990 added trackId to speakers/gallery) and is now provably wrong: its own comment at :74-78 asserts "agenda/schedule honour trackId/format/day/q/limit/accent as real SQL-level predicates on getPublicAgenda", while src/routes/public/dispatch.tsx:174-259 parses no format at all on those surfaces ("?format= is not an agenda facet at all") and calls getPublicAgenda(db, event, { day, q }) with no perPage, so `limit` is discarded too. buildEmbedUrl therefore serializes ?format=&limit= into a copied iframe snippet that the published page ignores — the exact generator-form lie DEC-490 was written to kill.

RULING: the HTML reader (dispatch.tsx) is normative and is NOT changed. The table is re-declared as sessions = trackId(filter), format, roomId, day, q, limit, fields, accent; speakers/gallery = trackId(filter), q, limit, accent; agenda/schedule = trackId(HIGHLIGHT), day, q, accent. It has ONE home in pure core (a new src/lib/embed-knobs.ts, following the existing src/lib/embed-formats.ts / embed-fields.ts boundary-crossing pattern), and trackId carries an explicit `highlight` annotation on agenda/schedule so the builder can say "Highlight track" instead of implying a filter. The parity test asserts the table against BOTH readers (dispatch.tsx and the .json/.xml feed twin), not against prose.
