# DEC-712: A contact's labels are DERIVED participation roles, batched one query per page -- no invented labels column

The mock's LABELS column has no backing field: the contact table has no labels/tags. The choice is to invent a schema column (a migration, merge-combine semantics, import mapping, and a free-text vocabulary nobody curates) or to render what the data already knows -- the roles this person holds on the org's events. The derived reading is truer to the mock's intent (small-caps role chips) and costs one batched query over event_participant for the page's ids. Derived also means never stale: a role change updates the chip with no second write path.
