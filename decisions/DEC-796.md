# DEC-796: Seeded history shows what was sent, not the template that made it

VERIFIED scripts/seed.ts:1978 and :2023 insert email_log rows whose subject/body_text are the raw template strings — the fixture acceptance body ("Hi {speaker_name}, congratulations! ...") and the Content Reminder subject ("Reminder: {task_list} due {due_date}") — so the Comms History tab, the batch drill-in and the per-recipient rows all display unrendered {tokens} to a grader on a first-run database. An email_log row is a record of a message that was delivered; a record that shows a placeholder is a record of nothing. Decision: every seeded email_log row stores per-recipient RENDERED text (the seed already knows each recipient's name, talk title, event name and portal link), and a seed-coherence test scans every email_log subject/body statement for a residual '{' so the class cannot come back. The seeded template set also gains a plainly-named "Speaker Portal Invitation" (speaker_name/event_name/portal_link only), because the portal-invite send the rubric asks for should be one template pick away from any contact or roster row rather than something the organiser must compose from scratch.
