# DEC-715: Reordering has ONE affordance, operable by pointer and by keyboard: the drag handle IS a button

The mock's form-builder row carries a drag handle and nothing else; prod adds a second action line with up/down arrows, making rows ~2.5x the mock's height. Simply deleting the arrows would repeat the Tier-0 agenda failure (a drag-only surface is invisible to the accessibility tree). Making the handle a real <button> whose accessible name states its position, moving the item on ArrowUp/ArrowDown, collapses two affordances into one that both input paths can drive -- the same resolution that fixed the agenda cards. One control, one meaning, no second reorder mechanism to keep in sync.

## Amendment (wave 18): a grid row declares one track per child it renders, and a field error spans the row

`.chq-review-criterion-row` (app/src/pages/review/review.css:722-729) declares four tracks (`1fr 1fr auto auto`) while the editable row renders five non-error children — drag handle, label input, guidance input, kind cell, Remove button (app/src/pages/review/PlanEditor.tsx:1256-1365) — so Remove wraps onto an implicit second row, and each of the three conditional `.chq-review-field-error` spans becomes a grid item that displaces everything after it. This is the gate-5 'criteria row: N tracks, N+1 children' finding surviving a rebuild in a new shape (the frame's anatomy is handle | label | guidance | weight+share | action). RULING: five explicit tracks (`20px minmax(0,1fr) minmax(0,1fr) auto auto` — minmax(0,1fr) because a 1fr column has a min-content floor, per the standing field-guide lesson), and validation errors get `grid-column: 1 / -1` scoped to this row so an error never steals a control's cell. The ≤700px stack rule is untouched (mobile is a separate round).
