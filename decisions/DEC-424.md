# DEC-424: The 390px overflow pass stops counting elements a horizontal scroller legitimately holds, and names the content-spill when the document overflows but no box escapes

docs/verification-log/task-w10-h-render-sweep-redesign.md:171-192 records six admin-advisory FAILs at 390px. Five of them (/admin/overview, /admin/submissions, /admin/submissions/forms, /admin/content, /admin/agenda) name children of .chq-chipstrip, .chq-status-pills or .chq-overview-deadlines -- and every one of those containers is overflow-x:auto at <=700px (app/src/styles.css:534-544, app/src/pages/submissions/submissions.css:436-446, app/src/pages/overview/overview.css:222-229), i.e. DEC-414's OWN sanctioned remedy. All five also report scrollWidth 390 == viewport 390: the document does not overflow at all. The instrument (scripts/render-sweep.ts:305-313) flags any visible element whose rect.right exceeds the viewport, so applying the prescribed fix does not change the verdict -- the pass can never read all-PASS and DEC-387's flip condition can never be met, and a gate that reports five non-defects trains the swarm to ignore it (the same harm DEC-419 forbids when it says an instrument failure is never written down as a number). Rule, settled here so no lane re-derives it: (1) an element contributes to maxElementRight/overflowOffenders only if no ancestor between it and document.body has computed overflow-x of auto or scroll; (2) document.scrollingElement.scrollWidth > innerWidth + 1 remains a hard FAIL, unchanged -- that is the page-level overflow this pass exists to catch; (3) when (2) fires but no element box escapes, the offender list is populated instead from elements whose OWN scrollWidth exceeds clientWidth (content spilling its box -- a nowrap string or unbreakable token), widest spill first, because silence is not an acceptable output for a failing route and the sixth FAIL (/admin/review/plans/:id/results, scrollWidth 415 > 390) shipped with an EMPTY offender list; (4) DEC-401's structural-only descriptors, DEC-411's shim-first rule and DEC-387's flip timing are all unchanged -- ADMIN_MOBILE_PASS_BLOCKING stays false this wave.
