# DEC-455: "Required" means non-blank: a string answer whose trim is empty is ABSENT to validateAnswers

src/forms/validate.ts:48 tests `value === ""` for absence, so "   " satisfies every required field in the product -- a blank session title reaches the public agenda and a blank email reaches DEC-454's collision. The fix is one line in the absence branch: a string whose .trim() === "" is treated exactly as undefined/null (required => errors[field.id] = "required"; optional => dropped from cleaned). This is deliberately scoped to the absence test only: values that survive are still stored as submitted (no silent trimming of user text), because changing stored values is a separate behavior change nobody asked for. The rule is separated from DEC-454 because its blast radius is every required field of every form, not just email, and the ledger row it repairs ("Public submission validates server-side against form schema", graded VERIFIED at task-w16-f-spec-audit-stage1.md:86 from the presence of a validateAnswers call) is a different row from the email one.
