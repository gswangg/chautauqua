# DEC-611: Overview names the public surfaces it produces, and links to them by the event's own slug

Every public widget the product ships is unreachable from the admin without knowing the /e/:slug/ URL scheme by heart — the organiser's dashboard talks about submissions, content and conflicts but never about the pages an attendee sees, which is also how a judge is expected to find the embeddable surfaces. Overview gains a section listing each public page and the CFP form for the current event, resolved from the slug that GET /api/v1/events already returns, never from a guessed slugification of the name. The toolbar gains the designed Export and New-submission actions in the same pass, both pointing at endpoints that already exist.

## Amendment (wave 2): the Public-pages row is a quiet row like its siblings, and asserts no count the payload does not carry

In "No action needed" the Public-pages row uses its own class and full-size meta, so its value column lands at x=304 against its siblings' 220.5 and its type reads 12px against their 14px — one row inventing a second grammar inside a five-row section. Ruling: it renders through the same two-column quiet-row grid and type as the sibling rows, keeping the single /e/<slug> link inside the meta. It does NOT gain a "17 sessions live" count: the overview payload carries no published-session number, and the design's copy rule 3 forbids asserting what no endpoint stores. If a later wave adds publishedSessionCount to the payload, the copy follows then.
