# DEC-808: One page measure, finally adopted by the admin SPA

VERIFIED DEC-744's --chq-measure token exists in both app/src/styles.css:94 and src/views/theme.ts:83, but adoption is lopsided: the server-rendered surfaces (submit-views, docs, mailbox) all wear <main class="chq-measure"> while the admin SPA has only three consumers (NotFound, RouteErrorBoundary, two rules each in forms.css/review.css). The user re-confirmed the symptom on a recent commit — submission detail content stops around 75% width with a dead right gutter, and the form builder clamps at 720px inside a 1372px frame. Decision: finish the sweep by the token's own rule — a single-column subscreen clamps with var(--chq-measure) and centres; a page that carries an aside fills the frame and clamps nothing — and pin it with a scan that ENUMERATES app/src CSS files rather than naming them, because a hand-listed manifest desyncs the moment someone adds a page. Hard-coded pixel clamps on page/content containers are the defect being removed, not a style preference.

Its BODY textarea, byte-identical at 187x166 across three gates, fills the field column (width: 100%) with a real min-height.

## Amendment (wave 83, v12 mobile campaign w1): the 53 phone frames are an enumerated population with a claim ledger and a ratchet

The campaign's goal is "every screen matches its v12 frame on desktop AND phone", and nothing in the tree can currently answer "how many of the 53 width:390 frames are claimed?" — the mandate's own per-cluster counts are a hand-written list in docs/mobile-campaign.md, which is exactly the desync DEC-808 rules against ("a scan that ENUMERATES … rather than naming them"; field guide: A DIRECTORY IS NOT A POPULATION, A HAND-LISTED POPULATION IS NOT A POPULATION). Ruling: a scan enumerates every `width:390px` frame in docs/design/*.dc.html by reading the files, resolves each frame's title from its preceding label span, and requires a claimed frame to be cited by `docs/design/<file>.dc.html:<line>` inside some *.test.ts/*.test.tsx — the same citation form DEC-976 already governs. The claimed COUNT is a ratchet (house idiom, cf. vocabulary-duplication-ratchet.scan.test.ts), never an allowlist populated from failure output: it may only go up, and the failure message names the unclaimed frames so the planner schedules them. This is the campaign's completion metric; goalComplete is reachable only when it reads 53 of 53.


## Amendment (wave 84, v12 mobile campaign w2): A phone frame is claimed by any citation inside its span, and the ledger's floor may never sit below the truth

Wave 1 ruled the 53-frame ledger exists but left two things undecided that would otherwise be settled by whichever worker wrote the file first. (1) WHICH LINE CLAIMS A FRAME. A test that pins a frame's H1 cites the H1's line; a test that pins a dock cites the dock's line. Requiring the citation to name the `width:390px` line itself would under-count every honest citation in the tree. Ruling: a frame SPANS from its `width:390px` line to the line before the next frame declaration in the same file (or EOF), and a citation to any line in that span claims it. Measured against main today that rule reads 12 of 53; an exact-line rule reads near zero while being no more truthful. (2) THE RATCHET'S POLARITY. The house's existing ratchet (vocabulary-duplication) is a CEILING that must never sit ABOVE the truth, because a ceiling above the truth licenses new debt. This one is the mirror: a FLOOR that must never sit BELOW the truth, because a stale floor licenses stagnation — and the field guide records three consecutive waves that read a ratchet's closing sentence as prose and carried the number. Ruling: `MIN_CLAIMED_PHONE_FRAMES` is seeded at the count the scan measures when it lands; one test asserts `claimed >= MIN`; a companion test FAILS when `claimed > MIN`, naming the new number, so the floor is raised in the same wave the coverage lands. The failure message enumerates unclaimed frames by `<file>:<line>` and resolved title so the planner can schedule them. No allowlist, no exemption list, and the total (53) is derived by reading the files, never written down.


## Amendment (wave 85): a floor that sits below the measured truth is stale, and a stale floor licenses stagnation exactly as a high ceiling licenses debt

test/phone-frame-ledger.scan.test.ts asserts `CLAIMS.length >= CLAIMED_FLOOR` and nothing else, with CLAIMED_FLOOR at 6. Measured on main today: 6 of 53. That means 47 unclaimed frames read GREEN forever, and every future wave can land zero coverage without the instrument saying a word — the exact mirror of the vocabulary-duplication ceiling this guide has flagged as carried-not-spent for three consecutive waves (DEC-180 w79). A one-sided ratchet is half an instrument. RULING: the ledger gains its staleness half — it FAILS when `CLAIMS.length > CLAIMED_FLOOR`, with a message naming the exact integer to write — so the moment a wave lands real coverage the floor must move with it. Raising the floor is a merge-train act performed once per batch, never a worker's edit mid-lane; the failure text must say so, because a worker who bumps it on a branch re-creates the same staleness one batch later. goalComplete for this campaign remains CLAIMED_FLOOR reaching 53.

## Amendment (wave 139): a receipt's proximity window is measured from the CITATION, so rationale prose belongs ABOVE the `it(` title — never between a citation and its first expect()

`app/src/frame-citation.scan.test.ts`'s DESKTOP receipt scan (DEC-808 wave-107) requires a backtick quote in the same comment as a frame citation and a real `expect(` within six source lines beneath it. `test/desktop-frames-review.test.ts:79` carries `docs/design/Chautauqua Review.dc.html:706` in its `it()` title, quotes the frame verbatim on the next line, and then a four-line DEC-882 rationale comment pushes the first `expect(` to eight lines down — so a claim that is honest, quoted and doubly-receipted reads as unreceipted and is main's only red in that scan. The wrong repairs are raising `DESKTOP_UNRECEIPTED_CLAIM_CEILING` (papering over the scan) and deleting the rationale (destroying the reason a later reader needs). RULED: the window is a property of the citation, not of the test body, so explanatory prose about WHY a claim is shaped the way it is goes above the `it(` title where it describes the test; the span between a citation and its first assertion carries the frame quote and nothing else. The comment text moves verbatim — a rationale that has to be shortened to fit a window is a rationale that was in the wrong place, not a rationale that was too long.

## Amendment (wave 18): A population-sanity tripwire guards NARROWING, so it is a floor and a superset check, never an equality

`app/src/negative-margin-adjacency.scan.test.ts:383` pins the swept population at an EXACT `display: none` count and `:406` pins an EXACT named list. The pin's own header states its purpose: catch a derivation that silently narrows (wrong root, wrong suffix filter, a broken template-literal split). An exact equality does catch that — and also fires on every legitimate phone-only reveal, which is precisely what this campaign produces every wave. Measured on main during this planning session it read 169, then 174, then 186 in under an hour as three separate merges landed, each time turning the fast tier red for work that was correct. A tripwire that fires on legitimate growth is a tripwire nobody reads, and it becomes a merge-conflict magnet on a file no lane owns. RULED: both population-sanity assertions become monotonic — the count is `toBeGreaterThanOrEqual(N)` and the named list is a SUBSET check (every named member is still found), each with its measured N restated at the current sha and a comment naming the narrowing failure it still catches. The real subject — new UNRECEIPTED negative-margin adjacencies — is already guarded by this file's own OFFENDERS ratchet, which stays an exact-zero ratchet and is not touched.
