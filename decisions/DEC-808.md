# DEC-808: One page measure, finally adopted by the admin SPA

VERIFIED DEC-744's --chq-measure token exists in both app/src/styles.css:94 and src/views/theme.ts:83, but adoption is lopsided: the server-rendered surfaces (submit-views, docs, mailbox) all wear <main class="chq-measure"> while the admin SPA has only three consumers (NotFound, RouteErrorBoundary, two rules each in forms.css/review.css). The user re-confirmed the symptom on a recent commit — submission detail content stops around 75% width with a dead right gutter, and the form builder clamps at 720px inside a 1372px frame. Decision: finish the sweep by the token's own rule — a single-column subscreen clamps with var(--chq-measure) and centres; a page that carries an aside fills the frame and clamps nothing — and pin it with a scan that ENUMERATES app/src CSS files rather than naming them, because a hand-listed manifest desyncs the moment someone adds a page. Hard-coded pixel clamps on page/content containers are the defect being removed, not a style preference.
