# DEC-385: One phone switch (max-width: 700px) and one set of phone metrics for every stylesheet in the product

Verified on main, the tree carries four different narrow-width breakpoints — styles.css and the shell tab bar switch at 700px, settings.css at 699px, content/comms/detail/agenda at 900px, event-switcher.css at 390px — so "the phone layout" is not a thing any lane can reason about and the render sweep's 390x844 measurements cannot be attributed to a rule. The phone switch is `@media (max-width: 700px)` everywhere, matching styles.css's two existing blocks and the width at which .chq-tabbar appears; a 900px block is permitted only as an intermediate two-column collapse and is never where phone metrics live; settings.css's 699px is normalized to 700px by whoever next owns that file. Inside the phone block the metrics are fixed here so seven parallel lanes do not each invent them: horizontal frame padding 16px (the mocks' phone frames use 16px, not the desktop 34px, which leaves 322px of usable width at 390px today), page title 27px, headline 29px, every interactive control `min-height: 44px` achieved with centred flex and never with padding (docs/design/README.md: "min-height:44px plus centred flex, not padding"), control radius `var(--chq-r-ctl-phone)`, chip and pill strips are `overflow-x: auto` with `flex-shrink: 0` children (with overflow hidden the last chip is unreachable), and any content wider than the viewport scrolls inside its own container so `document.scrollingElement.scrollWidth` never exceeds `window.innerWidth`. The shell owns the tab-bar bottom offset on .chq-main; no page stylesheet adds its own.

## Amendment (wave 12) — a phone-named class hidden at top level must be re-enabled inside a phone media query in the same stylesheet

app/src/phone-block-visibility.test.ts asserts one half of the contract (a phone-only class must be display:none, or absent, at top level) and never the other: nothing checks that the class is switched back ON under the 700px breakpoint. A class that is hidden everywhere and enabled nowhere is a picture that never renders — the mirror image of the desktop-leak bug the test was written for, and exactly the gap the mobile queue names ('enumerate ALL 22 chq-phone-* classes in the media override'). Ruling: the override side is asserted in the same scan, with per-selector exemptions carrying reasons. The invariant is repo-wide by construction (both stylesheet trees), never a per-area sweep.


## Amendment (wave 13) — ONE SSR phone action-bar band, declared once in THEME_CSS

Five separate 390 frames (Account "Change password · 390", Speakers "Roster · 390", Portal home, Portal · Your session, Submit a talk) draw the identical fixed footer: flex-shrink:0, 1px ink top rule, sunk-surface fill, 12px/16px/16px padding, 8px gap, a flex:1 centred primary at min-height 48 and a secondary at min-height 48. DEC-385 already owns "one set of phone metrics for every stylesheet in the product"; per-surface re-declaration of that band is exactly the per-page-fix pattern the mandate's standing rules forbid. RULING: the band is a named vocabulary — .chq-phone-actionbar / -primary / -secondary — declared exactly once, in src/views/theme.ts's THEME_CSS (the only stylesheet every SSR surface already includes), display:none at top level and display:flex inside the file's existing @media (max-width: 700px) block. Surfaces CONSUME the classes; they never restate the rules. Values are tokens only (DEC-383 bans colour literals in surface stylesheets); the frames' hex and their canvas drop shadows are never ported.


## Amendment (wave 84, v12 mobile campaign w2): SSR phone surfaces share the phone switch and the band metrics, but never the SPA's .chq-phone-* classes

w1-a landed `.chq-phone-head/-head-drill/-body/-dock/-back` in `app/src/styles.css`, which only the admin SPA bundle serves. Six of this wave's frames (Home x3, Account x2, Docs x1) render from `src/routes/**` against `src/views/theme.ts` and the `*.css.ts` modules; not one of them loads app/src/styles.css. Copying the class names into theme.ts would put one vocabulary in two files in a tree that already pins SPA/SSR token parity by set equality (DEC-372) and would break phone-block-visibility's no-top-level-`chq-phone-` invariant differently in each file — a second copy of a vocabulary with a delay fuse. Ruling: SSR pages keep page-local band class names and DO NOT gain `.chq-phone-*`. What is genuinely shared, and what SSR lanes must reuse rather than re-invent, is (a) the switch — one `@media (max-width: 700px)`, DEC-385's single direction — and (b) the band metrics, which are already tokens: head `padding:14px 16px` over a 1px ink bottom rule, dock `padding:12px 16px 16px` under a 1px ink top rule, and the two H1 registers `--chq-type-page-title-phone-size` (27px, cluster landing) and `--chq-type-page-title-phone-drill` (25px, back-linked drill-in), both present in theme.ts as of w1-a. A page needing a metric the tokens do not carry files it as a finding rather than inventing a number; SSR page lanes must not edit theme.ts, which stays shell-owned.


## Amendment (wave 85): single-direction is an ORDER as well as a direction: a stylesheet's phone block is its last top-level construct

content.css and comms.css each lost the equal-specificity tie to their own later desktop rules, were diagnosed independently by two lanes, and were fixed one file at a time with one bespoke pin each (SessionList.render.test.tsx:1297 'is the last block in content.css'). A per-file pin cannot see a sheet nobody has pinned, and the exposure is still live and measured: src/routes/portal/portal.css.ts declares its phone block at :444 of 752 lines; app/src/pages/settings/settings.css at :158 of 1439; app/src/pages/review/review.css at :333 of 2086; app/src/pages/speakers/speakers.css at :100 of 1441. RULING: DEC-385's single-direction rule gains its ordering half — narrow overrides wide, which in a flat stylesheet means LAST — and it is enforced by an ENUMERATING scan (readdirSync over every *.css under app/src and every *.css.ts under src/routes, never a manifest), which flags any declaration inside a max-width block whose selector is re-declared at top level for the same property AFTER that block closes. The violation count is a ratchet seeded at the measured truth and may only shrink; content.css and comms.css must read 0 forever, which is what makes the scan falsifiable rather than a rubber stamp.
