# DEC-263: Hand-authored SQL migrations are canonical; `npm run db:generate` is retired and schema/migration parity is enforced by a test

task-w3-a's closeout proved (by running it) that `drizzle-kit generate` emits a spurious migration re-declaring six existing tables and three existing columns, because migrations/meta/ snapshots stop at 0004 while 0005-0014 were hand-authored and renumbered (DEC-164). A generator that silently produces already-applied DDL is a house-style violation (fail loudly) and a live footgun for the next maintainer of an MIT repo whose premise is 'migrations in git'. Retroactively reconstructing snapshots for ten hand-edited migrations is not worth the risk. Decision: hand-authored migrations/NNNN_*.sql are the single source of truth; the `db:generate` npm script is DELETED (the drizzle-kit devDependency stays for ad-hoc introspection, so package-lock.json is untouched); migrations/meta/** is frozen historical data that nothing reads at runtime (`wrangler d1 migrations apply` reads the directory plus D1's own applied table); and the real risk - src/db/schema.ts declaring a table or column no migration creates, which breaks a fresh clone - is caught by a new test/migration-parity.test.ts that diffs getTableConfig() against the parsed CREATE TABLE / ALTER TABLE ADD COLUMN set. This closes the closeout's OPEN 'drizzle-kit snapshot staleness' item with a guard instead of a note.
