# DEC-015: Additive migration discipline; submission_track join; form.tracks_json

The initial schema (wave-1 task, still in flight) follows DEC-003, which omitted two things wave 2 needs; and parallel workers must never rewrite an already-committed migration. Discipline: migration files are append-only history — never edit a committed migration; all later schema changes ship as new numbered migration files plus append-only edits to the former src/db/schema.ts (now split across src/db/schema/). First addition (owned by exactly one task, w2-a, as the next-numbered migration — skip anything main already has an equivalent for): table submission_track { submission_id text references submission, track_id text references track, primary key (submission_id, track_id) } with FK indexes, because talks are submitted to one or more tracks (swyx) and reviewer assignment, filtering, and the agenda all key on a real join — track membership is NOT a form_field answer. Also form.tracks_json (JSON array of track ids offered on the form; null/empty means all event tracks) so J1's 'set one or more tracks on the form' has a home; add via ALTER TABLE in the same migration if the landed schema lacks it.
