# DEC-592: A public session's Format is the answer to one named form field, and an event without that field renders no Format row

EMB-01 and EMB-08 both require Format on public session cards and on the agenda drill-in, and the .json payload has no format key either. There is no format column in the former src/db/schema.ts (now split across src/db/schema/) — session format is a form answer, created by the seed as the literal id 'field_session_format'. Rather than sniff labels (hand-copied vocabularies drift) or add a migration, name the id once: SESSION_FORMAT_FIELD_ID in src/forms/types.ts, imported by scripts/seed.ts (killing its hand-copied literal) and by the public repo, which hydrates it in one batched query alongside tracks. When the event's default form has no such field the value is null and the surface renders nothing — never a labelled blank, per the copy rule against asserting what no endpoint stores.

## Amendment (findings wave 10): a form field's ROLE — not a global literal id — identifies session format and audience level

Verified on main: form_field.id is a GLOBAL primary key (src/db/schema/event.ts:58-85), yet SESSION_FORMAT_FIELD_ID='field_session_format' (src/forms/types.ts:93) and AUDIENCE_LEVEL_FIELD_ID='field_audience_level' (:101) are fixed literals created ONLY by scripts/seed.ts:478. createDefaultForm (src/server/repo/forms.ts:208-246) seeds locked fields only and createField mints a random id (:332), so the constant is unsatisfiable on any event created through J1 — a literal id can exist on exactly one event, forever. Consequence, all read off the tree: the public card/agenda format line and ?format= chips are permanently empty (src/server/repo/public/sessions.ts:85,479), the Home hub's format count is 0 (public/home.ts:141), the reviewer queue's format/audienceLevel are always null (review/submissions.ts:758), auto-schedule always falls back to defaultDurationMin (agenda/rows.ts:229), and POST /api/v1/events/:id/submissions {format} hard-400s 'This event's form has no session format field' (routes/api/submissions.ts:147-152) with no configurable path — while DESIGN-RULINGS A5 and A7 both require a format select. RULING: fix the IDENTITY, not each read site. Add a nullable column form_field.role with values 'session_format' | 'audience_level' (NULL for every other field); createDefaultForm mints both fields with ordinary ids and a role; role becomes the ONE matcher everywhere, expressed as an EXISTS join from submission_answer to form_field so it also works for the cross-event Home query that has no single form in scope. The literal constants are DELETED, not kept as fallbacks (house rule: no back-compat shims) — the seed carries a seed-local id and the same role. Deleting the field stays legal: DEC-592's original 'an event without that field renders no Format row' is unchanged, and the builder must never clear a role when a field is edited. No new index: the EXISTS join keys on form_field's primary key.
