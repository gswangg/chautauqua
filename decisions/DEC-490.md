# DEC-490: The embed builder offers only the knobs the selected surface honors

app/src/pages/settings/EmbedsPanel.tsx:131-178 renders Track ID, Day, Limit and Fields for every surface, and app/src/pages/settings/embedSnippet.ts:49-54 serializes whichever of them is set regardless of surface. The server honors trackId only on sessions and day only on agenda/schedule, so an organizer who builds a speakers embed with Day=2026-06-01 or a gallery embed with Fields unchecked copies a URL whose knobs do nothing. That is DEC-468's "a cap the UI cannot see LIES" in its generator form, and it is the producer-facing half of DEC-489. The knob table is DEC-489's -- this decision only fixes where the SPA reads it (EMBED_KNOBS_BY_SURFACE in embedSnippet.ts, the pure module that already owns the DEC-289 query-param contract) and what the UI does with it (buildEmbedUrl never serializes a knob the surface does not honor; EmbedsPanel renders a control only when the table lists it). No worker decides the table; both lanes consume it.

## Amendment (findings wave 12)

parseEmbedOptionsInput (src/routes/api/embeds.ts:39-121) validates each option key in isolation and never against the embed's own `surface`; POST (:174) and PATCH (:227) both call it, and PATCH can change `surface` alone (:214-219) without re-validating the already-stored optionsJson. So a `speakers` embed persists with day+roomId, an `agenda` embed persists with format+limit+fields, and switching an existing embed's surface silently keeps the previous surface's filters — which src/routes/public/saved-embed.tsx:93-106 then hands to renderSurfaceContent regardless of surface, where they are discarded. The organiser's saved recipe promises a narrowing that the published embed on a customer's site does not perform. DEC-490 already establishes that the builder must never offer a knob the surface ignores; the API is the same promise at the other door.

RULING: POST and PATCH refuse, with a 400 naming the key and the surface, any option key not listed for the target surface in DEC-489's table; a PATCH that changes `surface` validates the EFFECTIVE options (stored ∪ patched) against the new surface rather than only the patched keys.
