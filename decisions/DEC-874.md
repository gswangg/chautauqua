# DEC-874: A reviewer with one plan lands IN it; the queue row leads with its reference and ends with a full-width action

/review currently renders an unscoped "Your queue" hub (ReviewerQueue.tsx:282-296) that stacks a PlanSection per plan. The v5 pack has no frame for that hub — every Review screen in it is plan-scoped, headed "Review · <plan>" — and the mandate names the unscoped hub as a DECIDE item. Decision: zero plans keeps today's empty state; exactly ONE plan replaces the hub with the scoped queue (`<Navigate replace>` so Back does not bounce); two or more render a PLAN LIST (name, scope, count) whose rows link into a scoped queue — never N stacked queues, because a page that is several pages at once has no header that is true. The row takes the frame's anatomy: REF left, SCORED/NOT SCORED right, a meta line under the title, and the action as a full-width button; recused rows render INLINE in the same list, marked, with Undo, rather than in a trailing section that hides the reason the queue is short; the list ends with the footer "Scores stay hidden from other reviewers" beside the shell's existing sign-out. The externally-verified P0 reviewer path (login → review → scorecard) is a hard constraint: it must stay green, and each of the three landing branches gets its own test.

## Amendment (wave 65): the reviewer queue row's action is intrinsic-width and right-aligned, and a recused row's action IS its reason

DEC-874's own text specifies "the action as a full-width button" — written when the ONLY reviewer-queue frames in the pack were 390px phone captures, so the build graded a phone block button as frame-faithful. The REVIEW PACK vendored at wave 62 supplies the first DESKTOP frame for this surface (03--03) and the standing USER filing says the same thing: on desktop the primary is a normal intrinsic-width button right-aligned on the row, vertically centred against the title/meta stack. Verified still live at app/src/pages/review/review.css:1336-1340 (`.chq-review-queue-row-action { display:flex; width:100%; }`) and app/src/pages/review/ReviewerQueue.tsx:171-176 (both scored and unscored rows take `chq-btn-primary`). Ruling, superseding DEC-874's full-width clause for desktop: (a) the row is a two-column grid, body left, action right-aligned at intrinsic width; (b) an unscored row takes the olive primary face, a SCORED row the outlined secondary face — the action names what it offers and a row that already took the action must not shout; (c) on a recused row the RECUSAL REASON is the row action — an outlined, disabled-looking control carrying the reason (default copy "You work with this speaker"), with DEC-271's Undo demoted to a quiet link beneath, because a separate trailing Undo button competing with a bare reason line is two controls for one fact; (d) the state eyebrow reads RECUSED in the same bold caps as SCORED/NOT SCORED; (e) the queue gains the frame's title-row primary `Score the next one` (conditional-and-quiet: absent when nothing is unscored) and a footer "Showing N of M" + `Show all M` cap at 5 rendered rows, counted from the same arrays the list renders. DEC-939's wave-39 scoping rule stays binding: a page-scoped rule may set size/weight/spacing/width on a button-face element and NEVER color or background. The phone full-width treatment is deferred to the mobile round, not carried here.

## Amendment (wave 72): the queue row's eyebrow is ONE pair, a recused row keeps its meta line, and the queue owns its footer

Three gate-4 findings against frame 03--03, all verified on main. (a) REF and STATE are drawn ~8px apart as a single left eyebrow; `.chq-review-queue-row-top` declares `justify-content: space-between` (review.css:1387), so the app spreads them ~500px and they read as two unrelated columns. (b) A recused row drops the "Talk, 30 min · advanced" meta line the frame keeps, because `RecusalItem` (app/src/pages/review/types.ts:211) carries no `format` — while the actionable items do. The fix costs no query: src/routes/review/reviewer.ts already computes `formatBySubmission` over EVERY scoped id (line 140-143) and then throws the recused half away at line 167. A projection must carry its source's vocabulary. (c) The footer is the queue's own row: "Showing 5 of 18  Show all 18" as one LEFT group, and the reviewer reassurance right-aligned on that same row (see DEC-369's amendment — chrome no longer carries it). The footer row renders whenever the queue has rows; the count/Show-all group inside it stays conditional on >5.
