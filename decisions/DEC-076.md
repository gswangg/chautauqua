# DEC-076: Verification waves use a single code barrier: one closeout task lands/verifies the last outstanding code, every gate task chains behind it; log-only commits are not code-bearing under DEC-069

Waves 12 and 13 both produced gate sections that DEC-069's sha-scoping immediately invalidated because code merged behind the gate runs; wave 15 would be the third repeat. Structural fix: each verification wave designates exactly one closeout task that lands (or, if an in-flight lane already merged it, verifies) the final outstanding code change, and every gate task dependsOn that closeout so every gate section's sha is at or after the newest code-bearing main sha. Deliberately duplicating a still-in-flight lane inside the closeout (here task-w14-g's walkthrough conversion) is sanctioned: verify-first instructions make the duplicate a cheap no-op when the original lands first, and the merge agent resolves the overlap otherwise. Interpretive ruling on DEC-069's "code-bearing": commits touching only docs/verification-log.md and docs/verification-log/ are NOT code-bearing, so parallel gate lanes appending their own sections never invalidate each other — only product/scripts/test/config changes reset the predicate.
