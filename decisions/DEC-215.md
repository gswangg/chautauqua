# DEC-215: Org-user temp-password re-issue: POST /api/v1/users/:id/reset-password (organizer-only, own org, csrfJson) returns a fresh one-time password in the JSON response and revokes the target's sessions; never emailed

Per DEC-043/DEC-200 the temp password appears exactly once, in the 201 create response — if the organizer loses it there is NO recovery path anywhere in the product (verified: src/routes/api/users.ts has only list+create), stranding the account. Fix: a reset endpoint scoped to the caller's org (404 for unknown/cross-org ids) that generates a new DEC-043-style password via the existing generatePassword/hashPassword pair, updates password_hash, deletes ALL of the target user's auth_session rows (a reset invalidates possibly-compromised sessions), and returns {id, email, role, password} exactly once. No email is sent — same rationale as DEC-200 (email is not a secure channel for credentials; org may have zero events for the email_log anchor anyway). Resetting either reviewer or organizer accounts is allowed: DEC-043 already grants every organizer full intra-org account-creation power, so intra-org trust is established. SPA affordance: a per-row "Reset password" button on the PlanEditor reviewer roster reusing the existing revealedPassword one-time banner (app/src/pages/review/PlanEditor.tsx:189,539-546).
