# DEC-108: Public/embed visibility additionally requires participant.inviteStatus IN ('none','accepted'), enforced in visibleSubmissionConditions() and the hydrateSessions speaker sub-query

inviteParticipant inserts visible=true + inviteStatus='invited' (src/server/repo/participants.ts:78-84) and setInviteStatus never flips visible, while visibleSubmissionConditions() (src/server/repo/public.ts:25) gates only on status/contentStatus/participant.visible — so a co-speaker who never accepted, or explicitly DECLINED, renders on every public/embed surface of an accepted+approved session (J7/J10 scoping violation). Ruling: never announce an unconfirmed speaker. inviteStatus values are 'none' (direct submitter), 'invited' (pending), 'accepted', 'declined'; public queries require inviteStatus IN ('none','accepted') — written as inArray(schema.participant.inviteStatus, ["none", "accepted"]) with a 'two literals, bounded — DEC-104-exempt' comment — added to BOTH the shared gate and the standalone speaker-hydration query (public.ts:225). A session whose only qualifying participant is pending/declined drops off public surfaces via the existing innerJoin. Organizer and portal surfaces are unchanged; participant.visible semantics unchanged.
