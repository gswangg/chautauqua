# DEC-648: Saved views are a VISIBLE tab row derived from the live filter state, never a disclosure — the floating panel is deleted, not restyled

app/src/pages/submissions/ViewsDropdown.tsx is still a `<details>` summary opening an absolutely-positioned `.chq-submissions-views-panel` that collides with the toolbar beside it — the user re-flagged this as "poorly BUILT, not merely unintuitive". The mock (docs/design/Chautauqua Submissions.dc.html:66-78) draws a first-class row: a `VIEW` caption, then tabs, then `Save current as view` as the trailing action, with search+sort pushed right. The row's membership is built-in presets (Needs triage / All submissions / Accept queue) followed by the event's own saved views, and the ACTIVE tab is derived by comparing the live filter state to each view's serialized config — never from click state, the same rule the nav already follows (mandate item 11). A disclosure that has to be opened to learn which view you are in is a state the screen refuses to show.
