# DEC-448: `npm run dev` and its predev ensure-dev-vars hook are the one supported zero-setup entrypoint; verification lanes may not hand-copy .dev.vars

SPEC.md:44-45 makes it a hard rule that 'stage-1 code must run with no secrets present -- a fresh checkout plus npm ci plus one dev command is a fully working app.' The mechanism that actually delivers this is package.json:6-7: `predev` runs scripts/ensure-dev-vars.ts, which clones the tracked .dev.vars.example (DEV_MODE=1, PUBLIC_BASE_URL) into the gitignored .dev.vars the first time anyone runs the dev server. Nothing has ever verified that path end to end: task-w14-f-walkthrough-stage1.md:15 opens with `cp .dev.vars.example .dev.vars` and then boots `npx wrangler dev --port 8802` directly, bypassing predev entirely, and task-w15-e did the same. Every walkthrough for waves has therefore proven that the app works AFTER a manual step the quickstart never mentions, which is exactly the claim SPEC forbids us from needing. From here: the fresh-checkout claim gets its own evidence lane that runs the documented quickstart verbatim with no hand-created files; a lane that needs a non-default port passes `--var`/`--port` to `npm run dev` rather than substituting `cp` plus a bare wrangler invocation; and any stage-1 path that turns out to require an operator-supplied secret is a stage-1 defect, not a documentation gap.
