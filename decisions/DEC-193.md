# DEC-193: Client-side bulk-status chunking: SubmissionsTable splits selected ids into sequential batches of 500; on mid-run failure it stops loudly and refetches

DEC-182 deliberately caps server bulk-ids endpoints at 1000 per request, but the SPA accumulates selection across pages (selection.ts) and posts the whole set in one request, so select-all above 1000 hard-400s — failing SPEC principle 2's 500-5,000 design target. Keep the server cap (defense in depth) and chunk client-side: a pure helper in a new app/src/pages/submissions/bulk.ts (export const BULK_STATUS_CHUNK_SIZE = 500; export function chunkSelection(ids: string[]): string[][]) leaves 2x headroom under the cap; applyBulkStatus posts batches sequentially and sums updated counts. Failure semantics: earlier batches are already committed server-side, so no client rollback lie — stop at the failed batch, surface an error naming applied/total batches, and bump refreshToken to refetch truth.
