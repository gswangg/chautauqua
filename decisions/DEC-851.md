# DEC-851: One filter contract for a public surface: the page, its .json twin, its .xml twin and the embed builder's knob table all read the same enumerated set

VERIFIED, three separate disagreements around the same table. (1) getPublicAgenda (src/server/repo/public/agenda.ts:40) takes {day,trackId,q} and has no `format`, so /e/:slug/agenda?format= and /schedule?format= silently ignore a knob /sessions honours as a SQL predicate. (2) getSurfaceFeedPage's `case "agenda": case "schedule":` (src/routes/public/index.tsx:418-422) passes ONLY `{day}` — it DROPS trackId and q, so /embed/:slug/agenda.json?trackId=X returns the whole agenda while the HTML page at the identical query returns the filtered one; the feed and the page it claims to mirror return different row sets, which is DEC-649's rule broken on the public side. (3) The `.xml` route (index.tsx:215-222) omits `format` and `roomId` from its getSurfaceFeedPage call while the `.json` route passes both, contradicting DEC-775's own 'same envelope, same knobs' claim. (4) EMBED_KNOBS_BY_SURFACE (app/src/pages/settings/embedSnippet.ts:66-73) still lists agenda/schedule as ['day','accent'], a hand-listed manifest that desynced when DEC-783/DEC-804 taught the server trackId and q — so the builder refuses to serialize params the server honours. Decision: agenda and schedule honour exactly ['trackId','format','day','q','limit','accent'] (no roomId — the grid renders rooms as columns; no fields — there is no card-field allowlist on a time grid), that set is pinned HERE so two files cannot each decide it, format becomes a SQL-level predicate on getPublicAgenda (never a post-fetch JS filter, so items and total see one predicate), and every feed route threads the surface's whole knob set. /e/:slug/agenda.ics stays deliberately unfiltered — it is the WHOLE published agenda by DEC-289 and is out of scope.

## Amendment (wave 64): on a schedule, track HIGHLIGHTS and never filters; format and room are not agenda facets at all

A list filters; a schedule highlights (docs/design/README.md). Filtering a day schedule punches holes in the one thing the schedule is for — showing what runs concurrently — and an attendee following one track still needs to see what they are giving up at 10:00. DEC-851 added `format` to the itinerary surfaces as a filter and DEC-919's wave-40 amendment made track a pill filter there; both are superseded for /agenda and /schedule. RULING: the agenda bar is `[Search this day…][Highlight a track ▾]`; `?trackId=` on these two surfaces stops being passed to getPublicAgenda as a predicate and becomes a render-level highlight; matching blocks keep full ink, gain a 3px olive left edge and an inverted (filled) track chip, every other block recedes to a muted card via one class on the element already carrying `chq-pub-agenda-block`; the grid NEVER reflows and the Save control is NEVER dimmed, because the reason non-matching sessions stay on screen is that you might still take one. Day stays navigation (`?day=`), not a filter, and carries q/trackId forward through the existing agendaQs composer.

## Amendment (wave 5): the agenda highlight is a STATE with three consequences; the plain state pre-spends none of them

Gate-4 measured `.chq-pub-agenda-block` carrying `border-left: 3px solid rgb(78,92,49)` at rest, so the olive edge -- the signal the highlight exists to paint -- is already spent before any track is chosen; meanwhile the control stays a plain bordered box when set and the rail never swaps. A highlight is one state with exactly three visible consequences: matching blocks take the olive edge (non-matches keep a hairline), the control inverts dark with a caret, and the rail's first block becomes "N IN <TRACK>". At rest all three read neutral. This is the same rule DEC-851 already established (track is a highlight, never a filter) applied to the paint, not just the query.

## Amendment (wave 45): 'To be announced' is not a room — the public agenda gets ONE reader for rooms-in-use, and the roomless SESSIONS keep rendering

The wave-5 amendment recorded that the <h1> count and the rail's room list read the same roomsInUse() grouping so they 'can never disagree'. On main they do, three ways. AgendaContent's <h1> counts roomsInUse(activeDayItems).filter(r => r.roomKey !== 'tbd') (src/routes/public/agenda.tsx:130) — excluding the roomless bucket. RoomsRailSection renders EVERY row roomsInUse returns (src/routes/public/agenda-rail.tsx:103-120), including the 'tbd' row labelled 'To be announced' — so a day with two rooms and one unroomed session prints '2 rooms' above a 'Rooms in use today' list of three. And AgendaDay's own <h3> computes a THIRD count, `new Set(items.map(i => i.roomId ?? 'tbd')).size` (agenda.tsx:63), which includes tbd and never goes through roomsInUse at all. Ruling: export one derivation, realRoomsInUse(items) = roomsInUse(items) minus the 'tbd' bucket, and make all three call sites read it. The roomless bucket is dropped from the room VOCABULARY only: the grid's trailing To-be-announced column and the phone list are untouched, because SPEC §1 J10 makes the public programme the output and hiding an accepted, approved, scheduled session is never the fix. That is docs/design DESIGN-RULINGS ruling 25's intent ('never render it on the public agenda') honoured as far as it can be without dropping content, and the scope of that reading is recorded here deliberately so no later wave reads the ruling as licence to delete the column.

## Amendment (wave 55): a declared knob with no reader is a lie — the schedule surface drops `trackId`, and every (surface, knob) pair in EMBED_KNOB_TABLE names an exercised reader

`EMBED_KNOB_TABLE.schedule` declares `trackId` with trackMode 'highlight' (src/lib/embed-knobs.ts:52-55), but nothing honors it: `ScheduleContent` takes `highlightTrackId` and never reads it — its own comment says the highlight control was dropped (src/routes/public/agenda.tsx:358-362) and its body derives `days` from `byDay` alone (:366-367); `getSurfaceFeedPage`'s agenda/schedule branch threads only day/q (src/routes/public/index.tsx:515-516). The declaration is spent anyway: the builder offers a track knob for a schedule embed (embedSnippet.ts reads knobsForSurface), `saved-embed.tsx:86` serializes it into the .json/.xml redirect, and `deleteTrack` refuses to delete a track because a saved embed's `options_json.trackId` names it (src/server/repo/events.ts:522-547) — an unexplainable refusal defending a knob that does nothing. The table's own doc says the list is 'never a param the server ignores for it'; either the reader exists or the row is wrong. RULING: `schedule` loses `trackId`; the same table must gate the deleteTrack embed blocker (only surfaces that honor `trackId` can block); the dead `allDays`/`activeDay`/`highlightTrackId` props and the `getPublicScheduleDayCounts` read whose only consumer was `allDays` are deleted (DEC-774: a skipped read stays skipped, never fetched-then-discarded); and the pair population is asserted by a scan with written exemptions, not by memory. This is about HONORING a declared knob and is disjoint from wave 54's lanes b/f, which are about EMITTING knobs on paginating/day-switching links.

## Amendment (wave 64): a declared MOTION DURATION with no reader is a lie — spend the two enter tokens, delete the three exit tokens from both sheets

DEC-851's doctrine (a declared knob with no reader) applies verbatim to CSS. Measured on main: `app/src/styles.css:151-158` and its DEC-372 twin `src/views/theme.ts:156-161` declare six motion durations and two easings; grepping every consumer finds `--chq-motion-color` read three times (`styles.css:578`, `:745`, `:1192`, `theme.ts:344`) and `--chq-motion-appear`, `--chq-motion-geometry`, `--chq-motion-color-exit`, `--chq-motion-appear-exit`, `--chq-motion-geometry-exit` read NOWHERE. So B8's 180ms appear-in-place and 220ms geometry are documented, tokenised, reduced-motion-rebound — and never happen: modals, drawers and disclosures still pop, banners still snap in. RULED: (1) `--chq-motion-geometry` is spent on the modal and drawer entering (`.chq-modal`, `.chq-drawer`) and the expanded-disclosure band, via `animation` on mount with `var(--chq-ease-geometry)` — React unmounts instantly, so enter-only is the honest half. (2) `--chq-motion-appear` is spent on things appearing in place: the error/result banners and inline validation messages, with `var(--chq-ease-state)`. (3) The three `-exit` tokens are DELETED from `app/src/styles.css` and `src/views/theme.ts` in the same commit — a duration nobody can trigger is not a contract, and deleting from both sheets symmetrically preserves DEC-372 token parity. (4) `transition: all` and `ease-in`/`ease-in-out` stay banned; optimistic writes, arriving rows, numbers, the focus ring and print paths still animate NEVER. (5) The scan gets the tripwire: every `--chq-motion-*`/`--chq-ease-*` token declared in the SPA sheet must have at least one reader under `app/src/**`, with a negative control proving the check can fail.
