# DEC-172: Seed creates DEC-111 backing forms for form-kind onboarding tasks; manifest pins a speaker-owned pending form task

Root cause of render-sweep FAIL 2 (/portal/tasks/seed_task_assignment_0001/form → 400): scripts/seed.ts inserts DEFAULT_ONBOARDING_TASKS task rows with form_id null — including the two kind='form' tasks — bypassing the DEC-111 self-heal that the real acceptance flow applies, so the portal's correct fail-loud 400 (form task without formId) fires on seed data for every speaker clicking the task link. Rule: the seed inserts one backing form per form-kind template (title = task title, is_default false, null open/close dates so getDefaultForm can never surface it publicly) with its FORM_TASK_FIELD_SPECS fields in order, all ids deterministic via seedId, and sets task.form_id. app/src/routeManifest.ts pins TASK_ASSIGNMENT_ID to a pending form-kind assignment owned by the seeded speaker persona's contact so the sweep exercises the rendered form, not an ownership 403. The portal route's 400 behavior itself is correct and unchanged.
