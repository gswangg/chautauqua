# DEC-842: A submitted blank is an instruction to CLEAR; an absent key is silence

VERIFIED: src/forms/validate.ts:59-60 treats "" and any all-whitespace string as ABSENT (DEC-455) and `continue`s, so a blank NEVER enters `cleaned`. Downstream, src/server/repo/portal-edit.ts:264-269 documents 'empty string clears to null' and branches on `typeof jobTitle === "string"` — a branch that cannot be reached, because the key was dropped upstream. Consequence: a speaker who clears their job title, company, bio or any optional free-text answer in the portal edit form is silently handed the old value back. DEC-455 is right about REQUIREDNESS (a blank does not satisfy required) and wrong as a persistence rule. Decision: validateAnswers keeps rejecting a blank for a required field, and additionally reports `clearedFieldIds: string[]` — visible, non-required fields whose key is PRESENT in the input with a blank value. `cleaned` still omits them (no empty strings in submission_answer). Every writer treats a cleared id exactly as DEC-501 already treats a hidden id: delete the stored answer; and for the locked profile mirrors (job title / company / bio) write NULL on the contact. A key entirely absent from the payload still means 'not submitted this request' and leaves the column untouched — clearing and omitting must stay distinguishable, since the portal posts whole forms and other callers patch.
