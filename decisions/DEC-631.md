# DEC-631: A confirmation is a dialog in our own contract; window.confirm/prompt/alert are banned by an enumerating scan

Five consequential actions still stop on browser chrome the design never saw: FormsPage.tsx:78 (delete field), FormsPage.tsx:84 (re-using a server 409 message as a confirm prompt), PlanEditor.tsx:182 (delete plan), PlanEditor.tsx:407 (reset a user's password), ProgressPanel.tsx:51 (advance round). The Save-view window.prompt was already killed as a fidelity defect (DEC-610); the same class survived in five other places because nothing enumerates it. Every other modal in the SPA already hand-rolls the same contract (.chq-scrim + role=dialog + aria-modal + aria-label + useEscapeKey) and no test asserts it, so the contract is prose. Decision: ONE ConfirmDialog component owns the confirm shape, every native dialog call site moves to it, and a source scan asserts (a) no window.confirm/prompt/alert anywhere in app/src outside tests, (b) every role="dialog" carries aria-modal and an accessible name, (c) floor counts on files and dialogs scanned so a scan that matches nothing fails loudly rather than passing.
