# DEC-062: scripts/walkthrough.ts is a thin sequential runner over the five DEC-060 modules, in fixed order producer -> review -> speaker -> public -> data

task-w7-e (the DEC-053 monolithic J1->J12 script) was dropped — its branch is gone and the file is absent from main — while DEC-060 landed five standalone area modules via wave 8. Re-implementing J1->J12 inline would duplicate the modules; instead the orchestrator hard-asserts that scripts/walkthrough/{producer,review,speaker,public,data}.ts all exist (fail loudly, naming the missing file), spawns each via `npx tsx <module> --url <url>` with stdio inherited, and exits non-zero naming the first failing area. Order is producer first (it provisions state), data last (read-mostly exports/API checks). Modules must pass in this sequence against one freshly seeded server; a module that fails only because an earlier module mutated state has a sequence-tolerance bug, and fixes for that live in the module file — with the orchestrator's owner as the only sanctioned editor of scripts/walkthrough/*.ts in wave 9. DEC-053's conventions (per-persona cookie jar, chq_csrf form login, 'x-chq-csrf: 1' on JSON mutations, hard exit(1)) continue to govern module internals.
