# DEC-240: Task uploads join the content pipeline: task.deliverable_kind column, deterministic submission linkage, previous_file_id chaining on re-upload (supersedes DEC-029's submission_id-null rule)

DEC-029 parked task uploads at submission_id null / kind 'handout' / no chaining, which is why the Content worklist counts and Files library never reflect real speaker uploads (CNT-07) and re-uploads mint unlinked new files (CNT-04). New design: task gains nullable deliverable_kind ('presentation'|'poster'|'handout', meaningful only for kind='file_request', editable in TaskModal); the portal upload uses deliverableKind ?? 'handout' as the file kind; file.submission_id resolves deterministically to the uploader-contact's participant submission in the task's event (accepted with lowest seq, else lowest seq any status, else null); a re-upload sets previous_file_id to the assignment's current file_id and updates assignment.file_id, and is permitted while the assignment is complete (replacement keeps status complete). Files then flow into listEventDeliverableFiles, worklist counts, version history, and the approval loop with no dashboard-specific plumbing.
