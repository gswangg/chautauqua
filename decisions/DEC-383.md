# DEC-383: Page and surface stylesheets carry no colour literal at all; one allowlisted exception; no drop shadow anywhere

DEC-367's 'there is no red and no third accent' is only as strong as the thing that checks it, and a ten-lane re-skin is precisely where a stray `#c0392b`, a helpful grey or a soft shadow slips back in. The rule that makes it checkable is stronger than 'no red': a stylesheet that is not a token file may contain NO hex literal and no rgb()/rgba() at all — it composes `var(--chq-*)`. Scope: `app/src/pages/**/*.css` and `src/routes/**/*.css.ts`. Excluded by construction are the two token-owning files, app/src/styles.css and src/views/theme.ts, which are where colour is allowed to exist and are already pinned by the DEC-372 parity test. Exactly one exception is allowlisted, the one the handoff itself grants: `#A8A392` in app/src/pages/contacts/contacts-panels.css, used only for the merge screen's `text-decoration` strike-through (DEC-376). Additionally, no rule anywhere under app/src or src may set a non-inset box-shadow (the mocks' `0 18px 44px rgba(27,29,23,0.13)` frame shadows are canvas presentation, and the only sanctioned shadows are the two inset underlines on `.chq-nav-link.is-active` and `.chq-rail-link.is-active`), and the strings `#c0392b`, `#fdecea` and the named colours red/crimson must not appear at all.

## Amendment (wave 58): the interaction-state layer is TOKENS, and a `transition` names a property or it is banned

DEC-383 already rules that colour literals live only in the token files. V11's B8 standard (docs/design/DESIGN-RULINGS.md:108-177) adds four hover/active button families, three motion durations, two easings and an input hover border — all literals. Verified against main 50c3fcc4: `src` has ONE `transition` (in timezone.ts, unrelated) and `app/src` has four, none of them a state transition; there is no `:active` state, no secondary hover, no disabled-hover suppression, no `-webkit-tap-highlight-color`, and no `prefers-reduced-motion` block anywhere. Ruling: every new literal lands as a `--chq-*` custom property in `app/src/styles.css`'s `:root` and nowhere else. `transition: all` is banned outright (it catches the focus ring, which the ruling requires be instant); the transitionable property allowlist is exactly {background-color, border-color, color, opacity}. ONE easing family — `ease-out` for state, `cubic-bezier(0.2,0,0,1)` for geometry; `ease-in` and `ease-in-out` are banned, which closes `.chq-loading`'s existing `animation: chq-loading-fade-in 120ms ease-in` (styles.css:1066). Exits run at half duration. `prefers-reduced-motion: reduce` re-binds the duration tokens themselves (colour -> 0ms, geometry -> 90ms) rather than adding a second rule set, so states still change and nothing travels. Per the wave-57 doctrine that a population is a PROPERTY, the enforcing scan globs `app/src/**/*.css` (the stylesheets the SPA bundles) rather than naming files, asserts the population is non-empty, and carries a negative control proving the matcher catches `transition: all 200ms ease-in-out` in a fixture.

## Amendment (wave 60): the B8 interaction-state standard binds the server-rendered half too, and a global a:hover must never repaint a button's label

Wave 58 landed the V11 B8 tokens in app/src/styles.css with app/src/interaction-states.scan.test.ts, whose population is declared as `every .css under app/src` (:11-16). That is complete for the SPA and blind to the entire server-rendered product: src/views/theme.ts (the ~500-line THEME_CSS every public page, portal page, auth page and embed includes) and every src/routes/**/*.css.ts carry no transition, no :active, no hover tier and no prefers-reduced-motion block. This is the identical shape DEC-367/DEC-808 caught for the phone tap floor one wave earlier — a population defined by a path prefix plus a filename suffix instead of by a PROPERTY. Worse, theme.ts:172 `a:hover { color: var(--chq-brand-hover) }` applies to EVERY anchor including the public hub's `.chq-btn-primary` 'Submit a talk' CTA, so hovering the primary repaints its LABEL to the hover brand on the un-changed brand fill — dark-on-dark, a direct v11 tier violation (the tier darkens the FILL; the label stays on-brand). RULING: THEME_CSS declares the four B8 hover/active tiers, the three motion durations, the two easings and a prefers-reduced-motion block that re-binds the duration tokens; `a:hover` is narrowed so it cannot reach a button-classed anchor. A new scan enumerates its population by PROPERTY — every module under src/ that exports a `*_CSS` template literal — and enforces the BANS (no `transition: all`, no ease-in/ease-in-out, colour-family properties only) across all of them, while the POSITIVE token requirements are asserted against src/views/theme.ts alone, so the scan cannot fail a public stylesheet another lane is editing.

## Amendment (wave 64): the status-cell hover ring is OUTSET, and hover never paints a second fill

Gate-10 filed this as a RULING NEEDED: `docs/design/DESIGN-RULINGS.md:113` says a status cell that is a control takes a `0 0 0 2px #CFC7B7` ring on hover — no `inset` keyword — while `app/src/pages/speakers/speakers.css:292` and `app/src/pages/review/review.css:713` both paint `box-shadow: inset 0 0 0 2px var(--chq-border-strong)`. An inset ring eats 2px of the pill's own fill, which is precisely the collision the rule exists to avoid (the cell already encodes state with that fill). RULED: outset, literally as drawn; the two sites drop `inset` and keep enough cell padding that the ring is not clipped by a neighbour; and no `:hover` rule on a status cell may add a background — the ring IS the hover state.

## Amendment (wave 66): an anchor that paints itself as a button owns its own hover

theme.ts:201 (`a:not(.chq-btn):hover { color: var(--chq-brand-hover) }`) carves out exactly ONE class, and the carve-out is a hand-list. `.chq-home-action-primary` (home.css.ts:48, rendered at root.tsx:199 and :351) paints a `--chq-brand` fill with `--chq-on-brand` ink and is not `.chq-btn`, so hovering the hub's "Submit a talk" CTA repaints its LABEL to #3C471F on the unchanged #4E5C31 fill -- dark-on-dark, the exact v11 tier violation the wave-60 narrowing was supposed to end. `.chq-pub-day-pill-active` (public/css/agenda.css.ts:316-320, `--chq-ink` fill + `--chq-on-brand` ink) is the same shape one surface over. RULING: the population is DERIVED, never listed -- every class rule in an SSR `*_CSS` export that sets `color: var(--chq-on-brand)` is a filled surface, and an `<a>` in `src/routes/**` carrying such a class must EITHER also carry `chq-btn` (inheriting the tier's hover/active/motion) OR have an anchor-qualified `a.<class>:hover` in the same sheet. The qualifier is load-bearing: a bare `.<class>:hover` scores 0,2,0 and LOSES to `a:not(.chq-btn):hover` at 0,2,1.

## Amendment (wave 8, sha efb77e4a)

The hub's action family joins the B8 motion contract: 120ms property-scoped, 0ms under reduced-motion. Gate-11 confirmed the SSR button family and the SPA `.chq-btn`/input family at 120ms property-scoped with a reduced-motion 0ms override, but `src/routes/public/home.css.ts` contains the string `transition` ZERO times — `.chq-home-action-primary`, `-secondary` and `-quiet` change colour instantly while every sibling surface eases. The hub is the product's front door and the one page a judge lands on first. The transition is property-scoped (background-color/color/border-color), never `all`, and the reduced-motion override is part of the same rule set, not an afterthought — otherwise the file re-opens the exact `transition: all 0s` finding gate-10 filed against everything else.

## Amendment (wave 160): a phone-only chip control inherits the B8 tier states of the desktop control it re-lines, and a cancelled-padding face may darken its ink but never gain a surface

The three controls wave-16 landed in the Contacts 390 rule strip — `.chq-contacts-filter-add-chip`, `.chq-contacts-filter-rule-chip-edit`, `.chq-contacts-filter-rule-chip-dismiss` — are bare buttons with page-owned class names and NO hover, NO active and NO cursor declared anywhere, while the desktop control each one re-lines (`.chq-btn-tertiary`) carries the full B8 tier. Nothing caught it: app/src/interaction-states.scan.test.ts grades transition properties and easing, never the presence of a state. The re-lining doctrine already says a phone control is the same product at a different width, and that has to bind the control's behaviour as well as its geometry. RULED: a control that exists only under a phone rule takes the B8 tier states of the control it stands in for — tertiary rests at --chq-brand, hovers to --chq-brand-hover, presses to --chq-brand-active, takes cursor:pointer, and a disabled instance has no hover at all and takes cursor:default. ONE carve-out, which is the whole point of stating this: a control whose 44px floor is reached by the cancelled-padding idiom is required by DEC-937's wave-121 amendment to resolve faceless, so its hover may only darken ink (and, for a link-shaped control, underline) — never add a background or a border, which would give it the face the idiom forbids. A painted face like the dashed `+ Rule` chip darkens its border-color with the label instead, and never underlines, because its edge already bounds it.

## Amendment (wave 43): the two token files' colour literals are graded against the pack's own drawn colour set — palette CLOSURE is not palette CONFORMANCE (task w43-d)

`test/palette-conformance.test.ts` proves every page and surface stylesheet composes `var(--chq-*)` only, with colour literals confined to `app/src/styles.css` and `src/views/theme.ts` plus one allowlisted hex. That closure argument makes the two token files the COMPLETE population for colour fidelity — and nothing anywhere graded their VALUES against the pack before this wave. Built as `test/pack-colour-vocabulary.scan.test.ts` and `docs/design/audit/pack-colour-vocabulary-v12.md`. TOKEN_FILES is derived, never hand-listed: every file in the colour-legal scope (`app/src/**/*.css`, `src/views/theme.ts`, `src/routes/**/*.css.ts`) that declares a hex literal, minus any file whose whole hex population is the single DEC-376 allowlisted value — a PRINCIPLE exclusion, not a filename exclusion. Measured: the 13 `docs/design/*.dc.html` frames draw a non-empty hex vocabulary and a non-empty colour-function vocabulary; the two token files declare 23 distinct hex values (56 declarations across both files), of which 21 distinct values are drawn by the pack and 2 are not — `--chq-disabled: #7d7869` and `--chq-on-ink-muted: #b5afa2`, each declared once in both token files. The rgba()/colour-function grammar is graded in the same instrument by channel triple (alpha ignored, a translucency choice not a colour identity): the product's one function, `rgba(27, 29, 23, 0.5)`, matches the pack's own drawn `rgba(27,29,23,0.13)` family — 0 function offenders.

RULING: both hex offenders are ADJUDICATED, not repaired. `--chq-disabled: #7d7869` is DEC-436's wave-25 amendment, which darkened it FROM the pack's nearest neighbour `#8e8a7a` specifically to clear a WCAG 3:1 legibility floor that `#8e8a7a` measured only 2.43:1 against; `#8e8a7a` is now a different live token (`--chq-border-hover`), so reverting would both reintroduce the fixed contrast defect and collide two tokens onto one value. `--chq-on-ink-muted: #b5afa2` is DEC-367's original handoff value, verified at 7:1 and byte-pinned across both token files by `test/design-system.test.ts`; the pack's nearest neighbours are both lighter on-ink than the pinned floor. Neither offender has a v12 frame demanding the move, and DESKTOP IS FROZEN. Both are recorded as a stated-principle deviation in `docs/design/audit/pack-colour-vocabulary-v12.md`: a WCAG-contrast register the pack's own drawings were never graded against. `PACK_COLOUR_VOCABULARY_HEX_OFFENDERS_CEILING = 4` and `PACK_COLOUR_VOCABULARY_FUNCTION_OFFENDERS_CEILING = 0`, both two-sided, both registered in `scripts/exit-predicate/campaign-scope.ts`'s `OUT_OF_CAMPAIGN_SCOPE` — a freshly measured population must not move the campaign's goalposts mid-convergence, the same disposition `PACK_UNIT_GRAMMAR_OFFENDERS_CEILING` already carries.
