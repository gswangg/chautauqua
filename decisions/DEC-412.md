# DEC-412: Walkthrough repair policy: the design owns the copy, SPEC section 9 owns the behaviour, and each of the six areas has exactly one owning lane

DEC-407 made the orchestrator run every area and print a summary, but the last recorded run (docs/verification-log/task-w6-g-walkthrough-redesign.md) shows review/speaker/public/data as NOT RUN and scale never reached -- five of six personas have gone unmeasured for the entire redesign phase, during which every surface was re-skinned and much chrome copy was rewritten. Three lanes will therefore meet the same question at once, so the answer is fixed here rather than invented three times. When an area fails: if the shipped copy matches the design mock in docs/design/*.dc.html, the assertion is wrong -- re-pin it to the smallest token both the shipped copy and a future redesign would keep (the pattern DEC-407 set with /\bcloses\b/i), never to a full sentence of chrome. If the behaviour misses SPEC section 9's J-bar, the product is wrong and gets fixed. An assertion is never deleted, never softened to a tautology (.toBeTruthy() on a fetch that already threw), and never made conditional on the data it happens to find. Area ownership this wave is exclusive: producer+review, speaker+public, data+scale -- so no two lanes edit the same module, and each lane boots its own wrangler dev on its own port.
