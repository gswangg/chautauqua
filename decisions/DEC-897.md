# DEC-897: Required is an attribute, not an asterisk; a start and an end are one row

app/src/components/EventSwitcher.tsx:118-139 stacks Starts and Ends as two full-width FormRows; the frame's new-event modal renders them side by side as one range row (243.5px each, 16.5px gap), because a start and an end are one fact and reading them apart invites the invalid order the validator then rejects. And app/src/components/ModalFrame.tsx:57-59 paints a chq-form-row-required asterisk that appears in no frame in the pack -- decoration standing in for an affordance the control already carries. Rule: ModalFrame gains FormRowPair, laying two FormRows across one row of the modal's form grid and stacking below the modal's narrow breakpoint; the new-event modal uses it for Starts/Ends; the asterisk span is DELETED while the input keeps required/aria-required, moving the claim onto the control where assistive tech was already reading it. Modal action buttons take the input height so a footer never reads lighter than the field above it. This is a shared-vocabulary change: every modal in the app inherits it, which is the point.


## Amendment (wave 28): a server-only clash is reported AT its field and does not blame the input, and it names what survived on the page

EventSettingsPanel.tsx:170 funnels every save failure into one page-level string, so a slug already taken by a sibling event reads as 'Failed to save event settings' — the one class of error the form provably could not have caught client-side is also the one it reports least specifically. Rule 12 of the standard says a server-only error says what happened out there. Ruling: an ApiError naming the slug field (or a conflict code) becomes a FIELD error under Slug — 'That slug is already taken by another event in this org' — with .chq-field-invalid + aria-invalid on the input, the user's other edits left untouched in state, and the reassurance 'Everything else on this page is fine and is still here.' Errors that are genuinely page-level keep the existing banner; the split is by whether the server named a field.
