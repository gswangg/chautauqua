# DEC-066: Reviewers may download submission files for events where they hold a plan_reviewer assignment — read-only, no comment access

The review detail endpoint hands reviewers file ids inside sessionAnswers, but canAccessFile denies role 'reviewer' entirely (files.ts:102-114 'narrowest reading' of DEC-020), making J4 committee review unusable whenever a submission has an attached deck. Decision: a reviewer may GET /files/:fileId iff the file is attached to a submission whose eventId has at least one review_plan on which the reviewer holds a plan_reviewer row. Implemented as repo helper reviewerHasPlanForEvent(db, userId, eventId) computed in the route and passed into canAccessFile via an optional pure flag ({ reviewerAssignedToEvent }), keeping canAccessFile synchronous. Comment list/post endpoints stay organizer/speaker-only (review collaboration happens in evaluations, not file threads). Deck contents may reveal identity under anonymized plans — accepted: DEC-018 anonymization governs structured fields, not uploaded artifacts.
