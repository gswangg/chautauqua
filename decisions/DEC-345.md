# DEC-345: The review results table is ranked, sorted and paged on the server; the SPA's client-side column sort is deleted, because paginating without moving the sort would recreate DEC-341's bug

GET /api/v1/plans/:id/results (src/routes/review/plans.ts:245) returns every plan-filtered submission in one payload — at the SPEC's 2,000-submission scale that is the largest admin response in the app and the SPA renders all of it — and buildResults (src/routes/review/shared.ts:257) computes it with `submissions.map(sub => evaluations.filter(e => e.submissionId === sub.id))`, an O(submissions x evaluations) scan that is ~12M comparisons at 2,000 submissions and 6,000 evaluations. The same shape appears per-reviewer in /progress (:232) and /remind (:298). SPEC §7 names 'oversized payload' as a bug alongside N+1s, and SPEC §2.2 forbids exactly this. The load-bearing subtlety: app/src/pages/review/ResultsTable.tsx:84 sorts the loaded rows CLIENT-side by any column (resultsSort.ts), so naively adding LIMIT/OFFSET would sort one page and silently mis-rank the other 1,950 rows — precisely the correctness defect DEC-341 found on the content worklist's tabs. Pagination and server-side sorting are therefore one indivisible change. Binding contract: (a) buildResults groups evaluations into Map<submissionId, EvaluationRecord[]> once and the per-submission filter is deleted; /progress and /remind likewise build Map<reviewerId, Set<submissionId>> once; (b) sortResultsRows/sortValueForColumn and their key types move VERBATIM from app/src/pages/review/resultsSort.ts into src/domain/evaluation.ts (pure core, DEC-002) and the SPA copies are DELETED with no re-export shim (house rule: no backwards-compatibility shims); (c) the route always ranks with buildResultsRows (average desc, count desc) so an unsorted request keeps today's order, then applies the requested sort over the WHOLE ranked set, then slices — order of operations is normative; (d) query params sort (ref|title|count|average|rating|dropdown), criterionId (required when sort is rating|dropdown), dir (asc|desc, default desc), page, perPage (clampPage/clampPerPage, 50/200); envelope stays { items, total, page, perPage, round } with real values; (e) ?format=csv ignores page/perPage and emits every ranked+sorted row — an export is not a list view (DEC-105); (f) the SPA turns a header click and a pager click into server round trips and buildResultsCsvHref carries the active sort/dir.
