# DEC-795: You add someone to the event you are looking at, and a repeat roster line announces itself

VERIFIED app/src/pages/contacts/AddToEventModal.tsx:48 defaults the Event select to items[0] of /events — the CRM grader added a speaker to Forward Summit 2028 while working in DevFlow Conf 2027, which is data written to the wrong event, the worst outcome in a multi-event product; ContactsApp.tsx:73 already has useCurrentEvent(), so the correct default is one line away. VERIFIED the same modal offers no signal that the contact is already on the chosen event's roster (the grader got a duplicate roster row). Decision: the default is the event in context whenever it appears in the list (else the first). A second session for the same speaker is LEGITIMATE, so this is an advisory, never a block: when the contact already has participation on the selected event the modal states it in their own words ("Priya Raman is already on this event — 2 sessions") and the primary action reads "Add another session", so a duplicate is always a decision and never an accident. The already-on-roster fact is read from the contact's own history payload, which grows an eventId per submission (it currently carries only eventName — a name is not an identity).
