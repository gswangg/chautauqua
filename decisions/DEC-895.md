# DEC-895: A suggested placement is sized by the session's own format, and no two suggestions in one payload claim the same room-minute

src/server/repo/overview.ts:454 sends durationMin: null for every unplaced row and :370 sends format: null, so app/src/pages/overview/AgendaWorkSection.tsx:32 hardcodes DEFAULT_UNPLACED_DURATION_MIN = 30 for every PUT -- one click places a 120-minute workshop as a 30-minute slot. The authority already exists: parseFormatDurationMin (src/domain/schedule.ts:17, DEC-772) is what auto-schedule sizes by, and the submission's session format is persisted (DEC-755). Worse, buildPlacementSuggestion is called per row against the SAME `placed` array (overview.ts:455-462), so every unplaced row proposes the identical first free slot and accepting two of them manufactures exactly the clash this section exists to clear. Rule: the server derives each unplaced row's durationMin from parseFormatDurationMin (the client never re-derives it -- one function, one answer) and RESERVES each suggestion as it hands it out, so the suggestions in one payload are mutually placeable; the row's meta names format and duration, because a proposed time whose length the organizer cannot see is not a proposal.

## Amendment (wave 2): a placement suggestion is checked against the submission's FULL active-participant set, not its lead speaker

getOverviewPayload builds each unplaced row's suggestion with `speakerContactIds: leadSpeakerContactId ? [leadSpeakerContactId] : []` and reserves the accepted suggestion into suggestionOccupancy the same way, while findConflicts (and the whole agenda payload, DEC-974) reasons over every ACTIVE participant. A projection must carry its source's limits: "Place at 13:00" can therefore propose a slot that double-books a co-presenter, and the agenda then flags the clash the overview promised was free. Ruling: the suggestion path uses the same active-participant contact-id set the conflict engine uses, for both the candidate search and the reserved occupancy row.
