# DEC-041: Speaker submission editing: portal edit sub-app with server-side edit lock

J2/CFP-06 requires speakers to edit their submission until close date, with accepted speakers editing indefinitely (swyx) — no surface implements this and no wave-4 task owns it. Design: new sub-app src/routes/portal/edit.tsx (GET+POST /portal/submissions/:id/edit) behind speakerGate, repo src/server/repo/portal-edit.ts scoping every query by auth.contactId via the participant join, and pure src/domain/edit-lock.ts: canEditSubmission(status, closeDate, now) = status==='accepted' || !isFormClosed(closeDate, now), enforced on POST (fail loudly), never CSS-hidden. Edits re-validate through validateAnswers + conditional visibility; DEC-016 locked fields sync submission.title/description columns; tracks editable only while the window is open; file-kind answers read-only in v1. Separate file keeps the in-flight w4-b portal work conflict-free.
