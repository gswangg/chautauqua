# DEC-176: Wave-7 battery protocol: frozen sha = the harness-closure merge; every gate precondition-greps the fixes and runs at that sha; triage-closure verifies sibling sections plus eval-findings closure or fails cheaply

Batteries have repeatedly been voided by late code merges. Wave 7 therefore has exactly ONE code-bearing lane (harness closure); its merge commit S is the battery sha — all other wave-7 lanes append only to docs/verification-log.md (non-code-bearing per DEC-114), so every gate independently derives the same S per DEC-091/114. Each gate section must include the DEC-139 disambiguator `git merge-base --is-ancestor 2dd2f33 <sha>` (first-campaign sections reuse task-w7-* names) and precondition greps proving S carries the six w6 fixes and the harness closure: DEC-167 merge fields in src/domain/contacts.ts, ICS_ORGANIZER_EMAIL in src/mail/ics.ts, 'unknown track id' in src/routes/api/forms.ts, anonymized-plan exclusion in src/server/repo/files.ts, openDate/filters wire names in app/src/pages/review/, the DEC-172 backing-form block plus DEC-174 override in scripts/seed.ts, and DEC-175 probes in scripts/walkthrough/. A missing precondition ends the section 'RESULT: FAIL — precondition' without running the gate. Triage-closure additionally requires the five sibling sections present at S each ending RESULT: PASS, eval-findings A/B/E/F done, and every Section C item fixed or planner-waived; otherwise it ends 'RESULT: FAIL — battery incomplete', which is log-only, voids nothing, and is cheaply re-run next wave. Stage-1 exit is declared only when all six sections PASS at S with OPEN ITEMS: 0.
