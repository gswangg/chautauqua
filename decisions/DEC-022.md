# DEC-022: Public surfaces: single query gate, SSR + embeds, itinerary .ics, stage-1 cache headers

J10's five surfaces and embeds must be impossible to leak hidden content through, so visibility is enforced once: src/server/repo/public.ts is the ONLY query source for public/embed data, and every query enforces submission.status='accepted' AND submission.content_status='approved' AND participant.visible=1 in SQL (a speaker appears only via visible participant rows on qualifying submissions) — expose a single shared condition builder so the gate is single-sourced. Routes (DEC-005): /e/:slug/{sessions,speakers,agenda,schedule,gallery} as hono/jsx SSR, mobile-first, no client framework — only small inline vanilla JS for filters/show-more/itinerary. /embed/:slug/:surface renders the same five surfaces chromeless; embed responses set no frame-blocking headers so iframes work. Sessions: cards with title/speakers/track color chip, track+format filters via query params (server-rendered), show-more pagination via ?page. Speakers: alphabetical by surname with headshot/title/company. Agenda: per-day time grid. Gallery: headshot grid. Schedule: agenda plus a personal itinerary picker persisted in localStorage key chq_itinerary_<slug> (survives reload) and a Download .ics link -> GET /e/:slug/schedule.ics?ids=<comma-separated submission ids> returning one VCALENDAR via buildIcsCalendar with DEC-007 UIDs (chq-<submissionId>@chautauqua) and each submission's current ics_sequence. Stage-1 caching: public and embed GETs set Cache-Control: public, max-age=60, stale-while-revalidate=300; no purge machinery in stage 1 (bounded 60 s staleness is the accepted stage-1 behavior; stage 2 adds edge purge on publish-affecting writes). Embed generator: a panel on the admin Settings page listing the five surfaces with copyable <iframe> snippets built from location.origin — owned by the public-surfaces task.

## Amendment (wave 63): a break is a first-class agenda row, not a gap — schedule_break (event, day, label, location, start, duration) renders on the public agenda and never in a session feed

The vendored design handoff (docs/design/README.md, "Public agenda") specifies breaks as a spanning quiet rule with a small-caps label — "real programmes have them, and they explain gaps that would otherwise read as missing data" — and the agenda pack models them (`{ time: '9:45', blocked: true, note: 'Break · 15 min' }`). Nothing in the tree implements them: there is no break table, no repo, no route, no render, and the seed publishes days whose lunch hour reads as a hole in the data. Rule: a break is its own per-event row (day, label, optional location, startMin, durationMin) — it is NOT a submission, so it never acquires a ref, a speaker, an ics UID, a track, or a row in .ics/.json/.xml session feeds, and it can never be scheduled into a room. It renders as one full-width spanning row on the public agenda (both the desktop grid and the phone list) so a reader sees why 12:30-13:30 is empty. Its write routes are publish-affecting and join DEC-627's PUBLIC_AFFECTING list. The Settings editor for breaks is explicitly deferred to a later wave; this wave delivers the model, the organizer API, the seed rows and the public render, so the row has a reader on day one.

## Amendment (wave 66): the run-of-show is the one export where a break is a row, and a break may not run past midnight

`src/server/repo/breaks.ts:1-13` states the hard boundary as 'never wired into agenda conflict detection, auto-schedule, or export machinery', and `src/routes/public/feeds.ts` never reads the table. That boundary was written against PUBLIC SESSION FEEDS — .ics/.json/.xml consumers that would have to reason about a fake submission with no ref, speaker, track or UID. The show-flow export (`src/server/repo/exports/showflow.ts`, SPEC §10 nice-to-have 7) is not a session feed: it is the producer's own operational timeline, handed to AV and stage managers, and a run-of-show with no lunch in it is wrong in the way a spreadsheet is wrong. RULING: the boundary is narrowed to its actual reason — breaks stay out of every public/consumer feed and out of conflict detection, and are interleaved into the show-flow export as clearly-typed non-session rows (empty ref, label as title, location in the room column, an explicit kind marker), ordered by the same (day, start) key the session rows use, with unscheduled rows still last. Separately, `src/routes/api/breaks.ts:66-80` validates `startMin` and `durationMin` independently, so `{startMin: 1430, durationMin: 120}` is accepted and describes a break ending at 25:50 — an interval that no renderer, and now no exporter, can place. It becomes a named field error.

## Amendment (wave 69): GET / carries the standard public-page cache contract (60s + stale-while-revalidate, Vary: Cookie, no-store on the role redirects) and deliberately stays OUT of the version-salted purge cache

GET / became a real public surface in wave 65 (DEC-581/582) and is the single most-hit anonymous URL of a deployment, yet it emits no Cache-Control at all — every other public HTML GET goes through setCacheHeaders. It must NOT simply join publicCacheMiddleware, for two reasons that are worth writing down rather than rediscovering: (a) the middleware answers from the cache before the handler runs, so a signed-in organiser would be served the anonymous hub instead of their /admin redirect unless the read is gated on anonymity; and (b) every hub row carries now-derived state — cfpOpen via formWindowState, "N DAYS LEFT", and the past/published/openCfp grouping — so a copy keyed on a purge token would go stale with no mutation available to purge it (the same reasoning DEC-768 used to keep the agenda's default day deterministic). Bounded 60s staleness is DEC-022's accepted stage-1 contract and is the right instrument here; Vary: Cookie states the auth-dependence for any shared proxy, and the two redirects say no-store.

## Amendment (wave 71): a break is editable in place, through the same validator its creation uses

`src/routes/api/breaks.ts` offers GET/POST/DELETE only, so moving lunch fifteen minutes means destroying the row and retyping it. PATCH `/api/v1/breaks/:id` closes it. The create route already carries the day-shape gate, the event-range gate, the per-field `startMin`/`durationMin` bounds and the cross-field "a break cannot run past midnight" check (`breaks.ts:99-121`); PATCH must reuse ONE extracted validator rather than a second copy, because two writers of the same table drift. No pubcache change is needed or allowed: `/api/v1/breaks/:id` is already in `PUBLIC_AFFECTING` and `matchPattern` is method-agnostic.

## Amendment (wave 14): a public event surface has no publish gate, by design -- continuous publishing is the model (DEFERRED, do not re-file)

A reviewer filed this as an exposure: `getPublicEventBySlug` (src/server/repo/public/event.ts:22-27) selects on slug alone with no state predicate, and `POST /api/v1/events` (src/routes/api/events.ts:228) exists, so an organizer creating next year's event publishes its name, dates, location and branding at a guessable URL immediately. VERIFIED TRUE — the event table carries no status/visibility column and the repo's own comment at event.ts:42-45 names the gap. RULED NOT-A-DEFECT AND DEFERRED: (a) SPEC.md's J10 is titled 'Publish continuously to the website' and its gating clause — 'only accepted + visible + content-approved' — constrains RECORDS, which src/server/repo/public/gates.ts already enforces; nothing in SPEC or docs/clarifications.md asks for an event lifecycle state. (b) The v12 design authority draws no publish control on any of the 158 frames, and docs/design/DESIGN-RULINGS.md's derived ledger is fully honored — adding one would be inventing UI against the binding handoff. (c) The governing precedent is the user's own 2026-08-16 'Archive this event' ruling: event lifecycle states are built ONLY on a real customer request. A future lane must cite this ruling rather than re-file the finding; if the requirement ever arrives, the fix is a state predicate inside getPublicEventBySlug/getPublicEventById plus a settings control, not a change to the record gates.
