# DEC-201: Global public-cache bump on every mutation is ACCEPTED for stage-1; narrowing to publish-affecting writes is stage-2

bumpPublicVersionMiddleware (src/server/pubcache.ts, wired at src/server/app.ts:33 per DEC-083) purges the /e/* + /embed/* cache on any successful non-GET, so logins and reviewer ratings cold-start the public cache. This is correctness-safe (public pages can never be stale) and the local perf-smoke gate passes its budgets; the SPEC §7 "purged on publish-affecting writes" edge-cache TTFB budget is a production behavior whose validation is explicitly deferred to stage 2. A route-by-route purge predicate risks serving stale public data (a real correctness regression) for zero stage-1 benefit — it belongs with stage-2 production cache/perf validation.
