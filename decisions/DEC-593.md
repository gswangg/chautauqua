# DEC-593: The gallery is the speakers directory's photo-led twin: same person fields, one card, differing only in layout

EMB-12 requires gallery cards to carry headshot, name, job title and company and to degrade gracefully for a speaker with no photo; today GalleryContent renders a bare tile with an image or nothing at all and captions itself 'Headshots only, no session details', which is copy written against the code rather than the spec. SpeakersContent already renders the exact same fields correctly. Two renderings of one person must not disagree about which facts a person has: extract one speaker-card component, give the fallback tile the same treatment the directory uses, and let the two surfaces differ only in grid shape and in whether the session sublist is shown.

## Amendment (wave 65): a photo-led twin is not a nav destination — /gallery keeps its URL and renders Speakers as the active section

DEC-593 established the gallery as "the speakers directory's photo-led twin: same person fields, one card, differing only in layout". DEC-990's wave-53 amendment then put Gallery back in the public nav on the authority of frame 10--00's header row. Two later, higher-precedence rulings reverse that: the standing USER DECISION (a view switch that presents as leaving the section — the List/Grid toggle was jumping the nav highlight between two top-level entries) and the vendored v7 README's NAV RULING, which resolves the pack-internal discrepancy in favour of the README (frame 10--01 and "Changed since the previous handoff" §4 both drop the entry). Verified still live: src/routes/public/shell.tsx:55 (`NAV_SURFACES = SURFACES`, which includes "gallery") and src/routes/public/index.tsx:164 (speaker detail passes `active="gallery"` when reached from the grid). Ruling: public nav is Sessions / Speakers / Agenda / My schedule. `SURFACES` is UNCHANGED — /gallery keeps its route, its feeds, its embed membership and its settings surface-count row, because it is the URL the Grid segment, the deep links, the EMB photo-grid probe and the embed builder all use. Nav membership becomes its own derived list, and every shell call site maps the active surface through one helper so /gallery highlights Speakers. DEC-990's wave-53 nav clause is superseded on this one point only; its one-page-two-views ruling stands. The test asserting the Gallery nav entry (test/public-speakers-views.test.ts:102-116) is wrong by this ruling and is inverted, not deleted.
