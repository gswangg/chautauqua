# DEC-211: Every evaluation write and read on /api/v1/review/* must verify the submission belongs to the plan's event, for organizers as well as reviewers

PUT /api/v1/review/plans/:planId/evaluations/:submissionId (src/routes/review.ts:597-644) checks reviewer scope for reviewers but performs NO submission check at all for organizers: requireAssignedPlan scopes the plan to the org, then upsertEvaluation writes planId+submissionId blind. An organizer can persist evaluations against any submission id in the DB — another event's, another org's — creating phantom rows that trip planHasEvaluations (freezing criteria per DEC-123) while never appearing in results. Rule: immediately after requireAssignedPlan resolves the plan, the handler must call repo.getSubmissionSummaryInEvent(db, submissionId, plan.eventId) and throw ApiError('not_found', 'Submission not found') when null, for EVERY role, before any write; the reviewer-scope check remains layered on top for reviewers. This mirrors the existing GET /api/v1/review/submissions/:id behavior (review.ts:573-574) — existence-hiding 404, not 403, consistent with DEC-175.
