# DEC-726: A contact's Labels are its customFields, rendered in one keyed format everywhere (supersedes DEC-712)

DEC-712 decided the directory's LABELS column would render derived participation roles on the grounds that the mock's column has no backing field. docs/design/README.md §Contacts — the authoritative v4 handoff — decides otherwise and gives the reason: contact has no tags column, but customFields does exist, is settable through the import's custom.<key> targets, and is addressable in segment rules; so labels render customFields in one keyed format ('role speaker · year 2027') in the directory, the drawer, the phone rows and the merge screen, because the key is what makes a rule writable. Derived roles would render chips that SEGMENT_STANDARD_FIELDS cannot express — the same mistake an earlier draft of the design made and retracted — and would disagree with the merge screen, which already reports customFields through previewMerge (DEC-705). Where a participation role is genuinely useful it belongs in its own column, not inside Labels. No task this wave: the directory rebuild is in flight; the next contacts task adopts this.
