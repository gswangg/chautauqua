# DEC-578: The seed's wipe list is derived from the schema, with a source-scanning tripwire that fails when a table is missing

scripts/seed.ts hand-lists tablesInDeleteOrder. A table added later is simply not deleted, which is how a stale pipeline_entry row survived a reseed and collided on a UNIQUE index — the remote reseed failed silently and the whole design-fidelity pass ran against old data, costing a round of observations. Hand-listed manifests desync; enumerate them in a test (the DEC-518 rule). The delete ORDER stays explicit (FK-safe ordering is real knowledge the schema does not encode declaratively), but the delete SET is asserted equal to the set of tables exported by the former src/db/schema.ts (now split across src/db/schema/), and the test names any table present in the schema and absent from the list. A reseed that leaves rows behind is worse than one that crashes.
