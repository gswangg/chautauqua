# DEC-587: The organiser Review landing is a worklist carrying inline progress and a decision affordance on results; the standalone progress route survives only as a deep link

The organiser lands on a bare table of plan names whose real state — how much of the wave is in — sits one navigation away behind a 'Progress' link, so the page answers no question it was opened to answer. Each row therefore carries its own progress inline (evaluations in against evaluations expected, from the aggregate the progress endpoint already computes), and the ranked results table gains the Accept/Decline affordance the mock shows, since ranking a proposal you cannot then decide is a dead end. /review/plans/:id/progress and /results keep their routes as deep links and are not deleted — they are reachable state, and the DEC-514 verification lane addresses them by URL. The count on a row must be the same figure the progress page shows, computed by the same helper: two surfaces claiming the same semantics must end in the same function.
