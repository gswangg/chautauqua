# DEC-689: Three button tiers, and the tier class always wins: no element selector inside a tier rule, and an anchor styled as a button is a button

Verified: src/views/theme.ts:244 declares `.chq-btn-primary, button[type=submit] { background: var(--chq-brand); ... }`. `button[type=submit]` has specificity (0,1,1) and `.chq-btn-tertiary` at :255 has (0,1,0), so every `<button type="submit" class="chq-btn chq-btn-tertiary">` — the portal Sign out among them — renders as a filled primary no matter what the author asked for. That is mandate item 40(b), and its shape is general: folding an element selector into a tier rule means the tier vocabulary is not a vocabulary, it is a suggestion. Separately the base rule at :235 (`button, input[type=submit], .chq-btn`) never sets text-decoration and never mentions anchors, so `<a class="chq-btn">` renders underlined everywhere (item 40(c)) — nine such anchors exist across src/routes/portal and src/routes/public. The system defines exactly three tiers (item 19); a tier class must therefore beat any element default, an anchor carrying .chq-btn must be indistinguishable from a button, and both properties are locked by a stylesheet scan so the next author cannot re-merge the selectors.
