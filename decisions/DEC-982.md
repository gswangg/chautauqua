# DEC-982: A shared row-grid class is a contract on CELL COUNT: the saved-embed row owns its own grid

SavedEmbedsPanel renders eight direct children into `.chq-settings-public-pages-row` (name, path, recipe, state, Edit, Get code, Turn on/off, Delete — nine with the open Get-code <code> block), while that class is a five-column grid `170px 1fr 140px auto auto` authored in settings.css:463-470 for PublicPagesPanel's five-cell surface rows. Every cell past the fifth falls onto an implicit second row and the columns stop lining up with the rows immediately above — which is exactly the "embed row wraps at 1440" finding that has now survived three fidelity gates, because the markup and the grid that shapes it are owned by different components and neither file looks wrong on its own. The saved-embed row takes its own class whose template matches its own cells: its four controls collapse into ONE actions cell so the row reads name / path / recipe / state / actions against the same five columns, and the Get-code block spans the full width beneath the row instead of competing for a column. A test asserts the rendered direct-child count equals the CSS template's column count for both row kinds, so the next control added to either row fails loudly instead of wrapping.
