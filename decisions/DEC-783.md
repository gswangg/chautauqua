# DEC-783: The itinerary surfaces read the same query vocabulary as the sessions list, and a control names its state

The EMB shortlist's second line is "itinerary widget ignores ?q=/?trackId=" — VERIFIED: the /agenda and /schedule handlers in src/routes/public/index.tsx parse only ?day=, while /sessions has honoured q and trackId for waves. VERIFIED src/routes/public/agenda.tsx:202-207: the /schedule row control renders the literal "Add to itinerary" whether or not its box is checked, while the sessions card flips Save→Saved with CSS alone (DEC-683). Decision: ?q= and ?trackId= become server-side predicates inside the agenda repo's visible-item query — applied to BOTH the returned page and the `total` it reports, never as a post-filter over the page (DEC-774's rule for sessions, applied to the same kind of surface) — composing with ?day= and with each other; the /schedule row control adopts the DEC-683 Save/Saved state markup; and /schedule's per-day list groups rows under a time sub-header so a day reads as a timeline rather than a flat list. A surface that advertises a filter in one place and ignores it in another is two products.
