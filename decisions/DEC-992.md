# DEC-992: The merge compare table names BOTH records and their vintages, and the primary names its target with the swap beside it

v6 rebuilt Merge because the old screen put an instruction in one column head and a name in the other, so nothing on screen said which record was older or what the button was about to destroy. The column heads become "Keeping · <name> · added <date>" and "Discarding · <name> · added <date>" (DEC-802's "N other records" fallback survives for a 3+ group, and DEC-834's collision disambiguator still appends email/company when the two display names are identical), the combine rules move into a block ABOVE the actions rather than trailing them, the primary button names the record it keeps, and "Swap which is kept" sits beside it as a control rather than being buried in the pick list. "added <date>" needs a vintage the wire shape does not carry, so contact.createdAt joins the projected columns of findDuplicateGroupsForOrg and the client DuplicateGroup type — one more column on a query already running, never a second by-ids fetch (the same reasoning DEC-734 used for title/company). The date renders through app/src/lib/dates.ts, the app's ONE date grammar, never a hand-rolled Intl call.

## Amendment (wave 47): the merge page states each combine rule exactly once and names what is destroyed

DEC-992 moved the merge combine-rules into one block above the irreversible action. It ADDED "Labels combine, notes are appended" without DELETING DEC-834's "Labels always combine — they're never chosen one over the other.", so app/src/pages/contacts/MergePage.tsx:315-326 renders BOTH whenever the pair carries any custom field: one rule, two sentences, two authors, immediately above a button that cannot be undone. That is the house "A COUNT STATED TWICE IS TWO READERS DISAGREEING" failure applied to copy, and the general law is: an amendment that adds copy must delete the copy it supersedes. Separately, neither the rules block nor the ConfirmDialog body ever says the discarded contact ROW IS DELETED — they say only that history "moves onto the kept record" — so the page violates the standing invariant that an irreversible action is a page naming what goes AND what it refuses. Amendment: the rules block carries exactly one sentence per rule (labels combine / notes are appended / the discarded record is deleted), and the confirm dialog names the deletion too.
