# DEC-110: FieldRulesScript emits the rules JSON via dangerouslySetInnerHTML with '<' escaped to <

src/views/form-render.tsx:175-177 renders JSON.stringify(rules) as a plain JSX text child of <script type="application/json">; hono/jsx's escapeToBuffer entity-escapes double-quotes with no script special-case, and raw-text script elements never decode entities, so JSON.parse(textContent) throws the moment any rule exists — the toggler IIFE dies and CFP-03 conditional show/hide is dead in real browsers (the '[]' no-rules case masks it from naive checks). Ruling: emit the JSON script with dangerouslySetInnerHTML={{ __html: json }} where json = JSON.stringify(rules).replace(/</g, "\\u003c") — the < escape prevents a '</script>' sequence inside rule values from terminating the element, matching the sibling inline-JS script which already uses dangerouslySetInnerHTML. Server-side validateAnswers remains authoritative regardless of the client toggler.
