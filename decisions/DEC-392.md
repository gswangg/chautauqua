# DEC-392: The admin phone chrome is the tab bar alone: at <=700px the desktop nav strip and the identity text are hidden, and the More control is unconditional so Sign out is always reachable

Verified on main: app/src/App.tsx renders BOTH <nav class="chq-nav"> (every section, made overflow-x:auto at phone by app/src/styles.css:175) and <nav class="chq-tabbar"> (DEC-381's five tabs). Two navigations for the same destinations, and the top one is why DEC-387's admin mobile pass reads minControlPx 21 on all 20 routes (`header nav a` is a 13px link with padding:4px 0 = 21px, far under the floor) and part of why every admin route overflows 11px at 390px (.chq-header-identity is display:flex with no wrap, carrying a 220px event select + the signed-in email + Sign out on one line). The mock settles it: docs/design/Chautauqua Overview.dc.html:191-195 shows the phone header as exactly wordmark + ellipsised event name (max-width:160px) -- no nav strip, no email, no Sign out; navigation is the bottom bar and Sign out lives in the More sheet, which App.tsx:220 already renders. Rule: inside styles.css's 700px block, `.chq-nav { display: none }` and `.chq-header-identity .chq-meta`/the header Sign out button are hidden; the event switcher stays and is ellipsised; the header must not exceed the viewport at 390px. One consequence must land with it: App.tsx currently guards both the More button and the More sheet with `moreSections.length > 0`, and a reviewer has exactly one section, so hiding the header Sign out would strand reviewers with no way out. The More control and sheet therefore render unconditionally -- the sheet's job is Sign out plus whatever sections did not fit, not sections alone.
