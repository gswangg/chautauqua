# DEC-589: A completion figure names its own denominator, and conflict wording is imported from the vocabulary that owns it

Overview renders '{evaluationsSubmitted} of {plans} evaluation plans in' — a count of evaluation rows measured against a count of PLANS, which is how a real deployment displays '40 of 3'. A ratio whose numerator and denominator count different kinds of thing is not a rounding error, it is a sentence that cannot be true; the honest denominator is the number of evaluations expected, which is the same query with the submittedAt filter removed. The identical class of defect sits four lines away: the conflict row tests conflict.kind === 'room' while the payload's vocabulary is 'room_overlap' | 'speaker_overlap', so the comparison never matches and the raw enum ROOM_OVERLAP is printed at the judge. The agenda already owns the human wording for that vocabulary in ConflictChip; the fix is to IMPORT it, not to write a second copy that will drift the same way this one did. Both changes are truthfulness, not styling, and neither may be 'fixed' by softening the copy.

## Amendment (wave 49)

The overview payload's independent reads resolve in phases, one Promise.all per phase. src/server/repo/overview.ts's getOverviewPayload issues ~20 sequential `await db` queries (:57, :66, :74, :85, :99, :110, :121, :136, :157, :196, :218, :239, :292, :541 and id-dependent follow-ups). Most depend only on (eventId, now); serialising them makes the organizer's landing page — the first screen after every login — the slowest read in the product. The fix is phasing, not rewriting: phase 1 is every query whose only inputs are eventId/now; later phases are the ones needing ids produced by an earlier phase (lead speakers, latest files, slots, rooms), each phase itself one Promise.all. The payload SHAPE and every rendered number must be byte-identical; the five existing overview test files are the contract, not a suggestion.

Implemented (w49-d). getOverviewPayload now runs four waves: Phase 1 is ONE `Promise.all` over the ten queries that take only eventId/now (event, submission-status counts, plan count, evaluations agg, plan close, form close, speaker agg, DEC-776 overdue-assignment count, overdue detail rows, triage detail rows). Phase 2 is a `Promise.all` of `loadTrackNamesBySubmission` (needs triage's ids) alongside contentAgg/contentDetail (eventId-only, but not contiguous with Phase 1 in the original call order, so a separate wave). Phase 2b is `fileRows` (needs contentDetail's ids) alongside `acceptedRows` (eventId-only). Phase 3, fired once `placed`/`conflicts`/`unplacedCappedIds` are computed from the (unchanged, still-sequential) slot/participant chunkIds block, is one `Promise.all` of the lead-speaker lookup, the room-name lookup, and the DEC-895 format-answer rows — three lookups that are all sync-derived from the same upstream state and mutually independent of each other. The one query left untouched and unbundled is `comms` (:541 originally) — it depends only on eventId/now like Phase 1, but the fake-db test harnesses in test/overview*.test.ts hard-code its response as the LAST item in their queue (after every conditional slot/lead-speaker/room/format-answer query), so folding it into Phase 1 would have silently reordered the response-queue cursor and required editing every one of those "unchanged" contract tests — deliberately left as the original trailing sequential `await`, since a decision doc is not license to touch a pinned contract test to make a refactor land. Added one assertion to test/overview-payload-contract.test.ts proving all ten Phase 1 queries start (`.then()` is called) before any of them resolves, using a fake db that timestamps start/resolve events on a shared sequence counter.
