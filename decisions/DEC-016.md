# DEC-016: Submissions list API contract; locked built-in fields persist to real columns

The J3 API task and the SPA table task run in parallel and must agree; and every downstream surface (lists, agenda, .ics, public pages) needs title without joining answers. Locked built-ins (DEC-008) persist to real columns: title -> submission.title, description -> submission.description, speaker first/last/email -> contact.first_name/last_name/email; submission_answer rows store ONLY custom (non-locked) fields. List contract: GET /api/v1/events/:eventId/submissions with DEC-013 pagination plus q (case-insensitive LIKE over submission.title and participant contact names), status (comma-separated DEC-003 literals), trackId, sort in 'newest' (default) | 'oldest' | 'title' | 'ref'; items are { id, ref, title, status, contentStatus, speakers: [{ contactId, name }], trackIds, submittedAt, createdAt, answers? } where ref is the DEC-003 display ref (e.g. SES-014) and answers (custom-field map) is included only when ?includeAnswers=1. Status changes: POST /api/v1/events/:eventId/submissions/status with { ids: string[], status } -> { updated: number } — one endpoint for single and bulk, never sends email, first transition into 'accepted' runs the DEC-009 idempotent acceptance planner. Detail: GET /api/v1/submissions/:id -> full record + answers + participants + track ids.
