# DEC-942: The seed exercises the states the product can reach: a recusal, a spread of scores, and a rated pipeline

Three read paths have never been shown real data. (1) `review_recusal` appears in scripts/seed-lib.ts's delete order but no seed row is ever written, so the RECUSED queue row, the recusal-excluded weighted mean and the reviewer's own Undo path have never rendered against demo data — a state the code branches on and the demo cannot reach. (2) `insertEvaluation` (seed.ts:1337) derives both scores from `evalCounter` alone: `1+((n*7+2)%5)` and `1+((n*11+1)%5)` both cycle with period 5, so 31 evaluations produce five distinct score pairs and a handful of distinct weighted means — the RANK table, whose entire purpose is ORDER, ranks by coin flip. (3) `pipeline_entry` rows carry no `fit_score`/`rationale` although both columns and the Fit pill shipped. Rule: the seed writes at least one recusal for the demo reviewer persona on a plan they are scoped to (their queue then shows a RECUSED row AND a correspondingly smaller actionable count); evaluation scores are derived from a hash of (reviewer id, submission id) with enough spread that the weighted means separate into a genuine ranking; and a MAJORITY but not all pipeline entries carry a fit score plus a one-line rationale, because the dashed "Unrated" state must stay visible too. Seed-coherence tests assert all three, so a later seed edit cannot quietly drop them — a seed must satisfy every read, including the ones that only fire in a branch.
