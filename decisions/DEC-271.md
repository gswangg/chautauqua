# DEC-271: Reviewer conflict-of-interest / recusal (rubric ABS-12): a review_recusal row, a control in the scoring view, exclusion from the actionable queue, and honest organizer progress math

docs/verification-log/task-w2-h-rubric-coverage.md is the first run of section h in this campaign and found exactly two non-CONFORM ids out of 116. ABS-12 is the real one: docs/eval-rubric/02-abstract-management.yaml:295-302 requires a COI/recusal control in the reviewer's scoring view, with full credit if exercising it flags the submission or removes it from the reviewer's actionable queue, and a case-insensitive grep for recus|conflict|coi across src/ returns nothing. I fix the wire shape here so the server and SPA lanes cannot diverge (the DEC-239/DEC-246/DEC-265 defect class). Storage: table review_recusal {id PK, plan_id, submission_id, user_id, reason NULL, created_at}, unique on (plan_id, submission_id, user_id), with plan_id/submission_id/user_id each the FIRST column of an index (DEC-267 tripwire test/schema-fk-indexes.test.ts), hand-authored migration 0017_review_recusal.sql (DEC-263; 0016 is taken by the fk-index migration). Routes: POST and DELETE /api/v1/review/plans/:planId/recusals/:submissionId, csrfJson, reviewer-or-organizer, gated by requireAssignedPlan plus isSubmissionInReviewerScope for non-organizers with existence-hiding 404s (DEC-211). POST body {"reason": string|null}, max 500 chars; response envelope {"recusal": {"planId", "submissionId", "userId", "reason", "createdAt"}} with 201 on create and 200 when one already exists; DELETE returns 204, or 404 when none exists (no silent success). GET /api/v1/review/plans/:id/queue removes recused submissions from `items` (so they leave the actionable queue) and gains an envelope key `recused: [{"submissionId","ref","title","reason"}]` -- item keys are unchanged so test/review-queue-shape.test.ts stays valid. PUT /api/v1/review/plans/:planId/evaluations/:submissionId returns 409 conflict when the caller has recused. GET /api/v1/plans/:id/progress items gain `recused: number` and their `assigned` count EXCLUDES recused submissions, so a plan with a recusal can still reach 100% complete. Set-logic lives in pure functions in src/domain/evaluation.ts, not in the repo layer, because there is no real-D1 harness (DEC-266's lesson).
