# DEC-730: The onboarding grid's three status states are one control family: fill = done, outline = not done, ink caps = overdue

Verified on main: complete/pending render as pill controls but overdue renders `chq-flag chq-speakers-cell-late` — bare type — so the state most likely to be clicked reads as passive, and the grid never says the cells are clickable. Per design v4 §'Speakers grid — interaction rules' and mandate 32b/32c/32d: outline is the shared 'not done' axis and ink/bold-caps is the urgency modifier, so an overdue cell visibly belongs to the same family as pending; all three share the box metrics, a hover ring and cursor:pointer; the grid footer carries the mock's single line 'Click any status to mark it complete or pending'. The derived-overdue semantics (pending + past due, no third stored state) do not change — this is presentational.
