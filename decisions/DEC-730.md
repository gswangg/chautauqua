# DEC-730: The onboarding grid's three status states are one control family: fill = done, outline = not done, ink caps = overdue

Verified on main: complete/pending render as pill controls but overdue renders `chq-flag chq-speakers-cell-late` — bare type — so the state most likely to be clicked reads as passive, and the grid never says the cells are clickable. Per design v4 §'Speakers grid — interaction rules' and mandate 32b/32c/32d: outline is the shared 'not done' axis and ink/bold-caps is the urgency modifier, so an overdue cell visibly belongs to the same family as pending; all three share the box metrics, a hover ring and cursor:pointer; the grid footer carries the mock's single line 'Click any status to mark it complete or pending'. The derived-overdue semantics (pending + past due, no third stored state) do not change — this is presentational.

## Amendment (wave 39): the matrix header names BOTH axes, and the header row is closed by the section's 2px ink rule

DEC-730 gave the onboarding grid one status family. Its header lost the axis it belongs to: the first column reads `<th>Speaker</th>` (app/src/pages/speakers/OnboardingGrid.tsx:507) where the frame reads `SPEAKER · PARTICIPATION`, so a matrix whose first column now carries a participation control does not say so. The task columns invert the design's own emphasis — the task TITLE renders as 11px uppercase muted micro-label while the secondary due/required line renders beside it in the same register, when the frame gives the title sentence-case ink at ~15px and reserves the uppercase-muted register for the second line only. And the header row closes with a 1px hairline where every section rule in this design language is 2px ink; the design README states one 2px rule per section and that the rule IS the section header. Ruling: first column header names both axes; task title is sentence-case ink, second line stays uppercase-muted; the header row is closed by a 2px ink rule, guarded in speakers-css.test.ts alongside the existing participation-pill guards.

## Amendment (wave 19): the onboarding grid's task-column head takes the frame's 12px title register, and the identity column is a fixed 230px track

app/src/pages/speakers/speakers.css:184-190 sets `.chq-speakers-task-title` to 15px/700 on the strength of a wave-39 note reading "the frame gives sentence-case ink at ~15px". The vendored frame does not: docs/design/Chautauqua Speakers.dc.html:80 is `font-size:12px; font-weight:700; line-height:1.25` over a 10px/600/0.06em uppercase due line (:81, which the build already matches at :192-199). A header row whose titles run 25% larger than the pack eats vertical space in the one row whose job is labelling. The same frame fixes the grid at `230px repeat(6, 1fr)` with `gap: 12px` inside `min-width: 1060px` (:76, :86); the build honours the 1060 floor (speakers.css:172-177) but leaves the identity column to auto-size, so the speaker column's width is a function of the longest company name rather than a stated track.
