# DEC-730: The onboarding grid's three status states are one control family: fill = done, outline = not done, ink caps = overdue

Verified on main: complete/pending render as pill controls but overdue renders `chq-flag chq-speakers-cell-late` — bare type — so the state most likely to be clicked reads as passive, and the grid never says the cells are clickable. Per design v4 §'Speakers grid — interaction rules' and mandate 32b/32c/32d: outline is the shared 'not done' axis and ink/bold-caps is the urgency modifier, so an overdue cell visibly belongs to the same family as pending; all three share the box metrics, a hover ring and cursor:pointer; the grid footer carries the mock's single line 'Click any status to mark it complete or pending'. The derived-overdue semantics (pending + past due, no third stored state) do not change — this is presentational.

## Amendment (wave 39): the matrix header names BOTH axes, and the header row is closed by the section's 2px ink rule

DEC-730 gave the onboarding grid one status family. Its header lost the axis it belongs to: the first column reads `<th>Speaker</th>` (app/src/pages/speakers/OnboardingGrid.tsx:507) where the frame reads `SPEAKER · PARTICIPATION`, so a matrix whose first column now carries a participation control does not say so. The task columns invert the design's own emphasis — the task TITLE renders as 11px uppercase muted micro-label while the secondary due/required line renders beside it in the same register, when the frame gives the title sentence-case ink at ~15px and reserves the uppercase-muted register for the second line only. And the header row closes with a 1px hairline where every section rule in this design language is 2px ink; the design README states one 2px rule per section and that the rule IS the section header. Ruling: first column header names both axes; task title is sentence-case ink, second line stays uppercase-muted; the header row is closed by a 2px ink rule, guarded in speakers-css.test.ts alongside the existing participation-pill guards.

## Amendment (wave 90): the v12 status inversion is ONE vocabulary in every state including write-failure

`docs/design/Chautauqua Speakers.dc.html:549` ("Speakers · a write failed")
draws its own status cells by hand rather than through the shared
`DONE`/`PEND`/`LATE` constants the rest of the file uses: a filled-olive
`Complete` pill (`background:#4E5C31; color:#F7F9F0; border-radius:3px;
padding:3px 8px`), an ink-outlined `Overdue · not saved`
(`border:1px solid #1B1D17; border-left:3px solid #1B1D17`), and an outlined
`Pending` (`border:1px solid #BAB6A6`). Every other cut of this same grid in
the same document — the "Onboarding grid · 1600" frame (:28/:129), "One
task, every speaker" (:598), and "One task · still waiting" (:665) — draws
these three states through the inverted `DONE`/`PEND`/`LATE` constants (and
their `_M` roomy siblings) and agrees with itself byte-for-byte: Complete
bare-muted, Pending bare bold ink, Overdue the one filled chip. `:549` is the
single outlier in the file, and it is drawing the PRE-inversion vocabulary
this decision's original text described before the v12 pack superseded it.

DESIGN-RULINGS.md's B8 standard settles which cut is authoritative: "weight
goes to the exception, never to the resting state" — complete is the
majority of cells in a real grid, so filling it olive spends the page's one
unit of emphasis on the state nobody needs to act on. The inverted mapping —
"overdue is filled ink" (the only strong mark on the page), "pending is
outlined" (bold ink, no fill, per the frame's own legend text), "complete
recedes" (muted text, no fill, no border, no radius) — is what the standard
mandates and what three of the file's four cuts already draw. `:549`'s three
cells are not a second, deliberate vocabulary for a write-failure state;
they are the one cut of this grid that was never re-cut when the inversion
landed everywhere else in the document.

The literal reading is impossible to honour, not merely undesirable: a
status field's meaning-to-appearance mapping cannot be a function of an
unrelated write outcome. `Complete` means the same thing whether or not the
most recent save round-tripped, so it cannot be a filled pill in one grid
render and bare muted text in another render of the identical state. No
ruling anywhere states that a rollback banner repaints the grid's status
vocabulary, and B8 gives no interaction-state carve-out for it — a
write-failure banner is a banner, not a second status legend.

Ruling: `:549` is stale and does not bind. The v12 status inversion —
Complete muted/bare, Pending bold-ink/bare, Overdue filled-ink — is ONE
vocabulary that holds in every render of the grid, including under a
write-failure banner. The app's `.chq-speakers-status-complete` /
`-pending` / `-overdue` classes (`app/src/pages/speakers/speakers.css`) and
`TaskCell.tsx`'s `statusCellClass` already implement this correctly: a
`notSaved` cell reuses the `overdue` modifier rather than a distinct one, so
there is no second vocabulary to build. No status code changes as a result
of this amendment — it records why `:549` does not bind and forecloses the
question for future audits, guarded by
`app/src/pages/speakers/status-vocabulary-parity.test.ts`, which pins the
single vocabulary's CSS and asserts no rule under a write-failure ancestor
selector re-styles any `.chq-speakers-status-*` token.

## Amendment (wave 19): the onboarding grid's task-column head takes the frame's 12px title register, and the identity column is a fixed 230px track

app/src/pages/speakers/speakers.css:184-190 sets `.chq-speakers-task-title` to 15px/700 on the strength of a wave-39 note reading "the frame gives sentence-case ink at ~15px". The vendored frame does not: docs/design/Chautauqua Speakers.dc.html:80 is `font-size:12px; font-weight:700; line-height:1.25` over a 10px/600/0.06em uppercase due line (:81, which the build already matches at :192-199). A header row whose titles run 25% larger than the pack eats vertical space in the one row whose job is labelling. The same frame fixes the grid at `230px repeat(6, 1fr)` with `gap: 12px` inside `min-width: 1060px` (:76, :86); the build honours the 1060 floor (speakers.css:172-177) but leaves the identity column to auto-size, so the speaker column's width is a function of the longest company name rather than a stated track.
