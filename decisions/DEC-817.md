# DEC-817: A field accepts exactly the value its own placeholder shows

VERIFIED the embed builder's Accent color input (app/src/pages/settings/EmbedsPanel.tsx:289) placeholders `#4E5C31` and drops what you type straight into the embed URL's ?accent=, where parseAccent (src/routes/public/query.ts:74) requires 3- or 6-digit hex WITHOUT '#' and returns null for anything else — so copying the placeholder produces an embed with no accent and no error anywhere. DEC-793 settled this rule for the composer; this is the same rule one field over, and the general lesson is that a builder's parameter set and the live route's parsers are ONE contract that must be checked by enumeration, not by reading two files. Decision: parseAccent tolerates one optional leading '#' and still normalizes to '#rrggbb' (the value remains validated and never interpolated raw — DEC-374 untouched), and a parity test enumerates EVERY parameter the builder can emit against the parser the live route runs, so a future builder field the route ignores fails a test instead of a visitor.
