# DEC-371: SSR surfaces share one inlined THEME_CSS string in src/views/theme.ts; per-event branding recolours only .chq-brandable

The portal, public surfaces, CFP form, login, account, root and dev mailbox are Hono JSX with no bundler, and today each carries its own ad-hoc <style> block (public/shell.tsx BaseStyles, portal/shared.tsx, public/submit.tsx, auth.tsx, root.tsx, docs.tsx, dev/mailbox.tsx) — seven copies that would drift instantly under a redesign. One module, src/views/theme.ts, exports `THEME_CSS: string` (the DEC-367 tokens, @font-face pair, reset, and the SSR half of the shared component classes) and `ThemeStyles()` returning <style>{THEME_CSS}</style>; every SSR shell inlines it, so a public page stays one request and keeps the <150ms uncached SSR budget with no cache-busting problem. Two constraints: the string must survive hono/jsx text escaping (no quoted attribute selectors — the existing DEC-253 comment in shell.tsx explains why input[type=search] must stay unquoted), and per-event branding (event.brandingJson accentColor, portal_settings accent) no longer overrides the palette: it sets --chq-brandable-accent, which may only recolour the event logo lockup and the public surface's brandable accents, never the olive brand token, button tiers, or text colours. Keeping the accent scoped is what stops a customer's magenta from breaking WCAG AA across the product.
