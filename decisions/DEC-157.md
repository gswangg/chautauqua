# DEC-157: CRM sourcing pipeline: org-level pipeline_entry + pipeline_activity tables, five fixed stages, /api/v1/pipeline sub-app, fourth ContactsApp tab

CRM-07/08 need a kanban with 4-5 named columns including terminal won/lost-style stages, enroll + move persisting across reload, and a card detail with notes and timestamped stage history. Design: org-scoped `pipeline_entry` (id, org_id, contact_id, stage, created_at, updated_at; unique org_id+contact_id) with fixed stage enum 'identified' | 'contacted' | 'interested' | 'confirmed' | 'declined' (mirrors CRM-S2's expected names; renamed equivalents pass), plus `pipeline_activity` (id, entry_id, kind 'move'|'note', body, from_stage, to_stage, author_user_id, author_name, created_at). Enrollment writes a 'move' row from null to the start stage; every stage change writes a 'move' row — one table doubles as stage history and notes feed, which CRM-08 explicitly accepts as 'a general activity feed that includes the moves'. New route sub-app src/routes/api/pipeline.ts mounted only by src/index.ts (DEC-012/013), organizer-only, csrfJson on mutations, contact must belong to the auth org, duplicate enrollment fails loudly with the house error envelope, and this module never imports a mailer. UI is a fourth state-based tab in ContactsApp (like duplicates/segments) with Move-to select controls rather than drag — persistence is what is graded, and no dnd dependency is added.
