# DEC-394: For this wave only, the shared-CSS lane splits by surface: styles.css + event-switcher.css to the SPA shell lane, theme.ts to the SSR floor lane

DEC-368/372 made app/src/styles.css and src/views/theme.ts ONE lane so no two workers could redefine the same shared class in conflicting ways. Wave 6 has two shared-vocabulary changes that are disjoint by surface and must each be testable standalone: the SPA admin shell's phone chrome (DEC-392, styles.css only -- no SSR surface has a .chq-tabbar or a .chq-header-identity) and the SSR 44px floor (DEC-393, theme.ts's .chq-nav a plus the SSR page stylesheets, which the SPA never loads). Keeping them in one lane would force a single worker to carry an unrelated gate-constant change; splitting them across files with zero shared selectors carries none of the risk the original rule was written against. The split is scoped to this wave and to these files: neither task may touch the other's stylesheet, and the SPA lane must not redefine any .chq-pub-*/.chq-portal-*/.chq-auth-* class, nor the SSR lane any .chq-tabbar/.chq-header-* class.

## Amendment (wave 12) — the 44px tap floor becomes a POSITIVE invariant over a named interactive vocabulary, not a negative string scan

test/tap-target-floor.test.ts only forbids the literal `min-height: 40px` anywhere in the tree. That catches a regression to the old floor and nothing else: a control class that never declares a phone height at all passes silently, so the mandate's standing 'every interactive element is >=44px on phone' (docs/design/README.md) rests on nothing executable. A negative scan is not a floor. Ruling: the shared interactive vocabulary is enumerated once, and each member must resolve to min-height:44px inside a phone media block in app/src/styles.css or appear in a documented exemption list with a written reason — the same reviewable-escape-hatch shape NOT_PHONE_ONLY already uses. Fixes land inside existing phone media blocks only.
