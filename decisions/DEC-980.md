# DEC-980: A stage move and a fit edit are different writes: stage is optional on PATCH /pipeline/:id, a same-stage PATCH is never a move, and the card can edit fit after enrolment

DEC-821's fit score and "why them" can be written only at enrol time: PipelineBoard.tsx offers no edit, so "Unrated" is a permanent state and a mistyped score is uncorrectable. The API nominally supports it, but PATCH /pipeline/:id validates body.stage unconditionally (src/routes/api/pipeline.ts:188) and then always calls moveEntry, which unconditionally inserts a kind='move' activity row with fromStage === toStage and bumps updatedAt (src/server/repo/pipeline.ts:301-327) — and updatedAt IS stageSince (DEC-803), the value pipelineCardAge reads. So the only reachable way to fix a score would forge a stage-change in the entry's history and reset the card's staleness clock. Rule: `stage` becomes optional; the route calls moveEntry only when a stage is supplied AND differs from the stored one (a same-stage PATCH is a no-op for history, not a move); fit/rationale ride updateEntryFit, which never touches stage, updatedAt, or the activity feed. The board's card gains an explicit fit edit that sends fit only. Reason a value is editable exactly where it is displayed.
