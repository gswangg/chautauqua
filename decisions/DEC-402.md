# DEC-402: Every `<table className="chq-table">` in the admin SPA carries a page-prefixed class, and the import preview table gets the phone card it never had

app/src/pages/contacts/ImportWizard.tsx:197 renders a four-column Email/First/Last/Company table with no page-prefixed class, so no page stylesheet can address it: contacts-panels.css's 700px block converts `.chq-contacts-import-mapping` to cards and leaves this one as a real table full of unbreakable email addresses at 390px. It is invisible to every gate because it only exists after a CSV upload, which the sweep cannot reach. The two settings tables (ExportsPanel.tsx:27, ApiTokensPanel.tsx:103) are covered today only by settings.css's descendant rule `.chq-settings-panel .chq-table` — that works, but it means a table's phone behaviour depends on an ancestor nobody names. Rule: the second class is mandatory and checkable by a source guard; the descendant rules that already work stay as they are. This is the cheap, mechanical half of phone conformance — the measured half is DEC-401.
