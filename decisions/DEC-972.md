# DEC-972: A record prefix is per-event data, never a string literal — the public CFP confirmation quotes the event's own prefix, and a scan bans the literal form

src/routes/public/submit.tsx:439 calls formatRef("SES", submission.seq) while `event` is loaded and in scope two lines above (createContact reads event.orgId) and getEventBySlug already projects recordPrefix (src/server/repo/submit.ts:93). Every other ref site in the tree passes the row's prefix — 40 call sites, one exception. So on any event whose prefix is not the default (scripts/perf-seed.ts:165 seeds "PERF"), the public confirmation page and the confirmation email quote a ref that matches nothing in admin, portal, agenda, exports or Airtable, breaking SPEC §5's 'Stable IDs everywhere; per-event record prefixes' on the one screen a first-time submitter reads. It survived a spec audit (docs/verification-log/task-w15-f-spec-audit-stage1.md:49 marked DEC-435 VERIFIED via `grep -rln "SES-"`) because a grep for the OUTPUT structurally cannot match a literal in the CALL. Rule: the confirmation ref is formatRef(event.recordPrefix, submission.seq); and a scan test enumerates every *.ts/*.tsx under src/ and fails on any formatRef( call whose first argument is a string literal, naming file and line — the lock is on the call shape, not on the rendered string.
