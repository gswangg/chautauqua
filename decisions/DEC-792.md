# DEC-792: Compose speaks the whole merge vocabulary; a seeded template is a promise the send path must keep

VERIFIED src/domain/compose.ts:105 buildMergeVars supplies only speaker_name/talk_title/event_name/portal_link(+feedback), src/mail/render.ts:26 COMPOSE_MERGE_FIELDS excludes due_date/task_list, and scripts/seed.ts:1934 seeds a "Content Reminder" template whose subject/body use {task_list}/{due_date} — so picking the demo template fails preflightRender for EVERY recipient (repro'd by the probe). The vocabulary, not the template, is the defect: the compose path CAN derive both facts per recipient, because src/server/repo/tasks/reminders.ts already has listOutstandingForEvent(db,eventId,taskIds?,contactIds?) and buildReminderMessage's DEC-564 sorted, formatCalendarDate-rendered task lines. Decision: compose ALWAYS supplies task_list and due_date, built by the SAME exported line renderer the reminder email uses (imported, never re-typed — hand-copied vocabularies drift), with stated text for the empty case ("No outstanding tasks." / "No due date") rather than a blank, so a template referencing them preflights clean for every recipient; COMPOSE_MERGE_FIELDS grows to match, which is what every chip row and validator reads. A seeded template whose tokens the compose path cannot supply is a landmine, so the seeded template set becomes an importable constant and a parity test asserts every seeded template's tokens are a subset of COMPOSE_MERGE_FIELDS.

## Amendment (wave 45): the task-deadline merge token is {task_due_date}, with {due_date} a permanent resolving alias

src/mail/render.ts declares only `due_date`; frame 07 names the token `{task_due_date}`. A token is a name organisers type into stored templates, so renaming without an alias would silently break every seeded and user-authored body that already contains {due_date}. Decision: {task_due_date} is the canonical name — it is what the Insert-a-field menu offers and what documentation/preview sample values key on — and {due_date} resolves to the same value forever, never surfaced as a choice. The Insert-a-field helper line states its count from the same list it renders (never a hardcoded number), so the menu and its own sentence cannot disagree.
