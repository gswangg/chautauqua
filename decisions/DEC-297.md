# DEC-297: Public surfaces never emit a cacheable non-200: every 404/error response from src/routes/public/* carries Cache-Control: no-store

src/routes/public/index.tsx calls setCacheHeaders(c) at the top of every handler, before the not-found branches, so a 'Session not found.' 404 ships public, max-age=60, stale-while-revalidate=300. The edge layer is safe (servePublicGet stores only status 200), but the client is not: a producer approves a session, the speaker refreshes, and their browser serves its cached 404 for up to a minute — the exact opposite of J10's 'always current' promise, and it also applies to a slug typo'd once and fixed. Rule: a public handler that returns a non-200 overwrites Cache-Control with no-store; the 200 path keeps DEC-022's header byte-identical (DEC-099 requires it to match pubcache.ts's CLIENT_CACHE_CONTROL exactly). The rule is stated as a property of the file, not of specific handlers, so the JSON and iCal feed routes DEC-289 adds to the same file inherit it.
