# DEC-513: README evaluator credentials are contract-tested against the vendored fixture, in both directions

SPEC section 8 makes the seed the grader package and requires a README 'For evaluators' section listing URLs and credentials verbatim; a judge who copy-pastes a password that fails at the login form has already formed their opinion. README.md hard-codes those credentials twice (the summary table near line 18 and the persona table near line 167) while scripts/seed.ts derives them from the vendored fixture docs/fixtures/sample-data.json (`identities`, lines 27-58). Nothing connects the two. test/quickstart-contract.test.ts guards that README's Quickstart names real npm scripts but says nothing about credentials, and the campaign has re-seeded and re-pulled fixtures many times. This is the same shape as DEC-503's hand-listed manifest desync: two hand-maintained copies of one fact with no derivation between them. Decision: a contract test parses both README tables and the fixture identities and asserts equality in BOTH directions — no undocumented seeded login and no README-only ghost account — plus that the event slug in README's URL examples equals the fixture's. docs/ is vendored source per docs/README.md precedence, so the fixture is authoritative and README is the side that gets corrected.
