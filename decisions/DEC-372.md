# DEC-372: Wave-2 design-system lane owns BOTH shared stylesheets: the active pill is ink, SPA/SSR token names reach parity, nine shared classes are added

DEC-368 gives one lane sole ownership of app/src/styles.css and says a wrong shared class is fixed by that lane the following wave. Wave 2 has that lane, and it also owns src/views/theme.ts (DEC-371) so the two token vocabularies cannot drift again. Three corrections plus one addition set. (1) `.chq-pill.is-active` / `.chq-pill.active` must be INK-filled (#1B1D17 background, #F4F1E8 text, border matching the fill), not olive: every mock's selected filter/tab/pipeline chip is ink (Contacts.dc.html lines 67-70, phone chip strips at 171-173, pipeline stage chips at 393-396), and the olive fill is reserved for `.chq-btn-primary` so exactly one filled-olive control appears per row. (2) Token parity: THEME_CSS as landed declares `--chq-ink-secondary` where DEC-367 names `--chq-ink-2`, and omits `--chq-on-ink`, `--chq-on-ink-muted`, `--chq-on-ink-hairline` and the four radius tokens; app/src/styles.css omits `--chq-brandable-accent`. After this wave both files declare the identical name set with identical DEC-367 values, and a test asserts set equality so no later lane can drift them. Canonical name is `--chq-ink-2`. (3) Nine shared classes are added because two or more wave-2 screens each need them, with values read from the mocks rather than invented: `.chq-steps`/`.chq-step` (+`.is-done`,`.is-current`) for the Comms compose strip and the Contacts import wizard; `.chq-bar`/`.chq-bar-fill` for Review progress and portal task completion; `.chq-dot` (+`.is-on`) for the phone tab bar, pipeline and agenda states; `.chq-bulkbar`; `.chq-rail`/`.chq-rail-link` for the Settings section rail; `.chq-panel` for inverted-ink decision blocks; `.chq-kv` for drawer and detail label/value rows; `.chq-pager`; `.chq-scrim`. THEME_CSS gets only the SSR-needed subset (.chq-bar/.chq-bar-fill, .chq-dot, .chq-kv, .chq-pager). Page lanes may use these names before the lane lands (DEC-368 already permits it) and may now create more than one co-located stylesheet per area, each imported by the module that uses it, still prefixed `.chq-<area>-*` and still never redefining a shared class.
