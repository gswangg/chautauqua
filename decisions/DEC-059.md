# DEC-059: Headshot thumbnailing = client-side canvas downscale at upload; /headshots served immutable

SPEC §7 mechanics require "headshots thumbnailed at upload with long-lived cache headers", but workerd has no image codec and Cloudflare Images is stage-2 platform wiring. Decide the stage-1 implementation: a small framework-free inline <script> on the portal profile page intercepts the headshot file input and, when either image edge exceeds 512 px, downscales via canvas to max-edge 512 JPEG (quality 0.85) and swaps it into the form via DataTransfer before submit. Server-side validation (8 MB cap, extension allowlist) is unchanged as the authoritative backstop — this is a perf optimization, not a security gate, so client-side is acceptable. Because every upload gets a fresh random R2 key (headshot/<contactId>/<newId()>-name), the serving route GET /headshots/:fileId switches to Cache-Control: public, max-age=31536000, immutable.

## Amendment (wave 70): an immutable cache header may describe BYTES, never an AUTHORIZATION OUTCOME

DEC-059 reasoned correctly that a headshot's bytes never change (fresh random R2 key per upload) and concluded public, max-age=31536000, immutable. But src/routes/portal/profile.tsx:434-449 chooses that header from scope.publiclyVisible — a value getHeadshotServeScope derives from visibleSubmissionConditions(), which flips when a participant is hidden, an invite is declined, or content approval is revoked. The route is mounted at src/index.ts:79, outside publicCacheMiddleware's version-salted key space (that middleware covers only /e/* and /embed/*), so no purge can reach an already-issued response: a de-published speaker's headshot keeps returning 200 for a year. The immutability claim was about the wrong noun. Ruling: the publicly-visible branch serves the SAME bounded contract the page embedding it serves — CLIENT_CACHE_CONTROL from src/server/pubcache.ts:59, imported rather than retyped, so headshot and page expire on one clock — and both branches carry Vary: Cookie, because the same URL answers 404 to a stranger and 200 to the owning speaker while a headshot is private. The private branch stays private, max-age=0 and the 404s keep DEC-658's app-wide no-store.
