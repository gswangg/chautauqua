# DEC-472: A branch is not a landing: every graded row cites `git merge-base --is-ancestor`, and a decision doc is evidence of a decision, never of a fix

DEC-470 scheduled wave 21 to close on the premise that wave 20's five lanes would land. They did not. At wave-21 planning the reflog tip is `merge task-w20-c` and only that one lane is on main: `src/lib/pagination.ts` exports no `listPerPage`, `src/routes/api/views.ts:26` / `tokens.ts:25` / `comms.ts:31` still carry `perPageWithDefault200`, `src/routes/api/pipeline.ts:67` / `users.ts:54` / `contacts/segments.ts:98` still read `clampPerPage(q ?? 200)`, `src/routes/review/reviewer.ts:136` / `plans.ts:310` / `api/contacts/crud.ts:114` still emit `perPage: items.length || 1`, and `app/src/pages/contacts/PipelineBoard.tsx:63` still renders `{entries.length} people`. Yet `decisions/DEC-465..469` and `src/decisions.ts:471-476` are all on main, and field-guide/index.md lines 44-60 narrate those five fixes in the past tense. That asymmetry is structural — decision docs are committed by the scribe at plan time, source lands only if a worker's branch merges — so any grader who reads decisions/, src/decisions.ts, or the field guide will read a fix that does not exist. Rule: no ledger, evidence log, or audit row may be graded from a decision doc, a `void DEC_NNN;` marker, a field-guide line, or a prior wave's summary. Every row cites either (a) file:line read at the graded sha, or (b) `git merge-base --is-ancestor <branch-or-commit> <graded-sha>` returning true. A defect whose owning branch exists but is not an ancestor of the graded sha is PENDING-OWNED with that branch named (DEC-438) and forces NOT PASS — it is never pre-credited. This is DEC-448 ("a PASS ledger is evidence about ITS OWN sha only") pushed one level down: a PASS ROW is evidence about its own sha only.

## Amendment (wave 47): parity is not use — a DEC constant no source file references is a decision with no code, ratcheted

DEC-472 fixed the epistemics ("a decision doc is evidence of a decision, never of a fix") and test/decisions-parity.test.ts enforces half of it: decisions/DEC-NNN.md and the exported DEC_NNN constant stay 1:1 in both directions. Nothing enforces the other half. The compile-check idiom the codebase actually relies on is a `void DEC_NNN;` (or equivalent) reference from the implementing module; a constant that appears ONLY in src/decisions-data/*.ts and the src/decisions.ts barrel is a recorded decision whose implementation never landed — precisely the failure mode this swarm has been warned about for six waves and has never been able to measure. Amendment: an orphan is a DEC_NNN referenced nowhere under src/ or app/src/ outside src/decisions.ts and src/decisions-data/. The guard enumerates orphans, pins the CURRENT set in an explicit allowlist where each entry carries a one-line reason, and asserts the orphan set is a SUBSET of the allowlist — so the count can only fall. New orphans fail the build; retiring an orphan is deleting its allowlist line. The allowlist is the deliverable: it is the first honest inventory of decisions this product recorded but may never have built.
