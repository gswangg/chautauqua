# DEC-239: API wire shapes are server-canonical and contract-tested: /users items {id,email,role}, review queue items {submissionId,ref,title,ratingsCount,alreadyRatedByMe}, duplicates items {contactIds,contacts[]}

All three production P1s were client/server payload-shape mismatches that the render-sweep gate structurally cannot catch (routes render fine; interactions die). Resolution per surface: /api/v1/users keeps its tested {id,email,role,contactId} shape and the SPA maps id (ReviewerOption gains id, PlanEditor uses r.id); the reviewer queue endpoint changes to emit the client contract {submissionId, ref, title, ratingsCount, alreadyRatedByMe} preserving fewest-ratings-first order (the raw SubmissionSummary spread was accidental); /contacts/duplicates keeps its tested {contactIds, contacts} shape and DuplicatesView aligns. Every fix ships a route-level contract test asserting the exact key names the SPA consumes, and future SPA payload types must cite the route file they mirror.
