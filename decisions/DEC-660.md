# DEC-660: One merge-field vocabulary: the per-surface resolvable sets and the 100-recipient cap are declared once in pure core and reach the SPA through a single boundary module

Three hand-maintained copies exist: MERGE_FIELDS (src/mail/render.ts:5, seven fields), COMPOSE_MERGE_FIELDS (app/src/pages/comms/types.ts:6, five), BULK_EMAIL_MERGE_FIELDS (app/src/pages/contacts/types.ts:90, three) -- plus BULK_EMAIL_RECIPIENT_CAP=100 mirroring MAX_COMPOSE_RECIPIENTS=100. Each set encodes a real server fact: which vars that send path actually supplies, so a chip offering anything else is a control whose only outcome is a preflight rejection (the DEC-608 rule). Hand-copied vocabularies drift, and these are the vocabulary that decides whether an email to a real speaker renders. DEC-002 made pure core node/cf-free precisely so a browser bundle could share it; exactly ONE app-side module crosses the boundary so the blast radius on the bundle budget stays measurable.
