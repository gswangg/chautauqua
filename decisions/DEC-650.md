# DEC-650: The CFP builder's primary content is the QUESTION LIST, and a condition renders the referenced field's LABEL — an id in the UI is an internal handle leaking

FormsPage.tsx leads with a Settings section and buries an 8-column spreadsheet `<table>` below it; the mock (Submissions.dc.html:358-413) leads with breadcrumb + `CFP form` + Preview/Save, an Opens/Closes/Received strip, then the field list as flat rows, with settings and the public link trailing. FieldList.tsx:81 also prints `if <fieldId> eq "Workshop"` — a raw ULID the organizer never chose and cannot read. A condition is a sentence about two labels; an unresolvable fieldId says so in words rather than printing the handle.

## Amendment (wave 58): a conditional rule reads as a sentence, a hidden question is never required, and the blast radius is a count already held

DEC-650 forbids a raw fieldId leaking into the UI and `condition.ts:describeCondition` already discharges that for the FieldList row. V11 frame 02--10 (DESIGN-RULINGS:306-314) goes further and none of it is in the tree: verified `FieldModal.tsx` has a bare `required` checkbox (:196), no off-state copy, no kind-following value control and no header. Ruling: (a) the rule builder reads as a sentence — 'Only show this question when...' with the off state STATED ('Leave it off and the question always shows'), never implied by empty selects; (b) the value control follows the trigger field's kind (options dropdown / number / text) so an organiser cannot author a rule that can never match; (c) required and a visibility rule are MUTUALLY EXCLUSIVE and enforced on save, not merely captioned — a submitter who cannot see a question cannot be blocked by it; (d) the blast-radius header reads the count `FormsPage.tsx` ALREADY holds (`received.total`, :110) passed down as a prop — no new endpoint, no fabricated number, and `null` while loading renders NO line rather than a zero. `describeCondition` is untouched: the row summary is a separate landed contract.
