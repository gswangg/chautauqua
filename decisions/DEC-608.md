# DEC-608: A route that belongs to another role is neither a 404 nor a blank page: every role subtree ends in a catch-all that names the boundary

An organiser opening a reviewer scorecard URL matches no route in the organiser subtree, so React Router renders null and the shell paints an empty <main> — a soft-404 with no error, no redirect and no explanation, verified twice. The same hole exists in reverse for a reviewer. Roles partition the route table, so each partition must terminate: a catch-all that states whose route it is and offers the caller's own way back. The event switcher's unconditional 'New event…' is the same defect one layer up — an affordance for a role the caller does not have, whose POST can only 403.
