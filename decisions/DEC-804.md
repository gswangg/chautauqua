# DEC-804: A public surface renders a control for every filter it applies, and offers none it ignores

VERIFIED DEC-783 landed the ?q= and ?trackId= predicates on /agenda and /schedule, but src/routes/public/agenda.tsx renders no form of any kind — the only search inputs in the public family are sessions.tsx:165 and speakers.tsx:17. A filter that works only if you hand-edit the URL is a capability the reader cannot reach, which is exactly how the EMB probe scored it ('params work but NO search box renders'). The converse failure is just as bad: offering a control the server ignores. Decision: the two itinerary surfaces render the SAME role="search" GET form the sessions list uses — one text input named q plus a track select — carrying the active ?day= forward as a hidden field so filtering does not silently jump the reader off their day, and pointed at the surface's own base so an embed's form never breaks out of its iframe. Session format is deliberately NOT offered here: the agenda query has no format predicate, and a control whose value the server drops is worse than no control. If format filtering is wanted on these surfaces later it arrives as a server predicate first, control second.
