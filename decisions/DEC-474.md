# DEC-474: Wave 21 = one source lane + four independent evidence lanes + the ledger last; the ledger's PASS requires DEC-465..469 and DEC-471 to be ancestors of its own sha

DEC-447's trap is why wave 21 still cannot be planned as five fix lanes even though five fixes are outstanding: a ledger cut behind N concurrent source lanes reports N-1 of them PENDING-OWNED. So wave 21 keeps exactly one source-changing lane (DEC-471's two file lists, in src/routes/files.ts + one SPA file + one new test — a file set that no wave-20 branch touches, so the merge train can land w20-a/b/d/e beside it without contention), and spends the remaining lanes on the evidence the ledger has to cite and does not yet have anywhere in the tree: a build/test/bundle/render-sweep run, a J1-J12 persona walkthrough including the dev-mailbox/.ics surface, a perf smoke at the DEC-469 seed, and DEC-473's enumeration. None of those four may touch src/ or app/src — an evidence lane that edits product code invalidates the sha it is measuring. The ledger runs last and grades under DEC-472: for each of DEC-465, 466, 467, 468, 469 and 471 it runs the ancestry check against its own sha and reads the named file:line, and it is PASS only if all six read as landed, with wave-20 branches named for any that have not. If it returns NOT PASS, wave 22 is short and mechanical — re-land whichever wave-20 lane is still missing — because DEC-472 means the wave-22 planner will be reading ancestry, not the field guide's past-tense summary of it.
