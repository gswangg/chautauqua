# DEC-737: A results row states ONE blended score; per-criterion detail lives behind its Reviews disclosure, and arrow, CSV link and row order are the same fact

docs/design/README.md and the v4 Review pack put one SCORE column on the ranked results row, with per-criterion values behind the row's ▸ Reviews disclosure; today the table renders Average plus a column per rating criterion plus a column per dropdown criterion, which turns the one screen an organiser decides from into a spreadsheet and pushes the decision controls off the measure. The disclosure is where detail belongs because it is already the per-review view. Second: the ABS grader reports the sort direction inverted on every click. The domain sort and the route are correct, so the lie is client-side — nothing drops a stale in-flight response (two effects both key on `sort`, neither cancels), and a failed refetch leaves the previous rows under a new arrow. The invariant to hold, and to test, is that the `dir` sent, the arrow rendered and the rows displayed always come from the same request; a superseded response is discarded, and a failed one clears the rows rather than leaving them contradicting the header. First click on a numeric column sorts descending (best first) because that is what a ranked column is for; text columns keep ascending.

## Amendment (wave 2): an embedded ranked table is a PREVIEW, and a review row states one score everywhere

The review landing embeds the full paged results table — its own "Ranked results" heading, its own Download CSV beside the landing's title-row export link (DEC-763), and a Prev/Next pager — where frame 03--00 shows a four-row preview; and the standalone page prints both an h1 "Results: <plan>" and a "Ranked results" section label. Ruling: when ResultsTable is embedded it renders the first 4 rows, no pager, no export link (the landing title row is the ONE export owner), and a "See all N results ›" link to /review/plans/:id/results; its section label is the plan-scoped heading ("<plan> · ranked results", matching ProgressPanel's convention) and the standalone drops the duplicate label under its h1. The same one-score rule applies on submission detail: a review row is reviewer + blended score + date + comment, with per-criterion scores behind a disclosure, exactly as DEC-737 already requires of the results table.
