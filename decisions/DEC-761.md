# DEC-761: A submission detail knows its position in the list you came from, and re-derives it from the URL rather than router state

The mock's submission detail carries "‹ › N of 47" and an AWAITING TRIAGE banner; main renders neither. The tempting implementation — hand the ordered ids down through react-router state — produces a control that exists when you clicked through and vanishes on reload or on a shared link, and conditional visibility is a fixed point (field guide): the same URL must render the same controls. So the detail page re-runs the SAME list query from its own search params (the params the table already puts in its URL: status/track/q/sort/page/perPage) and derives total, position and the neighbour ids from that one response; a bare /submissions/:id falls back to the unfiltered default list, which is still a truthful position. Prev and Next are absent at the ends rather than disabled (DEC-733). The AWAITING TRIAGE banner renders exactly while the submission is pending — it is a restatement of the status, not a second source of it.
