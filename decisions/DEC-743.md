# DEC-743: The submission detail decides the SUBMISSION; content is decided on the content screen, and each section carries its own header

The Submissions pack shows the detail page as a main column of headed sections plus a Decision aside; the aside holds Accept / Decline / Waitlist under the micro-label "Awaiting triage · N days", and NOTHING about deliverables. Today the same aside also flips content_status, which puts two unrelated decisions behind one panel and duplicates the worklist's own Approve — the hub-gives-a-row-ONE-action rule applied to a page. Content approval therefore leaves this page entirely, replaced by a link to /content for that submission (the screen that owns versions, the thread and, per DEC-720/741, the send). The history section is a real section: an "History" label above the 2px rule with the show/hide as a link ON that rule (DEC-707's grammar), entries under it — not a toggle button standing in for the header. A review row reads reviewer NAME + the plan's weighted score + when, with the comment at full length below (copy rule 6), and criteria are named by their labels (DEC-723), never by raw ids.

## Amendment (wave 4): ONE format-label formatter, and a creation dialog stays quiet about optionality

'Talk (30 min)' is transformed to 'Talk, 30 min' inside ReviewerQueue.tsx:23 and nowhere else, so the submissions list still prints the raw parenthetical -- the same string, two grammars, two readers. Ruling: one exported formatter (`formatFormatLabel(raw, { abbreviate })`) owns the transform; the list abbreviates ('Talk, 30m'), the queue does not ('Talk, 30 min'), and no third site re-implements it. Same amendment on the New submission dialog: the controls stay (DEC-755 binds Track and Format to the store) but the '- OPTIONAL' suffixes and the native fieldset legend go -- optionality is carried by validation, not by shouting it on every label.

The one formatter lives at `app/src/lib/formatLabel.ts`. The server's Format field returns a verbatim raw label like "Talk (30 min)"; every screen that displays it reshapes that string through `formatFormatLabel`, never a private per-screen copy. The Submissions list's FORMAT column renders through it abbreviated (dense column width); a label with no matching "(N min)" parenthetical passes through unchanged.

The submissions ColumnPicker's `<summary>` matches the sibling status/filter pills (26px, `--chq-r-pill`) instead of the old 44px `--chq-r-ctl` box; the phone media query still grows it to a 44px tap target, unchanged.

The New Submission modal's Tracks control drops the native `<fieldset>`/`<legend>` wrapper for the same plain `FormRow` label every other field in that modal uses (label with no `htmlFor`, since the control is a checkbox group, not a single labelable element) -- Track and Format stay bound to the store per DEC-755.

Scope note: at implementation time (wave 4), neither the `- OPTIONAL` label suffixes nor a private per-screen format-transform copy in `app/src/pages/review/ReviewerQueue.tsx` were present in the codebase -- both had already been resolved by earlier waves, or the mandate's snapshot predated them. `formatFormatLabel` exists now as the one formatter for any future caller; ReviewerQueue was left untouched since there was nothing there to delegate.
