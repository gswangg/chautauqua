# DEC-915: A settings edit row is a DRAFT with an explicit Save, everything listed is editable, and a section you can enter is a section you can leave

app/src/pages/settings/TracksRoomsPanel.tsx:210 wires a track-name input's onChange straight to renameTrack -> apiPatch -> reload(): every keystroke is a network WRITE, and the reload rebinds the controlled value from server state mid-typing, so characters race and drop. Two rows below, rooms get no edit path at all -- the panel offers only Add and Delete while PATCH /rooms/:roomId already accepts {name, capacity} (src/routes/api/events.ts:503-537), so a capacity typo is permanent and the frame's '900 seats' is unmaintainable. And the edit view has no exit: SummarySection hides its action button while editing (SummarySection.tsx:56) and this is the ONE panel whose children supply no Cancel/Done, unlike EventSettingsPanel.tsx:216, ResourcesPanel.tsx:244, PeopleRolesPanel.tsx:201 and ApiTokensPanel.tsx:109 -- the only way back to the summary is browser Back. Rule: an editable row holds LOCAL draft state and writes exactly once, on an explicit Save, with Cancel restoring the loaded value; a list that renders a fact renders a control for that fact on EVERY row (a promised column needs controls on every row -- the field guide already says this); and every drilled edit view carries the same Done control as its siblings, because a drill with no way out is a trap, and one panel inventing its own exit grammar is how six grammars get installed.
