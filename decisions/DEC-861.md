# DEC-861: A single-choice filter is a select, not four pressable pills that silently clear each other; and two filter axes on one screen each name their axis

VERIFIED. app/src/pages/speakers/GridFilters.tsx:65-78 renders the four participation states as `chq-pill` buttons carrying `aria-pressed`, and its own comment claims 'a click composes the invite-status predicate, never replaces the other active pills' — but the state it writes is `filters.inviteStatus`, a single nullable value (`filters.inviteStatus === status ? null : status`), so picking a second pill REPLACES the first. Four independently-pressable controls that behave as a radio group is the same defect class as identical labels at an irreversible choice: the affordance describes an interaction the code cannot perform, and a screen reader is told four toggles are available when there is one choice. docs/design/README.md:291 (v5, authoritative and superseding DEC-789 for Speakers) fixes the shape: 'The filter row gains **Any participation ▾** beside the existing task filters, and the old "Any status" is relabelled "Any task status"' — the relabel already landed (GridFilters.tsx:42/48), its partner did not. Decision: the four pills become ONE `<select className="chq-select">` whose empty option reads 'Any participation', aria-label 'Any participation', built by mapping INVITE_STATUSES/INVITE_STATUS_LABELS (never a hand-listed option set), sitting immediately after the 'Any task status' select so the two axes read as a pair. The 'Overdue only' pill stays a pill — it is a genuine boolean toggle, and that is exactly why the single-choice axis must stop wearing its clothes. Filter state, the `inviteStatus=` query param and every server predicate are unchanged: this is a control shape, not a behavior change.
