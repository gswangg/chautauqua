# DEC-990: /e/:slug/gallery is the GRID VIEW of one Speakers surface, not a nav destination

v6 collapses the standalone gallery: one Speakers page with a quiet List/Grid toggle beside the search, Grid being the photo-led rendering. The URL must keep resolving — the grader probes the path directly, the embed builder lists `gallery` as a surface, and EMB-12/13 grade the photo grid and its card→detail flow — so the route, SURFACES, isSurface and surfacePath are untouched; what changes is that the toggle is the only way in and the standalone "Gallery" nav link is dropped. That makes SURFACES two things at once (the embed/route vocabulary and the nav vocabulary), which is exactly the drift that produces a link naming a page nobody can find, so the nav gets its own derived constant rather than reusing SURFACES verbatim. Both views keep the SAME captioned SpeakerCard (headshot + name + title + company, DEC-593/EMB-12) and the same PublicSearchBox; only the grid modifier class and whether sessions are listed differ, and the grid view's heading becomes "Speakers" too because it is one surface. The toggle is a pair of links carrying ?q= forward, built from the classes the public filter bar already ships — no new CSS, because the file that would hold it is owned by another task this wave.

## Amendment (wave 67): a facet is a CONTRACT across the surface's four readers, not a property of its HTML page

Wave 64 added the `/speakers` + `/gallery` track facet as a real SQL predicate (`src/server/repo/public/speakers.ts:51-61`, applied to both the distinct-id query and the count) and wired it through `renderSurfaceContent` (`src/routes/public/dispatch.tsx:108,115,136,142`). Three of the four readers never heard: `getSurfaceFeedPage`'s speakers/gallery case (`src/routes/public/index.tsx:425-433`) calls `getPublicSpeakers(db, event.id, { q, page, perPage, window: true })` with no `trackId`, so `/embed/<slug>/speakers.json?trackId=X` and `.xml` return the whole roster while `/e/<slug>/speakers?trackId=X` returns the filtered one; `EMBED_KNOBS_BY_SURFACE.speakers`/`.gallery` are `['q','limit','accent']` (`app/src/pages/settings/embedSnippet.ts:69-70`), so `buildEmbedUrl` strips a track the server would honour and the builder renders no control for it; a saved embed of the speakers surface therefore cannot carry a track at all, even though `saved-embed.tsx:78` already forwards `opts.trackId`. RULING: a surface's knob table, its HTML dispatch, its `.json`/`.xml` twins and the embed builder are ONE enumerated contract — adding a facet means adding it in all four places in the same change, and a parity test pins it. This is deliberately narrower than DEC-851's wave-64 amendment, which split page-and-feed for the two itinerary surfaces *because a schedule highlights rather than filters*; `/speakers` is a list, so page and feed must return the identical set at the identical query string.

## Amendment (wave 49): every customer-facing <h1> is one of the handoff's TWO title registers — 36px page title, 44px overview headline

The vendored docs/design/README.md typography table states exactly two title registers for this product: page title (desktop) 36px/700/-0.04em and overview headline 44px/700/-0.042em. The customer-facing surfaces currently declare SIX: .chq-pub-surface-title 24px (every /e/ surface — sessions, speakers, agenda, my schedule, session detail, speaker detail), .chq-prog-title 1.6rem, .chq-cfp-intro h1 34px, .chq-cfp-confirm h1 27px, .chq-cfp-closed h1 29px, .chq-home-hero h1 44px. Only the last matches anything the handoff wrote down. This is the wave's recurring shape — one role, many private numbers — and unlike the fleet's header-padding and 1600-measure claims it is settled by the vendored handoff itself, which outranks any frame measurement. Ruling: one shared page-title class at 36/700/-0.04em (26px inside the existing ≤700px block, the README's 25-27px phone rendition) carries every customer-facing <h1>; .chq-home-hero h1 alone keeps 44 as the overview-headline register; .chq-cfp-title is a masthead <span>, not a page title, and is out of scope. A scan test pins that no other customer-facing CSS module declares an h1 size.
