# DEC-623: A ref the product prints is a ref the API accepts

Every screen names a submission SES-014, but assign-by-submission (POST /api/v1/plans/:id/reviewers) only accepts the 20-char internal id and answers 'Invalid reviewer assignment' to the ref it just printed — verified STILL-OPEN in docs/mandates/defect-reverify.md. Human refs are the product's public vocabulary; an endpoint that prints one and refuses it is lying about its own contract. Resolution is event-scoped and server-side (parse the event's recordPrefix + seq), never a client-side guess, and the id path stays first so existing callers are untouched.
