# DEC-636: Framing is a closed two-list: /embed/* is framable, every other surface denies

Two independent browser verifications recorded that no response in this app carries X-Frame-Options or a frame-ancestors CSP, on a product whose whole admin, portal and account surface runs on HttpOnly session cookies — every authenticated screen is frameable and clickjackable. The reason it was never fixed is that a blanket header would break the one family designed to be embedded, which scripts/walkthrough/public.ts:521-523 already asserts must carry NO framing headers. Decision: framing is decided by a closed enumeration of two lists — the framable prefix set (/embed) gets neither header, everything else gets X-Frame-Options: DENY plus Content-Security-Policy: frame-ancestors 'none' — and a test names members of both lists with floor counts, so an unclassified surface is a failing test rather than a silent default.
