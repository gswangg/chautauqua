## Amendment (wave 71): a portal resource's TITLE is editable whatever its kind; only its BODY stays wiki-only

`src/server/repo/portal-config.ts:180` gates the whole PATCH on `kind==='wiki'` with the reason "file-kind resources are a later wave", so a title an organizer typed once when uploading the speaker handbook can never be fixed — only deleted and re-uploaded. The title is the label speakers read in the portal; it is not the bytes. Title and position become editable for every kind; `content` stays wiki-only and a file resource sent a `content` key is a loud 400 field error, not a silent write. Replacing a file's BYTES remains genuinely absent (there is no endpoint), and `ResourcesPanel`'s header comment must keep saying so — the honest remaining absence, narrowed to what is actually missing.

assertOwnAssignmentOr403's bare `catch {}` relabels any internal fault inside assertOwnAssignment -- a missing scope field, a shape violation, an assert -- as 'This task assignment does not belong to you', making a genuine bug indistinguishable from the legitimate foreign-contact path that tests exercise.
