# DEC-681: A conditional rule's value is TYPED by its trigger field's kind, and the browser toggler computes the same transitive fixed point as the server — one matcher, parity-locked

Verified on main: app/src/pages/forms/logic.ts:22-32 always serializes rule.value as a STRING, while answers are typed — src/routes/public/submit-body.ts:34-36 and src/routes/portal/edit.tsx:75-77 write a BOOLEAN for every checkbox, and submission_answer.value_json round-trips numbers back as NUMBERS (src/server/repo/portal-edit.ts:143 JSON.parse). src/forms/visibility.ts:16 compares with strict ===, so a rule on a checkbox trigger can never match on any path (the dependent field is permanently invisible and its answer stripped by src/forms/validate.ts:50-56 — J1 "show field X when format = Workshop" is broken for checkbox triggers), and a rule on a number trigger matches at /submit (string body) but NOT on /portal/.../edit (typed number), where src/server/repo/portal-edit.ts:305-317 then DELETES the stored answer. src/forms/builder.ts:63 type-checks nothing but op/fieldId/array-for-'in', so the builder cheerfully authors unsatisfiable rules. Separately src/views/form-render.tsx:176-190 evaluates each rule against its trigger's LIVE DOM value only and even sets input.required from it, while resolveHiddenFieldIds (visibility.ts:41-75) hides any field whose trigger is itself hidden — so an A→B→C chain is shown AND required in the browser, then silently dropped and hard-deleted server-side. The fix is one canonicalization (checkbox→boolean, number→number, everything else→trimmed string; ABSENT canonicalizes to undefined except an unchecked checkbox, which is false), used by isVisible/resolveHiddenFieldIds, enforced at authoring time by validateRuleReference, and mirrored by the inline script. The inline script cannot import TS, so its source is EMITTED from the same module and locked by a parity test that evaluates the emitted JS against the TS implementation over one shared case table — the field-guide rule that hand-copied vocabularies drift, applied to a vocabulary that must cross the wire.
