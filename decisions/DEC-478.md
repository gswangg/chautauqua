# DEC-478: ONE import row cap; two constants named MAX_IMPORT_ROWS with different values make the 400 message a lie

src/routes/api/contacts/import.ts:24 declares MAX_IMPORT_ROWS = 10_000 (DEC-417, route layer) and src/server/repo/contacts/import.ts:30 declares MAX_IMPORT_ROWS = 2_000 (DEC-356, repo layer). A 3,000-row file passes the route's check, is told nothing, then fails in the repo with a different message; a producer reading the route's own 400 ('Max 10000 rows') is being told something untrue about the system they are using. Only one of these can be the contract. The repo's 2,000 is the enforced number and the defensible one -- each row still costs its own D1 statement in a serial loop (src/server/repo/contacts/import.ts:87-111), so the cap is a real per-request write-burst bound, not decoration -- so the route imports it rather than re-declaring it. No compatibility shim, no second name: delete the duplicate.
