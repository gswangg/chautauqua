# DEC-415: Speaker portal edits to job_title/company/bio persist to the contact record, exactly like first/last name

DEC-321 appended job_title/company/bio to LOCKED_SPEAKER_FIELDS and DEC-121's prefill loads them from the contact (src/server/repo/portal-edit.ts:141-145), and src/routes/portal/edit.tsx:165-171 renders every speaker-section field except email as an editable input -- but saveSubmissionEdits writes only firstName/lastName to contact (:224-232) and the customEntries filter at :251 (`lockedFieldName(fieldId) === null`) drops the other three, so the 302 at edit.tsx:279 reports 'saved' for data that is discarded. That is a silent violation of SPEC.md:141-143 (J7: 'the changes appear on the producer's record instantly'). The direction is settled here so no lane re-litigates it: the edit page keeps rendering them, and saveSubmissionEdits writes them to contact.title/contact.company/contact.bio with the same semantics POST /portal/profile already uses (trim; empty string -> null; an absent answer key leaves the column alone) -- never to submission_answer (they are locked names), and never to participant.title_at_time/org_at_time, because DEC-258's frozen public snapshot must not be rewritten by a later profile edit.
