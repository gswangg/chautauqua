# DEC-200: Welcome email never carries the password; self-service password change at /account/password

DEC-043's "returns the password exactly once" means the 201 API response to the creating organizer is the ONLY cleartext exposure. The current welcome email embeds the temporary password, persisting it in plaintext in email_log (readable via /api/v1/events/:eventId/email-log and the dev mailbox) — and its "change your password" instruction is false because no password-update route exists (the only passwordHash writes are user-create and /claim). Therefore: (1) the welcome email must not contain the password — new copy tells the user to sign in at /login with the temporary password their organizer shares and change it at /account/password; (2) new SSR sub-app src/routes/account.tsx (accountRoutes), mounted only in src/index.ts per DEC-012/013: GET /account/password renders a form (current, new, confirm; csrf token via the ensureCsrfCookie pattern from auth.tsx) and POST /account/password (csrfForm) — anonymous requests 302 to /login; wrong current password or new<8 chars or confirm mismatch re-renders 400 with a visible error; success verifies via verifyPassword, writes hashPassword (DEC-004), bumps updatedAt, deletes ALL of the user's auth_session rows, then issues a fresh session (same flow as login) so every other session is revoked. Works for all three roles (global sessionLoader provides c.var.auth). Portal profile page and admin Settings page each link to /account/password.
