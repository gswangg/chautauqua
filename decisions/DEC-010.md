# DEC-010: Scheduling model: warn-never-block conflicts, greedy auto-schedule

schedule_slot: one row per placed submission (unique submission_id), { room_id nullable, day 'YYYY-MM-DD', start_min, end_min } as minutes-from-midnight in event timezone — nullable room supports "TBD is a real value, partial states always save". Conflict detection is a pure function over PlacedSession = { submissionId, roomId, day, startMin, endMin, speakerContactIds[] } returning Conflict[] of kind 'room_overlap' | 'speaker_overlap'; writes are NEVER blocked by conflicts — the UI shows warning chips and a live "N unplaced · M conflicts" counter. Auto-schedule is a greedy pure function: order sessions by duration descending then track, place each into the earliest slot on the grid in any room that produces zero new conflicts, skip (leave unplaced) if none fits.

## Amendment (wave 66): a break is blocked time for the MACHINE, never for the hand — scanForFreeSlot takes day-scoped blocked intervals, and both its consumers pass them

Verified on main: `src/domain/schedule.ts:178` `scanForFreeSlot` is the ONE candidate-slot scan shared by `autoSchedule` (:387) and `nextFreeSlot` (:495, DEC-652), and it consults only `roomIndex`/`speakerIndex` built from placed sessions. `src/server/repo/agenda/auto-schedule.ts:83` passes `existing` and nothing else; `src/server/repo/overview/scheduling.ts:81/:145` likewise. `schedule_break` rows have existed since wave 63 and the seed already writes a coffee break and a lunch per day (`scripts/seed.ts:2128-2147`), so today `POST /agenda/auto-schedule` will place a keynote at 12:15 and Overview §04 will offer 'Place at 12:15' inside lunch. Wave 65-d is about to hand producers break CRUD, which turns this from a seed artifact into a user-created trap. RULING: breaks become an input to the automatic placer only. A break blocks a candidate START TIME across EVERY room on its day (it is event-wide, exactly as the public agenda draws it — a spanning quiet rule), and a blocked candidate does NOT set `sawRoomAvailableCandidate`, because a break is not a fact about room availability. `findConflicts`, `buildConflictLabels`, `describeUnplaced`'s reason taxonomy and the manual `PUT /submissions/:id/slot` path are ALL untouched: SPEC J9 is warn-never-block, so a producer may still drop a session on top of lunch deliberately. The machine simply never proposes it. This amends DEC-010 rather than DEC-021/DEC-022 because DEC-010 is the decision `src/domain/schedule.ts` itself cites for the greedy engine, and DEC-021/DEC-022 are claimed by the in-flight wave-65 set and by this wave's own export lane.

## Amendment (wave 71): the conflict engine sees breaks, not only the placer — a session over a break is a third conflict kind

Verified split brain: `src/server/repo/agenda/auto-schedule.ts:95` and `src/server/repo/overview.ts:498-509` thread breaks as `blocked` so autoSchedule/nextFreeSlot refuse to place into lunch, while `findConflicts(placed)` (`src/domain/schedule.ts:303`) never sees a break at all, and `app/src/pages/agenda/DayGrid.tsx:365-374` states the band "never enters the conflict engine … the hand may still place a session over a break". The product therefore holds two different answers about the same minute depending on whose hand placed the session. SPEC's scheduling rule is warn-never-block: the drop stays legal, but it must be COUNTED and NAMED. `break_overlap` joins the same conflicts array, the same `summary.conflicts` count, and the same overview KPI/worklist rows. Public surfaces still render NO clash indicators (design pack v7) — this is a producer-side fact only. A session that ends exactly at a break's start does not overlap (same `intervalsOverlap` semantics the placer already uses).
