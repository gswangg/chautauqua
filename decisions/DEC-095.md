# DEC-095: The w3-c scale step-6 400 is a walkthrough-script defect, not a product defect: the portal-edit POST must include the trackIds a real browser would submit

task-w3-c's FAIL traced to scripts/walkthrough/scale.ts building the portal-edit FormData without trackIds, while its original public-submit FormData included one. Because the seeded form is open, canEditTracks returns true, extractTrackIds yields [], and validateTrackChoice (src/lib/submit-core.ts:45) correctly fails with 'Select at least one track.', producing the 400 re-render at src/routes/portal/edit.tsx:201-219. The product behavior is correct per DEC-041/DEC-074: the edit page renders the currently-selected track as a checked checkbox, and a real browser submits it. Fix is scripts-only: scale.ts derives trackIds from the edit page's checked trackIds checkbox (tolerant of hono/jsx boolean-attribute rendering), falling back to the submit-page track id it already captured, and fails loudly if neither exists. No product/handler change; the walkthrough FAIL is closed by this fix plus a gate re-run.
