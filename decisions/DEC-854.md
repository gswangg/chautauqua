# DEC-854: A seeded worklist that is empty for 28 of 30 rows fails its read no matter how correct the code is

The standing rule is that the seed must satisfy every read: a grader opening Content sees the worklist, and the mandate records it as almost entirely 'No files yet' (app/src/pages/content/SessionList.tsx:152). scripts/seed.ts creates only a handful of explicit file rows (seedId('file',1..3) plus per-task onboarding uploads), so the three worklist chips 'Needs a decision · N' / 'Approved · N' / 'All accepted sessions · N' and the DEC-773 unified library have almost nothing to show, and DEC-756's version-list-plus-scoped-note-thread detail is unreachable for most sessions. Decision: a MEASURED floor rather than a fixed number — at least two thirds of accepted submissions carry at least one deliverable version, spread across the three deliverable kinds and across pending/changes_requested/approved so all three chips are non-zero, with more than one real two-version chain (previous_file_id, version_no 1->2). Measured, not asserted blind, so this can never become busywork: if the tree already meets the floor the task is a no-op plus the test that pins it.
