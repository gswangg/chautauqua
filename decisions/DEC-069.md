# DEC-069: Machine-greppable stage-1 exit predicate in docs/verification-log.md (RESULT:/OPEN ITEMS: lines); green counts only for its named sha

Six verification lanes have now run (five dropped, one green pre-merge) with no objective way to say 'done'. Fix: stage-1 completion is declared only when docs/verification-log.md on main contains, at or after the newest code-bearing main sha, four gate sections — build+test, J1-J12 walkthrough vs seeded wrangler dev, perf smoke, SPEC §8/§9 static audit — each ending with exactly one line 'RESULT: PASS' (or 'RESULT: FAIL — <summary>' when failing), plus a triage-closure section ending 'OPEN ITEMS: <n>' with n=0. A green section counts ONLY for the main short-sha named in its '## <date> <branch> — <scope> @ <sha>' header; any later code merge invalidates it for exit purposes and requires a fresh run of that gate. This turns the wave-14 goalComplete call into a grep, prevents premature completion on an untested merged tree, and equally prevents endless re-verification of an unchanged one.
