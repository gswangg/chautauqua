# DEC-937: A stylesheet may only reference tokens that EXIST, and a button base rule always names its own face — both scan-locked

`var(--chq-sunk)` is referenced three times (app/src/pages/overview/overview.css:79 and :252, app/src/pages/submissions/detail.css:326) and defined NOWHERE — `--chq-surface-sunk` is the real token in app/src/styles.css:25. A `background: var(--chq-sunk)` with no fallback resolves to `unset`/transparent, so every secondary button on Overview and on the submission detail paints straight onto paper: the gate-2 report's cross-section "secondary buttons resolve transparent". The identical failure in the other direction: `.chq-overview-toolbar-btn` (:73), `.chq-overview-btn` (:246) and `.chq-day-grid-noroom-btn` (agenda.css:277) declare padding, border, size and weight but no `font-family`, so a bare `<button>` falls back to the UA face and renders in Arial beside Figtree body text. Both are one bug: a hand-written reference with nothing checking that what it names exists or is complete, exactly the "hand-listed manifests desync — ENUMERATE" rule. Rule: `--chq-sunk` is DELETED, not aliased (house rule: no compat shim); the three call sites take `--chq-surface-sunk`. A scan test enumerates every `var(--chq-…)` reference across app/src/**/*.css and requires each name to be declared either in styles.css's `:root` block or in the referencing file itself, and requires every top-level rule whose selector ends `-btn`/`-button` AND declares `padding` to declare `font-family` (or the `font` shorthand). Never a per-page fix; the scan is the fix.

## Amendment (wave 39): the typeface contract binds the ELEMENT, not the class name — and a var() fallback over an undeclared token is the same lie as a bare undeclared token

DEC-937's invariant (B) fires only on selectors ending in `-btn`/`-button`. `.chq-pill` (app/src/styles.css:588) and `.chq-overview-section-action` (app/src/pages/overview/overview.css:119) are button faces that do not end in that string, declare no font-family, and there is no global `button { font-family: inherit }` — so every worklist tab, library type chip, deliverable chip and section action computes the UA default (Arial) beside Figtree neighbours. A rule keyed on a NAME will be re-broken by the next name; the contract must key on the element that carries the class. Ruling: app/src/styles.css declares one global reset `button, input, select, textarea, optgroup { font-family: inherit; }` — the FAMILY only, never the `font` shorthand, which would also reset size/weight/line-height and repaint every control. Invariant (B) stands; two invariants join it. (E) every `font-family` declaration under app/src resolves through a `var(--chq-font-…)` token or is exactly `inherit`, with @font-face bodies and the one `monospace` code face named as the exemptions — a literal family list is a fork of the type system. (F) invariant (A)'s exemption for `var(--chq-foo, <fallback>)` is withdrawn: a fallback whose token is declared NOWHERE (neither :root nor the referencing file) is not a deliberate default, it is a dead reference that has quietly become the fallback's value. That is how `.chq-review-queue-score-action`'s `var(--chq-accent, var(--chq-ink))` paints ink-on-olive at 2.40:1 while reading like an accent, and how four overview rules, five forms/detail rules and two contacts-panels rules ride `--chq-display-font`/`--chq-font-body`, tokens this codebase never declared. Every such reference is renamed to the real token (`--chq-font-display` / `--chq-font-ui`) or the fallback is inlined; the scan makes the next one a build failure.

## Amendment (wave 23): phone data-labels are guarded, and an action cell carries none

Three stylesheets implement the phone label idiom and they disagree. `.chq-comms-templates-table`'s cells emit `data-label="Name"`/`"Last used"` (TemplatesTab.tsx:223,229) that NO rule consumes — comms.css scopes `::before` to `.chq-comms-compose-table` alone (comms.css:1007) — so those attributes are dead markup. review.css:317 declares an UNGUARDED `.chq-review-results-table td::before { content: attr(data-label) }`, so a cell with no label renders an empty pseudo-element carrying that rule's own box. RULING: the phone label rule is always `td[data-label]::before` (the guarded form settings.css:280 and comms.css:1007 already use), and an action/hug column carries no `data-label` at all — its control names itself, and "Revoke: Revoke" is noise. Either the attribute has a rule that consumes it or the attribute goes.

## Amendment (wave 24): a phone label is sourced from its cell, never from its position

DEC-937's wave-23 amendment already ruled the phone label idiom is `td[data-label]::before` with the label set from the same string the `<th>` renders. `app/src/pages/contacts/contacts.css:524` and `:541` still generate the contacts phone card's labels as CSS literals keyed to column INDEX -- `td:nth-child(3)::before { content: 'Company' }` and `td:nth-child(4)::before { content: 'Labels: ' }` -- while `ContactsTable.tsx:97,98` already render exactly those words as `<th>`s. A literal keyed to an index is two dependencies no compiler sees: it silently mislabels the moment a column is added, removed or reordered (this table already carries a select column before them and an actions column after), and it forks the phone vocabulary away from the desktop header. Ruling: generated LABEL text comes from `data-label` on the cell; positional selectors may still carry order and width (layout is a position), never letters. Punctuation-only decoration keyed positionally stays legal and is exempt as a REASON, not an allowlist entry -- submissions.css:515-517's `content: '· '` separator is a separator (DEC-610), not a label. Scan-locked: inside a phone media query, no positional selector may generate content containing a letter.

## Amendment (wave 160): the 390 head band's bottom edge is drawn by the body it opens, full-bleed through the gutter cancel — a band whose contents span three parents cannot carry its own box

docs/design/Chautauqua Contacts.dc.html:180 draws the Contacts 390 head as ONE band closed by `border-bottom:1px solid #1B1D17`, with the body at :201 opening `padding:4px 16px 16px` beneath it. r2-d landed the band's 11px rhythm but not its edge, so at 390 the head runs into the card list with no drawn boundary. The band's contents live in three different parents (.chq-contacts-title-row, .chq-toolbar.chq-contacts-tabstrip-row, and the two strips inside .chq-contacts-directory-main), so no element in the tree is the band; wrapping them would restructure ContactsApp.tsx markup at both widths for one hairline. RULED: where a frame's band is composed across siblings, its closing edge is drawn as a border-TOP on the body region it opens — here `.chq-contacts-table-wrap`, which always renders and always follows the last strip — carrying the frame's own 4px body inset above the first row. Full-bleed is reached with the established gutter cancel (`margin-inline: -16px` against app/src/styles.css's `.chq-main { padding: 16px }`, restored by an equal inline padding), the same idiom `.chq-phone-head` and contacts-panels.css:1886 already use; the ink lands where the frame draws it, no markup moves, and no desktop byte moves because the rule lives at the end of the sheet's single terminal max-width:700px block.

## Amendment (wave 13m): a design token referenced with a CSS fallback does not satisfy the token contract — `var(--chq-font-display, inherit)` is a second source of truth, drop the fallback

app/src/css-contract.scan.test.ts is red on main over one offender: `.chq-speakers-remind-card-subject` in speakers.css declares `font-family: var(--chq-font-display, inherit)`. The scan and the CSS are in direct contradiction, so one must move. The token is unconditionally defined in app/src/styles.css, so the fallback can only ever fire when the token is MISSING — i.e. it silently paints an off-system face at exactly the moment the design system has broken, which is the fail-loudly inversion. The CSS moves: `font-family: var(--chq-font-display)`. The scan's predicate stands unchanged.
