# DEC-937: A stylesheet may only reference tokens that EXIST, and a button base rule always names its own face — both scan-locked

`var(--chq-sunk)` is referenced three times (app/src/pages/overview/overview.css:79 and :252, app/src/pages/submissions/detail.css:326) and defined NOWHERE — `--chq-surface-sunk` is the real token in app/src/styles.css:25. A `background: var(--chq-sunk)` with no fallback resolves to `unset`/transparent, so every secondary button on Overview and on the submission detail paints straight onto paper: the gate-2 report's cross-section "secondary buttons resolve transparent". The identical failure in the other direction: `.chq-overview-toolbar-btn` (:73), `.chq-overview-btn` (:246) and `.chq-day-grid-noroom-btn` (agenda.css:277) declare padding, border, size and weight but no `font-family`, so a bare `<button>` falls back to the UA face and renders in Arial beside Figtree body text. Both are one bug: a hand-written reference with nothing checking that what it names exists or is complete, exactly the "hand-listed manifests desync — ENUMERATE" rule. Rule: `--chq-sunk` is DELETED, not aliased (house rule: no compat shim); the three call sites take `--chq-surface-sunk`. A scan test enumerates every `var(--chq-…)` reference across app/src/**/*.css and requires each name to be declared either in styles.css's `:root` block or in the referencing file itself, and requires every top-level rule whose selector ends `-btn`/`-button` AND declares `padding` to declare `font-family` (or the `font` shorthand). Never a per-page fix; the scan is the fix.

## Amendment (wave 39): the typeface contract binds the ELEMENT, not the class name — and a var() fallback over an undeclared token is the same lie as a bare undeclared token

DEC-937's invariant (B) fires only on selectors ending in `-btn`/`-button`. `.chq-pill` (app/src/styles.css:588) and `.chq-overview-section-action` (app/src/pages/overview/overview.css:119) are button faces that do not end in that string, declare no font-family, and there is no global `button { font-family: inherit }` — so every worklist tab, library type chip, deliverable chip and section action computes the UA default (Arial) beside Figtree neighbours. A rule keyed on a NAME will be re-broken by the next name; the contract must key on the element that carries the class. Ruling: app/src/styles.css declares one global reset `button, input, select, textarea, optgroup { font-family: inherit; }` — the FAMILY only, never the `font` shorthand, which would also reset size/weight/line-height and repaint every control. Invariant (B) stands; two invariants join it. (E) every `font-family` declaration under app/src resolves through a `var(--chq-font-…)` token or is exactly `inherit`, with @font-face bodies and the one `monospace` code face named as the exemptions — a literal family list is a fork of the type system. (F) invariant (A)'s exemption for `var(--chq-foo, <fallback>)` is withdrawn: a fallback whose token is declared NOWHERE (neither :root nor the referencing file) is not a deliberate default, it is a dead reference that has quietly become the fallback's value. That is how `.chq-review-queue-score-action`'s `var(--chq-accent, var(--chq-ink))` paints ink-on-olive at 2.40:1 while reading like an accent, and how four overview rules, five forms/detail rules and two contacts-panels rules ride `--chq-display-font`/`--chq-font-body`, tokens this codebase never declared. Every such reference is renamed to the real token (`--chq-font-display` / `--chq-font-ui`) or the fallback is inlined; the scan makes the next one a build failure.
